# 147 — Ship the minified bundles the site already builds (and un-blind `npm test`)

**Status**: promoted by the build loop 2026-07-26 — no READY items existed in BACKLOG.md.
**Score**: 7.8 · **Risk**: HIGH (touches `home.html`, the IA router / sacred parameterized-URL shell)

## Problem (documented evidence only — nothing new was discovered to file this)

Two things are broken by the same two lines of HTML.

### 1. The whole `npm test` gate is dark on `main`

`package.json`'s `test` script is a single `&&` chain of ~90 test files.
`test_minified_assets.js` sits **6th** in that chain and **exits 1 on unmodified
`main`**, so every test after it — ~85 files including every rendered-Playwright
acceptance test the loop relies on — never runs in a plain `npm test`.

This has been recorded, unfixed, by **eleven consecutive build loops**, each
correctly refusing to fix it as scope creep:

| Loop | Note |
|------|------|
| 117.2 | `specs/117.2-notes.md:48` — "still loads raw planner.js … reproduced identically on clean origin/main via git-stash" |
| 125 | `specs/125-notes.md:15` — "2 PRE-EXISTING reds" |
| 128 | `specs/128-notes.md:13` — "Confirmed pre-existing by `git stash`-ing this diff" |
| 130 | `specs/130-notes.md:15`, `130-pr.md:29` — "fixing it would be scope creep" |
| 137 | `specs/137-notes.md:22` — "2 failing assertions on `main`" |
| 138 | `specs/138-notes.md:17` — "reproduced on the clean tree BEFORE any change" |
| 139 | `specs/139-notes.md:84`, `139-pr.md:98` |
| 140 | `specs/140-notes.md:18` — "**also FAILS AT HEAD**" |
| 143 | `specs/143-notes.md:24` — "**exits 1** … and therefore [halts the chain]" |
| 144 | `specs/144-notes.md:50` — "the freshness gate is red on `main` today" |
| 146 | LOG.md 2026-07-26 — "halts the `&&`-chained `npm test` before it reaches this item's test **on EVERY run including unmodified main**, so each test the spec names was run individually" |

Every one of those loops had to hand-run its own tests one file at a time. That
is the compounding cost: the gate that is supposed to catch regressions catches
nothing past position 6, and each future item pays the same tax.

### 2. Prod serves the raw bundles, not the minified ones it builds every day

`minify-assets.js` (backlog 053) minifies `planner.js` and `translations.js`,
the daily `sitemap-update.yml` CI run regenerates **and commits** the outputs
(`.github/workflows/sitemap-update.yml:66,149`), and `test_minified_assets.js`
proves the committed `.min.` files are byte-fresh (7/7 green today). They are
simply **not referenced**:

| File | Line | Currently loads | Should load | Raw | Min | Saved |
|------|------|-----------------|-------------|-----|-----|-------|
| `home.html` | 175 | `translations.js` | `translations.min.js` | 90,310 B | 69,645 B | 20,665 B |
| `home.html` | 196 | `planner.js` | `planner.min.js` | 238,585 B | 100,417 B | 138,168 B |
| `plan.html` | 100 | `planner.js` | `planner.min.js` | 238,585 B | 100,417 B | 138,168 B |

Both are `<script defer>` in the **static** `<head>`/body — every visitor pays
for them, including the `?pool=` / `?token=` SEO landers that arrive on
`home.html`, i.e. the **north-star surface** (pool-detail conversion clicks).
`home.html` therefore ships **~159 KB of avoidable uncompressed JS on the
north-star surface**, and `plan.html` ~138 KB on the planner.

This is a regression, not a design choice: `specs/053-notes.md:7` and
`053-pr.md:21` record `home.html` and `plan.html` being swapped **to** the
`.min.` references when 053 shipped, `git log -S'planner.min.js' -- plan.html`
shows the string was later removed, and the comment left behind at
`home.html:194-195` still reads *"Minified in CI (backlog 053); edit
planner.js, never planner.min.js"* — the comment describes the intended wiring
that the `src` no longer matches. `specs/060-notes.md:38` and
`061-notes.md:7` document the era when the pages did load the bundles.

It also aligns with the direction of shipped item **140** (snapshot fast path
dead → SEO landers wait on the slow path): same surface, same "the page is
slower than it needs to be for the traffic we're courting" problem.

## Goal

`home.html` and `plan.html` load the minified bundles; `npm test` runs its full
chain again; nothing about rendered behavior changes.

## Non-goals

- Minifying anything not already in `minify-assets.js`'s `JS_FILES`/`CSS_FILES`
  (`analytics.js`, `landing.js`, `brand-icons.js`, `canonical.js` stay raw).
- Touching `minify-assets.js`, `compile-app.js`, the CI workflow, `vercel.json`,
  or `package.json` dependencies.
- Fixing any other pre-existing red (e.g. `test_waitlist_funnel.js`'s 3 cases,
  documented pre-existing in LOG 2026-07-26). If the un-blinded chain reveals
  further reds downstream, they are **recorded in `147-notes.md`, not fixed** —
  and the item is judged on the reds it was scoped to clear.
- Any copy, CSS, or component change. Zero new user-facing strings, so zero
  `translations.js` churn (and therefore no EN/KO pairing obligation).

## Change

Three `src` swaps, nothing else in product code:

1. `home.html:175` — `<script defer src="translations.js">` → `translations.min.js`
2. `home.html:196` — `<script defer src="planner.js">` → `planner.min.js`
3. `plan.html:100` — `<script defer src="planner.js">` → `planner.min.js`

Keep every surrounding comment (they already describe the min-wiring intent);
keep `defer`, attribute order, and load order **identical** — order is
load-bearing (`react` → `translations` → `analytics.js` → `planner`), and
`analytics.js` must stay statically deferred ahead of the planner (CLAUDE.md).

Plus one new rendered test (below) wired into `npm test` immediately after
`test_minified_assets.js`.

## Territory notes

- `terser` runs `{ compress: true, mangle: true }` with **`toplevel` unset**
  (`minify-assets.js:30`), so top-level/global names are NOT mangled — the
  cross-file globals (`window.TRANSLATIONS`/`t()`, `Analytics`, the planner's
  mount) survive minification. This is why the swap is expected to be
  behavior-neutral; the rendered test is what proves it rather than assumes it.
- `home.html` also injects `PoolDetail.compiled.min.js` + `app.compiled.min.js`
  dynamically (`home.html:354-355`) — already minified, untouched here.
- Staleness risk is already covered from both sides: CI regenerates + commits
  the `.min.` outputs daily, and `test_minified_assets.js`'s first 7 assertions
  fail loudly if a committed `.min.` file drifts from its source. After this
  item, a source edit without `npm run minify` is caught by that same test
  **and** actually matters again (it did not, while nothing loaded the bundle).
- Sandbox: browser-originated HTTPS is blocked (NORTH_STAR 2026-07-12), so the
  rendered test uses the house fixture-routing pattern (local static server,
  vendored React, `yields.llama.fi` fixture-routed) — same as
  `test_repeat_cta.js` / `test_northstar_cta_fires.js`.

## Acceptance criteria

Source-level:

1. `node test_minified_assets.js` exits **0** with **9/9** assertions.
2. `git diff --name-only` shows product-code changes confined to `home.html`
   and `plan.html`; no `.min.` file, no `translations.js`, no `planner.js`, no
   `package.json` dependency block, no CI/config file is modified. (The new
   test file, the `npm test` chain entry, and bookkeeping files are expected.)

Rendered — new `test_min_asset_boot.js`, real chromium against a real static
server, **all with no page/console errors** (house `IGNORABLE` filter for the
blocked externals only):

3. `plan.html` boots the planner from `planner.min.js`: the served document
   requests `planner.min.js` and **never** requests `planner.js`, and the
   planner's first screen actually renders (goal chips present, an interactive
   flow step completes) — proving the minified bundle executes, not just loads.
4. Bare `/` (planner mode via `__APP_MODE`) does the same, and additionally
   requests `translations.min.js` and never `translations.js`.
5. `/?pool=<id>` (the north-star surface) renders pool-detail with **both**
   CTAs ("Garden this pool" + "Start Earning on …") present, while the document
   loaded `translations.min.js` + `planner.min.js`.
6. `/?token=USDC` still renders pool cards — the sacred SEO/analytics path.
7. `?lang=ko` renders Korean copy on the planner, proving `translations.min.js`
   carries the full KO dictionary (a truncated/broken minify would surface here).
8. Non-vacuity: the test must be shown to FAIL on a stashed baseline (raw
   `src`s restored) for the request-level assertions — recorded verbatim in
   `147-notes.md`. A test that passes both before and after is not evidence.

Chain:

9. `npm test` proceeds **past** `test_minified_assets.js` — record in
   `147-notes.md` how far the chain gets inside the 5-minute timebox and which
   file (if any) is the next stopper, so the next loop inherits the fact rather
   than rediscovering it.
