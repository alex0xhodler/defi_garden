# Spec 091 — Expand the category taxonomy beyond Lending/Staking/LP-DEX

Status: IN_PROGRESS (2026-07-14)
Score: 7.0 · Risk: HIGH (user-facing analytics-app behavior + NL parser; per NORTH_STAR "anything user-facing beyond copy/styling → HIGH; when in doubt → HIGH")

## Source / evidence
- BACKLOG.md item 091 (human, 2026-07-14 analytics-UX audit): "expand the category taxonomy beyond Lending/Staking/LP-DEX — add Borrowing, RWA, and Pendle/yield-derivatives (human named these) as first-class `getPoolType` categories (`app.js:84`, + the `LENDING/DEX_LP/STAKING_PROTOCOLS` lists) so the nav tabs + counts (`app.js:1537`) + NL-search parser cover them. Classification MUST stay honest (a pool's category derives from protocol/poolMeta, never fabricated); Borrowing vs Lending needs a real distinguisher (supply vs borrow side) or ship only the categories we can classify truthfully."
- NORTH_STAR trust-rail principle: honest numbers/labels only; "a pool's category derives from protocol/poolMeta, never fabricated."

## The honest-classification decision (drives scope)
Live `yields.llama.fi/pools` audit (15,451 pools, 2026-07-14):

- **Yield Derivatives (Pendle & friends)** — classifiable. `pendle` (160 pools), `spectra-v2`/`spectra-metavaults` (32), `termmax` (13). These are principal/yield-token & fixed-yield derivative protocols; deriving the category from the protocol name is honest and deterministic. Today they fall to the default "Yield Farming" bucket.
- **RWA** — classifiable. Protocol-native RWA/tokenized-treasury/on-chain-credit projects present in live data: `ondo-yield-assets`, `centrifuge-protocol`, `goldfinch`, `openeden-tbill`/`openeden-usdo`, `matrixdock-stbt`, `midas-rwa` (32), `usual-usd0`/`usual-eth0`/`usual-eur0`, `credix`, `clearpool-lending`, `maple`. Deriving RWA from the protocol is honest.
- **Borrowing** — NOT honestly classifiable from this dataset, so **DEFERRED** (the row explicitly permits "ship only the categories we can classify truthfully"). The DefiLlama yields API is fundamentally a **supply-side** feed: `apy` is what a *depositor earns*. Only 81 / 15,451 pools (0.5%) carry "borrow" anywhere in `poolMeta`, and a borrow rate is a *cost*, not an earning — surfacing those 81 sporadic entries under a "Borrowing" tab, next to supply APYs, with a positive APY number, would misrepresent both coverage and meaning. No supply-vs-borrow-side distinguisher exists in the payload. Documented, conservative defer — revisit only if a borrow-side data source is added.

**Scope: ship RWA + Yield Derivatives. Defer Borrowing (documented above).**

## Territory notes (code as-is)
- `getPoolType(pool)` at `app.js:84` — ordered checks: `poolMeta` includes "lending" → Lending; then `LENDING_PROTOCOLS` / `DEX_LP_PROTOCOLS` / `STAKING_PROTOCOLS` substring match on `projectName`; else default "Yield Farming". Protocol lists at `app.js:7/14/23`.
- Nav tabs render at `app.js:2668-2683`: hardcoded English literals `All / Lending / Staking / LP/DEX` (they do NOT currently go through `t()`), each `onClick: setSelectedPoolTypes(['<Category>'])`. Internal category identifier === display label today.
- `poolTypeCounts` memo (`app.js:1611`, keys `All/Lending/LP/DEX/Staking/Yield Farming`) is defined but **currently unused** (no render site — grep-confirmed). Keep it consistent (add new keys) but it drives no UI.
- NL parser pool-type detection at `app.js:295-314` pushes to `poolTypes`.
- Filtering: `selectedPoolTypes.includes(getPoolType(pool))` at `app.js:1661/1731/1802` — new categories flow through automatically once `getPoolType` returns them and a tab can select them.
- CSS `.google-nav-tabs` (`style.css:1077`) is `overflow-x:auto` (hidden scrollbar) with `flex-shrink:0` tabs → **extra tabs scroll horizontally, no wrap/overflow breakage** at any width. This de-risks the responsive concern.
- Every user-facing string must go through `translations.js` (CLAUDE.md hard rule). Category tab labels currently violate this (hardcoded). This item adds new labels, so route the category labels through `t()` — EN + natural KO together.

## What to build (surgical)

Add two protocol lists near the existing ones (`app.js:7-28`):
- `YIELD_DERIVATIVES_PROTOCOLS = ['pendle', 'spectra', 'spectra-v2', 'spectra-metavaults', 'termmax', 'napier', 'sense', 'notional', 'element']` (live-present + a few well-known forward-compatible names; substring match, so `spectra` covers both spectra entries).
- `RWA_PROTOCOLS = ['ondo', 'centrifuge', 'goldfinch', 'openeden', 'matrixdock', 'midas-rwa', 'midas', 'usual', 'credix', 'clearpool', 'maple', 'superstate', 'franklin', 'backed', 'hashnote', 'mountain-protocol']`.

In `getPoolType`, add the two new checks **before** the `poolMeta`-lending check and the generic lists, so protocol-native classification wins (order: RWA → Yield Derivatives → existing poolMeta/lending/dex/staking → default). Returns the exact strings **`'RWA'`** and **`'Yield Derivatives'`**.
- Note: `maple` moves Lending → RWA (it is institutional private credit / RWA; more accurate). Document in notes.

### 2. Counts memo (`app.js:1614`)
Add `'RWA': 0, 'Yield Derivatives': 0` to the `counts` initializer so `counts[poolType]++` never writes an undefined key. (Memo is unused today but keep it correct.)

### 3. Nav tabs (`app.js:2668-2683`)

Order: All, Lending, Staking, LP/DEX, RWA, Yield Derivatives. The four filter buttons (Chains/TVL/Protocols/APY) after the tabs are unchanged.

4. NL search: "rwa" / "real world assets" select the RWA category; "pendle" / "yield derivatives" select Yield Derivatives; unrelated queries do not.
5. Borrowing is NOT shipped; the defer rationale is recorded in the spec + notes.
6. `app.compiled.js` / `app.compiled.min.js` (and `translations.min.js` if loaded) regenerated from source; `npm test` green including the new `test_category_taxonomy.js`; both router paths (`/` planner, `/?token=USDC` analytics) still render.
