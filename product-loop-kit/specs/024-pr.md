# PR explainer: spec 024 — working link promoted to primary share CTA

**Risk tier: HIGH** (render-path change to the bloom moment's primary CTA — the hero conversion surface — reversing a previously shipped decision, spec 008). Full walkthrough required before merge per NORTH_STAR.md risk policy.

## Goal
DeFi Garden's north-star metric is `share_link_opened → plan_created` weekly closures — the viral loop only closes if the thing a user shares actually carries a working link back into the app. As of 2026-07-10 (specs 004/005/008), the bloom-moment share hub's ONE button-styled CTA was the **image** download/share (📸), with the working link demoted to a small text link below it. On 2026-07-11 the human reversed that call (NORTH_STAR.md standing decisions): an image is a dead end — nobody can tap it to rebuild your garden — while the link (`encodePlanToUrl`/`decodePlanFromUrl`, already shipped and round-tripping full plan state per item 007) is the only artifact that can actually close the funnel. So the fix is a straight swap of prominence: link becomes primary, image becomes secondary. Nothing about *how* either action works changes.

## Intuition
Picture the bloom-moment share card as it existed before this change: a big raised button says "📸 Share my garden", and beneath it, in small blue text, is "or copy the link" / "or share the link". A user in a hurry taps the big button — gets an image file. That image has no return path; whoever receives it can admire the numbers but can't tap into their own copy of the plan. The metric this product is built around (`share_link_opened → plan_created`) can *only* be moved by the link path. So this change makes the big button say "🔗 Copy your garden link" (or, on a phone with a native share sheet, "🔗 Share your garden link"), and demotes the image to "or save as an image" underneath. Everything downstream — what happens when you click each one — is completely unchanged; only which one gets top billing changed.

## What changed and why (diff in reading order)

1. **`translations.js`** (EN block ~309-314, KO block ~792-797): three new keys added next to the existing `share*` keys —
   - `shareLinkPrimaryCta` ("🔗 Copy your garden link" / KO "🔗 정원 링크 복사하기") — the primary button's label on desktop browsers (no `navigator.share`).
   - `shareLinkPrimaryNative` ("🔗 Share your garden link" / KO "🔗 정원 링크 공유하기") — the primary button's label where the native OS share sheet is available.
   - `shareTextLinkImage` ("or save as an image" / KO "또는 이미지로 저장") — the new demoted label for the image action.
   No existing keys were removed (`shareTextLinkCopy`/`shareTextLinkNative` are now unused by `sharePromptElement` but left in place — they're small, harmless, and removing translation keys speculatively used elsewhere wasn't part of this item's scope).

2. **`planner.js`** (~2576-2596, `sharePromptElement`):
   - Before: `.gp-share-btn` (primary) → `onClick: doShare` (image). `.gp-share-textlink` (demoted) → `onClick: doNativeShare` or `doCopyLink` depending on `navigator.share`.
   - After: two new local variables, `linkPrimaryLabel` and `linkPrimaryHandler`, computed once (mirroring the existing `navigator.share` branch that was already there, just extracted so both the label and the handler pick the same branch). `.gp-share-btn` (primary) → `onClick: linkPrimaryHandler`, label = `linkPrimaryLabel` (with the existing `copySuccess` confirm-state logic preserved, just moved onto this element). `.gp-share-textlink` (demoted) → `onClick: doShare`, label = the existing `isSharing`/`imageShareConfirm` in-flight/confirm states, just moved onto this element with the new `shareTextLinkImage` copy for the idle state.
   - The handlers themselves (`doShare`, `doCopyLink`, `doNativeShare`, all defined earlier in the same function, ~1695-1824) are **byte-for-byte unchanged** — this is purely a "which JSX element calls which existing function" swap, not new share logic.
   - The stale comment above the element (which described the 008 image-primary rationale) was rewritten to record this 2026-07-11 reversal, so the next person reading the code isn't misled by a comment that no longer matches reality.

3. **`product-loop-kit/specs/024.md`** (new): the spec, written from the backlog row + NORTH_STAR standing decision + existing code, since none existed yet.

4. **`product-loop-kit/specs/024-notes.md`** (new): build notes — chiefly documenting an environment discovery: this sandbox's network policy blocks `unpkg.com` (React's CDN host) in addition to `yields.llama.fi`, which is a stricter wall than prior loop sessions (021/027) had documented. Verification routed those two hosts to local stand-ins (npm-installed React UMD bundles; a small realistic pool-data fixture) inside the Playwright `BrowserContext` only — no shipped file was touched to make this work; it's a test-harness substitution for a network hop the product will make normally in production.
