# Spec 131 — Dedupe "Browse tokens · Browse chains" on the north-star page (086-adjacent)

- **Backlog id:** 131 · **Score:** 4.5 · **Risk:** LOW (styling / critical-CSS; no router-logic or parameterized-URL behavior change)
- **Status:** IN_PROGRESS (2026-07-25)
- **North star:** pool-detail conversion clicks. This is a product-QUALITY fix on the north-star page (PRE-TRAFFIC MANDATE 2026-07-23: audit-and-fix rendered jank), not a conversion experiment.

## Problem (from the 2026-07-23 pool-detail UX audit screenshot)
"Browse tokens · Browse chains" renders **twice** on the pool-detail page — once high on the page (under the header) and once in the footer.

## Root cause (reproduced, rendered Playwright)
Two link sets carry these hub links:
1. Static `<footer class="seo-hub-links">` in `home.html` (lines ~312-315) — server-rendered so crawlers reach `/tokens` + `/chains` without executing the app (SEO de-orphan surface, item 045). Present in the raw HTML in every mode.
2. The React `<footer class="app-footer"><p class="app-footer-hub-links">` rendered by `app.js` (pool-detail branch `app.js:2823`, grid branch `app.js:3376`).

Item 086 deduped these by hiding the static footer in analytics mode with a CSS rule **in `style.css`**:
`html[data-app-mode="analytics"] .seo-hub-links { display:none }` (style.css:2588).

But `style.min.css` loads via the async `media="print" onload="this.media='all'"` swap (`home.html:134`). The dedup rule therefore does **not** apply:
- during initial paint, before the swap fires (a FOUC flash of the duplicate — worst on the pool-detail page, whose `#root` is briefly empty, so the static footer flashes high "under the header" before the app mounts and adds its own footer at the bottom → "renders both"), and
- in any headless render where the `media="print"` onload swap never fires (exactly the environment that produced the 2026-07-23 audit screenshot).

Reproduced with rendered Playwright on `/?pool=usdc-base-aave`:
- WITH the swap forced (real-Chrome-equivalent): **1** visible `/tokens` link (086 works).
- WITHOUT the swap (pre-paint / headless / audit state): **2** visible `/tokens` links, `.seo-hub-links` `display:block`.

## Fix (surgical, ~3 lines)
Promote the one dedup rule to **render-blocking inline critical CSS** in `home.html`'s `<head>`, so it applies before first paint independent of the async stylesheet:

```html
<!-- Critical dedup (131, mirrors the style.css rule 086 added): the static
     .seo-hub-links crawler footer is duplicated inside the React .app-footer in
     analytics mode. style.min.css loads async (media="print" swap above) so its
     copy of this rule can't hide the static footer before first paint — that
     flashed a duplicate "Browse tokens · Browse chains" (worst on the empty-#root
     pool-detail page). Inline + render-blocking = no flash, in every renderer.
     data-app-mode is set by the router script above before paint; crawlers run no
     JS so it's never set for them and the raw static anchor stays reachable. -->
<style>html[data-app-mode="analytics"] .seo-hub-links{display:none}</style>
```

Placed in `<head>` after the `style.min.css` link block (~home.html:135). The router script that sets `data-app-mode` already runs synchronously in `<head>` before body, so the attribute is present when this rule is matched at first paint.

**Leave `style.css`'s rule in place.** The inline block is deliberate critical-CSS mirroring it (standard pattern), not a duplicated component — a comment in each points to the other so they stay in sync. Not editing `style.css` also avoids regenerating `style.min.css` (keeps the diff to `home.html` + the test).

## Out of scope / non-goals

- No change to `app.js` render (the app-footer hub links are correct — they're the visible copy JS users get).
- No new CSS classes, no new dependencies, no i18n strings (the two anchors' text is unchanged).
