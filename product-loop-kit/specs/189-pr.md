# 189 — explainer (HIGH tier: full walkthrough + quiz)

## The goal in one sentence

Stop submitting sitemap URLs to Google that our own product renders as an empty grid — by deleting the
second, stale copy of the pool-type classifier that made us believe they were fine.

## The intuition

We publish `?token=USDC&poolTypes=Lending`-shaped URLs in `sitemap-category-*.xml`. Whether such a URL has
anything to show depends on one judgement call: **what category is this pool?** Two pieces of code answered
that question, and they were not the same piece of code.

- The **product** answers with `getPoolTypeShared` (`PoolDetail.js:47`) — six categories, five long protocol
  lists, RWA and Yield-Derivatives precedence. `app.js:161` delegates to it, and it is what the grid's
  `poolTypeMatch` filter actually runs. Its own header comment says: *"SINGLE SOURCE OF TRUTH … do not fork a
  second copy of this classifier."*
- The **sitemap generator** answered with its own `getPoolType` (`generate-sitemap.js:242`) — four categories,
  three short lists, written before spec 130 unified the product's copies and never updated after.

So the generator counted pools into buckets the product does not use, then applied item 013's "≥2 qualifying
pools" quality gate to those wrong counts, then published the URL. When a token's pools were all — say —
`ondo` (RWA to the product, "Yield Farming" to the generator), the generator saw two qualifying Yield-Farming
pools and published `?token=USDY&poolTypes=Yield%20Farming`; the product then filtered for Yield Farming,
found none, and rendered "no yields found".

Measured on the committed 736-pool snapshot before the change: the two classifiers disagreed on **90 pools
(12.2%)**, every disagreement in the same direction, and **8 of the 114 published category URLs rendered zero
pools**, 3 more rendered one.

The second half of the same root cause: the generator knew four of the product's six categories, so **41
pools** (31 RWA + 10 Yield Derivatives) could never earn a category URL at all.

### Why no checker caught it

`generate-llms.js:885` and `audit-app.js:1032` both `require('./generate-sitemap.js').getPoolType` — the
comment in `generate-llms.js` literally calls it *"the one classifier"*. So items 175/180/181/184's
link-integrity gates and the daily `audit-app.js` `link-target-integrity` check were asking the fork whether
the fork's own output was right, and getting "yes". This is the fourth time this loop has hit that shape (166,
183, 185) — **a checker that inherits the bug it exists to catch**.

## What changed, in reading order

**1. `generate-sitemap.js` — the fork is gone (Leg A).**
The 15-line local classifier is deleted. In its place, `extractGetPoolTypeShared()` reads `PoolDetail.js`,
slices from `const LENDING_PROTOCOLS` through the close of `function getPoolTypeShared`, and evaluates that
slice in a bare `vm` context — the same anchor-slice-evaluate pattern item 084 established for extracting
app.js's real NL parser into tests. The slice references only `String`/`Array` builtins and the five list
constants it declares itself (verified), so it runs cleanly outside a browser.

The extraction happens **at require time** (`const _getPoolTypeShared = extractGetPoolTypeShared();`) and
`getPoolType(pool)` becomes a one-line delegation. Name, signature and export are unchanged, which is why the
three downstream consumers needed **zero call-site edits** and picked up the correction for free.

On any failure — missing file, moved anchor, unparseable slice, non-function result — it **throws** a named,
actionable Error rather than falling back. That is deliberate: a silent fallback is exactly how the fork
survived undetected, and a loudly red SEO pipeline is strictly better than three checkers quietly re-adopting
a wrong taxonomy. It mirrors the posture this file already has toward a failed DefiLlama fetch.

**2. `generate-sitemap.js` — the taxonomy is complete (Leg B).**
`categories` and `categoryUrlMap` go from four entries to the product's six (`app.js:114-121`'s
`CATEGORY_TABS`), adding `RWA` and `Yield Derivatives` → `Yield%20Derivatives`. Filename derivation, index
entry and `cleanupStaleSitemaps()` were already generic over the written-filename list — verified, not
rewritten. Item 013's quality gate is untouched, so a new category file only appears once a token genuinely
clears ≥2 qualifying pools in it.

**3. `test_sitemap_category_urls.js` (new) — the gate.**
Rendered Playwright (fixture-routed, `test_pool_type_badge.js` harness, port 8866) proving the dead URL is
genuinely dead in the product and that every URL the generator emits for the fixture renders ≥2 cards, plus
Node-level gates for classifier agreement, the throw-don't-fall-back behaviour, and the emitted URL set.
Registered in `package.json`'s `test:serial` after `test_sitemap_filter_urls.js`.

**4. Regenerated SEO artifacts (Leg C).** `npm run sitemap && npm run generate:llms` against live DefiLlama;
never hand-edited.

## The numbers, before → after

| | before | after |
|---|---|---|
| classifier disagreement vs the product | 90/736 (12.2%) | **0/736** |
| category URLs published | 114 | **117** |
| …rendering 0 pools | **8** | **0** |
| …rendering 1 pool (gate promises ≥2) | 3 | **0** (live population) |
| pools in a category with no sitemap file | 41 | **0** |
| per category | L36 · S1 · LP13 · YF64 | L38 · S2 · LP20+1 · YF49 · RWA3 · YD4 |

Fifteen Yield-Farming URLs were removed: **9 moved** to their honest category (WBETH → Staking, SAVAX →
Lending, XMR/BEAT/ECR → LP/DEX, USDY/OUSG/USDAI/SIERRA → RWA or LP/DEX) and **6** (OSETH, RLUSD, SDAI, SOL,
SUSDS, USDS) fell below the ≥2 gate in their honest category — each verified still present in
`sitemap-tokens-all.xml`, so nothing is de-indexed; net published URLs **rose by 3**.

## Deviations from the spec

- The rendered test uses a fixture token (`GOLDX`) rather than the literal symbols the spec sketched: `ondo`
  and `pendle` are *project* names, not pool symbols. `WBETH` is used verbatim as specified. Recorded in
  `189-notes.md`.
- `extractGetPoolTypeShared` is exported un-cached (the module-scope constant holds the single production
  extraction) so the failure path can be exercised against scratch files without disturbing the real one.
- One URL (`?token=LUNC&poolTypes=LP%2FDEX`) reads "thin" against the committed snapshot and fine against the
  live population — the snapshot is ~6h older than the data the generator ran on. Reconciled independently by
  both the builder and the verifier against a fresh 15,873-pool fetch; population drift, not a defect.
