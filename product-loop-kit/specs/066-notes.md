## Deviations from spec
- Spec says "Reuse the existing rate/blend helpers" without naming one; picked `planner.js`'s `blendedApy` (median of `poolTotalApy` across the token's displayed pools) over the page's pre-existing `bestApy = Math.max(...)` because `blendedApy` is the literal function name/concept the rest of the product calls "blended," and median (not max) matches CLAUDE.md's "honest numbers beat exciting numbers" — a max-based headline would be the single best pool on the page, not a representative blended rate.
- Spec's open question suggested the v2/v3-doc "everyday-bills" ladder (Spotify → Netflix → Claude Pro → Gym → Phone bill) as a possible anchor set if one subscription needed picking. The SHIPPED `SUBSCRIPTION_LADDER` in `planner.js` doesn't contain Gym/Phone bill (it has spotify/netflix/claude/chatgpt/amazonprime — apparently drifted from that doc already, pre-existing and out of scope to reconcile here). Anchored the headline to the `claude` entry specifically (not the full ladder) — one number per page, matching NORTH_STAR's business-model framing ("$23/mo yield → Claude sub") and `generate-spotlight.js`'s own existing `DEFAULT_GOAL_ID = 'claude'` precedent, rather than inventing a per-page ladder-selection heuristic the spec didn't ask for.
- Placed the headline between the intro paragraph and the CTA button (still strictly "above the table" per the acceptance criterion) rather than immediately after the H1 — the H1-adjacent slot is already the 047 direct-answer block (a distinct SEO/GEO-purpose sentence); stacking two "answer-shaped" paragraphs back-to-back there would clutter the top of the page, whereas the yield headline naturally leads into the CTA button right below it.
- Chain pages (`generate-chain-pages.js`) intentionally untouched — spec explicitly scopes this to token pages only ("token-first this pass").
