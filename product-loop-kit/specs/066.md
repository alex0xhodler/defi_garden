# Spec 066: Honest "what your idle <TOKEN> could earn" headline (token pages + spotlight packs)

## Evidence
- Traffic is decaying (session_start daily 167→80→80→21, 2026-07-13); the 2,131 static SEO token/chain pages are the largest latent traffic asset but currently pitch a bare pool table. `/tokens/*` page_view = 0 (GSC 2–6wk indexing just begun) — when it lands, the pitch on those pages is what converts toward the card.
- North star = `waitlist_submitted` (card funnel); the card pitch is "your idle capital's yield pays a subscription." Today no page states the single honest number that makes that pitch concrete per token.
- 058 STUDY decided: NO backend — one number must derive from the single client-side `/pools` fetch through the existing trust rails (`APY_SANITY_LIMIT=1000%`, `DEFAULT_MIN_TVL=$10M`, degen ⅓ haircut). Ties the 058 direction to conversion without reversing the no-backend tenet.

## Hypothesis
We believe a single honest per-token headline ("Your idle <TOKEN> could earn ~X% — enough to run a $Y/mo sub, forever") on token pages and in the spotlight pack will strengthen the card pitch and give the SEO→waitlist bridge (062) a reason-to-act, because the forever-number frame is the product's front door (NORTH_STAR standing decisions) and the number is already computable from live data. Confidence: guess (no traffic yet to measure lift; ship measurable, decide later).

## Change
- Compute one blended headline number per token from the same live `/pools` data the generator already fetches, through the trust rails (min-TVL floor, sanity limit; anomalous pools excluded, never surfaced). Reuse the existing rate/blend helpers — do NOT invent a new calc path.
- Render it as a headline on `/tokens/<slug>` pages (above the table) and expose the same field in `generate-spotlight.js`'s Canva field pack. EN + KO via translations.js.
- Honest framing only: "could earn ~X%" from live blended rate; if a token has no qualifying pool, show nothing (no fabricated number). No fake availability of the card.
- OUT of scope: chain pages (token-first this pass), any backend/stored history, the card itself.

## Acceptance criteria
- [ ] Headline number derives ONLY from live `/pools` through the trust rails (min-TVL, sanity limit, anomaly exclusion) — verifiable in the generator; anomalous/low-TVL pools cannot influence it
- [ ] Tokens with no qualifying pool render NO headline (no zero/NaN/fabricated value)
- [ ] Both EN and KO strings present in translations.js (one language alone = FAIL); money/number formatting pinned en-US (formatApy/formatUsd)
- [ ] `generate-spotlight.js` pack exposes the same field
- [ ] Tests: `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` exit 0; token-page generator test exits 0; regenerated `stories/`/token output committed if the generator changed
- [ ] Instrumentation: no new event needed; the headline lives on already-instrumented (039/044) `/tokens/*` pages whose `page_view` will read via GSC-driven traffic

## Measurement
Metric: `page_view` → `waitlist_opened(source=seo_token)` on token pages carrying the headline, pre/post over 14 days once organic traffic exists. Decision rule: keep if it doesn't reduce the SEO→waitlist rate; the honest-pitch value is qualitative until traffic. Minimum sample ≥30 (NORTH_STAR.md) — until then, insufficient data.

## Risk tier (builder's guess — verifier assigns independently)
HIGH — touches the trust-rail-derived numbers on the sacred SEO surface + a generator that regenerates SEO pages; EN+KO copy. Any weakening of the min-TVL/sanity/anomaly filters in service of a bigger headline number = automatic FAIL.

## Open questions
None blocking — the headline is a display of an already-approved calc. If the "$Y/mo sub" pairing needs a specific subscription anchor set, reuse the existing everyday-bills set (Spotify→Netflix→Claude Pro→Gym→Phone bill) from the v3 spec.
