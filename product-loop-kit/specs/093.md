# 093 — SOTA nav-rail IA: primary category rail + secondary filter cluster

**Status:** IN_PROGRESS (2026-07-14) · **Score:** 6.5 · **Risk:** HIGH (analytics render path, user-facing beyond copy/styling; verifier confirms tier)
**Source:** Analytics-UX audit (human directive 2026-07-14). Presentation layer of the nav; consumes 091's expanded category taxonomy.

## Problem (documented evidence)

The analytics app's sticky-header nav row renders **one undifferentiated horizontal strip** that mixes two semantically different control types:

- **Primary category tabs** (`.google-nav-tab`, data-driven from `CATEGORY_TABS`): All / Lending / Staking / LP·DEX / RWA / Yield Derivatives — these *switch what you're browsing*.
- **Secondary filter buttons** (`.google-filter-btn`): Chains / TVL / Protocols / APY — these *narrow the current browse* via dropdowns.

Both live as flat siblings inside a single `.google-nav-tabs` flex container (`app.js` render block, `.google-nav-row`). Nothing signals that the first group is "what am I looking at" and the second is "how is it filtered." That's a state-vs-action IA smell on the app's most-used control surface.

Two secondary defects surface in the same code:
1. The four filter-button labels (`'Chains'`, `'TVL'`, `'Protocols'`, `'APY'`) are **hardcoded English** — a latent violation of the CLAUDE.md hard rule "every user-facing string goes through translations.js" (same class 091 fixed for the category tabs). Restructuring the secondary cluster with "EN+KO" in the item scope is the moment to fix this.
2. No iconography — the strip is text-only, below the SOTA bar the audit is targeting.

## Goal

Restructure the flat strip into a **clear primary category rail + a visually separated secondary filter cluster**, add **consistent monochrome (currentColor) neuro iconography** to both tab and filter controls, keep the header **sticky-on-scroll**, keep **active states unambiguous** with the existing press physics, and route the filter labels through **EN+KO** translations.

Non-goals (explicitly out of scope — do NOT touch):
- Category taxonomy / classification logic (`getPoolType`, `CATEGORY_TABS` keys) — 091 owns that; only add a per-entry `icon`.
- Filter dropdown *contents* / behavior, the `activeDropdown` state machine, or dropdown positioning.
- Trust rails, sort order, which pools render, the `__APP_MODE` router, `?token=/?chain=/?pool=` semantics.
- The planner. This is `app.js` (analytics) only.

## Territory notes (from code audit, before writing)

- Render site: `app.js` `.google-nav-row` block → `.google-nav-tabs` holds category tabs (`...CATEGORY_TABS.map(...)`) then the four `.google-filter-btn` buttons, then a sibling `.google-tools-section > .google-results-count`.
- `CATEGORY_TABS` is defined at `app.js:95` as `[{ key, labelKey }, ...]`.
- **Dropdowns position via element ID**: `document.getElementById('chains-btn'|'tvl-btn'|'protocols-btn'|'apy-btn').getBoundingClientRect()`. The four filter buttons carry `id="chains-btn"` etc. → **these IDs MUST be preserved verbatim** or every dropdown mis-positions. Do not rename them.
- **Class names `.google-nav-tab` and `.google-filter-btn` MUST be preserved** — the global press-physics rule (`style.css` ~4974: `.google-nav-tab:active, .google-filter-btn:active { translateY(1px) + --neuro-shadow-pressed }`) and the hover-elevation rule (~4992) key off them, and `test_category_taxonomy.js` / `test_default_sort.js` query `.google-nav-tab`. Reuse, don't rename — restructure by *wrapping*, not by re-classing.
- The header is already `position: fixed` (`.google-header-sticky`, `style.css:905`) → sticky-on-scroll already holds structurally; the restructure must not regress it.
- Existing dark-mode + 360/768/1280 rules live in `style.css` (mobile block ~1683). `.google-nav-tabs` is `overflow-x: auto; scrollbar-width: none; flex: 1` — horizontal scroll on narrow viewports is the established pattern (tabs scroll, never wrap). Preserve it.
- The compiled/minified pipeline ships to the browser: after editing `app.js` run `npm run compile` (→ `app.compiled.js`) then `npm run minify` (→ `app.compiled.min.js`, `translations.min.js`, `style.min.css`). `home.html` loads the `.min` assets — the rendered test won't see source edits until both run.

## Design (prescriptive)

### DOM restructure (`app.js`, inside `.google-nav-row`)
Keep `.google-nav-tabs` as the **outer horizontal-scroll container** (unchanged class → keeps scroll + fade behavior). Inside it, wrap the two control groups and insert a divider:

```
.google-nav-tabs                (unchanged: flex, overflow-x:auto, flex:1)
  .google-nav-primary           (NEW group: display:flex, align-items:center, gap)
    button.google-nav-tab       (unchanged class, now with leading icon)  × N categories
  span.google-nav-divider       (NEW: vertical hairline, aria-hidden)
  .google-nav-secondary         (NEW group: display:flex, align-items:center, gap)
    button.google-filter-btn#chains-btn   (unchanged class + id, now with leading icon)
    button.google-filter-btn#tvl-btn
    button.google-filter-btn#protocols-btn
    button.google-filter-btn#apy-btn
```

`.google-tools-section > .google-results-count` stays as the `.google-nav-row`'s second child (unchanged).

### Iconography (consistent, monochrome, currentColor)
Add **inline SVG** icons (NOT emoji — emoji are multicolor and read off-brand against the neuro system). One shared helper renders a 16×16 `<svg>` with `aria-hidden="true"`, `fill="none"` or `currentColor` as the glyph needs, `stroke="currentColor"`, `stroke-width` ~1.8, so the glyph **inherits the control's text color** — inactive tab = `--color-text-secondary`, active tab = `--color-primary`, has-selection filter = white. This makes the active state carry through the icon automatically (unambiguous active state, requirement met with zero extra state code).

- Add an `icon` field to each `CATEGORY_TABS` entry (a short key into a `NAV_ICONS` map): all, lending, staking, lpdex, rwa, yieldderiv.
- Map the four filters to icons: chains, tvl, protocols, apy.
- Icons are Lucide-style simple line glyphs (pick recognizable ones — e.g. grid/all, coins/lending, layers/staking, arrow-swap/lpdex, building/rwa, trending-up/yieldderiv, link/chains, database/tvl, box/protocols, percent/apy). Keep each path compact.
- Wrap label text in a `<span class="google-nav-label">` so icon+label align; the button becomes `[svg icon][label span]`.

### Visual separation (`style.css`)
- `.google-nav-primary`, `.google-nav-secondary`: `display:flex; align-items:center; gap: var(--space-4)` (primary) / `var(--space-8)` (secondary); `flex-shrink:0`.
- `.google-nav-divider`: a `1px` wide, ~`20px` tall element, `background: var(--color-border)`, `margin: 0 var(--space-12)`, `flex-shrink:0`, `align-self:center`. This is the primary/secondary boundary.
- Because the divider now provides separation, **remove the `margin-left: var(--space-8)` from `.google-filter-btn`** (it was the old ad-hoc gap) and let the `.google-nav-secondary` `gap` space them. Verify the first filter button no longer double-spaces.
- Icon inside button: `.google-nav-tab svg, .google-filter-btn svg { width:16px; height:16px; flex-shrink:0; }`, and give the buttons `display:inline-flex; align-items:center; gap: var(--space-6)` so icon+label sit inline. (`.google-nav-tab` currently has no display set — add inline-flex; keep its underline active style.)
- Mobile (≤ the existing breakpoint): the divider + groups must survive; icons may shrink slightly but keep the strip single-row, horizontally scrollable. Add rules to the existing mobile block so nothing wraps and both groups + divider remain in the DOM at 360px.
- Dark mode: all colors come from tokens (`--color-border`, `--color-text-secondary`, `--color-primary`, `--color-surface`) → dark mode inherits automatically; verify divider is visible (not invisible) in dark.

### Translations (`translations.js`, EN + natural KO together)
Add keys and use them for the filter labels (preserve the dynamic selected-state labels, only the default falls back to `t()`):
- `navFilterChains`: EN "Chains" / KO "체인"
- `navFilterTvl`: EN "TVL" / KO "TVL" (acronym, unchanged — standard in KO DeFi)
- `navFilterProtocols`: EN "Protocols" / KO "프로토콜"
- `navFilterApy`: EN "APY" / KO "APY" (acronym, unchanged)

Render sites become e.g. `selectedChain || t('navFilterChains')`, `minTvl > 0 ? (…existing…) : t('navFilterTvl')`, `selectedProtocols.length > 0 ? (…existing…) : t('navFilterProtocols')`, `minApy > 0 ? (…existing…) : t('navFilterApy')`. Do NOT change the selected-state label formatting (money/number pinned en-US stays as-is).

### Press physics / active states (reuse, do not reinvent)
- Category-tab active = existing underline + `--color-primary` (icon now inherits it too). Filter `has-selection`/`active` states unchanged. The global `:active` press rule already lists both classes → since class names are preserved, press physics carries through untouched. Do not add new active-state CSS beyond what's needed for icon alignment.

## Acceptance criteria (rendered product behavior — Playwright on the real UI, per NORTH_STAR 2026-07-11)

New test `test_nav_rail_ia.js` (model on `test_category_taxonomy.js` harness verbatim: local static server for `home.html`, `page.route` fixtures for unpkg React/Babel + a stale `data/pools-snapshot*` stub + `https://yields.llama.fi/pools` fixture, `IGNORABLE_ERROR_PATTERN`, `/opt/pw-browsers/chromium` executable). Fixture = a few pools on chain Base spanning ≥2 categories so tabs are meaningful. Load `http://localhost:PORT/?chain=Base`. Assertions:

1. **Grouping renders**: exactly one `.google-nav-primary` and one `.google-nav-secondary` exist, with a `.google-nav-divider` between them in DOM order (primary before divider before secondary).
2. **Primary rail holds only category tabs**: every `.google-nav-tab` is a descendant of `.google-nav-primary`; zero `.google-filter-btn` inside `.google-nav-primary`.
3. **Secondary cluster holds only filters**: the four buttons `#chains-btn #tvl-btn #protocols-btn #apy-btn` all exist, are descendants of `.google-nav-secondary`, and carry the preserved IDs.
4. **Icons render**: every `.google-nav-tab` and every `.google-filter-btn` contains an inline `<svg>` child.
5. **Active state is unambiguous**: after clicking a specific category tab (e.g. the one whose fixture pool is unique), exactly that tab has class `active` and no other `.google-nav-tab` does; grid filters to that category's pool(s) (proves the restructure didn't break wiring).
6. **Dropdown still positions off its button**: clicking `#chains-btn` opens `.global-filter-dropdown` (proves the preserved IDs still drive positioning); its computed `left` is within a few px of `#chains-btn`'s `getBoundingClientRect().left`.
7. **Filter labels are translated**: with `?chain=Base&lang=ko` (or toggling KO), the default (unselected) Chains/Protocols filter labels read the KO strings (`체인` / `프로토콜`), proving they route through `t()` not hardcoded English. (TVL/APY stay acronyms by design — assert they are NOT the literal lowercase/hardcoded English-only path by checking they come from `t()`; simplest: assert Chains label === `체인` in KO.)
8. **Sticky-on-scroll holds**: after scrolling the results, `.google-header-sticky` (containing the nav) still has its top edge at/near viewport top (getBoundingClientRect().top ≈ 0) — i.e. it stayed fixed.
9. **360px survives**: at 360×780 the primary rail, divider, and all four filters still exist in the DOM (single row, horizontally scrollable — they may be off-screen but present), zero layout error.
10. **Zero non-ignorable page errors** across the run.

Plus: existing `npm test` chain stays green (esp. `test_category_taxonomy.js`, `test_default_sort.js`, `test_list_default.js`, `test_smoke.js`, `test_compiled_assets.js`, `test_minified_assets.js`, `test_css_minified_render.js`) — restructure must not regress them. Recompile + reminify committed in the same commit.
