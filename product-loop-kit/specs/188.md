## The finding

`generate-sitemap.js:430-431` publishes **seven hardcoded filter URLs** into `sitemap-main.xml`
(priority 0.5, changefreq daily), with no liveness check of any kind:

```
?minTvl=1000000   ?minTvl=10000000   ?minTvl=100000000
?minApy=5   ?minApy=10   ?minApy=20   ?minApy=50
```

**None of them can ever render a pool grid.** Proven in code, not inferred: `app.js:2010-2013` —

```js
// Token-first mode: existing logic
if (!selectedToken) {
  setFilteredPools([]);
  return;
}
```

`minTvl`/`minApy` are *secondary* filters, applied only on top of a token or a chain-first selection.
A filter-only query never reaches a branch that populates `filteredPools`, so the page renders the
analytics app's empty search hero — the same content as `/`, on every one of the seven URLs.

Measured this run, rendered Chromium against **live DefiLlama** (15,878 pools) routed into the page
(browser-originated HTTPS is proxy-blocked in-sandbox — house fixture-routing pattern, NORTH_STAR
2026-07-12):

| URL submitted today | pool cards | results | `<meta robots>` | canonical |
|---|---|---|---|---|
| `?minTvl=1000000` | **0** | — | `index, follow` | self |
| `?minApy=5` | **0** | — | `index, follow` | self |
| `?minApy=50` | **0** | — | `index, follow` | self |

So they are **indexable near-duplicates of the homepage**, self-canonicalising to seven distinct
URLs (`canonical.js` normalises `minTvl`/`minApy` into `CANONICAL_PARAMS`, so each one claims to be
its own page). That is the *"Duplicate without user-selected canonical"* / thin-content class item
010's GSC diagnosis was opened for and 011–013 exist to drain — and 013's own quality gate
(`SITEMAP_MIN_QUALIFYING_POOLS = 2`, `generate-sitemap.js:29`) was only ever wired to the
token / token+chain / token+category families. This hardcoded block was never gated. Same shape as
`playbooks/detector-signal-coverage.md`: the gate scoped to the family that was broken at the time.

**The same list is the AI-discovery surface's "High-Value Filter Pages" section.** `generate-llms.js`
categorises the sitemap URLs (`:185`) and `buildFull()` (`:716`) emits them under
*"TL;DR: Filtered views for minimum TVL and APY thresholds"* — a claim no one of them satisfies.
`audit-app.js` flags one of them as its **only blocking P1** this tick (exit 1):

> `llms-full.txt`: 1 defi.garden grid link resolves to ZERO pools in the $10,000,000 snapshot at its
> effective floor — e.g. `https://www.defi.garden/?minApy=50`

Live confirmation: 15,878 pools → 548 clear the $10M floor + anomaly rail → **0** of them reach 50%
APY. Item 180's R3 repair ladder exists for exactly this, but is applied to exactly one hardcoded
URL (`applyLinkIntegrityGate`, `generate-llms.js:1090` — the concise file's "High APY staking" line);
the generated `categories.highValue` inventory in `buildFull()` bypasses it entirely.

## The fix — publish the URLs that work, gate the ones that can't

The app **already has** a token-less browse mode that renders a real grid: chain-first with
`chain=All` (`app.js:1837`). Reuse it (standing decision 2026-07-10, reuse before inventing) rather
than teaching `app.js` a new filter-only render path. Measured, same run, same live population:

| proposed URL | pool cards | results | robots |
|---|---|---|---|
| `?chain=All&minTvl=1000000` | 9 | 2,603 results | `index, follow` |
| `?chain=All` *(the $10M rung — see note)* | 9 | 738 results | `index, follow` |
| `?chain=All&minTvl=100000000` | 9 | 158 results | `index, follow` |
| `?chain=All&minApy=5` | 9 | 137 results | `index, follow` |
| `?chain=All&minApy=10` | 9 | 31 results | `index, follow` |
| `?chain=All&minApy=20` | 9 | 9 results | `index, follow` |
| `?chain=All&minApy=50` | 0 | **0 results** | **`noindex`** |

Two facts that decide the design:

1. **The `minTvl=10000000` rung normalises to `?chain=All`.** The app's own `updateUrl()` omits a
   `minTvl` equal to the default, so loading `?chain=All&minTvl=10000000` rewrites the address bar
   to `?chain=All`. Emit `?chain=All` for that rung — the app's own normalised form — so the
   submitted URL, the address bar and the canonical agree. (`?chain=All` is **not** in the sitemap
   today; grep-confirmed 0 occurrences.)
2. **`?chain=All&minApy=50` self-`noindex`es** (item 012's honest empty state fires correctly once
   the query actually resolves). Submitting it would manufacture a *"Submitted URL marked
   'noindex'"* GSC error — so the liveness gate is not optional, it is what makes leg A safe.

### Leg A — `generate-sitemap.js`
Replace the two unconditional `forEach` pushes at `:430-431` with gated emission of the chain-first
equivalents. A rung earns its `<loc>` only when **≥ `SITEMAP_MIN_QUALIFYING_POOLS` (2)** pools clear
that URL's *own* effective filter, computed with the app's semantics:

- floor = explicit `minTvl` when present, else `SITEMAP_MIN_TVL` ($10M) — mirrors `app.js:927`
  ("Respect explicit minTvl=0; fall back to DEFAULT_MIN_TVL only when param is absent");
- APY = **`apyBase + apyReward`**, matching `app.js:1869-1871`/`:1958-1960` — NOT the raw `apy`
  field. (These differ: `apy ≥ 5` counts 145 pools, the app shows 137. A gate written against `apy`
  would be measuring a different page than the one it publishes.)
- the existing anomaly rail (`APY_SANITY_LIMIT`, `tvlUsd > 0`) — reuse `isQualifyingPool()` where
  its semantics already match; do not duplicate the rail constants.

Today that emits six URLs and drops `minApy=50`. The gate is re-evaluated on every daily CI run, so
it tracks the market rather than hardcoding today's answer.

### Leg B — `generate-llms.js`
`buildFull()` emits `## Token Pages`, `## Chain Pages`, `## Pool Type Pages`,
`## High-Value Filter Pages` with an unconditional heading + TL;DR, while `## Other Pages` right
below them (`:721`) is already guarded by `if (categories.other.length > 0)`. Apply that same
existing guard to the four unguarded sections. This is **required for leg A's correctness**, not a
drive-by: once the filter list is gated it can legitimately empty out, and a heading promising
"Filtered views" above nothing is the same false claim in a new costume. It also fixes a defect
live in the shipped artifact today — `llms-full.txt:456-457` ships `## Pool Type Pages` +
*"TL;DR: Strategy-based categorization"* with **zero** links under it (no `?poolTypes=` URL exists
in the sitemap at all).

### Regenerate, never hand-edit
`npm run sitemap && npm run generate:llms` — commit the regenerated `sitemap-*.xml`, `llms.txt`,
`llms-full.txt`. Hand-editing generated SEO surface is a NORTH_STAR HIGH-risk violation.

## Not the NEVER list — stated, not assumed
NORTH_STAR's NEVER list includes *"deleting or de-indexing SEO surface."* This item **deletes
nothing and de-indexes nothing**: the seven bare URLs keep serving exactly what they serve today
(nothing about `app.js`, `home.html`, `vercel.json` or any route changes), they keep their
self-referential canonical, and no `noindex` is added to any page that lacks one. What changes is
which URLs we *submit* — seven duplicates-of-`/` are replaced by six URLs that render real,
distinct, pool-bearing content. That is item 013's stated purpose ("sitemap quality threshold —
≥2 live pools per URL") and matches the precedent the human resolved for item 148 (junk token slugs
dropped from the sitemap as quality work, shipped). Trust rails are untouched: `APY_SANITY_LIMIT`,
`DEFAULT_MIN_TVL`, anomaly flags, degen haircut — no diff. **The verifier judges this
independently; if it reads the diff as NEVER-list, the PR stays open and the item is BLOCKED.**

### Leg C — the link simulators must agree with the app about `chain=All` (found by the operator mid-build, 2026-07-31)

**This is not optional and not a follow-up: without it leg A ships URLs the repo's own checkers call
dead.** Both grid-link simulators match the chain param **literally**:

- `generate-llms.js:878` — `if (chain && p.chain !== chain) continue;`
- `audit-app.js:1038` — `if (chain && p.chain !== chain) continue;`

No pool has `chain === 'All'`, so every `?chain=All&…` URL simulates to **0 pools**. Two concrete
consequences, both regressions caused by leg A if leg C is skipped:

1. 180's R2 `applyChainRetarget()` (`generate-llms.js:904`) would classify each new URL as dead,
   look for `/chains/all` in the sitemap, not find it, and **omit the URL entirely** from
   `## Chain Pages` — the AI surface would silently lose exactly the links this item adds. Enough
   of them at once could also trip the structural tripwire and disable 180's whole gate.
2. `audit-app.js`'s level-3 `link-target-integrity` check would raise a **new blocking P1** per URL —
   turning an item that clears the audit's only blocker into one that multiplies it.

Fix: teach both simulators the wildcard the app has had all along — `app.js:1841`,
`chainMatch = selectedChain === 'All' || …`. `All` needs no lookup table: it matches every pool.
Make the change in both files, minimally, with a comment naming `app.js:1841` as the source of truth.

`chain=Popular` (`app.js:1838`'s 15-chain list) is the sibling case. **Do not duplicate that list
into two more files.** Instead: `grep -rn "chain=Popular" sitemap-*.xml llms*.txt tokens/ chains/
stories/` — if the count is 0, the case is dormant; record it in the notes as a known, deliberately
unfixed gap with the grep output as evidence (`playbooks/detector-signal-coverage.md`'s
dormant-vs-live decision rule, item 186's precedent), and state that a future `?chain=Popular` link
would be mis-flagged dead. If the count is NOT 0, it is live — handle it and say how.
