# 166 — PR explainer: the merge gate could report green without running anything

Written before merge, per the ship policy. **HIGH lane** — full walkthrough + 5-question quiz. The
tier was independently assigned HIGH by the verifier on diff size (226 new LOC vs the 150-line LOW
cap), correcting the spec author's LOW proposal; see `specs/166.md` § Risk tier.

## The goal, in one sentence

`run-tests.js --only=<name>` accepted names that matched no file, selected zero files, and exited
**0** — so a typo made the automated half of the merge gate report success while running nothing.

## The intuition

The autonomy decision this loop ships under (2026-07-10, ratcheted to (c)) is *"verifier PASS +
**tests green** → merge to main, ANY tier."* Item 163 built `run-tests.js` precisely so that "tests
green" would stop being a claim and start being a checkable fact — before it, `npm test` was 94
`node <file>.js` steps joined by `&&`, which died on the first red and had never been observed past
position 12.

But `run-tests.js` shipped with a hole its own notes recorded and its own spec declined to fix:

> `specs/163-notes.md:294-295` — *"`--only=<name>` that matches zero files exits 0 rather than
> erroring — a typo could silently report a 'passing' empty run."*

The unfixed half matters more than it sounds, because the loop leans on `--only` constantly. The
full browser lane (63 files) exceeds every session's 5-minute foreground timebox, so builders and
verifiers run targeted subsets instead — `165-notes.md`, `163-notes.md` and `162-notes.md` all
record exactly that, and their green subsets are the merge evidence. A flag that can silently
select nothing is a flag that can silently manufacture that evidence.

Two shapes, the second worse than the one the notes described:

1. **Total typo** — `--only=test_pool_detail_anomly_projection.js`: `0 file(s) selected`,
   `TOTAL pass=0 fail=0 timeout=0 total=0`, exit 0. Reads as green.
2. **Partial typo** — `--only=test_planner.js,test_typo.js`: one file runs, passes, exit 0, summary
   says `total=1`. You asked for two files and were told nothing about the second. This is the
   dangerous one, because the run *looks* like it did work.

## What changed, and why

Two guards and one pure helper in `run-tests.js`; everything else is the regression tests.

**1. `unknownOnlyNames(only, allFiles)` (`run-tests.js:162-181`)** — pure, no I/O, returns the
entries of `only` absent from `allFiles`, in input order, duplicates collapsed. Exported so the
tests can assert it directly rather than only through the CLI.

**2. Guard 1 — unknown names (`run-tests.js:322-333`)**, placed immediately after `allFiles` is
resolved and **before both** the `--list` branch and the `node_modules` preflight:

```
run-tests.js: --only names 1 file(s) not found in the test:serial chain: test_typo.js — run with --list to see valid file names.
```
exit **2**. The position is deliberate on both counts. Before `--list`, because `--list` is exactly
where someone checks a name and silently listing nothing is the same lie in a quieter voice. Before
the preflight, because a typo is an operator error a fresh clone with no `node_modules` must still
be told about.

**3. Guard 2 — zero files selected in RUN mode (`run-tests.js:362-369`)**, after lane+only
filtering:

```
run-tests.js: 0 file(s) selected (lane=plain, only=test_min_asset_boot.js) — a zero-file run is not a pass.
```
exit **2**. Guard 1 cannot cover this: every name is *valid*, they were just filtered out by
`--lane`. It sits before the `N file(s) selected` log line so nothing misleading is printed first.

Exit **2** on both, matching the existing preflight convention (`2` = cannot run / operator error);
exit `1` stays reserved for "tests actually failed or timed out". `--list` keeps exiting 0 when the
*filters* legitimately narrow to nothing — introspection is allowed to be empty; a *run* is not.

## Two things found while building that are worth more than the fix

**A fork bomb with no base case.** The obvious way to write the A2 test is
`--only=test_run_tests.js,test_typo.js` — one real file, one typo. But if either guard is missing or
broken, `run-tests.js` then actually *runs* `test_run_tests.js`, which contains that same assertion,
which spawns another copy, forever. A `spawnSync` timeout kills only its direct child, not the
descendants that child already spawned; dozens of orphaned processes were observed from a single
run. The shipped tests use `test_protocol_parsing.js` as the valid entry instead — semantically
identical, recursion-safe no matter what state the guards are in.

**Two guards that share an exit code can mask each other's absence.** With guard 1 disabled,
`--only=test_typo.js` still exits 2 — guard 2 fires instead, and its message *also* echoes the
filename. An assertion checking "exit 2, and the name appears somewhere in stderr" therefore stays
green with guard 1 completely removed. That draft assertion existed, and the mutation run caught it:
one red instead of three. A1 now anchors on `not found in the test:serial chain` — wording guard 2
never produces — and mutation 1 turns A1, A2 and A6 red. This is the whole reason the non-vacuity
step is mandatory: the fix was always right, but the evidence for it wasn't.

## Deviations from the spec

None on the design. One in the tests: the spec's acceptance table shows `--only=test_run_tests.js`
as the "valid" entry for A2/A4; those literal commands were run manually and pass, but the embedded
regression assertions substitute `test_protocol_parsing.js` for the recursion reason above. Full
detail in `specs/166-notes.md`.

Also disclosed there, in an operator addendum: the loop operator edited the working tree mid-run
believing the build agent had stalled. It changed no shipped byte — but it is what produced the
mask-detection above, and it's a process error recorded rather than quietly dropped.

## Verification

`30/30` assertions in `test_run_tests.js`, exit 0. Full plain lane `34 pass / 0 fail / 0 timeout` in
~7.5s. Both guards proven load-bearing by independent mutation cycles (builder's and verifier's),
each restored to a byte-identical tree afterwards. Browser lane not run — 63 files, exceeds the
5-minute timebox; it is stated as unrun, not implied green.
