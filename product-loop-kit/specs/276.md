# Spec 276: the occlusion lens cannot see one overlay occluding another overlay's content

Impact: defect-count 1→0 on the occlusion-lens detector class (audit-app.js); guardrail (item 273's own P0 shape, re-opened as a class)

## Evidence

`audit-app.js`'s victim scan (`occlusionPassEval`) skipped any element that was itself
fixed/sticky, and any element contained by ANY detected overlay — a blanket exclusion, not a
per-overlay-pair one. Item 273 found the live instance: on `pool-detail-360` (an audited surface,
lens green) `.language-toggle` (`position:fixed`) landed on `.app-search-input` — 1036.3px² at
360×780 — invisible to the lens because `.app-search-input` lives inside `.app-header-sticky`,
itself an overlay (`specs/273-notes.md` "Instrument gap"). Population: every audited surface
rendering a fixed/sticky container with interactive content — 8+ surface-viewport pairs
(grid-360/768/1280, pool-detail-360/-dark/-ko, planner, landing).

## Hypothesis

We believe replacing the blanket skip with a per-PAIR test (skip only when THAT overlay contains
the victim, keeping the legitimate self-containment exemption) closes this instance of the class
without opening false positives on legitimately-nested overlay content. Confidence: supported —
mechanically checkable, and empirically re-verified against every production surface below.
- Instance of: a detector whose exemption is wider than the mechanism it is meant to protect
  (RAZOR.md #5, the item 212 shape — a guard aimed at a resemblance).
- Class closed by this item: yes for THIS exemption (nested-victim-vs-sibling-overlay). The lens
  still exempts modal/scrim overlays ≥80% of viewport by design (unrelated, out of scope).

## Change

`audit-app.js` `occlusionPassEval`: removed the victim-side `position fixed/sticky -> always skip`
rule, and moved the `insideOverlay` check from a pre-filter (skips the candidate entirely) into
the per-overlay loop (`if (ov.el === vel || ov.el.contains(vel)) continue;` — skips only that one
pair). A fixed/sticky element can now be a victim, and a victim nested in overlay A is still
checked against every overlay B ≠ A. Out of scope: the 80%-viewport modal/scrim exclusion, the
two-position (at-rest/bottom-of-scroll) asymmetry, minCoverage/opacity gates — all unchanged.
