# 072 — Honest dead-`?pool=` empty state (HIGH-tier explainer)

## Goal
Close the last leg of the 012 "honest empty states" work: a `?pool=<id>` deep link whose pool
has left the live DefiLlama dataset used to render the FULL homepage grid under that dead URL —
no explanation, no signal to crawlers. To a human arriving from a shared garden, a token-page
pool row, or an X-spotlight, that's a silent bait-and-switch on the product's trust-first
surface; to Google it's the soft-404/duplicate mechanism the 010 diagnosis measured at 3,568
URLs (012 fixed the token/chain legs; `specs/012-pr.md` explicitly left this leg as a
"candidate for a future item"). Pool ids are the rot-prone unit — pools delist constantly, so
every deep link eventually dies.

## Intuition
Everything needed already existed from 012: the "resolved emptiness" flag pattern (never claim
dead while pools are still loading), the idempotent robots-meta effect, the alternatives
picker, and the empty-state UI classes. The fix is to give the dead-pool case its own flag and
route it through that same machinery — no new UI system, no new network calls, no new events.

## What changed and why (diff in reading order)
1. **`app.js` — `deadPoolParam` state (+1 line, ~785)**: string|null, the unresolved pool id.
2. **`app.js` — popstate handler (~932)**: URL drops the `pool` param → reset to null (back
   button out of a dead URL fully restores normal behavior).
3. **`app.js` — the `?pool=` effect (~1024/1035)**: `foundPool` → `setDeadPoolParam(null)`;
   miss with pools loaded → `setDeadPoolParam(urlParams.pool)`. The `Analytics.trackPoolView`
   call stays gated on `foundPool` only — `pool_view` never fires for dead ids (bot/crawler
   hits on rotted URLs can't pollute the funnel data).
4. **`app.js` — `deadPoolResolved` (~2067)**: `currentView !== 'pool-detail' && pools.length > 0
   && !!deadPoolParam` — same "only once the fetch resolved" rule as 012's
   `emptyStateResolved`, so the pre-fetch flash never claims a pool is gone.
5. **`app.js` — `deadPoolAlternatives` memo (~2095)**: `getEmptyStateAlternatives(null)` →
   top-TVL stablecoin pools already in memory, same trust rails (TVL floor), zero new fetches.
6. **`app.js` — robots effect (~2110)**: condition widened to `emptyStateResolved ||
   deadPoolResolved`. Same find-or-create single `meta[name=robots]` node; restores
   `index, follow` when neither holds (e.g. after clicking an alternative into a live pool).
7. **`app.js` — render (~2775, ~2843)**: results section also shows when `deadPoolResolved`
   (there are zero active filters on a dead-pool URL, so without this the grid of ALL pools
   renders); the grid ternary excludes it, so the `.empty-state` block renders instead, now
   branching FIRST on `deadPoolResolved` for `poolNotFoundTitle`/`poolNotFoundExplanation` +
   the alternatives grid. All existing 012 token/chain branches are gated `!deadPoolResolved`
   and render byte-identically when it's false.
8. **`translations.js` (+2 keys)**: `poolNotFoundTitle`, `poolNotFoundExplanation` — EN +
   natural KO together, placed next to the 012 empty-state keys.
9. **`app.compiled.js` / `app.compiled.min.js` / `translations.min.js`**: regenerated via
   `npm run compile && npm run minify` — home.html loads only the compiled/minified artifacts;
   without regen the change ships nowhere (061's caught-bug lesson). `style.min.css` and
   `PoolDetail.compiled.min.js` regenerated byte-identical, confirming zero CSS/PoolDetail
   change.
10. **`test_dead_pool.js`** (new) + **`package.json`** test-chain append: rendered-Playwright
    acceptance (fixture-routed `/pools`, test_search.js pattern): dead id → honest empty state
    + `noindex` + zero stray pool cards; alternatives above the $10M floor, click-through →
    pool detail + robots restored; valid `?pool=` NEVER noindexed (polled guardrail); KO
    strings; zero page errors; `?token=` path untouched. 5/5 green.
11. **Bookkeeping** (same commit, per docs-in-first-commit): `specs/072.md`,
    `specs/072-notes.md`, this file, BACKLOG row, LOG entry.

## Untouched, deliberately
Trust rails (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly flags, degen haircut), the
`__APP_MODE` router and canonical logic, PoolDetail.js, planner.js, all generators/SEO surface,
analytics events (nothing added, nothing removed). Dead-id handling inside an already-open
pool-detail view is out of scope per spec.

## Deviations from spec
None (builder's notes concur; verifier independently confirmed scope).
