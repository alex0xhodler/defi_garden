# 060 — X-spotlight pack generator (HIGH tier explainer)

## Goal
NORTH_STAR.md's 2026-07-12 distribution decision: the human posts weekly X/Twitter "protocol spotlights" (a pool's live yield + an example garden built on it, tagging a small, collaboration-keen protocol — Curve is the upper bound of "small") from a reusable Canva video template. The loop's job is to hand the human a per-pool data/copy/asset pack so they never have to hand-assemble numbers, links, or copy themselves: live numbers through the trust rails, a share link that actually rebuilds the spotlighted garden on open, a tweet draft, Canva field values, and a share-card PNG.

## Intuition
Two things had to be true for this pack to be honest and useful:
1. **The share link has to actually work for a specific pool.** Item 024 already shipped a working plan-share URL, but it only carries goal/persona/monthly — never a chain or token filter. Open any existing share link fresh and it just re-curates "top 3 by persona," ignoring whatever protocol/pool the sender actually had in view. For a spotlight ("look at this SOL-USDC pool on Orca"), that's not good enough — the link has to reproduce *that* pool. So this item had to first close a real, pre-existing gap in 024's URL scheme (additive — old links keep working exactly as before).
2. **"Small protocol" needed an actual definition, and trust rails needed to travel with it.** Nothing in the codebase classified protocols by size before. The generator aggregates each protocol's TVL across its trust-rail-qualifying pools and uses Curve's own aggregate as the ceiling — anything at or below that line is eligible, Curve itself is the boundary, not a candidate. Every candidate pool still has to clear the exact same `APY_SANITY_LIMIT`/`DEFAULT_MIN_TVL` rails the app and planner already enforce; nothing about "smallness" ever loosens them.

## What changed and why (diff in reading order)

**`planner.js`** — the share-URL fix (024's gap, above):
- `encodePlanToUrl(...)` gained an 8th optional argument, `poolFilters` (`{chain, token}`). When present it sets `chain`/`token` query params; when absent it deletes them — a link built the old way is byte-identical to before.
- `decodePlanFromUrl(...)` now reads `chain`/`token` off the URL and includes them in its returned object. Its existing "no goal/pace → return null" early-exit is untouched.
- `restart()`'s URL-param cleanup list now also clears `chain`/`token` so starting over doesn't leave a stale filter in the address bar.
- `poolFiltersState` (lives in the `Bloom` component, not `Planner`) now seeds from two new props, `initialChain`/`initialToken`, which `Planner` populates from the decoded `sharedPlan` at its own `Bloom` call site — `Bloom` has no direct access to `Planner`'s `sharedPlan`, so this is the minimal way to carry the value across that component boundary (mirrors how `answers` already gets seeded from `sharedPlan` one level up).
- The three places a share link actually gets built (`doShareImage`/`doCopyLink`/`doNativeShare`) now pass the live `poolFilters` through, so a user's *own* share (not just a spotlight-generated one) also preserves whatever chain/token filter they'd set — a natural side benefit of closing the gap, not extra scope.
- `planner.min.js` was regenerated (`npm run minify`) — `plan.html` loads the minified bundle, not `planner.js` directly, so skipping this would have shipped source code nobody's browser actually runs.

**`generate-spotlight.js`** (new) — the pack generator itself, following the existing `generate-token-pages.js`/`generate-og-images.js` conventions (fetch-or-`--fixture`, CLI flags, `@napi-rs/canvas` for the PNG):
- Reuses `poolTotalApy`/`isAnomalousApy`/`formatUsd`/`formatApy` from `generate-token-pages.js` rather than reimplementing them.
- Defines its own `DEFAULT_MIN_TVL = 10000000` / `APY_SANITY_LIMIT = 1000` — matching `app.js`/`planner.js` exactly, deliberately NOT the SEO generator's relaxed $100K floor, because a spotlighted pool feeds a real example garden (plan-entry semantics), not a search-traffic listing.
- Classifies "small enough" by aggregating TVL per protocol across qualifying pools and comparing against Curve's (`curve-dex`) own aggregate; Curve itself is excluded as a candidate.
- `--pool <id>` picks a specific pool (refuses non-zero if it fails rails or is too big); no flag auto-picks the highest-APY qualifying pool from a small-enough protocol.
- Picks a subscription goal (default `claude`) and a persona using the *same* `PERSONAS` band definitions `planner.js` uses (this needed both the APY ceiling AND the TVL floor per band — see Deviations) so the pack's own persona choice is guaranteed to actually render on the live site, not just look plausible on paper.
- Builds the share URL, a tweet draft (with an explicit, unconfirmed `@<project>` placeholder — never a fabricated handle), a flat Canva-field JSON object, and a 1200×630 share-card PNG (text-only, mirrors `generate-og-images.js`'s existing card style).

**`test_spotlight.js`** (new) — pure-function + CLI-subprocess assertions: trust-rail exclusion, the Curve-ceiling classifier, pool selection/refusal, pack shape, and PNG validity. 25/25 passing.

**`test_spotlight_url.js`** (new) — a real-Chromium Playwright check (mirrors `test_search.js`'s host-probe/fixture-fallback pattern, since this sandbox blocks browser-originated HTTPS even though `curl`/Node reach the same hosts fine) confirming a `chain=`/`token=`-bearing share link actually curates to that filter on open, and that a legacy link *without* those params still works exactly as before. 3/3 passing. This test is what caught two real bugs during the build (see Deviations) — it's doing its job.

**`package.json`** — adds the `spotlight` script and appends both new test files to the `test` chain.

## Deviations from spec (full detail in `specs/060-notes.md`)
- `poolFilters` turned out to already be local `Bloom` state (not a `props.poolFilters` the spec guessed might exist) — passed directly rather than inventing a prop that isn't there.
- Seeding `poolFiltersState` from the decoded shared plan needed two new props (`initialChain`/`initialToken`) rather than a direct `sharedPlan` read, because `Bloom` and `Planner` are different components.
- The persona classifier needed `PERSONAS`' `minTvl` floors, not just the spec's literal "APY ceiling only" description — without this, the generator could tag a pool `stable` that the live `curatePools` (which also gates on a $50M TVL floor for that band) would then reject, rendering an empty grid. The Playwright test caught this directly.
- `planner.min.js` needed regenerating — the first Playwright run silently exercised stale pre-060 minified code until this was done.
- Confirmed live that Curve's DefiLlama project key is `curve-dex` (distinct from `curve-llamalend`, deliberately excluded from the aggregate).

## Trust rails
Unchanged and unbypassable: `APY_SANITY_LIMIT = 1000`, `DEFAULT_MIN_TVL = 10000000` in `generate-spotlight.js` match `app.js`/`planner.js` literally. No pool that fails either rail can produce a pack, verified both by unit tests and by a manual CLI run against a hand-built fixture containing an anomalous pool.

## Out of scope (untouched, confirmed via diff)
`home.html`'s `?token=`/`?chain=`/`?pool=` analytics-app URLs (a completely separate, sacred sitemap surface from `plan.html`'s own param scheme touched here), `telegram-bot/`, `whatsapp-bot/`, `workers/`, any trust-rail constant, EN/KO translations (generator output is CLI/Node-only, no new user-facing app strings).
