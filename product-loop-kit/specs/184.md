# Spec 184: automate level-2 link checking on the HTML estate's `?pool=` deep links

## Evidence

Item 175 named the axis the loop had been circling for four consecutive bugs (148 → 159 → 166 → 173). A
link check has three levels:

1. **routed** — the query key is a member of `ANALYTICS_PARAMS ∪ PLANNER_PARAMS` (item 172, shipped).
2. **resolvable** — the value names a real pool id / project slug / preset key.
3. **non-empty** — the target, under its own default filters, returns what the linking page claims
   (item 175 for the prescan, 180 for `llms*.txt`, 181 for grid CTAs — all shipped).

**Level 2 on the HTML estate has never been automated.** It has been run **by hand four times in five
days** (07-26 through 07-30) — including this tick, where I checked every `?pool=` deep link the 2,181
generated pages emit:

| measurement (2026-07-30, against live DefiLlama, 15,992 pools) | value |
|---|---|
| distinct `?pool=<uuid>` deep links across `tokens/*.html` + `chains/*.html` | **3,677** |
| ids absent from live DefiLlama (dead) | **4 (0.11%)** |
| pages carrying ≥1 dead link | **5 of 2,181** |

The four: `tokens/aeon.html`, `tokens/harambe.html`, `tokens/robinhood.html`, `tokens/solna.html`.

**0.11% is ordinary pool churn, not a defect** — comfortably inside the `DRIFT_BUDGET_FRACTION = 1.0%`
item 181 already derived and shipped for exactly this class of live-data drift. So the finding here is not
"the estate is broken"; it is "**the only unautomated level of the model is the one we keep hand-running,
and today it happens to be green**".

Two facts make this worth building rather than deferring:
- These deep links are the estate's route to the **north-star surface**. 2,092 of 2,093 token pages and 87
  of 88 chain pages carry at least one (only the two `index.html` hubs do not). A dead one lands a reader
  on the honest dead-pool empty state (`app.js:1209` `setDeadPoolParam`) instead of a pool.
- Every previous level-2 hand-run has been prompted by a bug already found some other way. The pattern item
  175 documented is that the class nobody has been bitten by yet is where the next bug lands.

## Hypothesis

We believe **a level-2 liveness check over the estate's `?pool=` deep links, classified by item 181's
already-shipped contract/stale/drift rules**, will **catch the next dead-deep-link regression at the gate
instead of at a hand-run**, because the identical shape already works one surface over (181 for grid CTAs,
180 for text surfaces) and today's corpus provides a true negative to prove the check non-vacuous against.
Confidence: **validated-pattern** — this is the fourth application of a shape that has held three times.

## Change

- Extend the existing static-page scan with a level-2 `?pool=` liveness signal: collect every
  `?pool=<uuid>` emitted by `tokens/*.html` + `chains/*.html`, resolve against live
  `https://yields.llama.fi/pools`, and classify each miss using **181's existing classifier**, not a new one:
  - **contract** (repo-decidable — malformed uuid, a link whose id the page's own body never mentions):
    fatal at any count.
  - **stale** (dead id **and** the page's own visible `Last updated` date older than the same threshold
    181 uses): fatal at any count — this is the lifecycle failure, and it is what a regression looks like.
  - **drift** (dead id on a fresh page): bounded by 181's **existing** `DRIFT_BUDGET_FRACTION = 1.0%`.
    Today's 0.11% passes with ~9× headroom.
- **Reuse 181's constant and classifier. Do not introduce a second budget or a second floor literal** —
  item 174's rule binds: every threshold must derive from one constant.
- Emit the same shaped finding the other link signals emit so the heartbeat reads it without special-casing.

**Explicitly OUT of scope**
- Repairing the 4 dead links. They are drift; the next daily bake resolves them. A diff that regenerates
  `tokens/`/`chains/` to make the gate green is **the opposite of this item** — it ships a repair and
  leaves the gate unbuilt.
- Levels 1 and 3 (already shipped: 172, 175/180/181).
- `?token=`/`?chain=`/`?protocols=`/`?preset=` values — a level-2 check for those is a separate item if the
  hand-runs keep recurring.
- Any product code, any generated surface, any trust rail.

## Acceptance criteria

- [ ] The new signal appears in the audit's `bySignal` block alongside the existing link signals, with a
      count.
- [ ] **True negative proven non-vacuous, not reported as health** (172's precedent): on today's committed
      corpus the signal is green, AND the check is shown to go **red** on a deliberately broken copy —
      a page given a syntactically valid but nonexistent uuid ⇒ classified, counted, non-zero exit.
- [ ] **Each of the three classes exercised**, with `contract` and `stale` shown fatal at count 1 and
      `drift` shown bounded — the 181 verification standard.
- [ ] The drift budget is **read from 181's existing constant**; `grep` shows no second numeric literal for
      it. A duplicated threshold is a FAIL.
- [ ] The `stale` branch proven on a real page copied to a scratch location and backdated —
      `tokens/`/`chains/` left byte-untouched (181's method verbatim).
- [ ] Reported counts reproduce this spec's hand-measurement on today's corpus: **3,677** distinct deep
      links, **4** dead, **5** pages affected — or, if the live pool set has moved by the time the item is
      built, state the fresh numbers and the delta. Numbers that silently disagree with this spec without
      explanation are a FAIL.
- [ ] Non-vacuity: neuter the signal, show the broken-copy case stops reddening, restore and show
      byte-identical (md5).
- [ ] Live network dependency handled the way the existing checks handle it — a fetch failure must **not**
      silently pass the gate; it reports as unrun.
- [ ] Trust rails and all product files byte-untouched: `git diff origin/main` over `app.js planner.js
      PoolDetail.js translations.js home.html tokens/ chains/ llms*.txt sitemap*.xml package.json` = **0**
      lines beyond any test registration.
- [ ] Test gate: `run-tests.js --lane=plain` green; browser-lane status stated explicitly (Node-only item —
      "unrun" is the expected honest answer).
- [ ] Instrumentation: none — loop tooling under the 2026-07-23 pre-traffic mandate
      (142/149/154/155/160/171/172 disclosure pattern).

approach instead.
