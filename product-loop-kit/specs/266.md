# Spec 266: the WebMCP agent surface re-implements both trust rails as hardcoded literals

Written by the build loop 2026-08-11 (the BACKLOG row carried no spec file — build.md's
"no spec ⇒ write it from documented evidence first, same PR" path). Evidence below is

## Evidence

**1. The defect, verbatim from the source.** `home.html:228-343` registers WebMCP tools on
every page load of the document Vercel serves for `/` (and for every planner/analytics
parameterised URL — the router at `home.html:83-100` selects the *mode*, never whether this
script runs):

```js
// home.html:268-276
var filtered = pools.filter(function(p) {
    if (p.tvlUsd < 100000) return false;
    if (p.apy > 1000) return false;
    ...
    if (minApy && p.apy < minApy) return false;
```

`100000` and `1000` are a **third hand-typed copy** of `DEFAULT_MIN_TVL` and
`APY_SANITY_LIMIT`. They are correct today by coincidence only.

**2. `trust-rails.js` is already loaded on this page, synchronously, above this block.**
`home.html:80` — `<script src="trust-rails.js"></script>`, no `defer`, with a header comment
(`home.html:74-79`) stating it exists so no later script hand-types a rail figure. The tool's
own *description string* twenty lines below (`home.html:250`) already reads
`window.TRUST_RAILS.formatTvlFloor(window.TRUST_RAILS.DEFAULT_MIN_TVL)`, and its comment
(`home.html:246-249`) says the literal it replaced "drifted once already". **The prose was
tokenised; the executable predicate underneath it was not** — same tool object, ~20 lines apart.

**3. Second defect on the same predicate: it rails a DIFFERENT quantity.** `p.apy` is
DefiLlama's own field. Every railed surface computes total APY as `apyBase + apyReward`
(`edge/api-core.js:85`, mirroring `app.js`). So the filter is not merely an unlinked copy of the
rail — it is a copy of a *different* rail. Item 259 already tracks that `apy` disagrees with the
computed total on live pools. The same field is used for the `minApy` filter (`home.html:274`)
and is what the tool *returns* to the agent (`home.html:287`), where `/api` returns `totalApy`
(`edge/api-core.js:384`).

**4. The class, measured in this checkout.** A scan of every executable file in the repo
(root `*.js`, `edge/*.js`, `tools/*.js`, `test_*.js`, and the inline scripts of `home.html`
/`plan.html`; generated twins excluded — see the test header) for *a pool TVL/APY quantity
compared against a non-zero numeric literal* returned **~27 sites in 13 files** *as first measured
while writing this spec* — a figure the detector's later widenings (Leg E, then verifier rounds 1
and 2) superseded; the current counts live in the test header and are re-measured on every run.
Exactly **two of
those sites are unlinked copies of a platform rail**:

| site | literal | status |
|---|---|---|
| `home.html:269-270` | `100000`, `1000` | correct today, unlinked — this item's motivating instance |
| `tools/test-agent-tools.js:127-128` | `10000000`, `1000` | **already drifted** — asserts a `$10M` floor and prints `All pools strictly respect TVL >= $10M`; the floor has been `$100K` since commit `6fceca79bb` |

The second site was **not** in the backlog row. It is the same defect class, already broken,
on the same agent-facing surface family (`tools/*.json` are in item 261's guarded manifest
population; this is that surface's integration script) — and `tools/` is on `.vercelignore`'s
**deliberate must-keep allowlist** (`.vercelignore:10`, guarded by `test_vercelignore.js`), so

## Hypothesis

We believe sourcing both rail values from `window.TRUST_RAILS` and computing total APY the way
`edge/api-core.js` does will make the browser-agent surface follow the rails the moment the
human moves them — instead of silently applying the old ones — because that is precisely what
`trust-rails.js` was built for and what the neighbouring description string already does.
Confidence: **validated-pattern** (item 254 and item 261 are the same move on the prose and
manifest surfaces; this pays off across every future in which a rail value is ever changed, and
costs nothing in the futures where it is not).

- **Instance of:** *a trust-rail predicate implemented as a hardcoded numeric literal in
  executable code, outside `trust-rails.js`'s consumers.* Population (as first measured; see the
  note above — the shipped counts are re-derived at test time): ~27 pool-threshold
  literals across 13 executable files; 2 are rail copies (both fixed here), 25 are
  intentionally-different thresholds (classified in the guard's allowlist).
- **Class closed by this item:** **NO — partially closed, and the honest statement is a list of
  shapes, not a verdict.** This claim read "yes" through three verifier rounds and was falsified
  each time; the fourth statement is written to be falsifiable rather than reassuring. What the
  guard **does** catch, each proven red by a planted mutation and a byte-identical restore: a
  bare-operand comparison against a non-zero literal, over a statement window (so line-wrapping
  does not hide it), with a numeric grammar covering exponent/hex/underscore/leading-dot forms;
  a rail-named constant declaration terminated by `;`, `,`, `}`, `)` or end-of-line (so ASI and
  default parameters do not hide it); a `SCREAMING_SNAKE` object-property rail; a keyword-less
  assignment; and — added after round 3 — a comparison whose operand is a **parenthesised
  expression** containing a tvl/apy identifier, which is this repo's house idiom
  (`(pool.tvlUsd || 0) >= X`) and the exact form used at the three enforcement points this item
  rewired. Round 3's finding is why that last one exists: the guard had been blind to
  `generate-sitemap.js:88`, `generate-spotlight.js:79` and `generate-pools-snapshot.js:81`'s own
  shape — it would not have caught a hand-typed literal at the very lines this item repaired.
  **Stated open, with numbers** — and the standing lesson is that this list has been incomplete at
  every previous round, so treat it as the current best enumeration and not as a boundary:
  (0) **the object-property stratum is open for non-`SCREAMING_SNAKE` keys.** Relaxing that key
  restriction measures **1040** raw hits / **107** after excluding DefiLlama field names — too many
  to classify honestly here. It has a live, already-drifted instance:
  `generate-spotlight.js:419-421`'s `PERSONA_BANDS` hand-types `minTvl: 100000` for `rwa`/`degen`
  while `planner.js:567/572`, the bands its own comment says it mirrors, say `10000000` — a
  **100× divergence on 2 of 3 bands**, which the guard cannot see. A pin test records the exact
  divergence so either side moving fails loudly; which value is correct is a product decision and
  nothing was changed;
  (a) comparisons against literal `0` are excluded by design
  (a rail of 0 is degenerate — documented limitation, **72** such sites, measured by running the
  scan with the zero-filter removed: 127 comparison sites unfiltered vs 55 filtered); (b) rail *semantics*
  copied wrongly (this item's defect 3 — railing `apy` instead of `apyBase+apyReward`) is **not**
  machine-checked outside `home.html`: the guard sees the literal, never which quantity it rails.
  Leg D closes (b) for `home.html` only, by rendered behaviour; (c) **the prose stratum — a rail
  figure stated wrongly in a `*.js` COMMENT — is uncovered by anything in this repo.** Item 261's
  prose guard scans `*.md`/`*.json`/`*.txt` only, so root `*.js` comments were never in any
  population. Measured in this checkout: **four generator files** carry a stale `$10M` rail claim
  and/or cite the long-moved `app.js:729-730`, three of which this item repairs incidentally
  because it had to rewrite those exact comments to fix the code beneath them. The remaining
  count is recorded in `266-notes.md`. **Not ticketed by this run** — filing it is the
  heartbeat's job, and it is a widening of item 261's population, not of this item's.

## Change

Smallest version that tests the hypothesis. Three legs, one commit.

**Leg A — `home.html` (the motivating instance).** In the `search_yield_pools` `execute`:
1. read `window.TRUST_RAILS.DEFAULT_MIN_TVL` / `.APY_SANITY_LIMIT` instead of `100000`/`1000`;
2. add a local `totalApy(p)` = `(Number(p.apyBase)||0) + (Number(p.apyReward)||0)`, byte-equivalent
   to `edge/api-core.js:85`, and use it for the sanity rail, for the `minApy` filter, and for the
   `apy` value returned to the agent.
No other change to the tool's shape, name, schema, or description.

**Leg B — `tools/test-agent-tools.js` (the already-drifted sibling).** `require('../trust-rails.js')`
and derive both invariant thresholds + their printed messages from it, using the same `totalApy`
arithmetic. This file is not in the test registry (it needs a running server on :8001); it is
fixed because the guard in Leg C reports it, and leaving a known-stale rail claim on the agent
surface to satisfy a scanner is the defect, not the fix.

**Leg C — the class guard, `test_rail_predicate_derivation.js`** (named as the executable
counterpart to `test_rail_floor_derivation.js`'s prose guard and
`test_agent_surface_rail_claims.js`'s manifest guard; follows their idiom rather than inventing
a third one). Population derived at test time by glob, never a hand-typed file list. It scans for
a pool TVL/APY quantity compared against a non-zero numeric literal and asserts **set-equality,
both directions**, against a committed `ALLOWLIST` in which every entry names the threshold and
why it is not a platform rail:
- a scanned site absent from the allowlist → FAIL (a new unlinked rail copy cannot land);
- an allowlist entry that no longer matches anything → FAIL (the mirror cannot rot — the 212 rule);
- keyed on `file|normalised-expression`, never on line numbers.
Registered in `package.json`'s `test:serial` chain (`test_test_registry.js` enforces this).

**Leg D — rendered acceptance, `test_webmcp_rail_derivation.js`** (browser lane, standing
decision 2026-07-11: rendered product behaviour, never unit fixtures alone). Real Chromium on
the real `/`, DefiLlama routed to a fixture (established pattern — browser-originated external
HTTPS is blocked in this sandbox, standing decision 2026-07-12). It invokes the *live registered
tool* off `window.navigator.modelContext` and asserts the rails using values read from
`trust-rails.js` **at test time**, plus the two discriminating fixtures for defect 3.

**Leg E — the assignment stratum** (added by the operator on review of the built Legs A-D, before
verification; the detector's own residue note turned out to name a population, not an instance).
Leg C as first built saw only rail-shaped *comparisons*. A scan of the same population for
rail-*named* constants assigned a numeric literal returns **15 sites in 13 files**, of which two
generators declare the canonical name `DEFAULT_MIN_TVL` with a hand-typed `100000` and a third
carries an explicit "must stay in sync with app.js — no shared import exists" contract that
`trust-rails.js` has since made false. So Leg E:
1. widens the Leg C detector to rail-named assignments, folded into the same two-direction
   set-equality, with comment-stripping so the scan reads code and not prose (the header's own
   quoted example proved this was needed);
2. derives the unambiguous mirrors — `generate-pools-snapshot.js`, `generate-spotlight.js`,
   `generate-sitemap.js`, `generate-token-pages.js`'s `APY_SANITY_LIMIT`, and (added after
   verifier round 1) `src/poller-core.js`, which hard-declared **both** rails while its own header
   calls it "another enforcement point for the rails" — from `trust-rails.js`, values unchanged,
   exports and constant names unchanged;
3. classifies the rest in the allowlist as the intentionally-different thresholds they are
   (`generate-token-pages.js`'s long-tail `MIN_POOL_TVL` per the human's 2026-07-11 directive,
   item 216's `POOL_ARTIFACT_MIN_TVL`, `RISK_FREE_APY`, `BANK_APY`, four test fixture floors).
`app.js:800-801` and `trust-rails.js`'s own declarations are excluded by role as the canonical
source. Rationale for widening rather than ticketing: leaving two files that literally redeclare
`DEFAULT_MIN_TVL = 100000` while this item's whole thesis is that the value must be singular is
the item-138 failure mode — a narrow fix claiming a closed class.

**OUT OF SCOPE** (deliberate, each stated so the verifier can check it was not smuggled in):
`app.js:800-801` stay canonical and untouched; no rail VALUE changes; the second tool
(`calculate_savings_projection`) and its hardcoded `apy = 5.5` are untouched — a fabricated
projection rate is a different class (an unrailed *number*, not an unlinked *rail*), recorded in
the notes as residue; no `plan.html` change; no change to tool names/schemas (an agent-visible
contract); no design/CSS change.

## Verifier round 1 — FAIL, and what it changed in this spec

The verifier returned FAIL on 2026-08-11 with three findings, all upheld by the operator. Recorded
here because two of them changed the spec itself, not just the code:

1. **Stale `$10M` claims survived inside the very files Leg E rewired** — including
   `generate-spotlight.js:173`, which is not a comment but **emitted runtime text** telling a
   caller their pool "is below the $10M floor" while the code applies $100K. That is the identical
   defect Leg B exists to fix, in a file this item had already touched. Fixed.
2. **The detector was keyed on the two known instances' punctuation, not on the mechanism.** The
   verifier planted five rail copies that the guard scored green: `1e5` exponent form (house style
   in this repo — `trust-rails.js:50-52` itself uses it), a comparison wrapped across two lines, a
   declaration with no trailing `;`, an object-property rail (`{ DEFAULT_MIN_TVL: 100000 }`), and
   an assignment with no declaration keyword (`o.APY_SANITY_LIMIT = 1000`). This is RAZOR example 5
   exactly — a guard aimed at a resemblance launders the gap as coverage. The detector now scans a
   statement window with a full JS numeric-literal grammar and recognises all five shapes; each
   attack was re-run and must turn it red.
3. **Two residue numbers were wrong and one population member was unnamed.** The literal-`0`
   exclusion was stated as "~40 sites" in the spec and "~70+" in the test header; measured, it is
   **60**. And `src/poller-core.js` hard-declared both rails with stale `$10M` prose on the
   enforcement line — a textbook member of this item's own population, excluded by role and named
   in no residue. `src/*.js` is now in the scanned population and the file derives.

The honest reading of finding 2: the class claim in "Hypothesis" above would have been **false as
written** at round 1. It stands only because the detector was widened to match it — which is the
order the razor demands (fit the check to the class, not the claim to the check).

## Verifier rounds 2 and 3 — the same lesson, twice more

Round 2 found the widened detectors still scanning line-by-line (so a wrapped declaration or a
multi-line object literal escaped), an unjustified `SCREAMING_SNAKE` restriction on the
keyword-less-assignment detector (relaxing it cost 4 sites), and a false "zero exceptions"
justification. Round 3 found the comparison detector blind to **this repo's own house idiom** —
`(pool.tvlUsd || 0) >= X` — with **11 live unseen sites** in the scanned population, including
`test_pool_twins.js:117-118`, where two adjacent lines compare the same quantity to the same
literal and only one is visible to the scan.

**Three consecutive rounds found the same failure mode: the detector encoding the motivating
instances' punctuation rather than their mechanism** (round 1: exponent/wrapping/ASI/object-property;
round 2: line-based scanning; round 3: parenthesised operands). That is the
`148 → 159 → 166 → 173` pattern in RAZOR.md, reproduced inside a guard written to honour RAZOR.md.
The generalisable lesson, worth more than this item: **a regex-shaped detector over source text
will keep encoding punctuation, because punctuation is what a regex can see.** The durable fix is
to parse rather than to match — each widening here bought one shape, and the next shape was always
there. Recorded for the improve loop; not attempted in this item.

## Risk tier (builder's guess — verifier assigns independently)

**HIGH.** `home.html` is the IA router and a sacred parameterised-URL surface; the diff is
inside trust-rail semantics. It *strengthens* the rails (re-derives them from the single source
and widens the APY rail from `apy` to `apyBase+apyReward`, which admits strictly fewer anomalous
pools), so it is not a NEVER-list weakening — but the verifier must re-verify the rails
independently and confirm no router behaviour changed.

## Open questions

None that change the architecture. One judgement call recorded rather than asked: the tool's
returned `apy` field now carries the computed total instead of DefiLlama's `apy`. This changes
an agent-visible *value* (not the schema) and makes it agree with `/api`'s `totalApy` and with
every railed surface; the alternative — railing on the total but reporting the upstream field —
would report a number the rail did not apply to, which is the honesty defect this item exists to
remove.
