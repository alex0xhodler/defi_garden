Consequence, stated plainly: the moment the human relaxes or tightens a rail in `app.js` (the canonical

one audience that cannot see the code. And today, before any such change, it already applies a *third*
rail semantics that no other surface uses: a pool with `apyBase 600 + apyReward 600` (total 1200%,
anomalous everywhere else) passes this filter whenever DefiLlama's own `apy` field reads low.

## Hypothesis

We believe **sourcing both thresholds from `window.TRUST_RAILS`, computing total APY the way
`edge/api-core.js` does, and guarding the class with a derivation test that mutates the rail at runtime**
will remove the third rail copy and stop the class from recurring, because a test that *changes*
`window.TRUST_RAILS` at runtime and demands the filter's behaviour change with it cannot be satisfied by
a literal that merely happens to be equal. Confidence: **validated-pattern** — this is the fourth
instance of the same drift class (254's nine prose sites, `test_rail_floor_derivation.js`, 261's two
machine manifests, now this predicate), and the fix that worked each time was derivation plus a test, not
a careful edit.

- **Instance of**: *a surface that APPLIES a trust rail from a value it hand-typed instead of one it
  derived.* This is the applied-rail sibling of 254/261's stated-rail class. Population, enumerated
  in-session by `grep -rn "APY_SANITY_LIMIT\s*=\|DEFAULT_MIN_TVL\s*=" --include=*.js --include=*.html`,
  then **re-measured at test time by Leg C's own derived scan** (the grep undercounted — corrected here
  rather than left standing): **1 canonical site** (`app.js:800-801`, human-owned, never derived by
  design), **1 derived consumer** (`edge/api-core.js:64-65`, reads `trust-rails.js`, declares no
  literal), **21 named-constant mirror declarations across 15 tracked files** (measured, not estimated:
  `app.js`, `app.compiled.js`, `app.compiled.min.js`, `planner.js`, `planner.min.js`,

## Change

Smallest version that tests the hypothesis:

1. `home.html`, `search_yield_pools.execute` only:
   - `p.tvlUsd < 100000` → compares against `window.TRUST_RAILS.DEFAULT_MIN_TVL`.
   - `p.apy > 1000` → compares a locally computed total APY (`(Number(p.apyBase) || 0) +
     (Number(p.apyReward) || 0)`, the exact expression `edge/api-core.js:84-86` uses) against
     `window.TRUST_RAILS.APY_SANITY_LIMIT`.
   - The `minApy` argument filter uses that same computed total. The returned rows mirror
     `edge/api-core.js`'s `projectPool()` (`api-core.js:376-390`) **exactly**: `apy` stays DefiLlama's
     own field, passed through **unmodified**; `apyBase`/`apyReward` **preserve `null`** for an absent
     field; a new `totalApy` key carries the derived total. (Attempt 1 overwrote `apy` with the total and
     coerced `null → 0` while claiming to mirror api-core — the verifier measured the cost live: **185
     above-floor pools (2.5% of 7,350, median `apy` 6.05%) carry `apyBase`/`apyReward` both null with a
     positive `apy`**, and were being reported as `{apy: 0, apyBase: 0, apyReward: 0}` and dropped by any
     `minApy > 0`. Fixed in attempt 2; the mismatch between the claim and the code is why the claim is
     now stated as a checkable criterion below.) No pre-existing key is renamed or removed.
   - No defensive fallback literal: `window.TRUST_RAILS` is already dereferenced unguarded at
     `home.html:250` in the same object, and `trust-rails.js` is a synchronous tag at `home.html:80`.
     A `|| 100000` fallback would reintroduce exactly the copy this item removes.
2. New `test_webmcp_rail_derivation.js`, three legs (A rendered, B + C static), appended to
   `package.json`'s `test:serial` so `test_test_registry.js` stays green.
3. `product-loop-kit/playbooks/derived-number-rails.md` — UPDATE (never duplicate) Step 0's emitter
   list with the browser-inline agent surface, and record the generalisation: *a rail-applying surface
   can be an inline `<script>` inside an HTML document, not only a `.js` file* — which is why the
   emitter list, assembled by grepping `*.js`, could not see it.

**Explicitly OUT of scope**: the IA router (`__APP_MODE`) and every parameterized-URL code path are not
touched; `calculate_savings_projection`'s hardcoded `apy = 5.5` is a real, separate defect on the same
surface (an invented number on a product whose rail is "nothing is invented") and is FILED as a new
backlog row, not fixed here; `planner.js:19`'s named mirror is left as-is (Leg C covers it by equality —
converting it to a runtime read is a planner-surface change with its own risk); nothing under
`edge/`, `workers/`, or the generated estate changes.

## Acceptance criteria

      filter and the `minApy` filter, and reported as a new `totalApy` key.
- [ ] The returned row mirrors `api-core.js`'s `projectPool()`: `apy` unmodified, `apyBase`/`apyReward`
      `null`-preserving (never coerced to 0), `totalApy` derived — asserted by a Leg A fixture pool drawn
      from the real 185-pool live population (`apyBase: null, apyReward: null, apy: 6.05`, above floor):
      it is returned, its nulls come back as `null`, and with `minApy: 5` it is excluded (total 0 < 5 —

- [ ] Both router paths still work after the edit: bare `/` renders the planner/landing, `/?token=USDC`

      (`node test_test_registry.js` green).

      fixture, the page's *registered* tool list is read from `navigator.modelContext.tools` (population

      `DEFAULT_MIN_TVL - 1` is not; (ii) after mutating `window.TRUST_RAILS.DEFAULT_MIN_TVL` in the page
