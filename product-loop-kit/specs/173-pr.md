# 173 — Our own SEO pages were sending 1,749 readers into an empty grid

Risk tier: **HIGH** (verifier-assigned independently, agreeing with the spec's guess).
Explainer per the risk policy's HIGH requirement: full walkthrough + 5-question quiz at the bottom.

## The goal

Stop our own pages lying about where their button goes.

## The intuition, in one picture

A `/chains/cardano` page says, in its own prose:

> **33 pools** across 31 tokens clear DeFi Garden's $100K TVL floor, $20.36M in total.
> … **See live pools on Cardano →**

That button went to `https://www.defi.garden/?chain=Cardano`. Live pools that URL returned: **0**.

The page counted its pools at a **$100K** floor. The link it handed you was filtered at the app's
**$10M** default. Same data, same day, two different floors — 100× apart — and nobody had ever
compared the two numbers, because each side is internally consistent. The page is right about its 33.
The app is right to default to $10M. The **contract between them** was never checked.

Measured across the whole estate against live DefiLlama (16,038 pools):

| surface | pages | CTA returns 0 pools | share |
|---|---|---|---|
| `chains/*.html` | 88 | 48 | 54.5% |
| `tokens/*.html` | 2,112 | 1,701 | 80.5% |
| **total** | **2,200** | **1,749** | **79.5%** |

It concentrates in the long tail — precisely the pages SEO exists to serve. Of the pages that actually
took production traffic this week: `/chains/linea` → 1 pool, `/chains/aptos` → 1, `/chains/cardano` → 0.

## What changed, and why that is the whole fix

Two lines. Each generated page now links to the grid **at the floor that page was built with**:

```js
// generate-token-pages.js:673
- const appUrl = `${SITE_URL}/?token=${encodeURIComponent(rec.symbol)}`;
+ const appUrl = `${SITE_URL}/?token=${encodeURIComponent(rec.symbol)}&minTvl=${MIN_POOL_TVL}`;

// generate-chain-pages.js:149  (same shape, chain instead of token)
```

Three things make this the minimal correct change rather than a patch:

1. **The app already honoured it.** `app.js:927`: *"Respect explicit `minTvl=0`; fall back to
   `DEFAULT_MIN_TVL` only when param is absent."* No app change was needed — or made.
2. **The floor is read from the existing constant**, never re-typed as a literal (the 159 rule).
   `MIN_POOL_TVL` is already exported by `generate-token-pages.js` and already imported by
   `generate-chain-pages.js`, so there is exactly one definition of the number.
3. **Everything downstream inherits it.** `categoryLinksFor()` builds `${baseAppUrl}&poolTypes=…`
   from `appUrl`, and `poolHrefFor()`'s no-pool-id fallback does too — so the `&poolTypes=` variants
   were fixed without a second injection site to keep in sync.

## Reading the diff in order

The diff is ~6,670 files. **Everything hand-written is in 5 files**; the rest is regenerated output.

| file | what to look at |
|---|---|
| `generate-token-pages.js` | one line, 673 |
| `generate-chain-pages.js` | one line, 149 |
| `test_seo_cta_targets.js` | **new.** Scans every generated page, asserts the CTA carries the floor AND resolves to ≥1 live pool |
| `test_seo_cta_render.js` | **new.** Playwright: proves the contrast in the real UI |
| `test_token_pages.js` / `test_chain_pages.js` | 4 assertions that hardcoded the old href string, now interpolating `gen.MIN_POOL_TVL` |
| `package.json` | one line: the two new tests wired into `test:serial` |
| `tokens/`, `ko/tokens/`, `chains/`, `ko/chains/`, `og/`, `sitemap-*.xml`, `llms*.txt`, `stories/` | regenerated by the sanctioned scripts, never hand-edited |

## Why you can believe the numbers

- **Red→green, proven both ways.** The new test fails **2,200 of 2,200** against the pre-change
  output and passes **0 dead of 2,217** after. The verifier reproduced the red independently in a
  clean `origin/main` worktree, then went further: it stripped `&minTvl=100000` from one live page
  and confirmed the test caught that single regression, restoring the file byte-identically.
- **The page's claim now equals what the link delivers.** Cardano 33 = 33 · Celo 15 = 15 ·
  1INCH 17 = 17 · BUIDL 9 = 9. Cardano and Celo were re-derived by the verifier; Cardano was also
  checked independently by the operator before the build started (86 Cardano pools live, 33 ≥ $100K,
  **0** ≥ $10M — which is exactly why that button returned nothing).
- **Rendered acceptance, not fixtures** (2026-07-11 standing decision). Real Chromium against the
  real router: `/?chain=Cardano&minTvl=100000` renders 3 pool cards; bare `/?chain=Cardano` renders
  zero. The contrast *is* the proof.
- **Rails byte-untouched.** `git diff -- app.js canonical.js` is empty. `grep -c "10000000"` in both
  generators: 0 before, 0 after. `DEFAULT_MIN_TVL`, `APY_SANITY_LIMIT`, anomaly flags and the degen
  haircut are all unchanged. This change makes a link *more* honest; it loosens no filter.
- **Nothing was de-indexed.** 24 token pages dropped and 41 were added (net **+17**). The verifier
  re-ran `rankTopTokens()` against the live pool set for all 24 dropped slugs and confirmed every one
  genuinely no longer qualifies — ordinary daily churn at the $100K floor, the same churn the daily
  CI regen produces, not a code-caused deletion.

## Deviations and honest gaps

- **Two pre-existing tests needed 4 assertion updates.** They hardcoded the old exact href. Found by
  running the tests, not anticipated by the spec. Updated to interpolate the constant.
- **`package.json` was edited** (the two new tests into `test:serial`) and was **not disclosed in the
  first notes draft**. The verifier caught it and FAILed attempt 1 on exactly that — a config-infra
  file changed while the record said "exactly two source lines changed". Corrected in the notes, then
  re-verified. The change itself is one line and touches no dependency; the defect was the record.
- **`test_analytics_fires.js` fails** — proven **pre-existing** by running it in a clean `origin/main`
  worktree, where it fails identically (`page.goto` timeout on `/tokens/big`, 0 assertions). Not
  caused by this item, and not fixed by it.
- **The full `npm test` chain was NOT run** (100+ files, far over the 5-minute timebox). Stated as
  unrun rather than implied green. 13 targeted tests were run and are green.

## Two trade-offs the human should know about

1. **These landings lose the instant-snapshot render.** `app.js:1140` only takes the fast
   `data/pools-snapshot.json` path when `minTvl >= DEFAULT_MIN_TVL`. At $100K it goes straight to the
   live fetch. That is *why the fix works at all* — the snapshot only contains ≥$10M pools, so it
   could never have shown Cardano's 33 — but it is a real first-paint cost on these pages.
2. **`?token=X&minTvl=100000` is a new canonical variant.** `canonical.js:33` includes `minTvl` in
   `CANONICAL_PARAMS`, so the linked URL self-canonicals to itself rather than to the sitemap's
   `?token=X`. Nothing is de-indexed and no page is removed, but internal links now point at a URL
   shape that is not in the sitemap. `canonical.js` was deliberately not touched.

## The one question this item does not answer

Spec 173's open question, left for the human: should the SEO estate stay at **$100K** (2,200 pages,
long-tail reach) or be rebuilt at the product's **$10M** floor (~450 pages, all richer)? This item
implements the settled 2026-07-11 direction — the static page and the app view are two distinct
things, so the page's own pool set is authoritative and the link must reproduce it. Rebuilding the
estate at $10M is a different, bigger call and was not assumed.
