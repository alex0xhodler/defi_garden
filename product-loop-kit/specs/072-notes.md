Honest dead-`?pool=` empty state: noindex + "no longer tracked" + alternatives.
Extends 012's machinery to the pool deep-link leg. Reused 012 verbatim; invented nothing.

## Changes (file:line refs against post-edit app.js)

- **app.js**
  - `+785` new state `deadPoolParam` (string|null, default null), next to `detailPool`.
  - `~932` popstate handler: `if (!poolParam) setDeadPoolParam(null)` — clears the dead-pool
    state whenever the URL no longer carries a `pool` param (spec step 1/back-nav).
  - `~1024/1035` `?pool=` effect: on `foundPool` → `setDeadPoolParam(null)`; on miss (pool param
    present, not in live pools) → `setDeadPoolParam(urlParams.pool)`. `pool_view` still only
    fires for real pools (untouched — the spec requires it never fire for dead ids).
  - `~2067` new `deadPoolResolved = currentView !== 'pool-detail' && pools.length > 0 &&
    !!deadPoolParam` — same "never claim dead while loading / never while a real detail is open"
    rule as `emptyStateResolved`.
  - `~2095` new `deadPoolAlternatives` useMemo → `getEmptyStateAlternatives(null)` (top-TVL
    stablecoin pools through the identical trust rails). Only computes when `deadPoolResolved`.
  - `~2110` robots effect: condition `emptyStateResolved` → `emptyStateResolved || deadPoolResolved`;
    dep array extended. Same idempotent find-or-create node; restores `index, follow` when neither
    holds (e.g. after clicking into a live pool detail).
  - `~2775` results-section gate: added `|| deadPoolResolved` so the section mounts for a dead pool
    (which sets neither selectedToken nor selectedChain).
  - `~2777` inner ternary: `filteredPools.length > 0` → `filteredPools.length > 0 && !deadPoolResolved`
    so the (full, unfiltered) grid is suppressed and the empty-state branch renders instead.
  - `~2843` empty-state block: `empty-message`/`empty-submessage` branch FIRST on `deadPoolResolved`
    (`poolNotFoundTitle`/`poolNotFoundExplanation`); the existing 012 explanation + alternatives
    branches gated with `!deadPoolResolved` so the token/chain paths render byte-identically when
    `deadPoolResolved` is false. Added a dead-pool alternatives block reusing `.empty-state-alternatives`
    / `.pools-grid` / `renderPoolCard` verbatim with heading `emptyStateAltHeadingStable`.

- **translations.js**: new keys `poolNotFoundTitle`, `poolNotFoundExplanation` in BOTH `en` and `ko`,
  placed next to `emptyStateExplanation`. Calm honest tone; no scary jargon; mentions delisted/migrated
  and the $10M floor. No other key touched.

- **package.json**: appended `&& node test_dead_pool.js` to the end of the `test` chain

- **test_dead_pool.js**: new fixture-routed Playwright test (pattern from test_search.js + test_hero_copy.js).

- **Artifacts**: regenerated via `npm run compile && npm run minify`:

## Conservative choices

- Alternatives for the dead pool use `getEmptyStateAlternatives(null)` → the stablecoin branch (no
  target chain is knowable once the id is gone), exactly as the spec directs. Separate `deadPoolAlternatives`
  memo rather than overloading `emptyAlternatives`, to keep the 012 token/chain memo byte-identical.
- The reset-filters / "show smaller pools" buttons render as-is under the dead-pool empty state (spec
  allows; `resetApp` is a valid escape hatch). `minTvl > 0` is the default so the smaller-pools button
  shows — harmless, it just relaxes the floor and the dead-pool state persists.
