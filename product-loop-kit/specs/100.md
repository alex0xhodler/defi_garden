## The bug

`parseNaturalLanguageQuery` (app.js) has a **second token-parse fallback** (the
`if (!token && tokenCandidateText)` block, ~app.js:277-297) that uses a bare
substring test:

```js
if (t.length >= 3 && tokenCandidateText.toLowerCase().includes(tokenLower)) { ... }
```

For a query like `yields on ethereum`, the chain indicator `on` is the first
meaningful word, so `tokenCandidateText` becomes `"on ethereum"`. The primary
token loop uses a **word-boundary** regex (`\beth\b`) and correctly finds
nothing. But this fallback's substring test matches `'on ethereum'.includes('eth')`
→ **token resolves to `ETH`**. The guard that should stop it —
`const chainNames = ['base','ethereum','polygon','arbitrum','optimism','avalanche','fantom','solana']`
— lists the **long** chain names but not the **short aliases** (`eth`, `sol`,
`arb`, …), and the `wordsAfterChainIndicators` skip only rejects EXACT word
matches (`'ethereum' !== 'eth'`), so the short alias leaks through as a token.

**Impact:** a user searching `yields on ethereum` / `best yields on solana` /
`on arbitrum` gets spuriously token-filtered to ETH / SOL / ARB pools instead
of seeing all pools on that chain. The chain is still correct, so results are
narrowed wrongly rather than emptied — a quiet trust erosion on the search box.

## Confirmed offenders (live, this run)

Short aliases that are (a) ≥3 chars (the fallback's `t.length >= 3` gate) and
(b) a substring of a longer chain name that can appear after `on`:

| query | current (buggy) token | correct token |
|---|---|---|
| `yields on ethereum` | `ETH` | `""` |
| `highest apy on ethereum` | `ETH` | `""` |
| `best yields on solana` | `SOL` | `""` |
| `on arbitrum` | `ARB` | `""` |

`op`/`optimism` does **not** leak (`OP` is 2 chars, below the `t.length >= 3`
gate). `bnb`/`avax`/`ftm`/`matic`/`base` do **not** leak (either an exact word
caught by the `wordsAfterChainIndicators` skip, or not a substring of the chain
name). So the fix must cover at minimum `eth`, `sol`, `arb` — but the robust
fix covers **all** chain aliases so no future chain re-introduces the class.

## The fix (smallest change that satisfies acceptance)

In the second fallback's `chainNames` guard, expand the exclusion set to
include **every key of the `chainAliases` map** (both short and long forms:
`eth, ethereum, polygon, matic, arb, arbitrum, op, optimism, bnb, bsc, binance,
avax, avalanche, sol, solana, ftm, fantom, zksync, base, linea, celo, gnosis,
moonbeam, cronos`). `chainAliases` is declared later in the same function
(TDZ — cannot be referenced here), so hardcode the same alias keys inline (a
short code comment must point at `chainAliases` as the source of truth so the
two lists are kept in sync).

This is safe: the fallback is only reached when the primary word-boundary loop
found no token, so any token it would select via substring-of-a-chain-word is
by definition the bug, never a legitimate pick. A legitimate token that is a
whole word (e.g. `usdc on ethereum` → USDC) is found by the primary loop and
never reaches this fallback.

Do **not** touch: the primary token loop, the chain-parse block, trust rails,
the router, or `?token=`/`?chain=` direct-URL param handling (this only affects
free-text search-box parsing, not URL params).

## Build steps

1. Edit `app.js` — expand the `chainNames` array in the second token fallback.
2. `npm run compile && npm run minify` — regenerate `app.compiled.js` +
   `app.compiled.min.js` (prod loads the minified file via `home.html`). Commit
   the regenerated artifacts. (`@babel/core`, `terser`, `clean-css` must be
   installed — `npm install` the deps in `package.json`; they are not in the
   base sandbox image.)
3. Add `test_parser_chain_token.js` — extends the real-parser pattern
   (`test_helpers_parser.js` + `extractParser`, per spec 084). Assert the four
   offender queries above resolve to `token: ''` with the correct `chain`, plus
   a **regression** assert that a legit token before `on` still works
   (`usdc on ethereum` → token `USDC`, chain `Ethereum`). Add it to the
   `npm test` chain in `package.json`.
