# Spec 009: Instrument the waitlist funnel — it currently reports nothing

## Evidence
Found by the 008 build agent (008-notes.md): the "Join the waitlist →" CTA's onClick only flips local state (`setWaitlistOpen(true)`) and `submitWaitlist()`'s Formspree POST fires no analytics on success or failure. The monetization capture — the one CTA the whole checkout column optimizes for — is invisible in Mixpanel. Guardrail "planner conversion" can't extend to money-intent without this.

## Hypothesis
Not a growth experiment — pure instrumentation. Without it, 008's measurement ("waitlist engagement flat?") is unanswerable.

## Change
Smallest version, planner.js only:
1. Fire `waitlist_opened` (new event, properties: goal, persona, archetype) when the waitlist modal opens.
2. Fire `waitlist_submitted` (properties: goal, persona, archetype, success: true|false) on the Formspree response.
Add matching wrapper(s) in the Analytics object ONLY if the established pattern requires it (follow trackPlanCreated's shape in analytics.js). No UI changes, no copy changes, no new dependencies.

- [ ] `waitlist_opened` fires exactly once per modal open; `waitlist_submitted` fires exactly once per submit attempt with correct `success` value (trace file:line in notes)
