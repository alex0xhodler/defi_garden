## Goal
Stop the app from pinning the default TVL floor (`minTvl=10000000`) into every
`?token=`/`?chain=` URL it generates. Live evidence (heartbeat 2026-07-24,
`query_id 09fd9fb9`): crawlers re-walked indexed noisy URLs like
`?token=AVICI✨&minTvl=10000000` and `?token=INFINIFIUSDC&minTvl=10000000`. The
redundant default had leaked into externally-held / indexed links — noisier
canonicals, and old links that would pin $10M even if the default ever changes.

## Intuition
There are two halves to a URL param: **write** (serialize state → URL) and **read**
(URL → state). The read half already treats an *absent* `minTvl` as the $10M
default:

```
// app.js:927 — read
const minTvl = params.has('minTvl') ? parseInt(params.get('minTvl'), 10) : DEFAULT_MIN_TVL;
```

So "no param" and "param == 10000000" mean the *same thing* on the way in. The
write half, though, was emitting the default explicitly:

```
// app.js:945 (before) — write
if (minTvl > 0) params.set('minTvl', minTvl.toString());
```

That makes the default round-trip as visible noise. The fix simply teaches the
write half what the read half already knows: don't bother writing the value that
absence already implies.

## What changed (diff in reading order)

1. **app.js:945 — the one functional line.**
   ```diff
   - if (minTvl > 0) params.set('minTvl', minTvl.toString());
   + if (minTvl > 0 && minTvl !== DEFAULT_MIN_TVL) params.set('minTvl', minTvl.toString());
   ```
   `DEFAULT_MIN_TVL` (`10000000`, app.js:801) is in module scope here. Now the URL
   carries `minTvl` only when the user is on a *non-default* floor.

2. **app.compiled.js / app.compiled.min.js** — regenerated from source
   (`npm run compile && npm run minify`). home.html loads the `.min`. Verifier
   re-hashed both against a fresh build → byte-identical; min bundle contains
   `n>0&&n!==DEFAULT_MIN_TVL&&r.set("minTvl",…)`.

3. **test_minttvl_clean_url.js (new)** — rendered-Playwright acceptance, modeled on
   `test_plan_clean_url.js` (real Chromium, real UI, pools + snapshot fixture
   routes). 3 cases: (A) `/?token=USDC` settles to `?token=USDC` with NO
   `minTvl=10000000`; (B) bare `/?token=USDC` renders the >$10M USDC pools (floor
   still applies via the read path); (C) `?minTvl=50000` survives — a non-default
   floor is still serialized. Verifier proved the test *bites*: reverting the guard
   in the bundle makes Test A fail with `?token=USDC&minTvl=10000000`.

4. **package.json** — wires `node test_minttvl_clean_url.js` into `npm test` after
   `test_plan_clean_url.js`. No dependency changes.

## Why it's safe (trust rail + router)
- `DEFAULT_MIN_TVL` value is **unchanged** — the effective floor is still $10M; a
  bare `/?token=USDC` renders only >$10M pools (Test B). This is URL serialization
  only, never the floor itself.
- **Backward compatible.** Existing indexed/shared `?minTvl=10000000` links parse
  to `10000000 == DEFAULT_MIN_TVL` → identical floor *and* identical snapshot-first
  eligibility (app.js:1133 `urlParams.minTvl >= DEFAULT_MIN_TVL`, and an absent
  param defaults to exactly that). No parameterized-URL resolution regression; no
  SEO surface deleted or de-indexed (this is hygiene, not removal).
- **Non-default floors unaffected** — the $10k/$50k presets (app.js:3408/3423) and
  any user-chosen TVL chip are `!== DEFAULT_MIN_TVL`, so they still serialize.
