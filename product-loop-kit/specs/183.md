# Spec 183: give the rendered audit checks provenance and real north-star coverage

## Evidence

Both legs measured from this tick's `audit-app.js` run (`generatedAt` 2026-07-30T08:22:27Z), recorded in
`signals/2026-07-30.md`.

**(a) `dead-cta` findings carry no provenance.** The run's one blocking finding was, verbatim:
```
{ "surface": "pool-detail:ae6b7add", "check": "dead-cta", "severity": "P1",
  "detail": "\"Start Earning\" (.cta-button-protocol) missing or not visible" }
```
Classifying it took a live fetch of `https://api.llama.fi/protocols` (7,962 protocols / 5,181 url keys) and
a read of three call sites (`PoolDetail.js:583`, `:1662`, `app.js:2429`) to establish that the pool
resolves fine live and the finding is the **degraded path**, not a broken pool. The scanner had all the
information needed to say so — it knows whether the dynamic protocols fetch succeeded in its own browser
context — and said none of it.

Consequence, stated plainly: this exact P1 will recur on **every run** for as long as the harness blocks
`api.llama.fi`, indistinguishable from a real one. Item 171 built precisely this reconciliation for the
**pool prescan** (a promoted suspect that renders clean is auto-downgraded P1 → P2 with the reconciliation
recorded in the finding) and it has now worked correctly two days running on `201e5f6e`. The **rendered**
checks never got it.

**(b) The north-star surface is audited 3 pools deep out of 741.** `surfacesCovered` this run includes
exactly `pool-detail:201e5f6e`, `pool-detail:ae6b7add`, `pool-detail:2d1aa052` — and `201e5f6e` is present
only because the pool prescan promoted it. Pool-detail has been the north star since 2026-07-23
(NORTH_STAR line 16). It receives **0.4% coverage per run**, selected incidentally. `ae6b7add` — the pool
that surfaced item 182, the first defect the loop has found on the conversion surface itself — was luck.

This is item 154's own recorded limitation reappearing on the surface that matters most. `specs/154-notes.md`
states it verbatim: *"4 sampled token pages/day out of 2,079 ⇒ ~1.3%/day chance of hitting a specific
known-junk page — structural blindness removed, sampling rate still weak"*, and documents the fix
(prefer never-audited slugs / cheap prescan promotion) as **not built**.

## Hypothesis

We believe **recording why a rendered check failed, and rotating pool-detail coverage across
never-audited pools**, will **keep the audit's blocking findings actionable and raise the chance of finding
the next north-star-surface defect from luck to routine**, because (i) an unclassified recurring P1 trains
the loop to skim the gate — the alarm-fatigue failure 171 already fixed one class over — and (ii) a 0.4%
per-run sample of the conversion surface finds defects only by coincidence, which is exactly how 182 was
found. Confidence: **supported** for (a) — 171 is the shipped precedent on the same file; **supported** for
(b) — 154 documented both the limitation and the remedy.

## Change

**(a) Provenance on rendered CTA checks.**
- When `dead-cta` fires, record in the finding *why* the element was absent: whether the page's protocol
  resolution had a live dynamic map available, and which resolution tier (if any) produced a URL.
- Classify into exactly two reported kinds, mirroring 171's vocabulary:
  - **defect** — no tier resolves a URL for this project. Stays **P1, blocking**.
  - **environment** — a tier that exists in prod was unavailable in this run (the third-party host was
    blocked/failed). Downgraded to **P2, non-blocking**, with the reconciliation stated in `detail`,
    exactly as 171 does for `mean30d-rail-breach`.
- **The downgrade must never be the silent default.** If the scanner cannot determine which kind applies,
  it stays P1. A run in which every `dead-cta` is auto-downgraded without evidence is the failure this
  item exists to prevent — see the trap note below.

**(b) Rotate pool-detail coverage.**
- Extend the existing surface-selection logic so each run audits a small fixed number of pool-detail pages
  chosen **never-audited-first** from the snapshot, in addition to any the prescan promotes.
- Persist the audited-id set in a committed, bounded artifact so rotation survives a fresh clone (this is a
  cloud-clone loop — in-memory state does not carry between runs). Keep it small and append-only-on-change
  so it does not churn a daily Vercel deployment (the 087 churn-trap precedent).
- Wrap around when every id has been seen. Log the rotation position so a reader can tell coverage from
  luck.

**Explicitly OUT of scope**
- Any product code. `audit-app.js` and its own tests only — a diff touching `app.js`, `PoolDetail.js`,
  `planner.js`, the generators, or any generated surface is a verifier FAIL.
- Fixing item 182. This item makes the finding legible; 182 fixes the defect. **Land 182 first** — with 182
  shipped, leg (a)'s `defect` branch has a true negative to prove itself against, and a rotation that
  suddenly surfaces 216 pools' worth of missing CTAs would hold the gate red for the wrong reason.
- Raising the total surface count materially. Rotation replaces incidental selection; it is not a licence to
  audit 50 pool-detail pages per run and blow the runtime budget.

## Territory notes
<!-- Build loop appends findings from the blindspot pass here. -->

**T1 — item 182 landed between this spec being written and this build, and it invalidated leg (a)'s
literal premise.** 182 (merged as #339, commit `83e28459e`) added a CI-baked `data/protocol-urls.json`
tier to `getProtocolUrl()` **and** made `PoolDetail.js`'s `renderProtocolCtaBlock()` always render a
`.cta-button-protocol` element — the real "Start Earning on <project> ↗" CTA when any tier resolves, an
honest "View this pool on DefiLlama ↗" fallback (firing `defillama_fallback`, never `protocol_link`)
when none does. Measured on this checkout, baseline audit run 2026-07-30: **1 finding, 0 blocking, 29
surfaces** — the recurring `dead-cta` P1 this item was written to classify **no longer fires at all**.

Consequence: `dead-cta` can no longer be produced by protocol-URL resolution, so leg (a) as literally
specified ("when `dead-cta` fires, record why the element was absent") is a no-op. Worse, 182 left the
check **blind in the other direction**: the fallback button carries the *same* `.cta-button-protocol`
class, so a pool where half the north star (`protocol_link`) genuinely does not exist now audits clean.
Leg (a) is therefore built as: see the CTA's **shape** (real vs fallback vs missing), and attach the
resolution provenance + `defect`/`environment`/`undeterminable` classification to whichever finding
results. The classification decision rule and both branches' real instances are unchanged from the
spec's intent; only the triggering finding changed. Full deviation record in `183-notes.md`.

**T2 — the `defect` branch has exactly one real live instance, and it survived 182.** Of the 737 pools
in `data/pools-snapshot.json`, `data/protocol-urls.json` (schemaVersion 1, 475 keys) resolves all but
one: project `sdai`, pool `13392973-be6e-4b2f-bce9-4f7dd53d1c3a`, $55.5M TVL — absent from the baked
artifact *and* from the static `PROTOCOL_URLS` literal (`app.js:7`, ~96 entries). This is the spec's
named `sdai` case, still real post-182, and it is what keeps the `defect` branch non-vacuous.

**T3 — the baked artifact is generated from api.llama.fi only.** `generate-protocol-urls.js` contains no
reference to the static `PROTOCOL_URLS` map, so baked is *not* a superset of static: classification has
to consult both disk-side tiers or it will emit false `defect`s for any project covered only by the
hand-maintained static map.

**T4 — pool rotation already exists but is luck, not coverage.** `buildPoolSurfaces()` (spec 167) already
samples `DEFAULT_POOL_SAMPLE` rotation picks via `sampleBySeed(..., seed + ':pools')` with a date-derived
seed — consecutive days do differ (07-29: `ae6b7add`/`2d1aa052`; 07-30 baseline: `87c8ee0d`/`077b47b8`)
but nothing prevents repeats and nothing tracks what has been seen. Leg (b) replaces the candidate pool
with never-audited-first selection over committed state; the promotion path, the anchor block, and the
existing surface names stay untouched (167's own hard constraint).

**T5 — state artifact placement.** `product-loop-kit/signals/` is already committed daily by the
heartbeat (`audit-findings.json` lands there every tick), so rotation state riding in that same directory
costs **zero additional deploys** — the 087 churn trap is avoided by co-location plus a write-only-if-
bytes-differ guard, not by a new commit cadence.
