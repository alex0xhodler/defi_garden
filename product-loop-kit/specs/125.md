# 125 — Repeat the primary CTA after Pool Info (pool-detail)

**Status:** IN_PROGRESS · **Score:** 7.5 · **Risk:** MEDIUM · **North star:** pool-detail conversion clicks (`pool_click{source=garden_cta}` + `pool_click{source=protocol_link}`)

## Problem (documented evidence)
BACKLOG row 125: the pool-detail page is long — hero → 3 stat cards → Long Game → calculator → Pool Information — but the only "Garden this pool" / "Start Earning on <protocol>" CTAs live in the **top-right hero action card** (`PoolDetail.js:462-528`). A user who scrolls all the way down to read Pool Information must scroll back up to convert. The bottom of the page is a dead-end. This is directly upstream of the current north star (both CTA clicks) — a scrolled-away CTA that can't be reached without scrolling back is lost conversion, most acutely on mobile where the hero is far off-screen by the time Pool Info is read.

## Change (smallest that satisfies)
Add ONE **repeat CTA block after the Pool Information section** (the last child of the root `div`, `PoolDetail.js` ~L1539, just before the outer `);`). It mirrors the hero action card's two north-star CTAs so a reader who reaches the bottom can convert without scrolling back:

- Primary: **"Garden this pool"** — reuse the existing `.cta-button-primary` `<a>` with the same `gardenThisPoolHref`, same concrete/generic variant logic (`showConcreteCta`), firing `Analytics.trackPoolClick(pool, 'garden_cta', {...})`.
- Secondary: **"Start Earning on <protocol> ↗"** — reuse the existing `.cta-button-protocol` `<button>` (guarded on `protocolUrlWithRef`), firing `Analytics.trackPoolClick(pool, 'protocol_link', {...})`, same `window.open` behavior + muted hint.

**Instrumentation (placement measurability):** add a `ctaPlacement` prop to BOTH the hero and repeat `trackPoolClick` calls — hero = `'hero'`, repeat = `'repeat_footer'` — WITHOUT changing `source` (still `garden_cta`/`protocol_link`), so the north-star query (which filters on `source`) counts repeat-CTA clicks exactly like hero clicks, and a secondary breakdown by `ctaPlacement` reveals how much incremental conversion the repeat block drives. Additive property only — no rename, no event-name change.

**Decision — repeat inline CTA, NOT a sticky bottom bar.** The item says "after Pool Info **and/or** a sticky bottom bar (mobile)." The repeat block is the first branch, reuses existing components with ZERO new CSS, and carries no risk of overlapping footer content / covering the page / reduced-motion or fixed-position dark-mode edge cases. A sticky mobile bar is a heavier, higher-risk new UI element — deferred as a possible follow-up item, not built here (keep the diff tidy, per standing decision 2026-07-10 REUSE-COMPONENTS).

## Reuse (standing decision 2026-07-10)
- Wrapper: reuse `.pool-action-card` (neuro raised surface, already styled) with an inline `maxWidth: 420px` + `margin: 32px auto 0` so it's a centered, contained card rather than a full-bleed block. NO new CSS class.
- Buttons: reuse `.cta-button-primary`, `.cta-button-protocol`, `.pool-action-hint`, `.pool-action-hint--muted` verbatim.
- Copy: reuse existing translation keys — `gardenThisPoolCta` / `gardenThisPoolCtaConcrete`, `plannerCtaHint`, `startEarningOn`, `opensProtocol`. Optional ONE new heading key `repeatCtaHeading` ("Ready to start this garden?" / natural KO) — if added, EN+KO together in `translations.js`.
