# Spec 096: Signal integrity — environment-gate Mixpanel tracking to production hostnames

## Evidence
(signals/2026-07-14.md, second pull — live Mixpanel, project 4042048)
- `share_link_opened` last 2 days: **13/13 events from `http://localhost:*`** (ports 8003/8794/8799). Zero real share opens have ever fired.
- `plan_created` last 2 days: **11/11 localhost**; `plan_saved`: 12/12 localhost. The 07-14 "spike" (plan_created 10) was entirely dev/test.
- `session_start` 07-09→11: `localhost:8792/home.html?app=analytics` alone = **114 of 327** events; Vercel preview deploys (`defi-garden-*-alexs-projects-*.vercel.app`) add ~2 each.
- Restated real prod traffic (page_url contains www.defi.garden): 7 / 6 / 10 / 16 / 11 / 5 per day 07-09→14 — the prior "spike/collapse/rebound" narratives were all test-traffic artifacts.
- The contamination source is browsers on the human's machine running local servers (localhost/127.0.0.1) and preview-deploy visits — analytics.js fires `mixpanel.track` unconditionally when the `mixpanel` global exists (analytics.js:46-57).

## Hypothesis
We believe suppressing Mixpanel tracking on non-production hostnames will make every future metric read honest-by-default (no filter discipline required, no test pollution of the north-star funnel or the open 061/065/068/005/007/008 measurement windows) because 100% of the observed contamination carries a non-production `page_url` hostname. Confidence: supported (the split was verified event-by-event via page_url breakdowns).

## Change
Smallest version: a single hostname allowlist gate at the one choke point, `Analytics.track()` in `analytics.js`.
- Allowlist (exact or `*.` suffix match): `defi.garden`, `www.defi.garden`, `yield.garden`, `www.yield.garden` (yield.garden is a live production mirror that received the 07-09 launch traffic — keep tracking it unless 097 retires it).
- Non-allowlisted hosts (`localhost`, `127.0.0.1`, `*.vercel.app` previews, `file:`): `track()` returns early — no event sent. One `console.debug('[analytics] suppressed (non-production host)')` on first suppression so local devs aren't confused.
- Gate `startSession()`/auto-init implicitly via `track()` — do NOT add per-call-site checks.
- OUT of scope: deleting/re-labelling historical contaminated events (heartbeats filter `page_url` retroactively instead); a separate dev Mixpanel project; touching the mixpanel loader snippet in home.html/plan.html; any generated-page regeneration beyond what the repo's existing artifact pipeline requires (analytics.js ships raw — verify whether any `.min` or generated copies embed it and regenerate only those that do).

## Acceptance criteria
- [ ] `Analytics.track()` in analytics.js returns without calling `mixpanel.track` when `location.hostname` is not on the production allowlist; sends normally when it is (unit-testable by stubbing `window.location`/`mixpanel`).
- [ ] Allowlist covers exactly: defi.garden, www.defi.garden, yield.garden, www.yield.garden. `localhost`, `127.0.0.1`, and `defi-garden-anything.vercel.app` are suppressed.
- [ ] A rendered Playwright run against a local server (existing fixture-routing pattern) proves zero `api.mixpanel.com`/`mixpanel.track` calls fire from a localhost page load that previously fired `session_start` (mutation check: removing the gate makes the assertion fail).
- [ ] Every page that loads analytics (home.html, plan.html, generated /tokens/ + /chains/ + stories pages via their bootstrap) gets the gate through the shared analytics.js — verify no page embeds a private copy of `track()` that bypasses it.
- [ ] Tests: new test file in the npm chain; existing chain stays green.
- [ ] Instrumentation: this item REMOVES noise rather than adding events; no new event names.
