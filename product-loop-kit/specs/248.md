# Spec 248: `resultsColApy`/`resultsColTvl` are allowlist omissions, not untranslated copy — close the live P1 the way the dictionary already answers it

## Evidence

`audit-app.js` full run **2026-08-07T07:19:37.517Z**, 83 surfaces:

```
[P1] i18n :: i18n:en-ko-parity — 2 of 544 translation keys match en-ko-parity
     (allowlist: 24 keys) — examples:
       resultsColApy: ko value contains no Hangul and is byte-identical to en: "APY"
       resultsColTvl: ko value contains no Hangul and is byte-identical to en: "TVL"
```

Yesterday's run: **540 scanned / 0 suspects**. Today: **544 scanned / 2 suspects**. The four new keys and
both suspects were introduced by ONE commit — `75f7470646` (item **225**, the design reset, merged to main
2026-08-06T13:00 UTC), confirmed by `git log -S"resultsColApy" -- translations.js`.

Population measured, not assumed — 225 added **5 keys in both namespaces**, and **3 of the 5** have
byte-identical EN/KO values:

| key | value | caught by the gate? |
|---|---|---|
| `resultsColApy` | `"APY"` | yes (string leaf) |
| `resultsColTvl` | `"TVL"` | yes (string leaf) |
| `onProtocolChain` | `` (protocol, chain) => `${protocol} · ${chain}` `` | **no — function leaf** |

(`resultsColPool` was translated correctly: `"Pool"` → `"풀"`.) The third miss is item **249**, not this one.

**The dictionary already answers whether these are defects, and the answer is no.** `translations.js`'s KO
namespace renders these acronyms bare, consistently, in six places, and `audit-app.js`'s
`I18N_UNTRANSLATED_ALLOWLIST` (`:961-986`) already blesses every one of them with the same reason string:

```
navFilterTvl: 'acronym, same in KO'      ko: navFilterApy = "APY"
navFilterApy: 'acronym, same in KO'      ko: navFilterTvl = "TVL"
tvl:          'acronym, same in KO'      ko: tvl          = "TVL"
planner.poolApy: 'acronym, same in KO'   ko: planner.poolApy = "APY"
planner.poolTvl: 'acronym, same in KO'
tcpColApy:    'acronym, same in KO'   <-- the token/chain-page COLUMN HEADER for APY
tcpColTvl:    'acronym, same in KO'   <-- the token/chain-page COLUMN HEADER for TVL
```

`tcpColApy`/`tcpColTvl` are the *same semantic object* as `resultsColApy`/`resultsColTvl` — a results-table
column header for the APY/TVL acronym — already allowlisted. So this is an **allowlist omission introduced
alongside a new key family**, not untranslated Korean shipped to users.

## Hypothesis

We believe adding `resultsColApy`/`resultsColTvl` to `I18N_UNTRANSLATED_ALLOWLIST` with the existing
`'acronym, same in KO'` reason will clear the live P1 without weakening the gate, because six precedents in
the same allowlist — including the two token/chain-page column headers for these exact two acronyms — already
establish that a bare `"APY"`/`"TVL"` in KO is the dictionary's intended, consistent rendering.
Confidence: **supported** (six in-dictionary precedents + the gate's own documented allowlist purpose).

- **Instance of:** allowlist coverage lagging a new key family — the gate's exemption set is keyed by exact
  flattened key path, so every new surface that adds an APY/TVL column header needs a new line.
- **Class closed by this item:** **no.** After this change **8 of 26 allowlist entries (30.8%)** are
  "the acronym APY or TVL on some surface" (`navFilterApy`, `navFilterTvl`, `tvl`, `planner.poolApy`,
  `planner.poolTvl`, `tcpColApy`, `tcpColTvl`, + these 2). The next surface that renders an APY/TVL header
  adds a 9th. The weaker mechanism — exempt by VALUE over the bounded acronym set `{"APY","TVL"}` rather
  than by key path — is **deliberately NOT taken here** (see Open questions); the residual is stated with
  its number rather than silently absorbed.

## Change

Smallest version: **two lines** in `audit-app.js`'s `I18N_UNTRANSLATED_ALLOWLIST` (`:961-986`), placed
beside the existing `tcpColApy`/`tcpColTvl` entries and carrying the identical reason string:

```js
  resultsColApy: 'acronym, same in KO',
  resultsColTvl: 'acronym, same in KO',
```

**Explicitly OUT of scope:**
- Changing any KO or EN value in `translations.js`. The values are correct and consistent; a Korean gloss
  (e.g. `연이율(APY)`) would make KO *more* explanatory than the EN it mirrors, an asymmetry no other
  acronym key in this dictionary carries.
- Changing the allowlist's exact-key-path matching rule (that is the Open question, and item 249's
  territory is the adjacent one).
- `onProtocolChain` and the function-leaf blind spot → item **249**.

## Open questions

None blocking. One recorded for the human/next builder, **not** to be resolved inside this item: the
allowlist is keyed by exact flattened key path by explicit design (`audit-app.js:955-960` — "never a prefix
or substring match"), which is why 30.8% of it is now one repeated acronym pair. Exempting by VALUE over
`{"APY","TVL"}` would collapse 8 entries to 1 rule and cover every future surface for free, but it trades
away the per-key auditability the current design was chosen for, and `playbooks/guard-exemption-rate.md`'s
threshold (~⅓ before the mechanism itself is wrong) is approached but **not crossed** — 30.8% of a 26-entry
exemption set against a 391-string-key population is a **6.6%** exemption rate. So the narrow fix is correct
today; re-ask when a 9th acronym entry lands.
