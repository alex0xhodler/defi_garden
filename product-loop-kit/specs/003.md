# Spec 003: `npm test` smoke gate — make "tests green" mean the app actually renders

## Evidence
Autonomy level (b) auto-merges LOW items on tests-green + verifier PASS, but the only tests are three node unit files covering planner helpers — nothing proves the two sacred router paths render. CLAUDE.md requires verifying both router paths after any change near the router; today that check is manual.

## Hypothesis
We believe a Playwright smoke script wired into `npm test` gives auto-merge a real red/green and catches router regressions before loops can ship them. Confidence: supported — CLAUDE.md notes a working Playwright setup is typically at /tmp/neuro-shots.

## Change
Add Playwright as a devDependency and a smoke script asserting: (1) `/` renders the planner UI, (2) `/?token=USDC` renders pool cards, (3) no page errors (external font/analytics fetch failures are ignorable per CLAUDE.md), at 360/768/1280 widths. Wire `npm test` = the three existing node unit files + the smoke script. OUT of scope: full E2E suite, CI wiring, screenshot review automation.

## Acceptance criteria
- [ ] `npm test` exits 0 on a clean checkout in under ~2 minutes (document actual runtime)
- [ ] Sabotage check (verifier reproduces): temporarily breaking the router decision in `home.html` makes `npm test` exit non-zero; reverting restores green
- [ ] Diff touches only `package.json`, `package-lock.json`, and new test files — zero product-code changes
- [ ] The three existing node test files run as part of `npm test` and still pass
