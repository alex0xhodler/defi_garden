# 148 — PR explainer (risk tier: HIGH)

## Goal

Stop the static SEO generators from minting landing pages for strings that are not tokens.
A Pendle principal token is named `PT-SUSDE-22OCT2026`. The generator splits symbols on `-`, so that
one pool contributed three "tokens": `PT`, `SUSDE`, and the expiry date `22OCT2026` — and the third one
earned a real page, a Korean page, an OG card, a sitemap entry and an IndexNow submission, reading
verbatim:

> `<h1>8OCT2026 DeFi Yields</h1>` — *"4 live 8OCT2026 pools above the $100K TVL floor, up to 0.20% APY…"*

Seven such slugs were live on the committed surface: `8oct2026`, `17dec2026`, `2027`, `20261231`,
`00`, `01`, `67`. Crawlers were already walking the class — Mixpanel recorded a real `page_view` on
`?poolTypes=Lending&token=22OCT2026` in the last 7 days.

## The intuition

`isValidToken()` was a *shape* check (`/^[A-Z0-9][A-Z0-9.\-_]{1,14}$/i`) standing in for a *meaning*
check. Every date fragment and every pure-digit run satisfies the shape. The fix does not try to
recognise real tokens — an unwinnable problem — it rejects the two shapes that provably cannot be
tokens, and nothing else. That conservatism is the whole design: a greedier rule silently deletes real
ticker pages, which is far worse than leaving a few junk ones standing.

## What changed, in reading order

**1. `generate-token-pages.js`** — two named constants next to the existing `TOKEN_REGEX`, and three
lines in `isValidToken()`:

```js
const PURE_NUMERIC_REGEX  = /^[0-9]+$/;
const DATE_FRAGMENT_REGEX = /^[0-9]{1,2}(JAN|FEB|…|DEC)[0-9]{2,4}$/i;

function isValidToken(symbol) {
  if (!symbol) return false;
  if (!TOKEN_REGEX.test(symbol)) return false;
  if (PURE_NUMERIC_REGEX.test(symbol)) return false;   // "2027", "00", "67"
  if (DATE_FRAGMENT_REGEX.test(symbol)) return false;  // "22OCT2026", "16SEP26"
  return true;
}
```

Note what is *not* rejected: a symbol that merely **starts** with a digit. `1W`, `4W`, `13W`,
`50EIGEN`, `40AVAX`, `0X0`, `3CRV`, `1INCH` are all live slugs today and all still pass. The predicate
runs on the **symbol**, before `tokenSlug()` lowercases it — running it after would have made the
pure-numeric rule ambiguous.

**2. `generate-sitemap.js`** — the same rules in its own `isValidToken()`. The two functions are a
documented mirror pair (duplicated on purpose; `generate-chain-pages.js` imports the token-pages copy,
so there are exactly two definitions, not three). `isValidToken` is now in that file's `module.exports`
— it was unexported before, which is why nothing had ever tested it.

**3. `test_token_slug_validity.js`** (new, 66 assertions, wired into `npm test` after
`test_token_pages.js`) — runs every case against **both** mirrors, so a future drift between them fails
loudly instead of quietly leaking junk through one generator. Three layers:
- negative list (the 8 live date fragments + the pure-numeric slugs + lowercase variants),
- positive list (the digit-leading real tickers above — the "did the regex eat a real ticker" guard),
- an end-to-end `rankTopTokens()` run on a `PT-SUSDE-22OCT2026` fixture asserting `PT` and `SUSDE`
  survive and `22OCT2026` does not.

**4. Regenerated SEO surface** — produced by the sanctioned generators only, driving CI's exact
pipeline (`generate-pools-snapshot.js --seo-out` → token pages → chain pages → sitemap → llms).

## The measurement that matters

The junk set churns daily, so a before/after taken across two different fetches proves nothing. Both
runs used **one shared fixture** — baseline from `origin/main` in an isolated worktree, fixed in the
working tree:

| | token pages | sitemap `<loc>` |
|---|---|---|
| baseline (old predicate) | 2081 | 2109 |
| fixed (new predicate) | **2074** | **2102** |
| dropped | **7** | 7 |
| **added** | **0** | 0 |

Dropped: `00 01 17dec2026 20261231 2027 67 8oct2026` — every one pure-numeric or date-shaped. The empty
added-set is the real guarantee: the predicate removed junk and moved nothing else.

## Deviations from the spec

1. **The spec expected orphan files to need a manual prune.** They didn't: `generate-token-pages.js`
   (line 966) wipes every `.html` in its out dir before rewriting, and `generate-og-images.js` does the
   same for OG cards. The regen removed the seven junk pages by itself; a post-hoc predicate audit over
   the surviving pages found zero orphans.
2. **The tree diff also drops 19 real tickers** (`ens`, `toke`, `xsushi`, `ilv`, …) and adds 11 new
   ones. This is daily TVL churn, not the predicate — those tokens crossed the $100K floor between the
   committed 07:00 UTC bake and this regen. It is exactly what the daily CI commit does routinely
   (`3828f9e63` deleted `tokens/cbada.html` and `tokens/dfi.html` with no code change at all). The
   acceptance criterion's "drops by exactly the rejected slugs" is satisfied by the controlled
   same-fixture measurement above, which is the only churn-free way to read it.
3. **`20weth` / `20aaveprimeweth` were not cleared.** The spec guessed they were `%20`-encoding residue
   from an old dataset. They are not — both are reproducible from today's live data and both are
   legitimately valid under the new predicate (digit-leading, not pure-numeric, not date-shaped).

## Why this is NOT merged

NORTH_STAR's NEVER list includes *"deleting or de-indexing SEO surface"* — no exceptions, regardless of
verifier verdict. This diff removes 7 URLs from the sitemap and deletes their pages. The spec's own risk
section (and open question 1) flags the operator's read — that this completes item 013's already-sanctioned
sitemap-quality mandate rather than being a new de-indexing decision — as **a question for the human, not
a build decision**. So the PR is open and unmerged, and the item is BLOCKED pending that one answer.

Everything is built, tested and verified; the only thing missing is the human's yes.

## Guardrails unchanged

`MIN_POOL_TVL`, `APY_SANITY_LIMIT`, `MIN_QUALIFYING_POOLS`, `tokenSlug`, `tokenSymbols` byte-identical.
No new dependency. No `?token=` app behavior change — a user typing `?token=8OCT2026` still gets whatever
the app honestly returns; only the generated static surface changed. `/tokens/pt` deliberately untouched
(bug-class 8: honest labels — flag, don't auto-fix).
