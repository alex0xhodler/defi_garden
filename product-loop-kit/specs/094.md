# Spec 094: Pool-row iconography — protocol + chain logos on each row/card

## Evidence
- Human ticket, Analytics-UX audit batch (2026-07-14): pool rows show text-only badges (`ON MAPLE • ETHEREUM`) with zero visual protocol/chain identity — the last un-shipped item of the 089–095 audit (siblings 089/090/091/092/093/095 all SHIPPED).
- Current markup: `renderPoolCard` (`app.js:2561`) renders `pool-context-inline` = `t('onProtocolChain', pool.project, pool.chain, protocolUrl)` — a text-only link, no imagery. Shared by grid AND list views.
- Signal state 2026-07-15: north star `waitlist_submitted` = 0 (structurally absent from the 18-event lexicon); real prod traffic a flat ~5–16 sessions/day trickle; guardrail `error_occurred` 0 since the 07-13 one-off (082 holding). No new signal — this is a queued human-requested UX/trust item, the only READY build candidate.

## Hypothesis
We believe adding a small protocol + chain logo to each pool row/card will make the browse grid faster to scan and read as more credible (SOTA yield tables all carry protocol imagery) because the cautious-saver ICP recognizes brands visually before parsing text. Confidence: **guess** (no isolable Mixpanel funnel metric at current traffic — this is a clarity/credibility default in the analytics app, same disclosure class as 089/091/092/093/095).

## Change
Add a **decorative** protocol logo (and a small chain logo) to the pool-row identity block, in the ONE shared `renderPoolCard` path so grid + list both get it. Smallest honest version:
- **Icon source (decided): DefiLlama icon CDN, lazy + graceful fallback** — NOT a bundled logo set (2,000+ protocols; bundling is unmaintainable and bloats the payload). Load `<img loading="lazy">` from DefiLlama's icon host; on `error`/missing, fall back to a **monogram glyph** (first letter of `pool.project` in a neuro-token chip). This satisfies the item's "no new blocking third-party critical-path dep — lazy, `loading=lazy`, works offline" requirement: icons never block render, never enter the critical path, and a pool with no/broken icon still reads perfectly via the monogram + the existing text badge (which STAYS — the logo augments, never replaces it).
- **No layout shift:** fixed-size box (e.g. 20–24px square) with `object-fit: contain` and reserved dimensions, so a slow/failed image never reflows the row.
- **Trust rail:** icons are purely decorative. They must NOT affect pool ordering, filtering, the displayed APY/TVL numbers, anomaly flags, or the 092 "No supply yield" demotion. Reads `pool.project`/`pool.chain` only.

**Out of scope:** token/symbol logos (only protocol + chain); any change to numbers, sort, filters, trust rails; bundling a local icon set; SEO static-page rows (`/tokens/`, `/chains/` — those are separate generators, not `renderPoolCard`); prefetch/preconnect tuning.
