# 163 — Make `npm test` observable: a runner that preflights deps, never stops at the first red, and reports every file

Status: promoted by the build loop 2026-07-27 (no takeable READY item existed — 148, the only
`READY` row, is in flight as human-gated PR #306; 010-diagnosis's ranked fixes 011-015 are all
DONE; the newest report's build order 159 → 160 has shipped, as has 162).

## Problem

`package.json`'s `test` script is **94 `node <file>.js` steps chained with `&&`**. Two structural
consequences, both measured this run, not inferred:

**(1) A fresh clone fails at position 5 with a raw stack trace.** Every cloud-routine session
starts from a clone with no `node_modules`. Running the plain (non-browser) subset in that state:

```
PLAIN LANE (fresh clone, no node_modules): pass=19 fail=17
```

Every one of the 17 is `MODULE_NOT_FOUND` inside a *generator* the test requires — e.g.
`test_llms_rails.js` → `generate-llms.js:12`, `test_compiled_assets.js` → `compile-app.js:30`,
`test_token_pages.js` → `generate-og-images.js:28`. The chain's first casualty is position 5
(`test_compiled_assets.js`), so on a fresh clone `npm test` reports a Node module-resolution stack
and stops, having executed 4 of 94 files. This is exactly item **149**'s finding
(`audit-app.js` dying `MODULE_NOT_FOUND: playwright` in any checkout without `node_modules`)
generalised from one file to the ship gate itself. After `npm ci` (67 packages, 3s) the same
lane is **34 pass / 2 fail**, and both remaining failures are my 90s cap firing on files that
transitively drive a real browser — i.e. **the product's non-browser tests are green and the
fresh-clone reds were entirely environmental.**

**(2) `&&` means nothing after the first red is ever observed.** `specs/158-notes.md` records
this in the loop's own words: *"no known red remains at positions 1-12; the chain has never been
observed past position 12 in-sandbox"* — and positions 9-12 are heavy real-Chromium files that
alone exceed the 5-minute foreground timebox (the verifier needed a 550s cap to get
`test_search.js` green). So **82 of 94 files, including trust-rail tests
(`test_llms_rails.js`, `test_mean30d_sanity.js`, `test_zero_yield_demote.js`,
`test_kpi_rail_history.js`), have no observed result in any recent build session.**

**Why this outranks a feature.** The standing autonomy decision (2026-07-10, ratcheted (c)) is
*"verifier PASS + **tests green** → merge to main, ANY tier"*. "Tests green" is the only
automated half of that gate, and it is currently unverifiable by construction: a run either dies
on missing deps, or dies at the first red, or times out at position 12. Under the 2026-07-23
PRE-TRAFFIC MANDATE the loop's primary job is product quality — and the 82 unobserved files are
the largest single body of unread quality signal in the repo.

## Non-goals (explicitly out of scope for this item)

- Fixing any red the runner newly reveals. Reveal, record in the notes, ticket it — one item, one
  change. A red found is data for the next item, not scope creep for this one.
- Speeding up the browser suite, sharding it, or changing any test's assertions.
- Touching any product file, any generated SEO surface, or any dependency.

## Design

New `run-tests.js` (plain Node, **no new dependency**, `child_process` only) becomes `npm test`.

1. **Single source of truth for the file list.** `package.json` keeps the original 94-step
   `&&` chain verbatim under a new script `test:serial`. `run-tests.js` **parses that string**
   for its file list rather than holding a second copy — so a file can never be silently dropped
   from the gate, and A1 can assert exact equality.
2. **Preflight.** If `node_modules` is absent, print ONE actionable line
   (`dependencies not installed — run \`npm ci\``) and exit **2** without executing any test file.
   No 94 stack traces.
3. **Run everything.** Each file runs in its own child process; a failure never aborts the run.
4. **Lanes.** `--lane=plain|browser|all` (default `all`). Classification is a **transitive scan of
   local requires** (depth-limited, cycle-safe): a file is `browser` if it, or any `./`-relative
   module it requires, mentions `playwright`. A naive one-level grep is not sufficient and this is
   the concrete case that proves it — `test_seo_surface_audit.js` and `test_audit_prescan.js`
   contain no `playwright` string but require `./audit-app.js`, which drives real Chromium.
5. **Per-file timeout** (`--timeout=<s>`, default 120): kill the child, record `TIMEOUT`, continue.
6. **Parallelism** (`--jobs=<n>`): default `min(4, cpus-1)` for the plain lane, **1** for the
   browser lane (real Chromium files bind fixed ports — `audit-app.js` defaults to 8821 and
   `162-notes.md` records a live `EADDRINUSE` collision between two concurrent sessions; parallel
   browser files would reintroduce that race).
7. **Report.** Per-file `PASS/FAIL/TIMEOUT` + duration, a summary count, and the failing files'
   last output lines. Exit non-zero iff any file failed or timed out. `--json=<path>` optional,
   written only when asked (a default write would dirty the tree on every run).
8. `--list` prints the resolved file list + lane per file and exits 0.

## Acceptance criteria

Not a UX item — no rendered product surface changes, so the 2026-07-11 Playwright-on-real-UI rule
does not apply. It is replaced by a stricter bar: **every criterion below must be demonstrated by
running the runner, and A3/A5 must be mutation-proved (deliberately break something, watch the
runner catch it, restore, confirm byte-identical).**

- **A1 — no file lost.** `node run-tests.js --list` yields exactly the 94 files of
  `package.json`'s `test:serial` chain, same order, no additions or omissions. Asserted
  programmatically against the parsed script string, not eyeballed.
- **A2 — fresh-clone honesty.** With `node_modules` temporarily moved aside, `node run-tests.js`
  exits **2**, prints one actionable line, and executes **zero** test files (prove zero: no test
  file's output appears). Restore `node_modules` afterwards.
- **A3 — a red does not abort the run (mutation-proved).** Inject a deliberate failure into one
  plain-lane file, run `--lane=plain`, and show (a) every other plain file still executed,
  (b) the summary lists the injected file as FAIL, (c) exit code non-zero. Restore the file and
  confirm byte-identical (`md5sum` before/after).
- **A4 — lane classification is transitive.** `--list` places `test_seo_surface_audit.js` and
  `test_audit_prescan.js` in the **browser** lane despite neither file containing the string
  `playwright`, and places `test_llms_rails.js` / `test_planner.js` in **plain**. Lane counts are
  reported; the plain lane must contain no file that transitively requires playwright.
- **A5 — timeout is enforced (mutation-proved).** A fixture that sleeps beyond `--timeout` is
  recorded `TIMEOUT`, the run continues to the next file, and the exit code is non-zero.
- **A6 — plain lane is green and fast.** `node run-tests.js --lane=plain` completes inside the
  5-minute foreground timebox and reports the true pass/fail counts. Record the exact numbers in
  the notes. If any product red is revealed, record it verbatim and ticket it — do not fix it.
- **A7 — browser lane, honestly bounded.** Full browser-lane execution (58 files, real Chromium)
  is **expected to exceed the timebox**. Demonstrate the lane works on a **named subset**
  (`--only=` or an explicit file list) and state plainly in the notes what was not run. A claim
  that the full chain is green is a FAIL; the honest bounded claim is the deliverable.
- **A8 — `npm test` still gates.** `npm test` runs the runner, exits 0 only when every file
  passed, non-zero otherwise. `test:serial` still exists and still contains the original chain.
- **A9 — new test file.** `test_run_tests.js` covers A1, A3, A4 and A5 with local fixtures (no
  network, no browser), is wired into the chain, and is itself in the plain lane.
- **A10 — scope.** Diff touches only `run-tests.js` (new), `test_run_tests.js` (new),
  `package.json` scripts, and `product-loop-kit/` bookkeeping. **No** product file
  (`app.js`, `planner.js`, `PoolDetail.js`, `home.html`, `plan.html`, `translations.js`, any CSS),
  **no** generated SEO surface (`sitemap*.xml`, `tokens/`, `chains/`, `stories/`, `llms*.txt`,
  `og/`), **no** dependency added or changed, **no** trust-rail constant touched, no
  `.github/workflows/` change.

No funnel metric — this is a gate-integrity fix, not a growth change (the 020/048 precedent:

ticket. No 14-day window is opened.

## Territory notes

- `NODE_PATH=/opt/node22/lib/node_modules` makes globally-installed `playwright` resolvable in a
  fresh clone (item 149's workaround). The runner should NOT bake that in — `npm ci` is the
  correct fix and takes 3 seconds; the preflight is what makes that discoverable.
- Files 89-94 are the audit-suite tests added by items 154/157/160/162; several scope
  `runAudit()` with explicit `only:` allowlists and bind a fixed port. Browser lane, serial.
- `test_search.js` (position 12) needs ~550s standalone (`158-notes.md` verifier addendum) — it
  is the reason a per-file timeout must be configurable rather than fixed.
