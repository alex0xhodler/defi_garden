# Spec 063: Waitlist funnel drop-off instrumentation

## North-star alignment
North star = `waitlist_submitted`. 009 fires `waitlist_opened` + `waitlist_submitted`, but the gap between them is invisible — we can't see WHERE people abandon (email focus, validation error, second-thought). "You can't optimize a funnel you can't see" (the 020 lesson).

## Hypothesis
Instrumenting the intermediate waitlist steps + failure reasons surfaces the leak so the next conversion item is evidence-driven, not guessed.

## Change (planner.js — instrumentation only)
- Between `waitlist_opened` and `waitlist_submitted`, add: `waitlist_email_entered` (first focus/keystroke), `waitlist_submit_attempt`, and `waitlist_error({ reason })` (empty email / invalid / network / formspree non-ok). Keep 009's events unchanged. Reuse the existing Analytics pattern.
- No UX/behavior change; events only.

## Acceptance criteria
- [ ] The 3 new events fire on the right transitions (Playwright drives the real waitlist form); 009's events unchanged
- [ ] `waitlist_error` carries a `reason`; no PII beyond what 009 already sends
- [ ] test chain + test_smoke exit 0
- Metric: opened → email_entered → submit_attempt → submitted funnel; error-reason breakdown. Enabling instrumentation; decision rule = the next waitlist item targets the biggest observed drop.

## Risk tier
LOW — analytics instrumentation, no behavior change.
