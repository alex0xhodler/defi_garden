## Territory notes (verified in code 2026-07-15 — these BIND the design)

1. **Why the KPI notes hide on `?pool=` today.** `snapshotEligible = !urlParams.pool && …`
   (app.js:1132) forces ANY `?pool=<id>` deep link onto the LIVE `/pools` fetch
   (app.js:1088). Live DefiLlama data has NO `kpis` field, so `detailPool.kpis` is
   undefined and both 088.1's `.rate-track-record-note` (PoolDetail.js:1325) and 103's
   `.rate-momentum-note` (PoolDetail.js:1373) render nothing. In-app browse→detail carries
   `kpis` because `pools` came from the snapshot (which carries per-pool `kpis`, keyed by
   `pool.pool`, verified: `{historyPoints,firstSeen,apyMomentum,apyStdev,tvlTrend}`).
2. **The snapshot is the kpis source of truth.** `data/pools-snapshot.json`
   (`schemaVersion:1`, `pools[]`) carries `kpis` on each railed (≥$10M, sanity/anomaly
   filtered) pool, keyed by the same `pool.pool` UUID the deep link resolves against.
3. **`kpis` are slow-moving derived signals.** historyPoints/apyStdev/apyMomentum come
   from 087's retained daily history, not the live rate. The 15-min snapshot-meta
   freshness gate exists to keep the POOL LIST current for the perf path; it is not
   needed for kpis enrichment (a few-hours-stale track-record count is immaterial, and
   071's live-data volatility note takes precedence over both kpis notes anyway). So the
   enrichment reads the snapshot directly, no meta gate — simpler, and any failure leaves
   `detailPool` untouched (notes hide exactly as today).
4. **Compiled/minified artifacts.** home.html loads `app.compiled.min.js`. Editing
   `app.js` REQUIRES `npm run compile && npm run minify` or
   `test_compiled_assets.js`/`test_minified_assets.js` fail (052/053 precedent). PoolDetail
   and translations are UNCHANGED (this item adds no copy, no render logic — it only feeds
   `kpis` into the pool object the already-shipped notes read).

## Acceptance criteria

**A. Enrichment effect (`app.js`), purely additive.** A new `useEffect` that, when the
pool-detail view is active (`currentView === 'pool-detail'`) and `detailPool` exists but
carries no `kpis`, fetches `/data/pools-snapshot.json` once, finds the pool by
`pool.pool === detailPool.pool`, and — only if a matching pool with a real `kpis` object
is found — merges just that `kpis` onto `detailPool` via a functional `setDetailPool`
update. A `useRef` guards against refetching for the same pool id (no render loop). Any
failure (fetch error, non-ok, bad schema, pool absent from snapshot, no `kpis`) leaves
`detailPool` untouched.
- A1. Fires ONLY when `detailPool` has no `kpis` — in-app browse→detail (already carries
  kpis from the snapshot) short-circuits immediately; no redundant fetch.
- A2. Enriches ONLY the single `detailPool` object. It NEVER mutates the `pools` array,
  never filters/reorders/re-weights/re-flags a pool, and never reads or writes the rail
  constants (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly/haircut logic). Trust rails
  byte-untouched.
- A3. A pool present live but ABSENT from the snapshot (e.g. below the $10M floor, or a
  dead `?pool=`) yields no match → `detailPool` unchanged → notes stay hidden (honest).
- A4. Guarded by a `useRef` on the enriched pool id so the effect re-run triggered by its
  own `setDetailPool` short-circuits (the merged pool now has `kpis`) — no loop, no double
  fetch.

**B. No copy, no PoolDetail change.** This item adds ZERO translations and ZERO render
logic. The 088.1 + 103 notes already read `pool.kpis.*`; feeding them the kpis is the
whole change. (If the notes needed changes they would be separate items.)

**C. Artifacts regenerated in the same commit.** `npm run compile && npm run minify` →
`app.compiled.js`, `app.compiled.min.js` regenerated (byte-consistent with the source).

**D. Rendered-Playwright acceptance (`test_kpi_seo_enrichment.js`, mirrors
`test_kpi_track_record.js`).** Drives the REAL pool-detail UI via `?pool=<id>`, routing the
LIVE `/pools` fetch to a fixture WITHOUT kpis (real SEO-landing shape) and
`/data/pools-snapshot.json` to a FRESH fixture snapshot WITH kpis, asserting on the
rendered `.rate-track-record-note` DOM:
- D1. `?pool=<id>` where the pool is in BOTH the live fixture (no kpis) and the snapshot
  (hp:1) → `.rate-track-record-note` PRESENT with NEW-tier copy. (The core enrichment: an
  SEO landing now shows the trust signal it could not before.)
- D2. `?pool=<id>` where the pool is in the live fixture but ABSENT from the snapshot →
  `.rate-track-record-note` ABSENT (honest — no fabricated kpis).
- D3. `?pool=<id>` where the pool is in BOTH, snapshot kpis hp:30/steady → STEADY-tier
  copy incl. "30" (proves the merged kpis drive tier selection, not just presence).
- D4. Baseline regression: with the snapshot route returning a pool WITHOUT a `kpis` field
  → note ABSENT (enrichment only ever ADDS a real kpis object, never a placeholder).
- D5. Zero page errors across all renders.
Add `test_kpi_seo_enrichment.js` to `package.json`'s test chain.
