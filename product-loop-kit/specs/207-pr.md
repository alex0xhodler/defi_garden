# 207 — explainer (HIGH tier: full walkthrough + quiz)

## The goal, in one line

On 88.6% of the pool deep links we publish, the north-star page was **silently saying nothing** about a
pool's rate history — not a wrong number, a blank. This item gives that case its own honest sentence.

## The intuition

The pool-detail page has a family of four "honesty notes" that sit under the rate. They exist because the
product's whole proposition is that we disclose what we don't know instead of quietly omitting it. Three of
them (rate track-record 088.1, rate momentum 103, TVL trend 104) read `pool.kpis` — a small object of
derived history that `compute-kpis.js` produces.

Item 105 noticed a hole: a direct `?pool=<id>` landing loads the LIVE DefiLlama feed, which carries no
`kpis`, so those notes hid for exactly the SEO arrivals we most want to convert. 105's fix was to fetch
`data/pools-snapshot.json` on such a landing and merge the matching pool's `kpis` back in.

The heartbeat measured on 2026-08-02 how far that fix actually reaches:

| population | count | share |
|---|---|---|
| `?pool=` deep links we generate | 3,669 | 100% |
| present in the snapshot → 105 can fire | **420** | **11.4%** |
| absent → 105 cannot fire, by construction | **3,249** | **88.6%** |

The snapshot is railed to `DEFAULT_MIN_TVL` ($10M) for front-end payload reasons (item 059); the SEO estate
floors at $100K (human directive 2026-07-11). Two floors, each correct on its own terms, and 105 inherited
the wrong one as its idea of "all pools". The one real SEO→pool-detail arrival on record this tick
(`/tokens/jitosol` → a $1.5M Kamino pool) landed in the 88.6%.

And the honest fallback the product already owns — `rateTrackRecordNew`, *"We're still building this pool's
rate history"* — is **unreachable** for those pools: it lives *inside* the `pool.kpis && historyPoints >= 1`
gate, so a pool with no `kpis` object at all falls out before it. The disclosure was trapped inside the
condition it was supposed to catch.

This item adds the missing tier: **"no data at all."** Widening which pools get history is deliberately a
different item (**208**); auditing the right pool population was **206**.

## What changed, in reading order

**1. `translations.js` — one new key, EN + KO together.**
`rateHistoryUnavailable`, added beside the three existing `rateTrackRecord*` keys.

> EN: *"We don't have a rate history for this pool — we track rates day by day only for the largest pools,
> so there's nothing here to judge how steady this one has been. The rate above is live from DefiLlama."*

**The wording is the item.** The spec's open question asked the builder to choose — and to *argue the
choice* — between naming the reason and staying generic. **We named the reason.** Two reasons:

- Reusing `rateTrackRecordNew` was ruled out explicitly, and not on style grounds: *"we're still building
  this pool's history"* asserts a future we are not currently delivering for a sub-rail pool. A fallback
  that mis-states **why** the data is missing is worse than the blank it replaces — it converts an honest
  silence into a small lie, on the one surface whose entire job is being trustworthy.
- The disparagement risk the spec flagged is handled by pointing the sentence at **us**, not at the pool:
  it says what *we* track, not that this pool is too small to be worth anything. We are showing this pool
  by design (`app.js:1144` renders `?pool=` deep links below the grid floor); the note explains our
  coverage gap, and then immediately re-anchors the reader on the number that IS live and real.

KO is natural Korean written to the same frame, not the English left in place — one language alone is an
automatic FAIL under NORTH_STAR's risk policy.

**2. `PoolDetail.js` — a fourth tier, and the race that makes it non-trivial.**

The note itself is the easy half: a sibling `div` after the 088.1 block, with the **inline style object
copied verbatim** from it (neuro tokens only — `--neuro-radius-sm`, `--neuro-shadow-subtle`,
`--color-background`, `--color-text-secondary`, `--font-size-sm`), and the 071 volatility boolean copied
verbatim and negated so at most one note in the family can ever render.

The hard half is that **105's backfill is asynchronous.** `app.js:1253-1273` fetches the snapshot *after*
`detailPool` is already on screen, then merges `kpis` in. A naive "render whenever `pool.kpis` is falsy"
would paint *"we don't have a rate history for this pool"* first and swap it for the real track-record note
when the fetch lands — a visible flash of a **false statement**, on the 11.4% path the spec requires to stay
behaviour-unchanged. The spec did not name this race; the blindspot pass found it.

The fix is a settle gate: local state `historyLookupSettled`, reset whenever the pool changes, armed with a
1000 ms timer only when the pool arrives *without* `kpis`, cleared on unmount. A pool whose backfill lands
re-runs the effect, resets the flag, and never shows the note. The gate lives in `PoolDetail.js` rather than
being published from `app.js` because the spec requires `app.js` byte-untouched — a constraint accepted
rather than argued around.

**3. `test_kpi_history_unavailable.js` — rendered acceptance, not fixtures.**
Six assertions driving the real UI in Chromium against a local server (NORTH_STAR standing decision
2026-07-11 — item 017's precedent: UX acceptance measures rendered product behaviour). It covers the
present case, the absent case, KO, 071 mutual exclusion, page errors, and — the one that matters — a
**no-flash case** that routes a snapshot which DOES contain the pool, and asserts the new note never
survives.

**4. `package.json`** gains one `test:serial` step (item 205's registry test fails on an unregistered test
file). No dependency added, removed or changed.

**5. Generated artifacts.** `home.html` loads `PoolDetail.compiled.js` / the `.min` bundles, not the source,
so `npm run compile && npm run minify` were re-run and the regenerated `PoolDetail.compiled.js`,
`PoolDetail.compiled.min.js` and `translations.min.js` ship in the same commit. `app.compiled.*` did not
drift — `app.js` was never touched.

## Deviations from the spec

Three, all recorded in `207-notes.md` with reasoning: the distinct class name (**D1** — the spec's "reuse
the class name" line contradicts its own acceptance criterion that `test_kpi_track_record.js` D4 stay
green), the timer-based settle gate (**D2** — forced by `app.js` byte-untouched), and the `package.json`
test registration (**D3** — forced by item 205's registry guard).

## Measurement — stated, not invented

**No new analytics event**, deliberately, and the spec pre-registered this. The surface is already covered
by `pool_view{source=url_direct}` and the north-star `pool_click{garden_cta|protocol_link}`. At 6
`pool_view` and 0 `pool_click` over 30 days, a new event here would be unreadable — far under the ≥30-event
minimum — so adding one would manufacture the appearance of measurement without the substance.

**This item makes no conversion claim.** It ships under NORTH_STAR's 2026-07-23 pre-traffic mandate
(product quality, not conversion optimisation). Window: 14 days. Decision rule: **keep** if the rendered
criteria hold and no guardrail moves (`error_occurred` stays 0, planner conversion unchanged); record as
**INCONCLUSIVE at n≈0** in `LEARNINGS.md` at window close — the same honest disposition 088.1 took on
2026-07-28.

## Verification — two passes, and the first one is the interesting one

**Attempt 1: FAIL, 7/8.** Seven criteria met with independently re-derived evidence. The eighth — the
no-flash criterion — was rejected because the test could not fail: `C3` sampled the DOM once, after a
~1600 ms settle wait, long after the mocked sub-50 ms snapshot fetch had resolved. **The failure was in
the evidence, not the code**; the verifier said plainly it had no objection to the production gate itself.

**Attempt 2: PASS, 8/8, tier HIGH** (re-derived independently, not ratified). C3 now injects a deliberate
**~400 ms delay** into the snapshot route — below the 1000 ms gate, so the gate genuinely does the work
rather than winning a race — and **polls the DOM every 50 ms from `domcontentloaded`** (deliberately not
`load`, which stalls ~10 s+ in this sandbox waiting on proxy-blocked external hosts, by which point any
race is long over), asserting the note was never present at *any* sample. Non-vacuity proven, both halves
run by the verifier itself:

```
✗ C3 no-flash: pool backfilled from snapshot never shows .rate-history-unavailable-note at any point,
    and settles on .rate-track-record-note
    expected .rate-history-unavailable-note to never appear during the delayed 105 backfill window
5/6 rate-history-unavailable behavior assertions passed
```

— with the settle gate neutralised. Restored and recompiled, all four artifacts md5-identical.

### The trap both agents hit, and why it is now a playbook

`home.html:359` loads **`PoolDetail.compiled.min.js`**, not `PoolDetail.js`. Attempt 1's vacuity proof
mutated the source **without re-running `npm run compile && npm run minify`**, so the browser executed the
unmutated bundle and the green suite proved nothing in either direction — **that FAIL rested on void
evidence.** The fix agent independently rediscovered the same trap ("first attempt without recompiling
silently passed for the wrong reason") before producing a valid proof. Two capable agents, same structural
trap, one tick — so it is written down rather than remembered:
`playbooks/compiled-artifact-mutation-proof.md`.

The honest reading: **we do not actually know whether attempt 1's C3 was vacuous**, because the proof that
said so was invalid. What we know is that the C3 shipping here *is* falsifiable, proven by a valid
mutation. The test got strictly better; the stated reason for the first FAIL did not survive scrutiny.

### Test results (verifier's own runs, not the builder's)

`test_kpi_history_unavailable.js` 6/6 · `test_kpi_track_record.js` 7/7 unmodified (D4 still holds — no
regression) · `test_kpi_seo_enrichment.js` 5/5 unmodified · `test_test_registry.js` 5/5 ·
`test_compiled_assets.js` 4/4 · `test_minified_assets.js` 9/9 · `test_translations_fallback.js` 8/8 ·
`run-tests.js --lane=plain --timeout=90` → **42 pass, 0 fail, 0 timeout**.

**Timebox honesty:** the full browser lane (86 files) was NOT run and is NOT claimed — no command was
allowed past the 5-minute foreground cap (standing decision 2026-07-11). One variant the verifier reasoned
about but did not execute: whether C3 would still go red with the gate merely *shortened* to 100 ms rather
than deleted. The mechanics say yes (100 ms < the 400 ms route delay, so the note would paint and be
caught by the 50 ms poll); it is recorded as reasoned-not-run rather than folded into the green.
