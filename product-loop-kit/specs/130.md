# 130 — Pool-detail category mislabel: de-duplicate pool-type classification

**Status:** IN_PROGRESS (2026-07-24) · **Score:** 5.5 · **Risk:** HIGH (user-facing label correctness on the north-star pool-detail page; touches app.js + PoolDetail.js core classification — not trust rails)

## Problem (rendered audit evidence, 2026-07-24)

The pool-detail hero badge (`.pool-type-badge-hero`, `PoolDetail.js:400-415`) mislabels stablecoin-lending pools as **"YIELD FARMING"**:

- **SUSDS on `sky-lending`** — stablecoin lending, shown as "YIELD FARMING".
- **venus-core-pool on BSC** ($268M TVL lending market) — same mislabel.

A cautious saver (the ICP) reading "yield farming" on a stablecoin lender is a trust mismatch on the exact surface the north star measures.

## Root cause

Two divergent copies of the pool-type classifier:

1. `app.js:193-228` `getPoolType(pool)` — the complete classifier. Uses 5 shared list constants (`LENDING_PROTOCOLS`, `DEX_LP_PROTOCOLS`, `STAKING_PROTOCOLS`, `RWA_PROTOCOLS`, `YIELD_DERIVATIVES_PROTOCOLS`), checks RWA + Yield Derivatives first (spec 091), normalizes `project` with `.toLowerCase().replace(/\s+/g,'-')`. **`venus`/`moonwell`/`benqi-lending` are already in its LENDING list** — so the analytics grid classifies venus correctly.
2. `PoolDetail.js:73-91` — a **narrower inline copy**: `['aave','compound','morpho','spark','maple','euler','radiant']` for lending, no RWA/Yield-Derivatives handling, `.toLowerCase()` only. Missing venus/moonwell/etc. → mislabels them.

So venus mislabels **only on pool-detail** (grid is fine). And **`sky-lending` is missing from BOTH lists** → SUSDS mislabels everywhere.

## Fix — single shared classifier (REUSE-COMPONENTS standing decision 2026-07-10)

De-duplicate into ONE classification, sourced once, used by both surfaces.

- `PoolDetail.js` loads **before** `app.js` (home.html script-injection order, relied on already: app references the global `PoolDetail` function). Top-level **function declarations** become globals and survive terser (`mangle:true` without `toplevel:true` preserves top-level names — same mechanism that keeps `PoolDetail` global).
- **Move** the 5 list constants + the classifier into `PoolDetail.js` as a top-level `function getPoolTypeShared(pool)` — the classifier body is `app.js`'s current `getPoolType` logic **verbatim** (RWA → Yield Derivatives → poolMeta-lending → LENDING → DEX → STAKING → Yield-Farming order, `.replace(/\s+/g,'-')` normalization preserved). This UPGRADES pool-detail to the full, correct classification for free.
- **Add `'sky-lending'`** to `LENDING_PROTOCOLS` (the one genuine gap; fixes SUSDS on both surfaces).
- `PoolDetail.js` render: replace the inline `getPoolType()` with `getPoolTypeShared(pool)`.
- `app.js`: **delete** its 5 list consts + `getPoolType` body; replace with `const getPoolType = (pool) => getPoolTypeShared(pool);` (global from the first-loaded PoolDetail script; load order guaranteed by home.html).

No trust rail touched (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly flags, degen haircut unchanged). No new dependency. No copy/translations change (the badge text was already category names via existing `poolType`; no new user-facing string).
