# 077 — smoke gate now passes in-sandbox (fixture-routing fallback) · LOW tier explainer

## What changed
`test_smoke.js` (+85/−5) — nothing else but item bookkeeping. The smoke gate (003) drives real
Chromium against both sacred router paths, but cloud-loop sandboxes block browser-originated HTTPS
to `yields.llama.fi` at the proxy connection level (NORTH_STAR 2026-07-12), so the gate failed 7/8
here on every run since 052 — the whole `npm test` chain halted at it, and four items (069/071/073/074)
had to hand-prove the failure pre-existing instead of getting a green chain.

The fix mirrors the repo's established pattern (test_search.js, prescribed by the 2026-07-12
standing decision):

1. **Live-snapshot-first routing.** At startup the test probes `yields.llama.fi/pools` via curl
   (which honors the proxy and CAN reach it here). On 2xx it captures the real ~10.5 MB payload once
   and fulfills every browser request for that URL from the snapshot via `page.route` — so the test
   still exercises genuinely live data. Only when the probe fails does it fall back to an inline
   DefiLlama-shaped fixture (USDC pools well above the $10M `DEFAULT_MIN_TVL` rail). One `network:`
   line logs which mode ran.
2. **Ignorable errors classified by resource URL, not console text.** Chromium's "Failed to load
   resource" text never contains the URL, so the old text-match silently never matched; now
   `msg.location()?.url` is checked first (test_search.js technique). The ignorable set is limited
   to hosts product code actually references and degrades gracefully on (fontshare `@import`,
   mixpanel/analytics, `api.llama.fi/protocols`, Google favicon service used by `planner.js`
   `brandIcon()` with an emoji fallback). Genuine page errors still fail — verified by mutation
   check (an injected non-ignorable `console.error` flunked all 7 browser assertions, twice: once by
   the builder, once independently by the verifier).

## Result

- With full network: behavior unchanged in spirit — probe succeeds, live data serves.
