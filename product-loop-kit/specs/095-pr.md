# 095 — List-view SOTA table polish (LOW-tier explainer)

**Verdict:** verifier PASS · **Risk:** LOW · **Ships:** one commit + self-merged PR.

## What & why
The analytics browse defaults to the list/rows view (`.pools-list`, shipped by 090) but the rows read as loosely-stacked cards, not a scannable table. Four surgical CSS edits (style.css, `.pools-list` scope only) turn it into a clean SOTA table:

1. **Uniform row height** — `.pools-list .pool-card` `min-height: auto → 84px`, so a "No supply yield" row and a daily-preview row are the same height (no more wobble).
2. **Right-aligned APY column** — `.pools-list .pool-apy-section` `align-items: flex-start → flex-end` + `text-align: right`.
3. **Right-aligned TVL column** — `.pools-list .pool-tvl-section` same treatment. APY and TVL now read as proper numeric columns aligned to a consistent right edge.
4. **Calmer 0-yield hero (pairs with 092)** — new `.pools-list .pool-apy-section:has(.pool-apy-tag) .pool-apy-hero { color: var(--color-text-secondary); opacity: 0.75 }`. When a row carries 092's honest "No supply yield" tag, its `0%` hero is de-emphasized. **Trust rail intact: the number stays in the DOM, only its visual loudness drops** (opacity 0.75 ≥ 0.7, legible in dark mode).

Tabular numerals (criterion 2) were already global (style.css ~3111–3129); the list inherits them — verified, not duplicated. `style.min.css` regenerated (the app loads the min file).

## Verification
- New rendered-Playwright gate `test_list_polish.js` — 6/6 on the REAL DOM (fixture-routed, sandbox-safe): A/B right-alignment, C tabular-nums, D row-height ≥84, E calmer-0 (opacity 0.75 + secondary color + digit preserved), F grid-view regression guard. `test_list_default.js` 3/3 (no regression).
- Screenshots at 1280 (light), 768, 360, 1280-dark reviewed: right-aligned columns, uniform rows, blue heroes on yielding rows, calm-grey `0%` on the no-supply-yield row, dark mode legible.

## Deviations (all in 095-notes.md)
- (a) `style.min.css` regenerated — required, app loads the min file; single minified line changed.
- (b) Test-only async-CSS settle fix: the harness serves `style.min.css` as `media="all"` (its post-`onload` state) so the sheet is active before React renders cards, mirroring production ordering — otherwise a Chrome `:has()` style-invalidation gap left the already-rendered 0-yield hero un-restyled in headless. Also routes `api.fontshare.com` → empty CSS (the `@import` becomes render-blocking under `media=all`). No product change; prod's real `onload` fires before the async pool fetch renders cards, so `:has()` evaluates correctly at card creation.
- (c) 360px APY-pill clipping is **pre-existing** (090's `.pool-left-section { min-width: 250px }`), proven identical against a stashed baseline; 095's changes are neutralized at ≤768px by the existing center media query. Out of scope.
