# 252 — PR explainer (LOW tier, short form)

## Goal

On 2026-08-07 the north star fired for the first time in 30 days: `pool_click{source=garden_cta}` = 1,
with `pool_view` 4, `plan_created` 1, `plan_saved` 2. `playbooks/traffic-quality-classification.md`
scores that day REAL on **every** criterion it has — multi-step progression, clean params, mixed
fingerprints. Following the playbook as written **opens the north star's first traffic gate.**

Broken down by `$region`, 100% of that engagement is Utrecht/NL on iOS+Mac, on the day the operator
merged four design PRs, with `search_input` = 0 — a reviewer's sweep, not a searcher's task.

The finding is not "that click was fake." It is that **the loop has no instrument that can separate its
own shipping traffic from demand**, and the more it ships the more contaminated its own measurements
become. Geo/device correlation is a manual forensic argument, not a rail.

## Intuition

The weakest predicate that covers both contaminating populations is: **a gate should count only visits
that carry information we did not already have.** Crawlers fail it for want of intent; insiders fail it
because we already knew they were looking. That predicate is strictly weaker than the existing crawler
rule and *contains* it — which is why the fix is a named, subtractable population rather than
"exclude Utrecht" (which breaks the day the operator travels, or a real Dutch visitor arrives).

## What changed

`analytics.js` (+60/−2) — the whole product change:

1. `INSIDER_STORAGE_KEY: 'defi_garden_insider'` — same plain-localStorage convention as
   `theme` / `defi-garden-lang` / `garden-plan`.
2. `applyInsiderParam()` — called first thing in `init()`, before acquisition capture, so the session's
   very first event already reflects the current state. `?insider=1` persists; `?insider=0` clears;
   neither present leaves what's stored alone. Wrapped in `try/catch` like `captureAcquisition()` — a
   throw here must never break tracking site-wide.
3. `_insiderOverride` — this load's own param, held separately from the localStorage round-trip. This is
   the one thing the spec text didn't spell out, and it's load-bearing for the acceptance criteria: it's
   what lets "marking works" and "persistence works" fail **independently** in the non-vacuity proof.
   Without it a single break would redden both, and two guards masking each other is item 166's lesson.
4. `isInsider()` — override wins, else a fresh localStorage read; any storage failure reads as
   "not insider", never throws.
5. One spread in `getBaseContext()`: `...(this.isInsider() ? { insider: true } : {})`. Because
   `getBaseContext()` feeds the single `track()` chokepoint, every event inherits it. Unmarked visitors
   carry **no `insider` key at all** — never `insider: false`, matching how `src`/utm keys are omitted
   rather than emitted empty. The event shape for ordinary visitors is byte-unchanged.

`test_analytics_insider.js` (new) — rendered Playwright, fixture-routing style. `package.json` — the one
test registration. No UI, no dependency, no minified/compiled twin exists for `analytics.js`
(`minify-assets.js`'s `JS_FILES` and `compile-app.js`'s `FILES` both omit it — checked, not assumed).

## Why it can't disturb the router

`insider` is deliberately in **neither** `ANALYTICS_PARAMS` nor `PLANNER_PARAMS` (`home.html:90-91`), so
it cannot change which experience loads. `git diff origin/main -- home.html plan.html` is **empty**: the
`<script defer src="analytics.js">` tags are byte-unmoved (CLAUDE.md records that ordering as
deliberate — reverting it once raced the planner's first tracking call). The verifier additionally
render-checked all 7 mode cases, including the third router mode (`landing`, which bare `/` actually
resolves to — the spec's own warning text was inaccurate on that point) and odd param values
(`true`, `yes`, `2`, empty, `1%20`), none of which mark or clear.

## Non-vacuity (re-run independently by the verifier, not taken from the notes)

Baseline `md5sum analytics.js` = `be1c99dfae9069956645c521fa312995`.

- **(a) delete the `getBaseContext()` stamping line** → 5/9, `EXIT:1`, RED on **both** router-path tests.
  Restore → md5 identical → 9/9, `EXIT:0`.
- **(b) disable ONLY the localStorage writes** → 7/9, `EXIT:1`, red on **exactly** the two persistence
  assertions; marking, absence and clear stay green. Restore → md5 identical → 9/9, `EXIT:0`.

(b) is the one that matters: it proves the two halves are independent guards rather than one guard
double-counted. The verifier's (b) run reddened on `waitlist_opened` where the builder's reddened on
`session_start` — incidental ordering, and useful evidence that the RED does not depend on the
opportunistic event discussed below.

## Deviations from spec, stated plainly

1. **`_insiderOverride` is not in the spec's Change text.** Rationale above; the observable contract is
   unchanged.
2. **`session_start` is asserted opportunistically** (checked when observed, never required). The
   verifier reproduced the cause with timing instrumentation over 5 trials per path: the shared
   `neutralizeHostGate()` harness installs its double via an async poll, and a `load`-fired event can
   beat it, at which point `track()` takes its correct spec-096 early return. Harness property, not a
   product bug — in prod `isProductionHost()` is true on the first call. The suite still **hard-requires**
   `waitlist_opened` on planner and `page_view` on analytics, and mutation (b) reddens without
   `session_start`. Codified in the new `playbooks/load-time-event-test-race.md`.
3. **Population parse widened after the PASS.** The verifier flagged that parsing `analytics.js` alone
   was a guard narrower than the class it guards — `landing.js:205,223` also emit through
   `Analytics.track`. The file set is now derived at test time (every root `*.js` whose source contains a
   `track('…')` call), so a future emitter file is picked up with no edit; population 30 → 32. Widening
   the accepted set can only suppress a false failure, never cause one; drift is still caught by the
   size and must-contain self-checks, plus a new throw if discovery loses `analytics.js`/`landing.js`.
4. **The playbook query recipe (spec Change item 2) was not written.** The builder called it blocked on
   credentialed Mixpanel access; the verifier correctly pushed back that a *prose* filter recipe needs no
   credentials — only cohort **creation** is the org-admin action. Not an acceptance criterion, so it did
   not gate the ship, but the stated justification was stronger than the facts. Recorded honestly here
   rather than quietly dropped.

## Class NOT closed — with the number

The flag covers the operator **on devices they mark**. It does not cover an unmarked device, a teammate,
or a contractor. The residual is **unbounded and unmeasurable by construction**: any device that never
visits an `?insider=1` URL is indistinguishable from a genuine visitor by this mechanism alone. That is
why the flag is paired with — not a replacement for — the geo/device forensic step in
`playbooks/traffic-quality-classification.md`, and why gate reads must report the residual with a number
each tick rather than assume it is zero.

## What the human owes

- **Visit prod once per device with `?insider=1`.** Until ≥1 event carrying `insider: true` appears in
  Mixpanel, the instrument is unproven in production — and per LEARNINGS 2026-07-27 an unexercised
  instrument's zero is not evidence of health. Backstop: if none is seen within 60 days, close
  UNEXERCISED as a finding about the instrument, not about the operator.
- **`NORTH_STAR.md` gate language.** Deliberately not edited — that file says only the human edits it.
  Proposed wording is in `252-notes.md:52-69`: a **real** session is one that is BOTH not
  crawler-classified AND does not carry `insider: true`, so snapshots can state
  "N sessions, of which M insider, K crawler, R real."
- Open, non-blocking: whether the flag should also be honoured on Vercel preview deploys (moot today —
  item 096's host gate already suppresses non-prod hosts).
