# 095 — List-view SOTA table polish

**Status:** IN_PROGRESS (2026-07-14) · **Risk:** LOW · **Score:** 6.0
**Source:** Analytics-UX audit (human 2026-07-14). Promoted from BACKLOG row 095.

## Problem
The analytics browse defaults to the list/rows container (`.pools-list`, shipped by 090). Its rows currently read as loosely-stacked cards, not a scannable table: the APY and TVL numeric cells are **left-aligned** (`align-items: flex-start`), so numbers don't line up into columns; rows have `min-height: auto`, so a row showing the "No supply yield" tag (092) is a different height than one showing a daily-earnings preview — the list wobbles; and the stark `0.00%` APY hero on 0-yield pools reads as loud as a real yield even though 092 already demotes and honestly tags those pools.

## Scope (pure CSS/markup polish — NO data/trust-rail surface)
Touch **`style.css` only**, and only the `.pools-list` scope (≈ lines 2008–2121). The shared `renderPoolCard` in `app.js` is NOT modified — grid view must render byte-identically. No JS, no translations, no trust-rail constants.

This is a UX item: acceptance is **rendered product behavior** driven by Playwright on the real UI (per 2026-07-11 standing decision), with screenshots at 1280/768/360 + dark reviewed visually.

## Acceptance criteria
1. **Right-aligned numeric columns** — in list view, the APY column (`.pools-list .pool-apy-section`) and TVL column (`.pools-list .pool-tvl-section`) align their content to the column's right edge (`align-items: flex-end; text-align: right`). The symbol/context column stays left-aligned. Verified: computed `align-items` on both sections is `flex-end` in `.pools-list`.
2. **Tabular numerals** — APY hero, APY preview, and TVL value render with `font-variant-numeric: tabular-nums`. (Already true globally via lines 3111–3129; the list view inherits it. Criterion is satisfied-and-preserved — verify computed style, don't duplicate the rule.)
3. **Consistent row height** — every `.pools-list .pool-card` has a uniform minimum height (`min-height: 84px`) so a "No supply yield" row and a daily-preview row are the same height. Verified: all rendered list rows report equal `offsetHeight` (± sub-pixel) for same-content-shape rows; no row shorter than 84px.
4. **Calmer 0/near-0 values (pairs with 092)** — when a row carries the honest `.pool-apy-tag` ("No supply yield"), its `0.00%` APY hero is visually de-emphasized (calmer color `var(--color-text-secondary)` + reduced weight/opacity) while the number stays fully legible. **Trust rail intact: the number is never hidden or altered — only its visual loudness drops.** Use `.pools-list .pool-apy-section:has(.pool-apy-tag) .pool-apy-hero`.
5. **Hover/press physics preserved** — list rows keep the existing `.pool-card:active` sink (translateY(0) scale(0.99) + `--neuro-shadow-pressed`) and hover treatment. No new easings, no scale-pop, no glow (design ban-list).
6. **Flawless at 360 / 768 / 1280 + dark** — at 768 and below the row stacks (existing media queries at 2095–2121 center the cells); right-alignment applies only to the wide (row) layout, so it must not fight the stacked/centered mobile layout. Screenshots at all three widths + dark mode reviewed and clean (no overflow, no clipping, legible 0-value).

## Implementation notes
- Only edit inside the `.pools-list` scope. The `@media (max-width: 768px)` block already re-centers cells with `align-items: center` — that overrides the new `flex-end` at narrow widths, so mobile is unaffected. Confirm the cascade order keeps the media query winning (it appears later / equal specificity — verify in a screenshot).
- `min-height: 84px` on `.pools-list .pool-card` replaces `min-height: auto`. Keep `align-items: center` so short content vertically centers.
- The calm-0 rule uses `:has()` (supported in all current evergreen browsers; the app is React-18-UMD modern-browser only). Keep opacity ≥ 0.7 so the number stays legible in dark mode.
