# 274 — PR explainer (HIGH tier)

## Why HIGH

Two independent triggers: (1) edits `.pools-grid .pool-card`/`.pool-header-new`/
`.pool-apy-section`, grid-view templates every `?token=`/`?chain=` sitemap URL can
render (the sacred surface `CLAUDE.md` names). (2) diff is 213 lines across
`style.css`+`style.min.css`+`test_card_numeral_wrap.js`, over the LOW cap.

## Goal

Human live report: anomalous ⚠ APY numerals (and even a plain 705.51%) clip at the
grid-view card's right edge; the $/day line truncates too. Fix: contain every numeral
inside its own card, never clip, never ellipsize, ⚠ stays glued to its number (246's
guard), grid view only, zero drift on cards that don't overflow.

## Intuition

`.pool-header-new` is a flex row (`.pool-name-group` beside `.pool-apy-section`) that
spans both of `.pool-card`'s grid columns. Both children carry 246's `nowrap` numerals
with no width ceiling. With the header's default `flex-wrap: nowrap`, a wide APY
string can't shrink (nowrap forces min-content = full string width) and can't wrap, so
the row's required width exceeds the card and `.pool-card`'s `overflow: hidden`
silently eats the difference — verified by measuring the real rendered boxes
(Playwright), not by reading the CSS: a 128,000% fixture measured `card.scrollWidth=315
> clientWidth=281` at 1280px. `.pool-apy-section` is already a column (hero above
$/day) — the fix just lets that whole unit drop to its own line, as one piece, when it
doesn't fit.

## What changed and why (diff in reading order)

1. **`style.css`, `.pools-grid`**: `align-items: start`. CSS Grid's default cross-axis
   stretch was inflating normal cards' height when a same-row sibling grew taller from
   fix #2 below — measured 42.58px of unwanted height drift on non-overflowing cards
   before this line, 0px after. Required for the zero-drift acceptance criterion, not
   optional polish.
2. **`style.css`, `.pools-grid .pool-header-new`**: `flex-wrap: wrap; row-gap:
   var(--space-8)`. Lets `.pool-apy-section` wrap to its own line below
   `.pool-name-group` only when the line doesn't fit; a no-op when it does (measured
   0.044px max drift on 42 normal-card instances — see `specs/274-notes.md`).
3. **`style.css`, `.pools-grid .pool-apy-section`**: `margin-left: auto`. Keeps the APY
   block flush right in both the one-line and wrapped cases; on one line it reproduces
   `justify-content: space-between`'s exact existing gap (trailing auto-margin absorbs
   all remaining space first), so unwrapped cards are pixel-identical.
4. **`style.min.css`**: regenerated via `npm run minify`, never hand-edited.
5. **`test_card_numeral_wrap.js`**: new check J (grid-view numeral containment against
   `.pool-card`'s own bounding rect, all 4 edges, 1px tolerance — the gap check D can't
   see, since a nowrap element's own box always fits its own content trivially).
   Population is the same DOM-derived `NUMERAL_CLASSES` list checks A–H already use.
   Also asserts `card.scrollWidth <= clientWidth+1`, EXCEPT on a card where that's
   DOM-provably caused by a non-numeral leaf (a separate, pre-existing, out-of-scope
   byline-overflow defect surfaced by measurement — logged via `excusedByline`, not
   silently dropped; see notes). 3 fixture pools' `apyBase` retargeted to hit the 4
   digit-count buckets the spec's AC1 names (2/3/4/6-digit), without adding a 10th pool
   (would break the file's exactly-9/page-1 discipline).

## Deviations from spec

- `align-items: start` on `.pools-grid` wasn't in the spec's practical-approach list —
  added after measurement showed it's necessary for zero-drift, scoped to the
  container the spec already names in-scope.
- Did not fix a second, pre-existing, unrelated overflow defect discovered while
  measuring (a long project-slug byline blowing out the header via flexbox's default
  `min-width: auto`, independent of any numeral) — reproduced identically on a clean
  pre-274 worktree, so out of this item's "grid-card containment [for numerals] only"
  scope. Logged, not hidden — full writeup in `specs/274-notes.md`.
