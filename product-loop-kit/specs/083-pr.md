# 083 — PR explainer (HIGH tier, full walkthrough)

## Goal

Stop the daily sitemap-update CI from committing — and therefore consuming a
Vercel free-tier deploy (the documented 2026-07-13 quota crisis) — on runs
where NOTHING actually changed. After 081 fixed sitemap `<lastmod>` churn,
exactly two files still changed on every run no matter what: `llms.txt` and
`llms-full.txt`, whose "Last Updated" / "(fetched: …)" lines are stamped with
wall-clock time unconditionally. Because the workflow's commit gate is
whole-tree `git status --porcelain`, those 3 lines alone forced a commit +
deploy every single day, and made the files' freshness claim a daily lie (an
AI-crawler signal that lies routinely gets discounted, same as lying lastmod).

Live proof this was real: commit `8fee9e9ba` (2026-07-14, 18 min after the
prior run) — 1120 changed lines, 1114 of them sitemap lastmod (081's fix), the
remaining 6 exactly these llms timestamp lines.

## Intuition

Same honest-freshness principle as 081, applied one file-type over: a
timestamp should describe the CONTENT, not the generator's run time. If a
regeneration produces byte-identical content (modulo its own timestamp
lines), the committed file — old timestamps included — is still the truth, so
we keep it untouched. Untouched file → empty porcelain → the workflow's
existing gate skips commit, push, deploy, and search-engine pings with zero
workflow changes.

## What changed, in reading order

1. **`generate-llms.js`** (+52/−3, all additive around untouched content
   logic):
   - `LLMS_TS_PLACEHOLDER` — the sentinel used during comparison.
   - `normalizeLlmsContent(content)` — replaces the volatile values in the
     two emitted timestamp line shapes with the placeholder, via
     line-anchored `/gm` regexes: `- Last Updated: <iso>` (both files) and
     the `(fetched: <iso-or-"unavailable">)` value inside the
     `- Data Sources:` line (llms-full.txt). Anchoring to the exact emitted
     shapes means no body content can ever be rewritten; non-string input is
     returned untouched (treated as a mismatch → write fresh).
   - `writeIfContentChanged(filePath, newContent, now)` — reads the on-disk
     file; if `normalize(new) === normalize(existing)`, skips the write and
     logs `<file> unchanged — kept committed timestamps`; otherwise writes
     and logs `<file> content changed — stamped <iso>`. The read+compare is
     wrapped in try/catch: a missing/unreadable file or ANY comparison error
     falls back to writing fresh — pre-083 behavior, so the CI pipeline can
     never crash on this path.
   - `main()`'s two bare `fs.writeFileSync` calls now route through the
     helper. `buildConcise`/`buildFull` and every piece of data logic are
     source-byte-identical to HEAD (verifier-confirmed) — zero behavior
     drift in what the files SAY, only in WHEN they're rewritten.
   - The three new symbols are exported for testing (080/081 pattern).
2. **`test_llms_freshness.js`** (new, fixture-only, no network, 8 assertions):
   unchanged→skip/byte-identical, real-change→rewrite with new stamp,
   no-file→fresh, no-timestamp-lines→fresh fallback, `(fetched: unavailable)`
   normalization + unchanged-skip, and a guard that the normalizer touches
   ONLY the volatile metadata lines. Temp dirs via `os.tmpdir()` (the repo's
   fixture pattern).
3. **`test_lastmod_honesty.js`** (081's test, 2-line repair): its fixture dir
   was hardcoded to a now-dead session scratchpad path, so it ENOENT-failed
   8/8 at HEAD — silently breaking the `npm test` chain at position 33 and
   making 083's new test at position 34 unreachable. Same `os.tmpdir()` fix,
   nothing else touched. This is the verifier-evidenced prerequisite repair
   that made "wired into npm test" true, not a drive-by.
4. **`package.json`** — one line: `&& node test_llms_freshness.js` appended
   to the test chain. No dependency changes.

## Deviations from spec

- The spec's acceptance #3 anticipated the first live regeneration might
  rewrite legitimately; it did (a real `### Sonic` section removal in live
  data, verifier-observed) — the diff carried real content lines, exactly the
  honest behavior intended. Steady-state run 2 left porcelain EMPTY.
- Attempt 1 shipped the new test with a hardcoded session scratchpad path
  (verifier FAIL) — fixed to `os.tmpdir()` in attempt 2, plus the identical
  repair to 081's sibling test (operator-approved, documented in
  specs/083-notes.md).

## Verification (verifier PASS, HIGH, 6/6, independently re-derived)

Unit tests 8/8 both files; mutation checks bite in both directions
(always-changed and always-unchanged each fail the test); old-vs-new
`buildConcise`/`buildFull` source-byte-identical; live scratch-copy
idempotency — run 1 legitimate content rewrite, run 2 `porcelain` EMPTY with
sha256-identical files; `npm test` chain unchanged in behavior up to the
documented pre-existing Playwright timebox precedent; NEVER list clean.

## What to watch after merge

- The first no-data-change daily CI run should log both `unchanged — kept
  committed timestamps` lines and SKIP its commit entirely — the first
  zero-deploy day since the workflow existed; 081+083's deploy saving
  realized together.
- `llms.txt` "Last Updated" now only advances when content really changed
  (visible in git history).
