# Spec 172: give the STATIC-page prescan a link signal (`link-target-integrity` on generated HTML)

## Evidence

`prescanStaticPages()` (`audit-app.js:557`) reads **every** one of the 2,183 generated HTML SEO pages
(2,094 `tokens/*.html` + 89 `chains/*.html`) and applies four signals — `junk-slug`,
`zero-yield-claim`, `broken-number-literal`, `absurd-magnitude` (`PRESCAN_SIGNALS`, `:175-180`).
**Every one is a number-or-slug check.** Not one looks at a link.

Measured on this checkout (2026-07-29, before writing this spec — plain `fs`+regex over the committed
pages, no network, no render):

| | count |
|---|---|
| generated HTML pages scanned | **2,183** |
| same-origin links they emit | **~41,300** |
| of which `/?pool=<id>` links into pool-detail — the north-star surface | **4,989** |
| pool-row anchors (`a.tp-pool-link`) on token pages | 4,526, **100%** `?pool=`-targeted |
| distinct query keys emitted | `token, pool, poolTypes, chain, lang, preset, waitlist, src` |
| broken internal page targets (path → no file on disk) | **0** |

So the surface is healthy today under all three rules below — and **nothing has ever checked that**,
which is the point. This is the fourth instance of the pattern the product-audit playbook states in its
own words (`playbooks/product-audit.md:219-224`):

> a checker's signal set is always drawn from the last bug someone was bitten by, so the next bug is in
> whatever class no one has been bitten by yet

148 → 159 → 166 is the documented chain (`reports/2026-07-28.md:23-25`). Item **169** closed it for the
two generated **text** surfaces (`llms.txt`/`llms-full.txt`, ~2 files) by adding
`link-target-integrity` to `prescanTextSurfaces()`. It explicitly listed the HTML surfaces as out of
scope — `specs/169.md:41`: *"Extending the signal to HTML surfaces (`prescanStaticPages`), sitemaps, or
OG cards. One surface family per item."* This item is that follow-on, on a surface **1,000× larger**
by file count and the one that actually carries SEO traffic toward the north-star CTAs.

The playbook's own corollary points here (`product-audit.md:225-228`): *"the cheapest place to find the
next defect is the surface you audited yesterday, one class over."* 169 was yesterday; HTML is one
surface over.

Why it matters beyond detector hygiene: the SEO surface's whole job is the hop
`/tokens/<slug>` → `/?pool=<id>` → the two north-star CTAs (`pool_click{garden_cta, protocol_link}`,
NORTH_STAR:16). 4,989 links carry that hop and no gate has ever asserted that any of them addresses a
pool at all.

## Hypothesis

We believe adding one `link-target-integrity` signal to `prescanStaticPages()` converts three
link-defect classes on the generated HTML surface from hand-findable-only to automated, because all
three are decidable from committed bytes alone (measured above: the scan runs in seconds over the whole
2,183-page set). Confidence: **supported for the classes it implements, and stated as scoped** — today
all three rules are green, so their value is future regression coverage, not a live bug fix. That is
disclosed here rather than dressed up: this item ships a gate, not a repair.

## Change

**Detector only.** One new signal inside the existing `prescanStaticPages()` — same file, same pure
`fs`+regex pass over pages it *already reads*, same aggregate-finding emission. No new pass, no new
surface, no generator, no product file, no page regenerated.

`link-target-integrity` — severity **P1**, registered in `PRESCAN_SIGNALS` (`audit-app.js:175`) so
severity stays single-sourced and the `bySignal` block + aggregate `static-prescan:<signal>` finding
come for free, exactly as 169 did in `TEXT_SURFACE_SIGNALS`.

**Reuse before inventing** (standing decision 2026-07-10). 169 already shipped
`extractQuotedArray()` (`:242`) and `loadRouterAllowedParams()` (`:256`) — reuse both **verbatim**, do
not write a second copy or a second param list. A hardcoded second copy of the router's params is the
exact bug class this signal exists to catch and is a verifier FAIL.

Owned links = both forms the generated HTML actually emits: absolute
`https://(www\.)?defi.garden/...` **and** root-relative `/...`. HTML entities must be decoded before
parsing a query string (`&amp;` → `&`); a scanner that splits the raw attribute on `&` invents a
phantom `amp;src` key — verified during this spec's measurement, so the tests must pin it.

Three independently-neuterable sub-rules, **one suspect per file per signal** (the 160/169 convention:
a systemic breach is one suspect whose `detail` quotes ≤3 examples, never one finding per page):

1. **(a) unrouted query key.** The allowed set depends on the link's path, because the router only
   arbitrates the bare path:
   - path is `/` (or empty) → every query key must be in `ANALYTICS_PARAMS ∪ PLANNER_PARAMS ∪ {lang}`,
     **parsed out of `home.html:77-78`** at scan time via the existing `loadRouterAllowedParams()`.
     A key outside that set makes `home.html`'s IA router resolve `__APP_MODE = 'landing'` and the
     query is dropped — the live 166 defect (`?search=lido` → empty search box).
   - path is `/plan.html` → always the planner by path, so router membership does not apply. The key
     must instead be **read by `planner.js`**: single-source it by scanning `planner.js` for
     `urlParams.get('<key>')` / `urlParams.get("<key>")`. Today's generated pages emit
     `/plan.html?waitlist=1&src=seo_token` (item 062) and both keys are read at `planner.js:4005-4006`
     — so this rule is green today and must stay green, not be "fixed" by allow-listing them.
   - any other path (`/tokens/...`, `/chains/...`, `/ko/...`) → skipped by this rule; the page is fixed
     by path and query keys there are inert.
   - If `home.html` (or `planner.js`) cannot be read/parsed, the affected half of rule (a) is **skipped
     with a stderr note printed ONCE per scan** and every other rule + all four pre-existing signals
     keep working — the `prescanStaticPages()` never-throws contract (`audit-app.js:554-555`).
2. **(b) pool row → non-addressing target.** Every pool-row anchor (`class="tp-pool-link"` on token
   pages, `class="cp-pool-link"` on chain pages — the classes item 029 shipped) must target a
   `?pool=<id>` URL. The bare origin, a `?token=`/`?chain=` grid URL, or a missing/empty `href` is a
   suspect: a row that names one specific pool and its APY/TVL must link to a URL that *addresses*
   that pool, which for pools means `/?pool=<id>`, the north-star surface (166's rule (b)/(c), stated
   for HTML). `<id>` must be non-empty; do **not** validate it against any pool set (see non-goals).
3. **(c) internal target does not exist.** Every owned link whose path is not `/` and not `/plan.html`
   must resolve to a file on disk: `<path>`, `<path>.html`, or `<path>/index.html`, relative to `ROOT`.
   This catches the orphan-link class the generators make live: items 030/032/033 drop a token page
   when its quality gate stops passing and item 031 deletes stale pages, while item 023's
   related-token/related-chain cross-links were minted when the neighbour still qualified. Query and
   fragment are stripped before resolving.

Explicitly OUT of scope:
- **`?pool=<id>` liveness.** Measured by hand for this spec against a live 16,054-pool DefiLlama fetch:
  **15 of 4,989** `?pool=` targets across 14 token pages point at ids no longer live (0.3%; e.g.
  `tokens/xgcd.html`, `tokens/sbtc.html`) — real, but ≤24h of exposure since CI rebakes the pages daily,
  and it needs network, which this prescan deliberately never uses. **Do not approximate it with
  `data/pools-snapshot.json`**: the snapshot is the ≥$10M-floored 745-pool set while token pages use a
  $100K floor, so snapshot-validation false-positives **4,233 of 4,989** links (measured). Record this
  trap in the playbook; ticket the online check separately if it earns a slot.
- `stories/*.html`, `sitemap-*.xml`, OG cards, and the rendered `kind:'static'` checks — one surface
  family per item (160's rule). `prescanStaticPages()`'s page list (`listLeafPages('tokens')` +
  `listLeafPages('chains')`) is unchanged.
- Any change to a generator, a generated page, or any product file. Detector only.
- Non-`defi.garden` links (DefiLlama, protocol sites): we do not own their shape.
- Fetching, resolving over the network, or rendering any URL.

## Acceptance criteria

- [ ] `PRESCAN_SIGNALS` gains `'link-target-integrity': 'P1'`; the four existing signals, their
      severities and their detection blocks are **byte-identical** (`git diff` shows no edit inside them).
- [ ] Rule (a) reuses the existing `loadRouterAllowedParams()` / `extractQuotedArray()` — **no second
      copy of the param list anywhere in the diff** (`grep` for a literal `'token'`/`'poolTypes'` array
      in the new code must find nothing). Prove the coupling is live, not decorative: a test that points
      the loader at a **copied `home.html` fixture with one extra param appended** shows a link using
      that param flip from suspect → clean.
- [ ] Rule (a)'s planner half single-sources from `planner.js` the same way: a test using a copied
      `planner.js` fixture (or an injected path) shows a key flip from suspect → clean when
      `urlParams.get('<key>')` is added.
- [ ] **True negative on the real committed surface**: a full `prescanStaticPages()` over all 2,183
      committed pages emits **zero** `link-target-integrity` suspects (measured pre-build: 0 under all
      three rules). If it goes red, the signal is over-tight — fix the signal, never the pages.
- [ ] **Positive control per sub-rule**, each proven independently non-vacuous: a fixture page tripping
      only (a), only (b), only (c) produces exactly that rule's suspect and no other. Prefer real bytes
      where they exist (`git show <pre-029-commit>:tokens/<slug>.html` for rule (b) if such a commit is
      reachable in this checkout — state in the notes whether it was, and fall back to fixtures if not).
- [ ] Neuter each sub-rule one at a time and show the matching control loses exactly that suspect and
      keeps the others; restore byte-identically (md5) and show green. Three separate cycles.
- [ ] Entity decoding pinned by test: a fixture href `"/plan.html?waitlist=1&amp;src=seo_token"` yields
      keys `{waitlist, src}` and **never** `amp;src`.
- [ ] One suspect per file per signal maximum; `detail` caps examples at ≤3 per sub-rule and names the
      offending URL(s) — same spirit as the existing `hits.slice(0,10)` / `others.slice(1,3)` caps.
- [ ] Rule (a)/(c) degrade safely: unreadable `home.html`, unreadable `planner.js`, and an unreadable
      page each produce a stderr note (router/planner note printed ONCE per scan, not per file), do not
      throw, and leave every other signal working.
- [ ] `AUDIT_STATIC_PAGES=<paths>` still disables prescan entirely (spec 157 B.2) — unchanged behaviour,
      asserted.
- [ ] Runtime: the added work stays within a **≤2× wall-clock** budget for `prescanStaticPages()` alone
      (it parses links out of HTML the pass already read). Measure and record before/after in the notes.
- [ ] Tests: new cases go in the existing `test_audit_prescan.js` (or whichever existing file already
      covers `prescanStaticPages` — find it, do **not** create a second static-prescan test file). Stays
      browser-free, runs in the plain lane, already wired into `test:serial` (no `package.json` change
      expected — if one is needed, say why).
- [ ] `node audit-app.js` still completes and `surfacesCovered` loses nothing; the run's `prescan`
      block gains the new `bySignal` key. Run it (it took 1m44s on this checkout) or state honestly
      which subset ran inside the 5-minute timebox.
- [ ] No product file, generator, page, sitemap, OG asset, or dependency touched. `package.json`
      dependency blocks byte-identical (prove by structured diff).
- [ ] Instrumentation: **none** — loop tooling under the 2026-07-23 pre-traffic mandate. Record the
      disclosure per the 142/149/154/155/160/169 precedent.

## Measurement

Metric: **none — loop tooling.** No 14-day window. Success is observable at the next heartbeat:
`product-loop-kit/signals/audit-findings.json` either keeps `link-target-integrity: 0` (the SEO
surface's links stay honest) or tickets a real routing/orphan defect without a human curling prod.

## Risk tier (builder's guess — verifier assigns independently)

**HIGH on size.** The change is detector-only and touches nothing on the NEVER list, but 154 (+184),
157 (+224), 163, 166 (+226) and 169 all crossed the 150-line LOW cap once tests were counted, and three
sub-rules with three non-vacuity cycles will not be small. "When in doubt → HIGH" (NORTH_STAR:67). The
verifier assigns the tier from the measured diff, not from this guess.

NEVER-list check (builder's read, verifier re-derives): no trust rail weakened (`APY_SANITY_LIMIT` /
`DEFAULT_MIN_TVL` untouched — this only *adds* a check); no credentials/org-admin/money; **no SEO
surface deleted or de-indexed** (no generated file is written or removed at all — the diff must not
regenerate `tokens/`, `chains/`, `sitemap-*.xml`, `llms*.txt`, or OG images);
`telegram-bot/`, `whatsapp-bot/`, `workers/` untouched.

## Open questions

None that change the architecture. The one judgment call — what the allowed param set is for a
`/plan.html` link, where the IA router does not arbitrate — is resolved above by single-sourcing from
`planner.js`'s own `urlParams.get()` call sites rather than by allow-listing, so it cannot drift.

## Territory notes

- `prescanStaticPages()` at `audit-app.js:557`; `PRESCAN_SIGNALS` at `:175`; `extractPageText()` at
  `:534` **strips all tags**, so hrefs are gone by the time it returns — the link scan must run on the
  raw HTML string the loop already read at `:565`, not on `visibleText`.
- 169's reusable pieces: `extractQuotedArray()` `:242`, `loadRouterAllowedParams()` `:256`,
  `TEXT_DEFI_GARDEN_URL` `:234` (text-shaped, tuned for prose — HTML wants an `href="…"` extraction
  instead; reuse the *param-allow-list* logic, not necessarily that regex).
- Aggregate `static-prescan:<signal>` findings and the promotion path are built by
  `buildStaticSurfaces()` (`:622`); item 171's `reconcilePrescanFindings()` downgrades an aggregate only
  when every suspect was promoted AND rendered clean. A `link-target-integrity` suspect has no rendered
  equivalent, so it will simply never reconcile — that is correct ("unverified is not clean") and needs
  no change, but say so in the notes so the next reader does not treat it as a bug.
- Exported surface at `:1780` (`prescanStaticPages, prescanTextSurfaces, prescanPools,
  buildPoolSurfaces, …`) — `prescanStaticPages` is already exported; tests can call it directly.
- Measured baseline for the true-negative criterion (this checkout, 2026-07-29): query keys emitted by
  generated HTML are exactly `token, pool, poolTypes, chain, lang, preset, waitlist, src`; 0 broken
  internal targets out of ~41,300 links; 4,526/4,526 `a.tp-pool-link` anchors `?pool=`-targeted.
