# 144 — HIGH-tier explainer + quiz: `apyMean30d` can no longer render a 36,452% "30-day average"

## Goal
Pool-detail — the north-star surface (`pool_click{garden_cta|protocol_link}`) — was presenting an
out-of-rail percentage as a trusted fact. Live in the committed snapshot today: balancer-v2
**WSTETH-AAVE** (`201e5f6e-cf75-4d0e-b07f-d58da3cee23a`, Ethereum, TVL $12.4M, current APY **0.24%**)
carries `apyMean30d = 36452.38798`, so the page rendered a **"30d Mean APY — 36,452.39%"** stat card and
the 071 note repeated it in prose: *"0.24% right now vs a 36,452.39% 30-day average."* That is 36× the
product's own `APY_SANITY_LIMIT` (1000%), on a pool the app does **not** flag as anomalous.

## Intuition
The trust rails are enforced **per field**. `totalApy` (= `apyBase + apyReward`) is railed and
anomaly-flagged (`PoolDetail.js:164/242`), but `apyMean30d` had exactly one gate —
`typeof pool.apyMean30d === 'number'` — so any number DefiLlama reports went straight to the screen. This
pool's current rate is a perfectly sane 0.24%, so every rail the page *does* have said "trustworthy",
while the card beside it said 36,452%.

This is item **122**'s bug class (the −900T rate-stability score) on the same surface, and it inherits
122's key subtlety: **`Number.isFinite` alone does not catch it**. 36,452.38798 is a perfectly finite
number. The gate has to be a *magnitude* check against the rail.

## What changed and why (diff in reading order)
1. **`PoolDetail.js:158-164`** — one derived boolean, placed immediately after `APY_SANITY_LIMIT_LOCAL`:
   ```js
   const mean30dSane = typeof pool.apyMean30d === 'number' &&
     Number.isFinite(pool.apyMean30d) &&
     pool.apyMean30d >= 0 &&
     pool.apyMean30d <= APY_SANITY_LIMIT_LOCAL;
   ```
   Four terms, four real failure modes: missing, `Infinity`/`NaN`, negative, out-of-rail.
2. **`PoolDetail.js:1290`** — the "30d Mean APY" stat card now renders only when `mean30dSane`. We show
   **nothing** rather than a clamped or "corrected" figure — 122's precedent (`apySharpe = null` for a
   flat pool): honest omission beats a fabricated number.
3. **`PoolDetail.js:1376`** — the 071 rate-volatility note's divergence boolean takes `mean30dSane` as its
   first term, so the prose can never quote a number the card refuses to show.
4. **`PoolDetail.js:1404 / 1452 / 1498`** — the three sibling notes (track-record 088.1, momentum 103,
   tvl-trend) each carry a *negated* copy of that same divergence boolean so they stay mutually exclusive
   with 071. Only the `typeof …` term was swapped in each; the `!( … )` structure and every other term are
   untouched. Net effect on the bad pool: 071 goes quiet and a sibling becomes eligible — no visual gap.
5. **`PoolDetail.compiled.js` / `.compiled.min.js`** — regenerated (`npm run compile && npm run minify`);
   byte-identity freshness gates green. `home.html` loads the minified artifact, so this is what ships.
6. **`test_mean30d_sanity.js`** (new, wired into `npm test`) — 8 assertions on real Chromium renders of
   `/?pool=<id>`, fixture-routed in the `test_rate_volatility.js` style.

## Why we trust the test (negative control)
Run against stashed changes — i.e. against the shipped bug — the test fails **5/8** with the real strings:
```
✗ expected no "30d Mean APY" card, got: 30d Mean APY36,452.39%
✗ expected no .rate-volatility-note, got: This pool's rate moves a lot: 0.24% right now vs a 36,452.39% …
✗ got: 30d Mean APY0%      (NaN)
✗ got: 30d Mean APY-12.5%  (negative)
✗ got: 30d Mean APY∞%      (Infinity)
```
The two "sane pool" assertions pass **before and after** — that is the no-over-suppression control, and
`test_rate_volatility.js` stays 5/5, so item 071 is provably intact.

Worth recording: pre-fix, a `NaN` mean rendered as **`0%`**, because `_formatApy` is
`Number(pct || 0).toLocaleString(…)`. A fabricated `0%` is arguably worse than a visibly broken one — the
load-bearing assertion in the junk cases is *card absent*, not *no "NaN"* text.

## Deviations from spec
One, documented in `specs/144-notes.md` §1: `JSON.stringify({apyMean30d: NaN})` emits `null`, so a
JSON-routed NaN fixture would have been vacuous. The NaN case ships a sane `999` in the routed body and an
`addInitScript` shim rewrites that one pool's field to a real `NaN` before React renders. It is
self-verifying — if the shim ever stops applying, the card renders `999%` and the assertion fails loudly.
The render under test is still 100% real DOM. Also additive: a third junk case (`Infinity` via `1e999`),
which needs no shim at all.

Model note: the build agent ran on the **Opus** tier, not Sonnet 5 as this run's instruction specified —
three consecutive Sonnet 5 dispatches died on API 529 (capacity) with zero work produced. Flagged rather
than silently claimed, per the 2026-07-13 precedent.

## Trust rails
**Strengthened, never weakened.** No constant changed: `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly
demotion and the degen haircut are all untouched. This adds a bound where none existed. Not on the NEVER
list (weakening is forbidden; adding a rail is the point of the rails).

## Known-red, pre-existing (proven, not caused here)
`test_minified_assets.js` fails 2 assertions — `home.html` does not load `translations.min.js`, `plan.html`
still loads raw `planner.js`. Byte-identical failures reproduced on a `git stash` baseline. Both
`PoolDetail` byte-identity assertions — the ones this item could plausibly break — are green.

## Measurement
No isolable funnel metric (a trust/correctness fix). Proxy: pool-detail never renders an APY figure above
the rail; watch north-star `pool_click{garden_cta|protocol_link}` CTR now that the flagship page can't show
a 36,452% "average". Render-path merge → advisory human visual spot-check (003 smoke gate not yet shipped).

## Follow-ups observed (not built — spec non-goals)
- `compute-kpis.js`: the same pool has `kpis.apyMean = 21731`, `apyStdev = 72072`, yet `apySharpe = 0.3`
  passes 122's `|Sharpe| ≤ 50` gate — a stability score derived from out-of-rail history.
- Anomaly **risk classification** still keys off `totalApy` only, so this pool stays un-flagged despite an
  out-of-rail 30d mean. Changes rendered risk app-wide → its own item.
- `audit-app.js` blind spot (recorded in `playbooks/product-audit.md`): its `ABSURD_MAGNITUDE = 1e11`
  cannot see a 3.6e4 percentage. A rail-relative percent check would have caught 144 automatically.
- The 071 divergence boolean is now duplicated 4× with a 5-term body — a behavior-neutral cleanup
  candidate, deliberately skipped to keep this diff surgical.
