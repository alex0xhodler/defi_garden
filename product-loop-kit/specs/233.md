The row's hypothesis (b) is **half right and the wrong half**: `boundingBox()` is indeed *not*
opacity-gated — `ctaCount` was 1 and the box non-null at t=0 on all five surfaces, so 231's exact
mechanism (a still-fading victim reading as invisible) does **not** transfer. The failure mode transfers
through a *different* door: `.search-section` / `.results-section` / `.pool-hero-card` /
`.quick-metrics` / `.calculator-compact` / `.pool-info-section` / `.metric-card-simple` animate with
**`fadeInScale`** (`style.css:4580`, `scale(0.95) → 1`) and `.filters-section` with **`slideInLeft`**
(`style.css:4592`, `translateX(-20px) → 0`). Those are **ancestor transforms**, and
`getBoundingClientRect()` — which is what `boundingBox()` returns — reports the **transformed** rect. So
the numbers `checkResponsive` compares against `s.width` are literally shrunk toward the viewport centre
by up to 5 % for the first ~1.2 s. The mapping measured on `pool-detail-360` is exactly
`x → 180 + 0.95·(x − 180)` (scale 0.95 about the viewport centre; reproduced on both the clean and the
defected page).

**What that blindness costs, stated as a rule rather than an instance:** the lens cannot see any
responsive defect whose magnitude is smaller than ~5 % of the element's distance from the viewport
centre. On `pool-detail-360` that is every left-clip with an at-rest `box.x` in **[−10.5, −1)** and every
right-overflow with an at-rest right edge in **(361, 370.5]**. Marginal ancestor-clipping is precisely
the shape of the bug this check was added for (item 136).

Confirmed by construction on the real surface: with `.cta-button-primary{position:relative;left:-76px}`
injected — a permanent defect, at-rest `box.x = −4`, `scrollWidth` untouched at 360 so only the
ancestor-clip leg is exercised — the box reads `x = +5.2` at t=0, `+3.3` at t=200, `−0.9` at t=400 (still
inside the `< -1` threshold) and `−4` from t=800. **Blind window ≈ 0–500 ms; the lens measures at ≈ 0 ms.**

**Pre-fix detection rate on that permanently-broken surface — un-instrumented shipped path, N=10
isolated `runAudit()` processes, mean 3,790 ms/iteration: `0/10`.** Not "sometimes"; *never*. (The
instrumented build detects it every time — playbook trap 1 — so the shipped path's rate was measured
separately, with `audit-app.js` restored byte-identically first, and it is the only number that counts.)

## Hypothesis
We believe replacing `checkResponsive`'s inherited implicit settle with the **same mechanism-derived
`waitForQuiescence` predicate item 231 already shipped** (no running non-`Infinity` CSS animation + a
geometry signature stable across two samples ≥100 ms apart) will raise its detection rate on a
permanently-broken surface from the measured pre-fix rate to ≥19/20, because the defect is not
intermittency or contention but a deterministic ancestor-transform distortion with a measured ~500 ms
blind window and a measured ~1200 ms genuine settle. Confidence: **validated-pattern** — the identical
fix on the identical mechanism was measured 2/10 → 20/20 six hours earlier (item 231), and this run has
already measured the distortion itself on the real surfaces.
- Instance of: **checks in `audit-app.js` that measure at a constant instead of waiting for the mechanism
  they depend on.** Population as counted by the heartbeat: 4 `page.waitForTimeout(` sites plus
  `checkResponsive`'s inherited timing.
- Class closed by this item: **partially, with the numbers.** This item closes `checkResponsive`
  (the last of the 2 geometry-reading lenses) and the `:3642` 400 ms static settle. `:3475` is **not** a
  settle — it is `pollFor()`'s poll *interval*, which cannot decide a measurement (the predicate is
  re-evaluated until true or deadline), and this spec states that with evidence rather than converting
  it. Remaining open after this item: **0 of 4 fixed settles**, with `:3475` reclassified, and the
  3 surfaces whose CTA geometry happens to be transform-free today (`landing-360`, `planner-360`,
  `plan-bloom-360`) — those are covered by the same wait, so no separate ticket is needed.

## Change
Smallest change that tests the hypothesis:

1. `checkResponsive(page, s, findings, ctaSelector)` calls the **existing** `waitForQuiescence(page,
   OCCLUSION_QUIESCENCE_BUDGET_MS)` before its first read — reused, never re-implemented (RAZOR / the
   one-implementation rule). On timeout it pushes a P2 `responsive` advisory naming the numbers and
   **measures anyway** (231's rule: a readiness wait that can silently skip a measurement has only moved
   the false negative one layer down).
2. Kill switch, house convention, same shape as 231's: `s.responsiveQuiescence !== false &&
   process.env.AUDIT_RESPONSIVE_QUIESCENCE !== '0'`, resolved once into `ctx` by `runAudit()` and stamped
   onto the surface object by `main()`. Default ON. When OFF, the pre-233 behaviour is reproduced
   **exactly** (no wait at all) — this is what the positive-control leg drives.
3. The `kind: 'static'` branch's `await page.waitForTimeout(400)` (`audit-app.js:3642`) is replaced by the
   same `waitForQuiescence` call, under the same switch.
4. A P2 advisory when `ctaSelector` matches **zero** elements. Today that branch skips the entire
   ancestor-clip check **silently** — "a check that cannot go red is not a check", generalised in 231 to
   "a check that must never go silent". (Measured: `ctaCount` was 1 at t=0 on all five 360 px surfaces,
   so this is not the observed defect — it is the silent-failure hole next to it, and it is one `if`.)

**OUT of scope:** any product file (`style.css`, `app.js`, `home.html`, `planner.js`, `PoolDetail.js` —
this is loop tooling only), the `:3475` poll interval, changing what `checkResponsive` *asserts*
(thresholds, selectors, severities), and the occlusion lens.

## Territory notes
- `checkResponsive` runs **before** `checkOcclusion` in every driver and **before** any
  `page.setViewportSize()` call — the page is created at `s.width` by `browser.newPage({ viewport })`
  (`audit-app.js:3553`). So it is racing the *initial mount* animation, not 231's resize-triggered
  re-mount. Same animations, different trigger; the same predicate covers both.
- `--entry-delay-base: 100ms`, `--entry-duration-normal: 750ms`, `--entry-duration-fast: 400ms`
  (`style.css:151-153`); delays run to `base * 5`, so worst-case genuine settle is
  `500 + 750 = 1250 ms` — matching the measured ~1200 ms.
- `opts.injectStyle` (built by item 231) is the mechanism for creating a permanent defect on a real
  surface without touching a committed stylesheet, and is already threaded through both `page.goto` call
  sites. Reuse it; do not add a second injection path.
- Playbook trap 1 is live in this territory and was hit during the pre-build measurement: the
  instrumented build (which sleeps to sample) detected the injected defect **every** time, while the
  shipped path is measured separately. Never quote an instrumented rate as the shipped rate.
- Port hygiene: `test_audit_occlusion_lens_reliability.js` claims 9200/9250/9300 and the audit-lens tests
  claim 8901-8975. This item's diagnostic used 9411-9441 and 9500+; a new test file must claim a fresh,
  unused base.
