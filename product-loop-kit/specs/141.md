# 141 — CI honesty: remove the dead search-engine sitemap-ping step

**Status source:** promoted from BACKLOG row 141 (heartbeat, P3 CI honesty). No prior spec existed; written from documented evidence (BACKLOG row + the 2026-07-25 06:34 `sitemap-update.yml` run log cited there) per build.md's "no spec file → write one from documented evidence" rule.

## Problem (the misleading green)
`.github/workflows/sitemap-update.yml` has a step named **"Ping Google about sitemap update"** that, on every daily run where the sitemap changed, curls two long-dead HTTP endpoints and then unconditionally echoes `✅ Search engines notified`:

```yaml
- name: Ping Google about sitemap update
  if: steps.verify-changed-files.outputs.changed == 'true'
  run: |
    echo "🔔 Notifying search engines about sitemap update..."
    # Ping Google
    curl -s "https://www.google.com/ping?sitemap=https://www.defi.garden/sitemap.xml" || echo "Google ping failed"
    # Ping Bing
    curl -s "https://www.bing.com/ping?sitemap=https://www.defi.garden/sitemap.xml" || echo "Bing ping failed"
    echo "✅ Search engines notified"
```

Both curls hit endpoints that no longer accept sitemap pings, yet the step always prints "✅ Search engines notified" — a **misleading green**: the CI log claims a notification happened when nothing did. Same failure class as item 078 (a dead CI signal that reads as healthy).

## Evidence (both endpoints are dead; deprecations confirmed 2026-07-25)
- **Google** `google.com/ping?sitemap=` — deprecated by Google in a June 2023 Search Central announcement; the endpoint now returns **HTTP 404** (confirmed in the item's cited 2026-07-25 06:34 workflow log). Google's guidance: submit via `robots.txt` + Search Console instead (both already in place — `robots.txt` references the sitemap; GSC is human-owned per standing decision 2026-07-12 Q3).
- **Bing** `bing.com/ping?sitemap=` — deprecated by Microsoft (announced 2022); the endpoint returns **HTTP 410 Gone**. Bing/Yandex explicitly direct site owners to **IndexNow** instead.
- **IndexNow** — the live, working notification path — is a **separate** step immediately after (`- name: Ping IndexNow` → `node indexnow-ping.js`), verified **HTTP 200** in the same 2026-07-25 log (item 022's live proof: run 30147683111 submitted 2,102 URLs, HTTP 200). This step is **kept, untouched**.

## Change (smallest honest fix)
Delete the entire dead **"Ping Google about sitemap update"** step from `sitemap-update.yml`. Nothing in it does useful work: both pings 404/410, and the only other line is the misleading echo. The BACKLOG row says "remove the Google ping call (keep IndexNow)"; the honest reading is to remove the whole dead step, because the Bing line in the *same step* is equally dead (410) and the "✅ Search engines notified" echo is the misleading green the item targets — leaving Bing + the echo would preserve the exact dishonesty. IndexNow (the live path, kept) already covers Bing + Yandex, so no notification capability is lost.

- Remove lines 188–200 (the step + its trailing blank line) of `.github/workflows/sitemap-update.yml`.
- Touch **nothing else**: the IndexNow step, sitemap generation, validation, commit, and summary steps are byte-unchanged.
