# 125 — PR explainer (HIGH tier): repeat the primary CTA after Pool Info

## Goal
The pool-detail page is the north-star surface (2026-07-23: conversion clicks = `pool_click{source=garden_cta}` + `pool_click{source=protocol_link}`). It's a LONG page — hero → 3 stat cards → Long Game → calculator → Pool Information — yet both CTAs lived ONLY in the top-right hero card. A reader who scrolls to the bottom to read Pool Information hits a dead-end and must scroll back up to convert. Most acute on mobile, where the hero is far off-screen by then. Every scrolled-away CTA is lost conversion directly upstream of the metric.

## Intuition
Give the reader a second chance to convert exactly where their attention already is — the bottom of the page — without asking them to scroll back. The cheapest, tidiest way to do that is to repeat the two CTAs they already know from the hero, reusing the same components so there's nothing new to design, style, or maintain. And because it's a *second* placement of the *same* CTA, we tag each with a placement label so we can later measure how much the repeat actually earns.

## What changed and why (diff in reading order)

**1. `PoolDetail.js` — hero CTA calls gain a placement label (`:497`, `:517`).**
- The hero `garden_cta` `trackPoolClick` props object gains `ctaPlacement: 'hero'`.
- The hero `protocol_link` call goes from `trackPoolClick(pool, 'protocol_link')` → `trackPoolClick(pool, 'protocol_link', { ctaPlacement: 'hero' })`.
- Why: so hero and repeat clicks are symmetrically labelled and a Mixpanel breakdown by `ctaPlacement` can attribute conversions to placement. `source` is untouched — the north-star query (which filters on `source`) counts both placements identically.

**2. `PoolDetail.js` — the repeat block (new final child of the root `div`, after the Pool Information section).**
- Wrapper reuses `.pool-action-card` with inline `maxWidth: 420px; margin: 32px auto 0` (token-based sizing only — no new CSS class).
- A heading `<p>` using the new `repeatCtaHeading` key.
- Primary `.cta-button-primary` `<a>` — identical `href` (`gardenThisPoolHref`) and identical `showConcreteCta` concrete/generic label logic as the hero; fires `garden_cta` with `ctaPlacement: 'repeat_footer'`.
- `.pool-action-hint` (`plannerCtaHint`).
- `protocolUrlWithRef`-guarded `.cta-button-protocol` `<button>` — identical `window.open` behavior; fires `protocol_link` with `ctaPlacement: 'repeat_footer'`.
- Guarded `.pool-action-hint--muted` (`opensProtocol`).
- Why reuse: standing decision 2026-07-10 (REUSE COMPONENTS, KEEP DESIGN TIDY) — a new class, gradient, or one-off style would be a verifier FAIL. Zero CSS changed (`git diff --stat pool-detail-styles.css` empty, verifier-confirmed).

**3. `analytics.js` — `trackPoolClick` payload gains `ctaPlacement` (`:241`).**
- Added one additive line: `ctaPlacement: context.ctaPlacement || null`. The method's third arg is `context` and it cherry-picks specific keys into the event; `ctaPlacement` was not among them, so it would have been silently dropped. This line makes it reach the wire under key `ctaPlacement` (`'hero'`/`'repeat_footer'`/`null`).
- `source` (`:233`), the `'pool_click'` event name, and every other key are untouched. No rename. No trust-rail. Additive only.

**4. `translations.js` — `repeatCtaHeading` (EN + KO together).**
- EN `"Ready to start this garden?"`, KO `"이 가든을 시작할 준비가 되셨나요?"`. One language alone would be a verifier FAIL.

**5. Compiled/min assets regenerated** — `PoolDetail.compiled.js`, `PoolDetail.compiled.min.js`, `translations.min.js` via `npm run compile && npm run minify` (idempotent). Verifier confirmed the min output carries `repeat_footer` ×2, `ctaPlacement` ×4, `repeatCtaHeading` ×2 — not stale.

**6. `test_repeat_cta.js` (new) + `package.json` wiring** — rendered chromium test, 5/5, wired into the `npm test` chain after `test_northstar_cta_fires.js`.

## Trust rails / scope
Untouched: `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly demotion, degen haircut, `__APP_MODE` router, `?token=/?chain=/?pool=`. The repeat block reuses `showConcreteCta = !isAnomalous`, so anomalous pools get the generic (non-projection) CTA in the repeat block too — no anomalous projection leaks. `package.json` change is test-chain wiring only, NOT a dependency change. Not on the NEVER list.

## Deviations from spec
Only the spec-anticipated `analytics.js` adaptation (see 125-notes.md). Nothing else.

## Risk tier
HIGH — a wholly new rendered UI element on the pool-detail render path ("anything user-facing beyond copy/styling"; "when in doubt → HIGH"). Auto-merges under autonomy (c) after verifier PASS + tests green; NOT on the NEVER list. Render-path merge → needs human visual spot-check (no automated pixel QA until backlog 003's gate covers this surface).
