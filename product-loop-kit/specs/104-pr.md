# 104 — PR explainer (HIGH tier): TVL-trend honesty note on pool detail

## Goal

Item 088 (the human's 2026-07-14 directive) is: "start creating interesting KPIs that help
users take better decisions given their ICP." The ICP is the cautious retail saver who
thinks in monthly deposits and life goals, not APY/pools — so KPIs must translate raw pool
data into trust/stability/decision language, never more degen metrics. Item 087 built the
pipeline that COMPUTES per-pool KPI fields into the static snapshot
(`historyPoints`, `firstSeen`, `apyMomentum`, `apyStdev`, `tvlTrend`). The 088 legs SURFACE
them one at a time: 088.1 shipped the rate-track-record (steadiness) note, 103 shipped the
rate-momentum (rising/falling) note. **Item 104 is the next surfacing: the `tvlTrend` field
— whether a pool's deposit base is growing or shrinking.**

## Intuition

The app already filters every pool through a static $10M TVL floor (`DEFAULT_MIN_TVL`). But
a floor is a snapshot: a pool sitting at $12M today could have been $30M a month ago and be
bleeding deposits — still "passing" the floor while quietly heading for the exit. For a
cautious saver picking a pool to fund a garden they'll hold for *years*, the **direction**
of the deposit base is decision-relevant in a way the static floor can't express. 087 now
retains daily TVL points, so we can say one honest sentence: deposits have grown/shrunk
about X% over the N days we've tracked it — with the shrinking case flagged as the risk it
is, and the growing case explicitly *not* sold as a guarantee.

## What changed and why (diff in reading order)

1. **`PoolDetail.js` (~line 1404)** — a new `.tvl-trend-note` `React.createElement` block,
   placed immediately after the 103 rate-momentum note and before the Tokens Section. It is
   a carbon copy of the momentum note's *shape*:
   - **Gate**: renders only when `!(071 volatility boolean)` AND `pool.kpis` is an object AND
     `typeof pool.kpis.tvlTrend === 'number'` AND `historyPoints >= 7` AND
     `|tvlTrend| >= 0.25`. Every clause is a conservative guard: 071 wins if APY is volatile
     (one note, never two); a missing/live-SEO pool has no `kpis` → nothing renders; a
     sub-7-point window can't call a trend; a sub-25% move is noise, not a trend.
   - **Body** (IIFE): `pctStr = _formatNum(Math.round(|tvl| * 100)) + '%'` (en-US grouping
     via the existing helper — never bare `toLocaleString`, so `1,200%` groups correctly);
     `tvl <= -0.25` → SHRINKING copy, else GROWING copy.
   - **Styling**: reuses 071's exact neuro tokens (`--color-background`,
     `--neuro-radius-sm`, `--neuro-shadow-subtle`, `--color-text-secondary`,
     `--font-size-sm`, etc.). No new CSS, no one-off gradient — token system only.
   - **Trust rails**: reads only `pool.kpis.*` and the 071 APY fields. It NEVER reads or
     writes `APY_SANITY_LIMIT` / `DEFAULT_MIN_TVL` / anomaly flags / the degen haircut, and
     never filters, reorders, re-weights, or re-flags a pool. Rails byte-untouched.
2. **`translations.js`** — two keys added to BOTH the EN block and the KO block (together,
   never one alone): `tvlTrendShrinking(pct, hp)` and `tvlTrendGrowing(pct, hp)`. Calm
   cautious-saver, education-not-advice framing. The shrinking copy names the exact
   ICP-relevant risk ("A pool can keep clearing our $10M size floor while quietly losing
   deposits"); the growing copy refuses the hype ("More deposits isn't a guarantee").
   `${pct}` is the pre-formatted percent string incl. `%`.
3. **`PoolDetail.compiled.js`, `PoolDetail.compiled.min.js`, `translations.min.js`** —
   regenerated via `npm run compile && npm run minify` (home.html loads the minified
   artifacts; editing source without regenerating breaks `test_compiled_assets` /
   `test_minified_assets`). The 7 "byte-identical to a fresh minify" assertions all pass.
4. **`test_kpi_tvl_trend.js`** (new) — a rendered-Playwright gate mirroring
   `test_kpi_momentum.js`. Drives the REAL pool-detail UI via `?pool=<id>` against
   DefiLlama-shaped fixtures and asserts on the rendered `.tvl-trend-note` DOM: shrink/grow
   copy + percent + day count (D1/D2), absence below threshold / short window / no-kpis /
   null-tvl (D3–D5), 071 mutual exclusion (D6), Korean copy (D7), zero page errors (D8).
   8/8. Wired into `package.json` after `test_kpi_seo_enrichment.js`.
