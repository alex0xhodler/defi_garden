**Root cause of each, classified per `playbooks/pre-existing-red-triage.md` — all four are decision rule
B (stale test; the product deliberately moved), none is a product defect.** Each root cause is a
*widening* that shipped with its own green test and never updated these witnesses:

1. **`:320` ← item 203.** The estate's pool anchors now carry `&src=seo_token` (the north-star attribution
   rail). Measured: `tokens/usdc.html` emits
   `class="tp-pool-link" href="https://www.defi.garden/?pool=43641cf5-…&src=seo_token"`, while
   `ANCHOR_HREF_RE` at `:315` is `/(class="tp-pool-link" href="https:\/\/www\.defi\.garden\/\?pool=)([0-9a-f-]+)(")/i`
   — it requires the closing quote *immediately* after the id, so it matches **zero** anchors.
2. **`:520` / `:711` ← item 199.** `buildPoolSurfaces()` now appends lens surfaces (`audit-app.js:3106`,
   `lensPick: true`, deliberately **not** `rotationPick` — spec 199 §4, so they are never double-counted)
   into the same `extraSurfaces` array. Both assertions were written pre-199 and equate `extraSurfaces`
   with "the rotation picks": 3 picks now arrive as 6 entries (3 rotation + 3 lens).
3. **`:117` ← item 201.** The bloom branch's responsive check was widened from 360-only to 360+768:
   `audit-app.js:3689-3691` reads `// responsive — 360 + 768 surfaces (widened by backlog 201)` /
   `if (s.width <= 768) await checkResponsive(page, s, findings, '.gp-checkout-cta');`. The assertion
   still greps the source for the literal `s.width <= 360`. **The product got strictly better and the
   guard went red for it.**

**Why this scores where it does.** `package.json`'s `test:serial` is the only pre-ship gate this repo has
(item 205's evidence: `.github/workflows/` holds `sitemap-update.yml` alone — there is no test CI), and
every one of these four assertions is a **fixture-wiring check guarding a guard**: the checks that prove
the pool-link liveness gate, the rotation-honesty accounting, and the bloom-surface detector set are
actually pointed at something real. Two of the three files guard machinery on the **north-star surface**
(`?pool=` pool-detail) and one guards the rotation accounting item **206 shipped yesterday** onto the
3,984-candidate arrival population. A red fixture-wiring check is the loudest possible version of the
failure mode `pre-existing-red-triage.md` calls *"a green test file that nothing runs is not a gate"* —
except here the gate is red and has been read as background noise across at least two runs.

## Hypothesis

We believe **re-pointing these four assertions at the shape the product actually has today — without
relaxing any of them** will **restore four fixture-wiring guards to a state where they can go red for the
reason they were written**, because all four failures are decision-rule-B drift with a documented,
in-repo, already-tested cause (199/201/203), and in each case the assertion's *intent* still holds
exactly while only its *literal* is stale. Confidence: **validated-pattern** (items 156, 176 and 185 are
the same class, same repo, same playbook).

## Change

Test-file-only diff. **No product file, generator, generated surface, or dependency is touched.**

1. `test_audit_pool_link_liveness.js` — make `ANCHOR_HREF_RE` (`:315`) tolerate (and **preserve**) an
   arbitrary post-id query tail, so it matches today's `&src=…` anchors and any future param. The
   id-swap at `:326` must keep asserting the swapped id is backed by its own `tp-pool-link` anchor
   *with that tail intact* — the test's whole point is that this is a **stale** failure, never a
   **contract** failure. The minimal page builder at `:83` should emit the production anchor shape
   (`&src=`) so the synthetic fixtures stop encoding a shape the estate no longer produces.
2. `test_audit_cta_provenance.js` `:520` and `:711` — partition `pre.extraSurfaces` into rotation picks
   and lens picks instead of assuming they are the same set. Assert **`rotationPick` entries ===
   `poolSample`**, and add the assertion whose absence let this drift in: **every non-`rotationPick`
   entry is a `lensPick`** (a third, unclassified kind must still fail). Downstream uses of `pickNames`
   (the `only: [...]` lists, the skipped/rendered/`seen` accounting) must be re-derived so that every
   *existing* assertion in both tests keeps asserting the same thing it did before 199 — in particular
   `written1.seen.length === 1`, `renderedCount === poolSample`, `truncated === false`, and the
   `baseSeen` protection assertion at the heart of the second test.
3. `test_audit_planner_flow.js` `:117` — assert the bloom branch's responsive check is **scoped to small
   viewports** against the boundary the product has today (`s.width <= 768`, 201's widening), not the
   retired `360` literal. Keep the `checkResponsive(page, s, findings` half unchanged.
