# 273 — the KO/theme toggles stop landing on the search input (mobile, `?pool=`)

**What the human saw.** Dark theme, "STETH" in the search field, phone width: both header toggles
painted on top of the input's right end. "bad ux, fix it immediately."
**Where it was.** Not `?token=`/`?chain=` — clean at every width (222 fixed that row; re-measured
here). It is `?pool=`, which spec 247 gave the *same* sticky bar pre-filled with the query.

**The mechanism.** `style.css` has two mobile rules meant only for the homepage's free-floating
toggle pair: `.app:not(.has-results) .theme-toggle` / `… .language-toggle` (`<=640px` and `<=480px`
tiers, both `position: fixed`). `:not(.has-results)` counts as a class, so they weigh (0,3,0) —
heavier than 222's in-flow reset `.app-header-controls .theme-toggle` at (0,2,0) — and they were
written as **descendant** selectors. 222 argued they could never fire on a page with a header, since
`has-results` and `:not(.has-results)` are exclusive. True for results pages; the pool view is
`.app.pool-detail-view`, is *not* `has-results`, and renders a header. So both rules reached the
header's buttons two levels down and pinned them to the floating pair's coordinates — on the input.
At 360×780 the KO button overlapped `.app-search-input` by 1036px²; `.app-header-controls` was 0×0.

**The fix.** One character, four times: a `>` child combinator, so those rules reach only the
standalone pair (direct children of `.app`), never the header's grandchildren. The same sheet
already spells out that argument above `.app.has-results > .theme-toggle {display:none}`; this
applies it to the rules 222 didn't reach. CSS-only; `style.min.css` regenerated.

**Diff in reading order.**
1. `style.css` — 4 selectors gain `>`, plus a comment naming the specificity arithmetic.
2. `style.min.css` — regenerated (`npm run minify`); only this asset changed.
3. `test_header_controls_overlap.js` (new) — derives the control population from the DOM at test
   time; on both analytics surfaces at 320/360/480/768/1280 × light/dark × EN/KO asserts boxes
   disjoint from the search bar, controls pressable via `elementFromPoint`, input focusable and
   typeable, long queries clear, no overflow, homepage not regressed. Carries its own red proof.
4. `package.json` — one step added to `test:serial`; `test_test_registry.js` 5/5 green.

**Evidence.** 110/110 green. Reverting just the sheets (md5-tracked, byte-identical restore) gives
90/110, all 20 failures at 320/360/480 on `?pool=`. Box-compare vs the stashed baseline: `?token=`
identical at all five widths; `?pool=` unchanged at 768/1280; homepage pair unchanged everywhere.

**Deviation.** Boxes are clipped by their overflow ancestors before comparison (`.app-search-bar` is
`overflow: hidden` on mobile; raw rects there count pixels nobody can see or touch). Details and the
one pre-existing artifact this hides: `specs/273-notes.md`.
