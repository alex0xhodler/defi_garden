# Spec 005: One share hub at bloom — image-first, and the link always travels

## Evidence
Human review of production (2026-07-10, screenshot): the 004 prompt card AND the old footer share row ("📸 Share my garden" + "🔗 Copy link") are both visible → redundant. Human directive: the garden IMAGE is the hero share artifact ("users get an image with their garden status — that could be even more viral"). Lifetime `share_link_created`: still 0. Structural gap: a shared image alone carries NO URL — it can never fire `share_link_opened`, so image shares can't close the north-star loop.

## Hypothesis
We believe ONE image-first share hub at the bloom moment — where every share path (including the image) carries the plan URL — will produce the first organic shares AND make each of them loop-closable. Confidence: supported (human picked the artifact; the redundancy is observed).

## Change
Smallest version:
1. The 004 prompt card (`.gp-share-prompt`, planner.js ~2554) becomes the ONLY share surface in bloom: primary button "📸 Share my garden" (existing `doShare` image flow), secondary the existing native-share/copy-link button.
2. Remove the now-duplicate share buttons from `footElement` (keep unrelated footer content, e.g. "As featured on…").
3. The image path must carry the link: where `navigator.share` supports files, share the rendered image TOGETHER with the plan URL + one short line of text (reuse `encodePlanToUrl`); otherwise, after the image download, copy the plan URL to the clipboard and confirm in the UI ("Image saved — link copied"). Investigate `renderShareImage` first and extend its completion path, don't rewrite it.
4. Track every path with the EXISTING event: `share_link_created` with `method` = 'image' | 'native' | 'copy' (new property VALUE is fine; new event NAMES are not).

OUT of scope: redesigning the share image itself, referral/attribution params beyond the existing URL, waitlist/checkout panel changes, any router/URL semantics.

## Acceptance criteria
- [ ] Exactly ONE share surface renders in bloom (grep/trace proves the footer duplicate is gone and no orphan handlers remain)
- [ ] Image share results in BOTH the image artifact and the plan URL leaving the device (Web Share API with files+url/text where supported; else download + clipboard copy with visible confirmation)
- [ ] `share_link_created` fires on all three methods, with the `method` property set (trace each call site)
- [ ] New user-facing strings exist in BOTH en and ko (translations.js planner sections — add new keys at the very END of each planner block to avoid collisions)
- [ ] Neumorphic tokens only; no banned effects; reduced-motion respected; works at 360/768/1280 by construction
- [ ] `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` exit 0 (the Playwright smoke runs on the human's machine — note it, don't fake it)

## Measurement
Metric: weekly `share_link_created` by method, then `share_link_opened` · Window: 14 days (until 2026-07-24) · Decision rule: ≥1 organic share = keep + iterate on the winning method; 0 = revert-candidate, hypothesis moves to incentive/timing.
