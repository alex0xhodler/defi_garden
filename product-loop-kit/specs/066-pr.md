# 066 — PR explainer (HIGH tier)

## Goal
Give the 2,131-page static SEO surface (`/tokens/<slug>`) a reason to push a stranger toward the waitlist — the card funnel, DeFi Garden's current north star. Today those pages show a bare pool table plus a generic waitlist CTA (062); nothing on the page makes the card pitch ("your idle capital's yield pays a subscription") concrete for the specific token the visitor searched. 066 adds one honest, computed-from-live-data headline: *"Your idle USDC could earn ~8.42% — park $2,850 and it could run a $20/mo Claude Pro subscription, forever."*

## Intuition
The product's business model (NORTH_STAR.md, 2026-07-12 interview) is a card that spends yield, never principal — the "forever number" is the whole pitch. The planner already computes this exact concept for logged-in-plan users (`blendedApy` + `foreverNumber` in `planner.js`). This item just puts the SAME two numbers, computed from the SAME live pool data every other number on a token page already passes through the trust rails, in front of someone who hasn't opened the planner yet — a proof-of-concept of the card pitch, one click before the waitlist CTA.

Two things keep it honest, per CLAUDE.md's "honest numbers beat exciting numbers" and the 058 STUDY's no-backend/no-fabrication constraint:
1. **No new calc path.** The headline reuses `planner.js`'s own `blendedApy` (median APY across a token's pools — deliberately the median, not the page's pre-existing `Math.max`, because a max is "the single best pool," not a representative blended rate) and `foreverNumber` (capital needed so `capital * rate/12 >= monthly`). If the live planner is ever audited for its "blended"/"forever" math, this headline's math is the same code path, not a parallel one that could silently drift.
2. **No fabricated number.** If a token's blended (median) rate rounds to "0.00%" — which CAN happen even for a token that has a qualifying pool, if the median lands on one of its zero-yield pools — the function returns `null` and the page renders no headline at all. Never a "$Infinity" or "~0.00%" line.

## What changed, in reading order

1. **`generate-token-pages.js`** (the token-page generator, spec 014's original mechanism)
   - `require('./planner.js')` — confirmed live that `planner.js` IS Node-requireable (its own `module.exports = api` guard at the bottom, same convention `translations.js` already uses). A comment in `generate-spotlight.js` claimed otherwise; that claim was checked and found stale/incorrect for this use.
   - New `yieldHeadlineFor(rec, lang)`: `gp.blendedApy(rec.pools)` → `formatApy` → if `"0.00%"`, return `null`. Otherwise `gp.foreverNumber(anchor.monthly, blendedRate)` where `anchor` is the `claude` entry of `planner.js`'s `SUBSCRIPTION_LADDER` ($20/mo, "Claude Pro" — the flagship subscription throughout NORTH_STAR.md and `generate-spotlight.js`'s existing `DEFAULT_GOAL_ID`). Returns `{ apyStr, foreverAmtStr, monthly, subLabel }` or `null`.
   - New `renderYieldHeadlineHtml` renders `<p class="tp-yield-headline">` (empty string if `null`) using the new `tcpYieldHeadline` translation string.
   - Wired into `renderTokenPage`: placed between the intro paragraph and the CTA button — strictly above the pool table (`.tp-card`), matching the spec's "above the table" acceptance criterion, without crowding the existing 047 direct-answer block right after the H1.
   - New scoped CSS `.tp-yield-headline` reuses `var(--color-surface)` / `var(--neuro-radius-md)` / `var(--neuro-shadow-raised)` — no new colors.
   - New exports: `yieldHeadlineFor`, `renderYieldHeadlineHtml`, `yieldHeadlineAnchor`, `ladderLabelText`, `YIELD_HEADLINE_ANCHOR_ID`.

2. **`translations.js`** — new `tcpYieldHeadline(sym, apyStr, foreverAmtStr, monthly, subLabel)` in both the `en` and `ko` blocks (added together, same commit). `translations.min.js` regenerated via `npm run minify` — `plan.html`/token pages load the minified file, and 061's own notes documented a real shipped bug from forgetting this step, so it's called out explicitly here as done.

3. **`generate-spotlight.js`** — the acceptance criterion "generate-spotlight.js pack exposes the same field" is satisfied by importing `foreverNumber` from `planner.js` and adding `pack.foreverAmt` (number), `pack.foreverAmtStr` (string or `null`), and `canvaFields.foreverAmt` to `buildPack`'s output. A spotlight pack always covers exactly one pool, so "blended" (median of a 1-element array) is just that pool's own APY — same function, same honesty guard (`null`, never `"$Infinity"`, when the pool's own APY is 0).

4. **Tests** — `test_token_pages.js` gained 11 assertions (parity with the reused `planner.js` functions, the Claude Pro anchor, the null-on-median-zero honesty gate with a hand-built 3-pool fixture, document-order placement, XSS-escape, EN+KO presence, neuro-token-only styling). `test_spotlight.js` gained 2 assertions (pack field parity, null-on-zero-APY). Both suites run standalone (fixture-driven, no live network) — 88/88 and 38/38 respectively, zero regressions versus the pre-change baseline (77/77 and 36/36).
