# Spec 017: Natural-language search — every advertised example must work

## Evidence
Human report (2026-07-10): the search's typing-animation example queries FAIL when actually typed — the app advertises queries it cannot serve. Expected-to-work classes, verbatim from the human: bare chains ("solana", "base"), protocol names ("kamino", "curve", "convex"), protocol+category combos ("kamino lenders"). Structural rot: `parseNaturalLanguageQuery` lives in app.js:129 (used at 1272/1849), while test_protocol_parsing.js and test_qualifier_fix.js test STALE INLINE COPIES of it — the tests can pass while production drifts. Instrumentation exists: `search_success`, `search_abandonment`, `search_input` events.

## Hypothesis
We believe extracting the parser to a requireable module, turning the REAL typing-animation examples into hard test fixtures, and fixing the parses until all pass will make advertised searches work for every user archetype the examples target — and structurally prevent future drift. Confidence: supported (bug class observed by the human; drift mechanism identified).

## Change (surgical — tidy, no rewrite)
1. Extract `parseNaturalLanguageQuery` + its private helper maps (protocol name map, qualifier words, etc.) VERBATIM into `search-parser.js` — plain script, UMD guard (canonical.js precedent: `module.exports` for node, `window.__parseNLQuery` for browser). app.js calls the global; `<script src="search-parser.js">` added in home.html BEFORE app.js loads (mode-conditional analytics script section — do NOT touch the router block or ANALYTICS_PARAMS).
2. Locate the typing-animation example strings in the code (grep app.js/translations.js for the placeholder/animation array). EVERY example becomes a fixture in a new `test_search.js` (test_planner.js assert style): assert the exact parsed {token, chain, poolTypes, protocols}.
3. Add fixtures for the human's classes: "solana" → chain Solana; "base" → chain Base; "kamino" → protocol kamino; "curve", "convex" → protocols; "kamino lenders" → protocol kamino + poolTypes Lending; plus one token+chain combo and one qualifier query already covered by old tests.
4. Fix the parser until all fixtures pass. Bug-fix rules: root cause in the parser's matching order/maps — no special-casing individual strings with if-hacks unless the string is genuinely irregular; if an example is unfixable without a rewrite, document it and CHANGE THE ADVERTISED EXAMPLE to one that works (advertising honesty beats parser heroics) — flag any such swap prominently.
5. Convert test_protocol_parsing.js and test_qualifier_fix.js to require `search-parser.js` instead of their inline copies — keep their cases, harden prints into asserts where straightforward.
6. package.json test chain += `node test_search.js`.

OUT of scope: search UI/UX, autocomplete behavior, filter semantics beyond fixing wrong parses, router, planner surfaces.

## Acceptance criteria
- [ ] `search-parser.js` is the single source of truth: `grep -n "parseNaturalLanguageQuery" app.js` shows only the call sites + global reference, zero inline copies remain anywhere (including the two old test files)
- [ ] Every typing-animation example string is a fixture in test_search.js with exact expected parse — and passes
- [ ] The human's classes all parse correctly (fixtures above) — verifier re-runs and spot-checks 3 novel same-class queries (e.g. "arbitrum", "morpho lending", "aave") for generalization, not memorization
- [ ] test_protocol_parsing.js / test_qualifier_fix.js require the real module (no drift copies) and still exit 0
- [ ] Full chain exits 0: `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js && node test_canonical.js && node test_search.js`
- [ ] home.html change is EXACTLY one script tag in the analytics-conditional load path; router block byte-identical
