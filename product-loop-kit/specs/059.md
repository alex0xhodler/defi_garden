## What (verbatim from the 058 study's drafted item, now promoted)

A `generate-pools-snapshot.js` CI generator producing a trust-rail-filtered, 13-field snapshot
(+ per-chain/per-token slices) with a `generatedAt` freshness stamp, wired into `sitemap-update.yml`;
FE (`app.js`/`planner.js`/`PoolDetail.js`) reads the snapshot first and falls back to a direct
`yields.llama.fi` fetch when the snapshot is stale (>15 min) or missing.

The 13 used fields (058 §0): pool, chain, project, symbol, tvlUsd, apyBase, apyReward, apyMean30d,
poolMeta, url, exposure, ilRisk, underlyingTokens.

Live `https://yields.llama.fi/pools`, measured with Node 22 + zlib in this repo's sandbox:

| payload | rows | raw bytes | gzip bytes |
|---|---|---|---|
| full `/pools` | 15,416 | 10,575,356 | 2,095,248 |
| 13-field projection, ALL rows | 15,416 | 4,820,471 | 1,285,267 |
| 13-field, `tvlUsd >= $10M` (anomalous kept) | 712 | 202,268 | 50,962 |

The railed snapshot is a **97.6% cut on the wire** (2,095 KB → 51 KB gzip) vs what the FE
downloads today. Anomalous (`apyBase+apyReward > 1000%`) pools above $10M TVL: 0 on measurement
day — the keep-and-flag rule below still applies structurally. Railed set spans 40 chains /
371 distinct symbols (~411 slice files).

## Territory notes (verified in code 2026-07-14 — these BIND the design)

1. **The analytics app renders below $10M TVL on purpose**: `minTvl=0` is respected when
   explicit in the URL (app.js:833-834), and the All/Popular chain modes set 10k/50k floors
   (app.js:3050, 3065). A $10M-railed snapshot therefore CANNOT serve every filter state.
2. **Anomalous pools are rendered, not hidden**, in the analytics app (demoted + ⚠-flagged,
   app.js:2054/2411) — the snapshot must NOT drop them (study §5: ship flags through).
3. **planner.js floors are ≥ $10M** (50M stable / 10M elsewhere, planner.js:533/543) + sanity
   limit client-side — the railed snapshot always covers the planner.
4. **PoolDetail.js has no fetch of its own** — it rides app.js's `pools` state. "FE reads the
   snapshot" = the two fetch sites: app.js:989 and planner.js (`POOLS_API`). The home.html
   WebMCP agent tool keeps its live fetch (out of scope — agent-facing, not the FE hot path).
5. **CI cadence is daily** (`0 2 * * *`), so in production the committed snapshot will be
   older than the 15-min freshness gate almost always → the FE will fall back to live. That is
   the honest, intended leg-1 behavior: this item ships the plumbing, rails, equivalence proof
   and fallback proof; raising cadence is a human decision (every snapshot commit = a Vercel
   deploy — 2026-07-13 quota crisis) and/or 087's job. The snapshot must never be presented
   as fresher than `generatedAt`.
6. **072 shipped the dead-`?pool=` empty state** — a live pool below $10M served from the
   snapshot would falsely render "no longer tracked" on a sacred deep link. `?pool=` loads
   therefore ALWAYS fetch live.

## Full acceptance criteria (written by the picking loop, 2026-07-14)

**A. Generator (`generate-pools-snapshot.js`, Node 18-compatible, zero new deps)**
- A1. Fetches `/pools` once; emits `data/pools-snapshot.json`:
  `{ schemaVersion: 1, generatedAt: ISO-8601, source: "https://yields.llama.fi/pools", minTvlUsd: 10000000, count, pools: [...] }`
  where `pools` = every pool with `tvlUsd >= 10_000_000` (DEFAULT_MIN_TVL — the rail, applied
  upstream, never relaxed), projected onto exactly the 13 used fields; anomalous pools KEPT
  (flag logic stays client-side, unchanged). The builder re-derives the 13-field list by
  grepping app.js/planner.js/PoolDetail.js field accesses — do not trust the study blindly.
- A2. Emits `data/pools-snapshot-meta.json` (tiny: schemaVersion, generatedAt, count, bytes)
  so the FE can check freshness without downloading the full snapshot.
- A3. Emits per-chain slices `data/pools/chain/<slug>.json` and per-token slices
  `data/pools/token/<slug>.json` (same envelope, sliced from the railed set; slug =
  lowercased, URL-safe). No consumer yet — 087/088 build on these.
- A4. Freshness discipline (081/083 pattern): if regenerated output is byte-identical to what's
  on disk modulo `generatedAt` (and meta `bytes`), skip ALL writes — a no-data-change CI run
  must not produce a commit. Stale slice files from disappeared chains/tokens are deleted
  (031 pattern).
- A5. Respects `--out <dir>` for scratch/verification runs — writes NOTHING outside it
  (076 lesson: no cwd-coupled writes into committed surface during verification).
- A6. Trust-rail language: the generator carries a comment stating rails are applied upstream
  and may never be relaxed there; `APY_SANITY_LIMIT`/`DEFAULT_MIN_TVL` values mirrored
  verbatim from app.js.

**B. FE — app.js (edit app.js; regenerate app.compiled.js + app.compiled.min.js via
compile-app.js + minify-assets.js — 061's lesson: unregenerated artifacts ship nothing)**
- B1. Snapshot-first at load ONLY when: no `?pool=` param present AND initial `minTvl >=
  DEFAULT_MIN_TVL`. Otherwise straight to live (today's exact path).
- B2. Snapshot path: fetch meta → if fetch fails, JSON invalid, `schemaVersion !== 1`, or
  `now - generatedAt > 15 min` → live. Else fetch full snapshot, validate (schemaVersion 1,
  non-empty `pools` array) → `setPools(snapshot.pools)`; ANY failure at any step → live
  fallback, identical error handling to today.
- B3. Escape hatch: if pools came from the snapshot and the effective `minTvl` later drops
  below DEFAULT_MIN_TVL (chips, All/Popular chain modes, popstate, reset-to-zero), fetch live
  once and replace `pools`. No filter state may ever show fewer pools than live would.
- B4. Instrumentation: the existing `data_load_time` trackPerformance call carries a new
  `source: 'snapshot' | 'live'` prop (measurable rollout — an unmeasurable change is failed).
- B5. Trust rails in app.js byte-untouched: `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`,
  `isAnomalousApy`, demotion/flag logic, degen haircut. Attribution footer ("Powered by
  Defillama API") untouched.

**C. FE — planner.js (edit planner.js; regenerate planner.min.js)**
- C1. Same meta→fresh→snapshot / anything-fails→live logic in front of the existing
  `POOLS_API` fetch. Planner rails (floors, sanity, stable curation, degen haircut) apply
  unchanged to whichever payload loads. No relax path exists in the planner, so no escape
  hatch needed.

**D. Config/CI**
- D1. `vercel.json`: `/data/(.*)` gets `Cache-Control: public, max-age=300,
  stale-while-revalidate=600`. Nothing else in vercel.json changes.
- D2. `sitemap-update.yml`: new step running `node generate-pools-snapshot.js` (before the
  token/chain generators — future shared source, but those generators are NOT converted this
  pass); `data` added to the `git add` list; `generate-pools-snapshot.js` added to the push
  trigger paths.
- D3. A REAL live-generated `data/` output is committed in this PR (network reaches
  yields.llama.fi via Node in-session — 066 precedent: no false "network-blocked" claims).

**E. Tests (all wired into the npm test chain; every run timeboxed ≤5 min)**
- E1. `test_pools_snapshot.js` (pure Node, fixture input): 13-field projection exact (no
  extra/missing fields), $10M floor applied, anomalous pool KEPT, slices + meta correct,
  idempotency (second run over same data → zero writes), `--out` isolation (nothing written
  outside `--out`), stale-slice deletion.
- E2. `test_snapshot_first.js` (Playwright, fixture-routed per the test_search.js pattern,
  live endpoints blocked/routed):
  (a) fresh snapshot routed + live `/pools` ABORTED → `?token=USDC` renders pool cards
      (SEO-lifeline guardrail proven on the snapshot path);
  (b) snapshot 404 + live fixture → cards render (missing→fallback);
  (c) STALE snapshot (old generatedAt) + live fixture → cards render AND the live request
      was actually made (stale→fallback);
  (d) equivalence: same fixture served as snapshot vs as live → same rendered pool set;
  (e) `?minTvl=10000` + fresh snapshot + live fixture → live used (rail-relax gate);
  (f) bare `/` planner renders from fresh snapshot with live aborted (both router paths);
  (g) `?pool=<id>` + fresh snapshot + live fixture → live used (sacred deep link).
- E3. Full existing `npm test` chain green (077 made it sandbox-runnable).
