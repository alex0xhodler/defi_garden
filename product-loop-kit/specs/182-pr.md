# 182 — the "Start Earning" CTA stops depending on a third-party fetch that is allowed to fail

**Risk tier: HIGH** (verifier-assigned independently, agreeing with the spec's guess) · **Verifier: PASS
on attempt 2, 10/10 acceptance criteria (13/13 including sub-boxes), all independently re-derived** ·
Attempt 1 was a FAIL on missing bookkeeping only — no acceptance criterion ever failed.

---

## The goal, in one sentence

Half the north star could vanish because of somebody else's outage, and the app was written to let that
happen quietly. This makes the CTA's data come from our own origin, and renders something honest when
there genuinely is no link.

## The intuition — why this is a bigger deal than one broken button

The heartbeat's scanner found **one** dead CTA, on one pool. The interesting part is what happened when
the finding was checked rather than believed.

`PoolDetail.js` renders the "Start Earning on `<protocol>` ↗" button — the emitter of
`pool_click{source=protocol_link}`, **half the north star** by NORTH_STAR.md line 17 — like this:

```js
protocolUrlWithRef && React.createElement('button', { className: 'cta-button-protocol', … })
```

A falsy URL renders **nothing**. Not a disabled button, not an explanation — an empty space where the
conversion action should be. And the URL came from a chain ending in a `null`:

`pool.url` → `dynamicProtocolUrls` → `PROTOCOL_URLS` → `null`

- `pool.url` **is never present.** Zero of the 736 committed snapshot pools carry it (item 166 deleted
  the same phantom branch from `generate-llms.js`).
- `dynamicProtocolUrls` is built from **a second, different third-party host** —
  `api.llama.fi/protocols`, not the pools API — fetched 100 ms after mount and **failing silently by
  design.** `app.js:1285`, verbatim: *"Fail silently - static PROTOCOL_URLS will be used as fallback"*.
  The result is cached **permanently** in `localStorage['defi-protocols']`, so **the first visit
  decides** — and first-visit-from-search is precisely the cohort the whole SEO estate exists to serve.
- `PROTOCOL_URLS` is a **hand-maintained map of 96 entries.**

So the question was never "why is this one pool broken". It was "how much of the product is one
ad-blocker away from having no call to action". Measured, not estimated:

| population | CTA survives | CTA vanishes |
|---|---|---|
| committed snapshot (736 pools) | 522 (70.9%) | **214 (29.1%)** — $8.9B TVL, 134 distinct projects |
| pool-detail pages the SEO estate deep-links (438 resolvable ids) | 290 | **148 (33.8%)** |

An ad-blocker, a CSP, a DefiLlama blip, a slow paint, or a bounce before the 100 ms timer — any of them
produce the same result, and it is invisible in the metrics because the absent button emits nothing.

**The framing that made this worth doing properly:** item 138 already fixed this **once**, by hand, by
adding a single `sky-lending` entry to the static map after the same defect hit the ICP's flagship
stablecoin lender. That is item 175's *"the checker inherits the shape of the last bug"* thesis in its
**repair** costume — the fix, not just the detector, was scoped to the one instance that bit us. A map
needing 134 more hand-entries is not a fix. The spec makes this explicit: **a diff that only grows the
static map is a verifier FAIL.**

## What changed, in reading order

### 1. `generate-protocol-urls.js` (new, 250 lines) → `data/protocol-urls.json` (new, 475 keys, 20,426 B)

Bakes the map at CI time from the same `api.llama.fi/protocols` payload the runtime fetch reads, so the
data arrives from **our own origin** with the daily SEO bake instead of from a host we don't control at
render time.

Two things make it more than a `curl` in a wrapper:

- **The key transform is not re-typed.** The map is keyed by
  `<name>.toLowerCase().replace(/\s+/g, '-')`. If the generator ever keyed differently, the artifact
  would be a 20 KB file of keys nothing ever reads — a silent, total no-op that every test asserting
  "the artifact exists and is well-formed" would happily pass. So a `PROTOCOL_KEY_TRANSFORM` marker
  comment sits on **`app.js:1331`, the `dynamicProtocolUrls` builder**, and on the generator's
  `protocolUrlKey()`, and `test_protocol_url_keys.js` **extracts the expression from each of those two
  files and proves behavioural equality via `new Function`** over adversarial names (multi-space,
  unicode, dots, empty). This is item 166's precedent: `test_llms_link_integrity.js` parses `home.html`
  rather than duplicating a list. **Note which site is guarded:** the *lookup* site,
  `getProtocolUrl()` at `app.js:2497`, carries an unmarked third copy of the same expression that the
  parity test cannot see — pre-existing, byte-unchanged from main, and covered in Deviation 3 below.
- **Freshness discipline** (081/083 pattern): output byte-identical modulo `generatedAt` writes nothing.
  A no-data-change bake must not mint a commit, because every commit is a Vercel deployment.

### 2. `.github/workflows/sitemap-update.yml` — one inserted step

Rides the **existing** daily job (`cron: '0 2 * * *'`), immediately after the pools-snapshot step. No new
workflow, no new deployment trigger (2026-07-13 Vercel-quota decision). The existing `git add data …`
already stages the artifact, so that step is untouched.

### 3. `app.js` — one new tier, and a deliberately gated emit

```
pool.url → dynamicProtocolUrls → bakedProtocolUrls → PROTOCOL_URLS → null
```

Additive depth only. The live fetch still goes **first** (so a protocol that changes its URL between
daily bakes wins immediately), and the static map is untouched. The artifact loads at mount with **no
`setTimeout`** — unlike the background fetch it backstops, it has to win the race against the multi-MB
live `/pools` request.

The subtler half is instrumentation honesty. `pool_view{source:'url_direct'}` fires as soon as pools
land. A `protocolCtaPresent` sampled there — before `/data/protocol-urls.json` resolves — would report
`false` for CTAs that then render perfectly: **instrumentation manufacturing the exact defect it exists
to measure.** So the *emit* is deferred behind a `protocolUrlsSettled` flag while the *render*
(`setDetailPool`/`setCurrentView`/`document.title`) stays immediate and unconditional — that is the SEO
path's first paint and it waits for nothing. `protocolUrlsSettled` is set in a `finally`, so a 404 on a
bare dev server can never wedge the emit.

### 4. `PoolDetail.js` — stop rendering nothing

Both CTA sites (hero + repeat footer) now go through one `renderProtocolCtaBlock(placement)` helper —
reuse over duplication, since the sites differed only by the `ctaPlacement` value. When a URL resolves,
behaviour and copy are byte-identical to before. When **nothing** resolves (project `sdai` today, $61M,
and any brand-new protocol), it renders a labelled link to that pool's DefiLlama page instead of empty
space.

Two constraints on that fallback, both load-bearing:

- **It must not impersonate the protocol CTA.** Different copy naming DefiLlama as the destination,
  EN + KO together. Never "Start Earning on `<protocol>`".
- **It must not inflate the north star.** It fires `source: 'defillama_fallback'` — a fifth disjoint
  value. NORTH_STAR line 17's filter is `source ∈ {garden_cta, protocol_link}`, so the metric is
  unaffected **by construction**. The spec names reusing `protocol_link` here as an explicit verifier
  FAIL: it would silently redefine the north star, and the number would go up while nothing improved.

Zero new CSS — `.cta-button-protocol` and `.pool-action-hint--muted` already existed for exactly this.

### 5. `analytics.js` / `translations.js`

`pool_view` gains `protocolCtaPresent` **and** `protocol_cta_present` — the spec's camelCase name plus
the queryable house snake_case form, `null` (not `false`) when a caller never computed it, so "not
measured" stays distinguishable from "no CTA". Same keep-both precedent as item 123's
`click_type` + `source`. Two new EN + KO keys; the Korean was written to match the surrounding block's
terminology (`풀`) and label form, not glossed.

## The most interesting thing in this diff: item 182 nearly made an older guard vacuous

`test_protocol_cta_fallback.js` exists to prove item 138's hand-added static `sky-lending` entry is
load-bearing. Its positive control renders a `sky-lending` pool with the dynamic fetch blocked and
asserts the CTA appears "purely from the static fallback".

But the baked artifact **also** contains `sky-lending` (`https://app.sky.money/`). The test serves the
real repo, so post-182 that CTA would render from the **baked** tier even if item 138's static entry
were deleted — the assertion still passes, while the thing it was written to protect is unguarded.
**A fix silently disarming an older test is worse than the bug it fixed**, because the next person to
touch that map gets a green light.

The build agent's first pass instead left the file **red** and documented it. That was corrected on
operator direction, in two parts:

- The test now also **404s `/data/protocol-urls.json`**, restoring the static-tier isolation the
  positive control depends on.
- The negative control changed from *counting* (`0 buttons`) to **distinguishing**: a button IS present,
  its copy is not the protocol-CTA phrasing, it names DefiLlama, and clicking it fires
  `defillama_fallback` and never `protocol_link`. That is strictly stronger than a count — it fails if
  the fallback disappears, if the copy regresses, **or** if the click mislabels itself, none of which
  `count === 0` could tell apart.

The verifier's decisive check was `M3b`: with item 138's static entry deleted **and** the new 404 block
removed, the test passes 4/4. With the 404 block restored, it correctly fails 2/4. The guard is real again.

## Deviations from the spec — all disclosed, none silent

1. **Artifact population = projects in the live `/pools` feed, not `data/pools-snapshot.json`** (the
   spec's literal text). `?pool=` deep links **bypass the snapshot** and load live pools (spec 105;
   3,239 of the estate's 3,677 `?pool=` ids are off-snapshot), so a snapshot-keyed map would miss
   exactly the arrival cohort this item exists for. Satisfies the spec's stated *intent* ("keep the
   artifact small") at 475 keys / 20 KB raw / 5.9 KB gzip, covering 15,947 of 15,998 live pools —
   and it is **~100× smaller than the multi-MB runtime payload it backstops.**
2. **An https-only filter** on baked URLs (not in the spec): ~201 live protocols carry a blank or
   plain-`http://` url. Baking one ships a dead or insecure link from our own origin until the next
   regen. Cost: 7 keys, coverage 99.7% → 99.7%. The live runtime tier is untouched.
3. **`PROTOCOL_KEY_TRANSFORM` marker on one site, not two** (per the spec's singular wording). Residual,
   disclosed by the verifier: `app.js:2497` inside `getProtocolUrl()` carries an unmarked third copy of
   the same expression, byte-unchanged from main and outside the parity test's reach. Not introduced here.
4. **A false claim in the build notes, corrected in place rather than deleted:** the notes asserted the
   *spec* forbade modifying `test_protocol_cta_fallback.js`. It does not — that instruction came from the
   operator's build brief. Same failure mode items 166/177 recorded: a claim written beside the fact it
   asserts.

## Known risks, recorded rather than hot-patched (the 180 precedent)

- **R1 — the emit gate has no timeout.** `protocolUrlsSettled` releases on success, non-ok, and thrown
  error, but not on a request that *hangs*. Bias direction is favourable (missing views are the slow
  ones, so the rate is biased **upward** and cannot fake a REVERT signal), but it can under-count the
  north-star CTR **denominator** for the early-bounce cohort. An `AbortController` deadline is the fix.
- **R2 — the new CI step can fail the daily bake.** No `continue-on-error`, so an `api.llama.fi` outage
  now fails the sitemap job before its commit step. Consistent with the adjacent snapshot step's
  existing posture, and ironic in an instructive way: an item premised on "third-party fetches are
  allowed to fail" added one that isn't. The trade is deliberate — a bake-time failure is loud, visible
  in the Actions log, and leaves the committed artifact serving traffic, whereas the runtime failure
  being removed was silent and cost 29.1% of the estate its CTA. If it starts going red, the fix is
  `continue-on-error: true`, not reverting.

**Needs human visual spot-check: YES** — pool-detail render path, new user-facing element and copy. The
fallback is Playwright-asserted in EN and KO but not pixel-reviewed.

## Measurement

**Primary (presence — measurable today):** share of `pool_view` with `protocolCtaPresent: true`.
Code-derived degraded-path baseline **70.9%**; target **≥99%**; window 14 days. Decision rule: keep if
≥95%; below that the artifact is not loading in prod and this is a REVERT-CANDIDATE regardless of local
test results.

**Secondary (conversion — explicitly NOT claimed):** `pool_click{source=protocol_link}` is 0 all-time
against ~86 sessions/14d, far under the ≥30-event minimum-sample rule. **No conversion window is opened
on a zero-traffic funnel.** Re-evaluate when `pool_view` ≥ 30 in a window.

## Quiz (5 questions — answers base64 at the bottom)

**Q1.** The static `PROTOCOL_URLS` map covers 70.9% of pools. Adding the 134 missing projects by hand
would reach ~100% in a much smaller diff. Why does the spec call that a verifier FAIL?

**Q2.** `getProtocolUrl()` now checks the baked artifact *after* the live `api.llama.fi` fetch, not
before. Given that the whole point of the item is to stop depending on that fetch, why is it still first?

**Q3.** The DefiLlama fallback reuses the `.cta-button-protocol` class and sits in the same slot as the
north-star CTA. What single property stops it from inflating the north-star metric, and what would break
if it were changed to `protocol_link`?

**Q4.** `protocolCtaPresent` is computed from a deferred effect gated on `protocolUrlsSettled`, rather
than inline at the existing `pool_view` call site. What false reading does the gate prevent, and why is
the *render* deliberately not gated the same way?

**Q5.** After this item, `test_protocol_cta_fallback.js` had to start 404-ing `/data/protocol-urls.json`.
What would have silently broken if it hadn't — and which mutation proved it?
