# Spec 024: Make the working share link the primary one-tap action

## Evidence
- Backlog row 024 (score 7.8, READY): "North-star: make the plan share a UNIQUE WORKING LINK that reproduces the sender's exact garden on open — one-tap 'copy this garden' (human 2026-07-11: link attached to the garden, NOT an image download). Link must carry full plan state + actually rebuild the setup instantly on arrival."
- NORTH_STAR.md standing decision, 2026-07-11: "plan share = a UNIQUE WORKING LINK attached to the garden that reproduces the sender's exact setup one-tap on open (human directive, refines the 2026-07-10 image-hero decision for item 024): the link that rebuilds the garden is the primary artifact; an image may accompany but the working link is what closes the loop." This explicitly supersedes the 2026-07-10 decision that made the image share the sole/primary CTA (shipped as items 004/005/008).
- Backlog row 024 also records: "CORE DONE: encodePlanToUrl→decodePlanFromUrl already round-trips full plan state (verified 2026-07-11); remaining = UX promotion (make copy-link the primary one-tap action, image demoted) — render-path change, needs a browser to verify."
- Current code (planner.js ~2576-2596, `sharePromptElement`, the only share surface at bloom per spec 005): the image button (`doShare`, `.gp-share-btn` primary styling) is the sole button-styled CTA; the working-link actions (`doNativeShare`/`doCopyLink`) are a demoted `.gp-share-textlink` — the exact inverse of the 2026-07-11 directive.
- `encodePlanToUrl`/`decodePlanFromUrl` (planner.js ~848-900) already carry full plan state (goal, monthly, years, persona, capital, fundingMode, deadline) and are wired into the router (`decodePlanFromUrl(urlParams)` at ~3428) — the "unique working link" mechanism itself needs no change (per item 007's arrival-moment work, already shipped and measuring).

## Hypothesis
We believe promoting the working link to the primary button-styled CTA (native share sheet where available, clipboard copy otherwise) and demoting the image to a secondary text link will increase `share_link_created` events with `method: 'native'|'copy'` relative to `method: 'image'`, and that link-carrying shares convert better into `share_link_opened → plan_created` (the north-star funnel) than a downloaded image ever can — an image has no return path back to the app, a link does. Confidence: directed (explicit human standing decision), not exploratory.

## Change (planner.js + translations.js only)
Smallest version, `sharePromptElement` only (planner.js ~2576-2596). Do not touch `doShare`/`doCopyLink`/`doNativeShare` internals, `encodePlanToUrl`/`decodePlanFromUrl`, the waitlist modal's separate share row (`doWaitlistShare`/`doWaitlistDownload`, out of scope — that surface already leads with "Share on X" which carries the link via `doWaitlistShare`, not an image download, so it isn't the inversion this item fixes), analytics.js, or any router/URL code.

1. **Swap CSS-class roles, not handlers.** The link action (`doNativeShare` when `navigator.share` exists, else `doCopyLink`) gets `.gp-share-btn.gp-share-prompt-btn` (the raised, primary neumorphic button — reused as-is, no new class). The image action (`doShare`) gets `.gp-share-textlink` (the existing demoted text-link style, reused as-is) and keeps its `disabled: isSharing` state.
2. **New copy, both EN + KO together** (translations.js, next to the existing `share*` keys ~302-311 EN / ~786-794 KO):
   - `shareLinkPrimaryCta`: primary button label when falling back to clipboard copy (e.g. "🔗 Copy your garden link").
   - `shareLinkPrimaryNative`: primary button label when `navigator.share` exists (e.g. "🔗 Share your garden link").
   - `shareTextLinkImage`: demoted text-link label for the image action (e.g. "or save as an image").
   - Existing `shareLinkCopied` ("✓ Copied!") is reused for the primary button's post-copy confirm state; existing `sharePrepping`/`shareImageSaved` are reused for the demoted image link's in-flight/confirm states — no new state keys needed.
3. **Keep the confirm-state wiring exactly as it works today**, just reattached to the swapped elements: `copySuccess` drives the primary button's copied-confirm text; `isSharing`/`imageShareConfirm` drive the demoted image link's drawing/saved-confirm text.
4. Update the stale in-code comment above `sharePromptElement` (currently describes the 008/005 image-primary decision) to reflect the 2026-07-11 reversal, so the next loop doesn't re-read stale intent.
