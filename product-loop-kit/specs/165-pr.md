# 165 — explainer (HIGH tier: full walkthrough + quiz)

## The goal, in one sentence

Stop the pool-detail page from compounding an out-of-rail rate into a dollar figure, without hiding
the rate itself.

## The intuition

DeFi Garden's trust rails have always worked the same way: an anomalous rate (`> 1000%` APY) is
**demoted and flagged**, never hidden — the user sees the datum and a ⚠ next to it. That convention
is right for the *rate*. It is catastrophic for anything the page *derives* from the rate, because
compounding a 345,079% APY over five years produces a number that isn't a projection at all:

> **"$100 in this pool grows to ~$49,002,948,093,727,200,000 in 5y at current rates."**

That sentence rendered on production for any of **75 live pools** (measured this run against
`yields.llama.fi`, 16,050 pools; 3 of the 75 hold ≥$1M TVL). `?pool=` deep links always fetch live
(`app.js:1141`), so the $10M-railed snapshot never protected this surface — and pool-detail is the
current north-star surface.

Item 025 already established the exact principle in code, at exactly one node:

```js
// PoolDetail.js:263-264
// Concrete CTA (025): show the projected outcome ON the button — but NEVER for
// an anomalous pool (trust rail: anomalous rates are flagged, never hyped).
const showConcreteCta = !isAnomalous;
```

The button was railed. The projection card, the daily/monthly earnings cards and the yield
calculator — all computing from the same `totalApy` — were not. This item applies the existing
principle to the remaining four nodes. It is a strengthening of an existing rail; **no threshold
was relaxed, no constant changed.**

## What changed, and why — the diff in reading order

**1. `translations.js` (+3 lines, EN `:121-122` and KO `:825`)**
One new key, `projectionBodyOutOfRange`, added to both languages in the same diff (CLAUDE.md hard
rule). EN: *"This rate is too far outside normal ranges to project a dollar amount from — the
number would be fiction, not a forecast."* It is a **static string, not a template function** —
deliberately, because the entire point is that no number derived from this rate should appear, and
an unused interpolation slot is how one sneaks back in later.

**2. `PoolDetail.js` (+18/−10, four hunks, all inside `PoolDetail()`'s render)**
Every hunk is the same shape: a render-time ternary on the **pre-existing** `isAnomalous` const
(`PoolDetail.js:250`, unchanged). No new state, no new helper, no new CSS class — the replacement
text renders inside the same `<div>` with the same inline style object.

| hunk | node | anomalous renders |
|---|---|---|
| `:632-641` | "The Long Game" projection body | the new out-of-range line |
| `:697-708` | Daily earnings value | `—` |
| `:731-742` | Monthly earnings value | `—` |
| `:1099-1108` | Yield-calculator amount (all three tabs) | `—` |

For the metric cards the gate sits *outside* the `AnimatedNumber` branch, so no count-up animation
runs toward a suppressed value.

**3. `package.json` (+1/−1)** — `test_pool_detail_anomaly_projection.js` wired into `test:serial`
directly after `test_mean30d_sanity.js`, its closest sibling (144's rail test). No dependency
change; `package-lock.json` has no diff.

**4. `test_pool_detail_anomaly_projection.js` (new)** — 9 assertions, real Chromium against the
compiled bundle through `home.html`, fixture-routed (external hosts are blocked in this sandbox).
Criterion 1 is asserted **structurally**: every `$`-prefixed number is parsed out of
`document.body.innerText` and none may be ≥ $1e9 — not a match against one expected literal, so a
future regression that produces a *different* absurd number still fails the test.

**5. `PoolDetail.compiled.js` / `.min.js` / `translations.min.js`** — regenerated by
`npm run compile && npm run minify`, never hand-edited. `home.html:345-357` loads the **compiled
minified** bundle, so a `PoolDetail.js`-only edit would not reach production or the audit render
(the trap `specs/155-notes.md:246-252` recorded). `test_compiled_assets.js` (4/4) and
`test_minified_assets.js` (9/9) confirm byte-identical regeneration.

## What deliberately did NOT change

- **The hero APY and the Base/Reward APY cards still render the raw rate.** Two independent reasons:
  the demote-and-flag convention, and the fact that `test_audit_app.js` case 2 — the scanner's only
  P0 positive control, which item **155** had to restore after item **144** killed the previous one
  — injects `900,719,925,474,097.9` into `apyBase` and asserts a rendered `number-sanity` finding.
  Gating those cards would have killed that control for a second time. It still passes (3/3).
- `APY_SANITY_LIMIT_LOCAL`, `DEFAULT_MIN_TVL`, `isAnomalous`, `showConcreteCta`, `applyDegenHaircut`,
  `getRiskAssessment` — all read-only. Verified by diff-grep, not by eye.
- The degen-haircut warning still renders on anomalous pools: it prints a *percentage*, never a
  dollar figure, so it doesn't violate the rule and special-casing it would have been scope creep.

## Deviations from the spec

Two, both documented in `165-notes.md` and both judgment calls the spec left open:

1. `—` is a bare literal rather than a `t()` key. It is language-neutral punctuation and the
   codebase already treats it that way in ~15 existing call sites (`planner.js`, both page
   generators). Inventing a `dashPlaceholder` key that resolves to `—` in both languages would be
   ceremony, not i18n.
2. `projectionBodyOutOfRange` is a static string rather than a template function (reasoning above).
