# 159 — Apply the trust rails to the `llms.txt` surface (HIGH tier explainer)

## The goal in one line

The product refuses to show a 353,114% APY anywhere a human can see it. Its
AI-discovery file was leading with one. This item closes that gap.

## The intuition

DeFi Garden has exactly one non-negotiable promise: **every number it publishes
has passed a sanity filter.** `APY_SANITY_LIMIT = 1000` and
`DEFAULT_MIN_TVL = $10M` are the rails that enforce it. They are applied in
`app.js`, in `planner.js`, in the pool-detail page — everywhere a person looks.

`generate-llms.js` was written as a separate SEO utility and never got the memo.
It had its own filter (`tvl >= 10000 && apy > 0 && isFinite(apy)`), a TVL floor
**1000× looser** than the product's, and **no APY ceiling at all**. Then it
sorted APY-descending and took the top 15. That construction doesn't just
*permit* anomalies — it actively selects for them. The surface was, by design, a
leaderboard of the dataset's most broken pools.

The live evidence, fetched from prod this tick:

```
## Current Top Yields
TL;DR: Live highest APY opportunities (updated daily, TVL ≥ $10k).
- BSC · zeebu · ZBU — 353114.2% APY, $576,877 TVL — …
```

The tell that this was a genuine contradiction and not a judgment call: **`zeebu`
does not exist in `data/pools-snapshot.json` at all** — zero matches in the
735-pool, $10M-floored snapshot the product actually reads. The app would never
render this pool. `llms.txt` led with it.

Why that matters more than a normal cosmetic bug: `llms.txt` exists *specifically*
to tell LLMs and AI agents what DeFi Garden claims. It is the file a machine
reads to decide what this site is. We were telling every crawler on the internet
that we advertise 353,114% yields on $576k of TVL — the precise shape of the
scam-adjacent claim the whole product is positioned against. Trust is the
conversion currency; this was spending it in a room we never look at.

## What changed, in reading order

**1. `generate-llms.js` — two mirrored constants (new, top of file)**

```js
const APY_SANITY_LIMIT = 1000;   // mirrors app.js:800
const MIN_TVL_USD = 10000000;    // mirrors app.js:801 (DEFAULT_MIN_TVL, $10M)
```

Read-only mirrors, commented as such, with `app.js` named as canonical. The
comment explicitly tells a future editor not to change them here. This is the
same pattern item 145 established when `compute-kpis.js` needed to bound its own
derived math — a generator may *apply* a rail, never *own* one.

**2. `formatTvlFloor()` (new helper)**

Renders `10000000` → `"$10M"`. It exists for one reason: acceptance criterion 4
says the TL;DR string must **derive** from the constant, not restate it. A second
hardcoded `"$10M"` would be a fresh copy of the exact bug we're fixing — a claim
that can silently drift from the thing it describes. Money formatting is pinned
to `en-US` per CLAUDE.md; note the explicit locale on every `toLocaleString()`.

**3. `pickHighYield()` — the actual fix (2 lines)**

```diff
-  const { minTvlUsd = 10000, topN = 15 } = options;
+  const { minTvlUsd = MIN_TVL_USD, topN = 15 } = options;
...
-    return tvl >= minTvlUsd && apy > 0 && isFinite(apy);
+    return tvl >= minTvlUsd && apy > 0 && isFinite(apy) && apy <= APY_SANITY_LIMIT;
```

That is the whole behavioural change. Everything else is plumbing, tests, or
regenerated output.

**4. The TL;DR line (`:480`) now interpolates** `formatTvlFloor(MIN_TVL_USD)`.

**5. Regenerated `llms.txt` + `llms-full.txt`** via the sanctioned
`npm run generate:llms` (live DefiLlama fetch). Never hand-edited — NORTH_STAR
lists hand-editing generated SEO surface as HIGH risk for good reason.

Before → after, same section:

| | Before | After |
|---|---|---|
| Top line | `zeebu · ZBU — 353114.2% APY, $576,877 TVL` | `uniswap-v3 · WETH-USDC — 47.2% APY, $112,787,401 TVL` |
| Lines >1000% in `llms.txt` | 8 | **0** |
| Lines >1000% in `llms-full.txt` | 15 | **0** |
| TVL claim | "TVL ≥ $10k" (true, and damning) | "TVL ≥ $10M" (derived from the constant) |

**6. `test_llms_rails.js` (new, 14 assertions) + wired into `npm test`.**

## The trap this test had to avoid

The spec's Territory notes flagged it and the fixture design turns on it:
`data/pools-snapshot.json` **has no `apy` field** — its keys are `apyBase`,
`apyReward`, `apyMean30d`. The live `/pools` payload *does* carry `apy`, which is
what `generate-llms.js` reads. So a rail assertion written against snapshot shape
would pass **vacuously** — it would test nothing, forever, while looking green.
The fixtures use the live-payload shape deliberately.

The test also gates the **committed artifact**, not just the function: it parses
`llms.txt` and `llms-full.txt` off disk and asserts zero >1000% figures, in both
render formats (`.toFixed(1)` in the concise file, `.toFixed(2)` in the full one).
A future bad regen fails CI even if the function is still correct.

## Deviation from spec — one, and it made the test stronger

The spec asked for a fixture built from the live evidence: the 353,114% /
$576,877 pool, asserted excluded. During the non-vacuity check that fixture
turned out to be **insufficient on its own** — it is excluded by the *TVL floor
alone*, so the APY rail could have been deleted entirely and that assertion would
still have passed. A second fixture was added: **anomalous APY on a huge TVL**
(50,000% APY at $500M), which only the APY ceiling can exclude. Without it, the
test would have been quietly redundant with the TVL floor.

The non-vacuity run proves it landed: stripping `&& apy <= APY_SANITY_LIMIT`
turns the suite red on exactly two assertions — the huge-TVL anomaly and the
`1000.01` boundary — and the original spec fixture stays *green* through the
mutation. That green-under-mutation is the receipt that the extra fixture was
necessary, not decorative.

## The NEVER-list judgment (the reviewable risk)

NORTH_STAR's NEVER list gates "deleting or de-indexing SEO surface", and this
diff removes lines from a public file. The call to proceed rests on three facts:

1. **No URL leaves the index.** Zero sitemap `<loc>` entries change; every
   `sitemap-*.xml`, `tokens/`, and `chains/` file is byte-identical. This removes
   lines from *inside* one text file.
2. **`llms.txt` is not an indexable page** and nothing links to it for ranking.
   It is an AI-discovery manifest, not SEO surface.
3. **The rule it touches points the other way.** The NEVER list's first bullet
   protects against *weakening* a trust rail. This item strengthens one — it
   applies an existing rail to a surface that was missing it, and changes the
   rail's value nowhere.

Contrast with item 148, which genuinely drops 7 sitemap `<loc>` entries and is
correctly gated and left open. The distinction is URLs vs. lines.

## Instrumentation: none, deliberately

`llms.txt` is a static text file fetched by crawlers. It has no client-side
runtime — nothing in it can execute, so nothing in it can fire an event.
Inventing a metric here would mean inventing one with no mechanism to ever emit.
Recorded per the 142/149/154 precedent. Verification is functional: the
acceptance greps, the test, and the next heartbeat re-running the >1000% grep
against live prod.

## Honest limitations

- **Regen churn is real.** The diff carries ordinary daily data movement
  alongside the rail-driven removals. Split: `llms.txt` 20 churn / 18 rail-driven;
  `llms-full.txt` 48 churn / 40 rail-driven.
- `test_seo_surface_audit.js` could not run — headless-Chromium TLS is blocked at
  the proxy in this sandbox (NORTH_STAR 2026-07-12). Confirmed by grep that it
  never references `llms.txt`/`llms-full.txt`/`generate-llms.js`, so it does not
  cover this surface. Pre-existing limitation, not a regression.
- The full ~90-test `npm test` chain was not run end-to-end (timebox). Targeted
  set run instead; `test_minified_assets.js`'s 2 known reds pre-exist on `main`.
