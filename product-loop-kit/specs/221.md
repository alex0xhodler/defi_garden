## Hypothesis
We believe porting 218/220's footer-leaves-the-fixed-layer pattern to the analytics grid removes the last
surface where `.app-footer` (fixed, opaque, z-index 100) occludes content, because the same fix
verifier-passed on pool-detail (218) and landing (220), and clearance alone is proven insufficient: a
mid-document overlap at scroll 0 cannot be fixed by `padding-bottom` (218's recorded wall,
`pool-detail-styles.css:1080-1112`) — and the grid root `.app.has-results` ALREADY inherits `.app`'s 80px
clearance yet still shows the overlap. Confidence: validated-pattern (two shipped instances of this exact fix).

## Change
Smallest version: one CSS rule scoped to the grid view — `.app.has-results .app-footer { position: static;
margin-top: auto; }`-shaped (exact companion rules per what `.app.has-results` actually needs; check
whether `.app` is a flex column before relying on `margin-top:auto`, and whether a `padding-bottom`
companion must be zeroed like 218 needed — record the check either way, per the playbook's step 3b
Resolution discipline). Follow `playbooks/fixed-overlay-occlusion.md` end to end; update its three-site
sweep + "class closed" note on ship (this closes the third and last `app-footer` render site,
`app.js:3533`).
OUT of scope: item 222's duplicate theme-toggle; pool-detail and landing footers (already shipped); any
change to `.google-header-sticky`; any HTML/JS change unless CSS alone provably cannot fix it.
