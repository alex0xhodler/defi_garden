# Spec 234: Agentic commerce — x402-monetize the agent pillar (Cloudflare wallets suite)

## Evidence
- **Human directive, 2026-08-05 (live session): "add to backlog with high priority to be using the suite
  of tools to offer agentic commerce to the website as per https://blog.cloudflare.com/wallets/".**
- The announcement (fetched 2026-08-05): Cloudflare Wallets — Account Wallets (humans delegate spending
  authority), Virtual Wallets (agents purchase autonomously via API keys, stablecoin micropayments, no
  signup flow, owner-set caps/allowlists), **Monetization Gateway** (merchants sell resources headlessly),
  **x402 protocol** (micropayments attached to HTTP requests), **Web Bot Auth** (agent identity via
  keypairs), **cloudflare.pay** handles (claimable NOW, full functionality "coming soon", no pricing
  disclosed).
- Fit with the standing strategy (NORTH_STAR 2026-08-04): Q1 — the domain is ALREADY on Cloudflare;
  Q4a — agents are a product pillar (static layer → 227 read API → 228 MCP); Q5 — north-star leg (A) is
  agent consumption. This item is the monetization + identity leg of that same pillar.
- Current chain state at filing: 224 PARKED (PR #392, human call), 227/228 dep-blocked behind it. This
  item sits after 227/228 — it wraps their endpoints.

## Hypothesis
We believe adding an x402 payment layer over the railed read API (227) and MCP server (228) — while
keeping the static citation layer free — will (a) create the first revenue path that needs NO human in
the transaction, and (b) make north-star leg (A) partially self-verifying, because a request that carries
a payment or a Web Bot Auth signature is a real agent by construction (the crawler-classification problem
disappears for exactly the traffic that pays). Confidence: supported for the mechanism (the protocol
exists, the domain is on Cloudflare, the endpoints are already planned); **guess** for demand (nobody has
measured agents paying for railed DeFi data; the blog itself says full functionality is "coming soon").
The item still pays off under several futures — even at zero paid demand, Web Bot Auth identity upgrades
224's telemetry and the price-tagged surface is itself agent-legible metadata — which is what earns the
score alongside the human's explicit priority call.
- Instance of: the agent-pillar dependency chain (224 → 227 → 228 → 234) — each leg wraps the previous.
- Class closed by this item: no — it monetizes the API/MCP legs only. Explicitly NOT covered: charging
  for the static estate (deliberately never — citation is the moat), and any human-checkout/fiat commerce.

## Change
Smallest version that tests the hypothesis, in loop-buildable vs human-owned halves:

**Loop-buildable (code, on 227's Worker scaffold — read-only data, no user funds):**
1. x402 layer on the 227 Worker: unauthenticated/unpaid requests to designated PAID routes get the x402
   402 response with price + payment instructions; paid/verified requests get the data. Free routes
   (llms.txt, md twins, schema.org pages, a generous API free tier) are NEVER gated.
2. Price schedule as DATA (one exported table: route pattern → price/free-tier rule), not literals
   scattered in handlers — the 159/226 mirror rule; served in machine-readable form on the agent surface
   so agents can discover pricing without a probe request. **The boundary is the human's (2026-08-05):
   current-APY routes free; historical-series and computed-KPI routes paid.** The schedule's route
   classification must derive from what the endpoint SERVES (current feed passthrough vs computed/
   retained data), asserted in tests — a new computed-KPI endpoint added later must default into the
   paid class, not silently ship free.
3. Web Bot Auth verification middleware: verify agent identity signatures when present; pass the verdict
   (verified-agent id / unverified) into 224's D1 edge-log schema as a first-class column.
4. Docs on the agent surface (llms.txt + md twins): what is free, what costs, how to pay — honest copy,
   no fake availability (the 2026-07-12 card-copy precedent): if Cloudflare's gateway is still
   waitlist/coming-soon at build time, the surface says so.
5. SANDBOX/TEST mode default: the payment requirement ships OFF or in test-network mode until the human
   flips it (config flag read from Worker env, never hardcoded on).

**Human-owned (BLOCKED-class, NEVER auto-merged — money/org-admin, the 224 deploy split):**
- Claim the `cloudflare.pay` handle (do this EARLY — free, name-squattable, zero code dependency).
- Enable Monetization Gateway on the Cloudflare account; wallet custody/payout configuration.
- Flip real pricing LIVE (the env flag above).

OUT of scope: `workers/` (funds-moving, standing out-of-scope), any custody of user funds, fiat checkout,
paywalling the static estate, price experiments (a later item once ≥1 paid read exists).

## Acceptance criteria
- [ ] Paid route without payment/identity → exact x402-conformant 402 response (shape asserted against
      the protocol spec, not a hand-rolled lookalike); with a valid test payment → 200 + data. Both
      driven against the Worker in local dev (wrangler), transcripts in notes.
- [ ] Free routes (enumerated FROM the price-schedule data at test time, never a hardcoded list) return
      200 with no payment header on every request — the citation layer and every current-APY route are
      provably ungated; every historical/computed-KPI route is provably GATED (both directions of the
      human's boundary tested, populations derived from the route table).
- [ ] Price schedule: single source; the machine-readable pricing doc is GENERATED from it (mirror-rule
      test: set-equality both directions).
- [ ] Web Bot Auth: a validly-signed request logs `verified_agent=<id>` in the D1 schema; unsigned logs
      `unverified`; an INVALID signature is rejected/flagged, not silently accepted as verified —
      negative case required.
- [ ] Non-vacuity: neuter the 402 gate (always-200 mutant) → the paid-route test goes RED; byte-identical
      restore → green. Same for the signature-verification mutant.
- [ ] Ships with the live-pricing flag OFF; the diff contains no credential, no account id, no payout
      config (grep-asserted in the verifier pass).
- [ ] Population: route tests draw from the deployed router's own route table, not the motivating examples.

## Measurement
Metric: north-star leg (A) gains a paid/verified stratum — weekly count of paid reads + Web-Bot-Auth-
verified reads (from 224's D1 log; Mixpanel can't see these). Gate: window opens at ≥30 real paid-or-
verified reads (crawler heuristics irrelevant here — payment/signature IS the realness proof). Backstop:
gate unopened 60d after the human flips pricing live → close UNEXERCISED (the clock starts at the human's
flip, not at code-merge — before that the leg is deliberately dark). Decision rule: any non-zero paid
demand validates keeping the layer; zero after 60d live → keep the identity half (it feeds telemetry
regardless), file the pricing half as a learning.
