# Spec 040: JSON-LD structured data (Organization/WebSite, BreadcrumbList, FAQPage)

## Evidence
Repo-wide grep, this session (2026-07-11): zero `application/ld+json` script tags and zero `schema.org` references in any shipped page or generator (`home.html`, `generate-token-pages.js`, `generate-stories.js`, `plan.html`, `stories/*.html`, `tokens/*.html`). The only repo hit for `schema.org` is prose documentation in `.well-known/agent-skills/agentic-readiness/references/ai-visibility-audit.md` — not implemented markup.
- `PoolDetail.js` (lines ~244-275) renders a visual breadcrumb (`className: 'pool-breadcrumb'`) as plain `<div>`/`<span>` with a JS `onClick` — semantically inert, no `BreadcrumbList` schema despite the UI already having the data.
- `stories/kevin.html` (via `generate-stories.js` `faqHtml`, lines 338-349) renders an actual Q&A block (`p.faq` array, `st-faq-item`/`st-faq-q`/`st-faq-a`) — a direct `FAQPage` schema candidate already computed, just not marked up.
- 2026 SOTA research (this session, WebSearch): JSON-LD is the sole Google-recommended structured-data format; `Organization`/`WebSite`/`BreadcrumbList`/`FAQPage` all remain valid and indexed. Google retired the FAQ *visual* SERP rich-result 2026-05-07, but `FAQPage` markup itself stays valid and is explicitly still consumed by AI answer engines (GEO/AEO) as citation context. Pages with structured data see +35% CTR through rich results (cited across multiple 2026 sources). DeFi-specific research found entity/schema markup drove 560% AI-click growth in a cited case study for a comparable content category (protocol/yield comparison queries).

## Hypothesis
We believe adding JSON-LD (`Organization`+`WebSite` sitewide, `BreadcrumbList` on token pages and pool-detail, `FAQPage` on `stories/kevin.html`) will improve both classic rich-result eligibility and AI-answer-engine citation likelihood, because DeFi Garden currently has zero machine-readable entity/structured markup anywhere, and multiple independent 2026 sources cite this as one of the highest-leverage, lowest-risk levers for a content category (DeFi yield comparison) where AI Overviews are already resolving a majority of queries. Confidence: **supported by external research, not yet validated on this specific site** (no prior A/B here — track as a hypothesis, not a certainty).

## Change
Smallest version that adds real, content-accurate structured data — no visual UI change, no new dependency (hand-rolled JSON-LD strings, matching the existing hand-rolled HTML-string generator pattern; no schema library):
1. `home.html`: one `<script type="application/ld+json">` block with `Organization` (name, url, logo) + `WebSite` (name, url) types, planner mode only (or both modes — decide during build whether analytics-mode pages should instead carry a lighter/no site-level block to avoid duplicating on every parameterized URL; default to sitewide `WebSite`, homepage-only `Organization`, per validated JSON-LD examples).
2. `generate-token-pages.js`: add `<script type="application/ld+json">` with `BreadcrumbList` (Home → Tokens → `<SYMBOL>`) to `renderTokenPage()`. Values must derive from data already on the page (symbol, canonical URL) — no new computation, no trust-rail-adjacent numbers in the schema.
3. `PoolDetail.js`: add the equivalent `BreadcrumbList` JSON-LD alongside the existing visual breadcrumb (same trail data source, just also serialized as schema — do not alter the visual breadcrumb's rendering/behavior).
4. `generate-stories.js`: add `FAQPage` JSON-LD to `renderStoryPage()` ONLY when `p.faq` exists (currently: `kevin` persona only) — `mainEntity` array built directly from the same `p.faq` array already used for the visible HTML, so schema and visible content can never diverge (Google's own guidance: structured data must reflect what's actually visible on the page — do not invent Q&A pairs not shown).

OUT of scope: `Product`/`FinancialProduct` schema for individual pools (2026 sources note structured data must match visible content one-to-one; a pool's APY is not a "price" in the schema.org sense and mis-typing it risks a manual action for misleading structured data — needs its own careful spec, not bundled here). Also out of scope: any visual/UI change, any change to trust rails, canonical logic, ranking, or the underlying breadcrumb/FAQ content itself (schema wraps existing content, doesn't add new claims).
