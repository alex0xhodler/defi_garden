# Spec 140: Raise SNAPSHOT_MAX_AGE_MS to match the real bake cadence — revive the snapshot fast path in prod

## Evidence
- `app.js:1086`: `const SNAPSHOT_MAX_AGE_MS = 15 * 60 * 1000; // 3x the intended ~5-min cadence`.
- The "intended ~5-min cadence" never materialized: the 109 poller writes to Cloudflare D1, NOT to the repo's `data/pools-snapshot.json`. The committed snapshot is baked by `sitemap-update.yml` (schedule + push triggers): git log on `data/pools-snapshot-meta.json` for the last 24h shows 8 bakes — 09:38, 12:34, 15:32, 18:36, 21:49 (07-24), 03:47, 05:14, 06:33 (07-25) — i.e. a real cadence of ~1.5–3h.
- Consequence: the snapshot age gate (`age > SNAPSHOT_MAX_AGE_MS → return false → loadLive()`) rejects the snapshot ~85–90% of the day. Rendered repro 2026-07-25 (heartbeat audit): a fixture serving the committed snapshot (42 min old) silently fell through to the live `yields.llama.fi/pools` fetch; with a fresh-dated meta the same page rendered instantly from the snapshot.
- Who pays: every prod visitor outside the ~15-min post-bake window — including `?pool=`/`?token=` SEO landers (the north-star surface) — waits on the live DefiLlama fetch ("Loading live pools…") that 059 was built to eliminate.

## Hypothesis
We believe raising the max age to cover the real bake cadence will make the snapshot fast path serve the overwhelming majority of prod sessions (instant first paint of pool data on SEO landers), because the gate is currently the only thing rejecting an otherwise-valid committed snapshot. Confidence: supported (rendered repro both sides of the gate).

## Change
Smallest version:
1. `SNAPSHOT_MAX_AGE_MS` 15 min → **6 h** (~2× the slowest observed bake gap, same "cover a missed run" logic the original 3× multiplier intended), with the comment rewritten to state the REAL cadence and its source (CI bakes, git-observable), not the never-realized 5-min poller.
2. Keep everything else exactly as is: stale/invalid → live fallback, escape-hatch refetch on sub-floor minTvl, snapshot-eligibility rules (`!pool && minTvl >= DEFAULT_MIN_TVL`).
3. Regenerate compiled/minified assets (house rule since 052/053 — `npm run compile && npm run minify`).
OUT of scope: changing bake cadence/CI, D1 serving, any UI change, any trust-rail change (snapshot content is already $10M-railed; APY staleness ≤ bake gap was accepted when 059 shipped — this only aligns the constant with reality).
