# Spec 195: pool-detail prints non-EVM token addresses in full while truncating EVM ones

## Evidence

Surfaced by item **193**'s root-cause work (`specs/193-notes.md` residual (b)) and deliberately left
unfixed there — 193's scope was *the scanner reporting a defect where none exists*, not *what the page
renders*.

`PoolDetail.js:1611-1656` renders the "Underlying Assets" row. The chip branch is gated on:

```js
const isAddress = typeof token === 'string' && token.startsWith('0x') && token.length >= 40;
```

so an EVM address becomes a tidy monospace chip — `0xdac1...1ec7 ↗`, `title` = full address, href
`https://blockscan.com/address/<token>` — while **any** non-`0x` address falls through to the plain
`<span>` at `:1645-1656` and prints in full.

**Measured against the committed `data/pools-snapshot.json` (740 pools, this run):**

| population | count |
|---|---|
| underlying-token strings ≥20 chars that render **raw** (no chip) | **142** |
| …on Solana (43–44 char base58 mints) | **121** |
| …on Tron (34-char `T…` base58) | **9** |
| …on Stellar (56-char Soroban `C…` contract ids) | **4** |
| …chain-prefixed EVM (`ethereum:0x…`, on Base/Plasma) | **5** |
| …Stacks principals (`SP…usdcx`, 43–51 chars) | **2** |
| …`coingecko:<slug>` pseudo-ids (24–30 chars, human-readable) | **2** |
| pools carrying the wrapped-SOL mint `So1111…112` alone | **28** |

Two costs, one cosmetic and one real:

1. A 44-char monospace blob distorts the Underlying Assets row on the **north-star surface**
   (pool-detail) — worst at 360px, where the flex-wrap row has ~328px of usable width.
2. The un-truncated digit run is *precisely* what made 193's false P0 possible. A rendering choice that
   manufactures work for the scanner. 193 fixed the scanner; this fixes the render that provoked it.

## Hypothesis

We believe **extending the existing address-chip treatment to non-EVM address-shaped tokens** will
**remove 142 raw-rendered address blobs from the pool-detail surface without inventing a second chip
style or linking any address to a wrong explorer** because **the chip markup, tokens and truncation rule
already exist for EVM and the only thing missing is a shape classifier plus a per-chain explorer map.**
Confidence: **validated-pattern** — the EVM chip has shipped and rendered since before 122; this reuses
it verbatim.

Pre-traffic quality mandate (NORTH_STAR.md 2026-07-23): this is a product-quality item, not a conversion
experiment. No isolable funnel metric — measurement is the rendered assertion plus the audit scanner
staying quiet.

## Change

**One source file changes: `PoolDetail.js`** (plus its committed compile/minify output — see Territory
notes). No CSS file changes, no new translations key, no new dependency.

### 1. Classify the token shape (replaces the single `isAddress` boolean)

A pure helper, defined next to the render (module-local, no export needed):

```
classifyUnderlyingToken(token, chain) -> { chip: bool, address: string, href: string|null }
```

Rules, evaluated in order. `token` is trimmed; a non-string returns `{chip:false}`.

| # | shape | test | address | href |
|---|---|---|---|---|
| 1 | chain-prefixed EVM | `/^[a-z0-9-]+:(0x[0-9a-fA-F]{40,})$/` | the captured `0x…` | `https://blockscan.com/address/<address>` |
| 2 | bare EVM | `token.startsWith('0x') && token.length >= 40` | token | `https://blockscan.com/address/<token>` |
| 3 | Solana mint | `chain === 'Solana'` && `/^[1-9A-HJ-NP-Za-km-z]{32,44}$/` | token | `https://solscan.io/token/<token>` |
| 4 | Tron token | `chain === 'Tron'` && `/^T[1-9A-HJ-NP-Za-km-z]{33}$/` | token | `https://tronscan.org/#/token20/<token>` |
| 5 | generic opaque id | `token.length >= 32 && !/\s/.test(token)` | token | **`null`** — chip, but a `<span>`, never a link |
| 6 | anything else | — | — | not a chip; unchanged plain `<span>`, full text |

Rule 5 is what catches Stellar Soroban ids and Stacks principals **without guessing an explorer**. Rule 6
is what keeps `coingecko:openeden-tbill` (24 chars) and `coingecko:ondo-us-dollar-yield` (30 chars)
readable — they are slugs, not addresses, and truncating them destroys the only information they carry.
The 32-char threshold is chosen because it is the shortest real address shape in the data (Solana's
minimum base58 length) and sits above every human-readable id measured in the snapshot.

**Never** point a non-EVM address at `blockscan.com` — it is EVM-only, and a chip that links to a 404 is
worse than a chip that links nowhere (row 195's explicit instruction).

### 2. Render (reuse, do not invent — standing decision 2026-07-10)

- The chip's visual style becomes **one shared style object** used by both the `<a>` and `<span>`
  variants: the existing EVM-anchor style verbatim (`padding 6px 10px`, `var(--color-background)`,
  `var(--neuro-radius-sm)`, `var(--font-size-xs)`, `var(--neuro-shadow-subtle)`, `fontFamily: monospace`).
  Zero new CSS, zero new tokens, no gradient, no one-off.
- Linked chip: `<a>` with `color: var(--color-primary)`, `target="_blank"`, `rel="noopener noreferrer"`,
  `title` = the full original token string, label suffixed ` ↗`.
- Unlinked chip (rule 5): `<span>` with `color: var(--color-text)` — the *existing* plain-span colour, so
  a non-link never reads as a link — same shared chip style otherwise, `title` = full token, **no** `↗`.
- Label: `${address.slice(0, 6)}...${address.slice(-4)}` (existing EVM formula, now applied to the
  classified `address`, so `ethereum:0xa0b8…eb48` displays `0xa0b8...eb48`, not `ethere...eb48`).
- The existing symbol-derivation shortcut is **kept and generalised**: today it swaps the truncation for
  `pool.symbol`'s parts when `symbolParts.length === addressCount`. `addressCount` now counts **all
  chip-classified tokens** (not just EVM ones), so a 2-token Solana LP with symbol `SOL-USDC` shows
  `SOL ↗` / `USDC ↗` instead of two base58 blobs. Behaviour for pools with only EVM tokens is unchanged
  by construction (the count is identical when no non-EVM address is present).

### 3. Out of scope (stated, not silently dropped)

- Explorer coverage beyond Solana/Tron. Rule 5 renders those safely unlinked; adding Stellar Expert /
  Hiro is a separate, evidence-free-today item.
- The analytics grid's pool cards — they do not render `underlyingTokens`.
- `audit-app.js` — 193 already fixed the scanner; this item must not touch it.

## Acceptance criteria

Rendered-Playwright on the real UI (standing decision 2026-07-11 — never fixture strings alone). New file
`test_pool_underlying_address.js`, port **8868** (8791–8867 taken), house pattern from
`test_mobile_cta_clip.js` / `test_northstar_cta_fires.js`: local static server, unpkg React/Babel routed
to vendored `node_modules` copies, `yields.llama.fi` routed to an inline fixture, snapshot 404'd to force
the live path, `pageerror`/`console.error` collected. Fixture pools carry **real addresses copied from
`data/pools-snapshot.json`**.

1. **Solana mint is truncated.** On `/?pool=<solana fixture id>`, the Underlying Assets row contains no
   text node longer than 24 characters, and a chip whose text matches `/^So11\S*\.\.\.\S*112 ↗$/`-shaped
   truncation (`slice(0,6)…slice(-4)`) with `title` **exactly** the full 43-char mint.
2. **Solana chip links to Solscan.** That chip is an `<a>` with
   `href === 'https://solscan.io/token/So11111111111111111111111111111111111111112'`,
   `target="_blank"`, `rel` containing `noopener`. It must **not** contain `blockscan`.
3. **Tron chip links to Tronscan.** A Tron fixture pool's `T…` chip is an `<a>` with href
   `https://tronscan.org/#/token20/<addr>`; not `blockscan`.
4. **Opaque non-EVM, unknown chain, renders unlinked.** A Stellar 56-char `C…` contract id renders as a
   truncated chip that is **not** an `<a>` (no `href` anywhere on it), carries the full id in `title`, and
   nowhere in the row does the string `blockscan` appear for that pool.
5. **EVM regression (must not change).** A bare `0x…` fixture pool still renders the blockscan-linked chip
   with the same truncation/symbol-derived label it renders on `main` today.
6. **Chain-prefixed EVM.** `ethereum:0xdac17f958d2ee523a2206206994597c13d831ec7` renders label
   `0xdac1...1ec7 ↗` and href `https://blockscan.com/address/0xdac17f958d2ee523a2206206994597c13d831ec7`
   (the bare address, prefix stripped).
7. **Short readable ids are left alone (anti-over-reach).** A pool whose underlying token is
   `coingecko:openeden-tbill` renders that string **in full**, in a plain span, with no `↗`, no `title`
   and no truncation. A fix shipped too wide and a fix not shipped look identical from the outside on
   criteria 1–6; this criterion is what separates them.
8. **Layout holds at 360 / 768 / 1280.** For the Solana pool at each viewport: every chip's bounding box
   is fully inside its container's box (right edge ≤ container right edge + 1px tolerance), and
   `document.documentElement.scrollWidth <= innerWidth + 1` (no horizontal page overflow).
9. **No page errors** on any render above (`pageerror` + non-ignorable `console.error` both empty).
10. **Non-vacuity.** The test reads `data/pools-snapshot.json` and asserts ≥1 live pool actually carries a
    non-EVM underlying token ≥32 chars — if the population ever hits 0 the test fails loudly rather than
    passing on a fixture that no longer reflects reality.
11. **Registered.** `test_pool_underlying_address.js` is added to `package.json`'s `test:serial` chain
    (`run-tests.js:57-82` parses that chain as the file list — an unregistered test never runs).
12. **Compiled assets regenerated.** `npm run compile && npm run minify` re-run and the regenerated
    `PoolDetail.compiled.js` / `PoolDetail.compiled.min.js` committed; `test_compiled_assets.js`,
    `test_minified_assets.js`, `test_min_asset_boot.js` green. (Criteria 1–9 exercise the **prod** path,
    which loads `PoolDetail.compiled.min.js` — so a stale min asset fails them anyway.)

## Territory notes

- **`PoolDetail.js` is not the file the browser loads.** `home.html:359` loads
  `PoolDetail.compiled.min.js`. `compile-app.js` (FILES = `app.js`, `PoolDetail.js`) and
  `minify-assets.js` produce it; `home.html:342-345` says never hand-edit the compiled output. Any edit
  to `PoolDetail.js` MUST be followed by `npm run compile && npm run minify`, with the regenerated files
  in the same commit.
- **`React.createElement` only** — babel-standalone is present but JSX is banned repo-wide (CLAUDE.md).
- **No new user-facing string**, so the EN+KO parity rule is vacuously satisfied — the chip content is
  data (an address) and the row heading `underlyingAssets` already exists in `translations.js`. State this
  explicitly rather than letting the verifier infer it.
- **Trust rails untouched**: no `APY_SANITY_LIMIT`, no `DEFAULT_MIN_TVL`, no anomaly flags, no degen
  haircut, no `__APP_MODE` router, no parameterized-URL behaviour, no SEO artifact.
- Ports 8791–8867 are taken by existing `test_*.js` files; 8868 is free.
