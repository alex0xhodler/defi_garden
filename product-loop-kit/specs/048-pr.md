# PR explainer: 048 — freshness signals (HIGH tier)

## Goal
2026 AI answer engines carry a strong recency bias: content that reads as
undated or stale gets cited less, even when it's actually fresh. DeFi
Garden's ~2,108 static token/chain pages (and 3 story pages) are in fact
regenerated **daily** by `sitemap-update.yml`, but until this PR they carried
**zero** freshness signal — no visible date, no `dateModified`/`datePublished`
schema (`grep -iE "last updated|dateModified|datePublished" tokens/*.html
chains/*.html` → 0 hits). To a crawler or AI engine, a page regenerated an
hour ago and one nobody's touched in a year look identical. This ships the
cheap, high-ROI fix: say the honest thing — "this page was generated on
&lt;date&gt;" — visibly and in schema, so freshness the site already has
becomes freshness a crawler/AI engine can see.

## Intuition
Every generated page already computes a date for its sitemap `<lastmod>`
entry. This PR just plumbs that same date two more places on the page
itself: a visible sentence, and a `dateModified` field in the page's
existing JSON-LD. Nothing about the underlying data or trust rails changes —
this is pure disclosure, additive only.

The one design decision worth calling out: Google's structured-data
guidelines require schema to match visible content. So instead of computing
the date twice (once for display, once for schema — which risks the two
drifting apart on a code change six months from now), every page computes
**one** date string and hands that single variable to both the visible
`<p>` and the JSON-LD. They're structurally incapable of disagreeing.

## What changed and why (diff in reading order)

1. **`generate-token-pages.js`** (the shared implementation; chain pages
   reuse it per this repo's "reuse before inventing" rule):
   - `todayGeneratedDate()` — a human-readable en-US date
     (`"July 12, 2026"`), matching the format `generate-stories.js` already
     used for its own narrative date mentions. Exported for
     `generate-chain-pages.js` to reuse.
   - `renderLastUpdatedHtml(genDate)` — one `<p class="note">Last updated
     &lt;date&gt;</p>`, using the page's existing `.note` style (no new CSS).
   - `renderTokenPage`'s `genDate` variable — previously computed but only
     fed to the Dataset JSON-LD's `dateModified` (shipped back in 046, unused
     visibly until now) — now also feeds the new visible line. Its default
     (when no `generatedDate` param is passed) switched from a raw ISO
     fallback to the human-readable one, for a nicer default in production;
     tests that pass an explicit date string are pass-through and unaffected.
   - `main()` now computes `genDate` **once** for the whole run and passes it
     to every page, so a full daily regen (thousands of pages) can't disagree
     with itself if it happens to straddle midnight.

2. **`generate-chain-pages.js`** — imports the two new helpers from the
   token-pages module (this file already reuses most of that module's
   helpers) and wires them into `renderChainPage` + `main()` identically.

3. **`generate-stories.js`** — the 3 persona story pages already computed a
   human-readable `generatedDate` once per run and rendered it inside two
   narrative sentences (the illustrative-math intro and disclaimer), but
   never labeled it "Last updated" and never exposed it to structured data.
   Added:
   - A visible `<p>Last updated &lt;date&gt;</p>` line in the page footer.
   - A `WebPage` JSON-LD block (`dateModified` = the same `generatedDate`
     string) emitted for **every** persona — unlike the existing `FAQPage`
     block, which only kevin.html has, this needed a node every story page
     is guaranteed to carry.

4. **Tests** (`test_token_pages.js`, `test_chain_pages.js`, `test_stories.js`)
   — added assertions per page type: the visible line renders, and it's
   byte-for-byte identical to the schema field. All pass (62 / 56 / 21
   assertions respectively, full files green).

## Deviations from spec (see `specs/048-notes.md` for the full list)
- Hub/A-Z index pages (`/tokens`, `/tokens/az/<letter>`, `/chains`) were
  **not** given a freshness line — they're navigational indexes, not their
  own dataset, matching how 046's Dataset/ItemList JSON-LD also skipped them.
- `datePublished` omitted, per the spec's own default (no stable first-publish
  date is tracked by the generators today).

## Measurement
Not Mixpanel-isolable — proxy is GSC freshness/re-crawl cadence + AI-citation
recency, once backlog 026 (GSC connector) unblocks. 2-6wk GSC cycle. Decision
rule: keep as a best-practice freshness signal regardless (no A/B at this
traffic level).
