## Territory notes (verified in code 2026-07-15 — these BIND the design)

1. **`kpis.tvlTrend` shape (compute-kpis.js:100-102).** `tvlTrend = round((last.tvlUsd - first.tvlUsd) /
   first.tvlUsd, 4)` over the retained ascending series — a **fractional change** (0.15 = +15%,
   −0.20 = −20%). It is `null` when `series.length < 2` (`enough` guard) OR when `first.tvlUsd === 0`
   (division guard). Positive = capital grew; negative = capital shrank. Rounded to 4 decimals.
2. **How `kpis` reach PoolDetail (identical to 103/088.1).** `PoolDetail` takes `pool` as a prop; it does
   not fetch. In-app browse→detail (`?token=`/`?chain=`) loads `data/pools-snapshot.json`, which CARRIES
   `kpis` → the note renders. A direct `?pool=<id>` deep link loads LIVE `/pools` (no `kpis`) → the note
   hides honestly. SEO deep-link enrichment (105) already shipped for `?pool=`; this leg still null-gates
   so it degrades safely on any no-`kpis` path.
3. **Data reality today.** With <2 retained history points every pool's `kpis.tvlTrend` is `null`. So the
   note renders for NO pool today; it activates automatically as 087's daily CI accrues ≥7 history points
   (per the hp≥7 gate below). The code handles every case; the data catches up. Matches 103/088.1.
4. **Independent of the momentum note (103) and 088.1.** TVL-trend annotates a DIFFERENT axis (capital
   size) than 103 (rate direction) and 088.1 (rate steadiness) — no mutual-exclusion coupling is needed,
   but the note is ADDITIVE and never edits/gates 103's or 088.1's render logic (surgical diff). It may
   co-render with them; that is fine — they speak about different things (rate vs. capital). The
   magnitude gate (±10%) keeps it silent on near-flat pools so the surface never piles up trivial notes.
5. **Compiled/minified artifacts.** home.html loads `PoolDetail.compiled.min.js` and `translations.min.js`.
   Editing `PoolDetail.js`/`translations.js` REQUIRES `npm run compile && npm run minify`
   (052/053/061/088.1/103 precedent) or `test_compiled_assets.js`/`test_minified_assets.js` fail.

## Hard constraints (NEVER weakened)

- The note annotates WITHIN pools that already pass the sanity/TVL/anomaly rails — it never rescues a
  filtered pool or overrides a flag. `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly demotion, degen ⅓
  haircut untouched. The note reads ONLY `pool.kpis.*`; it never filters, drops, reorders, re-weights,
  re-flags a pool, and never reads/writes rail constants. It does NOT change the $10M floor — it adds
  context ALONGSIDE it.
- Every displayed phrase through translations.js EN + natural KO, both added together.
- Honest-numbers: the trend is explainable in one sentence from stored snapshots (last − first TVL over
  the tracked window, as a percentage of first). Shrinking TVL said out loud. "Education, not advice"
  framing; no hype, no "save up/afford/budget".

## Acceptance criteria

**A. Render logic (`PoolDetail.js`), placed immediately AFTER the 103 rate-momentum note (which sits
after the 088.1 track-record note, before the Tokens Section).** A calm, full-width note with
`className: 'tvl-trend-note'`, reusing the EXACT inline neuro styling of the 071/088.1/103 notes
(`background: var(--color-background)`, `borderRadius: var(--neuro-radius-sm)`,
`boxShadow: var(--neuro-shadow-subtle)`, `color: var(--color-text-secondary)`,
`fontSize: var(--font-size-sm)`, `lineHeight: '1.5'`, `padding: '12px 16px'`, `marginBottom: '20px'`).
Let `k = pool.kpis`; `trend = (typeof k.tvlTrend === 'number') ? k.tvlTrend : null`;
`hp = Number(k.historyPoints)`; `pct = (trend === null) ? null : Math.round(Math.abs(trend) * 100)`.
- A1. Render NOTHING when ANY of: `k` missing/not an object; `trend === null`; `hp < 7` (a directional
  read needs a real window — same 7-point threshold as 103/088.1); `Math.abs(trend) < 0.10` (below a
  meaningful ±10% move, no note — avoids trivial-noise pile-up). Null-safe: covers live no-`kpis`
  landings and single-point history.
- A2. Two tiers on the sign of `trend` (magnitude ≥ 0.10 already guaranteed by A1):
  - GROWING — `trend >= 0.10`: `t('tvlTrendGrowing', pct, hp)`.
  - SHRINKING — `trend <= -0.10`: `t('tvlTrendShrinking', pct, hp)`.
- A3. The note NEVER reads/writes rail constants and never mutates the pool list. Rails untouched.

**B. Copy (`translations.js`, EN + natural KO, both added together, placed next to the 103/088.1 keys).**
Two keys, calm cautious-saver "education not advice" framing (`pct` is a whole-number percent, `hp` a
day count ≥ 7 so plural is always correct):
- `tvlTrendGrowing` (fn `(pct, hp) =>`): EN "The capital deposited in this pool has grown about {pct}%
  over the {hp} days we've tracked it. A pool drawing more deposits is a sign others find it worth using
  — though size alone is never a guarantee."
- `tvlTrendShrinking` (fn `(pct, hp) =>`): EN "The capital in this pool has shrunk about {pct}% over the
  {hp} days we've tracked it. It still clears our $10M size floor, but money leaving a pool is worth
  knowing before you plan a garden around it."
- KO: natural (not literal) translations of each, same two keys, in the KO block. KO substrings the test
  asserts on must be stable and present verbatim in the KO copy.

**C. Artifacts regenerated in the same commit.** `npm run compile && npm run minify` →
`PoolDetail.compiled.js`, `PoolDetail.compiled.min.js`, `translations.min.js` regenerated.

**D. Rendered-Playwright acceptance (`test_kpi_tvl_trend.js`, mirrors `test_kpi_momentum.js`).**
Drives the REAL pool-detail UI via `?pool=<id>` with DefiLlama-shaped fixtures whose `/pools` objects

- D2. SHRINKING fixture (`hp:30, tvlTrend:-0.20`) → note present, SHRINKING copy incl. "20%" and "30".

- D4. Short-window fixture (`hp:3, tvlTrend:0.15`) → note ABSENT (hp < 7).
- D5. Null-trend fixture (`hp:1, tvlTrend:null`) and a NO-`kpis` fixture → note ABSENT in both (live
  SEO-landing behavior).
- D6. `?lang=ko` on the GROWING fixture → Korean TVL-trend copy substring present.
- D7. Zero page errors across all renders.
