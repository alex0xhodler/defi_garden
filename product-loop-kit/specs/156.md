# 156 — The `npm test` smoke gate has been blind on the bare-`/` route since the landing pivot

Status: READY → IN_PROGRESS 2026-07-27

Promoted by the build loop 2026-07-27 — **no READY items existed** (148 is built but its PR #306 is

## The problem

The 2026-07-15 landing pivot changed `home.html`'s IA router from two modes to three:

```js
// before (pre-2026-07-15)
window.__APP_MODE = needsAnalytics ? 'analytics' : 'planner';
// now — home.html:82
window.__APP_MODE = needsAnalytics ? 'analytics' : (needsPlanner ? 'planner' : 'landing');
```

Bare `/` is no longer the planner. It is the search-first landing, mounted by `landing.js` into
`#landing-root` (`home.html:198-199`, `home.html:319`). `test_landing.js:74` even asserts the new
truth explicitly: *"bare / must not mount the planner above the landing"*.

Two tests in the `npm test` chain were never updated and still encode the pre-pivot router:

1. **`test_smoke.js:181`** — the spec-003 smoke gate. For each of the three viewports it runs
   `bare / renders planner UI at <w>px` and waits for `#planner-root [class*="gp-"]`, a selector that
   can never appear on bare `/` any more. Three deterministic failures per run.
2. **`test_hub_pages.js:186`** — asserts `homeHtml.includes("window.__APP_MODE = needsAnalytics ?
   'analytics' : 'planner';")` with the failure message `router logic changed`. One deterministic
   failure per run.

### Reproduced on `main` this run (not inferred)

only failure being `✗ the router (__APP_MODE) and canonical logic are untouched by this diff / router

Network was **reachable**, the analytics route rendered at all three viewports, and the JSON-LD and
pool-detail assertions passed. The *only* red is the stale selector. This directly corrects LOG.md's
2026-07-25 item-142 entry, which recorded `test_smoke.js` as a **"sandbox render-timeout … CONFIRMED
pre-existing at HEAD"** — the timeout is real but its cause is a stale assertion, not the sandbox.

## Why it matters

`test_smoke.js` is backlog **003**, tier HIGH: the only multi-viewport (360/768/1280) real-Chromium
render + page-error gate on the two sacred router paths. Today it covers exactly one of them. The
default route every non-parameterized visitor lands on has **no** smoke coverage at any viewport, and
no page-error collection — the `errors.length` check on the bare-`/` page never runs, because the
`waitForSelector` throws first.

The second cost is normalisation. Eight logged loop runs (2026-07-13 069/070 · 07-15 114 · 07-24
136/138 · 07-25 142 · 07-26 147/149) recorded these as "pre-existing reds" and moved on, each
correctly refusing them as scope creep, none classifying them. That is the exact pattern item **147**
broke for `test_minified_assets.js`, where eleven loops had recorded a red that turned out to be the
test correctly reporting a real product regression. A permanently-red tail on `npm test` trains every
future loop — and the verifier — to skim the tail rather than read it.

## Acceptance criteria

1. `node test_hub_pages.js` exits 0 on this branch; its router assertion checks the **current**
   three-mode router (`'analytics' : (needsPlanner ? 'planner' : 'landing')`) and the unchanged
   `window.__canonicalFor(window.location.search)` line. Intent preserved: the test still fails if a
   diff alters the router or canonical logic.
2. `node test_smoke.js` exits 0 on this branch, with **no** assertion removed or weakened — the
   bare-`/` case asserts the surface that route actually renders (the landing mounted in
   `#landing-root`), and additionally asserts the planner does **not** mount there.
3. The planner render path stays smoke-covered at all three viewports: a `/plan.html` case asserts the
   planner mounts (`#planner-root [class*="gp-"]`), so the pivot does not cost the gate a route.
4. Page-error collection (`errors.length`) is asserted on every new/changed case, at every viewport —
   the property that the stale selector was silently skipping.
5. **Non-vacuity, proven by execution, twice** (builder + verifier independently): reverting
   `home.html:82` to the two-mode router must turn `test_hub_pages.js` red; pointing the landing
   assertion at a selector that does not exist must turn `test_smoke.js` red.
6. **Zero product-code changes.** `home.html`, `landing.js`, `app.js`, `planner.js`, `translations.js`
   and every generated SEO artifact are byte-identical to `main`. This item fixes tests only — if a

7. The rest of the `npm test` chain is no worse than `main`: any still-red suite is documented in
   `156-notes.md` with a baseline reproduction, not absorbed.

## Territory notes

- `test_smoke.js` builds its own static server mimicking `vercel.json`'s `/` → `home.html` rewrite, and
  routes `yields.llama.fi` to a live-curl snapshot with a DefiLlama-shaped fixture fallback. Reuse that
  machinery; do not add a second server or fixture path.
- `/plan.html` is planner mode by path (`isPlannerPath`, `home.html:80`), so it needs no query params
  and stays off the sacred parameterized-URL surface.
- `landing.js` mounts into `#landing-root`; `test_landing.js:70-88` is the reference for stable landing
  selectors (`[data-testid="landing-search"]`, `#landing-root .app-footer`). Prefer `data-testid` over
  class-shape matching so the new assertion does not become the next stale one.
- Existing chain position: `test_smoke.js` runs 9th and `test_hub_pages.js` 24th in `package.json`'s
  `test` script; neither position changes.
