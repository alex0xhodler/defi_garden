## What a Sharpe ratio means for a yield pool

Classic Sharpe = (mean return − risk-free) / stdev(returns). For a DeFi pool the natural, self-consistent
mapping over the retained series `apy_t` (already an annualized rate, %):

```
apySharpe = (mean(apy_t) − RISK_FREE_APY) / stdev(apy_t)
```

- **This is a RATE-STABILITY Sharpe**: return per unit of *yield volatility*. It rewards high, STEADY
  yields and penalizes high-but-erratic ones — the quantified form of 088's "a stable 6% beats a spiky
  20% for a subscription garden."
- **No √T annualization.** `apy_t` is already the quoted annualized rate; numerator and denominator are
  both in annual units. This is deliberately NOT a period-returns Sharpe (that's a noisier future
  refinement, needs Δt handling on irregular intraday timestamps). Document the choice so a reviewer
  doesn't "fix" it by multiplying by √252.
- **RISK_FREE_APY**: one disclosed benchmark constant, default **4.0%** (~US T-bill). Configurable; the
  displayed number must name it ("vs a ~4% risk-free rate"). A future variant may use our own median
  stablecoin-lending APY as the DeFi-native risk-free proxy — deferred.

## Honesty caveat (the reason this is HIGH — must ship WITH the number, never after)

`apySharpe` captures ONLY yield-rate volatility. It does **NOT** capture principal risk — impermanent
loss, stablecoin depeg, smart-contract exploit, or TVL flight. A pool that depegs to zero shows a
beautiful Sharpe the snapshot before it breaks. So:
- NEVER present it as a "safety score." Frame: "how steady this pool's yield has been relative to how
  much it pays — not a measure of principal safety."
- It ranks/annotates ONLY within pools that already pass the hard trust rails (`APY_SANITY_LIMIT=1000%`,
  `DEFAULT_MIN_TVL=$10M`, anomaly exclusion). It NEVER rescues a filtered pool or overrides a flag.
- "Education, not advice" framing, EN + KO, one-sentence-explainable (honest-numbers rule).

## Compute (≈free extension of computeKpis, compute-kpis.js:88)

`stdevPop` + the series already exist. Add:
```js
const RISK_FREE_APY = 4.0;      // disclosed benchmark (~US T-bill), configurable
const SHARPE_MIN_POINTS = 8;    // below this the ratio is too noisy → null (honest "not enough history")
// inside computeKpis, reuse the apy array:
const apys = series.map(s => s.apyTotal);
const mean = apys.reduce((a, b) => a + b, 0) / apys.length;
const sd   = stdevPop(apys);                       // == apyStdev (population)
const apySharpe = (series.length >= SHARPE_MIN_POINTS && sd > 0)
  ? round((mean - RISK_FREE_APY) / sd, 2)
  : null;                                          // null: <8 pts OR zero dispersion (undefined)
return { ...existing, apyMean: round(mean, 2), apySharpe };
```
`null` when: <8 history points (no track record), or `sd === 0` (division guard — a perfectly flat rate
has undefined Sharpe, not infinite). Same null-safe discipline as the existing KPIs.

## "Across pools" (the cross-pool view the human asked for)

Per-pool `apySharpe` makes a **risk-adjusted-yield ranking** possible: sort/surface pools by best
risk-adjusted yield, ALWAYS within the trust-rail-passing set. Two surfaces (each its own smallest-change
sub-item, 088 pattern — do NOT ship all at once):
1. Pool detail: an `apySharpe` annotation next to the stability note (extends 088.1).
2. Analytics app: an optional "risk-adjusted" sort alongside APY/TVL (089's sort infra) — clearly
   labelled, with the caveat one tap away.
3. (Later) Planner: prefer higher-Sharpe pools within a persona's blend — trust-rail-bounded.
