# Notes: 057 — OG image compression (PNG → JPEG)

## What shipped
- `og-image.build.mjs` now renders `og-image.jpg` via Playwright's real, quality-respecting JPEG encoder (`quality: 85`). Regenerated in-sandbox (no network needed — local `og-image.source.html` + a local woff2 font): 119,871 bytes vs the previous PNG's 286,318 bytes (~58% smaller). Visually inspected the output — no visible artifacts on the neumorphic gradient/shadow card.
- `generate-og-images.js` (051's per-page card renderer) now emits JPEG via `@napi-rs/canvas`'s existing `toBuffer('image/jpeg')` — no new dependency. Empirically ~22% smaller than the same card's PNG output (44,609B → 34,784B on a test render). `ogRelPath`/`FALLBACK_REL_PATH`/the stale-file sweep all switched to `.jpg`.
- `generate-token-pages.js`, `generate-chain-pages.js`, `generate-stories.js`, `home.html`, `plan.html`: every `og-image.png` literal → `og-image.jpg` (og:image, twitter:image, and home.html's Organization JSON-LD `logo`).
- `test_og_images.js`: `isPng`/`pngDims` → `isJpeg`/`jpegDims` (hand-rolled JPEG SOF-marker parser, mirrors the existing hand-rolled PNG IHDR parser); every `.png` path assertion → `.jpg`.

## Deviations from spec / conservative choices
- **`og-image.png` (legacy PNG) was kept, not deleted**, exactly as the spec's scope guard specifies. It's now unreferenced by every hand-maintained/generator-source file this PR touches, but the already-committed generated pages (`tokens/*.html`, `chains/*.html`, `stories/*.html`, `ko/**`) still reference it until their own next CI regen (network-blocked in this sandbox — same precedent as 040/044/045/048/051-056). Deleting it now would 404 their `og:image` in the interim.
- **The 2,113 `og/tokens/*.png` / `og/chains/*.png` files were NOT regenerated as JPEGs here** — `generate-token-pages.js`/`generate-chain-pages.js` need live DefiLlama pool data, and `yields.llama.fi` is network-blocked in this sandbox. They'll regenerate as real `.jpg` files (via the updated `generate-og-images.js`) on the next `sitemap-update.yml` CI run, same pattern as every prior generated-surface backlog item.
- **JPEG quality on the per-page cards is not actually tunable** — confirmed empirically that `@napi-rs/canvas`'s PNG/JPEG encoders ignore `compressionLevel`/`quality` config entirely (Skia backend uses fixed internal settings; identical byte counts across quality 0.01–0.9 in testing). The ~22% JPEG-vs-PNG win there is real but is purely from the format/encoder switch, not a quality knob — documented in a code comment so a future loop doesn't waste time trying to tune it further.
- **No resize, no WebP/AVIF**: 1200×630 is already the OG/Twitter-recommended size; JPEG was chosen over WebP/AVIF because it's universally supported by every social/search og:image consumer in 2026, where WebP/AVIF support is still inconsistent, and JPEG needed zero new dependencies (both Chromium via Playwright and `@napi-rs/canvas` already ship it).
