# 266 — PR explainer (HIGH tier: full walkthrough + quiz)

> **STATUS: PARKED, NOT MERGED.** Three build attempts, three verifier FAILs — the attempt budget
> (NORTH_STAR.md: max 3, then park with notes). **The product fix is verified correct**; what is
> unfinished is the guard shipped alongside it, whose scanner was bypassed by a different construct in
> each round (aliased constant → template interpolation → **regex literal**, the last one still open).
> Merging would ship a gate that claims coverage it does not have — this item's own failure mode.
> The branch and this PR stay open for the human. Full reasoning, the measured blast radius, and the
> one-task unparking recipe: `266-notes.md`.

## Goal

A live, MCP-branded surface was applying DeFi Garden's two trust rails from numbers somebody typed by
hand. This item makes it read them from the one place that owns them, fixes the fact that it was
applying the *wrong* APY, and puts a gate over the class so the next copy cannot arrive quietly.

## The intuition, in one picture

The product has exactly one pair of trust rails: `APY_SANITY_LIMIT = 1000%` and
`DEFAULT_MIN_TVL = $100K`. `app.js:800-801` is where a human sets them; `trust-rails.js` re-exports them
so every *other* surface can read rather than re-type. Item 254 did that work for the surfaces that
**state** the rails in prose. Item 261 did it for the machine manifests that **state** them in JSON.

Nobody did it for a surface that **applies** them.

`home.html` registers WebMCP tools on every page load — `navigator.modelContext.provideContext({tools:
[...]})` — so any browser-hosted agent can call `search_yield_pools` and get a filtered pool list back.
That filter read:

```js
if (p.tvlUsd < 100000) return false;
if (p.apy > 1000) return false;
```

Two hand-typed numbers that equalled the rails **by coincidence**. And the coincidence had already been
noticed once: nineteen lines above, a comment explains that the tool's *description string* was moved to
`window.TRUST_RAILS` "rather than a hand-typed '$10M' — that literal drifted once already". The prose was
tokenised. The predicate underneath it, in the same object, was not.

There is a second defect on the same two lines, and it is the more interesting one. `p.apy` is
DefiLlama's own field. Every railed surface in this repo computes total APY as `apyBase + apyReward`
(`edge/api-core.js`'s `totalApy()`, `app.js`, `planner.js:110`). So this filter was not a stale copy of
our rail — it was a copy of a **different rail**. A pool with `apyBase 600 + apyReward 600` (1200% total,
anomalous on every other surface) sailed through whenever DefiLlama's `apy` field happened to read low.

## What changed, in reading order

**1. `home.html`, inside `search_yield_pools.execute` only** (~10 lines):

```js
var totalApy = (Number(p.apyBase) || 0) + (Number(p.apyReward) || 0);
if (p.tvlUsd < window.TRUST_RAILS.DEFAULT_MIN_TVL) return false;
if (totalApy > window.TRUST_RAILS.APY_SANITY_LIMIT) return false;
...
if (minApy && totalApy < minApy) return false;
```

The `totalApy` expression is byte-identical to `edge/api-core.js`'s. Result rows now mirror
`api-core.js`'s `projectPool()` exactly — `apy` stays DefiLlama's own field **unmodified**,
`apyBase`/`apyReward` **preserve `null`**, and the derived total arrives as a new `totalApy` key:

```js
apy: p.apy,
apyBase: (p.apyBase === undefined ? null : p.apyBase),
apyReward: (p.apyReward === undefined ? null : p.apyReward),
totalApy: (Number(p.apyBase) || 0) + (Number(p.apyReward) || 0)
```

(The first cut of this item overwrote `apy` with the total and coerced `null → 0` — the verifier measured
what that costs: **185 above-floor live pools** carry both fields null with a positive `apy`, and were
being reported as `{apy: 0, apyBase: 0, apyReward: 0}` and dropped by any `minApy > 0`. See "Deviations".)
**No fallback literal** — `window.TRUST_RAILS` is already dereferenced unguarded
in the same object, and `trust-rails.js` is a non-deferred `<script>` at `home.html:80`; a `|| 100000`
would have re-created the exact bug being removed. Nothing else in `home.html` was touched: the IA
router (`__APP_MODE`) and every parameterized-URL path are byte-identical.

**2. `test_webmcp_rail_derivation.js` (new)** — three legs, because this class has three distinct ways
to come back:

- **Leg A — rendered Playwright, the mechanism itself.** Loads the real page in Chromium with the
  DefiLlama fetch routed to a fixture, finds the tool **by name** in `navigator.modelContext.tools`
  (population read at runtime, never a hardcoded index), executes it, then **mutates
  `window.TRUST_RAILS` in the page and re-executes**. This is the assertion that matters: a literal that
  merely *equals* the rail can satisfy "the filter uses 100000", but it cannot satisfy "the filter's
  output changes when I change `window.TRUST_RAILS.DEFAULT_MIN_TVL` at runtime". Leg A also proves the
  total-APY semantics in **both** directions — a pool with `apy: 5` but `apyBase 600 + apyReward 600` is
  excluded (the old code returned it), and a pool with `apy: 2000` but a sane total is included (the old
  code dropped it). Every threshold in the file is computed from `require('./trust-rails.js')`.
- **Leg B — static class scan.** Every root `*.html` that loads `trust-rails.js` (globbed at test time;
  2 files today), every inline `<script>`: **no bare numeric literal whose VALUE equals a
  `trust-rails.js` value** — decimal or exponential, evaluated with `Number()`, never string-matched,
  with strings and comments masked by a single-pass tokenizer. The predicate is deliberately
  shape-agnostic about the left-hand side, because the first version was not: it required a dotted pool
  field, and the verifier proved a fresh `var MIN_TVL = 100000; ... if (tvl < MIN_TVL)` walked straight
  past a green gate. Measured hits on the unmodified repo: **0**. Three in-process **self-defeat** cases
  (bare comparison, aliased constant, destructured/bracket access) prove it goes red. Plus a **coverage
  assertion** — the original dotted-field scan must still find ≥1 comparison in `home.html` and classify
  every one as derived — so a rename can never make "zero violations" mean "the scanner went blind".
- **Leg C — mirror set-equality, both directions.** Every declaration in the name family
  `APY_SANITY_LIMIT[A-Z0-9_]*` / `DEFAULT_MIN_TVL[A-Z0-9_]*` across tracked `*.js`, derived at test time
  — **21 declarations across 15 files** today — each equal to its base rail in `trust-rails.js`, with the
  site list printed in the run output. Two tiers, because a minifier can strand a name from its value:
  a text scan for ordinary source, and a `require()` fallback for `*.min.js` (`planner.min.js` keeps the
  original name only as an export key). "Fail loudly rather than skip silently" is implemented as a
  mechanism, not an aspiration: an unresolvable `.min.js` site throws, and a comment-aware loose scan is
  cross-checked against the anchored one so an unrecognised declaration shape goes red instead of
  silently leaving the population.

**3. `package.json`** — the new file appended to `test:serial` (so `test_test_registry.js` stays green).

**4. `product-loop-kit/playbooks/derived-number-rails.md`** — the compound step. Its Step 0 emitter list
was assembled by grepping `*.js`, which is *why* it could not see this surface. The playbook now records
the generalisation — a rail-applying surface can be an inline `<script>`, and a **stated** figure and an
**applied** predicate are different claim-shapes needing different guards (textual vs behavioural).

## What the verifier caught across three rounds

Round 3's summary first, because it is the one that parks the item: **`var reQ = /'/g; var MIN_TVL_X =
100000;` injected into the real `home.html` leaves the whole gate green (26/26).** The masker does not
know regex literals, so the `'` inside one opens a phantom string that blanks the next seven non-empty
lines. `t.replace(/'/g, "")` is ordinary JavaScript. Sized honestly: the masker is in sync across
today's population (a synthetic `100000` probed into all 7 inline scripts of `home.html` + `plan.html`
was caught in all 7), so the "0 hits" reading is real now — the exposure is a regex literal added later
hiding pre-existing violations downstream of it.

Round 3 also found a **live drifted rail this item does not fix**: `tools/test-agent-tools.js:127-128`
still applies the pre-`6fceca79bb` **$10M** floor and raw `apy`, and prints "All pools strictly respect
TVL >= $10M" — a fourth hand-typed copy, guarded by nothing (`test_agent_surface_rail_claims.js` globs
`tools/*.json`, not `tools/*.js`). It falsifies this item's "only member" claim, which is corrected in
the spec. **Filed as backlog row 270.**

Round 2's finding, for the record, because it is the same shape: the scanner masked template-literal
`${...}` contents **while its own header comment asserted it did not**, so
`` Number(`${100000}`) `` stayed green. Fixed by a stack-based tokenizer, along with `100_000` and hex
spellings.

## What the verifier caught (attempt 1 → 2)

The verifier FAILED the first cut with 10/11 criteria met and six findings — two real defects, four
documentation defects. All six are fixed in what you are reading; both defects are worth knowing:

- **The gate was narrower than the class it advertised.** Leg B required a *dotted* pool-field access
  next to a literal, so `var MIN_TVL = 100000; var tvl = p.tvlUsd; if (tvl < MIN_TVL) return false;` —
  two fresh hand-typed rail copies on the sacred surface — kept the whole gate green. Widened to the
  value-based predicate described above. A guard aimed at a resemblance of the mechanism launders the
  gap as coverage; this one did, and the PR text claiming otherwise was false until it was fixed.
- **The fix shipped a wrong number while claiming parity with api-core.** Overwriting `apy` and coercing
  `null → 0` misreported **185 above-floor live pools** (2.5%, median `apy` 6.05%) as
  `{apy: 0, apyBase: 0, apyReward: 0}` and dropped them from any `minApy > 0` query. Leg A's fixture
  always supplied numeric values, so that population was never tested. Now mirrors `projectPool()`
  exactly, with a fixture pool drawn from that 185-pool shape.
- Documentation defects: a "Filed as backlog row 269" claim that had not been filed (it is now); the
  figure "≈7,900 generated pages" misapplied from spec 261 (that is the `.md` twin count — the HTML count
  is **4,324**, corrected in four places); a spec claim falsified by `edge/MCP.md:254-268`, which still
  described this surface's *pre-fix* hardcoded literals in the present tense and is corrected in this
  same diff; and stale Leg C counts in the notes.

**One number worth keeping honest**: on today's live data the new filter admits **one more** pool than the
old one (7,336 vs 7,335) and blocks **zero** the old code let through. The `apyBase 600 + apyReward 600`
scenario is real, but it has **0 live instances right now** — this is a correctness and drift fix, not a
leak being plugged.

## Deviations from the spec, and one correction the build forced

- Leg C's population is **21 declarations / 15 files**, not the "8 sites" the spec estimated from a grep.
  The test derives the real population; the spec's number was corrected rather than the test trimmed.
  The assertion is `>= 8`, never `=== 21`, so tomorrow's mirror widens the population instead of failing
  a count.
- **The spec was wrong about its own residue, and the build proved it.** Spec 266 originally said a
  mirror under a different name was an open *shape* with "0 uncovered known sites today". While building
  Leg C, the implementing agent found `PoolDetail.js:297` — `const APY_SANITY_LIMIT_LOCAL = 1000; //
  mirror of app.js constant` — plus its generated twin at `PoolDetail.compiled.js:281`. That is **1**
  uncovered site, on the north-star leg-(B) surface. The response was to widen Leg C to the name family
  and make `PoolDetail.js:297` a **non-vacuity proof** (flip it to `999`, watch Leg C name it), not to
  soften the residue wording. `PoolDetail.js` itself is unchanged — its value is correct today, and
  converting it to a derived read is a pool-detail render-path change with its own risk.
- The `require()` fallback is scoped to `*.min.js` filenames only. A first attempt that required any file
  mentioning the constant pulled in ~40 `test_*.js` files that run their suites on require with no
  `require.main === module` guard.

## What this item did NOT fix, on purpose

`home.html`'s **other** WebMCP tool, `calculate_savings_projection`, hardcodes `var apy = 5.5;` and
reports it to agents as `estimatedApy`. On a product whose principle is "nothing is invented", that is a
fabricated number published to the audience that cannot see the code. It is a different defect (a number
*invented*, not a rail *misapplied*), and chasing it would have widened the diff on the IA router.
**Filed as backlog 269** with the evidence and the weakest-fix options. `planner.js:19`'s named mirror
also stays a literal — Leg C guards its value in both directions, and no drift has occurred.

## Class status

**Partially closed, with numbers.** Closed: applied-rail predicates on browser-inline surfaces (Leg B,
2 documents globbed at test time) and named-mirror equality across tracked `*.js` including suffixed
variants (Leg C, 21 declarations). Open: (a) a mirror under a completely unrelated name — 5 plausible
names grepped across 300 tracked `*.js`, 0 found (a measurement, not an assumption); (b) rail predicates
inside the 4,324 generated HTML pages (`tokens/` 2,076, `chains/` 86, `ko/` 2,162 — `pools/` and
`spotlights/` carry zero tracked HTML), outside Leg B's root-only glob and regenerated from
`trust-rails.js` each run; (c) which other surfaces read the raw `apy` field — item 259's territory;
**(d) one numeral spelling the value scan cannot resolve — arithmetic composition
(`var MIN_TVL = 50000 * 2;`), measured, not assumed.** Evaluating expressions is out of scope for a
literal scan. Exponential, numeric-separator, hex/octal/binary and template-literal-interpolation
spellings were all in this residue after round 2 and are **caught** as of attempt 3.
