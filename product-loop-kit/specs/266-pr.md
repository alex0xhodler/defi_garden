# 266 — PR explainer (HIGH tier: full walkthrough + quiz)

## Goal

The browser-agent surface — the WebMCP tools `home.html` registers on every page load — was applying
its own hand-typed copy of both trust rails. Make it read the rails from the one place that owns
them, and make it impossible for a fourth copy to land silently.

## The intuition, in one paragraph

`trust-rails.js` exists because a rail value once moved (`DEFAULT_MIN_TVL`: `$10M → $100K`,
commit `6fceca79bb`) and nine hand-typed copies of the old figure did not follow. Item 254 fixed
the copies that *state* the rails in prose; item 261 fixed the copies in machine-readable
manifests. Both left a third kind untouched: copies that *execute* the rails. `home.html:269-270`
was one — `if (p.tvlUsd < 100000) return false; if (p.apy > 1000) return false;` — sitting twenty
lines below a comment explaining that the neighbouring *description string* had been moved to
`window.TRUST_RAILS` precisely because "that literal drifted once already". The prose had been
tokenised; the predicate underneath it had not.

## What changed and why, in reading order

**1. `home.html` — the motivating instance (Leg A).**
The filter now reads `window.TRUST_RAILS.DEFAULT_MIN_TVL` / `.APY_SANITY_LIMIT`
(`trust-rails.js` is already loaded synchronously at `home.html:80`, above this block, which is
what the description string at `:250` has depended on all along). A local `totalApy(p)` mirrors
`edge/api-core.js:85` byte-for-byte and now feeds three places: the sanity rail, the `minApy`
filter, and the `apy` value returned to the agent.

That second half is a real behaviour fix, not tidying. `p.apy` is DefiLlama's own field; every
railed surface in this product computes `apyBase + apyReward`. So the old line was not merely an
unlinked copy of the rail — it was a copy of a *different* rail. Concretely: a pool with
`apyBase: 900, apyReward: 900` and `apy: 5` (total `1800%`, far above the sanity limit) was
**admitted** to an agent's results by the old predicate. It is now excluded. Nothing became more
permissive; the rail got strictly stricter on the axis that matters.

**2. `tools/test-agent-tools.js` — the sibling that had already drifted (Leg B).**
Not in the backlog row; found by scanning for the class rather than the instance. It asserted
`x.tvlUsd < 10000000` and printed `All pools strictly respect TVL >= $10M` — the floor has been
`$100K` since `6fceca79bb`. And `tools/` is on `.vercelignore`'s deliberate must-keep allowlist
(`.vercelignore:10`, guarded by `test_vercelignore.js`), so that file is **served live** at
`www.defi.garden/tools/test-agent-tools.js`: a public, false rail claim on the agent surface. Both
thresholds and both printed messages now derive from `trust-rails.js`.

This site is why the guard is keyed the way it is. A detector that asked "does this literal equal
the current rail value?" would have scored `home.html` red and this file **green** — it had already
drifted. The guard therefore asks the weaker question: *is there a rail-shaped literal here at all?*

**3. `test_rail_predicate_derivation.js` — the class guard (Legs C + E).**
Population globbed at test time (209 files: root `*.js`, `edge/*.js`, `tools/*.js`, `src/*.js`,
root `test_*.js`, plus `home.html`/`plan.html`; generated twins excluded by role). It scans
comment-stripped source for **four** shapes — a pool TVL/APY quantity compared against a non-zero
literal (over a statement window, so wrapped conditions are visible), a rail-*named* constant
declaration, an object-property rail (`{ DEFAULT_MIN_TVL: 100000 }`), and a keyword-less
assignment (`o.APY_SANITY_LIMIT = 1000`) — with a numeric grammar covering exponent (`1e5`), hex,
underscore-separated and leading-dot forms. It asserts **set-equality against a 69-entry allowlist
in both directions**:

- a scanned site missing from the allowlist → FAIL (a new unlinked copy cannot land);
- an allowlist entry matching nothing → FAIL (the mirror cannot rot — the item-212 rule).

Entries are keyed on `file|normalised-expression`, never line numbers, and each names what the
threshold actually *is*. That classification is the substance: over a 209-file population it finds 55 comparison sites,
18 rail-named declarations (plus 4 canonical ones excluded by role) and 6 keyword-less
assignments — and only a handful were ever rails. `PoolDetail.js`'s TVL confidence bands,
`generate-sitemap.js`'s `$1,000` quality gate, `compute-kpis.js`'s `RISK_FREE_APY`,
`planner.js`'s `BANK_APY` and `generate-token-pages.js`'s long-tail `MIN_POOL_TVL` are
intentionally different numbers — forcing them to derive would be the mirror-image error, and
`docs/garden-planner-v2-spec.md`'s persona tiers are the precedent for why (item 261 attempt 3).

The verifier's round-1 FAIL is worth reading before the rest, because it changed this guard's
shape. It planted five rail copies the first version scored **green**: `1e5` exponent form (house
style in this repo — `trust-rails.js` itself uses `1e9/1e6/1e3`), a comparison wrapped across two
lines, a declaration with no trailing `;`, an object-property rail, and an assignment with no
declaration keyword. Both known-bad instances happened to be single-line, decimal and
semicolon-terminated, so the detector had encoded *their punctuation* rather than their mechanism
— RAZOR example 5, in a guard written to honour that very rule. All five now turn it red, each
re-run and restored byte-identically.

**4. The generators and the poller (Leg E).**
Leg C as first built saw only comparisons, and its own header honestly recorded the blind spot:
a rail copy written as a bare assignment is invisible to it. On review that residue note turned
out to name a *population*, not an instance — 15 rail-named assignments, of which **two generators
declared the canonical name `DEFAULT_MIN_TVL` with a hand-typed `100000`**, and a third carried a
comment asserting "must stay in sync with app.js — no shared import exists between the two", a
sentence `trust-rails.js` had already made false. `generate-pools-snapshot.js` (which produces the
snapshot the front end actually consumes), `generate-sitemap.js` and `generate-spotlight.js` now
derive; `generate-token-pages.js`'s `APY_SANITY_LIMIT` does too, and so does `src/poller-core.js`,
which hard-declared **both** rails while its own header calls it "another enforcement point for the
rails" — the verifier found that one; it was in this item's population and named in no residue.
Values are unchanged everywhere — only their provenance is.

Their comments were repaired alongside, and this took two rounds. The first pass fixed the comments
it had to touch; the verifier then found `$10M` still stated on the enforcement lines themselves
(`generate-pools-snapshot.js:80`, `generate-sitemap.js:85`, `generate-spotlight.js:18` — the last
still citing `app.js:730` and still asserting the "deliberately NOT the relaxed $100K" rationale
that had become self-contradictory). One of them was not a comment at all:
`generate-spotlight.js:173` is **emitted runtime text** telling a caller their pool "is below the
$10M floor" while the code applies $100K — the exact defect Leg B exists to fix, in a file this
item had already edited. It now derives via `formatTvlFloor(DEFAULT_MIN_TVL)`.

**5. `test_webmcp_rail_derivation.js` — rendered acceptance (Leg D).**
Standing decision 2026-07-11: a UX item's acceptance measures rendered product behaviour, never
unit fixtures alone (item 017 is the precedent). Real Chromium loads the real `/`, DefiLlama is
routed to a fixture (browser-originated external HTTPS is blocked in this sandbox), and the test
invokes the **live registered tool** off `window.navigator.modelContext`. Fixture pools are built
relative to values read from `trust-rails.js` at run time — floor-minus-one excluded, exactly-floor
included — plus the two discriminating cases for the `apy`-vs-`apyBase+apyReward` defect.

The two tests are not redundant, and the non-vacuity log proves it: re-introducing the literal
`100000` in `home.html` turns Leg C **red** while Leg D stays **green** — because a copy that is
correct *today* is invisible to a behavioural test. Leg C exists for exactly that case.

## Deviations from spec

Leg E did not exist when the spec was first written; the operator added it on review of the built
Legs A-D and amended the spec before verification, with the reasoning recorded in place. The
alternative — shipping and ticketing — would have left two files literally redeclaring
`DEFAULT_MIN_TVL = 100000` while the item's whole thesis is that the value must be singular. That
is the item-138 failure mode (a narrow fix claiming a closed class), which this repo has already
paid for once.

## What this does NOT close, with numbers

**Read this section before trusting the guard.** The closure claim in this explainer was falsified
by the verifier three times running, each time because the detector had encoded the motivating
instances' *punctuation* rather than their *mechanism*. Round 3's counter-example is the one to
remember: the guard was blind to `(pool.tvlUsd || 0) >= X` — this repo's house idiom, and the exact
form used at `generate-sitemap.js:88`, `generate-spotlight.js:79` and `generate-pools-snapshot.js:81`,
the three rail-enforcement points **this very item rewired**. It would not have caught a hand-typed
literal at the lines it repaired. That shape is now covered; the pattern of discovery is the
warning. A regex over source text can only ever see punctuation — the durable fix is to parse, and
that is recorded as future work, not done here.

Closing that gap turned up something worse, which is the most useful thing this item found: the
comment/string stripper **had no notion of a JS regex literal**, so a regex containing an odd
number of quote characters (e.g. `generate-pools-snapshot.js:125`'s
`.replace(/("generatedAt":\s*)"[^"]*"/g, …)`) permanently desynced quote tracking and **blanked
the entire rest of that file from the scan**. Six files were silently invisible from that point
on — including `generate-pools-snapshot.js`, one of the files this item rewired. A guard reporting
"0 unclassified sites" over a file it had stopped reading is the purest form of the failure this
whole item is about, and no amount of widening the *patterns* would have revealed it. Fixed with a
regex-vs-division heuristic; the fix alone surfaced sites the operand widening could not.

**Still escaping, named and unfixed** (found by deliberately hunting for shapes rather than waiting
to be bitten): bracket/computed-property assignment (`obj['tvlFloor'] = 100000`), `Math.min`/`Math.max`
clamping (no comparison operator at all), a rail encoded in a function name rather than its argument
(`getTvlFloor() >= 100000`), equality operators (`===`/`!==` are not in the operator set), and
ternary/array right-hand sides on bare assignments. Confirmed **not** escaping: destructuring
defaults and template-literal interpolations.

- Comparisons against literal `0` are excluded by design. Measured, not estimated: the scan finds
  **127** comparison sites with the zero-filter removed against **55** with it, so **72** sites are
  excluded. A rail of `0` is degenerate and `> 0` is an emptiness test, never a rail copy — but it
  is a stated gap, not an absence of one. (The first draft of this explainer said "~40"; the
  verifier measured it and the number was wrong.)
- **A lowercase object-property rail still escapes** — `const R = { defaultMinTvl: 100000 }` is
  invisible to every detector, because `findObjectPropertySites` keys on `SCREAMING_SNAKE_CASE`.
  That restriction is kept for a measured reason, not a stylistic one: relaxing it yields **1040**
  raw hits, **107** after excluding DefiLlama's own field names — too many to classify honestly on
  this item's budget. (The keyword-less *assignment* detector had the same restriction and it was
  **not** justified; relaxing that one cost 4 sites, so it was relaxed.)
  This residue has a **named, live instance**, and it is not hypothetical: `generate-spotlight.js:419-421`'s
  `PERSONA_BANDS` hand-types `minTvl: 100000` for the `rwa` and `degen` bands, while `planner.js:567/572`
  — the `curatePools` bands the file's own comment says it mirrors — say `10000000`. **Two of three
  bands have already drifted by 100×**, and the guard cannot see it. A pin test records the exact
  divergence so that any change to either side fails loudly; which of the two numbers is correct is
  a product decision, so nothing was changed. The class is **open** for this shape.
- `telegram-bot/dist/src/utils/constants.js:111-116` declares `TVL_SAFE: 100000000` /
  `TVL_MINIMUM: 10000000` — the latter is exactly the pre-`6fceca79bb` floor. `telegram-bot/` is
  NEVER-touched (wallet/funds code, NORTH_STAR out-of-scope), so this is recorded, not fixed, and
  it is genuinely ambiguous whether it is an independent bot-risk policy or a fossil of the old rail.
- Rail **semantics** copied wrongly — the defect fixed here in `home.html` — is machine-checked
  nowhere else. The guard sees the literal, never which quantity it rails. Leg D closes it for
  `home.html` alone, by behaviour.
- **38 root `*.js` files** carry a stale `$10M` rail claim in a comment and/or cite the long-moved
  `app.js:729-730`. Item 261's prose guard scans `*.md`/`*.json`/`*.txt` only, so `*.js` comments
  were never in any population. Four were repaired here incidentally (their code had to change);
  the rest are untouched and **unticketed** — filing is the heartbeat's job, and it widens item
  261's population, not this item's.

1. The guard deliberately does **not** ask "does this literal equal the current rail value?".
   Name the specific site in this diff that a value-keyed guard would have scored green, and say
   why that makes the weaker question the correct one.

2. `home.html`'s filter now excludes a pool that the old code admitted. Give the pool's shape
   (the three APY-related fields) and explain why the change makes the rail stricter rather than
   looser — the distinction the NEVER-list turns on.

   red, and say which one — then explain what that asymmetry proves about why both exist.

4. `generate-token-pages.js`'s `MIN_POOL_TVL` and `trust-rails.js`'s `DEFAULT_MIN_TVL` both equal
   `100000`. One was made to derive from the other and one was deliberately left hand-typed.
   Which is which, and what would be wrong about "fixing" the other one?

   direction catches a new unlinked rail copy. What does the allowlist-⊄-scan direction catch,
   which prior item's failure is it derived from, and what would go stale without it?
