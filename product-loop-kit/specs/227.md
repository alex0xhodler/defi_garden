produce countable north-star leg (A) events (API calls) and give agents a citable, curated
alternative to DefiLlama's raw firehose, because the rails + the `rails` block that explains
them are the one thing the firehose cannot emit. Confidence: **supported** — it pays off in
every future where any agent reads the surface at all (the instrument records the zero
honestly otherwise), and it unblocks 228 and 234 regardless of its own traffic.

- Instance of: the **agent pillar** class — surfaces whose consumer is a machine, not a
  browser (llms.txt, md twins, schema.org, `/api`, MCP). Population: 4 planned legs

- Class closed by this item: **no.** This ships 1 of 4 legs. 228 (MCP) and 234 (x402) remain

## Change

Smallest version that satisfies the row, on the **same Worker as 224's logger (one deploy)**,
exactly as the row instructs.

**New — `edge/api-core.js`** (CommonJS, pure, zero network, zero Cloudflare APIs; mirrors the
`edge/agent-log-core.js` shape so plain-Node tests can `require()` it):
- `handleApiRequest({ pathname, searchParams, pools })` → `{ status, body }`, a pure function
  of its inputs. All routing, railing, filtering and math live here.
- Routes (v0):
  - `GET /api` — the contract document: version, endpoint list with parameters, the `rails`
    block, and the data-source attribution.
  - `GET /api/health` — `{ ok, version, poolsAvailable, generatedAt }`.
  - `GET /api/pools` — railed pool list. Params: `token`, `chain`, `minTvl`, `limit`
    (default 50, max 200), `project`.
  - `GET /api/pools/:id` — one pool by DefiLlama `pool` id.
  - `GET /api/forever-number?monthly=X[&apy=Y]` — the SUBSCRIPTION-archetype math
    (capital whose yield pays a monthly bill). When `apy` is omitted, the blended rate is
    derived from the railed pool set, never from a hand-picked pool.
- Unknown `/api/*` path → 404 JSON carrying the same `rails` block and a `endpoints` list.

**Rails, and the mirror rule (RAZOR / item 212) — no mirror is created.**
`edge/api-core.js` **`require`s `../trust-rails.js`** and reads `APY_SANITY_LIMIT` /
`DEFAULT_MIN_TVL` from it. There is therefore **one source**, not a server-side
re-implementation. The rails as applied:
1. **Anomaly rail.** Any pool whose total APY exceeds `APY_SANITY_LIMIT` is **excluded from
   every list response**. On the single-pool route it is returned but carries
   `"anomalous": true` plus the reason string — an agent can never receive an anomalous rate
   presented as sane.
2. **TVL floor.** Default `minTvl = DEFAULT_MIN_TVL`. The `minTvl` param may only **RAISE**
   the floor; a lower value is clamped up to `DEFAULT_MIN_TVL` and the response reports
   `railsApplied.minTvlClamped: true`. (Strictly stronger than `app.js`, which permits
   `minTvl=0` for interactive users — a curated endpoint agents cite does not.)
3. **Explainability.** Every response — including errors — carries a `rails` object stating
   the numbers and, in prose, what they do. This is the differentiator, so it is not optional
   per-route.
4. Blended/derived rates (`forever-number`) are computed only from pools that already passed
   rails 1 and 2.

**Changed — `edge/agent-log.mjs`**: dispatch `/api` and `/api/*` to the API handler *before*
the pass-through `fetch(request)`. **Every other path keeps today's byte-for-byte pass-through
unchanged** — the existing contract ("PASS-THROUGH FIRST … byte-parity holds BY CONSTRUCTION")
is preserved for all non-`/api` paths and asserted by a test. Pool data is fetched from
`https://yields.llama.fi/pools` with Cloudflare edge caching (`cf: { cacheTtl, cacheEverything }`)
plus an in-isolate memo; a fetch failure returns a 503 JSON with the rails block, never a crash
and never the pass-through path. `OPTIONS` preflight + `Access-Control-Allow-Origin: *` for
`GET, OPTIONS` (generous CORS, as the row requires). Responses carry
`Cache-Control: public, max-age=300` and `X-Defi-Garden-Api-Version`.

**New — `edge/API.md`**: the stable versioned contract (endpoints, params, response shapes,
rails semantics, caching, CORS) + the deploy delta appended to `edge/DEPLOY.md` (same Worker,
same `wrangler deploy -c edge/wrangler.toml`, no new binding).

**New — `test_api_worker.js`**, registered in `package.json`'s `test:serial` (which
`run-tests.js` parses — never a second hardcoded list).

## Acceptance criteria

- [ ] `edge/api-core.js` exists, is `require()`-able in plain Node, and reads both rail
      constants from `require('../trust-rails.js')` — **grep-provable that it declares neither
      value itself** (no second literal `1000` / `100000` rail constant in the file).
- [ ] All five routes return the documented shape: `/api`, `/api/health`, `/api/pools`,
      `/api/pools/:id`, `/api/forever-number`; unknown `/api/*` → 404 JSON with `rails`.
- [ ] Every response body, on every route including 404/503, contains a `rails` object with
      `apySanityLimit`, `minTvl`, and a human-readable explanation of each.
- [ ] `edge/agent-log.mjs`: `/api` paths are served by the handler; **every non-`/api` path
      returns the identical Response object from `fetch(request)` as before** (asserted).
- [ ] `OPTIONS /api/pools` → 204 with CORS headers; `GET` responses carry
      `Access-Control-Allow-Origin: *` and a `Cache-Control` max-age.
- [ ] Tests (`test_api_worker.js`, plain-Node lane, registered in `test:serial`):
  - [ ] **Population**: pool fixtures are drawn at test time from `data/pools-snapshot.json`
        (the real ~16k-pool estate, regenerated daily — never a hardcoded pool list).
  - [ ] **Invariant, not instance**: for the whole population, *no* pool in any `/api/pools`
        response has total APY > `APY_SANITY_LIMIT`, and *every* returned pool has
        `tvlUsd >= DEFAULT_MIN_TVL`. Assert over all of them, not a sampled few.
  - [ ] **Positive control**: the test derives its controls from the live snapshot and asserts
        each is absent from list results. **Measured on the 2026-08-10 snapshot before writing
        this:** the anomaly control is natural — **17 of 7,339 pools** exceed
        `APY_SANITY_LIMIT` (max total APY **394,208.17**). The TVL control is **not** natural:
        the snapshot is pre-floored (`minTvlUsd: 100000`, min observed `tvlUsd` **100,010**,
        **0** sub-floor pools), so the test takes a real pool from the population and perturbs
        only its `tvlUsd` below the floor — preferring natural sub-floor instances when a
        future snapshot contains them, and stating in output which kind it used. A test that
        finds no anomalous pool at all must fail loudly rather than pass vacuously.
  - [ ] **Mirror/set-equality, both directions**: the rail values the API emits are parsed
        out of `app.js` at test time and compared to what `/api` reports — equal both ways.
        If a human moves `APY_SANITY_LIMIT` or `DEFAULT_MIN_TVL` in `app.js` without the API
        following, this test goes red.
  - [ ] `minTvl` below the floor is clamped up and reported; above the floor is honored.
  - [ ] `forever-number` math matches `planner.js:162`'s `foreverNumber` semantics
        (`monthly*12/rate`), including the `rate <= 0 → not financeable` branch.
- [ ] **Non-vacuity**, proven in-session and written into `227-notes.md`: each rail is
      neutered **separately** (anomaly exclusion, TVL floor, mirror assertion) → the
      corresponding test goes **red** → restore is **byte-identical** (`md5sum` before/after
      quoted) → green. Three separate red/green cycles, so "three working rules" is
      distinguishable from "one working rule and two dead ones".
- [ ] `node run-tests.js --lane=plain` passes (timeboxed to 5 foreground minutes per
      NORTH_STAR's 2026-07-11 decision; if it exceeds, document and proceed).
- [ ] No product render path touched: `git diff --stat` shows no change to `app.js`,
      `PoolDetail.js`, `planner.js`, `home.html`, `plan.html`, `style.css`, `translations.js`.
- [ ] No new npm dependency.

## Territory notes

- `edge/` is the 224 Worker's home and is **not** the out-of-scope `workers/` directory
  (funds-moving code). Confirmed by reading NORTH_STAR's OUT OF SCOPE list and `edge/`'s
  contents.
- File-extension trap, documented at length in `edge/agent-log.mjs`'s header: the Worker entry
  must stay `.mjs` (native ESM for the plain-Node test) while cores stay `.js`/CommonJS
  (`require`-able, and the repo root `package.json` has no `"type"` field and must not gain
  one). New core file therefore is `edge/api-core.js`, CommonJS.
- `edge/wrangler.toml`'s `main` resolves **relative to `edge/`**, so it stays `agent-log.mjs`
  — no config change is needed for this item, and changing it would break the deploy.
- `run-tests.js` derives its file list by parsing `package.json`'s `test:serial` string; a new
  test is registered by appending there and nowhere else (`test_test_registry.js` guards this).
- `data/pools-snapshot.json` (3.4MB, regenerated daily by `generate-pools-snapshot.js`) is the
  in-repo population for tests — no network needed in the test lane. Its root is an OBJECT
  (`schemaVersion, generatedAt, source, minTvlUsd, count, pools`); the array is `.pools`.
- **Total APY has no single field.** Every site in `app.js` that needs it computes
  `(pool.apyBase || 0) + (pool.apyReward || 0)` — lines 1965, 2066, 2166, 2930, 3694. The API
  uses that same expression; there is no `apy` property to read.
