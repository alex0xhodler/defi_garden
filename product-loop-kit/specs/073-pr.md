# 073 — Minify planner-styles.css + pool-detail-styles.css (HIGH-tier explainer)

## Goal
Finish what backlog 053 started: every shipped stylesheet goes through the CI minify pipeline. 053 deliberately minified only the 5 files its evidence named and left `planner-styles.css` (83,011 B) and `pool-detail-styles.css` (23,812 B) as a documented follow-up (specs/053-notes.md). Those two files ship on the most conversion-critical routes: planner-styles on the default `/` planner (the top of the `waitlist_submitted` funnel) and pool-detail-styles on the analytics/pool-detail path (the SEO-lander conversion route, 019).

## Intuition
The pipeline, the dependency (clean-css), the freshness test, and the CI wiring all already exist — 053 built them. This item is almost pure configuration: tell the pipeline about two more files, point the two HTML entry points at the `.min.css` outputs, and teach CI + tests to keep them fresh. The risk isn't the transform (clean-css is proven on style.css, −22.5%); it's a wrong URL reference, which would serve an unstyled planner on the default route. That's why acceptance demanded a rendered-browser proof, not just string checks.

## What changed and why (diff in reading order)

1. **`minify-assets.js`** — `CSS_FILES` grows from `['style.css']` to `['style.css', 'planner-styles.css', 'pool-detail-styles.css']`. Everything else (minPath derivation, transformCss, the freshness-test export surface) is untouched; the pipeline was built to be extended this way.
2. **`plan.html`** — the non-blocking `<link>` (line 56) and the `<noscript>` fallback (line 58) now reference `planner-styles.min.css`. Same load pattern (`media="print"` onload swap) as before; only the URL changed.
3. **`home.html`** — the router's `addCSS('pool-detail-styles.css')` (analytics mode) and `addCSS('planner-styles.css')` (planner mode) now load the `.min.css` variants. Both router modes covered — this is the render-path hunk that makes the item HIGH.
4. **`planner-styles.min.css` / `pool-detail-styles.min.css`** (new, generated) — committed outputs of `npm run minify`: 67,196 B (−19.05%) and 19,244 B (−19.18%). Combined saving 20,383 B (~20.4 KB, −19.08%) — inside the spec's 20–25 KB expectation. Sources are the edit surface; the `.min` files are never hand-edited (053 convention).
5. **`.github/workflows/sitemap-update.yml`** — the `push.paths` trigger now watches both source CSS files (so an edit re-runs the regen job), and the regen job's `git add` list carries both `.min.css` outputs (so CI keeps them fresh, same as style.min.css).
6. **`test_minified_assets.js`** — the freshness loop already iterates `CSS_FILES`, so the two new files are covered automatically; added explicit reference assertions that plan.html/home.html load the `.min.css` names and no longer reference the raw ones. Now 9/9.
7. **`test_css_minified_render.js`** (new) + **`package.json`** (test-chain insertion after test_minified_assets.js) — rendered acceptance per the 2026-07-11 standing decision: real local HTTP server + real Chromium, external hosts fixture-routed (test_search.js pattern). Asserts plan.html gets a 200 on `planner-styles.min.css`, zero requests for the raw sheet, AND a computed style (`.gp-tagline { text-align: center }` — a rule that exists only in the planner sheet) actually applies; then asserts `?token=USDC` analytics mode requests `pool-detail-styles.min.css` and never the raw name. The verifier mutation-checked it: deleting the min file makes the test fail with a 404, so the gate genuinely detects a broken reference.

Not touched: all three source CSS files (byte-identical, acceptance-checked via `git diff`), `style.min.css`, `vercel.json` (its `/(.*)\.(js|css)` cache header already covers the new files), app.js/planner.js/translations.js (no copy, no numbers, no trust-rail contact).

## Deviations from spec
- Rendered test shipped as a standalone `test_css_minified_render.js` rather than extending `test_hero_copy.js` — the spec offered the choice; standalone keeps the rendered gate adjacent to the static `test_minified_assets.js` gate and the diff smaller.
- Computed-style probe chose `.gp-tagline` / `text-align: center` — literal (non-variable) and unique to planner-styles.css, so the assertion can't pass off style.css alone.
