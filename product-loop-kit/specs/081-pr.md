# 081 — Honest sitemap lastmod (full HIGH-tier explainer)

## Goal

Stop the daily sitemap CI from (a) committing — and therefore spending a Vercel deployment — on runs where nothing actually changed, and (b) telling Google that every one of ~4.8k URLs and ~110 child sitemaps changes every single run, which is the kind of systematic `lastmod` lying that makes Google ignore the field entirely and forfeits the crawl-scheduling benefit that 013/080's quality-gate work exists to earn.

## Intuition

`generate-sitemap.js` computed one `const now = new Date().toISOString()` and stamped it on **everything**: every `<url>` entry in every child sitemap, and every `<sitemap>` entry in the index. So even a run where the pool data produced byte-for-byte identical URL sets rewrote every file with a fresh timestamp. The workflow's commit gate is `git status --porcelain` — a fresh timestamp is a diff, so the gate *always* fired. Live proof on 2026-07-14: commit `8fee9e9ba` landed 18 minutes after `117d14a2d` with a diff of exactly 560 insertions / 560 deletions across 109 sitemap files — every changed line a `<lastmod>`. One wasted commit, one wasted Vercel deploy (the quota that was already exhausted once, per the 2026-07-13 ship-path decision).

The fix's core idea: **a timestamp is content-derived, not run-derived.** An entry that is byte-identical to the committed one (modulo its timestamp) keeps the committed timestamp. Only genuinely changed or new entries get `now`. Once that holds per-entry, everything else falls out: unchanged files come out byte-identical (git sees nothing), the index entry for each child can honestly be "the newest thing inside that child", and a no-change run leaves the tree clean so the workflow's *existing* gate skips the commit — no workflow commit-logic change needed at all.

## What changed, in reading order

### `generate-sitemap.js`

1. **`LASTMOD_PLACEHOLDER`** (`__DEFI_GARDEN_LASTMOD__`) — a sentinel that stands in for the timestamp while an entry is built, so a fresh entry can be compared byte-for-byte against a committed one with the timestamp factored out.
2. **`parseExistingUrlEntries(filePath)`** — reads the committed child file and regex-parses its `<url>` blocks into `loc → { lastmod, normalizedEntry }`, where `normalizedEntry` has the lastmod value replaced by the placeholder. Missing or unparseable file → empty map → every entry gets a fresh timestamp, i.e. exactly the pre-081 behavior. (Regex parsing is safe here: these files are self-generated in a fixed format.)
3. **All 9 `generateUrlXml(...)` call sites** now pass `LASTMOD_PLACEHOLDER` instead of `now`. `generateUrlXml` itself is untouched — it just interpolates whatever lastmod string it's given.
4. **`resolveLastmods(placeholderEntries, existingMap, now)`** — for each freshly built entry: same `loc` exists in the committed file AND the normalized bytes match → reuse the committed lastmod; otherwise → `now`. Returns the resolved entries plus the file's max lastmod (ISO-8601 strings compare lexicographically, so string `>` is a correct time comparison).
5. **The write loop** parses each target file's committed entries, resolves, records `childMaxLastmod[filename]`, writes. An unchanged child resolves every entry to its committed timestamp → output is byte-identical → no git diff for that file.
6. **The index** stamps each child entry with `childMaxLastmod[filename]` instead of `now` — the index only moves when a child really changed. The 4 foreign page-sitemaps (`sitemap-token-pages.xml`, `sitemap-chain-pages.xml` + KO twins — written same-run by the token/chain generators, listed in `FOREIGN_PAGE_SITEMAPS`) get **`maxLastmodFromFile(file, now)`**: their index lastmod is derived from their actual content instead of fabricated.
7. **Exports**: the three helpers + the placeholder join `module.exports` (the 080 `cleanupStaleSitemaps` pattern) so the unit test can exercise them without network.

Deliberately untouched: timestamp format, URL membership, the 013 quality gates (`SITEMAP_MIN_QUALIFYING_POOLS`, TVL floor), priority/changefreq math, hreflang emission, `cleanupStaleSitemaps`, robots.txt/llms generation, all trust rails.

### `.github/workflows/sitemap-update.yml`

One top-level block: `concurrency: { group: sitemap-update, cancel-in-progress: false }`. The daily cron and push-triggered runs serialize instead of interleaving checkouts/pushes (today's 04:32/04:50 pair ran in exactly that collision window). `cancel-in-progress: false` because killing a half-finished sitemap push is worse than waiting.

### `test_lastmod_honesty.js` (new) + `package.json`

Fixture-based, no network, 8 asserts: unchanged entry preserves lastmod · changed-priority entry gets `now` · new loc gets `now` · missing old file → all-new · unparseable old file → all-new · `resolveLastmods` max-lastmod correctness · `maxLastmodFromFile` derivation · placeholder round-trip. Appended to the `npm test` chain. An always-return-`now` mutation fails 3 of the asserts.

## Deviations from spec

One, documented in `specs/081-notes.md`: acceptance #1's "empty porcelain after run 2" is fully met, but the *first* run against the current committed tree makes a one-time legitimate correction — the 4 foreign page-sitemap index entries change from the fabricated `2026-07-14T04:50:54.912Z` to the honest file-derived value. That correction *is* the fix working (spec §C anticipated honest lastmods landing "naturally" on the next CI run); from then on the steady state is: no data change → no diff → no commit → no deploy.

Nothing was committed to the sitemap surface in this PR (spec §C: the committed sitemaps are correct; only future churn behavior changes).

## What to watch after merge

- The next CI run's diff should shrink from ~110 churned files to only really-changed children (+ the one-time foreign-entry correction).
- GSC (human's manual window through ~2026-08-23): lastmod now honest, crawl scheduling can trust it.
- **Known residual (verifier finding, spec gap not build defect):** the commit gate is whole-tree porcelain and `generate-llms.js` still stamps an unconditional `new Date().toISOString()` into llms.txt/llms-full.txt (lines 318/418/547 — the 6 non-lastmod lines in `8fee9e9ba` were exactly that). So the daily run will **still commit every run** until llms.txt gets the same content-derived-timestamp treatment. 081 delivers the ~110-file lastmod churn elimination, honest GSC lastmod, index honesty, and the concurrency guard; the skip-the-commit deploy saving needs the documented follow-up (llms timestamp honesty — evidence recorded for the next promotion).
