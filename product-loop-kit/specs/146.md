# Spec 146: Post-waitlist share path is subscription-hardcoded — TARGET/GROWTH plans get goal-incoherent, wrong-number, link-less cards

## Evidence
Promoted by the build loop 2026-07-26 — **no READY items existed** (140/141/142/143/144/145 all
SHIPPED; 097/118/133 BLOCKED on the human; 026/057 PARKED). Promotion is from documented in-repo
evidence, not invention:

1. **`specs/139.md` Territory notes (lines 101-110), verbatim**: "Found (not fixed, flagged
   separately): `mixStats()` (planner.js ~276) can misread a TARGET goal's one-time item price
   (`GOALS[].target`, e.g. iphone=1100) as if it were a $/mo subscription cost, because SUBSCRIPTION
   and TARGET goals reuse the same `target` field for different meanings. This previously could
   render a nonsensical 'garden already covers X — a card funded by $91k/mo' line inside the waitlist
   modal for TARGET plans. Gated shut in this item by restricting that line's render condition to
   `archetype === 'subscription'` … The deeper root cause … was NOT touched here (scope discipline) —
   flagged as a follow-up task."
   `specs/139-notes.md:29` and `specs/139-pr.md:80` repeat the same follow-up flag. **139 gated ONE
   symptom (one modal line). This item fixes the root cause and the remaining un-gated consumers.**

2. **Code-read confirmation of the remaining un-gated consumers** (planner.js, current `main`):
   - `mixStats()` **planner.js:285-288** — its own doc comment (line 273) says it resolves ids "from
     GOALS (**subscription archetype**)", but the code accepts *any* goal with a numeric `target`.
     TARGET goals carry `target` = one-time item price and **no** `isMonthly` flag
     (`sneakers` 180, `iphone` 1100, `watches` 400 — planner.js:793-800), so `iphone` resolves to
     "$1,100/mo". GROWTH goals (`home`, `retirement`) carry no `target` and already resolve to
     nothing.
   - The **mix seed effect planner.js:1684-1688** runs `setSelectedSubs([goal])` for **every**
     archetype — no archetype guard — so a TARGET plan's `currentMixStats` is populated with that
     bogus $/mo from first render.
   - **`doWaitlistDownload()` planner.js:1886-1920** (the "Download card" button on waitlist step 2,
     planner.js:2803-2808) hardcodes the SUBSCRIPTION frame for every archetype:
     `t('shareSubBundle', dlList)` + `t('shareSubSubline', neededCapital, apy, combinedMonthly)`.
     For a TARGET iPhone plan that renders a card reading "🌱 My yield covers **iphone** — forever"
     over "≈$220,000 working at 6.0% · **$1,100.00/mo** covered forever" — a number the user never
     entered, for a goal that is not a subscription.
   - **Raw-id leak**: both `doWaitlistDownload` (line 1893) and `doWaitlistShare` (line 1874) fall
     back to the **raw lowercase id** (`return found ? t(found.labelKey) : id`) when an id is not in
     `SUBSCRIPTION_LADDER` — so the card headline and the tweet say `iphone`, not "iPhone".
   - **`doWaitlistShare()` planner.js:1868-1884** posts `t('shareTweet', labels)` = "My yield pays
     for iphone — forever" for a one-time-purchase goal.
   - **The waitlist email payload** `msgSummary` (planner.js:1830-1833) is built un-gated too:
     "covers iphone (~$1,100.00/mo) for ~$220,000, risk …" lands in the operator's Formspree inbox.
   - **`doWaitlistDownload` passes no `url`** — `renderShareImage` line 3334 comments "No plan URL
     supplied (e.g. the waitlist card download) — unchanged pre-005 behavior: just deliver the
     image." So this share surface ships a PNG with **no plan link at all**, and reports no
     share-link analytics.

3. **Standing decisions this violates** (NORTH_STAR.md): 2026-07-10 — "every share path must carry
   the plan URL or it can't close the loop"; 2026-07-11 — "plan share = a UNIQUE WORKING LINK …
   the link that rebuilds the garden is the primary artifact"; 2026-07-23 PRE-TRAFFIC MANDATE — the
   loop's primary job is product quality: "broken/absurd numbers … goal-incoherent copy".

4. **The correct implementation already exists in this file**: `doShare()` (planner.js:1990-2055)
   branches by archetype (subscription-capital / subscription-monthly / target / growth), always
   resolves labels through `goalLabel(t, …)`, and passes `url: shareUrl`. The two waitlist share
   functions are a copy that never got the branching. Per the 2026-07-10 REUSE directive, the fix is
   to reuse that logic, not to write a third variant.

## Hypothesis
We believe making the post-waitlist share path archetype-correct, number-honest and link-carrying
will (a) remove a class of absurd-number/goal-incoherent output on the product's hero share artifact
and (b) let a waitlist-completing TARGET/GROWTH user actually propagate a working plan link, because
today that path is provably subscription-only in its copy and carries no URL at all.
Confidence: **validated-pattern** (same defect class and same fix shape as 139, which the human
accepted; the archetype-branching reference implementation already ships in `doShare`).

## Change
Smallest change that removes the defect at its root and stops re-deriving it per call site.

1. **Root cause — `mixStats` (planner.js:285-288)**: the `GOALS` fallback resolves an id **only** if
   that goal is genuinely a monthly cost (`g.isMonthly === true`). This restores the function's own
   documented contract. Every `archetype: 'subscription'` GOAL has `isMonthly: true`, so the
   subscription path is **behaviourally identical**; only TARGET ids stop resolving.
2. **Mix seed (planner.js:1684-1688)**: gate the seed on `archetype === 'subscription'`. A
   TARGET/GROWTH plan keeps `selectedSubs = []`, so every mix-derived label/figure degrades to the
   already-correct `goalLabel(t, goal)` fallback instead of a bogus bundle.
3. **Extract one share-copy builder**: lift the archetype branch inside `doShare()` (planner.js:
   1993-2055) into a single helper (e.g. `buildShareCopy()`) returning
   `{ headline, subline, rowLabel, featured, drawChart }`, and call it from **`doShare`**,
   **`doWaitlistDownload`** and **`doWaitlistShare`**. `doShare`'s own output must not change.
4. **`doWaitlistDownload` carries the plan URL**: pass `url: encodePlanToUrl(...)` (same argument
   list `doShare` uses at planner.js:2057) and `shareText: headline`, so the waitlist card closes the
   loop like every other share path.
5. **Raw-id leak**: any remaining `: id` label fallback becomes `goalLabel(t, id)`.
6. **Waitlist email `msgSummary` (planner.js:1830-1833)**: branch by archetype. Subscription keeps
   today's "covers …" string verbatim; TARGET/GROWTH gets an honest plain-English summary of the
   plan the user actually built (goal label + capital or monthly×years + risk). This string is not
   user-facing UI and is not translated today — keep it untranslated.
7. **New strings, if any, land in `translations.js` EN + natural KO together.** Prefer reusing
   existing keys (`shareTargetNew`, `heroTarget`, `bloomHeadline`, `shareSubline`) — at most ONE new
   key pair is expected, for a non-subscription tweet frame (`shareTweet` is subscription-worded).
8. **Instrumentation**: `doWaitlistDownload` fires `Analytics.trackShareLinkCreated({ method:
   'waitlist_card', goal, persona })` when the URL is attached — a **new, disjoint** `method` value
   that cannot pollute the existing `image`/`link` series.
9. Regenerate `translations.min.js` / `planner.min.js` per repo convention (`npm run minify`).

**OUT of scope**: renaming the shared `GOALS[].target` field across call sites (139 flagged it; the
`isMonthly` guard removes the harm without a rename); the main `doShare` path's copy or behavior;
the mix UI; the checkout panel; anything under `telegram-bot/`, `whatsapp-bot/`, `workers/`;
`APY_SANITY_LIMIT`/`DEFAULT_MIN_TVL`/anomaly flags/degen haircut (untouched — this item only makes
numbers *more* conservative).

deleted, no credentials/money/org-admin, nothing under the out-of-scope bot/worker dirs.

None that change the architecture. The one judgment call — whether TARGET/GROWTH should keep a
