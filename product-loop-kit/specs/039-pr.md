# 039 — PR explainer (HIGH tier): instrument the static SEO surface

## Goal
The human asked for SOTA-grade organic-growth initiatives. Research (this session) plus a direct grep turned up something more urgent than any new content idea: **zero of DeFi Garden's 2,048 static SEO pages (2,045 `/tokens/<slug>` + 3 `stories/*.html`) can fire a single trackable event.** Five-plus HIGH-tier build-loop items (014, 021, 023, 028, 029-033) shipped real, crawlable, trust-rail-consistent landing pages — and none of them can answer "is anyone actually landing here?" This item closes that gap, the same shape of fix 020 was for the in-app search funnel, one layer further upstream.

## Intuition
`home.html`/`plan.html` already do this correctly: a synchronous Mixpanel stub loader, then `<script defer src="analytics.js">`, then `analytics.js` self-fires `session_start` on `window.load`. `page_view` has always been an explicit call site (`app.js` calls `Analytics.trackPageView(path, props)` at several points) — it never auto-fires. The static-page generators (`generate-token-pages.js`, `generate-stories.js`) never got any of this wired in when they were built, because they're plain server-rendered HTML with no JS bundle at all by design (that's *why* they're fast and crawlable — the fix has to be additive, not touch that architecture).

## What changed and why
1. **`generate-token-pages.js` / `generate-stories.js`**: added a `MIXPANEL_STUB` constant (the exact Mixpanel loader snippet from `home.html:141-145`, reproduced via `String.raw` so its own regex literal `/^\/\//` can't be corrupted by template-literal escape processing — verified programmatically that the reproduction is byte-identical, not just eyeballed) and a `renderAnalyticsBootstrap(path, properties)` helper that assembles: the stub → `<script defer src="https://www.defi.garden/analytics.js">` → a `window.load` listener that calls `Analytics.trackPageView(path, properties)` once `analytics.js` has executed (the listener only registers immediately; its body runs at `load` time, after all deferred scripts, regardless of registration order — no race).
2. **Wired into both generators' `<head>` output**: token pages get `path: '/tokens/<slug>'`, `properties: { page_type: 'token_landing', token, pool_count }`; story pages get `path: '/stories/<slug>'`, `properties: { page_type: 'story_landing', persona }`. New `page_view` path-taxonomy values — no new event names.
3. **Deliberately did NOT add outbound click-tracking.** `analytics.js`'s `getBaseContext()` already stamps `referrer: document.referrer` on every event, and this site's `Referrer-Policy: strict-origin-when-cross-origin` sends the full path for same-origin navigation — so once this ships, filtering Mixpanel by `referrer LIKE '%/tokens/%'` on app-side events already answers "did this click through," with zero extra code. Verified this claim rather than assuming it.
4. **`package.json`**: added `test_stories.js` (new) to the `npm test` chain.
5. **Two new test files / one extended**: `test_stories.js` (new, 12 assertions — story-page analytics wiring + a regression check that `kevin.html`'s FAQ block is untouched), `test_token_pages.js` (+5 assertions — analytics wiring per generated page + a placement/content-untouched check).
