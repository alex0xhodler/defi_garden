## Goal → intuition

The card the business sells is *yield-funded*: your deposit's yield pays a subscription "forever." That
promise is only as trustworthy as the pools behind the blended rate. Item 088 already started translating
087's stored history KPIs into calm, honest language — 088.1 put a per-pool track-record note on the
analytics pool-detail page. **106 is the plan-level sibling on the planner bloom** — the surface where a
`plan_created` happens and the card funnel begins. It answers, in one calm line, "how steady is the
ground this plan stands on?" — directly serving the forever-number confidence problem without inventing
any new number: it only summarizes the `historyPoints` / `apyStdev` that 087's daily CI already computes.

North-star fit: the bloom is the `plan_created` / card-funnel front door, so a trust signal here is the
most direct READY lever on `share_link_opened → plan_created → waitlist_submitted`. (It was the tiebreak
winner over the two other 7.0 READY items — 102 pure CI plumbing, 103 the analytics app.)

## What changed and why (diff in reading order)

1. **`planner.js` — `planConfidence(curated)` helper** (immediately after `blendedApy`). Pure function
   over the ≤3 rail-passing pools behind the blended rate. Filters to pools that actually carry usable
   kpis (`kpis` object with `historyPoints >= 1`); returns `null` if none do — that null is what makes
   the note **hide honestly** on the live-fallback / cold-CDN path where DefiLlama returns no kpis (same
   discipline as 088.1's live-landing hide). Otherwise returns `{total, steady, minHp}`:
   - `minHp` = the *minimum* historyPoints across the plan's pools — the honest floor for any "N days"
     claim (a plan is only as tracked as its least-tracked pool).
   - `steady` = how many pools clear 088.1's exact steadiness test (`hp>=7` and `apyStdev/cur <= 0.2`).
   It reads only `p.kpis.*` + `poolTotalApy(p)` and never filters, reorders, re-weights, or re-flags a
   pool — the trust rails do the gating; this only *describes* what already passed.
2. **`planner.js` — `planConfidenceElement`** render IIFE. Maps the helper to one of three calm tiers:
   STEADY (all pools steady, `minHp>=7`), PARTIAL (some steady), BUILDING (none steady yet / still
   accruing). `null` helper → renders nothing. `🌱` icon + a text span, `.gp-plan-confidence` class.
3. **`planner.js` — placement.** Inserted right after `heroElement,` in **both** bloom return trees
   (subscription and target/growth), because those are two separate JSX-free `e(...)` trees and the
   subscription tree never renders the engine room. One line each.
4. **`translations.js` — 3 keys** (`planConfidenceSteady` fn, `planConfidencePartial` fn,
   `planConfidenceBuilding` string) in the **nested `planner`** block of both `en` and `ko`. Calm
   "education not advice" copy; counts come only from args; no "save up / afford / budget". KO is natural,
   not literal (back-translations in `106-notes.md`).
5. **`planner-styles.css` — `.gp-plan-confidence`** calm full-width note, modeled byte-for-byte on the
   adjacent `.gp-tangibility` rule; neuro tokens only, no gradient/glow/one-off color.
6. **Minified artifacts** (`planner.min.js`, `translations.min.js`, `planner-styles.min.css`) regenerated
   via `npm run minify` — proven regenerated (not hand-edited) by `test_minified_assets.js` 9/9.
7. **`test_plan_confidence.js`** — new rendered-Playwright gate (real plan.html + Chromium + routed
   fixtures). Unlike the share test (which routes a *stale* snapshot to force the no-kpis live path), this
   routes a *fresh* meta + a kpis-carrying snapshot so the tiers actually fire. 6 cases: STEADY / PARTIAL
   / BUILDING / live-absent / KO / zero-errors. Wired into `package.json`'s test chain.

## Data reality (why prod shows only BUILDING today)

087's CI has accrued 1–2 history points so far, so no pool has `hp>=7` yet → in production the note
currently renders only its BUILDING tier. STEADY/PARTIAL activate automatically as history accrues. The
code handles all three tiers; the Playwright fixtures exercise all three now. Same "code ready, data
catches up" precedent as 088.1.
