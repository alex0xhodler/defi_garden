# 132 — explainer (LOW): no "No yields found" flash before data loads

## What was wrong
On a `?token=X` SEO landing, the results area's grid-vs-empty ternary (`app.js:3146`) chose the empty
state whenever `filteredPools.length === 0` — with NO check on `loading`. So during the initial fetch
(pools not yet loaded) the empty-state top message "No yields found for X / Try adjusting your filters"
rendered immediately. Only the honest 012 explanation below it was `emptyStateResolved`-gated; the top
line wasn't. A search-engine visitor saw a false "No yields found" flash.

## Fix
Insert a middle branch: while the fetch is in flight and nothing has resolved
(`loading && !emptyStateResolved && !deadPoolResolved`), render a calm `t('loadingYields')` line instead.
The existing empty state renders unchanged once resolved. New `loadingYields` string (EN "Loading live
pools…" + KO "실시간 풀 불러오는 중…"). Regenerated `app.compiled.js/.min.js` + `translations.min.js`.

## Why it's correct / can't get stuck
- Pre-fetch: `pools.length === 0`, so both `emptyStateResolved` and `deadPoolResolved` (which require
  `pools.length > 0`) are false while `loading` is true → loading line.
- Resolved-empty: `emptyStateResolved` flips true → honest empty state (unchanged), regardless of `loading`.
- `loading` always flips false in `fetchPoolsInBackground`'s `finally` (app.js:1156), even on fetch error
  → the line can't hang; grid wins when pools exist.

Untouched — this does NOT relax the $10M floor (that is the sibling item 133); it only fixes WHAT renders
during load.
