# Spec 222: Remove the duplicate in-flow theme-toggle the sticky header buries at 360

## Evidence
Audit run `2026-08-04T07:13:34.180Z`, occlusion lens, at rest (scrollY=0):
- **P0 · grid-360 · 360×780:** interactive victim `<button class="theme-toggle">` rect {x:284, y:32, w:64,
  h:26} occluded by `<div class="google-header-sticky">` rect {x:0, y:0, w:360, h:130} — 100% covered,
  hit-test at centre resolved to the overlay. A control the user can never press.
- Root cause measured by 219 (day-one finding, LOG 2026-08-03): `app.js:3139` renders a SECOND
  `.theme-toggle`, distinct from the sticky header's own copy at `app.js:3062`; `.app.has-results` leaves
  the mobile `position:fixed` override (`style.css:4329`) un-applied, so the duplicate sits in flow exactly
  under the fixed header's 130px band.

## Hypothesis
We believe removing the duplicate render site (not repositioning it) fixes the P0 because the sticky
header already renders a working toggle — two toggles is the defect, the occlusion is just how it
surfaced. Confidence: supported (both render sites read directly in app.js; the header's copy is the one
users see and press today).

## Change
Smallest version: delete the `app.js:3139` duplicate `.theme-toggle` render (and any now-dead handler/CSS
that ONLY it used), recompile `app.compiled(.min).js`. Pre-registered fallback: if a surface provably
depends on the duplicate (check pool-detail's and landing's toggle render paths BEFORE deleting), keep it
and instead apply the `position:fixed` override on `.app.has-results` — and record why the preferred
option lost.
OUT of scope: item 221's footer occlusion on the same surface; any change to `.google-header-sticky`
itself; theme persistence logic (localStorage `theme` + `data-theme` — untouched).

- [ ] The audit's grid-360 occlusion pass no longer reports the theme-toggle victim; its quarantine entry

- [ ] Tests: dark-mode/theme tests plus the plausibly-affected set run individually.
