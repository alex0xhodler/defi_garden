# 225 — DESIGN RESET: one clean-minimal system ("Quiet"), neumorphism stripped

**Risk tier: HIGH** (render path on every surface, including the sacred `?token=` / `?chain=` / `?pool=`
URLs). **This PR does NOT auto-merge.** Item 225 carries an explicit human pre-merge screenshot gate —
your carve-out from autonomy (c), recorded in the 2026-08-04 standing decision. It waits for your yes.

## Goal

You said the UI is "below any amateuristic ui back from the 2020 … now it's all over the place." The
structural reason, measured: the product ran **two** design systems at once — 2020 google-mimic chrome on
the analytics app (`.google-header-*`, `.google-nav-tab`, `.google-filter-btn`) and the 2026 neumorphic
skin on planner/landing/pool-detail. Three weeks of loops kept fixing bugs *at the seam between the eras*
(217, 218, 220, 222) without ever being allowed to remove the seam. Q2b authorised removing it.

## The intuition

Neumorphism makes depth out of **two shadows pointing opposite ways**, so every surface must be almost
the same colour as the page or the illusion breaks. That is why the old planner is a field of pale puffy
pills on a pale background: the design system was spending its entire contrast budget on the illusion.
The new system ("Quiet") makes depth out of **a 1px border and a background step**, which costs no
contrast at all — so text can be dark, surfaces can be white, and the accent can mean "this is the thing
to press" instead of competing with decoration.

One shadow token survives, `--ui-shadow-overlay`, and only for things that genuinely float (dropdowns,
popovers, modals).

## What changed, in reading order

1. **`product-loop-kit/specs/225-design-system.md`** — the written design spec the build was executed
   against: token values, one rule per component (header / card / button / chip / input / nav tab /
   focus / press physics), and the invariant list. Read this first; everything else implements it.
2. **`style.css`** — the token layer. `--ui-*` light ramp in `:root`, a real `--ui-*` dark ramp in
   `[data-theme="dark"]` **and** in `@media (prefers-color-scheme: dark)` (dark mode was previously
   half-wired: it re-tinted shadows only and never redefined surfaces). Then ~280 neuro usages converted
   to borders/flat surfaces, the dead `var(--neuro-shadow-inset)` reference removed, and the `.google-*`
   era renamed 1:1 to `.app-*` with four dead rule sets deleted.
3. **`app.js`** — className strings only, per the rename table. No state, no handlers, no logic, no copy.
4. **`planner-styles.css`, `landing-styles.css`** — the planner's preset grid becomes ONE chip
   component; both headers get the shared surface + hairline pattern.
5. **`pool-detail-styles.css`, `PoolDetail.js`, `stories/stories.css`** — the north-star surface. The two
   CTAs ("Garden this pool →" primary, "Start Earning on <protocol> ↗" secondary) are now the design
   spec's primary/secondary buttons; the calculator's quick-amount chips are one chip component.
6. **Deprecated alias block** (in `style.css`) — every `--neuro-*` NAME still resolves, pointing at the
   flat values. This is deliberate, and the most important design decision in the PR: ~4,281 generated
   static pages bake those token names into inline `<style>` blocks, and 7 test assertions require the
   literal string. Aliasing means the whole SEO estate inherits the reset with zero generator churn.
7. **Regenerated artifacts** — `app.compiled*.js`, `PoolDetail.compiled*.js`, `*.min.css`, `*.min.js`.
   The site loads the minified files; a raw-only change would ship dead.
8. **Screenshots** — `product-loop-kit/specs/225-screenshots/{before,after}/`, 24 shots each
   (landing / planner / grid / pool-detail × 360/768/1280 × light/dark). **This is the review artifact.**

## Deviations from the spec (all four are in `specs/225-notes.md` in full)

1. `--neuro-*` names survive as deprecated aliases (spec-permitted; reasons above). Nothing yet prevents
   a future rule from spelling one — **the class is open**, no grep gate was built.
2. The sticky analytics header is flat at rest *and* scrolled; adding a scrolled state means touching
   `app.js` state, outside this item's className-only scope for that file.
3. `.gp-header` / `.landing-header` are content-width, not edge-to-edge — a true app bar needs a markup
   change in `planner.js` / `landing.js`. **This is the most visible cosmetic inconsistency in the
   screenshots**; say the word and it is a small follow-up.
4. Filter chips keep a **filled-primary** selected state (accent fill, white text) instead of the uniform
   accent-soft — because the uniform treatment regressed `test_filter_dropdown_polish.js`, whose spec-111
   assertion exists to make a selected filter unmistakable. The older decision won; the exception is now
   written into the design spec.

  the lens's two documented blind spots.
