# 058 — PR explainer (LOW tier)

## What shipped
A feasibility study, `docs/feasibility-data-layer.md`, answering whether DeFi Garden should add a data wrapper/cache layer in front of the DefiLlama `/pools` API. Per its spec (`product-loop-kit/specs/058.md`), the output is a decision document — no product code changed.

## What it says
- Options matrix: (a) static snapshot via the existing CI/generator pattern, (b) serverless + edge DB (Turso/libSQL or Cloudflare D1), (c) hybrid.
- Recommends shipping (a) first — it's the same shape as work already in production (sitemaps, `/tokens/`, `/chains/`, OG images) and doesn't reverse the no-backend tenet. The KPI/history feature that genuinely needs a real DB (b/c) is deliberately deferred to a separate, later, human-approved decision.
- Payload-size estimate and the DefiLlama ToS/attribution answer are both marked ASSUMED and disclosed prominently — `yields.llama.fi` is network-blocked in this sandbox (confirmed via a failed `curl` and a live proxy-status rejection log entry), the same restriction every prior loop item touching live DefiLlama data has hit. The doc makes "take a real measurement" and "human confirms ToS" the first two steps of its phased plan rather than guessing.
- Trust rails (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`) are explicitly addressed: the layer would enforce them once upstream, never relax them.
- A follow-up build item (059, static-snapshot option) is drafted inside the doc, explicitly marked BLOCKED pending human ToS confirmation and sign-off — not promoted to a live BACKLOG row.

## Why LOW, not HIGH
The spec itself tags this HIGH/human-decision because the *eventual recommended build* reverses the no-backend tenet. This diff doesn't build anything — it's a docs file + a 1-line BACKLOG status edit + a notes file (136/-1 lines, no new dependencies), which is exactly NORTH_STAR's LOW bucket. The verifier independently re-derived LOW on the same reasoning and confirmed no backend/DB was stood up.
