# Spec 160: Extend the product audit to non-HTML generated surfaces

## Evidence

Two P0/P1-class defects on public surfaces in two consecutive days, both found **by hand**, both structurally invisible to `audit-app.js`:

- **2026-07-26 — item 148.** `audit-app.js` scored "10 surfaces, 0 findings" on the same day a human traced three odd prod URLs back to our own token-page generator. Fixed structurally by items 154/157 (the scanner can now see generated *HTML* pages).
- **2026-07-27 — item 159.** `llms.txt` publishing 353,114.2% APY live on prod, no `APY_SANITY_LIMIT` applied. Found by a hand-written node scan during the heartbeat's data-layer check, not by any automated gate. This tick's `audit-app.js` run was **clean apart from the known 148 class** while this was live.

What the scanner covers today (`audit-app.js`, 16 surfaces this tick): rendered HTML only — 9 app surfaces + `static-page` + a rotating `static-page:<slug>` sample, plus `prescanStaticPages()` over the 2,197 `tokens/*.html` + `chains/*.html` leaves.

What it has never read, despite all of it being committed, publicly served and generator-produced:
- `llms.txt`, `llms-full.txt` — the AI-discovery surface (**where 159 lives**)
- `sitemap-*.xml` — the SEO index surface
- `og/**/*.png` — social cards

`prescanStaticPages()` already proves the cheap approach works: pure `fs` + regex over 2,197 files in ~480 ms, emitting one aggregate finding per signal. Text surfaces are strictly easier — there are ~2 files, not 2,197.

## Hypothesis

We believe adding a text-surface pass to `audit-app.js` will convert the current hand-found class into an automated one, because the two misses that motivated it (148, 159) are both **greppable string patterns in committed generator output**, and the existing prescan already demonstrates the pattern at 1000× the file count. Confidence: **supported** — it would have caught 159 on day one; whether it catches the *next* unknown class is the actual open bet.

## Change

Smallest version: a `prescanTextSurfaces()` alongside the existing `prescanStaticPages()`, emitting aggregate findings in the same shape, covering `llms.txt` and `llms-full.txt`:

1. **`apy-rail-breach` (P0)** — any `% APY` figure in the file exceeding `APY_SANITY_LIMIT` (1000). This is 159's detector.
2. **`tvl-floor-claim` (P1)** — the file's stated TVL floor (the `TVL ≥ $…` string) disagrees with the smallest TVL figure actually listed.
3. **`broken-number-literal` (P0)** — reuse the existing predicate: `NaN`, `Infinity`, `undefined`, `null` appearing where a number belongs.
4. **`empty-surface` (P1)** — a generated text surface that lists zero pools (the soft-404 equivalent; guards against a future over-tight filter silently emptying the file, which is exactly the failure mode 159's own fix could introduce).

Explicitly OUT of scope:
- Fixing 159 itself. **159 ships first**; this item is the gate that keeps it fixed. If they land out of order, this scanner correctly goes red until 159 merges — that is the 157 precedent and is not a reason to weaken a severity.
- `sitemap-*.xml` and `og/*.png`. Named here as known-uncovered, deliberately deferred — sitemaps already have `validate-sitemaps` (112/112) and OG images need image decoding, a different cost class. One surface family per item.
- Any change to `generate-llms.js` or any product file.

## Acceptance criteria

- [ ] `audit-app.js` gains a text-surface pass; `surfacesCovered` includes a new entry naming it, and never loses any surface it covered before (16 this tick is the floor).
- [ ] Positive control, executed: with the **current** committed `llms.txt` (or a fixture reproducing it), the pass emits a P0 `apy-rail-breach` finding whose `detail` quotes a real figure > 1000%.
- [ ] Negative control, executed: against a fixture whose figures are all in-rail, the pass emits **zero** findings.
- [ ] Boundary: exactly `1000.0% APY` does **not** trigger; `1000.1% APY` does.
- [ ] `empty-surface` fires on a fixture listing zero pools.
- [ ] Aggregate shape matches the existing prescan — one finding per signal with ≤10 examples, so a systemic defect cannot emit hundreds of findings.
- [ ] Runtime: the text pass adds < 1 s to a full `audit-app.js` run (it reads ~2 files).
- [ ] The pass honours the existing `opts.only` allowlist, matching how 157 scoped its aggregate findings, so the legacy scoped-clean-run tests keep passing.
- [ ] Tests: new cases wired into `npm test` in the existing convention. Non-vacuity: neuter the rail comparison, prove the positive control goes red, restore byte-identically and prove green.
- [ ] No product file, generator, page, sitemap or dependency touched. `APY_SANITY_LIMIT` read from a single source, not re-hardcoded a third time.
- [ ] Instrumentation: **none** — loop tooling under the 2026-07-23 pre-traffic mandate. Record the disclosure per the 142/149/154/155 precedent.

## Measurement

Metric: **none — loop tooling.** Success is observable at the next heartbeat: the tick's `audit-findings.json` either shows the text surface clean, or tickets a real defect without a human tracing it by hand. Do not open a 14-day window.
