## Evidence

`package.json`'s `test` script is a ~90-file `&&` chain. `test_landing.js` is file **10**. Item 156
(shipped 2026-07-27) cleared file 9 (`test_smoke.js`); the chain now halts here instead, so **~80 test
files still never run** on a plain `npm test`. Reproduced on this branch's base commit (`7989cf070`,
`origin/main`) with `node_modules` installed via `npm ci`:

```
$ node test_landing.js
```

### The product is not broken — three separate test-harness defects are

Measured this run with a Playwright probe driving the identical flow against the identical routed server
(scratch script, not committed):

**1. `page.waitForURL` defaults to `waitUntil: 'load'`, and `load` never fires on the analytics route.**
The navigation itself is correct and fast — `framenavigated → http://localhost:PORT/?token=USDC` — and the
grid renders (9 `.pool-card` elements, "148 pools found"). But 12 s after the search,
`document.readyState` is still `interactive`, with these requests still outstanding:

```
https://mp.defi.garden/lib.min.js
https://api.fontshare.com/v2/css?f[]=satoshi@400,500,700&display=swap
https://icons.llamao.fi/icons/protocols/maple?w=48&h=48        (+ 9 more llamao icon URLs)
```

Browser-originated HTTPS is blocked at the proxy connection level in cloud-loop sandboxes (NORTH_STAR
standing decision 2026-07-12), so those never settle and the `load` event never arrives. The assertion is
waiting on a lifecycle event the sandbox cannot deliver, not on the behaviour it claims to test.

`test_search.js:244` and `test_smoke.js:129` already ship the fix for exactly this, with the reason in the
comment: `page.route('https://icons.llamao.fi/**', route => route.abort()); // decorative icon host
(spec 094) is proxy-blocked in-sandbox; abort so requests never delay the load event`. `test_landing.js`
never adopted it.

**2. `test_landing.js`'s `FIXTURE_POOLS` is dead code — the test silently reads the committed snapshot.**
It routes `https://yields.llama.fi/pools` (`:44`) and nothing else, but the app is snapshot-first since
item 059: the probe rendered **148 USDC pools** off `data/pools-snapshot.json`, not the 2 fixture pools.
So the one Playwright gate for the landing→analytics handoff asserts against whatever DefiLlama happened
to return at the last CI bake — a moving target, and the "fixture" gives no isolation at all.
`test_smoke.js:130` and `test_search.js:245` both route `**/data/pools-snapshot*`; this file does not.

**3. Ignorable-error matching is URL-blind and misses three hosts.** `test_landing.js:19` is
`/mp\.defi\.garden|cdn\.mxpnl\.com|mixpanel|fontshare\.com/i`, tested against `msg.text()` only (`:65-67`).
Chromium's `"Failed to load resource: net::ERR_CONNECTION_RESET"` text **never contains the URL** — the
exact trap `test_smoke.js:26-40` documents — and the pattern is missing `icons.llamao.fi`,
`api.llama.fi/protocols` and `www.google.com/s2/favicons`. The probe observed two such bare
`ERR_CONNECTION_RESET` console errors on the landing route. They do not fail the run today only because
the run dies at defect 1 first; fixing 1 without 3 would move the red rather than clear it.

## Hypothesis

Confidence **supported** (measured, reproduced, root-caused above): bringing `test_landing.js` onto the
fixture-routing pattern that `test_search.js`/`test_smoke.js` already ship makes it pass in-sandbox
without weakening any assertion, and unblinds the ~80 downstream files in the chain. Confidence **guess**:
how many of those 80 are themselves red — unknown until they run, and explicitly *not* this item's job
(one item, one red class — `playbooks/` trap from 156).

## Change

`test_landing.js` only. **No product code, no `translations.js`, no generated SEO surface, no dependency.**

1. Route the external hosts on the page before the first `goto`, copying the shipped pattern verbatim:
   - `page.route('https://icons.llamao.fi/**', route => route.abort())` — keep the existing comment's
     wording so the three files stay greppable as one pattern.
   - `page.route('**/data/pools-snapshot*', …)` fulfilling a minimal snapshot envelope so `FIXTURE_POOLS`
     becomes the real source for the grid (`test_smoke.js:130` shape).
   - Keep the existing `yields.llama.fi/pools` and `api.llama.fi/protocols` routes.
2. Replace the `load`-gated wait with a URL-only wait that does not depend on the lifecycle event
   (e.g. `page.waitForURL(pred, { waitUntil: 'commit' })` or an equivalent poll on `page.url()`), then
   keep the existing `waitForSelector('.pool-card')` — the render assertion is what actually proves the
   handoff and it must stay.
3. Extend `IGNORABLE_ERROR_PATTERN` to `test_smoke.js:40`'s set (`icons.llamao.fi`,
   `api.llama.fi/protocols`, `www.google.com/s2/favicons`) and match it against `msg.location().url`
   **and** `msg.text()`, per `test_smoke.js:117-122`.
4. Change **no existing assertion's meaning**. All five current checkpoints keep asserting what they
   assert today — the landing SVG geometry, the `data-mode`, the no-planner-above-landing guard, the
   footer text, `plan.html`, the planner share URL, `?app=1`. Loosening an assertion to get green is a FAIL.

**Explicitly out of scope:** any other red in the chain (whatever file 11+ turns out to be — document it,
don't fix it); the `MODULE_NOT_FOUND`-on-fresh-clone class already ticketed as 149; product code of any
kind; `home.html`, `landing.js`, `app.js`.
