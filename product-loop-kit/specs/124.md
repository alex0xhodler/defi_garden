# 124 — Elevate "Start Earning on <protocol> ↗" to a real secondary CTA

**Score:** 8.0 · **Priority:** P1 · **Risk tier (proposed):** LOW (styling + class reuse; no copy change, no new deps, diff ≪ 150 lines)

## Why (evidence)
- North star (NORTH_STAR.md, 2026-07-23): pool-detail conversion clicks = `pool_click{source=garden_cta}` + `pool_click{source=protocol_link}`. The `protocol_link` half is emitted by `PoolDetail.js:517`.
- Audit finding (BACKLOG 124, screenshot): the "Start Earning on <protocol> ↗" affordance is now a north-star metric but renders as tiny muted fine-print (`.pool-action-protocol-link`: 14px, `--color-text-secondary`, no button chrome) directly under the filled primary button. It reads as a footnote, not a call to action, dampening `protocol_link` clicks.
- Pre-traffic mandate (2026-07-23): product-quality/trust work over speculative A/B — a visible, honest secondary CTA is exactly that.

## What (acceptance criteria)
1. The protocol affordance renders as a **visible secondary neuro button**, not muted text — a raised neumorphic surface button with clear affordance.
2. **Clear two-tier hierarchy** vs the primary "Garden this pool": primary stays the filled `--color-primary` button; the protocol CTA is a distinct, lower-emphasis raised-surface button (not filled, not the same visual weight).
3. The honest sublabel **"Opens protocol • Wallet required"** (`opensProtocol`, EN+KO) still renders directly below the button.
4. The **↗** external-link glyph is retained in the button label.
5. The click still fires `Analytics.trackPoolClick(pool, 'protocol_link')` on activation (unchanged) and still opens the protocol URL in a new tab with `noopener,noreferrer`.
6. No copy change (EN/KO strings `startEarningOn`, `opensProtocol` unchanged) → no translations.js edit required.
7. Works at 360 / 768 / 1280px and in dark mode; keyboard-focusable with a visible focus ring; `prefers-reduced-motion` honored.

## How (reuse before inventing — build.md §1b)
- `pool-detail-styles.css` **already defines `.cta-button-protocol`** (a raised neuro secondary button: `--color-surface` bg, `--neuro-shadow-raised`, press physics on `:active`) but **no render code uses it** (grep confirmed zero usages). This is the reuse target — the intended secondary-CTA class was authored and orphaned.
- Change: in `PoolDetail.js`, swap the protocol `<button>`'s class from `pool-action-protocol-link` (text-only link) to `cta-button-protocol` (existing neuro button). Keep the same `onClick` (tracking + `window.open`), keep the label + ` ↗`, keep the `.pool-action-hint--muted` sublabel.
- Focus ring: global `style.css:773 :focus-visible` already applies `--focus-outline` to any focused element — the `<button>` keeps its ring. No trust-rail (focus-ring) weakening.
- Layout: `.pool-action-card` is `display:flex; flex-direction:column; gap:10px` — the new button inherits correct spacing automatically.
- The now-orphaned `.pool-action-protocol-link` rules may be left in place (dead CSS, not in scope) OR removed; prefer removing them if trivially safe, else leave a note.

## Territory notes
- Two entry paths to pool-detail (url_direct `/?pool=`, card_click) both render this same component — one change covers both.
- `protocolUrlWithRef` guards the render; when a pool has no protocol URL the CTA (and its sublabel) don't render at all — unchanged.

## Acceptance verification
- Rendered Playwright on the real UI (build.md UX rule / standing decision 2026-07-11): load a pool-detail view, assert the protocol CTA has class `cta-button-protocol`, is visible, is visually distinct from the primary (different background), retains the ↗ and the "Opens protocol • Wallet required" sublabel, and that clicking it invokes the `protocol_link` tracking path. Browser-originated external HTTPS is proxy-blocked (2026-07-12) → use the established fixture-routing pattern; assert render + click wiring, not the live protocol navigation.
