> at **224 tracked lines** (`audit-app.js` alone is 195/3) against NORTH_STAR's 150-line LOW cap and failed

## The goal in one sentence

Two Korean strings were never translated, and — more importantly — nothing in the repo was capable of
noticing, so this translates them and adds the check that was missing.

## The intuition

`translations.js` holds 543 keys per language. Ask "is our Korean complete?" and the obvious check is
**key parity**: does every EN key have a KO counterpart? Run it and the answer is a clean 543/543, zero
missing in either direction. That is a true negative, and it is exactly what kept the real defect invisible
— because two of those KO "counterparts" were the English string, copied verbatim:

- `ko.landing.footerPoweredBy` = `"Powered by"`
- `ko.landing.footerMadeWith` = `". Made with AI & Degen Love."`

Parity asks *does a value exist*. Nothing asked *is the value translated*. `landing.js:357-361` composes
those two around the DefiLlama link, so the Korean landing page closed with an English sentence — reached
without anyone typing `?lang=ko`, because `detectLanguage()` (`landing.js:47-55`) auto-selects Korean from
`navigator.language`.

### Why no existing check could see it

Three i18n tests already existed, and each was specced from the last i18n bug someone had been bitten by:

- `test_ko_pool_money_honesty.js` — KO **currency units** (item 137's `원`-on-USD bug)
- `test_i18n_pages.js` — page **wiring** (does the KO page get KO copy plumbed in)
- `test_translations_fallback.js` — behaviour when a key is **absent**

None of them asserts that a KO value *differs from its EN value*. This is item 175's thesis on its Nth
instance: **a checker's signal set is drawn from the last bug someone was bitten by, so the next bug lives
in whatever class nobody has been bitten by yet.** The fix for that is not another test for this specific
string — it is a signal for the class.

## What changed, in reading order

### 1. `translations.js` — the repair (KO only, EN byte-unchanged)

- `footerPoweredBy: "데이터 제공:"`
- `footerMadeWith: ". AI와 디젠의 애정으로 만들었어요."`

These are deliberately **not** a word-for-word split of the English. `landing.js` renders
`[powered] + ' ' + <a>DefiLlama API</a> + [madeWith]`, so the two halves have to read correctly *with the
link text sitting between them*. Rendered and read back by Playwright:

> 데이터 제공: **DefiLlama API**. AI와 디젠의 애정으로 만들었어요.

The 요-polite register matches the neighbouring KO landing copy (`gardenBody`, `gardenNote`).

### 2. `translations.min.js` — regenerated via `npm run minify`

`home.html:180` loads the **minified** asset. Editing the source alone would have shipped the fix nowhere —
item 061's documented lesson, where exactly that mistake made a copy change invisible in production. The
verifier reproduced the minified output byte-identically from the build step, confirming it is not a
hand-edit (a hand-edited generated asset would be a NEVER-list issue, not merely HIGH).

### 3. `audit-app.js` — the gate (the bulk of the diff)

A new `prescanI18n()` family, modelled on the text-surface prescan (backlog 160) but **separate** from it:
`translations.js` is a dictionary, and the text family's APY/TVL regexes have no business scanning it.
Pure `fs` + `require`, no render, no network, never throws — an unloadable or malformed dictionary emits one
stderr note and returns the unrun shape, exactly like `prescanTextSurfaces()`'s unreadable-file path.

One signal, `en-ko-parity` (P1), asserting both halves:

1. **Key parity** — flattened EN and KO key sets must be identical; both directions reported.
2. **Value honesty** — a KO leaf byte-identical to its EN counterpart **and** containing no Hangul
   (`/[가-힣ᄀ-ᇿ㄰-㆏]/`) is a finding, unless its exact key path is on `I18N_IDENTICAL_ALLOWLIST`.

Non-string leaves (153 of the 543 keys are function-valued interpolators) get parity checking only — you
cannot byte-compare a function, and pretending otherwise would produce noise.

**The allowlist is the load-bearing decision**, so it is data, not a loosened predicate: 24 keys that are
genuinely identical in Korean — acronyms (`APY`, `TVL`, `RWA`, `LP/DEX`) and brand names (`Netflix`,
`Spotify`, `Claude Pro`, `ChatGPT Plus`, `Apple TV+`, `Uber One`, `DoorDash`, `Audible`, `Walmart+`,
`Peacock`, `Hulu`, `Max`, `Leviathan News`, `DefiLlama API`) — each with a one-line reason in the source.
Adding a real brand string later is a one-line diff. Adding a *non-brand* string to silence a finding is the
documented failure mode this gate exists to prevent, and spec 190's decision rule makes it a
revert-candidate signal.

Wiring, mirroring the text pass exactly: computed before the browser launches; kill switch
`opts.i18n` / `AUDIT_I18N=0` (documented in the file's env-knob header block); `opts.only` filtering; its own
`surfacesCovered` entry; **one aggregate finding** with ≤10 example keys, never one finding per key; and
`result.i18n = { scanned, suspectCount, bySignal, allowlistSize }`.

`allowlistSize` is reported **even when `suspectCount` is 0**. That is not decoration: a gate reporting
"clean" and a gate reporting "everything suspicious has been allowlisted into silence" look identical from
the outside unless the allowlist size is on the record next to the zero.

Live, today: `{ scanned: 543, suspectCount: 0, bySignal: { 'en-ko-parity': 0 }, allowlistSize: 24 }`.

### 4. The tests

`test_audit_i18n_parity.js` (13 assertions) carries the item's actual point — the **positive control**: a
fixture dictionary injected through `prescanI18n({ dict })` with (a) a KO key missing and (b) a
non-allowlisted KO value byte-identical to EN, asserting the signal reports **both**. A filter that has only
ever returned zero is not evidence of health (LEARNINGS 2026-07-27, takeaway 2). It also proves the allowlist
matches exact key paths only — an allowlisted `planner.goalMax` does not silence `planner.goalMaxPlus` — and
does not swallow a real finding sitting beside allowlisted ones.

`test_ko_landing_footer.js` (Playwright, PORT 8867, modelled on `test_footer_hub_links.js`'s rig) proves the
copy fix in the **rendered product**, per the 2026-07-11 standing decision that unit fixtures alone are a
FAIL for UX items: on `/?lang=ko` the footer paragraph contains Hangul, the `DefiLlama API` anchor renders
inline with non-empty Korean on both sides, neither English half survives, the paragraph equals the exact
expected sentence, and there are zero non-ignorable page errors. Control: `/?lang=en` is unchanged. Because
that route reads `translations.min.js`, this test also proves the minify regen landed.

## Two of the spec's own numbers were wrong

Both were re-measured before building, and both corrections were independently reproduced by the verifier:

1. **Blast radius.** The spec claimed `landing.js` backs 2,113 `tokens/*.html` + 88 `chains/*.html` = 2,201
   pages. Those pages do not load `landing.js` at all (`grep -o 'src="[^"]*"' tokens/usdc.html` → only
   `analytics.js`); `home.html:204` is its sole loader. The surface is the bare `/` landing route — the
   product's default entry, still auto-KO for Korean browsers, but one route, not 2,201 pages. The defect is
   real; the scale claim was inflated. Consequence: the spec's rendered criterion named a `tokens/*.html`
   lander, a page that never renders this footer, so it was re-aimed at `/?lang=ko` — a **stronger** check
   (it exercises the real `home.html` + `translations.min.js` boot path), not a relaxed one.
2. **Allowlist size: 24, not 8.** The spec counted 10 zero-Hangul KO values; the real count is 26 — the same
   2 prose defects plus 24 legitimate brand/acronym values. Shipping with the spec's 8 would have produced
   16 false findings on a clean dictionary on day one, which is the reliable way to make a new gate ignored.

Neither correction changes the architecture, so the build proceeded rather than blocking; both are recorded
in the spec's Territory notes and `190-notes.md`.

superstring keys, case variants) without success.
