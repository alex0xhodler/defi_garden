# Spec 062: Waitlist entry point on the static SEO pages (token + chain)

## North-star alignment
North star (2026-07-12) = `waitlist_submitted` (the card funnel). The 2,131 `/tokens/<slug>` + `/chains/<slug>` SEO pages are the traffic engine but have ZERO path to the waitlist today (they link only to `?token=`/`?pool=`). This is the missing SEO → north-star bridge.

## Hypothesis
Adding one honest, on-brand waitlist CTA to every generated token/chain page converts a share of SEO landers into the card funnel. Confidence: supported — it's a new entry point where there was none; measurable via `waitlist_opened(source=seo_token|seo_chain) → waitlist_submitted`.

## Change
1. `generate-token-pages.js` + `generate-chain-pages.js`: add ONE waitlist CTA block per page — honest card pitch (e.g. "A card that spends your <TOKEN> *yield*, not your <TOKEN>. Join the waitlist →"), on-brand neumorphic tokens, no hype, EN + KO. Copy via translations.js pattern (generators already emit EN+KO for 050).
2. CTA deep-links into the waitlist: `plan.html?waitlist=1&src=seo_token` (define one param). Small `planner.js` addition: honor `?waitlist=1` on load → open the waitlist modal, and pass `src` into `trackWaitlistOpened({ source })`.
3. Trust rails: honest framing only; the pitch never overstates yield; anomaly/floor untouched.

## Acceptance criteria (experiment discipline)
- [ ] Hypothesis → change → metric → 14d → decision rule present (below)
- [ ] Every generated token/chain page renders one waitlist CTA (grep), on-brand tokens-only, EN+KO
- [ ] `plan.html?waitlist=1` opens the waitlist; `trackWaitlistOpened` fires with `source` (Playwright)
- [ ] No trust-rail/ranking change; test chain + test_smoke exit 0
- Metric: `waitlist_opened(source=seo_*)` and its `→ waitlist_submitted` rate. Window 14d. Decision: keep if it produces ≥30 seo-sourced opens with a non-trivial submit rate; else iterate copy/placement.

## Risk tier
HIGH — SEO-surface generators + planner.js (waitlist open path). Verify both router paths.
