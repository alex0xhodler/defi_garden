# Spec 009 — Instrument the waitlist funnel

**Risk tier: LOW** (per spec 009's own tier and NORTH_STAR policy — pure analytics
instrumentation, no UI/copy/CSS/translations changes; no quiz per LOW-tier policy).

## Goal / what changed

The "Join the waitlist →" CTA and its Formspree submission were invisible in Mixpanel: clicking
the button only flipped local React state, and the signup POST fired no event on success or
failure, so the one call-to-action the checkout column optimizes for couldn't be measured. This
item adds two wrapper events to `analytics.js` — `trackWaitlistOpened` and
`trackWaitlistSubmitted`, matching `trackPlanCreated`'s existing shape exactly — and wires them
into `planner.js` at the points where they belong: both `setWaitlistOpen(true)` call sites
(`waitlist_opened`, properties `goal`/`persona`/`archetype`) and all three resolution branches of
`submitWaitlist()`'s Formspree `fetch` (`waitlist_submitted`, same properties plus
`success: true|false`). No UI, copy, CSS, or translation changes; diff is +32/-0 lines across the
two files; full test suite (`test_planner.js`, `test_protocol_parsing.js`, `test_qualifier_fix.js`)
exits 0. One notable pre-existing finding, not introduced by this change: of the two
`waitlist_opened` call sites, only one (`checkoutPanelElement`'s button) is actually reachable in
the current render tree — the other (`ctaElement`) is dead code that predates this item (full
trace in `009-notes.md`). It's instrumented anyway per the spec's "instrument each" instruction,
since doing so is zero-risk and future-proofs the code if it's ever wired back in, but it won't
fire in production today.
