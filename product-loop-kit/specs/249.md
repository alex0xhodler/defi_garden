# Spec 249: the `en-ko-parity` gate cannot see 153 of 544 translation keys — every function-valued leaf, which is where the planner's Korean lives

## Evidence

`audit-app.js:1071` — the value-honesty rule, verbatim:

```js
if (typeof enVal !== 'string' || typeof koVal !== 'string') continue; // function/array/number leaves: parity only
```

So Rule 2 (is the KO leaf actually Korean?) runs on string leaves only. Function leaves get Rule 1 —
**key existence in both namespaces** — and nothing else.

Population measured this tick against the live dictionary (`require('./translations.js')`, recursive
flatten, `typeof === 'function'`):

| | count | share of 544 |
|---|---|---|
| string leaves — value-checked | **391** | 71.9% |
| **function leaves — existence-checked ONLY** | **153** | **28.1%** |

The blind region is not peripheral. It is where the product's narrative copy lives: **~80 of the 153 are
`planner.*`** — `bloomHeadline`, `heroTarget`, `heroTargetFlip`, `subHeroWin`, `shareTweet`,
`comparisonMoneyGone`, `planConfidenceSteady`, `degenHaircutNote`, … — i.e. the **default surface for the
ICP** (NORTH_STAR: the planner is the bare-`/` product; the cautious retail saver is the audience), plus the
entire `tcp*` family that renders the generated token/chain SEO estate.

**How the gap surfaced:** item 225's merge added 5 keys in both namespaces; 3 of the 5 have byte-identical
EN/KO values. The gate caught the two string ones (`resultsColApy`, `resultsColTvl` → item **248**) and was
structurally unable to see the third:

```js
onProtocolChain: (protocol, chain) => `${protocol} · ${chain}`   // identical source in en AND ko
```

**The blind region is CLEAN today — measured, with the number, before scoring.** Two independent passes over
all 153:
- **EN/KO source byte-identical:** **2 of 153 (1.3%)** — `onProtocolChain`, `poolPageTitle`. Neither carries
  Latin prose in its literal text (both are pure interpolation + punctuation), so neither is untranslated copy.
- **The gate's OWN predicate applied to KO function bodies** (strip the parameter list, strip `${…}`
  interpolations, then: no Hangul AND ≥1 Latin letter): **1 suspect of 153**, `poolPageTitle` —
  `` (symbol, project) => `${symbol} (${project}) | DeFi Garden 🌱` `` — whose only Latin content is the
  **brand name**, exactly what the allowlist exists for.

So: **zero live untranslated-copy defects behind the blind spot right now.** This item is a coverage/latent
fix, and is scored as one. It is filed because the gate cannot demonstrate that result on its own — the
measurement above was done by hand, this tick, and nothing re-runs it.

## Hypothesis

We believe extending Rule 2 to function leaves — by evaluating the KO function's literal text (source with
the parameter list and `${…}` interpolations stripped) under the same no-Hangul-AND-has-Latin predicate —
will bring 153 keys (28.1% of the dictionary) under the gate that guards them, because the defect class the
gate exists to catch (stale/untranslated English shipped as Korean) is entirely indifferent to whether the
value is a string or a template function. Confidence: **supported as a coverage claim** (the blind fraction
is measured, not estimated); **guess** as to when it pays off — no live defect exists today, so the payoff
is in futures where planner or `tcp*` KO copy is added or reworded, which is the direction the product is
actively moving (247's design work, 236/237/238/246 all touch these surfaces).

- **Instance of:** *"no check narrower than the class it guards"* (RAZOR side 2). Two precedents, same gate
  and same shape: **item 198** — "190's i18n gate implements half of its own playbook predicate; an
  untranslated KO string one space away from its EN twin passes clean" (predicate too narrow, fixed by
  keying on the KO value alone); **item 212** — "a guard watching a mechanism that RESEMBLES the real one is
  strictly worse than no guard — it launders the gap as coverage." This is the **third** narrowing found in
  this gate's predicate, and the first found in its *type* coverage rather than its logic.
- **Class closed by this item:** **partially, and the residual is numbered.** Function leaves are the whole
  of the non-string population **today** (391 string + 153 function = 544, no array/number leaves exist in
  the current dictionary — verified). If a future leaf type appears (array of strings, nested plural table),
  the `typeof !== 'string'` skip catches it again. The weakest form — *every leaf the dictionary can hold is
  value-checked, whatever its type* — should be the predicate written, not `typeof === 'function'`.

## Change

Smallest version that tests the hypothesis, in `prescanI18n()` (`audit-app.js` ~`:1068-1078`):

1. Replace the `typeof !== 'string'` skip with a **normalising extractor** that returns the comparable
   literal text of any leaf type: strings return themselves; functions return
   `fn.toString()` with the leading parameter list removed and every `${…}` span removed; anything else
   returns `null` and is skipped **with its count reported**, so a future unhandled type is visible rather
   than silent.
2. Run the existing, unchanged Rule 2 predicate (no-Hangul AND has-Latin AND not allowlisted) over that
   extracted text.
3. Add `poolPageTitle` to `I18N_UNTRANSLATED_ALLOWLIST` with reason `'brand name (DeFi Garden)'` — the one
   suspect the widened gate legitimately surfaces (measured above). Do **not** pre-emptively allowlist
   anything else; if the widened gate finds more than the one predicted suspect, that is a **finding to
   report, not to silence** — stop and record it in `specs/249-notes.md`.

**Explicitly OUT of scope:** changing any value in `translations.js`; the allowlist's exact-key-path matching
rule (item 248's Open question); item 248's two acronym entries (land independently — this item must not
depend on them, and must not re-fix them).

## Acceptance criteria

- [ ] `prescanI18n()` value-checks **all 544** keys. Assert the counts are **derived at run time from the
      dictionary** (flatten + `typeof`), never hand-typed: `stringLeaves + functionLeaves === scanned`, and
      `functionLeaves === 153` is asserted as *"> 0 and equal to the live count"*, not as a frozen literal —
      the dictionary grows every week and a pinned 153 re-breaks on the next copy change.
- [ ] The extractor is proven on both shapes: a fixture function leaf whose literal text is Korean passes;
      one whose literal text is English is flagged; one that is pure interpolation
      (`` (a,b) => `${a} · ${b}` ``) is **not** flagged (no Latin letter survives extraction).
- [ ] Unhandled leaf types are **counted and surfaced** in the prescan result (e.g. `skippedLeafTypes`),
      not silently `continue`d. Assert this count is 0 against today's dictionary.
- [ ] After the change, a full run reports `i18n.suspectCount === 0` with `allowlistSize` = 25 (this item's
      `poolPageTitle`) — or 27 if 248 has already landed. State which in `specs/249-notes.md`.
- [ ] Tests: `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` green;
      the new assertions live in the repo's existing i18n test file if one exists (grep first — do not
      create a second home for i18n assertions).
- [ ] **Non-vacuity — this is the criterion that matters most here, because the item's whole claim is that a
      green gate was not evidence.** Prove the widened gate can go red on a FUNCTION leaf specifically:
      temporarily replace a `planner.*` KO function's literal text with its English twin → the gate names
      that key; restore → byte-identical file (`md5sum` recorded before and after) and `suspectCount` returns
      to its baseline. A red demonstrated only on a *string* leaf does **not** satisfy this — that path
      already worked before the change.
- [ ] **Population:** assertions draw from the full flattened dictionary at test time. `onProtocolChain` and
      `poolPageTitle` may be used ONLY as positive/negative controls, never as the population.

## Measurement

Metric: the count of value-checked keys in `signals/audit-findings.json`'s i18n block (**391 → 544**), and
`skippedLeafTypes === 0` · **Build-leg (calendar) verification only** — a checker-coverage change, not a
growth experiment; no traffic gate applies. Decision rule: keep if the next two ticks report
`scanned === valueChecked` with `suspectCount === 0`; revert-candidate if the widened gate produces suspects
that turn out to be extraction artefacts (e.g. Latin leaking out of a `${…}` span the stripper missed) rather
than real copy — that would mean the extractor, not the dictionary, is wrong.

## Open questions

None blocking. Recorded: `flattenI18nDict`'s own comment (`audit-app.js:988-992`) already names function

explanatory comment reads as a considered decision and is therefore *less* likely to be revisited than an
undocumented one.
