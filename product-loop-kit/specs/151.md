# Spec 151: PT family and parent-asset search

Impact: defect-count 2→0 on the analytics search surface.

## Evidence

- `availableTokens` splits pool symbols on separators, so `PT-SUSDAI-<expiry>` becomes independent `PT`, `SUSDAI`, and expiry tokens.
- A bare `PT` query can bind to the `PT` token and `symbolMatchesToken` can already return the whole PT family.
- `PT-SUSDAI` cannot bind as a parent asset because that compound is absent from `availableTokens`; generic substring fallback can choose `PT`, widening the result to every PT pool.
- The compact form `ptsusdai` has the same ambiguity.
- Current DefiLlama data has no YT symbols. The YT half remains deferred; this change must not invent a source.

## Change

1. Recognize exact PT parent-asset queries in hyphenated and compact forms before generic token scoring.
2. Validate the underlying against the available token inventory, then return the canonical `PT-<UNDERLYING>` token filter.
3. Keep bare `PT` unchanged so it returns every PT symbol.
4. Reuse the existing token-first filter and trust rails; do not add a second pool-filter path.
5. Register one rendered browser regression test and regenerate minified app assets.

## Acceptance

- Typing `PT` and pressing Enter renders every fixture pool whose symbol belongs to the PT family, and no unrelated pool.
- Typing `PT-SUSDAI` renders every dated `PT-SUSDAI-*` variant and excludes other PT assets.
- Typing `ptsusdai` produces the same result as the hyphenated query.
- Unknown `PT-<asset>` queries do not fabricate a token match.
- Existing natural-language token, chain, protocol, and category parsing remains green.
- Rendered checks run at desktop and 360px with zero non-ignorable page errors.

## Measurement

Build leg only. Keep if the rendered regression remains green for two ticks.

## Risk

HIGH — changes parsing on the primary analytics search path. Pool eligibility and trust rails are unchanged.

## Open questions

None for the PT half. YT remains deferred pending a human-selected data source.
