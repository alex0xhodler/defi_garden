# Spec 256: the audit asserts the honest empty state EXISTS, never that it says anything — so a rendered raw translation key scores clean

## Evidence

- `audit-app.js:3697`, the entire `dead-pool` positive check:
  ```js

  if (!ok) findings.push(finding(s.name, s.vpLabel, 'dead-pool-empty-state', 'P1', …
  ```

  A presence-only selector wait. The element's text is never read.
- Item **253** is live on `main` at HEAD (`7ab2994aff`): `grep -c "poolNotFoundTitle:" translations.js` → **0**,
  `translations.js:1546` returns the key string on a double miss, and `app.js:3558` renders it as the
  `.empty-state .empty-message` heading of the dead-`?pool=` state.
- The audit run of **2026-08-09T07:16:46Z** (83 surfaces, exit 1) reports **`dead-pool-empty-state` ABSENT**
  while the defect is present — because `.empty-message` *does* render, populated with the literal string
  `poolNotFoundTitle`, so the selector resolves and the check passes.
- The 2026-08-08 run *did* fire the finding, with detail `"dead ?pool= id did not resolve to the honest empty
  state within 10s"` — a `waitForSelector` **timeout**, i.e. a slow render, not a detection of this defect.
- Two instruments actually witness item 253: `node test_dead_pool.js` (exit **1**, 2 of 12 assertions fail,
  prints `EN: "undefined", KO: "undefined"` — it asserts the title TEXT) and loading the dictionary. The

## Hypothesis

We believe making the audit assert **rendered content**, not element presence, will convert a class of
silently-vacuous passes into findings, because a missing translation key produces a perfectly well-formed DOM
whose text is the key's own name — the exact shape every presence-based check is blind to.
Confidence: **validated-pattern** (extension is the argument, not conviction: it pays off under every future
in which any key is deleted, renamed, or typo'd in either namespace, on any surface, by any author — not only
under the future where `poolNotFoundTitle` specifically is missing).

- **Instance of:** checks whose predicate is narrower than the class they guard. Population: every
  `waitForSelector`-shaped assertion in `audit-app.js`. Fifth in this family — precedents **190** (shipped half
  its conjunction), **198** (fixed the predicate), **212** (guard watching a resembling mechanism), **249**
  (blind to 28.1% of leaves by value type). Named in `playbooks/detector-signal-coverage.md`.
- **Class closed by this item: no.** This closes the *rendered* leg. The *source* leg — a key deleted or
  duplicated in `translations.js` at all — is item **255**, and 255 remains the pre-merge gate: it would have
  caught 253 before `6fceca79bb` landed, where this item catches it after. The two overlap deliberately and
  neither subsumes the other: 255 cannot see a key that is present in the dictionary but never rendered
  correctly, and 256 cannot see a key on a surface the rotation did not visit that tick.

## Change

Smallest version that tests the hypothesis:

1. In `audit-app.js`, extend the `dead-pool` check to read `.empty-state .empty-message`'s `textContent` and
   emit a finding when the text is a **raw translation key**.
2. Make the predicate general rather than a `poolNotFoundTitle` literal: build the key-name set once from the
   parsed dictionary (both namespaces, all nesting levels — the same walk `en-ko-parity` already performs at
   `audit-app.js:~1071`), and flag any rendered text that **exactly equals** a member of that set after trim.
   Register it as its own signal (suggested `i18n:raw-key-rendered`, severity **P1**) so it is reported by
   name rather than folded into `dead-pool-empty-state`.
3. Run that predicate over the text the audit **already collects** on every surface it visits, not only the
   dead-pool heading. No new page visits, no new rotation cost.
4. Keep the existing presence check and its `dead-pool-empty-state` finding unchanged — a timeout is still a
   real (different) failure. This item **adds** a signal; it does not replace one.

**Explicitly OUT of scope:** fixing item 253 (restoring the two strings) — that is 253's own item, and this
item's non-vacuity control depends on the defect still being reproducible from git history either way.
Also out of scope: source-level dictionary integrity (item **255**), the function-leaf blind spot (item
**249**), and any change to `translations.js`.

### 2026-08-10 (build loop, measured — this changed the design)

The first implementation derived the key-name population **from the parsed dictionary alone**, exactly as the
spec's Change §2 reads. A real rendered run proved that population is blind to the defect this item was
written about:

1. `poolNotFoundTitle` deleted from BOTH namespaces of `translations.js` **and** from `translations.min.js`
   (which is what `home.html:201` actually loads) — item 253's exact shape.
2. Playwright on the dead-pool surface: `.empty-state .empty-message` textContent === `"poolNotFoundTitle"`.
   The raw key is unambiguously on screen.
3. `node audit-app.js --only=dead-pool` with that tree: **`findings: []`**. Zero. The new gate did not fire.

Why: `app.js:3587` still calls `t('poolNotFoundTitle')`, but the moment the key leaves the dictionary its NAME
leaves a dictionary-derived population — the population shrinks exactly when the defect appears. That is the
same shape as this item's own precedent list (190/198/212/249), one level further in.

The dictionary leg alone covers only: an emptied/falsy value, and a namespace miss where the key still exists
somewhere in the dictionary. It does NOT cover a key deleted or renamed away entirely, which is the single
most likely way this defect reaches production and is what actually happened in 253.

**Design consequence, built:** the population is the UNION of two run-time-derived legs — (A) every key name in
the parsed dictionary (both namespaces, dotted path + bare leaf), and (B) every key-name literal referenced at
a `t('…')`/`rootT(…, '…')` call site in the product sources the audited shells actually load (file list derived
by parsing `home.html`/`plan.html` for local `<script src>`, mapping `.min`/`.compiled` artifacts back to their
sources). Leg B is what survives the key being deleted, and it is derived from the mechanism that renders the
miss, not from a resemblance of it.

**Residual blind spots, stated with their shape rather than implied away:** a computed or interpolated key at a
call site (`t(someVar)`) is in neither leg; and exact-LINE matching means an inline raw key sharing a line with
other prose is not flagged — deliberate, because presence-over-precision is the failure mode this item exists
to correct, so the predicate stays conservative in the other direction.
