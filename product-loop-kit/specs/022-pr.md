# 022 — PR explainer (HIGH tier): IndexNow ping for freshly generated token pages

## Goal
021 made `/tokens/<slug>` real — 2,028 pages, regenerated and committed daily by CI. Bing and Yandex still only learn about new/changed URLs by re-crawling `sitemap.xml` on their own schedule. IndexNow is the protocol both document for "notify me the instant a URL changes" — a single POST with an explicit URL list, authenticated by a key file hosted on the domain. This wires that in as one more step in the same CI job that already regenerates and pings for the sitemap.

## Why CI, not the loop or this session
`api.indexnow.org` is unreachable from this sandbox (`curl` → 403 CONNECT tunnel failure), the same class of block `yields.llama.fi` hit for 021/013/018. GitHub Actions already runs `sitemap-update.yml` daily with real network access and already does the "ping search engines" step (Google/Bing's legacy `/ping?sitemap=`) right before where this new step lands. Real submission can only be confirmed by a human watching that job's log after a future run.

## What changed (reading order)
1. **`fa81c8f43e7870a3b48e7481b2b7c8df.txt`** (new, repo root) — the IndexNow ownership-proof key file. IndexNow's convention: a file named `<key>.txt` containing exactly `<key>`, served at `https://www.defi.garden/<key>.txt`. Generated once via `crypto.randomBytes(16).toString('hex')`; no `vercel.json` rewrite touches arbitrary root `.txt` files, so Vercel's default static handling serves it as-is.
2. **`indexnow-ping.js`** (new) — mirrors `generate-token-pages.js`'s CLI/module pattern:
   - `findKeyFile`/`loadKey` — locates the committed `<hex>.txt` at the repo root and reads the key from it at runtime. This is the one design choice worth calling out: the key is **never** duplicated as a literal string inside the script. If the key file's content and its filename ever disagreed, every future submission would silently authenticate with the wrong value — reading from the file at runtime makes that impossible.
   - `extractLocs`/`collectUrls` — parses `<loc>` entries out of sitemap XML with the same lightweight regex approach already used elsewhere in this codebase (no new XML-parsing dependency), dedupes, and caps at IndexNow's documented 10,000-URL-per-submission limit (current count: 2,028, well under it — the cap is a safety rail for whenever that grows, not a limitation being hit today).
   - `buildIndexNowPayload` — pure function, returns exactly `{host, key, keyLocation, urlList}` per IndexNow's API spec. No I/O.
   - `submitToIndexNow` — the only network call in the file (`https.request` POST to `https://api.indexnow.org/indexnow`).
   - `main()` — reads the key, collects URLs from `sitemap-token-pages.xml` (default; `--sitemap` can add more), builds the payload, and returns **before** calling `submitToIndexNow` whenever `--dry-run` is passed or the URL list is empty — so building/testing this script never makes a network call unless it's genuinely about to submit real URLs.
3. **`.github/workflows/sitemap-update.yml`** — one new step, "Ping IndexNow," placed immediately after the existing "Ping Google about sitemap update" step and before "Summary." Same `if: steps.verify-changed-files.outputs.changed == 'true'` guard as the step next to it — it only runs when the day's regen actually produced a diff.
4. **`package.json`** — `test` script chain gained `&& node test_indexnow.js` at the end.
5. **`test_indexnow.js` + `test_fixtures/sitemap-indexnow-sample.xml`** (new) — 10 assertions: payload shape, `<loc>` extraction/dedup/cap/missing-file handling, key-file discovery + exact-byte content, and two tests that monkey-patch `https.request` to throw if called, proving the dry-run/zero-URL paths never reach the network.

Nothing in `home.html`, `app.js`, `PoolDetail.js`, `planner.js`, `translations.js`, `generate-sitemap.js`, or `generate-token-pages.js` was touched — no trust rail, ranking gate, or canonical logic is in this diff's path.

## What this PR can't prove
Whether IndexNow actually accepts the submission and Bing/Yandex act on it needs a human to watch the "Update Sitemap" Action's job log after a real run (the "Ping IndexNow" step logs the HTTP status code IndexNow returns). Same residual shape as 021's "trigger the Action, eyeball `/tokens/usdc`."
