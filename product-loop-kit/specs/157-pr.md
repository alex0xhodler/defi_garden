# 157 — PR explainer: prescan the whole SEO surface, aim the render budget at the suspects

*(HIGH-tier explainer per NORTH_STAR.md risk policy — full walkthrough + quiz at the bottom.)*

## Goal

Yesterday's heartbeat ran the product-audit scanner and reported **"10 surfaces, 0 findings"** on the same day a human found item 148's live junk pages (`<h1>8OCT2026 DeFi Yields</h1>`) by tracing odd prod URLs by hand. Both statements were true. The scanner renders ~6 static SEO pages per day out of **2,176**, picked uniformly — so the chance of it landing on one of the 7 known-bad pages was about **1.3% per day**.

Item 154 built the checks (`junk-slug`, `zero-yield-claim`, `empty-table`, `number-sanity`) and proved they fire on real renders. Its own builder wrote the limitation down and named the follow-up (`specs/154-notes.md:243-248`). This is that follow-up.

## The intuition

Rendering is expensive (~10s per static page, because each one holds DOMContentLoaded waiting on a production `analytics.js` the sandbox can't reach). Reading a file is not — the full 2,176-page scan takes **~480ms**.

So: read everything cheaply, render only what looks wrong. The render budget doesn't grow; it gets *aimed*.

## What changed, in reading order

### 1. `prescanStaticPages()` — new, exported (`audit-app.js`)

Pure `fs` + regex over every `tokens/*.html` + `chains/*.html` leaf (via the existing `listLeafPages`). Per file: drop `<script>`/`<style>` blocks, capture the `<h1>`, strip remaining tags to visible text. Four signals:

| signal | severity | source of the predicate |
|---|---|---|
| `junk-slug` | P1 | **reuses** `JUNK_SLUG_NUMERIC` / `JUNK_SLUG_DATE` — the same constants the rendered check uses, not a new mirror |
| `zero-yield-claim` | P1 | **reuses** `ZERO_YIELD_CLAIM` |
| `broken-number-literal` | P0 | new — bare `NaN`/`Infinity`/`undefined`/`null` in visible text |
| `absurd-magnitude` | P0 | new — a standalone `…T`/`…Q` magnitude |

The magnitude regex is deliberately **tightened**: the obvious form (`-?\$?[0-9][0-9,.]*\s?[TQ]\b`) false-positives on `tokens/a0t.html`, because the ticker `A0T` contains the substring `0T`. Requiring the character before the digit to be start-of-string or non-alphanumeric drops that and measures **0/2,176** on this checkout. The comment in the code says not to revert it, and `test_audit_prescan.js` criterion 2 pins `a0t` specifically.

Never throws: an unreadable file is skipped with a stderr note and doesn't count toward `scanned`.

### 2. Promotion (`buildStaticSurfaces`)

Suspects are promoted into the rendered sample **ahead of** the uniform rotation, capped at `AUDIT_STATIC_PRESCAN_MAX` (default 4, clamped to the sample size), and the uniform rotation then fills only `sampleSize − promoted.length`. Promoted rels are excluded from the uniform pick lists, and the anchor's own leaf is never promoted. **The total static budget is unchanged** — this re-aims spend, it doesn't add any.

When suspects exceed the cap, `sampleBySeed(suspectRels, cap, seed + ':prescan')` picks among them, so successive days work through the backlog of suspects rather than re-rendering the same four forever. When suspects ≤ cap, every suspect is promoted — promotion is suspicion-driven, not seed-driven, which is what criterion 6 pins.

`buildStaticSurfaces()` now returns `{ surfaces, prescan, prescanFindings }` instead of a bare array; that's the one shape change, and `runAudit()` is its only caller.

### 3. Aggregate findings + result shape

One finding per signal that has ≥1 suspect — `surface: 'static-prescan'`, `check: 'static-prescan:<signal>'`, ≤10 example slugs plus the count — so a systemic defect reports as *"7 of 2176 … examples: …"* rather than 2,000 separate findings. `runAudit()`'s result gains `prescan: { scanned, suspectCount, bySignal, promoted }`.

**Intended behaviour change:** while item 148's 7 junk pages are still live (PR #306 unmerged), a default `node audit-app.js` now exits non-zero with a P1 `static-prescan:junk-slug` finding on *every* run instead of roughly 1 run in 75. That is the detector being right. It self-clears when #306 merges.

### 4. Tests — `test_audit_prescan.js` (new, wired into `npm test` after `test_seo_surface_audit.js`)

Seven cases, criteria 1–7. Two properties worth calling out:

- **Nothing is hardcoded to today's data.** The junk set churns daily and #306 may delete it, so criteria 1/2/5 re-derive the expected set from disk at runtime and compare predicate-to-predicate.
- **Criteria 3/4 are real Chromium renders**, not fixtures (standing decision 2026-07-11). A temp probe page (`tokens/_audit_probe_<pid>.html`, a copy of a real token page with a date-shaped `<h1>`) is written, rendered, and deleted in a `finally`. Criterion 3 asserts the probe is *covered and flagged*; criterion 4 asserts the identical run with `prescan: false` does **not** cover it — a uniform pick would find it with p ≈ 0.3%, so coverage can only have come from promotion.

The test sizes `prescanMax`/`staticSample` to today's live suspect count + 1 so promotion of the probe is a guarantee rather than a lucky hash, and throws a clear "test assumption broken" error if that ever exceeds `MAX_STATIC_SAMPLE`.

## Deviations from the spec (both in `157-notes.md`, both about protecting tests this item may not edit)

1. **`opts.staticOnly` defaults prescan OFF** unless the caller passes `prescan: true`. `staticOnly` is test-support-only (one caller in the repo: `test_seo_surface_audit.js`'s determinism check, which drives `staticSample: 1`). With prescan default-on there, the cap collapses to 1 and that legacy test's "a different seed picks a different page" assertion becomes ~1-in-7 flaky for reasons unrelated to what it tests. **The production path never sets `staticOnly`, so it is unaffected.**
2. **Aggregate findings honour the same `opts.only` allowlist** the rendered surfaces already honour. Without it, `test_audit_app.js`'s clean-run case — scoped away from the static rotation, asserting zero P0/P1 — would pick up the real junk-slug true positive through the back door. This scopes the finding the same way the surfaces are already scoped; it never downgrades or drops a finding on an unscoped run (the CLI default).

## What this does not do

Design A from 154-notes (persisted never-audited rotation) is still unbuilt and still ticket-worthy. Nothing here fixes a junk page — 148 owns that, and `/tokens/pt` remains bug-class 8 (flag, don't auto-fix). No generator, no SEO surface, no trust rail, no dependency was touched; `audit-app.js` remains a read-only detector.
