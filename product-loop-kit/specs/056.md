# 056 — Self-host React (react/react-dom), drop the unpkg 3rd-party critical dependency

Status: promoted from BACKLOG (score 6.0, MED) to READY on 2026-07-12, evidence-backed per this spec (no spec existed — written per build.md §1 from `product-loop-kit/reports/2026-07-12-pagespeed.md`).

## Evidence this spec is built on

`product-loop-kit/reports/2026-07-12-pagespeed.md`, finding 5 (impact-ordered): *"React/Babel from third-party unpkg (no control/cache)."* Proposed item: *"056 (6.0, MED) — Self-host React (react/react-dom) to drop the unpkg 3rd-party critical dependency."* The report's "Framing vs no build step" section explicitly sanctions this pattern: CI already commits generated/vendored artifacts (sitemaps, compiled JS, minified JS/CSS) — vendoring the React UMD build the same way is the same pattern, not a new one. Sequencing note: *"052/053/056 interact ... Sequence 052 → 053 → 056; each is independently shippable."* 052 (precompile, drop Babel) and 053 (minify) already shipped and merged — this item is next in that chain and touches only the React `<script>` tags, not the compile/minify pipeline.

Grep-confirmed against the live repo (2026-07-12):
- `home.html:139-140` — `<script defer crossorigin src="https://unpkg.com/react@18/umd/react.production.min.js">` (+ react-dom), inside the shared analytics/planner head, loaded on every page.
- `home.html:59,61` — `preconnect`/`dns-prefetch` to `unpkg.com` (added by 054), exists solely to serve this fetch.
- `plan.html:49-50,76-77` — identical unpkg React UMD `<script>` tags, plus a `<link rel="preload" ... as="script">` pair for the same two URLs (`plan.html:49-50`).
- `plan.html:51,53` — `preconnect`/`dns-prefetch` to `unpkg.com`, same purpose.
- `package.json` devDependencies already pin `"react": "^18.3.1"`, `"react-dom": "^18.3.1"` (installed for `test_search.js`'s offline Playwright route-interception, which already vendors `node_modules/react/umd/react.production.min.js` and `node_modules/react-dom/umd/react-dom.production.min.js` at test time — see `test_search.js:224-231`). Same exact files this spec commits as static assets, just now served in production instead of only intercepted in tests.
- `test_compiled_assets.js:30` asserts home.html no longer fetches `@babel/standalone` from unpkg (052) — no existing test currently asserts anything about the React unpkg tags, so no test contradicts this change; a new assertion is added per acceptance criteria below.

## Change

1. Vendor the two React 18.3.1 UMD production builds as static files at the repo root (flat structure, matching `translations.min.js`/`style.min.css`/`app.compiled.min.js` convention — no `vendor/` subdirectory):
   - `react.production.min.js` (copied from `node_modules/react/umd/react.production.min.js`)
   - `react-dom.production.min.js` (copied from `node_modules/react-dom/umd/react-dom.production.min.js`)
   These are committed, edited-by-copy-only files (same status as the other committed vendored/generated assets) — pinned to the `react`/`react-dom` devDependency version in `package.json`. A version bump means re-copying these two files, not hand-editing them.
2. `home.html`: change the two `<script defer crossorigin src="https://unpkg.com/...">` tags (lines 139-140) to `<script defer src="./react.production.min.js"></script>` / `./react-dom.production.min.js` (drop `crossorigin` — same-origin static file needs no CORS mode). Remove the now-unused `unpkg.com` `preconnect` (line 59) and `dns-prefetch` (line 61) — nothing else fetches from unpkg after 052 removed `@babel/standalone`. Keep the `yields.llama.fi` preconnect/dns-prefetch untouched (still a live 3rd-party fetch).
3. `plan.html`: same two script-tag edits, plus removing the `preload`/`preconnect`/`dns-prefetch` triplet pointing at unpkg (lines 49-53) for the same reason.
4. No change to `__APP_MODE` router logic, `ANALYTICS_PARAMS`, script load order (React still loads before `translations.min.js`/`planner.min.js`/analytics-app scripts — same `defer` position, browsers execute deferred scripts in document order regardless of same- vs cross-origin), or any compile/minify pipeline. This is a source-swap of two `<script src>` values plus their now-dead resource hints, in two files.
5. `.github/workflows/sitemap-update.yml`: no change needed — these two files are static vendored assets that don't change per-run (unlike sitemap/tokens/chains/compiled output), so they don't belong in the CI-regenerated commit list; they're committed directly in this PR like `translations.min.js`/`style.min.css` were when 053 shipped.

## Acceptance criteria

1. `home.html` and `plan.html` load React and ReactDOM from local `./react.production.min.js` / `./react-dom.production.min.js`, not `unpkg.com` (grep both files for `unpkg` — zero matches after the change; `@babel/standalone`-related comments referencing 052's history are prose, not fetches, and are unaffected).
2. `react.production.min.js` and `react-dom.production.min.js` exist at the repo root, byte-identical to `node_modules/react/umd/react.production.min.js` and `node_modules/react-dom/umd/react-dom.production.min.js` (React 18.3.1, matching `package.json`'s pinned devDependency version).
3. The unpkg `preconnect`/`dns-prefetch`/`preload` hints tied only to the React fetch are removed from both files; the `yields.llama.fi` hints are untouched.
4. `__APP_MODE` router block and `ANALYTICS_PARAMS` byte-identical (diff must not touch them).
5. `test_smoke.js` (Playwright, both sacred router paths: bare `/` → planner renders, `?token=USDC` → analytics app renders pool cards) passes with zero new console/page errors, with `unpkg.com` requests blocked/unrouted in the test (proving the app no longer depends on it — the opposite of `test_search.js`'s current network-degraded fallback, which intercepts unpkg URLs and can stay as a defense-in-depth fallback for other unpkg-dependent code paths if any remain, or be simplified since local files now load directly without interception).
6. `npm test` (full chain per `package.json`) still green.
7. Diff stays surgical: two new committed binary/text assets + script-tag/resource-hint edits only in `home.html` and `plan.html`. No compile/minify script changes, no CI workflow changes, no other file touched.

## Risk tier

HIGH — per NORTH_STAR.md's risk policy, `home.html` is the sacred IA router file and this touches its render-critical script loading (React must still load and mount correctly on every analytics/SEO page and the planner). `plan.html` is the planner's dedicated entry shell serving the default `/` experience. Both are render-path changes; verify `__APP_MODE`/`ANALYTICS_PARAMS` are byte-identical and both router paths (`test_smoke.js`) still render. Per the standing note ("Until 003 ships, any render-path merge gets flagged needs human visual spot-check") — 003 (npm-test smoke gate) has since shipped and `test_smoke.js` is part of `npm test`, but this PR should still flag a human visual spot-check given it changes the actual JS runtime source for every page (unpkg CDN → local file) — a mistake here (stale/corrupt vendored file, wrong load order) breaks every page, not just SEO metadata.

## Territory notes

`test_search.js` already proves the exact two files (`node_modules/react/umd/react.production.min.js`, `node_modules/react-dom/umd/react-dom.production.min.js`) work correctly as a same-origin-served substitute for the unpkg URLs — it's been route-intercepting them for offline test runs since before this spec. This item makes that substitution real (production-served) rather than test-only. No new territory: the files, their content, and their behavior as drop-in UMD replacements are already validated by every existing offline test run.
