# 090 — Analytics default view → list/rows (not grid/boxes)

Status: READY → this loop. Risk: LOW. Score: 7.0.
Spec written by the picking loop 2026-07-14 from documented evidence (BACKLOG row 090,
the human's 2026-07-14 Analytics-UX audit) — no prior spec file existed.

## Evidence / rationale (human 2026-07-14 audit)
The analytics browse defaults to a grid of boxes (`app.js:758` `useState('grid')`). SOTA
yield tables are row-first: denser scan, aligned numbers, less scroll — the read the cautious
ICP does first. The list path already exists and is fully styled (`app.js:2904` renders
`viewMode === 'list' ? 'pools-list' : 'pools-grid'`; `.pools-list` CSS at `style.css:1957+`),
reached today only by the ☰ toggle. This item makes list the DEFAULT.

## What (smallest change)
- Flip the default: `app.js:758` `useState('grid')` → `useState('list')`. That is the entire
  product change — `viewMode` is component state only (not persisted to localStorage or a URL
  param, grep-confirmed), and both views render the SAME `renderPoolCard` (only the container
  class differs), so no data/render path changes, only the CSS layout the user sees first.
- Regenerate the compiled + minified artifacts the HTML actually loads: `node compile-app.js`
  then `node minify-assets.js` (app.compiled.js / app.compiled.min.js embed the default).
- Keep the grid/list toggle fully working (both buttons, both directions).

## Non-goals (explicitly out of scope)
- Row-level table polish (column alignment, tabular-nums, right-aligned numerics, calmer 0%
  styling) = item 095 (soft-pairs with this). 090 ships the default flip; 095 polishes the rows.
- No sort-default change (that's 089/092). No new CSS classes, no new components.

## Trust rails / guardrails (binding)
- The parameterized analytics URLs remain sacred: `/?token=`, `/?chain=`, `/?pool=` must still
  render pool cards — list view renders the SAME cards, just in a row container, so the SEO
  lifeline is preserved. Verify both.
- No translations change (the toggle titles are pre-existing; no new user-facing strings).
- Neumorphic design system only; reuse the existing `.pools-list` styling (no new visual
  elements) — per the 2026-07-10 reuse-before-inventing standing decision.

## Acceptance criteria (UX item → rendered Playwright on the real UI, per 2026-07-11 standing decision)
1. On `/?token=USDC`, with NO prior interaction, the pools container renders with class
   `pools-list` by default (NOT `pools-grid`), and at least one `.pool-card` renders inside it.
2. The ☰/▦ toggle still works both ways: clicking ▦ (grid) switches the container to
   `pools-grid`; clicking ☰ returns it to `pools-list`.
3. `/?chain=<chain>` (chain mode) also defaults to the list container and renders pool cards.
4. The bare `/` planner is unaffected (router path unchanged; planner does not use `viewMode`).
5. No new page/console errors introduced (fixture-routed browser per the 2026-07-12 sandbox
   network note; snapshot route stale-stubbed like the other suites so the fixture is used).
6. Renders without layout breakage at 360 / 768 / 1280 widths and in dark mode (spot-check;
   deep row polish is 095).
7. Compiled/minified artifacts regenerated and consistent (the loaded files carry the new
   default) — asserted via the existing compiled/minified-asset test pattern if cheap.

## Measurement
No isolated Mixpanel funnel metric (a default-layout change on the analytics browse, not a
funnel step). Guardrails watched: `error_occurred` rate unchanged; `?token=/?chain=/?pool=`
keep rendering pool cards (SEO lifeline). Human visual spot-check advisable (render-path
default flip) until the 003 smoke gate covers list-default.
