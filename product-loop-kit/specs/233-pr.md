## The goal

Item 231 fixed one detector. This fixes the one standing next to it, and answers a question 231
deliberately left open rather than guessing at.

`audit-app.js` is the product-audit scanner — the loop's own eyes. It drives ~83 rendered surfaces per
tick and reports what looks broken. Two of its lenses read **geometry**: `checkOcclusion` (is something
covering something else?) and `checkResponsive` (does the primary CTA fit inside the viewport, and does
the page scroll sideways?).

231 discovered that `checkOcclusion` measured **too early** — it slept a flat 150 ms after resizing the
viewport, and the resize re-mounted the React subtree, restarting `style.css`'s `.animate-on-mount`
entry animations. Because the lens's visibility test is opacity-aware, a still-fading element read as
*invisible*, so a **permanently broken page measured clean 8 times out of 10**. 231 replaced the magic
number with a predicate derived from the mechanism — wait until no CSS animation is running and the
geometry has stopped moving — and the rate went **2/10 → 20/20**.

231 stopped there, on purpose, and filed row 233 with an unusually honest framing: `checkResponsive`
reads `boundingBox()`, which is **not** opacity-gated the way the occlusion lens's `checkVisibility()`
is, so it may genuinely share no failure mode. The row demanded the answer be **MEASURED, not argued**.

## The intuition

Here is the whole thing in one sentence: **a CSS `transform` on an ancestor changes what
`getBoundingClientRect()` returns.**

That is not a bug in the browser; it is the definition. `getBoundingClientRect()` reports where the
element *actually is on screen right now*, transforms included. And `boundingBox()` — Playwright's API,
the one `checkResponsive` calls — is `getBoundingClientRect()`.

Now look at what the entry animations do:

```css
@keyframes fadeInScale { from { transform: scale(0.95) } to { transform: scale(1) } }
@keyframes slideInLeft { from { transform: translateX(-20px) } to { transform: translateX(0) } }
```

`.pool-hero-card`, `.quick-metrics`, `.calculator-compact`, `.pool-info-section`, `.search-section`,
`.results-section` all animate with `fadeInScale`. `.filters-section` uses `slideInLeft`. These are the
CTA's **ancestors**. So for the first ~1.2 s of every page's life, every box the responsive lens
measures is **shrunk toward the viewport centre by up to 5 %** — and then compared against a viewport
width that has not shrunk.

The lens was measuring a scale model of the page and asking whether it fit through the door.

## The measurement, before any code was written

`checkResponsive` instrumented at t = 0/100/200/400/800/1200/1600/2400 ms past its existing measurement
point, on the real surfaces through the real driver:

| surface | CTA box at t=0 | at rest | error at t=0 | anims running at t=0 | settle |
|---|---|---|---|---|---|
| `pool-detail-360` | x 77.4, w **205.2** | x 72, w **216** | **−5.0 % width, +5.4 px inset** | 12 | ~1200 ms |
| `grid-360` | x 20, w **320** | x 16, w **328** | **−2.4 % width, +4 px inset** | 30 | ~800 ms |
| `landing-360` | stable | stable | 0 | 7 | ~1200 ms |
| `planner-360` | stable | stable | 0 | 4 | ~800 ms |
| `plan-bloom-360` | stable | stable | 0 | 15 | ~1600 ms |

Two things worth pausing on.

**First, the row's hypothesis (b) was half right, and it was the wrong half.** `boundingBox()` really is
not opacity-gated — the CTA box was non-null with `count() === 1` at t=0 on all five surfaces, so 231's
*exact* mechanism does not transfer. Had the item stopped at that check, it would have concluded "no
shared failure mode" and closed. The failure mode transfers through a different door entirely.

**Second, three of the five surfaces show zero distortion** — and they are not safe, they are lucky.
They still have 4–15 animations running at the moment of measurement; their particular CTAs simply are
not inside a transforming ancestor *today*. One `fadeInScale` added to a planner container turns them
into `pool-detail-360` with no warning.

### What the blindness costs, as a rule rather than an anecdote

The mapping on `pool-detail-360` is exactly `x → 180 + 0.95·(x − 180)` — scale 0.95 about the viewport
centre. So the lens cannot see **any responsive defect smaller than ~5 % of the element's distance from
the viewport centre**: every left-clip with an at-rest `box.x` in **[−10.5, −1)**, every right-overflow
with an at-rest right edge in **(361, 370.5]**.

Marginal ancestor-clipping *is* the shape of the bug this check was added for (item 136).

### The number

A permanent defect was injected on the real surface via 231's `opts.injectStyle`:
`.cta-button-primary{position:relative; left:-76px}`. At rest that puts `box.x` at **−4** — a genuine
P2 finding. `scrollWidth` is untouched at 360, so *only* the ancestor-clip leg is exercised and the
finding count is unambiguous.

Watch it disappear and come back:

| t | `box.x` reads | flagged? |
|---|---|---|
| 0 ms | **+5.2** | no |
| 200 ms | +3.3 | no |
| 400 ms | −0.9 | no (threshold is `< −1`) |
| 800 ms | −3.9 | **yes** |
| 1200 ms+ | −4.0 | **yes** |

**Pre-fix detection rate, un-instrumented shipped path, N=10 isolated processes: `0/10`.** Not
"sometimes" — never. Note the trap that had to be dodged to get that number: the *instrumented* build
detects the defect every single time, because the diagnostic's own sampling waits let the animation
finish. `audit-app.js` was restored byte-identically (`md5 31f16b3e…`) before the rate that counts was
measured. That is `playbooks/detector-detection-rate.md` Trap 1, and it is the difference between a real
measurement and a flattering one.

## What changed, and why

**1. `checkResponsive` waits on the mechanism.** It calls the **existing** `waitForQuiescence()` — 231's
function, reused, not re-implemented — before its first read: poll until no non-infinite CSS animation is
running *and* the geometry signature is stable across two samples ≥100 ms apart. Bounded at 3000 ms.

**2. On timeout it advises and measures anyway.** A readiness wait that can silently skip a measurement
has only moved the false negative one layer down. So the reads always run — on timeout, on a clean
settle, and with the switch off.

**3. A kill switch, because a positive control needs one.** `s.responsiveQuiescence` /
`AUDIT_RESPONSIVE_QUIESCENCE=0`, default ON, resolved once in `runAudit()` and stamped onto the surface
object by `main()` — the exact convention `occlusionQuiescence` already uses. When OFF, the pre-233
behaviour is reproduced *exactly* (no wait at all). This is not a nicety: it is what lets the test run
the OLD path in the same session and prove the harness can tell the two apart.

**4. The static branch's flat 400 ms settle** becomes the same predicate under the same switch, with a
P2 advisory under a new check name `quiescence`. Two of the four fixed waits 231 counted are now gone.

**5. A zero-match `ctaSelector` now advises instead of skipping silently.** "A check that cannot go red
is not a check", generalised. This one found something — see below.

**Not converted:** `audit-app.js:3475`'s `waitForTimeout(120)`. It is `pollFor()`'s poll *interval*, not
a settle: the predicate is re-evaluated until true or deadline, so it cannot decide a measurement.
Converting it for symmetry would have been cargo cult. Stated with evidence rather than done.

## The proof

Rates on the real `pool-detail-360` surface through the real `runAudit()` driver, N isolated processes
each:

| leg | | rate |
|---|---|---|
| **A** | quiescence ON + the permanent defect | **20/20** |
| **B** | positive control — same defect, switch OFF | **0/20** |
| **C** | non-vacuity — no-op injected style, switch ON | **0/5** |

Leg B is the load-bearing one. A harness nobody has seen fail is not evidence, and 0/20 reproduces the
operator's independent 0/10 pre-build measurement.

Mutation matrix, **each condition neutered separately** — the check item 231 itself failed at attempt 1
*with this playbook already written and open*:

| mutation | leg A | fixture (D) | fixture (E) |
|---|---|---|---|
| M1 — short-circuit the new wait | **RED** | green | green |
| M2 — neuter the zero-match advisory | green | **RED** | green |
| M3 — neuter the "not reached" advisory | green | green | **RED** |

Each mutation turns exactly one thing red. `audit-app.js` restored byte-identically after every one
(`md5 9f1eaf3e5680f3c0218eed2a9d81fd3d`).

**The full-tick before/after diff** — the acceptance criterion 231 owed and did not satisfy: a complete
tick with the switch ON and OFF on the same commit, both findings JSONs written and diffed. **0 missing,
0 added**, identical 8-finding sets. The fix only ever *adds* detections; on the current rotation it
added none, because none of the rotated surfaces happens to carry a defect inside the blind band.

**Cost:** +282 ms/surface mean across the five `≤768px` surfaces (`pool-detail-360` alone +914 ms);
full-tick delta **+634 ms** (313,022 → 313,656 ms). Much cheaper than 231's ~1.4 s/surface, because most
surfaces settle immediately. Both tick runs took ~313 s against `DEFAULT_TIME_BUDGET_MS = 300 s`, but
that is pre-existing sandbox slowness — present with the switch OFF too — and no truncation occurred
(`rot.truncated: false`, read from the written JSON rather than inferred).

## The thing that was found by accident, which may matter more than the fix

The new zero-match advisory fired **on the live default rotation**: `planner-768`'s `.gp-chip` selector
matches **zero elements**. So `checkResponsive`'s ancestor-clip leg has been measuring *nothing* on that
surface — not passing, not failing, silently absent — and there was no way to know, because the old code
skipped the branch without a word.

The build's first write-up called this an open product question ("is `.gp-chip` conditionally absent at
768 px, or a stale selector?"). **The verifier refuted that framing, and it was right.** It is neither —
it is deterministic **test-harness self-interference**, discoverable by reading the adjacent code:

- `audit-app.js:~3778` — the planner driver's backlog-164 interactive check **clicks the first
  `.gp-chip`** to prove the flow advances. Gated on `s.width > 360 && !s.ko`.
- `audit-app.js:~3804` — `checkResponsive(page, s, findings, '.gp-chip')`. Gated on `s.width <= 768`.
- `planner-768` is the **only** surface where both gates fire (`planner` at 1280 skips the check,
  `planner-360` skips the click, `planner-ko` skips both). Measured directly: `.gp-chip` count is **24**
  before the click, **0** after.

The harness's own click destroys the selector it later measures. That means the ancestor-clip leg has
been dead on `planner-768` since item **201** widened the check to 768 px — and 164's comment still
claims the click is "scoped to the 1280/EN surface only", which stopped being true at that moment and
nobody noticed, *because the check it broke was silent by construction*. The P2 will now fire on every
tick, forever, until someone decides which way to resolve it.

Filed as **backlog 234**. Not fixed here: reordering a surface driver is a scanner behaviour change
beyond this item's smallest-change scope. What this item ships is the advisory that made a
silent-since-201 hole visible at all — which is exactly what change item 4 exists to do.

## Deviations from the spec

1. Check name `quiescence` for the static branch — the spec left this as an open decision and asked for
   a grep for an existing allowlist first. There is none: no test enumerates check names, and
   `blockingFindings()` filters on **severity** alone, so a new P2 name cannot change the item-142 exit
   contract.
2. The zero-match advisory is **not** gated behind the quiescence switch, deliberately — it is an
   independent fix, and coupling it would mean a caller who disables quiescence also loses the
   don't-skip-silently guarantee for an unrelated failure mode.
3. Fixture (E) copies 231's monotonic-nudge mechanism character-for-character but adds an off-viewport
   `.cta`, because `checkResponsive` has no notion of occlusion and would otherwise have nothing to
   report for the "measure anyway" assertion.
4. This item ships as **four commits, not one** — a deviation from the single-commit shape 226/231 used.
   The session's stop hook rejects a tree holding a subagent's in-flight work, so each artifact was
   committed as it completed. The docs-first rule still held: the spec landed ahead of the code.
