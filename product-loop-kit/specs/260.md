# Spec 260: a card numeral cell must not intersect ANY other element of the same card — the numeral-vs-control half 246 left open

## Evidence

Backlog row 260 (written at 246's merge, renumbered 259 → 260 per the `main`-ids-win precedent) plus
`specs/246-notes.md` "Attempt 2", which carries both reproductions verbatim:

**Instance (i) — `.pool-apy-hero` × `.pool-context-inline`, list view, 768px, both themes.**
Reproduced by the 246 verifier with real `getBoundingClientRect()` intersection, using the longest project
slug actually present in `data/pools-snapshot.json` paired with an anomalous APY:

```
✗ list/light/768px: numeral-cell class scan
    card[4] .pool-apy-hero "⚠ 9,999,999.99%" overlaps .pool-context-inline
    "hamilton-lane-senior-credit-opportunities-securitize-fund · Polygon"
✗ list/dark/768px: (identical)
```

Confirmed on BOTH sides of 246's `white-space: nowrap` change — wrapping neither causes nor cures it
(`nowrap` stops the hero's own text from wrapping; it does not stop the hero's box from growing out of its
110px grid track into the neighbouring cell). 360/1280/1540px and both grid-view passes stayed green at
that magnitude. Pre-existing on `main`, not introduced by 246: it depends only on `.pool-context-inline`'s
existing layout (`style.css:4081`, predates 246) and a long-slug × high-APY pairing.

**Instance (ii) — `.tvl-value` × `.calculate-yield-btn-new`, grid view, 1280/1540px, both themes.**
Surfaced when an early draft of 246's neighbour derivation included interactive controls, then deliberately
excluded: `test_card_numeral_wrap.js:304` filters `!el.closest('.pool-cta-section')` out of the neighbour
set, so the guard is structurally blind to it. Reproduction magnitude: the pre-existing `usdc-tvl-glitch`
fixture (`tvlUsd: 950e15` → `.tvl-value` "$950000000.0B") overlapping the "View & calculate →" button.

**Live-data reachability, measured this session against `data/pools-snapshot.json` (7,334 pools) — this is
the number the ticket's "reproduce both from live data" ask actually returns, and it splits the two
instances:**

| fact | value |
|---|---|
| pools above `APY_SANITY_LIMIT` (1000%) | **21 / 7,334 (0.29%)** |
| worst live total APY | **394,208.17%** — `zeebu` · BSC · ZBU (`tvlUsd` $555,125) → hero renders `⚠ 394,208.17%` |
| longest project slug anywhere in the snapshot | `hamilton-lane-senior-credit-opportunities-securitize-fund` (57 chars) |
| longest project slug **among the 21 anomalous pools** | **20 chars** (`aerodrome-slipstream`) |

| **max live TVL** | **$17,707,651,767 → `formatCurrency` renders "$17.7B" (6 chars)** |

Two honest consequences, both of which this spec is written around:

1. **Instance (i) IS reachable from live data — but not with the 57-char slug.** The 57-char slug and the
   anomalous magnitudes do not co-occur in today's snapshot (max anomalous slug = 20 chars). The collision
   does not require a 57-char slug: it requires the hero's box to exceed its 110px track while the byline
   fills its own column. `⚠ 394,208.17%` at 16px/600 tabular-nums is the live worst case and is the pairing
   the acceptance criteria must exercise. Whether it exceeds 110px is a MEASUREMENT, not an assumption —
   see AC-1.
2. **Instance (ii) is NOT reachable from live data today.** $17.7B renders as 6 characters and cannot reach
   the grid card's closing-line CTA. It is a durability defect of the same class (item 122's precedent: a
   garbage-magnitude TVL-shaped number DID render on this product once), currently unguarded, and its
   reproduction requires a stress fixture. This spec says so with the number rather than dressing it as a
   live P1.

## Hypothesis

We believe giving the numeral cell's grid track a content-derived floor — so an oversized numeral takes
space from the adjacent TEXT column (which already ellipsizes) instead of overflowing into it — will
eliminate both intersections without ever truncating a numeral, because in both instances the numeral's box
is larger than the track the layout reserved for it and the overflow spills toward a neighbour.
Confidence: **supported** (mechanism directly measured in 246's verifier reproduction; the remedy class is
untested and must be measured, not assumed).

- **Instance of:** *a `white-space: nowrap` numeral cell in a fixed-or-flexible grid track whose box may
  exceed the track, with the overflow landing on a sibling cell of the same `.pool-card`.* Population = every
  numeral cell (`.pool-apy-hero`, `.pool-apy-preview`, `.pool-apy-tag`, `.tvl-value`) × every other rendered
  element of the same card, across both views × both themes × 4 viewports. 246 closed the
  numeral-vs-passive-text half **for the neighbour set its check derives**; the numeral-vs-interactive-control
  half is guarded by nothing (the `.pool-cta-section` exclusion at `test_card_numeral_wrap.js:304`).
- **Class closed by this item:** the guard side, **yes, for `.pool-card`** — after this item the neighbour
  derivation has NO class exclusion, so any element of the card (passive text or interactive control) that a
  numeral cell intersects turns the gate red. The *fix* side is closed only for the two reproduced
  mechanisms; a third mechanism (e.g. an absolutely-positioned overlay) would be caught by the widened guard
  but not prevented by this CSS. **Left open, with the number:** the guard's population is `.pool-card` only
  — the planner (`planner.js`), the pool-detail body (`PoolDetail.js`) and the generated token/chain pages
  render numerals under different classes on **~4,400 generated static pages** and are covered by nothing
  here. Not ticketed as a new item (no evidence of a defect there yet); recorded in the notes' class
  statement, per RAZOR "ship the narrow fix and state the class it leaves open with a number".

## Change

`style.css` only (plus the regenerated `style.min.css`), and `test_card_numeral_wrap.js`.

**Leg A — instance (i), list view.** Give the right-aligned APY and TVL tracks a content floor so an
oversized numeral shrinks the `1fr` byline column rather than overflowing into it. The starting candidate,
to be MEASURED not assumed:

- `.pools-list .pool-card` / `.pool-columns` (`style.css` ~2790 / ~2775): third and fourth tracks gain a
  content-derived sizing function (e.g. `auto` with a `min-width` floor on `.pools-list .pool-apy-section` /
  `.pools-list .pool-tvl-section`, or `minmax(110px, max-content)` / `minmax(130px, max-content)`),
  whichever the browser actually resolves the intended way.
- Both cells are right-aligned (`align-items: flex-end`) and track 5 is fixed, so widening a track moves only
  its LEFT edge: the numerals' right edges — and therefore their alignment with the `.pool-columns` header
  labels — must be unchanged for normal rows. **This is an acceptance criterion, not a hope (AC-3).**
- The `@media (max-width: 767px)` list layout (`style.css:2957`) re-templates the card entirely; any floor
  added must be reset there if it changes the mobile row.

**Leg B — instance (ii), grid view.** Same principle on `.pools-grid .pool-card`'s closing line
(`minmax(0, 1fr) auto`, `style.css` ~3059): let the numeral cell claim the width it needs and let the CTA
**control label** yield (ellipsis on a button label is not a trust-rail violation; ellipsis on a numeral is).
Any solution must keep the header row (`grid-column: 1 / -1`) from inheriting a `min-content` contribution
from the nowrap `.pool-context-inline` — that is why the track is `minmax(0, 1fr)` today, and blowing that
up would overflow the whole card.

**OUT of scope:** truncating, clipping or abbreviating any numeral (trust rail — CLAUDE.md); clamping the
`$/day` or TVL value at the data layer; the `.pool-symbol` list-view wrap recorded as an open sibling in
`specs/246-notes.md`; any surface outside `.pool-card`; layout recomposition of either view.

**If leg B has no CSS remedy that satisfies the constraints** (numeral never truncated; normal-card geometry
unchanged; header contribution not blown up), ship leg A, state leg B open with the number above, and do NOT
widen the guard's neighbour set past what stays green on the asserted fixture population — a permanently-red
gate is not a gate. Say which of the two happened, explicitly, in the notes.

## Acceptance criteria

- [ ] **AC-1 (reproduction, live-derived).** Before the CSS change, the widened check reproduces instance (i)
      at **768px, list view, both themes**, using the LIVE worst case derived from
      `data/pools-snapshot.json` at test time (highest `apyBase + apyReward` pool and its real
      `project`/`chain`) — not the invented `9999999.99`. If the live worst case does NOT reproduce it, say
      so with the measured pixel numbers (hero box width vs. 110px track) and fall back to the verifier's
      reproduction magnitude as the positive control, stating that instance (i) is currently
      **latent-not-live**. Either outcome is acceptable; guessing is not.
- [ ] **AC-2 (fix).** After the change, `node test_card_numeral_wrap.js` is green with the widened neighbour
      set — **no `.pool-cta-section` exclusion** (leg B shipped) or, if leg B is honestly abandoned, with the
      exclusion retained and the reason stated in the notes and in the file's own header comment.
      Instance (i) does not intersect at any view × theme × viewport.
- [ ] **AC-3 (no regression on normal data).** For non-anomalous rows the rendered geometry is UNCHANGED:
      every numeral cell's right edge in list view sits at the same x as before the change (±1px), measured
      by capturing the rects on `main` and after the change with the same fixture. No horizontal page scroll
      at 360/768/1280/1540 in either view.
- [ ] **AC-4 (numeral never truncated).** For every numeral cell in the population:
      `scrollWidth <= clientWidth + 1` AND computed `text-overflow !== 'ellipsis'` AND rendered on one line.
      A fix that clips or ellipsizes a number is a FAIL regardless of whether it removes the overlap.
- [ ] **Tests:** `node test_card_numeral_wrap.js` (extended), `node test_list_default.js`,
      `node test_list_polish.js`, `node test_test_registry.js`, `node test_minified_assets.js`,
      `node test_css_minified_render.js`, and `node run-tests.js --lane=plain --timeout=90`. Each timeboxed
      to 5 foreground minutes. Any failure must be proven pre-existing on clean `HEAD` (stash-baseline) or
      fixed — `test_translations_number_format.js` and `test_vercelignore.js` were already failing on `main`
      as of 246 (`specs/246-notes.md`); re-confirm rather than inherit the claim.
- [ ] **Non-vacuity:** each shipped CSS rule neutered SEPARATELY (so "two working rules" is distinguishable
      from "one working rule and one dead one") → gate red → byte-identical restore (`md5sum` before/after)
      → green. `home.html` loads `style.min.css`, so every trial is
      `edit style.css` → `npm run minify` → run → restore → `npm run minify` → checksum. The widened
      neighbour set gets its OWN non-vacuity proof: with the shipped CSS in place, a DOM-level mutation that
      moves a control onto a numeral must turn the check red and NAME `.calculate-yield-btn-new` (the class
      the old exclusion could never see), then restore green.
- [ ] **Population:** the fixture's worst-case pool is DERIVED at test time from `data/pools-snapshot.json`
      (longest slug — already done in the file — plus, new here, the highest live total APY and its real
      project/chain), so the guard follows the snapshot instead of a hardcoded instance. The scan enumerates
      every numeral cell that exists in every rendered `.pool-card` across 2 views × 2 themes × 4 viewports.

## Measurement

Metric: **build-leg only** — no funnel step is claimed to move. This is a rendering-integrity fix on the
analytics pool card (the surface `?token=`/`?chain=` SEO traffic lands on, upstream of the pool-detail
north-star CTAs); the two intersections it removes are reachable only on anomalous data (0.29% of live
pools) and stress data (0 live pools), so no ≥30-event window can exist for it and none is claimed.
Gate: n/a. Backstop: n/a. Decision rule: keep if `node test_card_numeral_wrap.js` stays green on the next 2
ticks with the widened neighbour set and a live-derived worst case.

## Risk tier (builder's guess — verifier assigns independently)

**LOW** — CSS-only + test-only; no JS, no translations, no new dependency, no router/parameterized-URL
behavior, no trust-rail constant touched. Flagged for the verifier's independent call: it edits the shared
`.pools-list .pool-card` / `.pools-grid .pool-card` grid templates, which every parameterized analytics URL
renders, so a geometry regression would be broadly visible — AC-3 exists precisely to make that assertable
rather than argued. If the diff exceeds 150 lines the tier is HIGH by the NORTH_STAR rule.

## Open questions

None that change the architecture. The one judgment call — *byline min-width/flex-shrink discipline vs.
truncation-with-title on the project slug* (the ticket's own framing) — is resolved here in favour of
**neither**: both would have the TEXT yield by a NEW mechanism, while `.pool-context-inline` already
ellipsizes at `max-width: 100%` (`style.css:4081`); the actual defect is that the numeral's track never
reserved its own content width, so the fix belongs on the track, not on the byline. Truncation-with-title on
the slug is additionally rejected because a `title` tooltip is not reachable on touch.

## Territory notes

- `.pools-list .pool-card` and `.pool-columns` carry the SAME `40px 1fr 110px 130px 120px` template
  (`style.css` ~2775 / ~2790) — the header row is a separate grid, so any change must preserve right-edge
  alignment rather than track-for-track equality (AC-3).
- `.pools-list .pool-left-section` already has `min-width: 0`; the grid-view `.pool-left-section` does NOT,
  which is why `.pools-grid .pool-card`'s first track is pinned to `minmax(0, 1fr)`.
- `.pool-context-inline` (`style.css:4081`) already has `white-space: nowrap; overflow: hidden;
  text-overflow: ellipsis; max-width: 100%` — it is ALREADY a yielding cell. Nothing to add there.
- `@media (max-width: 767px)` (`style.css:2957`) re-templates the list card to
  `40px 1fr auto` / two rows and hides `.pool-apy-preview`, `.pool-apy-tag` and `.pool-cta-section`. Any
  desktop-track floor must not leak into it.
- `home.html` loads `style.min.css`, NOT `style.css` — `npm run minify` after every CSS edit, and
  `test_minified_assets.js` enforces it.
