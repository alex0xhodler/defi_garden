# 261 — PR explainer (LOW tier: short explainer)

Branch `claude/loop-261` · spec `specs/261.md` · notes `specs/261-notes.md`

## The defect

`openapi.json:17` and `tools/get_curated_pools.json:5` — the two machine-readable documents an agent
actually parses before calling this site's API — both said:

> "…curated DeFi yield pools matching your criteria with **TVL >= $10M** and APY <= 1000%."

The real floor is `app.js:801` `DEFAULT_MIN_TVL = 100000` — **$100K**. Item 227's Worker *enforces* $100K
(`edge/api-core.js` requires `../trust-rails.js`) and `edge/API.md:50` states $100K. So as of `d4f7b3cf3c`
the repo stated the same rail two different ways in two documents describing the same endpoint, and the
wrong one was in the machine-readable half.

This is residue of `6fceca79bb`, the authorized 100× relaxation. Backlog **254** cleaned up the nine
hand-typed `$10M` strings it stranded in `generate-llms.js`, `generate-stories.js`, `translations.js` and
`home.html` — the **prose** stating-sites. Its population never included the **machine** stating-sites.
Item 227 shipped the API on top of them without touching either file.

Why it matters more than a typo: an agent that installs `tools/get_curated_pools.json` as a function-calling
manifest will present a $150K-TVL pool to a user as having cleared a $10M bar. **The rail is not weakened in
code — it is misreported to the one audience that cannot read the code.**

## What changed

1. **`openapi.json` (1 line)** and **`tools/get_curated_pools.json` (1 line)** — `$10M` → `$100K`, which is
   what `formatTvlFloor(DEFAULT_MIN_TVL)` renders. `git diff --numstat` is `1 1` on each file; both still
   `JSON.parse`.
1b. **`CLAUDE.md:17` and `PRODUCT.md:35` (1 line each)** — the same `$10M` → `$100K` correction, plus a
   `$100k` → `$100K` casing fix in `stakeholder_communication_plan.md:255`. These were **not** in attempt 1;
   the verifier found them by taking this spec's own population definition ("every agent-facing document
   that states a rail figure") more seriously than the builder's glob did. `CLAUDE.md` is the file injected
   as context into every Claude Code session on this repo — it had been handing every agent the wrong rail.
   Two other root-`.md` `$10M` occurrences were read and deliberately left alone: a filter-tier checklist
   (`stakeholder_communication_plan.md:256`, which enumerates selectable options) and a hypothetical
   user-chosen filter state in a journey diagram (`user_journey_diagrams.md:324`). Neither states the
   default rail.
2. **`test_agent_surface_rail_claims.js` (new, plain lane)** — the reason this is an item and not
   a two-character edit. It derives its population by **globbing** the agent-facing set at test time
   (`openapi.json`, `tools/*.json`, `.well-known/**/*.json`, `llms*.txt`, `edge/*.md`, root-level `*.md`
   and `docs/**/*.md` → **31 files** today), finds every **claim-shaped** rail figure (**10 TVL-floor
   claims, 8 APY-limit claims**), and asserts each one equals the value derived from `trust-rails.js`.
   - **Attempt 3 (second verifier FAIL) widened it again**, to `docs/**/*.md` and `edge/*.md`. The
     round-2 justification for a root-only glob only ever addressed `product-loop-kit/**`; it never
     addressed `docs/`, which is not an archive and carried present-tense wrong claims —
     `docs/discovery-data-layer-134.md` (**30 occurrences**) and `docs/feasibility-data-layer.md:82`,
     both authored 2026-08-03, before the relaxation, both citing `file:line` references that had since
     moved. Fixed. The population is now an **enumerated** boundary in the test's header (included:
     machine-manifest + root `*.md` + `docs/**` + `edge/*.md`; excluded, each with a role reason), not a
     boundary that falls out of a glob's recursion depth — which is exactly how the gap survived twice.
   - Five `$10M` occurrences were **deliberately left**, inside explicitly self-dated measurement tables
     ("§4a — Measured (2026-07-14, live in-session)"). Relabelling a dated measurement's floor without
     re-running the pipeline would assert a number nobody measured. Disclosed, not hidden.
   - The `*.md` scan uses **anchored claim shapes only** (`DEFAULT_MIN_TVL = $X`, `$X default TVL floor`,
     `minimum TVL … $X`), because `docs/garden-planner-v2-spec.md` legitimately states persona-tier
     thresholds of $50M/$10M in the bare `TVL ≥ $X` shape and those are **not** `DEFAULT_MIN_TVL`. That
     narrowing is a disclosed gap, not a per-file exclusion list.
   - The root-`*.md` glob is **non-recursive on purpose**, so `product-loop-kit/**` never enters the
     population. That archive quotes past rail values verbatim as history (`specs/226.md`,
     `specs/104-notes.md`, and 254's own backlog row all contain `$10M`); rewriting a record of what was
     said would itself be a defect. The exclusion is by **role** — a log of what was true then, not a
     statement of what is true now — and it is documented in the test's header rather than left implicit.
   - "Claim-shaped" rather than "every number in the file" is the load-bearing choice: `llms.txt` legitimately
     contains hundreds of TVL figures (`Ethereum ($86.9B TVL)`). The test asserts *in-file* that those are
     not captured — so the exclusion is a property of the **shape**, not a file-exclusion list, which is the
     too-narrow check RAZOR warns against.
   - **Anti-vacuity floor**: the test fails if it finds fewer than 2 TVL claims or fewer than 2 APY claims.
     A scan that silently matches nothing cannot read as green.
3. **`package.json`** — one `&& node test_agent_surface_rail_claims.js` appended to `test:serial`, which
   `run-tests.js` parses and `test_test_registry.js` enforces.

## What this does NOT close, with numbers

- **Bare, unformatted `NAME = value` rail figures are invisible to this detector.** Attempt 2 added a
  `NAME = value` shape but scoped it to `$`/`%`-marked values (the form `CLAUDE.md` actually used), so
  `edge/API.md:50`'s `DEFAULT_MIN_TVL = 100000` / `APY_SANITY_LIMIT = 1000` still is not seen.
  **1 known site, 2 claims** — currently correct, currently unguarded.
- **Rail semantics are not machine-checkable here at all** — a document that describes the *behaviour*
  wrongly ("anomalous pools are flagged" when the API excludes them) passes this test.
- **`openapi.json`'s declared PATH set still disagrees with what the Worker routes** — it declares
  `POST /planner` (not implemented) and omits `/api`, `/health`, `/pools/{id}`, `/forever-number`
  (implemented): **4 undocumented endpoints and 1 documented-but-missing, out of 5 routed** (the first
  count written here said 3 — it dropped the self-describing `/api` root from the numerator while keeping
  it in the denominator; the verifier caught it). Same false-claim class,
  different axis. Deliberately not fixed here because it carries a question the human owns —
  `POST /planner`'s `x-payment-info` block is item 234's groundwork, so "deprecate in place" vs "remove" is
  not a builder's call. Filed as backlog **262**, status BLOCKED on that answer.

## The third verifier round, and what was done about it

Round 3 returned **7/7 acceptance criteria independently re-derived as met** — the verifier re-ran every
non-vacuity proof itself, reproduced the whole-repo sweep with its own greps, and independently confirmed
the two judgement calls (the five dated-measurement occurrences left alone, and the prose-only claim-shape
narrowing) by writing its own bare-shape and anchored-shape probe files into `docs/` and observing exactly
the miss and the catch the notes predicted.

It still returned **FAIL**, on two documentation-accuracy findings, and it was right about one and a half:

- **Real:** `261-notes.md` said `docs/feasibility-data-layer.md` had "5 `$10M` occurrences" when it had
  **3** — and the paragraph's own itemisation (1 fixed + 2 left) already summed to 3.
  `git show HEAD:docs/feasibility-data-layer.md | grep -c '$10M'` → 3. Corrected in place, with the
  correction recorded rather than silently overwritten. This is the **second** arithmetic slip on this item
  (round 1 caught the Leg B "3 vs 4"), which is worth more attention than either slip individually.
- **Real:** this file claimed the new test had "7 assertions" when it has **11**. Corrected.
- **Not real:** the same finding also asserted this file still said "24 files / 8 TVL / 6 APY" and omitted
  the `docs/` widening entirely. It does not, and did not at the time — those sections had already been
  rewritten. The verifier flagged in its own round-2 report that a `Read` of this file had once returned a
  stale shorter version; that artifact recurred. Recorded here rather than quietly dropped, because a
  verifier finding that is wrong is exactly as important to write down as one that is right.

**No product code changed after the verified state** — the corrections are confined to these two write-ups.
The shipped diff is byte-identical to what round 3 judged 7/7.

## How this item actually went

Three attempts, two verifier FAILs, and **both FAILs were the same shape**: the population the test drew
from was narrower than the population the spec's own words claimed, and a real, currently-wrong site was
sitting in the gap. Round 1 found `CLAUDE.md` and `PRODUCT.md`; round 2 found `docs/`. Each time the fix was
to widen the population and re-measure, not to soften the claim.

That is worth recording because it is the item's own thesis turned on itself: a check narrower than the
class it guards launders the gap as coverage. The final population boundary is enumerated and reasoned
per-directory precisely so a fourth round cannot happen the same way.
