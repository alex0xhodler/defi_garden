Confidence: supported for the mechanism-in-general (Google's own thin-content guidance; the human's Q3b directive), guess for the Google response (only the human's GSC read can settle it — 013 precedent). The item pays off across several futures — agents citing richer pages, Google indexing them, users landing on them, 229 packs quoting them — which is what earns its score despite the Google leg being unobservable from inside the loop.

Blindspot pass, 2026-08-05 (build loop). Six constraints the spec did not state, each of which
would have changed the build:

1. **CORRECTED — the original version of this note was WRONG, and it was the most load-bearing claim
   in the item.** It said: *"the production fixture carries only 13 pool fields… `sigma`, `mu`,
   `apyPct30D`, `count`, `predictions` do not survive the projection… a depth section built on them
   renders fully locally and empty on every production page."* **False.** The verifier caught it on
   attempt 2 via the extension attack, and the operator (who wrote it) confirmed the verifier is
   right.

   What is actually true: `generate-pools-snapshot.js` writes **two different artifacts**.
   `generateSnapshot()` produces the committed `data/pools-snapshot.json` — the $10M trust-railed
   snapshot the APP reads — and *that* is the one projected through the 13-field `FIELDS` whitelist
   (`:58`, `projectPool` at `:66`). The `--seo-out` transient that CI actually feeds the generators
   (`:305`) is a **raw, FULL-FIELD, $1,000-TVL-floored** copy — its own comment says so: *"also emit
   a $1000-floored RAW-pool transient (full fields preserved, a provable superset of every pool the
   3 SEO generators consume)"*. Measured against the very fixture used for this item's controlled
   delta (`seo-pools.json`, 15,600 pools): `sigma` **15,600/15,600**, `mu` **15,600/15,600**,
   `count` **15,600/15,600**, `apyPct30D` **12,560/15,600**.

   So the risk is the **opposite** of what the note claimed, and the wrong version was the more
   dangerous one to leave lying around: those fields are **present and live in production, and
   nothing rails them**. A future item that renders `sigma`/`mu`/`apyPct30D` will not go blank — it
   will publish unbounded figures, which is precisely the item-122/144 defect class (`apyMean30d`
   rendering 36,452% as a trusted card). Anything new drawn from this fixture needs a **per-field
   rail at every render site**, exactly like `mean30dSane`.

   This item's section is unaffected: it reads only `project`, `chain`, `apyBase`, `apyReward`,
   `apyMean30d`, `ilRisk` — safe by choice, not by field-stripping. **Restricting to those fields
   was a scope decision, never a protection**, and no part of this item's evidence depended on the
   false claim (the controlled delta measured real rendered output either way).
2. **The 30d-mean rail already exists and is exported** — `mean30dSane()`
   (`generate-pool-pages.js:139`, itself a mirror of `PoolDetail.js:285`, item 144's fix: finite,
   `>= 0`, `<= APY_SANITY_LIMIT`). REUSE it; do not re-derive the predicate (mirror rule). It must
   be a **lazy `require()` inside the function**, not at module top level:
   `generate-pool-pages.js:55` requires THIS module, so a top-level require is a load-time cycle —
   `main()` already uses the lazy pattern for `generate-chain-pages.js` for the same reason.
3. **`selectHeadTokens` is already imported here** (`generate-token-pages.js:34`) but `main()`
   calls it only inside `if (args.sitemap)`. Hoist that ONE call so the sitemap filter and the
   depth-section predicate read the SAME `Set` — a second call/derivation would be the mirror the
   226 close-out warns about.
4. **Do NOT commit a regenerated estate.** `tokens/` is 4,194 committed files, but
   `sitemap-update.yml` triggers on pushes to `main` touching `generate-token-pages.js` and
   regenerates + commits the whole estate itself. The PR ships the generator + tests only.
5. **`apyMean30d` already has an EN+KO translation key** (`translations.js:119` / `:848` —
   "30d Mean APY" / "30일 평균 APY"); reuse it for the column header instead of adding a key.
   `rateVolatilityNote` is the existing honest phrasing for current-vs-mean divergence.
6. **Head membership is not currently visible to the render functions.** `renderTokenPage` /
   `renderTokenPageMarkdown` take `(rec, related, generatedDate, chainLinks, lang, ogImagePaths)`;
   head-ness has to be threaded in explicitly. Default it to "not head" so every existing caller
   (tests, chain generator reuse) keeps today's output byte-identical.

### Found DURING the build, not by the blindspot pass — recorded so the next item starts with them

7. **`run-tests.js` classifies lanes by a STATIC text scan for `require('./…')` — it cannot see that
   a require is lazy or conditional.** Territory note 2's lazy `require('./generate-pool-pages.js')`
   (correct for the *runtime* cycle) therefore added a text-level edge
   `generate-token-pages.js → generate-pool-pages.js → audit-app.js`, and `audit-app.js` is the
   "browser" marker. That silently re-laned `generate-token-pages.js` and everything transitively
   requiring it — `generate-llms.js`, `test_llms_rails.js`, `test_token_pages.js`,
   `test_chain_pages.js`, `test_hub_pages.js`, `test_sitemap_xml.js`, `test_i18n_pages.js`,
   `test_og_images.js`, … — from `plain` to `browser`, dropping the plain lane **52 → 31 files** and
   turning `test_run_tests.js` red. **A require edge in this repo has a blast radius beyond the two
   files it connects.** Resolved by keeping `mean30dSane` local (see 8) rather than by touching the
   classifier.
8. **Consequence: this item ships a THIRD copy of `mean30dSane`** (after `PoolDetail.js:285` and
   `generate-pool-pages.js:139`, both of which already carry "mirror of…" comments). Reuse-by-require
   and lane-integrity are in genuine tension here, and lane-integrity won. Per RAZOR side 2 /
   `build.md`'s guard rule, the copy is therefore accompanied by `test_mean30d_mirror.js` — a tested
   set-equality against the original, both directions, over a derived population plus the boundary
   values, in the same commit that creates the copy.
9. **Regenerating `translations.js` without `translations.min.js` breaks an existing green test.**
   `test_minified_assets.js` compares the committed minified asset against a fresh minify. Any
   translations change must run `npm run minify` and commit the result in the same commit. Running
   only the new test file in isolation will not catch it — the full `node run-tests.js --lane=plain`
   is what catches it, and it takes ~34s.
