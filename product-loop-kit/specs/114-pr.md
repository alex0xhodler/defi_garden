# 114 — "Welcome back" saved-garden re-entry card (HIGH-tier explainer)

## Goal
Reconnect the hook model's **investment → variable-reward** bridge at the real front door.
A user who plants a garden and comes back to `defi.garden` (bookmark / repeat visit) now
lands on the search-first landing (`/`, item #237) — which showed **no trace** of their
saved garden. The payoff (report mode: "on track / ahead of plan", garden stage, forever
number) lived one click away on `plan.html` but was never surfaced. This card surfaces it.

## Intuition
The landing's hero already has a card slot: the `.landing-garden-card` aside ("Have a goal
in mind? / Plant a garden"). For a returning user that generic prompt is noise — they
already have a garden. So we **swap** that one card: when `localStorage['garden-plan']`
holds a valid plan we recognize, the slot becomes a "Welcome back" re-entry card that names
their goal and offers one tap back into report mode. First-timers (and anyone with a
malformed/unknown plan) keep the generic prompt unchanged. One card in the slot, always.

## What changed and why (reading order)

### 1. `landing.js` — the read + validation (top of the IIFE)
- `GOAL_LABEL_KEYS`: a static `goal id → translations.planner label key` map (all 24 current
  goals). **Why duplicated:** planner.js owns the canonical GOALS list but is NOT loaded on
  the landing route, and there's no shared-module system (IIFEs, no build step). The id→key
  mapping is irregular (`uber`→`goalUberOne`, `youtubepremium`→`goalYouTubePremium`), so it
  can't be derived by a transform. This is a **label lookup, not rate math** — the spec's ban
  on duplicating `gardenStage` (rate logic) is fully honored: no stage math on the landing.
- `readSavedPlan()`: `try/catch` reads `localStorage['garden-plan']`, `JSON.parse`, and
  returns the plan **only** if it's an object with a `goal` string present in
  `GOAL_LABEL_KEYS`. Any parse/shape/unknown-goal problem → `null` → generic card. Same
  try/catch discipline as the existing theme/lang reads.

### 2. `landing.js` — derivation inside `Landing()`
- `useState(readSavedPlan)` (lazy init — runs once). `plannerCopy` resolves the goal label
  via `translations[lang].planner[labelKey]` (falls back to `translations.en.planner`).
- `showReturnCard = !!goalLabel` — if we can't resolve a label, we don't show the card
  (fail safe). `plantedDate` is the saved date formatted `en-US` `{month:'long',
  year:'numeric'}` (reuses the planner `ReportJourney` framing), inside its own try/catch.
- `tendGarden()` — CTA click handler; fires `garden_reentry_clicked` (guarded), no
  `preventDefault` so navigation proceeds.

### 3. `landing.js` — the shown-event effect
- A second `useEffect` keyed on `[showReturnCard]` fires `garden_reentry_shown` once when the
  card renders. Guarded by `typeof Analytics !== 'undefined'` (the 044 precedent: `Analytics`
  is a bare script global, never a `window` property). `Analytics.track` itself no-ops on
  non-production hosts and when `mixpanel` is absent.

### 4. `landing.js` — the render swap
- The single generic `aside` becomes `showReturnCard ? <return card> : <generic card>`. The
  return card reuses the EXACT same neuro classes (`.landing-garden-card`,
  `.landing-card-topline`, `.landing-seed-icon`, `.landing-card-caption`,
  `.landing-garden-link`) + reused components (`LeafMark`, `ArrowIcon`, `PlantIllustration`)
  → **zero new CSS**. Adds `data-testid="landing-return-card"` / `landing-return-cta`. The
  status `<p>` renders only when `plantedDate` resolved and `copy.returnStatus` is a function.

### 5. `translations.js` (+ regenerated `translations.min.js`)
- `en.landing` and `ko.landing` each gain `returnCaption`, `returnStatus` (a
  `(date) => \`Planted ${date}\`` function, mirroring the planner `journeyPlanted` pattern),
  and `returnCta`. `translations.min.js` regenerated via `npm run minify` (consumed by
  plan.html); verified byte-correct by `test_minified_assets.js`.

### 6. `package.json` + `test_landing_return.js`
- New rendered-Playwright gate appended to the `npm test` chain. Seeds `garden-plan` via
  `localStorage` + reload (never drives the planner, never leaves the landing route). 5/5
  pass: valid plan → card w/ Spotify label + plan.html CTA; no plan / malformed → generic
  card, no page error; EN+KO strings, no raw keys; dark mode at 360/768/1280, no h-scroll.

## Deviations from spec (full list in specs/114-notes.md)
1. Goal label via a duplicated static lookup map (module boundary; fails safe for unknown ids).
2. CTA arrow is the reused `ArrowIcon` SVG, not a literal "→" glyph in the string.
3. No garden-stage emoji / no rate math on the landing (static leaf mark + factual "Planted
   <Month YYYY>" only) — per the spec's explicit preference.
4. Card swap (not a sibling card) — one card in the hero slot, all existing CSS reused.
5. Test harness: single browser context + reload (sandbox cgroup can't hold 7 contexts);
   external-host stub + URL-aware console-error filter (sandbox blocks mp.defi.garden/fonts).

## Risk: HIGH (auto-mergeable)
Search-first landing is adjacent to the sacred `__APP_MODE` IA router — hence HIGH. But the
change is **additive render only** inside the landing component: it does NOT touch the router
logic, canonical/OG, or any parameterized-URL (`?token=/?chain=/?pool=`) behavior. No trust
rails, no credentials, no SEO deletion, no out-of-scope dirs. NOT on the NEVER-auto-merge
list → auto-mergeable after verifier PASS. Render-path change with the 003 pixel-gate still
unshipped → flagged "needs human visual spot-check" (advisory, post-merge).
