# 070 — PR explainer (HIGH tier, full walkthrough)

## Goal

The card waitlist is the north-star funnel (`waitlist_submitted`), and the standing decision of 2026-07-12 requires its copy to stay honest: "it's a waitlist for early access, the card does not exist yet — no fake availability." The honest disclaimer string existed (`ctaWaitlistMicro`: EN "Free to join • Card doesn't exist yet • We'll email you when it does", KO "무료 가입 • 카드는 아직 없어요 • 준비되면 이메일로 알려드려요"), was translated, styled, and even guard-tested since item 061 — but it rendered NOWHERE. Its only call site was a dead React element. This item makes the honest disclaimer actually reach users, at the exact button that opens the waitlist.

## Intuition

`Bloom()` in planner.js built two waitlist-CTA elements: `ctaElement` (older, "shared") and `checkoutPanelElement` (newer, the checkout panel with price, trust pills, and note). At some point `checkoutPanelElement` superseded `ctaElement` in both of Bloom's return trees, but `ctaElement` was never deleted. Everything attached only to `ctaElement` — most importantly the micro-disclaimer — became unreachable. specs/009-notes.md discovered this while instrumenting waitlist events; specs/061-notes.md confirmed it after refreshing the copy ("currently unreachable by any user"). Both flagged it as a future backlog item; this is that item.

## What changed and why (diff in reading order)

1. **planner.js — deletion (former ~2425-2443).** The entire dead `ctaElement` declaration: a `gp-cta-row` wrapper, a duplicate waitlist-open button (with its own duplicate `trackWaitlistOpened` call that could never fire, since the element was never mounted), and the microcopy `<p>`. Deleting rather than wiring the whole element in avoids two competing CTA blocks and removes the drift hazard of a second, near-identical onClick handler. `grep '\bctaElement\b' planner.js` → 0 hits after.
2. **planner.js — insertion (one line, now :2669).** Inside the live `checkoutPanelElement`, directly after the `gp-primary-cta gp-checkout-cta` button and before the `gp-checkout-trust` pills: `e('p', { className: 'gp-cta-microcopy' }, t('ctaWaitlistMicro'))`. One insertion point covers both bloom layouts (subscription and growth/target both mount `checkoutPanelElement`). Reuses the existing `.gp-cta-microcopy` rule (planner-styles.css:1411) — zero CSS changes, neumorphic system untouched.
3. **planner.min.js — regenerated** via `npm run minify`. plan.html loads the min bundle; shipping only the source edit is exactly the bug 061's first attempt hit. `test_compiled_assets.js` re-asserts byte-identity with a fresh minify.
4. **test_waitlist_microcopy.js — new rendered gate** (fixture-routed Playwright, no live network, mirrors test_hero_copy/test_waitlist_pitch). Asserts on real DOM: microcopy visible under the CTA with byte-exact `ctaWaitlistMicro` text read from translations.js at runtime, on a subscription bloom (goal=claude) AND a growth bloom (goal=retirement), in EN and KO; CTA click still opens the waitlist modal; zero page errors.
5. **package.json** — `&& node test_waitlist_microcopy.js` appended to the npm test chain.
6. **Bookkeeping** (same commit, per docs-in-first-commit): specs/070.md (spec, promoted this run — no READY items existed), specs/070-notes.md (builder notes), this file, BACKLOG.md row 070 → SHIPPED, LOG.md entry.

## Deviations from spec

One, test-only: the spec's suggested subscription bloom URL (`?goal=claude&pace=stable&fm=monthly`) never reaches bloom — planner.js:3797 requires a `capital` or `monthly` VALUE for non-growth archetypes. The test uses `?goal=claude&pace=stable&fm=capital&capital=5000` instead (the natural forever-number URL). Verifier independently confirmed the guard condition and that both archetype layouts are genuinely exercised.

## What did NOT change

Translations (both languages untouched — the strings shipped in 061), analytics call sites (the live CTA's `trackWaitlistOpened` intact at planner.js:2664; the deleted one was unreachable), all CSS, trust rails (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, degen haircut), waitlist modal, share surfaces, app.js/home.html/PoolDetail.js.
