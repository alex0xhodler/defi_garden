# 112 — PR explainer (HIGH tier): one-source-of-truth transient for the 3 SEO generators

## Goal
The daily `sitemap-update.yml` CI hit `yields.llama.fi/pools` **four separate times** per run — once for the committed $10M FE snapshot (059), then once each inside `generate-token-pages.js`, `generate-chain-pages.js`, and `generate-sitemap.js`. Four fetches of the same ~10 MB payload, the trust-rail TVL filter re-applied three times, and three chances for a transient network blip to prune the SEO surface. 112 collapses **these four** to **one fetch**, feeding the three generators, without changing a single byte of the generated output.

> **Honest scope caveat (verifier-flagged):** a *fifth* fetch lives in `generate-llms.js` (`fetchYieldsSafe`), a later workflow step that is not one of "the 3 SEO generators" and was never in 112's enumerated scope. So the job still makes 2 `/pools` fetches per run, not a literal 1. Folding `generate-llms.js` onto the same transient is a clean follow-up candidate; 112 delivered its charter (the enumerated snapshot+token+chain+sitemap fetches → 1).

## Intuition
There is already a single fetch that must happen: the snapshot generator's. So let that one fetch *also* drop a plain scratch file — every pool with `tvlUsd >= 1000`, full fields, raw — and point the three generators at it. Why $1000? Because it's the loosest floor any consumer needs: token/chain pages floor at $100K, the sitemap skips anything under $1000. So a $1000-floored array is a **superset** of every pool all three generators actually keep. Feeding them the superset is therefore output-identical to feeding them the full live array — and we can *prove* that byte-for-byte, which is the whole ballgame: byte-identical is what keeps this off the NEVER-list that blocked its predecessor (102 would have de-indexed ~1,800 URLs).

## What changed, in reading order
1. **`generate-pools-snapshot.js`** — `parseArgs` learns `--seo-out <path>` (`SEO_OUT` env). In `main()`, right after the pools are in hand and *before* the "no data change → return early" branch, it writes `pools.filter(tvlUsd >= 1000)` as JSON to that path. Placed before the early-return on purpose: the transient must be fresh for the generators every run, even when the committed snapshot is unchanged. The committed `data/` outputs are untouched — this write is purely additive to a separate scratch path.
2. **`generate-token-pages.js` / `generate-chain-pages.js`** — a new `loadFixturePools(path)` helper: returns a non-empty pool array, or `null` on missing/empty/malformed input (with a warning). `main()` becomes `let pools = loadFixturePools(args.fixture); if (!pools) pools = await fetchPoolData();`. This is the **fail-safe**: a bad transient falls through to today's exact live behavior — never a truncated run that would prune the sitemap. (The spec's "zero code change" aside was overridden by its own non-negotiable fallback clause; the old `JSON.parse(readFileSync)` branch threw on a missing file and silently truncated on an empty one.)
3. **`generate-sitemap.js`** — same `loadFixturePools` helper + a tiny `parseFixtureArg` (reads `--fixture`/`POOLS_FIXTURE`). `main()` computes `override = loadFixturePools(...)` and passes it into `generateSitemapSuite(override)`, which already had the `Array.isArray(poolsOverride) ? poolsOverride : await fetchPoolData()` seam. `null` ⇒ live-fetch, byte-identical to today.
4. **`.github/workflows/sitemap-update.yml`** — snapshot step: `--seo-out "$RUNNER_TEMP/seo-pools.json"`; token & chain steps: append `--fixture "$RUNNER_TEMP/seo-pools.json"`; sitemap step: prefix `POOLS_FIXTURE="$RUNNER_TEMP/seo-pools.json"`. `$RUNNER_TEMP` lives outside the repo checkout, so no transient is ever committed.
5. **`test_seo_shared_source.js`** (new) + wired into `npm test`. Network-free. Proves **B1** (full-payload output === $1000-filtered output for all three generators — real generator invocations into temp dirs, real recursive diff after date/lastmod normalization, including OG PNGs, with a sub-$1000 "dust" pool injected so the filter genuinely drops something) and **C1** (`loadFixturePools` returns the array for a good fixture and `null` for missing/empty/malformed, across all three modules).

## Trust rails / NEVER-list
No rail moved — `$1000` is a superset gate on a scratch file, not a change to any generator's `APY_SANITY_LIMIT` / `MIN_POOL_TVL` / `DEFAULT_MIN_TVL` / anomaly logic (all byte-untouched). No SEO deletion (byte-identical, proven). No credentials, no served/committed re-serve of DefiLlama data (transient is scratch-only) — so 107's ToS keystone is not widened. Not NEVER-listed; HIGH tier for the workflow + SEO-generation-path touch.

## Deviations
See `112-notes.md`: (1) token/chain generators *were* modified (fail-safe loader — required by C1); (2) C1 proven via the `loadFixturePools` decision, not a live fetch (deterministic, network-free); (3) transient is raw pool objects, not the 13-field projection (byte-identity guarantee); (4) `npm install` was needed locally, no dependency change.

All proven independent by reverting the 4 generators to base and re-running — identical failure.
