# 113 — Fold `generate-llms.js` onto 112's shared SEO transient (single CI `/pools` fetch)

**Status: BLOCKED (human-judgment SEO-surface tradeoff — NOT a clean byte-identical loop build).**
Promoted + analyzed by the build loop 2026-07-15 (no actionable READY item existed; 110 is READY-after-109 and 109 is BLOCKED on human CF-D1 provisioning per 108). Recorded here so the next loop doesn't re-tread the analysis — loops are already colliding on stale candidates (report 2026-07-15, "the autonomous build loop has caught up to itself").

## Evidence (why this was promoted for evaluation)
- 112's verifier caveat, carried into BACKLOG 112's row and `specs/112-notes.md`: *"`generate-llms.js` keeps its OWN separate `/pools` fetch … so the job still makes 2 fetches/run, not a literal 1 — folding llms onto the transient is a clean next item."*
- CI (`.github/workflows/sitemap-update.yml`) after 112 makes **2** live `yields.llama.fi/pools` fetches per run: one in the snapshot step (writes the `$RUNNER_TEMP/seo-pools.json` $1000-floored transient) and one inside `generate-llms.js` (`fetchYieldsSafe`, generate-llms.js:155-196). The three SEO generators (token/chain/sitemap) already consume the transient via `loadFixturePools`/`--fixture`/`POOLS_FIXTURE`.
- Upside if built: **one fewer DefiLlama fetch per daily CI run**, trust-rail/TVL filtering applied once not twice, llms aligned onto the same fail-safe transient pattern. That is the *entire* upside.

## Why it does NOT cleanly qualify for autonomous build + auto-merge (the blocker)
112's whole safety story is a **provable byte-identical** guarantee: the token/chain generators floor at $100K, the sitemap at $1000, so a $1000-floored transient is a *structural superset* — feeding it can never drop a pool those generators would have kept. That byte-identical proof is exactly what kept 112 (and option A) off the NEVER-list that BLOCKED 102 ("no SEO deletion").

**That guarantee does not transfer to `generate-llms.js`.** Its `analyzeYieldData` (generate-llms.js:251-253) aggregates chain / protocol / token / token-chain TVL over **every** pool with `tvl > 0` — there is **no $1000 (or any) TVL floor** on that aggregation. (Only `pickHighYield` floors, at $10K.) So the $1000-floored transient is *not* a superset for the llms aggregates: any pool with `0 < tvlUsd < 1000` that the full live payload would fold into a top-N chain/protocol/token bucket is silently dropped when reading the transient. The generated `llms.txt` / `llms-full.txt` "Top Chains/Protocols/Tokens by TVL" sums (and, at a boundary, their rankings) become a function of a $1000-floored input where today they are a function of the full input.

### Empirical measurement (live payload, 2026-07-15, sandbox `node` reaching yields.llama.fi)
- Total pools: **15,460**; pools with `tvl > 0`: **15,406**.
- Pools in the dropped gap `0 < tvlUsd < 1000`: **13**, summing to **$4,310** total.
- At the llms display granularity (`$X` M via `(tvl/1e6).toFixed(0)`, or `$X.X` B), $4,310 spread across many buckets shifts **no** displayed value and reorders **no** ranking → **byte-identical today**.

So it is byte-identical *on this payload* but only *empirically*, not *structurally*. A future payload with enough sub-$1000 pools concentrated on one chain/protocol/token (or a single well-placed dust pool, exactly the kind 112's verifier injected to prove the token/chain filter drops something) **would** change the generated SEO/LLM-discovery surface, with **no** guardrail able to catch it (a rigorous byte-identical test would itself FAIL the moment a dust pool lands in a top-N bucket — because the full-payload run includes it and the transient run drops it).

## The question for the human
Is it acceptable for `llms.txt` / `llms-full.txt` aggregate TVL figures to **exclude sub-$1000 pools** (in exchange for one fewer daily CI DefiLlama fetch)?
- **Yes** → this becomes buildable: point `generate-llms.js` at the transient via the shared `loadFixturePools` fail-safe pattern, wire `POOLS_FIXTURE` in the workflow, and add a test that asserts identity *given identical inputs* (mechanism), explicitly documenting that outputs legitimately differ by the excluded-dust contribution. Risk HIGH (generated SEO surface), but a signed-off content-semantics change.
- **No / keep exact** → leave `generate-llms.js` fetching live (today's behavior); the item is closed as WON'T-BUILD, and the 2-fetch CI cost stands as the accepted price of an exact llms surface. (Alternative, larger-scope: widen 112's transient floor to `> 0` so it becomes a true superset for llms too — but that changes 112's shipped artifact and re-opens its byte-identical proof for the token/chain/sitemap consumers; a separate, bigger item, not this one.)

The value (1 fetch/day) is small; the surface (LLM-discovery SEO content) is HIGH and un-guaranteeable byte-identical. Per NORTH_STAR risk policy, an un-guaranteed content change to generated SEO surface is reserved for the human, not an autonomous auto-merge. Hence BLOCKED, not built.
