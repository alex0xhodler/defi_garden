# Spec 257: the north star's denominator is lossy — a third pool-detail entry path fires no `pool_view`

## Evidence

**Code, grepped this tick (2026-08-10) against `main` @ `24f31de724`:**

`grep -n "setCurrentView('pool-detail')" app.js` → exactly **three** sites.
`grep -n "trackPoolView" app.js PoolDetail.js analytics.js` → exactly **two** emit sites
(`app.js:1332`, `app.js:2670`; `analytics.js:212` is the helper definition).

| `setCurrentView('pool-detail')` | entry path | paired `trackPoolView`? |
|---|---|---|
| `app.js:1293` | `?pool=<id>` landing (`source: url_direct`) | yes — `app.js:1332` |
| `app.js:2683` (`handlePoolClick`) | grid card click (`source: card_click`) | yes — `app.js:2670` |
| **`app.js:2787` (`handleCalculateYield`)** | the pool card's "calculate yield" button (`app.js:3048`, `.calculate-yield-btn-new`) | **NO** |

`handleCalculateYield` (`app.js:2778-2791`) runs `Analytics.trackPoolClick(pool,'yield_calculator')` →
`setDetailPool(pool)` → `setCurrentView('pool-detail')` → `setSearchInput(...)` → `window.scrollTo(0,0)`.
A full pool-detail render, no view event. **2 of 3 entry paths instrumented.**

**Prod, measured (Mixpanel defigarden 4042048, prod filter `$current_url contains www.defi.garden`):**
- 2026-08-09 daily (`38ec7ca5`): `pool_click` **1**, `pool_view` **0**.
- That click (`c21d823d`): `source=yield_calculator`, `$region=Iowa`,
  `$current_url=https://www.defi.garden/?token=USDC%60`.
- A pool-detail page rendered in prod and **no instrument recorded it**.

**The claim this breaks.** `NORTH_STAR.md` line 37: *"the CTR formula stays correct as long as `pool_view`
fires exactly once per pool-detail render (verified for both current paths; test asserts no double-fire)."*
Correct about what it verified — `test_northstar_cta_fires.js` covers `url_direct` and `card_click` — and
narrower than the class it guards. `yield_calculator` is named in NORTH_STAR line 42 as an emitter that
"jumps straight into pool-detail"; nobody asked whether that jump was instrumented.

## Hypothesis

We believe **asserting one `pool_view` per transition into `currentView === 'pool-detail'`, enforced by
set-equality between the emit sites and the transition sites in both directions**, will make the north star's
denominator complete and keep it complete, because the defect is not a missing line — it is that nothing
relates the two sets. Confidence: **validated-pattern**.

- **Instance of:** the 212 mirror class — *"when a fact must exist in two places and only one is read at
  runtime, the other is a mirror; mirrors get an equality test against the original in the same commit."*
  Here the two places are "the set of ways to reach pool-detail" and "the set of places that report reaching
  it". Also RAZOR worked example 5 (a guard aimed at the paths someone already thought of). Population: every
  present and future `setCurrentView('pool-detail')` call site — 3 today.
- **Class closed by this item:** **yes for pool-detail**, no for the general case. The same
  transition-vs-emission gap can exist for any view the app tracks (`plan-bloom`, the planner steps). That
  residual is **not** ticketed and is stated here rather than pretended away; a build run that wants it should
  file it, not widen this one.

## Change

Smallest version that satisfies the hypothesis:

1. `handleCalculateYield` emits `trackPoolView` with a `source` distinguishing it from `card_click`
   (proposed value: `yield_calculator` — same vocabulary as its own `pool_click`, so the two events join).
   Additive only; do not touch the existing two emit sites' payloads (saved reports depend on them).
2. A test that derives **both sets from the source at test time** and asserts set-equality both directions:
   parse `app.js` for `setCurrentView('pool-detail')` occurrences and for `trackPoolView(` occurrences, and
   fail if either set has a member the other lacks. A hand-typed list of three line numbers is the same
   mistake as `MIN_TVL_USD = 10000000 // mirrors app.js:801` and is a verifier FAIL.
3. Rendered proof that the new emit actually ships: drive the real app, click `.calculate-yield-btn-new`,
   spy at the **delivered** boundary (`Analytics.track`, not `trackPoolView`) — per
   `playbooks/analytics-regression-triage.md`'s 214 addendum step 3.

**Explicitly OUT of scope:** changing the north-star `source` filter or its definition in `NORTH_STAR.md`
(human-owned); backfilling history (impossible — every past calculator-entry render is unrecoverable, say so
and move on); the `pool_click` surface-attribution gap (**item 258**, separate); any other view's transition
coverage; any change to `handlePoolClick`/`url_direct` payloads.

## Acceptance criteria

- [ ] `grep -c "setCurrentView('pool-detail')" app.js` and the count of `trackPoolView(` emit sites in
      `app.js` are **equal**, and each transition site has an emit site within its own function body.
- [ ] `handleCalculateYield` emits exactly one `pool_view`, and exactly one `pool_click`, per invocation — no
      double-fire (the same property `test_northstar_cta_fires.js` already asserts for the other two paths).
- [ ] The existing `url_direct` and `card_click` payloads are byte-identical to before the change
      (diff the emitted objects, not the source lines).
- [ ] Tests: a new assertion set that derives the transition-site and emit-site sets **from `app.js` at test
      time** and compares them both directions; plus a rendered-Playwright leg that clicks
      `.calculate-yield-btn-new` on the analytics grid and asserts a `pool_view` with
      `source: 'yield_calculator'` reaches `Analytics.track`.
- [ ] Instrumentation: event `pool_view` fires on the `handleCalculateYield` path with properties
      `source: 'yield_calculator'` plus the standard `enrichPoolData()` set (`pool_id`, `pool_project`,
      `pool_chain`, `total_apy`) — verified at the `Analytics.track` boundary, not the helper argument.
- [ ] **Non-vacuity:** delete the new `trackPoolView` call from `handleCalculateYield` → both new assertions
      (set-equality and rendered) must go **RED**; restore byte-identically → **GREEN**. Record both runs'
      output in `specs/257-notes.md`. A set-equality test that passes with the call removed is measuring
      nothing, which is exactly how this defect survived.
- [ ] Population: the transition-site set is parsed from `app.js` at test time, never hardcoded to the three
      sites known on 2026-08-10 — a fourth entry path added tomorrow must fail the gate.

## Measurement

Metric: `pool_view` total, and the north-star CTR `pool_click{source ∈ {garden_cta, protocol_link}} ÷ pool_view`.
· **Build leg (calendar, verifiable now):** the rendered test proves the event fires on the third path — that
is the whole of what can be measured pre-traffic, and it is enough to ship.
· **Traffic leg gate:** window opens at ≥30 real exercised `pool_view` events (crawler-classified never count;
`playbooks/traffic-quality-classification.md` decides). Real count today: **0, 33rd day.**
· Backstop: gate unopened 60d after ship → close UNEXERCISED in LEARNINGS.
· Decision rule: this is a correctness fix to a metric definition, not an experiment — **keep unconditionally**
once the build leg is green. There is no "didn't move" outcome that would justify reverting a denominator.

**Stated plainly for the ledger:** the historical `pool_view` series is a lower bound of unknown tightness.
Prod has exactly one confirmed missed render (08-09). Do not retroactively "correct" any past number.
