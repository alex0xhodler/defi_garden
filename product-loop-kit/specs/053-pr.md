# 053 — Minify JS/CSS in CI: PR explainer (HIGH tier)

## Goal
Cut transfer size on every page load. Backlog 052 already stopped shipping `@babel/standalone` (the ~2.9MB in-browser transpiler) by precompiling `app.js`/`PoolDetail.js` in CI. 053 goes one step further: the ~557K of raw, unminified JS/CSS the site still ships every page load (`app.compiled.js`, `PoolDetail.compiled.js`, `planner.js`, `translations.js`, `style.css`) gets minified, and `home.html`/`plan.html` load the minified copies instead.

## Intuition
Same pattern this repo already uses for sitemaps, token/chain pages, and 052's compile step: a Node script runs, its output is committed, and the *source* stays the hand-edited surface. Nothing here is a "build step" in the sense CLAUDE.md bans — there's still no bundler, no dev-time compile-on-save. It's CI generating derived artifacts, same as `generate-sitemap.js` always has.

`minify-assets.js` does two things, cleanly separated so a freshness test can call the pure half without touching disk:
- `transformJs(file, source)` → runs `terser` (compress + mangle) — used on `app.compiled.js`, `PoolDetail.compiled.js` (052's *output*, not the raw JSX-free source, so the two perf passes stack instead of double-transforming), `planner.js`, `translations.js`.
- `transformCss(file, source)` → runs `clean-css` — used on `style.css`.

The CLI half (`minifyOne`/`minifyAll`) reads each source file, runs the pure transform, writes `<name>.min.<ext>` next to it.

## What changed and why (diff in reading order)

1. **`package.json`** — added `terser` and `clean-css` as `dependencies` (not `devDependencies`) so `npm install --only=production` in CI picks them up, matching how `@babel/core` was added for 052. Added `npm run minify` and inserted `test_minified_assets.js` into the `test` chain right after `test_compiled_assets.js`.

2. **`minify-assets.js`** (new) — the minifier, described above. `JS_FILES`/`CSS_FILES`/`minPath` are exported so the test can stay in lock-step with what actually gets minified without duplicating the file list.

3. **`home.html`** — five swaps: `style.css`→`style.min.css` (both the real `<link>` and its `<noscript>` fallback), `translations.js`→`translations.min.js`, `planner.js`→`planner.min.js`, and the dynamically-injected analytics-app pair `PoolDetail.compiled.js`/`app.compiled.js` → `PoolDetail.compiled.min.js`/`app.compiled.min.js` (the `onload`-chained load order — PoolDetail before app, since `App` references the global `PoolDetail` function — is untouched, just the filenames). Comments at each site point back at source files as the edit surface.

4. **`plan.html`** — same three swaps that apply to the planner path: `style.css`, `translations.js`, `planner.js`. `planner-styles.css`/`brand-icons.js` are untouched — out of this item's named scope (see Deviations).

5. **`test_compiled_assets.js`** — updated (not weakened): its two home.html assertions literally string-matched `addScript('PoolDetail.compiled.js'` / `addScript('app.compiled.js')`. Now that home.html loads the *minified* compiled output, those assertions had to move to a prefix match (`addScript('PoolDetail.compiled` / `addScript('app.compiled`) so they still catch the real regression they exist for (wrong load order) without hardcoding a filename this PR intentionally changed.

6. **`test_minified_assets.js`** (new) — same shape as `test_compiled_assets.js`: for every file in `JS_FILES`/`CSS_FILES`, assert the committed `.min.` output is byte-identical to a fresh re-minify of the current source (catches drift/hand-edits), then assert `home.html`/`plan.html` reference the minified filenames and *not* the raw ones.

7. **`.github/workflows/sitemap-update.yml`** — added a "Minify JS/CSS" step right after the existing 052 compile step, added the new source files (`minify-assets.js`, `planner.js`, `translations.js`, `style.css`) to the `paths:` push trigger, and added the five `.min.` outputs to the commit step's `git add` list.

8. **Committed `.min.` outputs** — `app.compiled.min.js`, `PoolDetail.compiled.min.js`, `planner.min.js`, `translations.min.js`, `style.min.css`, produced by running `node minify-assets.js` once locally (same as any generator script's first commit).

## Deviations from spec (logged in `specs/053-notes.md`)
- Minified exactly the 5 files the spec's Evidence section named. Did **not** touch `planner-styles.css` (83K) or `pool-detail-styles.css` (23K) even though they're sizable — a reasonable follow-up, not silently folded into this diff.
- The app/PoolDetail minified filenames came out `app.compiled.min.js`/`PoolDetail.compiled.min.js` (mechanical `.compiled.js`→`.compiled.min.js`), not `app.min.js` — kept consistent with "minify whatever 052 already produces" rather than inventing a second naming scheme.

## Verification caveat
`test_smoke.js` (the real-Chromium Playwright gate for both router paths) cannot complete in this sandbox: `unpkg.com` (React/React-DOM UMD) and `yields.llama.fi` (pool data) are network-blocked here — confirmed via `curl` (connection failures on both), and reproduced by stashing this diff and running the same test against unmodified `main` with the identical timeout-and-fail outcome. This is the same pre-existing sandbox limitation already on record against backlog 040/044/045/051/052 — **needs a human/CI visual spot-check on the next live run** to confirm both paths still render pixel-identical.
