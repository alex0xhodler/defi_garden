## Goal

`npm test` is a ~91-file `&&` chain. It has been stopping early for weeks, and each stop hides every
file after it. Item 147 cleared position 6, item 156 cleared position 9, and this item clears
**position 10, `test_landing.js`** — the file 156's own notes named by name as the inherited next
stopper.

## The intuition

The landing page's search box works fine. The *test* was waiting for the wrong thing.

`page.waitForURL(...)` defaults to `waitUntil: 'load'`. When you search from the landing page you land
on `/?token=USDC`, and that page asks for ~10 protocol/chain icons from `icons.llamao.fi`, the Mixpanel
bundle from `mp.defi.garden`, and a webfont from `api.fontshare.com`. In the cloud sandbox
browser-originated HTTPS is blocked at the proxy (NORTH_STAR standing decision 2026-07-12), so those
requests never settle, `document.readyState` sits at `interactive` forever, and the `load` event never
arrives. The test timed out waiting on a lifecycle event the sandbox cannot deliver — while the
behaviour it meant to check had already succeeded. Measured: the navigation completes correctly and 9
pool cards render, 12 s before the assertion gives up.

`test_search.js` and `test_smoke.js` already ship the cure for exactly this. `test_landing.js` had
simply never adopted it.

## What changed and why — `test_landing.js` only

Four edits, all additive:

1. **Abort the decorative icon host.** `page.route('https://icons.llamao.fi/**', route => route.abort())`
   — copied verbatim from `test_smoke.js:129`, comment wording included, so the three files stay
   greppable as one pattern.
2. **Route the pools snapshot.** The app has been snapshot-first since item 059, and this test never
   routed `**/data/pools-snapshot*` — so its `FIXTURE_POOLS` was **dead code** and it was silently
   asserting against the committed 738-pool snapshot (148 USDC results). It now serves a deliberately
   stale envelope (`generatedAt: 2020-01-01`), which `tryLoadSnapshot()`'s 6-hour age check
   (`app.js:1119`) rejects, falling through to the routed fixture. The grid now renders 2 pools — the
   fixture — so the gate no longer depends on whatever DefiLlama returned at the last CI bake.
3. **Match ignorable errors by URL, not text.** Chromium's `"Failed to load resource: ERR_..."` message
   never contains the URL, so the old `msg.text()`-only filter could not classify these at all. Now
   checks `msg.location().url` too, with the same host set as `test_smoke.js:40`.
4. **Wait on the URL, not on `load`.** `waitUntil: 'commit'` on the existing `waitForURL`. The
   `waitForSelector('.pool-card')` immediately after is untouched — that render assertion is what
   actually proves the handoff worked.

**No assertion was weakened, reordered or removed.** The verifier diffed all five checkpoints against
`git show origin/main:test_landing.js` line by line to confirm it.
