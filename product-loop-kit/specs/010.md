# Spec 010: Google Search Console indexing failures on the analytics app — diagnose, then fix the top pattern

## Evidence
Human-provided GSC screenshot (2026-07-10, "seeing this for a while"): Soft 404 3,568 · Alternate page with proper canonical 1,955 · Page with redirect 534 · Crawled-not-indexed 22,877 · Discovered-not-indexed 10,585 · Duplicate-Google-chose-different-canonical 521. The affected surface is the analytics app (`?token=/?chain=/?pool=` parameterized URLs) — the repo's sacred SEO lifeline (~35k sitemap URLs) and an explicit guardrail.

## Architectural prior (to be confirmed, not assumed)
Every parameterized URL serves the same client-rendered `home.html` shell; content exists only after JS runs against the live DefiLlama API. Likely mechanics: dead/thin tokens render empty states → Soft 404; tens of thousands of near-identical shells → dedupe/not-indexed; canonical rewriting in the router (home.html sets canonical to `https://www.defi.garden/` + search) interacting badly with `plan.html`/`stories/` → alternate-canonical classes.

## Phase 1 — DIAGNOSIS (this item; no product code changes)
Deliverable: `specs/010-diagnosis.md` with root-cause per GSC class, each backed by observed evidence (fetched URLs, raw HTML, sitemap counts), plus a ranked smallest-fix plan compatible with the hard rules: static hosting, no build step, sitemap/stories generated via `generate-*.js` only, parameterized URLs must keep serving the analytics app unchanged.

## Phase 2 (separate follow-up items, spawned from the diagnosis)
Expected shape (to be validated): (a) client-injected `noindex` on empty/dead result states → kills Soft 404 class; (b) static generation of real-content token/chain landing pages via the existing generate-script pattern (generate-stories.js precedent) → attacks crawled-not-indexed; (c) canonical hygiene between `/`, `?lang`, plan.html, stories; (d) sitemap pruning to URLs with live pool data above dust thresholds.

## Acceptance criteria (phase 1)
- [ ] Each of the 6 GSC classes mapped to a concrete mechanism with evidence (URL examples fetched, response/rendered-content compared)
- [ ] Sitemap audit: URL count by type; % of sitemap URLs whose token/chain has zero live pools today (script the check against the live pools API + committed sitemaps; read-only)
- [ ] Canonical audit: what canonical each surface actually emits (home.html router lines ~70-80, plan.html, stories/*, generated sitemaps)
- [ ] Ranked fix plan: impact × effort per fix, each fix scoped to ≤1 build item, none violating the sacred-URL guardrail
- [ ] Zero product-code changes in this item

## Measurement
GSC classes trend after phase-2 fixes ship (validation cycles are weeks — set expectations in the report). Proxy metric until then: count of sitemap URLs serving real content.

## Risk tier
Diagnosis: LOW (read-only). Phase-2 items: HIGH by default (SEO surface).
