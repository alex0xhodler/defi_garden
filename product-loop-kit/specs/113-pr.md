# 113 — PR explainer (HIGH tier)

## Goal
Kill the second of two live DefiLlama `/pools` fetches the daily `sitemap-update.yml` CI makes. After 112, three SEO generators (token/chain/sitemap) read a single shared `$1000`-floored transient (`$RUNNER_TEMP/seo-pools.json`, written once by `generate-pools-snapshot.js`), but `generate-llms.js` still did its own `fetchYieldsSafe()` live fetch. This folds llms onto the same transient — one fewer external fetch per daily run, one trust-rail filter applied once instead of twice.

## Intuition
112's whole safety story is *byte-identical output*: the token/chain generators floor at `$100K` and the sitemap at `$1000`, so a `$1000`-floored transient is a **structural superset** — it can never drop a pool those generators would have kept. That proof does **not** transfer to llms: `analyzeYieldData` sums chain/protocol/token TVL over **every** pool with `tvl > 0`, no floor. So reading the `$1000` transient legitimately drops sub-`$1000` "dust" from the llms "Top … by TVL" aggregates. On the live 2026-07-15 payload that gap was 13 pools / $4,310 total — below llms' display granularity (`$X M` via `(tvl/1e6).toFixed(0)`), so byte-identical *today*, but only empirically, never structurally. That is exactly why this was BLOCKED for the human, not auto-built. The human answered on 2026-07-15: **EXCLUDE** — accept the sub-`$1000` aggregate drift for one fewer daily fetch. That sign-off makes it *buildable*; it stays HIGH risk (generated SEO/LLM-discovery surface + CI config).

## What changed, in reading order
1. **`generate-llms.js`** — added `loadFixturePools(fixturePath)` and `parseFixtureArg(argv)` immediately after `fetchYieldsSafe`. Copied verbatim from `generate-sitemap.js` (same `raw.data || raw` unwrap, same non-empty-array gate, same **null-on-any-failure = fail SAFE to live**), differing only in using this file's `log()` helper for the two fallback warnings (no `console.warn` convention here).
2. **`generate-llms.js` `main()`** — the single `const { yields, sourceTs } = await fetchYieldsSafe();` line became a prefer-transient / fail-safe-to-live block: `parseFixtureArg(process.argv.slice(2))` → `loadFixturePools`. On a good fixture it uses those pools and stamps `sourceTs` from the fixture file's mtime (the transient was produced by a live DefiLlama fetch earlier in the same CI run, so its mtime is an honest "fetched" time — and `normalizeLlmsContent` scrubs that line from the byte-comparison anyway, so it never forces a spurious rewrite). On `null` (fixture missing/empty/malformed) it falls through to `await fetchYieldsSafe()`, byte-for-byte the old behavior. `pickHighYield(yields)` / `analyzeYieldData(yields)` unchanged.
3. **`generate-llms.js` `module.exports`** — appended `analyzeYieldData`, `loadFixturePools`, `parseFixtureArg` (needed by the test). Existing exports untouched.
4. **`.github/workflows/sitemap-update.yml`** — the "Generate LLM files" step: `node generate-llms.js` → `POOLS_FIXTURE="$RUNNER_TEMP/seo-pools.json" node generate-llms.js`. The named path is the identical literal the snapshot step's `--seo-out` writes (line 72) and the other three generators already consume (lines 84/90/96). Step order (snapshot → token/chain → sitemap → llms) means both the transient and `sitemap.xml` (which llms' `parseSitemap` reads) exist before this step. Nothing else in the workflow touched; the `paths:` trigger list is deliberately unchanged (llms regenerates on every run regardless of what triggered it, so listing it would only cost extra deploys).
5. **`test_llms_shared_source.js`** (new) — pure Node, network-free, writes only under `os.tmpdir()`, exits non-zero on failure (12 assertions). MECHANISM: two end-to-end `node generate-llms.js` runs over the *same* fixture emit byte-identical `llms.txt`/`llms-full.txt` after `normalizeLlmsContent` (faithful, deterministic transient read; env overrides keep output in tmp). DIVERGENCE: 3 sub-`$1000` dust pools concentrated on one chain/protocol/token → `analyzeYieldData(full)` exceeds `analyzeYieldData(filtered)` by *exactly* the dust total, with assertion messages naming it the KNOWN, human-signed-off exclusion (backlog 113), not a regression. C1: `loadFixturePools`/`parseFixtureArg` fail-safe. Guardrail: `git status` unchanged before/after.

## Deviations from spec
None material. Spec left `sourceTs` in fixture mode to the builder; chose the fixture file's mtime (honest, non-null) over `null`/"unavailable". The "identity given identical inputs" leg was implemented end-to-end (child_process, real emitted files) rather than function-level — stronger evidence, matches the 112 test precedent.
