# 154 — explainer: the audit scanner now samples the SEO surface it was supposed to be watching

**Risk tier: HIGH** (operator assessment before verification: `audit-app.js` alone is +184/-11, over the
150-line LOW cap, and "when in doubt → HIGH"). Per NORTH_STAR's HIGH gate this file is a full walkthrough
ending in a 5-question quiz. No NEVER-list category is touched: the scanner only READS rendered pages —
it deletes nothing, de-indexes nothing, changes no generator, adds no dependency.

## The goal, in one sentence

On 2026-07-26 `audit-app.js` reported **10 surfaces, 0 findings** — and on the very same day a human found
item 148 (live `/tokens/8oct2026` pages rendering `<h1>8OCT2026 DeFi Yields</h1>`) by hand, tracing odd
prod URLs. This item removes the structural reason the scanner missed it.

## The intuition

The scanner's static-SEO coverage was one line:

```js
const staticPage = ['/tokens/usdc.html', '/chains/ethereum.html'].find(rel => fs.existsSync(...));
```

`/tokens/usdc.html` exists, so **every run audited exactly one page** — and not a random one: the single
best page in the set, the flagship token, the page most certain to be fine. Meanwhile the checkout carries
**2,079 `tokens/*.html` + 88 `chains/*.html`**. Junk never lives in the flagship page; it lives in the tail
(`tokens/00.html`, `tokens/01.html`, `tokens/8oct2026.html` — all on disk right now). A scanner pointed
permanently at the best page is a scanner that reports clean by construction.

Two things follow, and both are in this diff:
1. **Sample the tail, and rotate** so coverage accumulates across daily heartbeat runs.
2. **Look for page-level nonsense**, not only absurd numbers — the old static branch ran number-sanity
   and page-error checks only, neither of which fires on a perfectly-rendered page about a date.

## What changed, in reading order

### 1. `audit-app.js` — surface construction (`buildStaticSurfaces()`, replaces the one-liner)

- **Anchor kept.** The old fallback pair still runs, still named `static-page`, so `surfacesCovered` never
  regresses and every existing assertion keeps its meaning.
- **Rotating sample added**, named `static-page:<slug>`. Default 6 extra pages (4 token, 2 chain), capped
  at 12 so a heartbeat run stays bounded.
- **Deterministic, no `Math.random`.** An FNV-1a hash of a seed string picks a start index; a stride walks
  the sorted candidate list. Default seed is the UTC date, so a same-day re-run reproduces the exact
  sample (and therefore the exact finding), while the next day covers a different slice.
- **Three overrides**, matching the file's existing env/opts convention: `AUDIT_STATIC_PAGES` (exact paths,
  replaces anchor + rotation — this is how you reproduce a finding), `AUDIT_STATIC_SAMPLE`, `AUDIT_STATIC_SEED`.
- Hub pages are excluded (`index.html` filtered; `tokens/az/*` is a directory, so the `.html` file filter
  drops it for free) — hubs have their own test (`test_hub_pages.js`).

### 2. `audit-app.js` — the `kind: 'static'` branch, three new P1 checks

| check | fires when | the class it comes from |
|---|---|---|
| `junk-slug` | the rendered `<h1>`'s lead token is pure-numeric (`/^[0-9]+$/`) or date-shaped (`/^[0-9]{1,2}(JAN…DEC)[0-9]{2,4}$/i`) | item **148** — `PT-SUSDE-22OCT2026` split on `-` mints the expiry as a "token" |
| `zero-yield-claim` | rendered copy says `up to 0.00% APY` | item **032**'s visible-non-zero-APY gate leaking (the PT/fixed-yield class in PR #309's Finding 1) |
| `empty-table` | zero `.tp-pool-link` / `.cp-pool-link` rows rendered | soft-404 class (item **012**'s honest-empty-state mandate) |

The junk-slug predicate is 148's, mirrored: it must accept digit-**leading** real tickers — `1W`, `4W`,
`13W`, `3CRV`, `1INCH`, `50EIGEN`, `0X0` are live slugs today. Both regexes are anchored with no
wildcard-letter branch, so none of them can match. This is a **detector only**: it emits findings and
changes no page, no generator, no sitemap.

### 3. `test_audit_app.js` — case 1 scoped, and why that is not a weakening

Case 1 asserts "zero P0/P1 on a clean run". Real junk pages exist on disk, so an unscoped full-rotation
run now legitimately reports them. The honest fix is to scope that case to the surfaces it was written
about (the 9 app surfaces + the clean anchor) via `runAudit({only: […]})` — **not** to downgrade a
severity or filter the class away. The true positives stay true positives, and the new test asserts them
directly. If a future run makes this test red because a junk page appeared, that is the system working.

### 4. `test_seo_surface_audit.js` (new) + `package.json`

Five real-Chromium tests, one per acceptance criterion: coverage >1 static page · positive control
(`tokens/00.html` → `junk-slug` P1 quoting the rendered `<h1>`) · negative control (`tokens/usdc.html`
clean) · false-positive guard (digit-leading real tickers do not trip) · determinism (same seed → same
sample, different seed → different sample). Wired into `npm test` after `test_audit_runner.js`. The only
`package.json` edit is that one chain entry — no dependency change.

## Deviations from the spec (all builder-flagged, operator-reviewed)

1. **`opts.staticOnly`** — a test-support flag (not one of the three named env overrides) letting the
   determinism test skip the 9 app surfaces. Reason: static SEO pages carry an absolute-URL
   `<script defer src="https://www.defi.garden/analytics.js">`, unresolvable in-sandbox, which holds
   `domcontentloaded` ~10s per page. Additive, inert when omitted.
2. **Sample ratio at non-default sizes** — the spec pinned only the default (6 → 4+2); the build
   generalized to a 2:1 token:chain ratio, which reproduces 4+2 exactly at the default.
3. **Anchor's own leaf excluded from the rotation pool**, so the rotation can never redundantly re-pick
   the anchor page.

## Pre-existing red, confirmed NOT caused here

`test_audit_app.js` **case 2** (inject −900,719,925,474,097.9 → expect a P0 number-sanity finding on
pool-detail) fails. The operator reproduced it on a clean `origin/main` worktree before verification
(`1 passed, 1 failed`), so it predates this branch. Likely cause worth a separate ticket: items 144/145
added rails that may now null/suppress the injected field, making the test's premise stale — i.e. the
positive control no longer controls anything. Not fixed here (fixing it means touching `PoolDetail.js`,
outside this item's scope, and this loop ships one item).

## Measurement

No Mixpanel funnel metric — loop tooling under the pre-traffic quality mandate (the 142/149 disclosure
pattern). The operational signal lands on the next heartbeat tick: static coverage >1 page, and any junk
page still live shows up as a finding the heartbeat can ticket **without a human tracing URLs by hand**.
