# Spec 008 — Checkout column CTA hierarchy — one action per intent level

**Risk tier: HIGH** (builder's guess, per spec 008's own tier — user-facing beyond pure copy;
touches interactive-control styling and two new translation keys, not just text swaps).

## Goal

The bloom checkout column was stacking three competing calls to action: "Join the waitlist →"
(primary), "📸 Share my garden" (button), "🔗 Copy link" (button, equal visual weight to the
share button). Two equal-weight buttons force the visitor to choose between them at the exact
moment we want a reflex, not a decision. Human prod review (2026-07-10, post-005 screenshot)
called this out directly: "tighter, to convert better — remember the north star." The north star
is viral loop closure (`share_link_opened → plan_created`), and every un-taken share opportunity
is a loop that never gets a chance to close.

This item makes the share card obey one-action-per-intent-level: exactly one button-styled CTA
("📸 Share my garden," the hero share artifact per NORTH_STAR's 2026-07-10 standing decision),
with the link-sharing fallback demoted to a small text link underneath it, plus a shortened
headline and tightened spacing so the whole card reads as one decision, not three.

## Intuition

Buttons compete for attention proportional to how many of them look alike. Two identically
styled buttons ("Share my garden" / "Copy link") sitting side by side don't say "primary and
secondary" — they say "pick one, I don't know which." Demoting the second action to plain
underlined text (no background, no shadow, no equal footing) does the hierarchy work with zero
new UI: the eye lands on the one raised/shadowed control first, and the text link is still fully
there — same click target, same handler, same keyboard access, same analytics — just visually
quieter. This is the same principle as a form's primary submit button vs. its "forgot password?"
link: both work, only one is shouting.

The headline and spacing changes serve the same goal from a different angle: a two-line headline
plus generous padding made the card feel like three separate paragraphs of decision-making;
tightening both makes it visually read as a single compact unit.

## Diff walkthrough

### `translations.js` (EN block ~294, KO block ~762)

- `sharePromptHeadline` shortened from a 59-char two-clause sentence ("Your plan is ready — send
  it to someone who'd want one too.") to a 27-char single clause ("Send this garden to
  someone"), verified to render on one line inside the tightened card at 360px viewport (see
  008-notes.md for the exact character-width math). KO mirrors this with a natural 18-character
  equivalent, not a literal translation.
- Two new keys added directly after `sharePromptHeadline` in both language blocks:
  `shareTextLinkCopy` ("or copy the link" / "또는 링크 복사") and `shareTextLinkNative` ("or
  share the link" / "또는 링크 공유") — one per branch of the existing native-share-vs-copy
  conditional, since a single shared label would have been inaccurate for the native-share case
  (it doesn't copy anything, it opens the OS share sheet).

### `planner.js` (`sharePromptElement`, ~2561–2580)

- The demoted button's `className` changes from `'gp-share-btn gp-share-prompt-btn'` to
  `'gp-share-textlink'` in both branches of the `navigator.share ? ... : ...` ternary. The
  `onClick` handlers (`doNativeShare` / `doCopyLink`) are byte-for-byte unchanged — same function
  references, so `share_link_created` still fires with methods `'native'`/`'copy'` exactly as
  before.
- Label text drops its icon prefix (`↗`/`🔗`) and switches to the new translation keys for the
  resting state; the "✓ Copied!" transient success state (`copySuccess ? ('✓ ' +
  t('shareLinkCopied')) : ...`) is untouched, per spec.
- The primary button (`doShare`, `gp-share-btn gp-share-prompt-btn`, `isSharing`/
  `imageShareConfirm` states) is completely untouched — it's still the only button-styled CTA in
  the card.
- Leading comment updated to describe the new native-share/copy split accurately (was describing
  pre-005 behavior).

### `planner-styles.css` (`.gp-share-prompt*`, ~628–669)

- `.gp-share-prompt` padding tightened `var(--space-16) var(--space-20)` →
  `var(--space-12) var(--space-16)`; `gap` tightened `var(--space-12)` → `var(--space-8)`.
  `margin-top` (space above the card, relative to the checkout panel) is untouched — the spec
  scopes the tighten to internal spacing only.
- New `.gp-share-textlink` rule block: no border/background/padding (no button chrome), colored
  with `--color-text-secondary` at rest and `--color-primary` on hover/active/focus (token-only,
  no new colors), `--font-size-sm`, underlined like the existing `.gp-press-mention a` link
  pattern in this same file, `align-self: flex-start` so it hugs its own text width instead of
  stretching full-width like the button above it, `:focus-visible` outline matching the existing
  `.gp-arrival-dismiss:focus-visible` pattern (`outline: 2px solid var(--color-primary);
  outline-offset: 2px;` — focus rings are a trust rail, never removed), and a chrome-free press
  cue (`transform: translateY(1px)` on `:active`, no shadow).
- Leading block comment above `.gp-share-prompt` corrected (was describing "two full-width
  buttons," now describes one button + one demoted text link).

## Deviations

See `specs/008-notes.md` "Deviations / judgment calls" for the full list with reasoning. Summary:
headline copy used the spec's own suggested EN example near-verbatim (lowest risk); KO headline
is a natural equivalent, not literal; spacing tighten applied to both padding axes and gap
(interpreted "one step" as uniform, not partial); two new translation keys instead of one
(native-share branch needed accurate copy, not a reused "copy" label); demoted control stayed a
`<button>` (not `<a>`) since it triggers JS, not navigation; press feedback used a plain
`translateY` instead of the site's usual `--neuro-shadow-pressed` inset, since that token needs a
background surface to look right and this element deliberately has none; a stale explanatory
comment inside the exact block being edited was corrected; two now-unused translation keys
(`shareLink`, `shareNative`) were left in place rather than deleted (not asked for, small risk to
remove speculatively). The waitlist-CTA instrumentation gap the spec asked me to check for is
confirmed real (zero `Analytics.track*` calls anywhere in the waitlist open-modal or
form-submission code paths) and is noted, not fixed, per spec's explicit instruction.

## What the human should eyeball

- Bloom checkout column at 360px, 768px, 1280px, light and dark mode: confirm the headline is
  one line, only one button-styled CTA is visible, and the text link reads as clearly secondary
  but still comfortably tappable.
- Tab through the card with keyboard only: confirm the text link gets a visible focus ring
  (`outline: 2px solid var(--color-primary)`) and Enter/Space activates it exactly as before.
- Click the text link in a browser with and without `navigator.share` (e.g. desktop Chrome vs.
  mobile Safari) to confirm both the "or copy the link" → "✓ Copied!" swap and the native share
  sheet path both still work.
- Confirm no visual "double CTA" moment remains — the card should read as one decision block, not
  a stack of options.
