# 162-pr — short explainer (LOW tier)

## Goal

`audit-app.js` is the scanner the daily heartbeat runs to find product-quality
bugs without traffic. Until this change it had **never loaded the planner** —
the product's default face. Its 16 covered surfaces were all analytics app
(`?token=`/`?chain=`/`?pool=`) or static SEO pages; `grep` for `plan.html`,
`planner-root`, `landing-root` or `gp-` in `audit-app.js` returned zero hits,
and `signals/audit-findings.json` from the 2026-07-27 07:22Z heartbeat confirms
it live.

That is the same blind-spot class as items 154 (one hand-picked SEO page), 157
(uniform sampling) and 160 (non-HTML surfaces) — three consecutive items closing
gaps in what the scanner can see. This was the largest one left, and it sat on
the surface CLAUDE.md calls "the DEFAULT feature".

## What changed

`audit-app.js` (+85/-6 hand-written), one new test file, one `package.json`
test-chain line. No product file, no dependency, no trust rail, no router, no
user-facing string.

1. Two new driver kinds, alongside the existing `grid`/`pool`/`dead-pool`/
   `static`/`loading` branches:
   - `kind: 'landing'` — bare `/`, the search-first landing (`#landing-root` →
     `.landing-app`).
   - `kind: 'planner'` — `/plan.html`, the Garden Planner (`#planner-root` →
     `.gp-app`), first screen only (the goal picker).
2. Four surfaces appended **after** `pool-detail-ko`, so no existing
   `surfacesCovered` entry moves or is renamed: `landing` (1280), `planner`
   (1280), `planner-360` (360), `planner-ko` (1280, `?lang=ko`).
3. Checks reuse the file's existing helpers and check names only — `dead-end`,
   `number-sanity` (via `auditText`), `page-error` (via `makeErrorSink`),
   `dead-cta`, `responsive` (360 only), `i18n` Hangul (KO only). No new detector
   vocabulary.
4. Disclosed deviation: `--only=`/`--static-only` never existed as CLI flags.
   `opts.only`/`opts.staticOnly` were real `runAudit()` parameters every test
   used, but the `require.main` block called `runAudit()` with no arguments, so
   the flags were silently ignored from the command line. ~12 lines of argv
   parsing now wire them through; the no-flags default path is unchanged
   (verified by the full unscoped run).

## What it found

**Zero findings on all four new surfaces**, in the builder's full run and again
in the verifier's own. The run's 5 findings are the pre-existing `junk-slug`
class on numeric-slug token pages — item 148's territory, gated on PR #306.

Honest limitation: item 146's bug class (a TARGET goal's item price read as a
monthly subscription, rendering six-figure capital the user never entered) lives
several steps past the first screen, so this item's driver cannot reach it. A
later item extending the planner driver into the conversation flow (goal →
funding mode → bloom) is the way to catch that class automatically. Named here
as a real gap, not filed as a ticket — one item, one change.

## Why LOW

Tooling and tests only. `audit-app.js` is not shipped to users — it is not
loaded by `home.html`, `plan.html` or any generated page. Hand-written diff is
well under the 150-line cap, `package.json`'s dependency blocks are untouched,
and the trust rails / `__APP_MODE` router / `?token=`/`?chain=`/`?pool=`
behavior are grep-proven byte-identical. Verifier independently agreed: PASS,
8/8, LOW.
