# 081 — Honest sitemap lastmod: preserve timestamps for unchanged entries so no-change CI runs commit nothing

## Change (surgical, generator + workflow only — no page content, no URL-membership logic)

### A. `generate-sitemap.js` — per-entry lastmod preservation

- Before writing each child, read the **existing on-disk file** (if any) and parse its `<url>` blocks into a map `loc → { lastmod, normalizedEntry }` where `normalizedEntry` is the block with its `<lastmod>…</lastmod>` line replaced by a fixed placeholder. Files are self-generated so a regex parse over the known format is acceptable; a file that fails to parse simply yields an empty map (→ fresh timestamps, current behavior).
- When emitting a URL entry: build it with the placeholder, compare against the old normalized entry for the same `loc` **in the same file**. Identical → reuse the old lastmod; different or new → `now`. Then substitute.
- Index entries: each child's `<lastmod>` = the **max `<lastmod>` value among that child's URL entries** (ISO-8601 compares lexicographically). For the 4 foreign page-sitemaps (`FOREIGN_PAGE_SITEMAPS`, written same-run by the token/chain generators), derive the same way from their file content, falling back to `now` only if no lastmod is parseable.
- Net effect: a child whose URL set + attributes are unchanged is **byte-identical** output (write skipped or identical write — git sees nothing either way), and the index only changes when a child really changed. A no-data-change run touches zero files → the workflow's existing porcelain gate skips the commit → no deploy.
- Export the new helper(s) alongside the existing `module.exports` (080's pattern) for unit testing.
- **Do NOT change:** timestamp format, URL membership, quality gates (`SITEMAP_MIN_QUALIFYING_POOLS`, TVL floor), priority/changefreq computation, `cleanupStaleSitemaps`, hreflang emission. Trust rails untouched.

### B. `.github/workflows/sitemap-update.yml` — concurrency guard

- Add a top-level `concurrency: { group: sitemap-update, cancel-in-progress: false }` so a push-triggered run and the daily cron can't interleave checkouts/pushes (today's 04:32/04:50 pair is the live example of the collision window).
- No other workflow change.

### C. Regenerated committed output

- Do **not** commit a live regen in this PR (unlike 066/080 — there the committed surface was wrong; here the committed sitemaps are correct, only future churn behavior changes). The next daily CI run lands honest lastmods naturally, and its diff shrinking to only-really-changed children is the live proof.
