# 054 — `preconnect` to unpkg + yields.llama.fi

Status: promoted from BACKLOG (score 7.0, LOW) to READY on 2026-07-12, evidence-backed per this spec.

## Evidence this spec is built on

`reports/2026-07-12-pagespeed.md` (finding 3, impact-ordered): *"No `preconnect`. Only `dns-prefetch` for unpkg/yields.llama.fi (home.html); the React/Babel critical fetches want a full `preconnect`. 0 preconnect tags."* Proposed item: *"`preconnect` to unpkg + yields.llama.fi (keep dns-prefetch fallback)."*

Grep-confirmed against the live repo (2026-07-12, post-052/053 which already shipped precompiled/minified JS — this spec is unaffected by either, it only touches `<head>` resource hints):
- `home.html:59-60` — `<link rel="dns-prefetch" href="//unpkg.com">` + `//yields.llama.fi`, no `preconnect` anywhere in the file.
- `home.html:137-138` — `<script defer crossorigin src="https://unpkg.com/react@18/umd/react.production.min.js">` (+ react-dom) — the actual critical-path fetch from unpkg, on every analytics/SEO page load (`__APP_MODE==='analytics'` branch) and gated behind DNS-only today.
- `home.html:191` — `fetch("https://yields.llama.fi/pools")` — the live pool-data fetch every render depends on.
- `plan.html:49-52` — same two `dns-prefetch` hosts, plus `<link rel="preload" ... as="script">` for the same two unpkg React UMD bundles (no `preconnect`), and the identical `defer crossorigin` script tags at `plan.html:74-75`.
- Both files load React from unpkg on every page view (planner default `/` via plan.html, analytics via home.html) — `preconnect` benefits both router paths identically, not just one.

`dns-prefetch` alone resolves DNS but not the TCP+TLS handshake; `preconnect` does all three, saving one full round-trip before the deferred scripts (and the `yields.llama.fi` fetch that fires shortly after) can start. Because the React scripts are `crossorigin`, and the `yields.llama.fi` fetch is a plain same-page `fetch()` (no credentials), unpkg's preconnect needs the `crossorigin` attribute to match the actual request mode; yields.llama.fi's does not.

## Change

Add `preconnect` hints alongside (not replacing) the existing `dns-prefetch` fallback, in both `home.html` and `plan.html`:

```html
<link rel="preconnect" href="https://unpkg.com" crossorigin>
<link rel="preconnect" href="https://yields.llama.fi">
<link rel="dns-prefetch" href="//unpkg.com">
<link rel="dns-prefetch" href="//yields.llama.fi">
```

- `home.html`: insert immediately before the existing `dns-prefetch` pair (lines 59-60), inside the existing "Performance: Preload critical resources" block.
- `plan.html`: insert immediately before its existing `dns-prefetch` pair (lines 51-52), inside its equivalent preload block.
- No other lines touched. `dns-prefetch` stays as the fallback for browsers/edge cases that cap `preconnect` connection reuse (both hints coexisting is the standard, recommended pattern — not redundant).

## Acceptance criteria

1. Both `home.html` and `plan.html` carry a `preconnect` link to `https://unpkg.com` (with `crossorigin`, matching the `crossorigin` React script tags) and one to `https://yields.llama.fi` (no `crossorigin` — the pools fetch carries no credentials).
2. Existing `dns-prefetch` tags for both hosts remain untouched in both files (fallback preserved, per the report's explicit instruction).
3. No other content in either file's `<head>` changes — this is a resource-hint-only diff, nothing else in the router, canonical logic, or script loading order moves.
4. `test_smoke.js` (Playwright, both sacred router paths: bare `/` → planner, `?token=USDC` → analytics app with pool cards) passes with zero new console/page errors.
5. `npm test` (the three node test files per NORTH_STAR.md's Commands section) still green.
6. Diff stays surgical: 4 new lines total (2 per file), no deletions beyond what's listed above.

No constraints beyond keeping `crossorigin` consistent with the actual script tags' cross-origin mode (unpkg yes, yields.llama.fi no, since the latter is an uncredentialed `fetch()` not a `<script crossorigin>` tag).
