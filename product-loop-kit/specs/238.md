# Spec 238: retire the terminal skin — one type system on the Quiet base

## Evidence
UX audit F3, measured ON `claude/loop-225` (not main): 11 `text-transform: uppercase` rules (identical
count to main — untouched by the reset), 4 hardcoded `'SF Mono','Monaco',…` stacks (style-225.css:3259,
3389, 3463, 3696 + `monospace` at 3906) beside the single tokenized `--font-family-mono` (line 93),
`.pool-symbol` / `.pool-context-inline` mono-uppercase badges ("ON LIDO • ETHEREUM"). The grid's data
rows read as a different product from the sentence-case landing — visible in the human's screenshots.
Plus `style.css:1644` `.logo:hover { transform: scale(1.02) }` — a banned scale-pop hover with no
reduced-motion guard, flagged by 225's verifier as pre-existing and left for its own ticket (this is it).

## Hypothesis
Sentence-case labels + mono restricted to the token and to tabular numerals only will close the last
visible "different product" gap between grid rows and the rest of the Quiet system. Confidence:
supported (the human's screenshots show exactly this contrast; 225's instrument proves the component
layer is already unified, leaving typography as the dominant remaining divergence).
- Instance of: hardcoded style values bypassing the token layer (the class 225 exists to kill).
- Class closed: font-stack half yes (0 hardcoded mono stacks is testable); uppercase half scoped to
  label/badge text — uppercase that is DATA (ticker symbols are inherently uppercase strings) is not a
  styling defect; state the residual count in notes.

## Change
`style.css` (+ regen `style.min.css`): every hardcoded mono stack → `var(--font-family-mono)` or removed;
mono usage limited to tabular numerals (APY/TVL/$-day figures) if kept — labels, badges, protocol/chain
context lines ("on lido • ethereum") drop `text-transform: uppercase` and render sentence case with the
body stack; `.logo:hover` scale-pop deleted (press physics stay). No markup changes unless a badge's
casing comes from JS string literals (then fix at the render site, EN+KO via translations.js where
user-facing). OUT of scope: component geometry (done by 225), any new font.

## Acceptance criteria
- [ ] `grep -c "SF Mono" style.css` → 0; every `font-family` in style.css is a token reference or the
      body stack (enumerated by test, not hand-checked).
- [ ] Uppercase transforms on label/badge classes removed — test enumerates `text-transform: uppercase`
      rules and asserts each survivor is on an allowlisted data-display class with a one-line reason
      (the 189-allowlist pattern: data, keyed, reported by size).
- [ ] `.logo:hover` scale transform gone; no `transform: scale` on any `:hover` rule repo-wide
      (CLAUDE.md ban, now machine-enforced) — reduced-motion contexts show no motion.
- [ ] Rendered grid row + pool hero + landing side-by-side (Playwright, both themes): computed
      font-family of labels identical across surfaces; numerals may share the mono token.
- [ ] Non-vacuity: reintroduce one hardcoded stack → enumeration test red; restore → green.
- [ ] Visual regression pass at 360/768/1280 × light/dark on grid/detail (the 225 screenshot harness,
      `specs/225-screenshots/capture-shots.js`, reused).

## Territory notes (added at build time, 2026-08-10 — build.md §2)

**The tree this spec was written against no longer exists.** The spec measured `claude/loop-225`
(2026-08-05). Since then item 247's design world shipped to main across three human-merged PRs —
#409 `514b4ba236` (08-07T12:55), #412 `6c33899fee` (certificate button skin app-wide), #413
`60278d4d47` (world buttons) — under the human directive "ONLY SOTA GRADE WORK given the ICP". The
BACKLOG row's "247 sequencing caveat" is exactly this. Re-measured on main at pickup:

1. **Mono half — 247 already closed most of it.** `grep -c "SF Mono" style.css` → **0** on main
   (criterion 1's literal grep already passes; it passes *vacuously*, which is why the enumeration
   test is the real deliverable). Remaining hardcoded stacks in product CSS: **3** —
   `style.css:4473` (`.pool-info-item .value.token-pair`, renders via `app.js:3667`),
   `planner-styles.css:2729` (`.gp-waitlist-link-text`), and `planner-styles.css:1785`
   (`.gp-journey-status`, a token ref carrying a dead hardcoded fallback stack). The five
   `font-family` declarations inside `@font-face` blocks (`style.css:818/831/840`,
   `pool-detail-styles.css:21/30`) are descriptors, not declarations — allowlisted by construction.

2. **Uppercase half — the spec's hypothesis is FALSIFIED on main, and this loop will not override a
   human design directive on a guess.** The spec assumed uppercase was terminal-skin residue the
   Quiet reset had failed to clear. `git blame` shows the opposite: the 247 world *authored*
   uppercase micro-labels. `pool-detail-styles.css:654` (`.pool-action-apy-label`) came from #412;
   `planner-styles.css:1929/1934` (`.gp-goal-cat-label`, `.gp-sub-ladder-title`, uppercase at
   `letter-spacing: 0.22em` on `--font-family-display`) came from #413. Uppercase-with-wide-tracking
   is a deliberate convention of the certificate world, not a leftover. Current population: **24
   `text-transform: uppercase` rules** across the five product stylesheets (style.css 6,
   planner-styles.css 11, pool-detail-styles.css 4, landing-styles.css 2, stories/stories.css 1) —
   not the spec's 11, which counted one stylesheet on a different tree. (This number was first
   written here as 23 from a hand survey that omitted `stories/stories.css`; the enumeration test
   derived 24 from the files and the hand count was corrected to match the instrument — which is the
   argument for deriving the population at test time rather than listing it.)
   **Criterion 2 is therefore re-scoped, not dropped:** enumerate every uppercase rule against an
   allowlist that requires a one-line reason per entry (the 189 pattern the criterion already names),
   seeding the allowlist with the current 23 as the 247-world baseline, and change **no rendering**.
   That closes the class the criterion actually cares about — *an un-reasoned uppercase rule can no
   longer be added* — without this loop silently reverting the newest human-directed visual world.
   **Open question for the human (does not block the rest):** of the 23, which are the certificate
   world's intended micro-label convention and which are terminal-skin residue that should go
   sentence-case? The allowlist file is the answer sheet — flip a reason to `residue` and the sweep
   becomes a mechanical follow-up ticket.

3. **Scale-pop half — the class is wider than the spec's instance.** `.logo:hover` (`style.css:5200`,
   the ticketed one) is not alone: `.modal-close:hover` (`style.css:4409`) is the same banned
   scale-pop, and `.modal-close:active` (`style.css:4415-4416`) declares `transform: translateY(1px)`
   and then immediately overrides it with `transform: scale(0.95)` — the press physics CLAUDE.md
   mandates are dead code at that call site. Criterion 3 already states the weak form ("no
   `transform: scale` on any `:hover` rule repo-wide"); all three are fixed.
   **Residual stated with a number (RAZOR class rule):** `@keyframes yieldBounce`
   (`style.css:6079-6089`) is a scale-pop animation on a bounce easing
   (`cubic-bezier(0.34, 1.56, 0.64, 1)`) — both banned by CLAUDE.md, applied via `.yield-pulse-active`.
   It is **not** a `:hover` rule, so it is outside criterion 3's predicate and outside this diff.
   **1 rule, 1 keyframe block, ticketed for its own item — this item does not close the
   banned-motion class, only the hover half of it.**
