# Spec 236: one nav contract across landing / grid / pool-detail

## Evidence
UX audit F1 (`reports/2026-08-05-ux-audit.md`, human's prod screenshots): landing header = wordmark +
"Search yields / How it works / My garden" + lang/theme; grid = search+tabs, ZERO nav links
(`grep 'How it works\|My garden' app.js` → 0 hits); pool detail = breadcrumb pill "Search Results →
USDC Pool" (rendered even on direct `?pool=` arrivals with no search context) + no nav. 225's divergence
instrument unified header *styling* (56px, grid 113px) — the STRUCTURE divergence is untouched.

## Hypothesis
One persistent header band (wordmark → `/`, the three nav destinations, lang+theme in identical
positions) on all three surfaces will make them read as one product and give every analytics surface a
path back to the planner/"My garden" — the retention surface. Confidence: supported (the human named
the incoherence twice: Q2b root-cause + 2026-08-05 directive).
- Instance of: cross-surface IA divergence (the two-design-systems root cause, structural half).
- Class closed: for the three audited surfaces yes; stories/ static pages excluded (count: 3 persona
  pages + generated estate keep their own lightweight header — out of scope here, note left open).

## Change
Shared header band on landing (`landing.js`), grid (`app.js`), pool detail (`PoolDetail.js`): wordmark,
nav (Search yields / How it works / My garden), lang + theme controls — SAME order/position, 225's Quiet
classes only (invent no new visual style). Grid keeps its search bar + category tabs BELOW the band.
Breadcrumb renders ONLY when arrival context exists (came from grid); direct arrivals show the band only.
All strings via translations.js, EN + natural KO. OUT of scope: stories/ and generated static pages;
any visual-token change; mobile nav drawer (band must simply not overflow at 360px).

## Acceptance criteria
- [ ] Rendered-Playwright (house fixture pattern) on `/`, `/?token=USDC`, `/?pool=<live id>`: the band's
      wordmark/nav/controls present with identical DOM order and identical computed geometry (±1px)
      across all three, at 360/768/1280, light+dark.
- [ ] "My garden" from grid and pool-detail navigates to the planner surface (assert route, not href).
- [ ] Direct `?pool=` arrival: no "Search Results" breadcrumb; grid→detail arrival: breadcrumb present.
- [ ] No horizontal body scroll at 360px on any of the three; controls pressable (mobile-controls rail).
- [ ] EN+KO for all band strings; focus rings intact; `?token=/?chain=/?pool=` behavior byte-unchanged
      otherwise (sacred URLs render pool cards — guardrail test stays green).
- [ ] Non-vacuity: remove the nav from ONE surface → the cross-surface identity test goes red; restore.

## Measurement

and planner sessions (no gate claimed).
