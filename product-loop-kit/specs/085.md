# 085 — BUG (human ticket 2026-07-14): subscription checkout auto-selects Spotify alongside the picked service

Status: IN_PROGRESS (2026-07-14)
Risk: HIGH (planner bloom/checkout render path — user-facing beyond copy; regenerated planner.min.js)
Score: 8.6 — human-reported production bug at the card-funnel checkout step (SUBSCRIPTION archetype is
"the product's front door" per the 2026-07-12 business-model decision; NORTH_STAR: a bug at a funnel
step outranks any experiment).

## Report (human, verbatim intent)

"When user picks from subscription chatgpt plus for example, selects the risk, the chatgpt and spotify
will be selected at checkout — and with any other subscription spotify is auto selected by default."
Only the picked subscription should be selected at checkout.

## Root cause (operator triage, read-only)

- `planner.js:1429` — `slideCapital` defaults to `propCapital || 5000`.
- `planner.js:1507-1513` — the checkout mix seed effect runs while `!mixTouched` and sets
  `selectedSubs = coveredBundle(slideCapital, apy, goal).covered.map(id)` — i.e. EVERY anchored-ladder
  rung the capital already covers, not the user's pick. The anchored ladder (`buildLadder`,
  planner.js:150-183) is [anchor, then rest ascending by monthly]; Spotify ($12/mo) is the cheapest
  non-anchor rung, so whenever the default $5,000 (or the user's capital) covers anchor + $12/mo at the
  current blended APY, Spotify is silently added to the selection. Example: goal=chatgpt ($20/mo) at 8%
  → anchor forever ≈ $3,000, +Spotify cum $32/mo → ≈ $4,800 ≤ $5,000 → seeded mix = [chatgpt, spotify].
- The fallback branch (`if (!ids.length) ids = [goal]`) proves `[goal]` is already a valid mix shape.

## Change

In the seed effect (planner.js:1507-1513): seed `selectedSubs` with exactly `[goal]` — the user's picked
subscription — instead of the covered bundle. Nothing else about the mix UX changes: the ladder still
renders all rungs, `unlocked`/`pct` visual states still come from the capital, the user can still toggle
any additional rungs on (setSelectedSubs at planner.js:2093, which sets `mixTouched`), and
`currentMixStats`/capital sync behave as today from the seeded `[goal]`.

Constraints:
- Guard the shape: only seed `[goal]` when `goal` resolves via `brandForId`/ladder/subscription-archetype
  (the effect only runs in subscription bloom, but keep the existing falsy-goal safety).
- DO NOT regress the share/arrival path (024/024-refinement): a restored/shared plan carrying an explicit
  `mix` must still reproduce the sender's exact mix. Trace how `plan.mix` reaches the bloom component
  (planner.js:1747/1775 write it; check the restore path around planner.js:3325) — if a prop-supplied mix
  seeds `selectedSubs`, it must keep winning over the new `[goal]` seed. If shared plans re-derive the mix
  on arrival through this same effect, verify a shared 2-subscription garden still arrives as 2
  subscriptions (rendered Playwright check, not an assumption).
- `planner.min.js` regenerated (plan.html loads the min — 061's caught-bug precedent) and byte-idempotent.
- EN/KO untouched (no copy change).
