# 080 — Deploy 013's sitemap quality gate for real (HIGH-tier explainer)

## Goal

Item 013 (shipped 2026-07-11) added a quality gate to `generate-sitemap.js`: a URL only
enters a sitemap if its exact filter view has ≥2 non-anomalous pools at ≥$10M TVL — the
same predicate the live app renders with by default. The 010 GSC diagnosis identified the
old 20k+-URL programmatic sitemap as the driver of the "Discovered/Crawled — currently
not indexed" crisis. 013's gate was supposed to deploy via the daily
`sitemap-update.yml` CI run. It never did. This item makes it deploy — nothing more.

## Intuition

The daily CI runs `node generate-sitemap.js`, which regenerates ALL ~106 child sitemaps,
the index, and robots.txt in the CI workspace. But the workflow's `git add` names only 5
sitemap files (the index + the four token/chain page-sitemaps owned by other
generators). Everything else the generator wrote was silently discarded, every day.
Worse, the freshly regenerated INDEX (with today's `<lastmod>`) *was* committed — over
stale children — so the deployed index claimed freshness for content frozen at
pre-gate state (~25k URLs). And 12 child sitemaps the generator no longer produces at
all (`sitemap-combos.xml`, `sitemap-chains.xml`, 10 `sitemap-chain-*.xml`) stayed
committed and deployed, unreferenced by the index.

How we know: 078 (shipped 2026-07-13) made the CI commit message report honest counts.
Its first live run (commit `6e2853340`, 2026-07-14 03:27 UTC) said "6202 total URLs"
while the committed tree held 25,051 — the count saw the fresh workspace, the commit
kept the stale files. specs/013-notes.md line 21 shows 013's author believed the CI
"commits regenerated sitemap files"; the git add list proves it didn't for the gated
files.

## What changed, in diff reading order

1. **`generate-sitemap.js`** (+44 lines)
   - `FOREIGN_PAGE_SITEMAPS` constant: the four page-sitemaps owned by
     `generate-token-pages.js`/`generate-chain-pages.js` — never deleted by this script.
   - `cleanupStaleSitemaps(writtenFilenames, dir)`: after the index is written, deletes
     root files matching `/^sitemap-.*\.xml$/` that were NOT written this run and are
     not foreign page-sitemaps. Logs each deletion + summary (auditable, never silent).
     The regex requires the hyphen, so `sitemap.xml` (the index) can never match.
     Exported for the test; CLI behavior otherwise unchanged. This is the 031
     stale-artifact-cleanup pattern applied to sitemap children.
   - The write loop now records `writtenFilenames` — the cleanup's source of truth.
   - Trust rails (`SITEMAP_MIN_TVL`, `APY_SANITY_LIMIT`, gate logic) byte-identical.
2. **`.github/workflows/sitemap-update.yml`** (+1 line)
   - `git add -A -- 'sitemap*.xml'` after the existing add-list. The pathspec is QUOTED
     so git (not the shell) expands it — a shell glob cannot match a deleted file; `-A`
     stages deletions of tracked files. Verifier demoed D/M/A staging in a scratch repo.
3. **`test_sitemap_cleanup.js`** (new) + **`package.json`**
   - No-network temp-dir test: stale child deleted; page-sitemap kept; written child
     kept; `sitemap.xml` kept; non-sitemap file kept. Wired into the `npm test` chain.
     Verifier mutation-checked it (removing the keep-set guard or loosening the regex
     makes it fail).
4. **Regenerated output, committed live** (106 children + index + robots.txt modified,
   12 orphans deleted): real generator run this session (full 15,408-pool fetch).
   Deployed sitemap URLs: 25,051 → 4,774 (448 generator-owned + 4,326 in the four
   page-sitemaps). `sitemap-tokens-all.xml` 4,147→107; `sitemap-chain-Ethereum.xml`
   2,301→67. Index/children now consistent: all 110 refs resolve, zero unreferenced
   root children. 066 precedent: network is open, so real output ships with the fix
   instead of waiting a day for CI.

## Why this is safe (NEVER-list assessment, verifier-concurred)

No content page is deleted or noindexed. `?token=`/`?chain=`/`?pool=` URLs, the
`/tokens/`+`/chains/` static pages, and all app code are untouched — only sitemap
*membership* changes, which is precisely the change 013 shipped through the sanctioned
review path with "expect a material drop" documented. The 12 deleted files are stale
sitemap *list* files unreferenced by the deployed index. The verifier independently
judged the NEVER list not triggered. Residual flagged for the human: an 81%
sitemap-membership shrink lands during the manual GSC watch window — that is the
intended effect of 013, now actually measurable.

## Deviations from spec

None functional. The builder ran `npm install` (node_modules absent in the sandbox;
`fast-xml-parser` was already a declared dependency — nothing new added). One sentence
in 080-notes.md misstated which total included the page-sitemaps; corrected
pre-commit per the verifier's finding.
