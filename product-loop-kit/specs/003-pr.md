# 003 — `npm test` smoke gate: explainer + quiz

Branch: `loop/003` (`926415e`) · Risk tier: HIGH (new dependency) · Verifier: PASS

## Goal
Autonomy policy (c) merges any tier the moment `npm test` is green and the
verifier agrees — but until this item, "tests green" only meant the planner's
pure-function unit tests passed. Nothing proved the router itself still
worked. A loop could ship a broken `home.html` and auto-merge it, because the
only thing gating merge had never looked at a browser.

## Intuition
CLAUDE.md already states the manual check every human/agent is supposed to
run after touching the router: load `/` and confirm the planner shows up,
load `/?token=USDC` and confirm pool cards show up. That check just never
lived in code. This item turns it into an automated `npm test` step —
without inventing new infrastructure, since the repo already has zero build
step and three plain `node file.js` test scripts chained with `&&`.

## What changed, in reading order
1. **`package.json`** — added `playwright` under `devDependencies`, and
   appended `node test_smoke.js` to the `test` script, after the three
   existing unit-test files. `dependencies.fast-xml-parser` is untouched.
2. **`package-lock.json`** — the corresponding lockfile update for the new
   devDependency (auto-generated by `npm install --save-dev playwright`,
   not hand-edited).
3. **`test_smoke.js`** (new file) — the smoke script itself:
   - Spins up a plain `http.createServer` static file server over the repo
     root (no new server dependency — this repo already has zero build
     step, so a hand-rolled server keeps that true). It special-cases
     `GET /` to return `home.html`'s bytes, mirroring `vercel.json`'s
     production rewrite (`"/"` → `/home` → `home.html`), since there's no
     `vercel dev` available in this environment.
   - Launches Chromium via `playwright` and, at 360/768/1280px, loads `/`
     and waits for `#planner-root [class*="gp-"]` — a real, heavily-used
     class prefix from the Planner component tree (not a generic "any
     child" check, which would pass even on a blank mount).
   - Loads `/?token=USDC` and waits for `.pool-card` — the class app.js
     gives every rendered pool card, which only appears once live
     `yields.llama.fi` data has round-tripped through the analytics app.
   - Collects `pageerror` and `console.error` events on every load, with a
     narrow ignore pattern (`mp.defi.garden|cdn.mxpnl.com|mixpanel`)
     matching CLAUDE.md's documented carve-out that external analytics
     fetches are allowed to fail without failing the check.

## Deviations from spec (full reasoning in `specs/003-notes.md`)
- No `@playwright/test` runner/config — a hand-rolled script matches the
  existing `node file.js` convention and keeps the diff smaller.
- `/` is served by the smoke script's own server rather than `vercel dev`,
  since the router's actual logic is query-param-driven, not
  pathname-driven (see `home.html`'s `ANALYTICS_PARAMS` check), so this is
  behaviorally identical to production for what this test needs to catch.
- Found (not fixed, out of scope): `npm audit` shows a critical,
  pre-existing vulnerability in `fast-xml-parser` (used by the SEO
  generator scripts), predating this branch. Logged as a new backlog
  candidate — fixing it is a breaking major-version bump to a different,
  unrelated dependency and deserves its own HIGH-risk item.

## Verification
- `npm test`: 185 pre-existing unit assertions + 6 new smoke assertions,
  all green, ~7.7–8.5s total (target: under ~2 minutes).
- Sabotage check (both self- and verifier-corroborated): forcing
  `window.__APP_MODE = 'planner'` unconditionally in `home.html`'s router
  made the 3 analytics-mode smoke assertions fail (`.pool-card` never
  appears) while the 3 planner-mode assertions kept passing — exactly the
  fault this test exists to catch. Reverted cleanly; `git diff` on
  `home.html` is empty on this branch.
- Diff scope confirmed by both builder and verifier: exactly
  `package.json`, `package-lock.json`, `test_smoke.js` — zero product-code
  changes.
