# Spec 202: `src` — the product's own arrival tag is the one attribution param analytics drops

**Promoted by the build loop, 2026-08-01** — `BACKLOG.md` had **no READY item** at pickup (197/198/199/200/201
all shipped and merged today; every row 001-201 parses SHIPPED / DONE / PARKED / BLOCKED / CULLED). Promotion
follows `build.md`'s no-READY rule, from documented evidence already in the repo.

## The claim, in one line

`analytics.js`'s `captureAcquisition()` captures `utm_*`, `ref`, `gclid`, `fbclid`, `twclid` and
`referring_domain` — but **not `src`**, which is the tag the product's *own* internal acquisition links
carry on every surface. So every event except the hand-threaded `waitlist_*` family is unattributable, and
the heartbeat's 20-day "`page_view` by `src` → `undefined` × 47, zero tagged arrivals" reading is measuring
a property no emitter can populate.

## Evidence (all measured in-repo, before any change)

### 1. `src` is the repo's own arrival tag, on three surfaces, all shipped

| where | link shape | items |
|---|---|---|
| every static token/chain SEO page (2,093 + 87 EN, same again KO) | `/plan.html?waitlist=1&src=seo_token` (`tokens/usdc.html`, grepped) / `src=seo_chain` | 062, 066, 075 |
| every spotlight pack link | `params.set('src', SPOTLIGHT_SRC)` → `x_spotlight` (`generate-spotlight.js:236-248`) | 064, 069 |
| **the north-star CTA itself** | `plan.html?goal=…&fm=capital&years=…&src=pool` (`PoolDetail.js:365`, `gardenThisPoolHref`) | 143 |

### 2. `captureAcquisition()` does not capture it

`analytics.js:41-54` — the captured list is literally:

```js
['utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content',
  'ref', 'gclid', 'fbclid', 'twclid'].forEach((k) => { … });
```

`grep -n "src" analytics.js` → **zero** hits for the param. The session-scoped `this.acquisition` object is
spread onto every event by `getBaseContext()` (`analytics.js:76-78`), so a captured key reaches
`page_view`, `session_start`, `pool_view`, **`pool_click`** (the north star), `plan_created`, `plan_saved`,
`share_link_created` and the rest for free. `src` never enters that object, so it reaches none of them.

### 3. The only place `src` reaches Mixpanel today is hand-threaded, and only on the waitlist family

`planner.js:4029` reads `urlParams.get('src')` into `waitlistSrc` and passes it as the **`source`** property
to `trackWaitlistOpened` / `…Submitted` / `…EmailEntered` / `…SubmitAttempt` / `…Error` (`:4042`, `:4059-4093`).
`planner.js:4179` reads it again for the `src === 'pool'` arrival branch (143). Neither path puts it on any
other event, and neither is what a `page_view` breakdown reads.

### 4. The heartbeat has been reporting the consequence as a finding for 20 days

`reports/2026-08-01.md`: *"`src` = `undefined` × 47, **20th day of zero tagged arrivals**"*, and
`signals/2026-08-01.md:63`: *"Prod `page_view` by `src` over 14d: **one row, `undefined` = 47**."* That row
is not evidence about distribution. `page_view` has no `src` property to break down — a spotlight arrival, an
SEO-page waitlist arrival and a cold direct hit are **indistinguishable by construction**. This is the
"detector that cannot see" class the loop has fixed five times on its own tooling (166/198/199/200/201);
this instance is on the product's analytics, on the north-star funnel.

### 5. It is SEO-safe to attribute this way — already proven by `canonical.js`

`canonical.js:33` `CANONICAL_PARAMS = ['token','chain','pool','poolTypes','protocols','minTvl','minApy']` —
`src` is not on it, so it is stripped from the self-canonical (spec 011's "junk params never fragment one
page's indexing signal"). Tagging arrivals cannot fragment indexing.

## Change (leg A only — the emitter)

**One file, `analytics.js`.** Add `'src'` to `captureAcquisition()`'s param list, with the treatment `ref`
already gets: `String(v).substring(0, 200)`, omitted entirely when absent, inside the existing try/catch.
Comment it as the internal-link counterpart to `ref` (seo_token/seo_chain/x_spotlight/pool), so the next
reader knows why an internal tag sits next to third-party click ids.

Nothing else. `planner.js`'s `source` threading stays exactly as-is (different property name, different
meaning: `source` on `pool_click` is CTA identity per NORTH_STAR:29 — the two never collide).

## Acceptance criteria

1. `Analytics.captureAcquisition()` returns `src: '<v>'` for a landing URL carrying `?src=<v>`; key is
   **absent** (not `"undefined"`) when the param is absent; value capped at 200 chars. Proven by extending
   `test_analytics_acquisition.js` (the 064 unit rig, `require('./analytics.js')`).
2. `getBaseContext()` carries it onto an emitted event — asserted through an event's props, not by reading
   the source array.
3. **Rendered proof, real Chromium, fixture-routed** (NORTH_STAR 2026-07-11 rule; `test_analytics_fires.js`
   is the pattern — same local HTTP server + `/opt/pw-browsers/chromium` + mixpanel stub): loading
   `/plan.html?waitlist=1&src=seo_token` — the exact URL every static token page links to — produces at
   least one `mixpanel.track` call whose props include `src === 'seo_token'`, **and** the pre-existing
   `waitlist_opened` `source` property is still `'seo_token'` (no regression, no collision).
4. **Rendered, north-star surface**: `/?pool=<id>&src=seo_token` emits `pool_view` carrying
   `src === 'seo_token'`. This is the mechanism the deferred generator leg needs; proving it here is what
   makes that leg a pure generator change.
5. **Control, rendered**: the same two pages loaded WITHOUT `?src=` emit no `src` key at all.
6. **Non-vacuity**: deleting `'src'` from the list turns the new assertions red **by name** in every new/

8. Green: the new/changed test files, plus NORTH_STAR's verbatim Test line

9. Bookkeeping in the SAME commit (2026-07-13 rule): `BACKLOG.md` row 202, `specs/202-notes.md`,

## What this ships — stated honestly

A **measurement fix, not a traffic fix.** Zero tagged arrivals will very likely still read zero tomorrow,
because there is little traffic and the SEO estate's `?pool=` deep links are not yet tagged (deferred leg,
below). The deliverable is that the property becomes *populatable*: the spotlight packs (20 days unposted)
and the 2,180 static pages' waitlist links become attributable the moment anyone clicks one, and the
heartbeat's `undefined` row stops being a vacuous signal it has repeated for 20 days.

## Out of scope (do not build here)

- **Adding `src=seo_token` / `src=seo_chain` to the 8 `?pool=` deep links on the static estate**
  (`generate-token-pages.js` / `generate-chain-pages.js`). It is the natural leg 2 and it is why criterion 4
  exists — but it regenerates ~4,360 HTML files, is HIGH-tier SEO surface, and deserves its own item with its
  own diff. **File it as the follow-up in `202-notes.md`; do not build it.**
- Renaming `source` → `src` (or vice versa) anywhere. Two different properties with two different meanings.
- Any Mixpanel-side report/query change, any new event, any change to what `planner.js` does with `src`.
- Backfilling or reinterpreting the 20 days of `undefined` rows.

## Territory notes

- `analytics.js` is served RAW (`home.html:197`, `plan.html` `<head>`, static `defer`) — it is absent from
  `minify-assets.js:20` `JS_FILES` and from `compile-app.js`. No `.min.` regeneration in this item.
- `Analytics.init()` runs `captureAcquisition()` ONCE at landing, before SPA navigation clears the query —
  that is exactly why the tag survives the planner's `u.searchParams.delete('src')` clean-up
  (`planner.js:1008`, spec "plan clean URL"). Do not move the capture.
- Non-production hosts suppress all tracking at the single `track()` choke point (spec 096,
  `analytics.js:95-104`), so any rendered test must stub `mixpanel` **and** satisfy `isProductionHost()`
  the way `test_analytics_fires.js` / `test_northstar_cta_fires.js` already do — read how they do it, reuse it.
