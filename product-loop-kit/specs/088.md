## Candidate KPIs (each derived from 087's history through the trust rails, each disclosed)

1. **Rate reliability / stability** — dispersion of the pool's rate across the retained window; surfaced
   as calm language ("steady for 30 days" vs "moves a lot"), feeding the 071 volatility-note pattern.
   Directly serves the forever-number confidence problem: a stable 6% beats a spiky 20% for a
   subscription garden.
2. **Rate momentum** — rising/falling over the window; honest version of "exciting": falling rates get
   said out loud (degen-honesty precedent, ⅓ haircut stays untouched).
3. **Track record / pool age in our history** — "new pool, no track record yet" flag (higher-risk by
   default, 058 §6); cautious-saver framing, never a hype badge.
4. **TVL trend** — growing/shrinking alongside the static $10M floor (a shrinking-TVL pool passing the
   floor today is decision-relevant for a 5-year plan).
5. **Plan-level: "projection confidence"** — planner picks annotated with the stability KPI of the pools
   behind the blended rate ("this plan is built on pools steady for 30+ days").

## Hard constraints (NEVER weakened)

- KPIs rank/annotate WITHIN pools that already pass the sanity/TVL/anomaly rails — they never rescue a
  filtered pool or override a flag. APY_SANITY_LIMIT, DEFAULT_MIN_TVL, anomaly demotion, degen haircut
  untouched.
- Every displayed KPI phrase through translations.js EN + natural KO; numbers via formatUsd/formatApy.
- Honest-numbers rule: every KPI must be explainable in one sentence from stored snapshots; no black-box
  scores. "Education, not advice" framing.
- Rendered-Playwright acceptance (2026-07-11 standing decision) when built.

### Territory notes (verified in code 2026-07-14 — these BIND the design)

1. **Where 087's `kpis` actually flow into the app.** `PoolDetail` takes `pool` as a prop; it does not
   fetch. The pool reaches it two ways: (a) `handlePoolClick` (app.js:2272) passes the object straight
   out of the `pools` array; for `?token=`/`?chain=` browse `pools` is loaded from
   `data/pools-snapshot.json` (the snapshot CARRIES `kpis`, verified — 087). So in-app browse→detail
   navigation carries `kpis` into PoolDetail TODAY. (b) A direct `?pool=<id>` deep link ALWAYS loads
   LIVE `/pools` (app.js:1041 `snapshotEligible = !urlParams.pool && …`), and live DefiLlama data has NO
   `kpis` → the note must hide honestly. This is correct: the SEO deep-link enrichment is a documented
   follow-up sub-item, not this one.
2. **Data reality today.** With one retained history point, EVERY pool's `kpis` is
   `{historyPoints:1, firstSeen:"<date>", apyMomentum:null, apyStdev:null, tvlTrend:null}`. So today the
   note only ever renders its "still building a track record" tier; the steady/tracked tiers activate
   automatically as 087's daily CI accrues history. The code handles all tiers; the data catches up.
3. **Never double-note with 071.** 071's "moves a lot" note owns the volatile case. The new note yields
   entirely when 071 fires (same divergence boolean), so the two are mutually exclusive.
4. **Compiled/minified artifacts.** home.html loads `PoolDetail.compiled.min.js` and
   `translations.min.js`. Editing `PoolDetail.js`/`translations.js` REQUIRES `npm run compile &&
   npm run minify` (052/053/061 precedent) or `test_compiled_assets.js`/`test_minified_assets.js` fail.

### Acceptance criteria

**A. Render logic (`PoolDetail.js`), placed immediately after the 071 note (~line 1313).** A calm,
full-width note with `className: 'rate-track-record-note'`, reusing 071's exact inline neuro styling
(`var(--color-background)`, `var(--neuro-radius-sm)`, `var(--neuro-shadow-subtle)`,
`var(--color-text-secondary)`, `var(--font-size-sm)`, `lineHeight:'1.5'`, `padding:'12px 16px'`,
`marginBottom:'20px'`). Let `cur = (pool.apyBase||0)+(pool.apyReward||0)`; `k = pool.kpis`;
`volatilityFires` = the exact 071 boolean (apyMean30d number, cur>0, apyMean30d>0, max/min ≥ 1.5).
- A1. Render NOTHING when: `volatilityFires` is true, OR `k` is missing/not an object, OR
  `Number(k.historyPoints)` is not `>= 1`. (Null-safe — covers live SEO landings and missing data.)
- A2. Let `hp = Number(k.historyPoints)`, `stdev = (typeof k.apyStdev === 'number') ? k.apyStdev : null`.
  - Tier NEW — `hp < 7`: `t('rateTrackRecordNew')` (number-free copy; no fabricated steadiness claim).
  - Tier STEADY — `hp >= 7 && stdev !== null && cur > 0 && (stdev / cur) <= 0.2`:
    `t('rateTrackRecordSteady', hp)`.
  - Tier TRACKED — otherwise (`hp >= 7`, not steady, or stdev null): `t('rateTrackRecordTracked', hp)`.
  (`hp` only ever appears in copy when `hp >= 7`, so plural is always correct; no date is interpolated.)
- A3. The note reads ONLY `pool.kpis.*` + `pool.apyBase/apyReward/apyMean30d`. It NEVER filters, drops,
  reorders, re-weights, or re-flags a pool, and never reads/writes the rail constants. Rails untouched.

**B. Copy (`translations.js`, EN + natural KO, both added together).** Three keys, calm cautious-saver
"education not advice" framing, no hype, no "save up/afford/budget":
- `rateTrackRecordNew` (string): EN "We're still building this pool's rate history — not a long enough
  track record yet to judge how steady it is. A longer history makes a rate easier to trust."
- `rateTrackRecordSteady` (fn `hp =>`): EN "Steady so far: across the {hp} days we've tracked it, this
  pool's rate has stayed close to level. Steadier rates are easier to plan a garden around."
- `rateTrackRecordTracked` (fn `hp =>`): EN "We've been tracking this pool's rate for {hp} days.
  Watching how a rate holds up over time is one honest way to judge it."
- KO: natural translations of each (not literal), same three keys, in the KO block.

**C. Artifacts regenerated in the same commit.** `npm run compile && npm run minify` →
`PoolDetail.compiled.js`, `PoolDetail.compiled.min.js`, `translations.min.js` regenerated.

**D. Rendered-Playwright acceptance (`test_kpi_track_record.js`, mirrors `test_rate_volatility.js`).**
Drives the REAL pool-detail UI via `?pool=<id>` with DefiLlama-shaped fixtures whose `/pools` objects
carry (or omit) a `kpis` field, asserting on the rendered `.rate-track-record-note` DOM:
- D1. Fixture pool `hp:1` (kpis present, momentum/stdev null) → note present, text is the NEW-tier copy.
- D2. Fixture pool `hp:30, apyStdev:0.4, cur~6%` (ratio ≤0.2) → note present, STEADY-tier copy incl. "30".
- D3. Fixture pool `hp:30, apyStdev:5, cur~6%` (ratio >0.2) → note present, TRACKED-tier copy incl. "30".
- D4. Fixture pool with NO `kpis` field → note ABSENT (real SEO live-landing behavior).
- D5. Fixture pool that also trips 071 (divergent apyMean30d) WITH kpis → `.rate-track-record-note`
  ABSENT (071 wins; mutual exclusion).
- D6. `?lang=ko` on the NEW-tier fixture → Korean copy substring present.
- D7. Zero page errors across all renders.
Add `test_kpi_track_record.js` to `package.json`'s test chain.
