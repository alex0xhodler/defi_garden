## Goal
Stop build runs from spending a whole session on work that already landed or is already in flight.

## Intuition
The rule this replaces was prose in `prompts/build.md`: run `git ls-remote origin
'refs/heads/claude/loop-<id>'` at pickup. It has three blind spots, each of which has already cost this
repo real work:

1. a merged-and-deleted branch leaves **no ref** — `ls-remote` reads clean for a FINISHED item;
2. the base commit goes stale the moment the run starts, and **nothing re-reads it**;
3. **PR state is never consulted at all** — a closed-and-merged PR is invisible to a branch-name grep.

On 2026-08-11 a run picked 227, read clean, built the item across four agents, and found at push time
that 227 had merged hours earlier as PR #425. Roughly half that run's spend was discarded. Two more
recorded instances: row 260's renumber, and PR #419 ("COLLIDES with a concurrent run"). A fourth turned
up during this very run — see "Dogfood" below.

## What changed, in reading order

1. **`product-loop-kit/check-item-inflight.js`** (new) — pure core + thin CLI, zero new dependencies,
   following `pr-orphan-detector.js`'s architecture (item 245). Three legs:
   - **A** — remote branch refs, matching a `loop-<digits>` token compared **numerically** (so a
     zero-padded id like `065` matches `loop-65`). Refs that merely contain the digit run are printed as
     an informational **weak** line and never change the exit code.
   - **B** — commit subjects on a **freshly fetched** `origin/main` (the CLI fetches; `--no-fetch` is for
     tests only).
   - **C** — pull requests in **any** state, injected via `--prs=<path.json>`, because loop scripts stay
     offline and the calling prompt owns the GitHub credentials (245's precedent).
   - Exit codes: `0` CLEAR · `1` COLLISION · `2` usage/env · `3` CLEAR-WITH-UNAVAILABLE-LEG. Running
     without `--prs` **can never return 0** — a leg that cannot see PR state says so out loud.
2. **`product-loop-kit/prompts/build.md`** — the prose rule becomes a command run **twice**: at pickup,
   and again **immediately before the first push**. The second call site is the one that did not exist,
   and is the only one that can see blind spots 1 and 2.
3. **`product-loop-kit/test_item_inflight_check.js`** (new) — 52 assertion groups. The population legs are
   derived at test time from live repo data (every BACKLOG id × real `git ls-remote` refs; every real
   `origin/main` subject), and every reported match is re-extracted by a **separate** implementation, so
   the matcher is never its own witness. The residue is likewise **derived**, not remembered: a third,
   more permissive extractor sweeps the corpus and the leftovers are asserted set-equal to
   `KNOWN_LEGBC_RESIDUE` in both directions.
4. **`playbooks/loop-container-contention.md`** — the "unmerged PRs hold IDs invisibly" trap now points at
   the executable check and both call sites.
5. **`playbooks/matcher-predicate-widening.md`** (new) — the compound step; see below.
6. **`BACKLOG.md`** — row 271 files the open class residue (53 memory-enforced prompt rules remain).
