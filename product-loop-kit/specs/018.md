# Spec 018: NL search actually works — behavior on live data, not fixtures

## Evidence
The human tested the preview after 017's build: search is still very bad despite all 14 parser fixtures passing. 017's acceptance measured PARSING (unit fixtures against mock lists), not the PRODUCT (what the grid renders when a real person types). That gap is now a standing decision (2026-07-11): UX acceptance criteria must measure rendered product behavior, never only unit fixtures.

## Hypothesis
Fixing the parser + matching + ranking against LIVE pools data — and asserting on the rendered result grid, not parser return values — will make every advertised and canonical query produce a correctly filtered, non-empty grid where live pools exist.

## Change
1. Root-cause the full pipeline against live DefiLlama pools data: parser output → token/chain/protocol matching → filter application → result ranking. Fix in the pipeline, no per-query hacks.
2. Playwright behavior test: launch the app (`npm run dev` + chromium), TYPE each canonical query into the real search input, and assert on the rendered grid:
   - grid is non-empty wherever live pools exist for the query
   - filters actually applied: chain queries show only that chain, protocol queries only that protocol, category combos apply poolTypes (e.g. "kamino lenders" → protocol kamino + Lending)
3. Canonical query set (≥10): EVERY typing-animation example string, plus: "solana", "base", "kamino", "kamino lenders", "curve", "convex", "arbitrum", "morpho lending", "aave", "usdc on base".
4. Timebox all test runs — 5-minute foreground cap per run (standing decision 2026-07-11); never wait unbounded on background jobs.

OUT of scope: search UI redesign, router semantics, planner.

## Acceptance criteria
- [ ] Playwright run drives the REAL UI (npm run dev + chromium) typing all ≥10 canonical queries; rendered grid non-empty where live pools exist and correctly filtered (chain/protocol/poolTypes applied) — asserted on DOM, not parser output
- [ ] Root-cause fixes in parser/matching/ranking — grep-verifiably no per-string special cases
- [ ] Verifier independently REPRODUCES the Playwright run (not just reads its output)
- [ ] Existing test chain still exits 0; every run timeboxed at 5 min foreground

## Measurement
search_success vs search_abandonment events, 14-day window post-ship.

HIGH — user-facing search behavior on the SEO-critical analytics surface.
