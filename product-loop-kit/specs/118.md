# 118 — GSC "Excluded by 'noindex' tag" — diagnose intentional vs regression

Human forwarded a Google Search Console email 2026-07-16: *"some pages on your site are not being
indexed due to … Excluded by 'noindex' tag."* Diagnosis-first (mirrors item 010); do NOT change any
noindex behavior until the flagged URLs are classified.

## Code audit (done 2026-07-16 — the ONLY noindex source in the repo)

Grepped the whole tree. `noindex` is emitted in exactly ONE place at runtime:
- **`app.js:2341-2361`** injects `<meta name="robots" content="noindex">` CLIENT-SIDE when
  `emptyStateResolved` OR `deadPoolResolved`, else sets `index, follow`. This is the intentional
  honest-empty-state fix from **item 012** (zero-result `?token=`/`?chain=` queries) and **item 072**
  (dead `?pool=<id>` deep links). Both are GUARDED against the SPA loading race:
  - `emptyStateResolved` (app.js:2300) = `currentView !== 'pool-detail' && pools.length > 0 &&
    filteredPools.length === 0 && (selectedToken || (chainMode && selectedChain))` — requires pools
    LOADED and the filtered set genuinely empty.
  - `deadPoolResolved` (app.js:2305) = `pools.length > 0 && deadPoolParam` — id absent from the live list.
- Everything else ships `index, follow`: `home.html:15`, `plan.html:12`, `generate-token-pages.js`
  (`/tokens/*`), `generate-chain-pages.js` (`/chains/*`). No generator or static page emits noindex.

**Most-likely verdict: WORKING AS DESIGNED.** GSC is very likely reporting the empty-`?token=`/`?chain=`
and dead-`?pool=` URLs that 012/072 deliberately noindex — which is the honest fix draining the
soft-404 / thin-content class item 010 diagnosed. "Excluded by noindex" for those URLs is the intended
outcome (better than being crawled + soft-404'd). If so: NO fix — just confirm + close.

## Classification rule (once the URLs are in)

- URLs are `?token=X` / `?chain=Y` with **no qualifying pools**, or dead `?pool=<id>` → **INTENTIONAL
  (012/072).** No action; close as working-as-designed. Optionally note the count trend for the human's
  GSC window.
- URLs are static content pages (`/tokens/<slug>`, `/chains/<slug>`), the planner (`/`, `/plan.html`),
  or `?token=`/`?chain=` queries that DO return pools → **REGRESSION.** Open a fix sub-item. Suspects to
  check, in order:
  1. **SPA render race w/ the 059 snapshot-first path.** Googlebot renders JS; if the snapshot-first
     load (059/099) ever leaves `pools.length > 0` while a valid query's `filteredPools` is transiently
     0 (stale/partial slice, filter state), the client could inject noindex on a page that resolves to
     results. Re-verify the guard holds under snapshot-first loading.
  2. **Over-broad empty classification.** A `?token=X` for a token whose only pools are sub-$10M is
     "empty" by the trust-rail floor and gets noindexed — intentional, but if the human wants some of
     those indexed it's a product call, not a bug.
  3. **A static generator regression** silently emitting noindex (grep says no today — re-confirm on the
     live deployed HTML, not just source).
