# Spec 180: the AI-discovery surface must not publish links to an empty grid

## Evidence

Item 175's new level-3 (`link-target-integrity`, "non-empty") signal found **63 dead grid links on
`llms.txt`/`llms-full.txt`** on its first run — the first scanner-originated link finding after four
consecutive days (07-26 → 07-29) of every link bug being found by hand. Filed as BACKLOG row 180.

**Independently re-measured by this run before any code was written**, against a live
`yields.llama.fi` fetch (**16,038 pools**, 2026-07-30), simulating the app's own filter arithmetic:

| file | grid links checked | dead | sections affected |
|---|---|---|---|
| `llms.txt` | 38 | **1** | `## Common Search Patterns` |
| `llms-full.txt` | 497 | **62** | `## Chain Pages` |

Reproduces 175 T4 exactly (1 + 62). The other **473** grid links resolve — the defect is confined to
those two sections.

- `llms-full.txt:378+` `## Chain Pages` — 102 `/?chain=<C>` links, **62 resolve to zero pools**
  (`/?chain=Cardano`, `/?chain=Celo`, `/?chain=Abstract`, …). None carries `minTvl`, so the app resolves
  them at `DEFAULT_MIN_TVL` = $10M (`app.js:801`, `app.js:927`), where those chains have no pools.
- `llms.txt:71` — `/?poolTypes=Staking&minApy=10`, published verbatim as *"High APY staking"*. Measured:
  **14** Staking pools clear $10M; the highest APY among them is **5.24%**, so `minApy=10` is
  unsatisfiable — 0 pools, live and in `data/pools-snapshot.json` alike.

### Two findings that decide the fix (this is why the spec does not simply copy 173)

**1. 173's fix shape does not transfer.** 173's repair was *"emit the generator's own eligibility floor on
the link"* — it worked because the HTML generators build at `MIN_POOL_TVL` = $100K while the app filters at
$10M, a 100× mismatch. `generate-llms.js:28` `MIN_TVL_USD = 10000000` is **already identical** to the app
default. These links are dead at the generator's *own* floor. Adding `&minTvl=10000000` would change
nothing; adding `&minTvl=100000` would publish a floor below the one the same file claims in prose
(*"TVL ≥ $10M"*), which is 174's defect re-introduced.

**2. The section is mis-targeted — measured, per 175's instruction to check this before touching a floor.**
`## Chain Pages` ("*Blockchain-specific yield markets and protocols*") lists app-grid query URLs, while the
**real chain pages it is named after already exist and are already in the file** — all 88 `/chains/<slug>`
URLs are present, dumped into `## Other Pages` under *"Additional site functionality and tools"*.
Cross-referencing the 62 dead chains against them:

| dead `?chain=` links | has a static `/chains/<slug>` page | destination |
|---|---|---|
| **48** | yes | the static page — real content at the $100K page floor |
| **14** | no | none exists |

The 14 (`Abstract Alephium Boba Carbon Chia Kasplex Metis Moonriver Obyte Rollux Shape Taiko Telos Unit0`)
have **zero pools with a non-zero APY even at the $100K page floor** — measured live; largest TVL on any of
them is $198K. That is *why* they never earned a page (`generate-chain-pages.js:78`
`MIN_QUALIFYING_POOLS`). There is no honest destination for them.

## Hypothesis

We believe **gating every emitted grid link on "does this target return at least one pool?" at generation
time, and retargeting the chain section at the real chain pages, removes all 63 dead links and keeps them
removed under pool-population drift** because the generator runs daily against live data, so the gate
re-decides every link on every bake — unlike item 181's class, where a mint-time-only predicate let the
defect return by drift alone. Confidence: **supported** — the check has been executed by hand on the exact
corpus and produced the exact answer (63); only the codification is open.

## Change

All in `generate-llms.js`. One shared helper, three rules, applied at emit time.

**R1 — `gridLinkPoolCount(url, pools, opts)` (new, exported).** Mirrors the app grid's qualification for a
`defi.garden` home-path link, reusing existing sources — never a second copy of a rail or a classifier:
- `minTvl` explicit param wins, absent → `MIN_TVL_USD` (the existing mirror; **no new floor literal**, 174's
  rule); qualification is `(tvlUsd||0) >= floor && (tvlUsd||0) > 0` (`test_seo_cta_targets.js:117` is the
  reviewed reference, 175 T6).
- `token` → case-insensitive substring on `symbol` (`app.js:835`); `chain` → exact; `protocols` → exact
  `project`; `poolTypes` → `getPoolType` lazily required from `generate-sitemap.js` in a `try/catch` (the one
  classifier, 175 T6 — if unavailable, the `poolTypes` constraint is dropped and the drop is **counted and
  logged**, never silently ignored); `minApy` → `apy >= minApy`.
- Applies **only** to links carrying at least one of `token chain poolTypes protocols minTvl minApy`.
  **`?pool=<id>` is never simulated** (175's 4,233-false-positive trap) and path-only URLs are untouched.

**R2 — chain-section retarget.** In `## Chain Pages`, a `/?chain=<C>` link with `gridLinkPoolCount === 0` is
replaced by `${baseUrl}/chains/<slug>` **iff that URL is present in the parsed sitemap URL set** (48 today).
Slug via `tokenSlug` reused from `generate-token-pages.js` — the same import `generate-chain-pages.js:41`
uses (`tokenSlug: chainSlug`); never a second slug implementation. A retargeted URL is then **skipped in
`## Other Pages`** so it appears exactly once in the file. A dead link with no static counterpart (14 today)
is **omitted and counted**.

**R3 — `minApy` repair ladder.** A dead link carrying `minApy` retries the descending rungs
`[10, 5, 3, 1]`, taking the highest that resolves ≥ 1 pool; if none does, `minApy` is dropped entirely; if
the link is still empty, it is omitted. Today `?poolTypes=Staking&minApy=10` → **`minApy=5`** (2 pools live,
3 in the snapshot — the rung must resolve under **both** populations, because `audit-app.js`'s level-3
re-checks the committed file against `data/pools-snapshot.json` using `apyBase+apyReward`, `audit-app.js:925`).

**Anti-vacuity rails (the failure mode this item could cause).** With an empty population every link
resolves to zero and the gate would gut the surface:
- `pools` empty / absent (`fetchYieldsSafe` fails SAFE to `[]`) → **gate disabled entirely**, links emitted
  unchanged, loud `stderr` note. Never an omission caused by missing data.
- Structural tripwire: if the gate would retarget-or-omit **> 40%** of checked grid links (today: 63/535 =
  11.8%), it emits everything unchanged, prints a loud `stderr` note, and sets a non-zero `process.exitCode`.
  A simulation bug must fail loudly, not quietly shrink the AI surface.
- Every retarget / repair / omission is `log()`ged with per-class counts.

**Regenerate** `llms.txt` + `llms-full.txt` via `npm run generate:llms` (generated surface — never
hand-edited).

**Update the pinned known-defect assertion**, per its own instruction
(`test_audit_text_surfaces.js:363-370`: *"a different count means either backlog 180 landed (great —
re-measure and update this pin, don't delete it)"*): flip it to a **true negative** (zero level-3 suspects on
the real committed `llms*.txt`), citing 180. The frozen pre-166 **excerpt positive control** (`:302`,
`:325`) stays untouched — it is what keeps level 3 non-vacuous after this lands.

**Explicitly OUT of scope:** the sitemap still lists `/?chain=Abstract` etc. (item 013's class — a sitemap
quality question, not an llms one); restructuring `## Token Pages` / `## Other Pages` around the 2,118
static token pages (the same mis-targeting one surface over — file it, don't build it here); `?pool=`
liveness; item 181's regen-lifecycle question.

## Territory notes

### T1. The `## Chain Pages` population comes from the sitemap, not from pool data
`categorizeUrls()` (`generate-llms.js:143`) buckets **sitemap URLs** by query key, so the section inherits
whatever floor the sitemap minted `?chain=` URLs at (`generate-sitemap.js:29`
`SITEMAP_MIN_QUALIFYING_POOLS = 2`) — never the app's default. That is the structural reason the two
surfaces disagree, and it is why the gate has to live at emit time in this generator rather than in the
sitemap.

### T2. The audit and the generator judge the same link against different populations
`audit-app.js` level 3 uses `data/pools-snapshot.json` (complete at ≥$10M, 747 pools, 175 T1) and derives
apy as `apyBase+apyReward` (`:925`) because the snapshot has **no `apy` field**. The generator uses the live
feed's `apy`. Any rung/threshold choice must resolve under both or the audit stays red — measured for the
chosen rung (`minApy=5`: 2 live, 3 snapshot).

### T3. `fetchYieldsSafe` fails SAFE to `[]`, which makes the gate dangerous by default
`generate-llms.js:225-234` resolves `{ yields: [] }` on error or timeout. Without the empty-population rail
above, a 10-second DefiLlama timeout would publish an llms surface with **every** grid link stripped. This is
the single highest-consequence detail in the item.
