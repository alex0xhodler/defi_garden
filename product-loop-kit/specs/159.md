# Spec 159: Apply the trust rails to the `llms.txt` surface

## Evidence

Fetched from **live production** this tick (`curl https://www.defi.garden/llms.txt`, 2026-07-27) — verbatim:

```
## Current Top Yields
TL;DR: Live highest APY opportunities (updated daily, TVL ≥ $10k).
- BSC · zeebu · ZBU — 353114.2% APY, $576,877 TVL — https://www.defi.garden/?token=ZBU&chain=BSC
- Base · aerodrome-slipstream · USDC-VFY — 220925.6% APY, $29,382 TVL — https://www.defi.garden/?token=USDC-VFY&chain=Base
- Avalanche · blackhole-clmm · WAVAX-USDC — 144006.1% APY, $58,744 TVL — https://www.defi.garden/?token=WAVAX-USDC&chain=Avalanche
- Base · aerodrome-v1 · WETH-TRAC — 95371.1% APY, $44,329 TVL — https://www.defi.garden/?token=WETH-TRAC&chain=Base
```

Scale, measured on the committed artifacts:
- `llms.txt` — **8** lines with APY > 1000%.
- `llms-full.txt` — **15** lines with APY > 1000%, across 6 chain sections (BSC, Base, Avalanche, Polygon, Aptos, Solana). Max **353,114.16%**.

Root cause, `generate-llms.js`:
- `pickHighYield()` (`:227`) — `const { minTvlUsd = 10000, topN = 15 } = options;`
- `:237` — `return tvl >= minTvlUsd && apy > 0 && isFinite(apy);` — the **only** APY predicate in the file.
- `grep -nE "SANITY" generate-llms.js` → **zero matches**. There is no sanity limit anywhere in this generator.
- Results are then sorted **APY-descending**, so the surface is by construction a leaderboard of the dataset's most anomalous pools.
- Rendering sites: `:236` (`Number(pool.apy) || 0`), `:462` (`.toFixed(1)`), `:576` (`.toFixed(2)`).

Rails being breached (both, simultaneously):
| Rail | Product value | `generate-llms.js` value |
|---|---|---|
| `APY_SANITY_LIMIT` | `1000` (`app.js:800`, `planner.js:19`) | **not applied at all** |
| `DEFAULT_MIN_TVL` | `10000000` (`app.js:801`) | `10000` — **1000× looser** |

Corroboration that the product itself disagrees with its own llms surface: `zeebu`/`ZBU` — the pool at the top of the live list — **is not present in `data/pools-snapshot.json` at all** (0 matches on `symbol==='ZBU' || project==='zeebu'` in the 735-pool, $10M-floored snapshot). The app would never show this pool; `llms.txt` leads with it.

Regeneration: `.github/workflows/sitemap-update.yml:110` runs `POOLS_FIXTURE="$RUNNER_TEMP/seo-pools.json" node generate-llms.js` daily, so the surface self-refreshes with each day's worst outlier. Committed via `chore: update sitemap and LLM files with latest yields`.

## Hypothesis

We believe applying `APY_SANITY_LIMIT` (and an honest TVL floor) to `generate-llms.js` will remove a standing contradiction between what the product enforces and what its AI-discovery surface publishes, because `llms.txt` exists specifically to tell LLMs and agents what DeFi Garden claims, and it currently claims 353,114% APY under the header "Live highest APY opportunities". Confidence: **validated-pattern** — this is item 013/144/145's exact class (a rail enforced on one surface and absent on another), and NORTH_STAR's product direction is explicit: *"every displayed number derives from live DefiLlama pool data through sanity filters"*, *"honest numbers beat exciting numbers"*.

This is a **correctness/trust fix, not a growth experiment.** It is not expected to move the north star and must not be scored or closed as though it were.

## Change

Smallest version:

1. In `generate-llms.js`, define the sanity limit **once**, at the top, matching the product: `const APY_SANITY_LIMIT = 1000;` with a comment naming `app.js:800` as the source of truth.
2. Extend `pickHighYield()`'s filter (`:237`) to also require `apy <= APY_SANITY_LIMIT`.
3. Raise the default `minTvlUsd` so the surface stops advertising dust. **Decide and state which floor**, then make the rendered TL;DR string tell the truth about it (today it says "TVL ≥ $10k" — whatever the new floor is, that string must match it, and it must be derived from the constant, not hardcoded a second time).
4. Regenerate via the sanctioned path (`npm run generate:llms`) and commit the regenerated `llms.txt` + `llms-full.txt`. **Never hand-edit them.**

Explicitly OUT of scope:
- Any change to `app.js` / `planner.js` / `PoolDetail.js` — the product rails are correct; only the generator diverges.
- Any change to the sitemap generators, token/chain page generators, or OG images (that is item 160's territory).
- Changing `APY_SANITY_LIMIT` itself, anywhere. NORTH_STAR NEVER list: weakening a trust rail is human-gated. This item only **applies** the existing rail to a surface that was missing it.
- Adding a demote/⚠-flag presentation for anomalous pools in `llms.txt` (the analytics-app treatment). For a plain-text AI-discovery surface, exclusion is the honest and simpler answer; revisit only if the human asks.

## Acceptance criteria

- [ ] No line in the regenerated `llms.txt` matches an APY figure > 1000. Checkable: `grep -oE "— [0-9.]+% APY" llms.txt | sed 's/— //;s/% APY//' | awk '$1>1000' | wc -l` returns **0**.
- [ ] Same check returns **0** for `llms-full.txt`.
- [ ] The rendered TL;DR TVL claim in `llms.txt` matches the floor actually used by `pickHighYield()`, and neither is a second hardcoded literal — a verifier can change the constant, regenerate, and see the string follow.
- [ ] `llms.txt` and `llms-full.txt` are **non-empty and still list real pools** after the change — a filter that empties the surface is a FAIL, not a fix. Assert ≥ 5 pool lines remain in each.
- [ ] The `?token=…&chain=…` deep links on the surviving lines still resolve to pools present in `data/pools-snapshot.json` (spot-check ≥ 3).
- [ ] `app.js`, `planner.js`, `PoolDetail.js`, `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, all sitemaps and all `tokens/`/`chains/` pages are **byte-identical** in the diff.
- [ ] Tests: a new `test_llms_rails.js`, wired into `npm test`, that (a) runs `pickHighYield()` against a fixture containing a 353114.2% / $576,877 pool and asserts it is excluded, (b) asserts an in-rail pool at the new TVL floor **is** included, (c) asserts the boundary — exactly 1000% is included, 1000.01% is excluded — and (d) parses the committed `llms.txt` and `llms-full.txt` and asserts zero >1000% figures, so the committed artifact itself is gated, not just the function. Non-vacuity: prove the test goes red with the filter removed, and restore byte-identically.
- [ ] Instrumentation: **none, and that is deliberate.** `llms.txt` is a static text file consumed by crawlers and LLMs; it has no client-side runtime and cannot fire events. Do not invent a metric for it — record the disclosure in `159-notes.md` per the 142/149/154 precedent.

## Open questions

1. **Does the NEVER list gate this?** Operator's read: **no.** The NEVER list protects the *SEO lifeline* — indexable pages and sitemap URLs. `llms.txt` is not a page, nothing links to it for ranking, and this removes **lines from inside one file**, not URLs from the index. More decisively, the rule it collides with is a rail rule, and this item *enforces* `APY_SANITY_LIMIT` rather than weakening it — the NEVER list's first bullet points the other way. Distinct from item 148, which genuinely does drop 7 sitemap `<loc>` entries and is correctly gated. **Builder: proceed. If the verifier disagrees, stop and flag rather than merging.**
2. **What TVL floor?** `$10k` is indefensible next to the product's `$10M`. But `$10M` on `llms.txt` may leave the surface very short. Operator's recommendation, to be implemented unless the human says otherwise: use **`DEFAULT_MIN_TVL` ($10M)** for consistency with every other surface, and if that leaves fewer than ~8 lines, fall back to a clearly-labelled `$1M` floor with the TL;DR string saying so. Either way the string must not lie. Not blocking — implement the recommendation and record the resulting line count in `159-notes.md`.
