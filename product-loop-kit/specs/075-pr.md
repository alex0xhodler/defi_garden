# 075 — Explainer (HIGH tier): honest idle-yield headline on chain pages

## Goal
North star is `waitlist_submitted` (the card funnel). Item 066 put one honest, trust-railed number — "your idle TOKEN could earn ~X%, park $Y and it runs a $Z/mo subscription forever" — on all 2,011×2 token pages, because that number IS the card pitch made concrete. 066's spec deliberately deferred the chain half ("token-first this pass"). Result: 86×2 `/chains/<slug>` pages carried the 062 waitlist CTA with no concrete reason-to-act next to it. 075 closes that asymmetry.

## Intuition
Everything hard was already decided and verified in 066: the anchor (Claude Pro ladder entry), median-not-max (honest blend, not the flashiest pool), the null gate (no number beats a fabricated one), the placement (above the table, feeding the CTA), the phrasing pattern. Chain records were already shaped right — `rec.pools` on a chain page is the displayed top-8-by-TVL set that passed `isQualifyingPool` (the $100K TVL floor + `APY_SANITY_LIMIT` anomaly exclusion) plus the 032-style visible-non-zero quality bar. So the correct build was maximal reuse: call the exact same `yieldHeadlineFor` on the chain record and only add what genuinely differs — the sentence (a chain has no single token, so "Idle assets on Ethereum…") and the scoped CSS class.

## What changed, in reading order
1. **translations.js** — new `tcpYieldHeadlineChain(chain, apyStr, foreverAmtStr, monthly, subLabel)` in BOTH language blocks, adjacent to `tcpYieldHeadline`. EN: "Idle assets on ${chain} could earn ~${apyStr} — park ${foreverAmtStr} and it could run a $${monthly}/mo ${subLabel} subscription, forever." KO mirrors the existing 유휴-자산 phrasing, chain-scoped. `translations.min.js` regenerated (`npm run minify`) — plan.html loads the min bundle; shipping the source alone was 061's caught bug.
2. **generate-token-pages.js** — `renderYieldHeadlineHtml(headline, subject, t)` gained two optional trailing params `(cssClass = 'tp-yield-headline', msgKey = 'tcpYieldHeadline')`. Defaults preserve token behavior exactly; verifier independently re-rendered all fixture token pages against origin/main's generator: 10/10 byte-identical. `yieldHeadlineFor` untouched.
3. **generate-chain-pages.js** — imports `yieldHeadlineFor, renderYieldHeadlineHtml`; `renderChainPage` computes `yieldHeadlineFor(rec, language)` and renders `<p class="cp-yield-headline">` via `tcpYieldHeadlineChain` in the same slot token pages use (after the intro, immediately before the `.cp-cta`, above the pool table). Null headline → empty string. New `.cp-yield-headline` scoped style mirrors `.tp-yield-headline` character-for-character — neumorphic tokens only (`--color-surface`, `--neuro-radius-md`, `--neuro-shadow-raised`).
4. **test_chain_pages.js** — new "075" section, 12 assertions mirroring 066's token section: median/forever/anchor derivation, median-zero → null and no rendered class, document order (intro < headline < table), EN+KO rendered presence, script-injection escaping, style block token-only. Suite: 67 → 79 assertions.
5. **chains/ + ko/chains/ (+ og/chains/)** — REAL live regeneration (`node generate-chain-pages.js --out chains --sitemap sitemap-chain-pages.xml`, 15,398 pools fetched): 86 EN + 86 KO pages committed, 77/86 each carrying the headline; the 9 without (Berachain, DefiChain, Filecoin, Hyperliquid-L1, Kava, Linea, Move, Sonic, Stable) are the null gate firing honestly on 0.00% displayed medians — verifier checked each numerically. Content diff vs origin/main is exactly the style block + headline lines (+326/−0); sitemap URLs unchanged, so sitemap files are untouched.

## Trust rails
No constant, gate, or filter changed. The headline number is `gp.blendedApy` (median) over the already-gated displayed pools; the page's max-based `bestApy` is not used. Verifier spot-check on chains/ethereum.html: headline 2.28% = the table's true median, not the 4.88% max; forever number ≈ $20×12/0.0228.

## Deviations from spec
None material. The helper generalization used the spec's first suggested option (optional trailing params). The chain test reuses `yieldHeadlineFor`/`yieldHeadlineAnchor` via the token module rather than re-exporting from the chain module.

## Disclosures (verifier)
- The verifier's own independent live regen exposed a latent footgun: `generateOgImages(..., process.cwd())` in generate-chain-pages.js ignores `--out`, so its scratch run rewrote repo `og/chains/*.png` (and briefly deleted `metis.png` when Metis drifted out of the live ranking mid-verification; restored from origin/main). The committed OG bytes are same-day, same-generator output — functionally equivalent; the daily chore regen reconciles. The cwd-coupled OG path is noted in specs/075-notes.md as a future backlog candidate.
- Live-data drift: `chains/metis.html` is committed but Metis had fallen out of the live ranking ~7 minutes later — inherent to a point-in-time regen of a live-data surface; next daily CI regen reconciles (031's stale-page cleanup).

## Measurement
`page_view` → `waitlist_opened(source=seo_chain)` on chain pages, pre/post 14d once organic traffic exists (GSC 2–6wk in progress); ≥30 events per claim, otherwise "insufficient data". Lands inside 062's existing measurement stream — same disclosure pattern as 066.
