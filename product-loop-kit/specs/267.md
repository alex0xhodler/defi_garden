# Spec 267: derive every prose free/paid route list from `PRICE_SCHEDULE`

Impact: agent-contract correctness on API, MCP, and x402 documentation surfaces

## Evidence

Item 234 made `edge/x402-core.js`'s `PRICE_SCHEDULE` the machine-readable source of truth, but four
prose copies still name today's boundary independently:

1. `edge/X402.md` lists free and paid routes.
2. `edge/MCP.md` lists free and paid tools.
3. `edge/API.md` says everything except `/api/forever-number` is free.
4. `buildPricingDoc()` returns a hand-written `boundary` sentence naming today's routes.

A future route-tier change can update the schedule while these agent-facing contracts continue to
publish the previous split.

## Hypothesis

Generated marked regions and a schedule-derived machine boundary remove the independent route/tool
populations. A freshness test over the real schedule and real MCP tool table catches any future
change whose generated documentation was not committed.

## Change

- Add pure pricing-boundary renderers derived from `PRICE_SCHEDULE` and the existing MCP `TOOLS`
  route mapping.
- Make `buildPricingDoc().boundary` use the route renderer's schedule-derived sentence.
- Add generated marked regions to `edge/X402.md`, `edge/API.md`, and `edge/MCP.md`.
- Add a small generator that rewrites only those marked regions.
- Extend the existing plain-Node x402 gate; do not add a second test harness or dependency.
- Keep conceptual prose, disabled/live availability language, prices, and protocol behavior intact.

## Acceptance criteria

- [ ] Mutating a schedule tier changes `buildPricingDoc().boundary` without editing another literal.
- [ ] X402 and API generated regions exactly match the renderer derived from all real schedule rows.
- [ ] MCP's generated region exactly matches all real tools classified through their declared routes.
- [ ] Each generated region has exactly one begin/end marker; missing, duplicate, or stale regions fail.
- [ ] The existing route/endpoint/tool three-way set-equality checks remain green.
- [ ] No product runtime, payment availability, tier, price, or dependency changes.

## Measurement

Build-leg only. Keep while the freshness gate remains green when pricing routes change.

## Risk tier

LOW — documentation generation plus drift assertions; no product render or payment behavior change.
