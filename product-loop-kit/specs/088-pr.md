# 088.1 — PR explainer (HIGH tier): rate-track-record note on pool detail

## Goal

Item 088 (data-layer leg 3) is the human's 2026-07-14 directive: "start creating interesting KPIs that
can be used in the app for the users to take better decisions given their ICP." The ICP is the cautious
retail saver who thinks in monthly deposits and life goals, not APY/pools — so KPIs must translate pool
data into trust/stability/decision language, never more degen metrics. Item 087 built the pipeline that
COMPUTES per-pool KPI fields (`historyPoints`, `firstSeen`, `apyMomentum`, `apyStdev`, `tvlTrend`) into
the static snapshot. 088 SURFACES them. This sub-item, 088.1, is the smallest first surfacing: ONE KPI
(rate track record / steadiness) on ONE surface (pool detail), extending the 071 volatility-note pattern
and serving 019's SEO→pool-detail conversion goal.

## Intuition

For a cautious saver picking a pool to fund a "forever number," a stable 6% beats a spiky 20%. DefiLlama
gives you a single instantaneous APY with no sense of how much it wobbles. 087 now retains daily
snapshots, so we can say honest things about a pool's rate over time: how long we've watched it, and —
once we have enough history — whether it's held steady. 088.1 puts that in one calm sentence under the
pool's numbers.

## What changed and why (diff in reading order)

1. **`PoolDetail.js`** (~line 1314, immediately after the 071 `.rate-volatility-note`): a new sibling
   `React.createElement('div', {className:'rate-track-record-note', style:{…}}, …)`. The style object is
   copied verbatim from 071 (neuro tokens only — `--color-background`, `--neuro-radius-sm`,
   `--neuro-shadow-subtle`, `--color-text-secondary`, `--font-size-sm`). The render guard is:
   `!(071 divergence boolean) && pool.kpis && typeof pool.kpis === 'object' && Number(pool.kpis.historyPoints) >= 1`.
   The child is an IIFE that computes `_cur = (apyBase||0)+(apyReward||0)`, reads `historyPoints`/`apyStdev`,
   and picks a tier: `hp<7` → NEW ("still building history"); `hp>=7 && stdev!==null && _cur>0 &&
   stdev/_cur<=0.2` → STEADY (rate has held level); else → TRACKED (neutral "tracked N days"). Each tier
   uses the `t ? t(key,…) : '<EN fallback>'` idiom exactly like 071.
   - *Why yield to 071:* the guard negates the exact 071 boolean, so a visibly volatile pool shows only
     071's "moves a lot" note. Never two rate notes, never a contradiction.
   - *Why hide when kpis absent:* `?pool=` SEO deep links load LIVE DefiLlama data (no kpis); the note
     simply doesn't render there. It renders on in-app browse→detail navigation, where the pool came from
     the snapshot (which carries kpis).
2. **`translations.js`**: three keys — `rateTrackRecordNew` (string), `rateTrackRecordSteady(hp)`,
   `rateTrackRecordTracked(hp)` — added to BOTH the `en` and `ko` blocks, right after `rateVolatilityNote`.
   Calm, "education not advice" framing; numbers appear only in the hp>=7 tiers (plural always correct).
3. **`PoolDetail.compiled.js` / `PoolDetail.compiled.min.js` / `translations.min.js`**: regenerated via
   `npm run compile && npm run minify` — home.html loads the compiled+minified artifacts, so source edits
   don't reach production until these are rebuilt (052/053/061 precedent).
4. **`test_kpi_track_record.js`** (new): mirrors `test_rate_volatility.js` — a static server + real
   Chromium landing on `?pool=<id>` with DefiLlama-shaped fixtures, asserting on the rendered
   `.rate-track-record-note` DOM. Covers NEW/STEADY/TRACKED tiers, no-kpis→absent, volatile+kpis→071-wins,
   Korean copy, zero page errors. Wired into `package.json`'s test chain.

## Deviations from spec

None material — built as specified. The one design decision (documented in 088-notes.md): surface via
`pool.kpis` with zero new fetch (so the note appears on in-app browse→detail today and on SEO deep-links
only after a follow-up wires snapshot enrichment), chosen over adding a fetch on the conversion-critical
deep-link page. With one history point live today, only the NEW tier renders in production until 087's CI
accrues history; all three tiers are exercised by the fixtures.

## Trust rails

Untouched. The note reads only the derived `kpis` object and `apyBase/apyReward/apyMean30d`; it never
filters, drops, reorders, re-weights, or re-flags a pool, and never reads/writes `APY_SANITY_LIMIT` or
`DEFAULT_MIN_TVL`. Not on the NEVER list → auto-merge eligible after verifier PASS + tests green.

## Risk tier: HIGH

User-facing number on the pool-detail render path (trust-rail adjacent), even though additive. Auto-merges
per the 2026-07-10 (c) autonomy directive; render-path touch → flag "needs human visual spot-check" (003
smoke gate isn't pixel-level).
