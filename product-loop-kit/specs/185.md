# Spec 185: the merge gate's own two red tests — a counter that fires on prose, and a positive control that can no longer prove anything

## Evidence

Item 184 shipped on 2026-07-30 and, per `playbooks/pre-existing-red-triage.md`, baselined every
`runAudit()` caller it could have broken. Two were **already red on `origin/main`**, reproduced on a
stashed clean baseline, and neither was in 184's scope. Its LOG entry and BACKLOG row both say so
verbatim — *"neither is fixed here (a second item, filed as such)"* — but **no such item was ever
filed**: the backlog's max ID was 184 when this run picked up, and there were **no READY items at all**.
This is that item, promoted from documented in-repo evidence per build.md's no-READY-item branch.

Both failures were re-measured on `origin/main` (`b2044a363`) at the top of this run, on a clean
`npm ci`, before any change:

### (a) `test_audit_prescan.js` — A6b, `40 passed, 1 failed`

```
✗ A6b (spec 171): runAudit() never passes textSurfaceFindings to reconcilePrescanFindings …
  expected exactly 3 occurrences of "reconcilePrescanFindings(" (1 function definition +
  2 runAudit() call sites) — a new call site changes this count … got 5
```

The count is 5 because the regex `/reconcilePrescanFindings\(/g` is run over **raw source, comments
included**, and items 183/184 added two *prose* mentions:

| `audit-app.js` line | what it is |
|---|---|
| 2741 | comment — *"Mirrors `reconcilePrescanFindings()`'s reconciliation wording"* |
| 2837 | **the function definition** |
| 3059 | **real call site** — `reconcilePrescanFindings(prescanFindings, {` (static leg) |
| 3068 | **real call site** — `reconcilePrescanFindings(poolPrescanFindings, {` (pool leg) |
| 3127 | comment — *"how `reconcilePrescanFindings()` is already exported for 171's tests"* |

So the gate is red for a reason that has **nothing to do with the guarantee it exists to defend**
(that `textSurfaceFindings` is never reconciled — still true, and A6b's other four assertions still
pass). Worse, it is red in the *permissive* direction for the case it was written for: with the
threshold now stale at 3-vs-5, the very next real call site added would move the count 5 → 6 and the
failure message would look identical to today's, so the signal that is supposed to force
"a new call site needs its own A6-equivalent proof" has already been drowned in its own noise.

### (b) `test_seo_surface_audit.js` — criterion 2, the positive control

```js
// test_seo_surface_audit.js:57-61 (verbatim, on main)
// Positive control (criterion 2): tokens/00.html renders "<h1>00 DeFi
// Yields</h1>" verbatim on disk (grepped, this checkout) — a real junk page.
const pCriterion2 = runAudit({
  port: 8902, staticPages: 'tokens/00.html', only: ['static-page'], outPath: outPaths.c2
});
```

`ls tokens/00.html` → **No such file or directory**. Item 148 removed every junk slug from the estate
on 2026-07-29 (confirmed in the 07-30 report: *"`/tokens/20` returns 404, zero junk slugs remain"*),
which is correct and permanent — the control was anchored to a page whose deletion was the whole point
of another item.

The mechanism that makes this silent rather than loud is one line in `audit-app.js`:

```js
// audit-app.js:1609 — buildStaticSurfaces(), the explicit-override branch
.filter((s) => fs.existsSync(path.join(ROOT, s.url)));
```

An override entry naming a file that does not exist is **dropped with no note of any kind**. The run
proceeds with zero static surfaces, finds nothing, and returns a well-formed empty result. Today that
surfaces as a FAIL only because criterion 2 happens to assert the *presence* of a finding; any control
written the other way round — "assert this page yields no findings" — would have gone **green while
testing nothing**. That is the exact failure class the loop has now hit four times (166 `--only`
vacuous green; 175 a signal scoring 0 on 1,749 real defects; 183 a check blinded by an upstream repair;
this).

**Why it's worth a build rather than a deferral.** Both files are in the browser lane — the rendered
half of the merge gate, whose structural unrunnability was item 170's whole subject. A lane that is
permanently N-red trains every subsequent run to read "2 failures, both pre-existing" and move on;
LEARNINGS' `pre-existing-red-triage` playbook exists because that judgment already costs a stashed
baseline run per item. Every red that is *not* a real regression is a tax on every future item.

## Hypothesis

We believe **repairing both gates at their root cause — counting call sites instead of text, and making
the positive control provision its own fixture — plus making the silent override-drop audible** will
**return the audit lane to 0 unexplained reds and stop the per-item baseline tax**, because neither
failure reflects a product defect and both are pinned to artifacts (a literal count; a deleted file)
that the repo will keep moving. Confidence: **high** — the defects are mechanical and fully measured
above, with no open architectural question.

## Change

Three legs, one item, all in the merge gate's own machinery. **No product code.**

### Leg A — `test_audit_prescan.js`, A6b: count call sites, not mentions

Strip line comments, block comments and string literals from the source **before** counting, then
assert on the count of real invocations. Keep the guarantee and the intent of the message intact:
the definition + exactly two call sites. Do **not** relax the assertion to a range or delete it — the
"a new call site needs its own A6-equivalent proof" contract is the point, and 183/184 both prove
comment prose about this function keeps getting written.

A6b must stay coupled to reality, so the fix ships with its own non-vacuity proof (see acceptance 2):
a scratch **copy** of `audit-app.js` gaining a real third call site must still trip the assertion, and
the same copy gaining only a comment mention must not.

### Leg B — `test_seo_surface_audit.js`, criterion 2: a self-provisioning positive control

The control stops depending on a junk page existing in the estate — which it must not, ever again.
Instead, at run time the test writes a fixture that is a **copy of a real, committed page** with only
its `<h1>` replaced by a junk-slug one (`00 DeFi Yields`), points the override at it, and removes it in
a `finally`. Constraints, all load-bearing:

- The fixture must live **under `ROOT`** — both `buildStaticSurfaces()` (`path.join(ROOT, s.url)`) and
  `startServer()` (`path.join(ROOT, urlPath)`, plus an explicit `!filePath.startsWith(ROOT)` 403)
  resolve against the repo root, so an `os.tmpdir()` fixture is unreachable by construction. Put it at
  **depth 1** (same as `tokens/x.html`) so the page's relative asset refs resolve identically, and give
  it a pid-suffixed name so concurrent runs cannot collide.
- It must **never** land in `tokens/` or `chains/` — those are the SEO estate and are globbed by the
  generators. Deleting SEO surface is on the NEVER list; *adding* junk to it is the defect item 148
  just spent an item removing.
- The page it copies must be **byte-identical afterwards** (md5 asserted, item 184's method verbatim).
- The rendered check this drives is `audit-app.js:2473-2478`, which reads the **rendered `<h1>` only**
  and is path-independent — so a fixture outside `tokens/` still exercises the real detector, not a
  weakened one.

Criterion 2 additionally asserts `surfacesCovered` contains the control surface, so a future silent
drop can never be mistaken for a clean run.

### Leg C — `audit-app.js`: the override drop becomes audible

One `console.error` note in `buildStaticSurfaces()`'s override branch naming each dropped path, in the
file's established *"degrades safely (stderr note, no throw)"* idiom. Behaviour is otherwise unchanged:
the entry is still dropped, nothing throws, no finding is emitted, no exit code moves. This is the
smallest change that converts a silent vacuity into an observable one; anything larger (a finding, a
throw) changes what the merge gate blocks on and belongs to its own item.

## Metric to move

None — this is gate-integrity work with no user-facing surface and no funnel step. The measurable
outcome is **the audit lane's unexplained-red count: 2 → 0**, re-measured by the verifier on its own
run, and the elimination of the stashed-baseline triage those two reds impose on every future item.

Guardrails that must not move: `error_occurred`, planner conversion, and parameterized-URL rendering
are all untouched by construction (no product file changes).

## Acceptance criteria

Every criterion is measured by running the real gate, not by reading the diff.

1. `node test_audit_prescan.js` → **41 passed, 0 failed** (was 40/1). A6b passes.
2. **A6b is non-vacuous, proven both ways on a scratch COPY of `audit-app.js`** (original md5 asserted
   unchanged): (a) a copy with a genuine third call site added trips A6b's count assertion;
   (b) a copy with only an added *comment* mentioning `reconcilePrescanFindings(` does **not** trip it.
   Both directions asserted in the test file itself, not just demonstrated in the notes.
3. A6b's other guarantees are unchanged and still asserted: no
   `reconcilePrescanFindings(textSurfaceFindings`, both named call sites present, static leg passes
   `prefix: 'static-prescan'`, pool leg passes `prefix: 'pool-prescan'`.
4. `node test_seo_surface_audit.js` → **all 5 criteria pass**, criterion 2 included, run against real
   Chromium (this is a rendered acceptance test; the 2026-07-11 rendered-behaviour rule is satisfied by
   the real `runAudit()` renders, not by fixtures).
5. Criterion 2's fixture is **self-provisioning and self-cleaning**: created at run time, removed in a
   `finally`, and after the run `git status --porcelain` shows **no untracked or modified file** in
   `tokens/`, `chains/`, or anywhere else outside the intended diff. The copied source page's md5 is
   asserted identical after the run.

   `surfacesCovered`. Prove it by pointing the same assertion at a deliberately nonexistent page in a

7. `buildStaticSurfaces()` emits a stderr note naming a dropped override path, asserted by a test.
   No behaviour change beyond the note: the same run still returns the same surfaces, findings and exit
   code as before the change.
8. **Scope proof:** `git diff origin/main --stat` touches only `test_audit_prescan.js`,
   `test_seo_surface_audit.js`, `audit-app.js`, and `product-loop-kit/**`. Zero lines in `app.js`,

10. Plain lane green: `node run-tests.js --lane=plain` shows **no new failure** versus the baseline

## Risk

Author's guess: **LOW** — tests plus a single stderr line, no product file, no new dependency, and the
expected diff is well under the 150-line cap. The verifier assigns independently and should consider
one argument for HIGH: `audit-app.js` is the merge gate itself, and NORTH_STAR lists changes to what the
gate blocks on as a re-tier trigger (154/157/163/166/169/172/184 precedent). The counter-argument is
that Leg C is additive logging only — no finding, no severity, no exit-code path. If the verifier judges
that `audit-app.js` cannot be touched at LOW regardless of the line's semantics, HIGH is correct and the
full explainer + quiz is owed.

## Out of scope (do not build here)

- Item 170's browser-lane serialization / runtime problem. Different item, still open.
- Turning the silent override-drop into a *finding* or a hard failure. Leg C is a note only; escalating
  it changes gate semantics and needs its own spec.
- Any regeneration of `tokens/`/`chains/`. If a criterion appears to need the estate regenerated to go
  green, that is a signal to stop and re-read the spec, not to regenerate (item 184's precedent).
- Re-adding any junk-slug page to the committed estate under any name.
