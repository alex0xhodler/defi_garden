# PR: Re-brand the empty-state action buttons (backlog 016)

**Risk tier: LOW** (styling only, per spec 016's own tier and NORTH_STAR policy — no quiz required
for LOW). Git is unavailable in this environment (task constraint: no git operations, read-only bash
mount aside from grep/read/test-running), so there is no branch or commit — this file is the PR,
reviewable at the working-tree path cited below.

## Goal
"Show pools with lower TVL" and "Reset Filters" (`.reset-filters-btn`, app.js:2745-2752, unchanged
by this item) were the last gradient one-offs in the analytics empty state: a teal/blue gradient
with a colored glow shadow (`0 8px 25px rgba(33, 128, 141, 0.4)` on hover), predating the neumorphic
redesign, that grew prominent once 012 shipped a stronger empty state around them. This item brings
them onto the token-only neumorphic system — the human directive behind spec 016: "reuse components,
keep design tidy."

## Reuse check first (the new standing decision: reuse before inventing)
Hunted every button-shaped class actually rendered elsewhere in the app: `.btn`/`.btn--primary`
(dead CSS — zero JSX usage), `.filter-pill`/`.filter-button` (chip/toggle semantics, has its own
"selected" fill state), `.pagination-button` (pagination-specific), `.search-button` (closest visual
match — it's literally the button this one was designed to mimic — but its `display:flex` vs. this
button's `display:inline-flex` risks the empty-state layout, which 012 owns and this item must not
touch), `.start-earning-btn` (filled-primary CTA, visually too heavy for "both stay calm"). None
reusable as-is without either a semantic mismatch or a layout-model change outside scope. Full
candidate table and reasoning in `016-notes.md`. Re-tokened `.reset-filters-btn` in place instead,
following spec 016's own fallback recipe verbatim.

## What changed — style.css:2445-2477 only
No app.js edit — no class was reused wholesale, so there's no className to swap; the two buttons
keep `className: 'reset-filters-btn'` exactly as before.

Before:
```css
background: linear-gradient(135deg, var(--color-primary), var(--color-teal-600));
color: white;
border-radius: var(--neuro-radius-lg);
box-shadow: var(--neuro-shadow-raised), 0 4px 15px rgba(33, 128, 141, 0.3);

/* :hover */
background: linear-gradient(135deg, var(--color-teal-600), var(--color-teal-700));
box-shadow: var(--neuro-shadow-raised), 0 8px 25px rgba(33, 128, 141, 0.4);
transform: translateY(-3px);

/* :active */
box-shadow: var(--neuro-shadow-flat);
transform: translateY(0);

/* :focus-visible — none (relied on the un-scoped sitewide outline rule) */
```

After:
```css
background: var(--color-surface);
color: var(--color-text);
border-radius: var(--neuro-radius-md);
box-shadow: var(--neuro-shadow-raised);

/* :hover */
box-shadow: var(--neuro-shadow-flat);
transform: translateY(-2px);

/* :active */
box-shadow: var(--neuro-shadow-pressed);
transform: translateY(1px);

/* :focus-visible — new, explicit */
outline: none;
box-shadow: var(--focus-ring);
```

Zero gradients, zero new colors, zero px/rgba shadow one-offs remain — every value on the button is
a `var(--...)` token. `:active` sinks into `--neuro-shadow-pressed` with the documented 1px
press-physics convention (CLAUDE.md: "controls sink 1px into `--neuro-shadow-pressed` on `:active`
(global rule)"). `:focus-visible` gets an explicit box-shadow ring matching `.filter-pill`'s
treatment, on top of the sitewide outline ring that already covered this button before this change
(style.css:773-776 — it never overrode `outline`, so the "trust rail" was technically already
present; this makes it explicit and directly grep-able against the class itself). Dark mode and
360/768/1280 come free — no non-token value and no breakpoint rule was touched.

## Explicitly not done
- No app.js edit (no class was reusable wholesale — see reuse table in `016-notes.md`).
- No accent-color hierarchy between the two buttons. Spec bullet 2 says the primary action "may"
  use accent text color — optional — and doing it would need a new modifier class, which spec
  bullet 3 forbids beyond a 1:1 class replacement. Both buttons render identically calm, which the
  spec explicitly allows.
- Empty-state layout untouched — display model, gap, padding, margin-top all unchanged, per spec
  016's own OUT-of-scope line ("the empty-state layout (012 owns it)").
