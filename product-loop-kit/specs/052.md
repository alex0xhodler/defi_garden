# Spec 052: Precompile app.js/PoolDetail.js in CI — drop in-browser Babel

## Evidence
reports/2026-07-12-pagespeed.md. Analytics/SEO pages (`?token=`, `?pool=`, every `/tokens/`→app link) inject `app.js` (119K) + `PoolDetail.js` (52K) as `text/babel` and load `@babel/standalone/babel.min.js` (~2.9MB from unpkg) to transpile them on the main thread at page load (home.html ~300-310). This is the dominant mobile PageSpeed hit (TBT/LCP/TTI) and lands on exactly the SEO pages 011–051 optimized.

## Change
1. New CI step (in `sitemap-update.yml`, same pattern as the generators): transpile `app.js` + `PoolDetail.js` with `@babel/core` (JSX/React preset — they use React.createElement already, so mostly a plain pass; confirm the actual transforms needed) into committed `app.compiled.js` / `PoolDetail.compiled.js`. Add a `test`-chain check and an `npm run compile` script.
2. `home.html` analytics-conditional block: load the **compiled** files as plain `<script defer>` (NOT text/babel), and REMOVE the `@babel/standalone` injection + `Babel.transformScriptTags()` call. Do NOT touch the `__APP_MODE` router or `ANALYTICS_PARAMS`.
3. Keep `app.js`/`PoolDetail.js` as the editable source (unbuilt locally — CI compiles). `.gitignore`? No — commit the compiled files so Vercel serves them (same as sitemaps).

## Acceptance criteria
- [ ] Analytics pages load NO `@babel/standalone`; app + PoolDetail load as plain JS (grep home.html)
- [ ] The analytics app still mounts + renders pool cards on `?token=USDC`; planner still renders on `/` (test_smoke.js both paths)
- [ ] `__APP_MODE` router block + `ANALYTICS_PARAMS` byte-identical
- [ ] Compiled files produced by CI (not hand-edited); source app.js/PoolDetail.js unchanged as the edit surface
- [ ] Full test chain exits 0

## Risk tier
HIGH — home.html (sacred router) + the render path for all analytics/SEO pages. Needs test_smoke both-paths + a human render spot-check. Sequence before 053/056.

## Open questions
Confirm exactly which Babel transforms app.js/PoolDetail.js rely on (JSX? they claim React.createElement-only; if so the transpile is near-identity and even simpler). If truly no JSX, this may reduce to "load as plain JS + drop babel" with no compile step at all — verify first.
