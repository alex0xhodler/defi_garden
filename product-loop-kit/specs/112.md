## Origin

at 059's committed `data/pools-snapshot.json`. That was BLOCKED: the snapshot is $10M-railed

de-index ~1,800 token URLs (NEVER-list). The human was given the coverage analysis (specs/102.md,

that build. **Coverage must stay byte-identical to today — that is the whole point of A over the
rejected naive path.**

## Design (the transient-intermediate realization — better than 102.md's "committed JSON" sketch)

The three generators today each fetch `yields.llama.fi/pools` independently in `sitemap-update.yml`
(lines 84/90/96), on top of 059's `generate-pools-snapshot.js` fetch (line 72) — **4 live llama
fetches per CI run.** Collapse to ONE.

**Key refinement vs 102.md:** the shared SEO source is a **CI-internal transient**, NOT a committed
or served artifact. This matters:
- No git-bloat (102.md's stated cost of A disappears).
- **No new DefiLlama re-serve / ToS exposure** — nothing extra is published to our CDN or shipped
  to users; the generators still emit the exact same public HTML + sitemaps. So item **107**
  (ToS/attribution keystone) stays scoped to the $10M FE snapshot only; 112 does not widen it.
  (Had A committed/served a $1000 snapshot, it WOULD widen 107 — flag preserved for the record.)

**Mechanism:**
1. One fetch feeds everything. Extend `generate-pools-snapshot.js` (059) so the SAME `/pools`
   fetch that produces the committed $10M FE snapshot ALSO writes a **$1000-floored transient**
   pool array to a scratch path (e.g. `--seo-out <path>`, default off; CI passes an explicit
   scratch path OUTSIDE committed surface — 076 `--out`-isolation lesson). No behavior change to
   the committed `data/` outputs. If splitting 059 is undesirable, a tiny standalone
   `prefetch-pools.js` that fetches once and writes the transient is an acceptable alternative —
   builder's call, whichever keeps the diff smaller and 059's outputs byte-identical.
2. The transient = every pool with `tvlUsd >= 1000` (the sitemap's own hygiene floor, line 129 —
   the loosest floor any consumer needs), projected to the fields the generators read, with **no
   other filter removed**. This is a provable **superset** of every pool the three generators
   keep (token/chain floor $100K > $1000; sitemap skips `< 1000`; sub-$1000 pools are used by
   none of them — verified: token/chain TVL sums run only over $100K-qualifying pools, sitemap
   `extractValidCombinations` skips `< 1000`). Feeding this transient is therefore output-identical
   to feeding each generator the full live array. (Maximal-safety variant: ship the transient
   unfiltered — bigger file, zero floor-reasoning risk. $1000 is the recommended default.)
3. Wire the generators to consume it:
   - `generate-token-pages.js` / `generate-chain-pages.js`: already read `--fixture` /
     `POOLS_FIXTURE` (lines 892-908 / 419-435). CI passes the transient path. Zero code change.
   - `generate-sitemap.js`: `generateSitemapSuite(poolsOverride)` already accepts pools
     programmatically (line 324/330), but its CLI `main()` (line 624) always live-fetches. Add a
     `POOLS_FIXTURE` / `--fixture` read to `main()` that loads the array and passes it as
     `poolsOverride` — the ONLY product-code change to a generator, tiny and filter-neutral.
4. `sitemap-update.yml`: fetch once (step 1's transient), then run all three generators pointed at
   it. Keep 059's `generate-pools-snapshot.js` committed-output step exactly as-is.

## Live fallback (non-negotiable — no coverage regression on a bad fetch)

If the shared fetch/transient is missing or empty at generator time, each generator falls back to
its **existing** live `fetchPoolData()` — today's exact behavior, today's exact coverage. The
`--fixture` path must fail SAFE to live, never fail to an empty/partial run that would prune the
sitemap. A malformed/empty transient → live fallback, not a truncated sitemap.

## Acceptance criteria

**A. One fetch, shared source**
- A1. CI performs exactly ONE `yields.llama.fi/pools` fetch per run (down from 4); the $10M FE
  snapshot and the SEO transient both derive from it. Prove by grepping the workflow + a dry-run
  log showing a single fetch.
- A2. The transient is written only to an explicit scratch path outside committed surface; `git
  status` after a full CI-equivalent run shows NO new/committed transient file (076 lesson).

**B. Byte-identical coverage (THE guardrail — A's entire justification)**
- B1. A `tokens/` + `chains/` + every `sitemap-*.xml` produced from the shared transient is
  **byte-identical (modulo the lastmod/date placeholder)** to the same generators run against a
  direct live fetch of the SAME `/pools` payload. Prove with a scripted diff over one captured
  fixture: `run-live` vs `run-shared` → `diff -r` clean. **0 dropped `/tokens/` pages, 0 dropped
  `/chains/` pages, 0 dropped sitemap `<loc>`.** Target counts to hold: 2,131 token-page URLs
  (×2 en/ko), 86 chain-page URLs (×2), the per-chain `?token=&chain=` combos, the category
  sitemaps, 105 `?token=` deep links, 12 static — ~4,881 total.
- B2. Rendered spot-check on both router paths unaffected (this item touches CI generation only,
  not `app.js`/`planner.js`/`home.html`; note that explicitly and skip Playwright UI driving —
  the acceptance surface is generated files, verified by diff, not runtime UI).

**C. Fallback proven**
- C1. Transient absent → each generator live-fetches and produces the same full output (fixture
  test simulating a missing/empty transient; assert non-empty sitemap + full token/chain set).

**D. Trust rails (binding)**
- D1. Rails applied at the shared filter are the SAME rails, mirrored verbatim, never relaxed:
  the $1000 transient floor is a superset gate, not a rail change; each generator's own
  `APY_SANITY_LIMIT` / `MIN_POOL_TVL` / anomaly handling stays byte-untouched. No rail moved.
- D2. Attribution ("Powered by Defillama API") and every generator's public output semantics
  unchanged.

**E. Tests + bookkeeping (same single commit as the code — 2026-07-13/14 standing decisions)**
- E1. A `test_seo_shared_source.js` (pure Node, fixture input, ≤5 min): asserts the shared-source
  run == live-source run for all three generators (the B1 diff, automated), and the fallback (C1).
- E2. Full existing `npm test` chain green.
- E3. BACKLOG status, `specs/112-notes.md` (deviations), `specs/112-pr.md` (HIGH-tier full
  explainer + 5-question quiz, answers base64), LOG.md entry — all in the same commit.
