## Hypothesis
We believe a proxy-enabled logging Worker writing per-request rows for the agent surface into D1 gives
the heartbeat a truthful daily agent-consumption signal, because Cloudflare sees every request (JS or
not) and the D1 read-path from CI/heartbeat is already proven by item 108/110.
Confidence: supported.
- Instance of: instrument-blindness on non-JS traffic — the population is EVERY consumer that never
  executes analytics.js (AI crawlers, agents, curl, feed readers).
- Class closed by this item: yes for the read-visibility class on the proxied domain; the un-proxied
  gap (any request bypassing Cloudflare) is 0 by construction once the DNS proxy is on.

## Change
1. New Worker (NEW top-level dir, e.g. `edge/` — NOT `workers/`, which is out-of-scope funds code),
   route `www.defi.garden/*`: pass-through fetch to origin (Vercel), and for requests matching the agent

## Territory notes
<!-- Build loop appends findings from the blindspot pass here. -->
Found during the 2026-08-04 build (blindspot pass + implementation):

1. **The house Worker pattern already exists and was mirrored, not reinvented**: `src/poller.js` (ESM
   `export default`, bundled by wrangler) + `src/poller-core.js` (CJS `module.exports`, unit-tested by
   plain `node test_poller.js`) + root `wrangler.toml` (with a HUMAN-provisioning comment block) +
   `schema.sql`. `edge/` reproduces that split exactly. The root `wrangler.toml` is UNTOUCHED — this is a
   second, independent Worker sharing only the D1 database.
2. **`edge/agent-log.mjs`, not `.js` (deviation).** The test must `import()` the REAL Worker file natively
   in plain Node (spec's own "never a copy" requirement). Node decides ESM/CJS per file by extension or an
   inherited `package.json` "type"; the repo root has no `type` field and every other `.js` is implicitly
   CJS. A directory-scoped `package.json` in `edge/` would force `agent-log-core.js` into ESM too and break
   the `require()`-ability the house test pattern needs. `.mjs` is the per-file escape hatch; wrangler
   bundles it identically.
3. **`main` in `edge/wrangler.toml` is `agent-log.mjs`, not `edge/agent-log.mjs` (deviation).** Wrangler
   resolves `main` relative to the config file's directory. The root config's `src/poller.js` happens to be
   correct both ways because that config sits at the repo root; a config inside `edge/` does not.
4. **Path-class precedence is load-bearing, not decorative.** `.well-known/agent-skills/agentic-readiness/SKILL.md`
   is a real on-disk file that is BOTH under `/.well-known/` and ends in `.md`. `well_known` is checked
   before `md_twin`, and the test asserts that specific file's class so a future reorder fails loudly.
5. **`tools/test-agent-tools.js` is a real non-JSON file under `tools/`** — used as a precision negative
   control against the `/tools/*.json` rule (the rule must not widen to "anything under /tools").
6. **The agent surface is wider than the spec's list.** The spec named llms.txt/llms-full.txt/`**/*.md`/`/api/*`.
   `.vercelignore`'s own header documents `/.well-known/` (incl. its `.md`/`.py`/`.js`/template files),
   `openapi.json` and `tools/*.json` as LIVE agent-discovery assets. Logging them is the weaker predicate
   (RAZOR.md: no check narrower than the class it guards) — a logger blind to them would under-report
   north-star leg (A) exactly where agent discovery starts. Classified as `well_known`, so the slice stays
   separable at query time.
7. **KNOWN GAP, deliberately not built (out of this spec's Change list): no retention prune runs.**
   `RETENTION_DAYS`/`retentionCutoff()` exist and are tested, but this Worker has only `fetch()` — no
   `scheduled()` Cron Trigger — so nothing calls them automatically. `agent_reads` grows unbounded until
   pruned. `edge/DEPLOY.md` documents the manual prune command; the follow-up item is backlog **232**
   (filed in the same commit as this item).
