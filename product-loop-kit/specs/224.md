# Spec 224: Edge telemetry — make agent reads measurable (Cloudflare Worker → D1)

## Evidence
- Item 212 (LEARNINGS 2026-08-03): agent reads of `/tokens/<slug>.md` are "structurally unmeasurable...
  no client-side event can fire for an agent that never runs JS. Any future claim needs edge/server
  request logging by `Accept` header first (a different item)." **This is that item.**
- 60d Mixpanel (`3b2555fb`, 2026-08-04): perplexity.ai sent 2 referred sessions unprompted; bing-family
  ~14. The whole GEO channel currently produces exactly these client-side crumbs — everything a non-JS
  agent does on the site is invisible.
- The domain is ALREADY on Cloudflare (human, interview Q1); the account already runs a Worker + D1
  (`defi-garden-history`, item 108, hourly poller live since 2026-07-23).
- North-star leg (A) (2026-08-04) counts "verified AI-crawler reads of the agent surface" — undefined
  until this log exists.

## Hypothesis
We believe a proxy-enabled logging Worker writing per-request rows for the agent surface into D1 gives
the heartbeat a truthful daily agent-consumption signal, because Cloudflare sees every request (JS or
not) and the D1 read-path from CI/heartbeat is already proven by item 108/110.
Confidence: supported.
- Instance of: instrument-blindness on non-JS traffic — the population is EVERY consumer that never
  executes analytics.js (AI crawlers, agents, curl, feed readers).
- Class closed by this item: yes for the read-visibility class on the proxied domain; the un-proxied
  gap (any request bypassing Cloudflare) is 0 by construction once the DNS proxy is on.

## Change
1. New Worker (NEW top-level dir, e.g. `edge/` — NOT `workers/`, which is out-of-scope funds code),
   route `www.defi.garden/*`: pass-through fetch to origin (Vercel), and for requests matching the agent
   surface — `llms.txt`, `llms-full.txt`, `**/*.md`, `/api/*` (future), plus `Accept: text/markdown`
   negotiations — INSERT `{ts, path, ua, accept, referer, status, bot_score?}` into D1 table
   `agent_reads` (item-108 database, new table; write-behind via `ctx.waitUntil`, never blocking the
   response; failure = silent pass-through, logging must never break serving).
2. Daily aggregation query (by UA-family × path-class) exposed the same way 110 reads history — the
   heartbeat's §2 gains an "agent reads" read.
3. One-page deploy runbook (`edge/DEPLOY.md`): wrangler deploy + enable orange-cloud proxy on the DNS
   record. **Human executes both** (credentials); code + runbook are the loop's deliverable.
OUT of scope: any caching/redirect/WAF behavior change (pass-through only, this item); the 227 API
(separate item, same scaffold); touching `workers/`.

## Acceptance criteria
- [ ] Worker unit tests (miniflare/vitest or the house pattern): agent-surface request → row written with
      correct fields; non-agent path → no row; D1 outage → response still 200 pass-through.
- [ ] Response BYTE-parity proof: for a sample of paths (html, md twin, llms.txt, an asset), body+status
      via the Worker === direct origin fetch.
- [ ] Runbook complete enough that the human can deploy without reading Worker source.
- [ ] Heartbeat read documented: the exact query returning "reads by UA-family by day".
- [ ] Non-vacuity: point the logging match at a nonexistent-path pattern in a scratch copy → the
      agent-surface test goes red (0 rows where ≥1 expected); restore byte-identical → green.
- [ ] Population: tests draw paths from the REAL generated estate on disk (a sampled md twin, llms.txt,
      a token page), never a hardcoded fixture-only path.
