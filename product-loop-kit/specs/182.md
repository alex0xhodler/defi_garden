# Spec 182: the "Start Earning" CTA must not depend on a silently-failing third-party fetch

## Evidence

All numbers measured 2026-07-30 (`signals/2026-07-30.md`), against live sources, not the checkout snapshot.

1. **`audit-app.js` this tick, verbatim finding:**
   ```
   { "surface": "pool-detail:ae6b7add", "viewport": "1280px", "check": "dead-cta",
     "severity": "P1", "detail": "\"Start Earning\" (.cta-button-protocol) missing or not visible" }
   ```
   `ae6b7add-6505-492e-9bee-0e55fa8c5670` = uniswap-v4 PAXG-ILMU, Polygon, $13,983,796 TVL.

2. **That button is half the north star.** NORTH_STAR.md line 17 defines the metric as
   `pool_click` where `source ∈ {garden_cta, protocol_link}`; `PoolDetail.js:517` is the `protocol_link`
   emitter and it sits inside this CTA.

3. **Render gate.** `PoolDetail.js:583` (hero) and `PoolDetail.js:1662` (repeat footer) are both
   `protocolUrlWithRef && React.createElement('button', { className: 'cta-button-protocol', … })`.
   Falsy URL ⇒ **no element, no fallback, no explanation**.

4. **Resolution chain** — `app.js:2429` `getProtocolUrl(pool)`:
   `pool.url` → `dynamicProtocolUrls[key]` → `dynamicProtocolUrls[pool.project]` → `PROTOCOL_URLS[key]` → `null`.
   - `pool.url` is **never present**: no DefiLlama pools payload carries a `url` field (established by
     item 166, which deleted a `pool.url || meta.baseUrl` branch that had been firing on 100% of rows).
   - `dynamicProtocolUrls` is built from a **second, different third-party endpoint** —
     `https://api.llama.fi/protocols`, not the pools API — fetched at runtime ~100ms after mount and
     **failing silently by design** (`app.js:1285`: *"Fail silently - static PROTOCOL_URLS will be used as
     fallback"*). Result cached permanently in `localStorage['defi-protocols']`, so **the first visit
     decides** — the SEO-arrival cohort.
   - `PROTOCOL_URLS` (`app.js:7`) has **96 entries**, hand-maintained.

5. **Coverage of the static fallback — what survives a failed/blocked `api.llama.fi/protocols` fetch:**

   | population | CTA survives | CTA vanishes |
   |---|---|---|
   | today's 741-pool snapshot | 525 (70.9%) | **216 (29.1%)**, $8.9B TVL, **134 distinct projects** |
   | pool-detail pages the SEO estate deep-links (438 of 3,677 `?pool=` ids resolvable in-snapshot) | 290 | **148 (33.8%)** |

   Largest uncovered projects: `uniswap-v4` (10 pools), `pendle` (8), `aave-v4` (6), `orca-dex` (5),
   `nest-credit` (5), `navi-lending` (5), `vaneck-treasury-fund` (4), `liquity-v2` (4),
   `apollo-diversified-credit-securitize-fund` (4).

6. **The audit finding is the degraded path, not a broken pool — verified, and it survives the check.**
   A live in-session fetch of `https://api.llama.fi/protocols` returned **7,962 protocols / 5,181 url
   keys**, and `uniswap-v4` **does** resolve there (`https://app.uniswap.org/`). The harness blocks that
   host, so the scanner faithfully reproduced the ad-blocker / outage / CSP / slow-paint / early-bounce
   condition. Per `playbooks/product-audit.md`, a fixture-caused finding must be checked before ticketing —
   this one was, and the check **enlarged** it from one pool to 29.1% of the estate.

7. **One pool is unreachable even on the happy path.** Project `sdai` ($61M, 1 pool) resolves to no URL
   from live-dynamic *or* static. Its detail page permanently renders one of the two north-star CTAs.

8. **The class was opened and closed once before, by hand.** Item 138 added a single static
   `sky-lending` entry after the same defect hit the ICP's flagship stablecoin lender;
   `test_protocol_cta_fallback.js` guards **that one protocol** with a 2-fixture test (1 positive,
   1 negative control). Nothing asserts coverage across the estate. This is item 175's
   "checker inherits the shape of the last bug" thesis in its **repair** costume: the fix, not just the
   detector, was scoped to the instance that bit us.

## Hypothesis

We believe **serving the protocol-URL map from our own origin (a CI-baked artifact, exactly like
`data/pools-snapshot.json`) and rendering an honest labelled fallback when no URL exists at all** will
**make the `protocol_link` half of the north star present on ~100% of pool-detail renders instead of
70.9% on the degraded path**, because the CTA's absence today is caused entirely by a runtime dependency on
a third-party host that the app itself documents as allowed to fail, and the data needed to remove that
dependency is already fetched daily by CI for the pools snapshot.

Confidence: **supported** — the coverage numbers are measured, not estimated, and the resolution chain is
read from source. The *conversion* effect is unmeasurable at current traffic (0 north-star clicks in 22
days) and this spec does not claim one; the claim is presence, which is measurable today.

## Change

Smallest version that closes the class rather than one more instance.

**(A) Bake the map — remove the runtime third-party dependency.**
- New generator script producing **`data/protocol-urls.json`**: `{ generatedAt, urls: { <key>: <url> } }`,
  built by fetching `https://api.llama.fi/protocols` and keying **exactly as `app.js:~1270` already does**
  (`protocol.name.toLowerCase().replace(/\s+/g,'-')`, plus `protocol.slug` when it differs) so the baked
  keys and the runtime keys cannot drift apart. Restrict entries to projects present in
  `data/pools-snapshot.json` to keep the artifact small.
- Wire it into the **same CI workflow that already regenerates the snapshot**, so it self-heals daily and
  new protocols appear without a hand edit. It must ride an **existing** scheduled job — do not add a new
  workflow or a new deployment trigger (2026-07-13 standing decision: Vercel quota).
- `getProtocolUrl()` gains **one tier**, inserted between dynamic and static:
  `pool.url → dynamicProtocolUrls → bakedProtocolUrls → PROTOCOL_URLS → null`.
  Load `data/protocol-urls.json` from our own origin with the same defensive/silent-failure posture the
  snapshot loader already uses. **Do not delete** the dynamic fetch or the static map — this is additive
  depth, and keeping the live fetch first means a protocol that changes its URL between bakes still wins.

**(B) Stop rendering nothing — honest fallback for the true-null case (`sdai` and any brand-new protocol).**
- When all four tiers return null, render a labelled link to that pool's **DefiLlama page**
  (`https://defillama.com/yields/pool/<pool.pool>`) instead of an empty space.
- **It must not impersonate the protocol CTA.** Different copy (EN + natural KO together, via
  `translations.js`) naming DefiLlama as the destination — never *"Start Earning on <protocol>"*.
- **It must not inflate the north star.** It fires `pool_click` with **`source: 'defillama_fallback'`**,
  a fourth disjoint value alongside `garden_cta`/`protocol_link`/`yield_calculator`. NORTH_STAR line 17's
  filter is `source ∈ {garden_cta, protocol_link}`, so the metric is unaffected by construction.
  **Reusing `protocol_link` here is a verifier FAIL** — it would silently redefine the north star.

**(C) Instrument the thing we just claimed, so the next tick can check it without a code read.**
- Add property **`protocolCtaPresent: true|false`** to the existing `pool_view` event
  (`Analytics.trackPoolView`). No new event. This makes the degraded-path rate a one-query read in
  Mixpanel instead of the four-hour investigation this tick required.

**Explicitly OUT of scope**
- Any change to `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly demotion, or the degen haircut — untouched.
- The `garden_cta` CTA, `home.html`'s `__APP_MODE` router, `?token=`/`?chain=`/`?pool=` behaviour.
- Item 133 (discovery below the $10M floor) — human-gated, unrelated.
- Hand-adding entries to `PROTOCOL_URLS`. That is item 138's move and it is what failed; a hand-maintained
  map that needs 134 more entries is not a fix. **A diff that only grows the static map is a verifier FAIL.**
- Removing the `api.llama.fi` runtime fetch.

## Acceptance criteria

- [ ] `data/protocol-urls.json` exists, is generated by a committed script, and its keys are derived by
      **the same expression** as `app.js`'s runtime mapping — proven by a test that reads both, not by
      inspection. A second hardcoded copy of the key transform is a FAIL (item 166's precedent:
      `test_llms_link_integrity.js` parses `home.html:77-78` rather than duplicating the list).
- [ ] The generator is wired into an **existing** scheduled CI job. No new workflow file, no new
      deployment trigger. Show the workflow diff.
- [ ] **Coverage, measured on the real corpus and reported as a number:** with `dynamicProtocolUrls` forced
      empty (the degraded path), the share of today's snapshot pools for which `getProtocolUrl()` returns
      non-null goes from **70.9%** to **≥ 99%**. State the exact before/after counts out of 741.
- [ ] **Non-vacuity, proven not asserted:** delete the new baked tier, re-run, and show the coverage number
      falls back to ~70.9% and the relevant test goes red; restore and show byte-identical.
- [ ] Rendered Playwright (real Chromium, house fixture-routing pattern — external HTTPS is
      connection-blocked per NORTH_STAR 2026-07-12), extending or siblinging `test_protocol_cta_fallback.js`:
  - [ ] With the dynamic fetch aborted, a pool from a project with **no** static entry
        (use `uniswap-v4`) renders `.cta-button-protocol`, and clicking it fires
        `pool_click{source:'protocol_link'}`. **This case must be shown to FAIL on `origin/main`** — that
        is the regression this item exists to close.
  - [ ] A pool whose project resolves in **no** tier renders the DefiLlama fallback, its copy does **not**
        contain the protocol-CTA string, and clicking it fires `pool_click{source:'defillama_fallback'}` —
        **never** `protocol_link`.
  - [ ] `pool_view` carries `protocolCtaPresent`, `true` in the first case and `false`/`true` matching the
        rendered reality in the second.
  - [ ] KO renders the fallback copy in natural Korean (EN-only is a FAIL per the risk policy).
- [ ] `translations.js` EN + KO updated together; no bare `toLocaleString()`; neumorphic tokens only, no new
      gradient/one-off styling (2026-07-10 reuse directive). Reuse the existing
      `.cta-button-protocol` / `.pool-action-hint--muted` classes — **zero new CSS** is the target.
- [ ] Compiled/minified bundles regenerated for every source file touched (`home.html` loads the compiled
      artifacts, not the sources) — the item-165 precedent.
- [ ] Trust rails byte-identical: `git diff origin/main` shows no change to `APY_SANITY_LIMIT`,
      `DEFAULT_MIN_TVL`, the anomaly demotion block, or the degen haircut. No sitemap entry, page, or
      `stories/` file deleted.
- [ ] Test gate: `run-tests.js --lane=plain` green, plus the new/extended browser-lane test run and its
      result stated. If the browser lane is not fully run, say so explicitly — **"unrun" stated beats
      "green" implied** (2026-07-11 timebox decision).
- [ ] Instrumentation: `pool_click` fires with `source='defillama_fallback'` on the fallback path;
      `pool_view` carries `protocolCtaPresent: boolean`. NORTH_STAR line 17's `source` filter still selects
      exactly `garden_cta` + `protocol_link`.

## Measurement

**Primary (presence, measurable now):** share of `pool_view` events with `protocolCtaPresent: true`.
Baseline: unmeasured today (the property does not exist); the code-derived degraded-path baseline is
**70.9%** of snapshot pools / **66.2%** of SEO-linked pool-detail pages. Target ≥ 99%.
Window: 14 days · Decision rule: keep if the observed rate is ≥ 95%; if it sits below, the baked artifact
is not loading in prod and the item is a REVERT-CANDIDATE regardless of local test results.

**Secondary (conversion — explicitly NOT claimed):** `pool_click{source=protocol_link}` is 0 all-time and
prod traffic is ~86 sessions/14d, far under the ≥30-events minimum-sample rule. **No conversion window is
opened on a zero-traffic funnel** (2026-07-27 takeaway). Re-evaluate when `pool_view` ≥ 30 in a window.

## Risk tier (builder's guess — verifier assigns independently)

is de-indexed, no credentials involved. Per policy this still auto-merges on verifier PASS, but requires
the full explainer + 5-question quiz in `specs/182-pr.md` **before** merge, and top billing in the next
report.

Needs human visual spot-check: **YES** — pool-detail render path, new user-facing element and copy.

## Open questions

None that block. The one judgment call — whether the true-null fallback should point at DefiLlama or simply
render an honest "no link available" note — is resolved **in the spec** rather than escalated: DefiLlama is
already the app's cited data source and the destination is honest and useful. If the human disagrees, the
change is one string and one href.
