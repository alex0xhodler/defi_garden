# 064 — PR explainer (LOW tier)

## What shipped
`generate-spotlight.js`'s share URLs now carry `src=x_spotlight` + a stable per-pool `ref` (reused from the same slug already used for the output directory). `planner.js` threads the arriving `?src=` onto `Bloom`'s `plan_created`/`waitlist_opened` events (`analytics.js` gains a `source` field on `trackPlanCreated` to match — `trackWaitlistOpened` already had one). The generator also writes `spotlights/CADENCE.md` on every run: which pools are already spotlighted + the next N qualifying, uncovered candidates, so the human's weekly posting stays systematic and non-repeating.

No UX/copy change, no new event names, no new dependency.

## Why
060 shipped the spotlight pack generator, but its share URL carried no attribution — any garden or waitlist opened from an X spotlight post was invisible in Mixpanel, at the exact moment (traffic decaying 167→80→80→21/day) X spotlights are the only in-theme distribution channel. This closes that gap and gives the human a running coverage list instead of guessing which pool to spotlight next.
