# Spec 047: GEO/AEO — direct-answer opener + FAQPage on token/chain pages

## Evidence
Direct grep, 2026-07-12:
- No FAQ or direct-answer block on any token or chain page — the only `FAQPage` on the whole site is `stories/kevin.html` (040). `grep -icE "faq|question" tokens/1inch.html chains/*.html` → the only matches are the "Related tokens/chains" `<h2>`, not a Q&A block.
- Token/chain pages currently open with a single data-derived intro sentence ("`<TOKEN>`'s largest live pool is `<project>` on `<chain>` at `<apy>` …"), which states a fact but does not answer the head query ("what is the best `<TOKEN>` yield?", "is `<TOKEN>` yield safe?") in the extract-friendly, answer-first format AI engines reward.
- 2026 SOTA (GEO/AEO): ~70% of DeFi-category queries resolve inside AI answers; AI systems that use real-time retrieval judge relevance primarily on a page's opening content — the first ~200 words should directly and completely answer the primary query. FAQ/definition blocks are prime citation fuel; `FAQPage`'s visual SERP rich-result was retired 2026-05-07 but the markup stays valid and is still consumed by AI answer engines for citation context.

## Hypothesis
We believe adding (a) a direct-answer opening block that answers "what's the best/safest `<TOKEN>`/`<CHAIN>` yield right now?" in the first ~200 words, and (b) a small data-derived `FAQPage` (with matching JSON-LD), will increase AI-answer citation likelihood and head-query relevance for the token/chain pages — because their current data-intro doesn't lead with a query-answering statement and carries no FAQ schema, while 2026 AI retrieval weights exactly those. Confidence: **supported by external 2026 sources; unvalidated here.**

## Change
Content + schema, additive, trust-rail-consistent (every number still derived from the same live pool data through the same sanity rails):
1. Token/chain generators: add a short **direct-answer block** immediately after the H1 — 2–4 sentences that answer the head query using data already computed (e.g. "The highest honest `<TOKEN>` yield right now is `<apy>` on `<project>` (`<chain>`), among `<n>` pools above the $100K TVL floor. Rates are live from DefiLlama and exclude anomalous (>1000% APY) pools."). Answer-first, then context. Copy ban-list + honesty rules from CLAUDE.md apply.
2. Add a small **`FAQPage`** (2–4 Q&A) built from real page data, e.g. "What's the highest `<TOKEN>` yield today?" / "How many `<TOKEN>` pools clear the TVL floor?" / "Are these rates safe?" (answer references the trust filters honestly — TVL floor, anomaly exclusion, education-not-advice). Visible HTML Q&A + matching `FAQPage` JSON-LD whose `mainEntity` text is byte-for-byte the visible answer (Google's must-match-visible-content rule — the 040 kevin precedent).
3. EN + KO for any user-facing copy IF these pages later gain i18n (they're English-only today per 050; for now EN only, but write the copy through a structure that 050 can translate — do not hardcode in a way that blocks 050).

OUT of scope: changing the pool table, ranking, canonical, trust rails; adding `HowTo` schema (not applicable); the direct-answer block must never quote an anomalous or sub-floor pool (trust rail — reuse the same gated data the table already uses).

## Acceptance criteria
- [ ] Every generated token/chain page renders a visible direct-answer block within the first content section (after H1, before the table) that answers the head query using only gated (non-anomalous, ≥$100K TVL) data already on the page. Verified on a fixture-generated page.
- [ ] Every generated token/chain page renders a visible `FAQPage` Q&A block (2–4 items) AND a matching `FAQPage` JSON-LD whose `mainEntity[i].name`/`acceptedAnswer.text` are byte-for-byte the visible question/answer text. Verified programmatically (parse JSON-LD, compare to rendered text) — the 040 kevin invariant.
- [ ] No anomalous or sub-floor pool appears in the answer block or FAQ (trust rail). Verified with an anomaly fixture (a $900M @ 2100% pool leaves no trace, as in existing token-page tests).
- [ ] No change to the pool table, canonical, ranking, or trust-rail constants — additive content + schema only.
- [ ] Tests: new assertions in `test_token_pages.js`/`test_chain_pages.js` (answer block present, FAQ↔JSON-LD byte-match, anomaly exclusion), in the `npm test` chain.
