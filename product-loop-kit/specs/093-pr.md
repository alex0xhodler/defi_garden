# 093 — PR explainer (HIGH tier)

## Goal
Restructure the analytics app's sticky-header nav strip so it stops mixing two different kinds of control in one undifferentiated row. Before: category tabs (All / Lending / Staking / LP·DEX / RWA / Yield Derivatives — "what am I browsing") sat as flat siblings next to filter buttons (Chains / TVL / Protocols / APY — "how is it narrowed"). After: a clear **primary category rail**, a hairline **divider**, and a **secondary filter cluster**, each control carrying a consistent monochrome icon, with the filter labels finally routed through EN+KO translations.

## Intuition
This is the analytics app's most-used control surface, and its information architecture had a state-vs-action smell: switching *what you browse* looked identical to *filtering what you see*. Grouping the two, separating them with a divider, and giving each control an icon that inherits the control's own text color (so the active tab's icon turns primary-blue automatically) makes the hierarchy legible in one glance — without inventing any new component or breaking the sacred parameterized-URL behavior underneath.

## What changed and why (diff in reading order)

1. **`app.js` — `CATEGORY_TABS` (~L95):** each entry gained an `icon` key (`all`/`lending`/`staking`/`lpdex`/`rwa`/`yieldderiv`). `key` and `labelKey` values are byte-identical — no classification change (091 owns taxonomy).
2. **`app.js` — new `NAV_ICONS` map + `navIcon(key)` helper (~L104–150):** ten Lucide-style single-glyph 24×24 line icons rendered as a 16×16 `<svg fill="none" stroke="currentColor" stroke-width="1.8" aria-hidden>`. `currentColor` is the whole trick: the icon inherits the button's text color, so inactive (secondary) / active tab (primary) / has-selection filter (white) recolor for free — no extra active-state code.
3. **`app.js` — nav render block (~L2745):** `.google-nav-tabs` (unchanged outer scroll container) now wraps three children in order: `.google-nav-primary` (the category tabs), a `.google-nav-divider` span (`aria-hidden`), and `.google-nav-secondary` (the four filter buttons). Every control is now `navIcon(...)` + a `<span class="google-nav-label">`. **Class names `google-nav-tab`/`google-filter-btn` and IDs `chains-btn`/`tvl-btn`/`protocols-btn`/`apy-btn` are preserved verbatim** — the press-physics `:active` rule, the existing render tests, and the dropdown positioning (`document.getElementById('chains-btn').getBoundingClientRect()`) all still key off them untouched. The filter *default* labels now read `t('navFilter*')`; the selected-state dynamic labels (money/number, pinned en-US) are unchanged.
4. **`translations.js` (EN ~L28, KO ~L644):** added `navFilterChains/Tvl/Protocols/Apy` to **both** language blocks together (KO: 체인 / TVL / 프로토콜 / APY). This also closes a latent CLAUDE.md hard-rule violation — those four labels were previously hardcoded English.
5. **`style.css` (~L1092):** new `.google-nav-primary` / `.google-nav-secondary` (flex groups) / `.google-nav-divider` (1px × 20px `--color-border` hairline); `display:inline-flex; align-items:center; gap` added to the two button classes so icon+label align; the old ad-hoc `margin-left` on `.google-filter-btn` removed (the divider + secondary `gap` now provide separation); mobile block keeps groups+divider on one horizontally-scrollable row at 360px and shrinks icons to 14px. Tokens only → dark-mode-safe by construction.
6. **`test_nav_rail_ia.js` (new):** rendered-Playwright gate mirroring the `test_category_taxonomy.js` harness (fixture-routed real chromium). Ten assertions, one per spec acceptance criterion, all on real DOM structure/geometry (grouping + DOM order, group membership, preserved IDs, an `<svg>` in every control, single-`.active` + grid re-filter on tab click, dropdown geometry off `#chains-btn`, KO default labels, sticky-after-scroll, 360px survival, zero page errors).
7. **Regenerated** `app.compiled.js` / `app.compiled.min.js` / `translations.min.js` / `style.min.css` via `npm run compile && npm run minify` (home.html ships the `.min` assets).

## Deviations from spec
- **Acceptance #7 (KO label):** `?chain=Base` populates `selectedChain`, so the Chains button renders "Base", not the default `t()` label, in any language — the spec's literal `?chain=Base&lang=ko` Chains-default check is unreachable. The test asserts the default labels under `?token=USDC&lang=ko` (leaves `selectedChain` empty): Chains===체인 AND Protocols===프로토콜. Faithful substitute, zero product-code change.
- **Acceptance #8 (sticky):** the header rests at ~8px top (a pre-existing baseline, reproduced by the verifier against a pre-change stash), so exact `top===0` would be a false-failure trap. The test asserts the header stays pinned (top ≤12px) and unchanged (Δ≤1px) across a scroll — the true meaning of "stayed fixed".

Both deviations were independently reviewed by the verifier and judged faithful, not evasions.

## Risk
HIGH — user-facing render-path DOM restructure + new iconography on the analytics app's primary browse/filter surface (beyond copy/styling; NORTH_STAR risk policy places this in HIGH by rule). **Not** on the NEVER-auto-merge list: no trust-rail weakening (`APY_SANITY_LIMIT`/`DEFAULT_MIN_TVL`/anomaly/haircut grep-confirmed untouched), no credentials/money, no SEO deletion, no `__APP_MODE` router or `?token=/?chain=/?pool=` semantics change (nav chrome only — same pools, same canonical, SEO lifeline intact). Verifier PASS, independently re-derived HIGH, 10/10 acceptance + regression suite green. Render-path → needs human visual spot-check (003 smoke gate is not pixel-level).
