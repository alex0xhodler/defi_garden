## Problem

`package.json`'s `test:serial` chain is the **single source of truth** for what `npm test` runs.
`run-tests.js` deliberately holds no second copy: `readSerialChain()` (run-tests.js:76-85) reads
`scripts["test:serial"]` and `parseFileList()` (run-tests.js:63-74) splits it on `&&` — the header
comment at run-tests.js:5-6 states this explicitly ("never a second hardcoded copy").

The consequence nobody enforced: **a `test_*.js` file that is not in that string does not exist as
far as the gate is concerned.** Measured on `main` @ `a4dbd99cd`:

```
listed in test:serial: 120     test_*.js on disk: 127
```

Seven files are on disk and in no lane, no run, no count:

| orphan | lane | what it guards |
|---|---|---|
| `test_seo_src_attribution.js` | browser (via `./audit-app.js`) | item **203**'s `src=` attribution on `?pool=` deep links — the rail that makes north-star arrivals attributable |
| `test_audit_768_lens.js` | browser (via `./audit-app.js`) | the 768px audit lens surfaces |
| `test_nav_rail_ia.js` | browser | spec 093 nav-rail IA, 10 rendered assertions incl. KO filter labels |
| `test_list_polish.js` | browser | spec 095 list-view polish, 6 computed-style assertions |
| `test_earnings_dedup.js` | browser | pool-detail earnings surface dedup (north-star page) |
| `test_llms_shared_source.js` | plain | `generate-llms.js` shared-source rails |
| `test_helpers_parser.js` | plain | helpers parser unit rails |

This is the **exact failure mode `playbooks/test-gate-observability.md` step 4 was written to
prevent** — "`node run-tests.js --list` must equal `package.json`'s `test:serial` chain … If you add
a test file, append it to `test:serial`". That step is a human-memory rail with nothing enforcing it,
and it has now been violated seven times. Item 204's LOG line records one instance
(`test_seo_src_attribution.js` "was never wired into `test:serial` at all — found by grep while
placing the new test, left alone rather than swept in as a drive-by"); measuring the whole population
rather than the one file it named is what turns that residual into this item.

There is **no test CI**: `.github/workflows/` contains only `sitemap-update.yml`, which runs
generators, never `npm test`. So the loop's own pre-merge run *is* the gate, and the gate has a
5.5% blind spot.

  `✓ 6/6 list-polish assertions passed` and then sets `process.exitCode = 1` at line 246-249 because its

  Its `IGNORABLE_ERROR_PATTERN` (test_list_polish.js:32) omits `icons\.llamao\.fi`, which **both** of its

  not a product defect, and wiring the file without fixing it would install a permanently-red step.

## Scope — build exactly this, nothing else

1. **Wire all seven orphans into `package.json`'s `test:serial`**, appended in the existing style
   (` && node <file>.js`). Preserve the existing 120 steps verbatim and in order — the chain is parsed,
   so a formatting slip is a runtime error, not a style nit. Place each new step next to its topical
   neighbours where one obviously exists (e.g. `test_seo_src_attribution.js` beside the other
   `test_seo_*` steps, `test_audit_768_lens.js` beside the other `test_audit_*` steps); otherwise append.

2. **Fix `test_list_polish.js` so a default invocation can exit 0**:
   - add `icons\.llamao\.fi` to `IGNORABLE_ERROR_PATTERN` (test_list_polish.js:32), matching
     `test_nav_rail_ia.js:31` verbatim in spirit — reuse the sibling's pattern, do not invent a new mechanism.
   - replace the hardcoded dead scratch path (`SCRATCH`, test_list_polish.js:26 — a *different* session's
     UUID directory that does not exist on any other machine) with an `os.tmpdir()`-derived path so
     `shot()` writes somewhere real. `shot()` already swallows its own errors, so this is a
     correctness/portability fix, not a behaviour change.
   - **Do not weaken any assertion.** The six computed-style assertions stay byte-identical. Only the
     console-error allowlist and the screenshot destination change.

3. **Add `test_test_registry.js` — the guard that closes the class permanently.** Plain lane, no
   dependencies beyond `fs`/`path`/`assert`. It must assert, against the real repo:
   - **(a) no orphans**: every `test_*.js` in the repo root appears in `test:serial`. Failure message
     names the missing files.
   - **(b) no ghosts**: every step in `test:serial` resolves to a file that exists on disk.
   - **(c) no duplicates**: no file appears twice in the chain.
   - **(d) parse integrity**: every step matches `node <file>.js` — reuse `run-tests.js`'s exported
     parser if it exports one; if it does not export, re-derive the chain with the same regex and say so
     in a comment (do **not** add an export to `run-tests.js` unless it is a one-line, zero-risk addition —
     prefer no product-file change).
   - **(e) it can go red**: a self-defeat case proving the check is not vacuous — construct an in-memory
     chain string missing a known file and assert the checker reports it. (`playbooks/test-gate-observability.md`
     step 5, and `derived-number-rails.md` Step 0b: a check never shown to fail is not evidence.)
   - It must itself be wired into `test:serial` (chicken-and-egg is fine and intended).
   - It must classify into the **plain** lane — i.e. it must not mention the browser-driver package name
     as a literal string, and must not `require('./run-tests.js')` by a literal path, or
     `run-tests.js`'s transitive scanner flips it to the browser lane. This trap is documented in
     `playbooks/test-gate-observability.md` ("A program that scans its own repository can misclassify
     itself" — use a computed path and a reconstructed marker string). **Verify the lane after writing it**
     with `node run-tests.js --list --lane=plain`.

4. **Playbook (compound step)**: UPDATE `playbooks/test-gate-observability.md` — never duplicate. Step 4
   currently *instructs* humans to keep the chain in sync; it now has an enforcing test, and the measured
   fact (7 of 127 files unwired, ~6 months of accumulation) belongs in the record. Keep it a checklist.
