# Spec 053: Minify JS/CSS in CI

## Evidence
reports/2026-07-12-pagespeed.md. Raw unminified assets shipped: app.js 119K, planner.js 196K, style.css 123K, translations.js 67K, PoolDetail.js 52K (~557K). PageSpeed "Minify JS/CSS" + transfer-size wins.

## Change
- CI step (sitemap-update.yml) minifies the shipped assets into committed `.min.js`/`.min.css` (terser + a CSS minifier, or esbuild --minify — no local build; CI commits the output, same pattern as sitemaps). Reference the minified files from home.html / plan.html.
- Source files stay the editable surface; minified files regenerate in CI.
- Sequence AFTER 052 (compile app first, then minify the compiled output) to avoid double-work.

## Acceptance criteria
- [ ] home.html/plan.html reference minified assets; raw sources still the edit surface
- [ ] Both router paths render (test_smoke.js); no behavior change
- [ ] Minified files produced by CI, not hand-edited
- [ ] Full test chain exits 0

## Risk tier
HIGH — touches home.html/plan.html asset references (render path). Verify both paths.
