## Change
Smallest version that adds the sort and nothing else:
- Add a `sortBy === 'sharpe'` branch to each of the three existing `filtered.sort(...)` blocks in `app.js` (token/chain/default modes). Sort **descending by `pool.kpis.apySharpe`**, applied **only within the existing sane group** — anomalous pools stay demoted below the sane group exactly as they are for `tvl`/`apy` today. Pools with `apySharpe == null` sort **after** pools with a numeric Sharpe, tie-broken by TVL descending (the existing default), so the option is a graceful no-op until data accrues ~07-22.
- Add the sort control (a new option in the existing sort UI — reuse the existing sort toggle/segmented control markup and neuro classes; ZERO new CSS, no new component). Label via `translations.js`, EN + natural KO together.
- Regenerate compiled/minified assets (`app.compiled.*` etc.) since `app.js` IS touched this time.

**Explicitly OUT of scope:** 117.3 (planner blend preference — planner.js). Any change to `APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly demotion/flagging, the degen ⅓ haircut, the `__APP_MODE` router, or `?token=`/`?chain=`/`?pool=` URL semantics. No new sort surfaces beyond this one option. No tooltip/annotation rewrite (117.1 already annotates Sharpe on pool detail).
