# 223 — PR explainer (HIGH tier)

**What shipped:** a `.vercelignore` file that stops www.defi.garden from
serving this repo's dev/test/tooling/internal-doc files — ~190 `test_*.js`
files, `audit-app.js`, every `generate-*.js` script, `product-loop-kit/`
(694 files, including the entire growth-proposal/backlog/spec history),
`.claude/agents/verifier.md`, `docs/`, `telegram-bot/`, `workers/`, `src/`,
and a handful of named root docs — all of which return 200 on prod today,
alongside a permanent test (`test_vercelignore.js`) that re-checks the
enumeration on every future change to either the ignore file or the
repo's file set.

Risk tier **HIGH**, builder's own assignment, matching the spec's guess:
this is deploy-config/infra governing what exists on prod, spent against a
metered Vercel deployment. **Mis-enumeration breaks prod harder than the
exposure ever would** — the whole design of this item is organized around
that asymmetry.

---

## 1. The goal, in one line

A file that exists in a public GitHub repo for development reasons — a test
script, an internal strategy doc, a bot's SQLite backup — has no reason to
also be an HTTP response at www.defi.garden. Today, every one of them is.
This stops that, without touching a single byte of what the site actually
needs to run.

## 2. The intuition — why this is a real problem, not just tidiness

Vercel's zero-config static deploy uploads the whole git tree and serves it
byte-for-byte unless told otherwise. This repo has never told it otherwise —
no `.vercelignore` exists before this change, and `vercel.json` has no file
inclusion/exclusion mechanism at all (it only carries rewrites, redirects,
and headers). So everything checked into git that isn't caught by Vercel's
own small built-in denylist (see Territory note 2 below) is a live URL.

The measured consequence, not a hypothetical: a URL-extracting crawler
scraped `` `/plan.html?lang=ko` `` — a JS **template literal**, backtick and
all — directly out of `test_min_asset_boot.js:262`'s served raw source, and
hit `/plan?lang=ko%60` (the trailing `%60` is the literal closing backtick)
twice in prod session-start events on 2026-08-03. No generated `href` in the
real app emits that string anywhere (grep: 0 hits across `tokens/`,
`chains/`, sitemaps, `llms*.txt`, the shipped app JS) — it can only have come
from reading the test file as if it were content. That's crawl-budget spent
on the SEO-moat domain, internal strategy docs sitting discoverable next to
`llms.txt` (an AI-discovery surface this product actively cultivates), and a
live source of phantom planner arrivals.

## 3. What changed, in reading order

**`.vercelignore`** (new, 76 lines) — a denylist, gitignore-style syntax,
grouped into five sections by comment: dev/test/tooling scripts, deploy/db
config, root-level internal docs, fixtures, and out-of-scope source
directories. Two hard rules, both load-bearing:

1. **Every pattern is anchored** (`/`-prefixed). A root-level exclude can
   never accidentally shadow a nested runtime file of the same name — e.g.
   `/CLAUDE.md` cannot match a hypothetical `tokens/CLAUDE.md`, and `/*.sh`
   cannot reach into a subdirectory.
2. **No `!` negations anywhere.** Vercel's negation handling is documented
   as unreliable; every pattern here is written narrow enough that no
   negation is ever needed to carve an exception back out.

**`test_vercelignore.js`** (new, ~495 lines) — the gate, in six parts:

- **(a)** A small gitignore-ish matcher (anchored `/x`, directory `x/`,
  globs `*`/`**`), unit-tested against 7 hand-written cases (including two
  that specifically probe for the naive-`startsWith` bug: `/docs/` must not
  match `docsish/x.md`, and a root glob must not match a nested file of the
  same shape) before it is trusted against anything real.
- **(b)** Enumerates the real deployable set via `git ls-files` (19,956
  tracked files) and classifies every one KEPT/EXCLUDED using that matcher
  against the real `.vercelignore`.
- **(c)** A MUST-KEEP allowlist of ~70 real paths spanning every runtime
  class in the spec's facts — app bundles and every `.min`/`.compiled` twin,
  all CSS, `data/`, `tokens/`/`chains/`/`ko/` including their item-212
  `.md` twins, `pools/` (json + md), `.well-known/**` including its
  non-JSON files, `stories/`, `og/`, `fonts/`, `tools/`, `spotlights/` —
  asserted present in KEPT, one assertion per file, failing loudly by name.
- **(d)** A MUST-EXCLUDE list covering every class the spec names, asserted
  present in EXCLUDED the same way.
- **(e)** **Link integrity** — scans every KEPT served text asset that could
  reference another file (root `*.html`, `stories/*.html`, all 14 shipped
  app JS files, `llms.txt`/`llms-full.txt`, all 114 `sitemap*.xml` files,
  every `.well-known/**/*.json` file, `openapi.json`, `tools/*.json`) for
  same-origin references (`src=`, `href=`/`href:`, `fetch(...)`, absolute
  `https://www.defi.garden/...` URLs), resolves each one against the real
  tree (`cleanUrls`-aware: `/tokens/usdc` resolves via `tokens/usdc.html`),
  and asserts none of them land on an EXCLUDED file. **This is the check
  that caught a real bug — see §4.**
- **(f)** A self-defeat rail: an in-memory mutated pattern set (never
  touching the real file) proves the classifier itself can flag `app.js`
  and a `pools/` sample as excluded, then re-confirms the real, unmutated
  file still keeps them. A check that has never been observed to fail is
  not evidence it works.

**`package.json`** — one line: `test_vercelignore.js` appended to the end of
`test:serial`'s chain (same placement item 222 used for its own new test).
Registered per this repo's `test_test_registry.js` invariant — verified
green (5/5) after the edit.

**`vercel.json` — zero diff.** Confirmed with `git diff --stat` after
staging every changed file; not touched, not needed (a `.vercelignore` is a
separate, additive mechanism).

## 4. The deviation that matters: the spec's own suggested exclude list was wrong about `auth.md`

The spec listed `auth.md` alongside `CLAUDE.md`/`README.md`/`SITEMAP.md` as
a root-level internal doc to exclude. **`test_vercelignore.js`'s own
link-integrity check caught this on the very first run:**

```
✗ (e) LINK INTEGRITY: no KEPT served asset references an EXCLUDED path
  .well-known/oauth-authorization-server.json -> "/auth.md" -> auth.md (EXCLUDED)
  .well-known/openid-configuration.json -> "/auth.md" -> auth.md (EXCLUDED)
```

`auth.md` looks like an internal doc — root-level, markdown, written for
readers — but it is actually a **live agent-discovery asset**: both
`.well-known/oauth-authorization-server.json` and
`.well-known/openid-configuration.json` point their `agent_auth.skill` field
at `https://www.defi.garden/auth.md`, and `auth.md` in turn instructs
arriving agents to read those same two `.well-known` endpoints. It's part of
the site's agent-auth discovery loop, one hop removed from the
`.well-known/agent-skills/index.json` → `SKILL.md` pattern CLAUDE.md already
flags as a trap. `auth.md` was removed from `.vercelignore` and added to the
test's MUST-KEEP allowlist; the ignore file itself carries a comment
recording why, so nobody re-adds it later without re-reading this.

## 5. What was deliberately NOT done

- **No post-deploy curl matrix.** `.vercelignore` only takes effect once
  Vercel builds from a merged commit; this branch is unmerged and unpushed
  per this run's instructions. The operator runs the post-deploy matrix
  (both directions — every runtime class 200, every excluded class 404)
  after merge; the pre-change baseline it diffs against is recorded in
  `specs/223-notes.md`.
- **The full `~140`-file `test:serial` chain was not run** (standing
  5-minute foreground timebox) — only the three files the spec's own step 4
  names: `test_vercelignore.js`, `test_test_registry.js`, `test_run_tests.js`.
  Nothing else in the chain touches deploy config, a generator, or a
  render path.
- **`vercel.json` untouched**, as the spec requires — this item is
  additive-only.
- **No file deleted from the repo.** `.vercelignore` controls what Vercel
  uploads, not what git tracks; every excluded file is still in the repo,
  still on GitHub, still readable by a human or CI.

## 6. How to check it by eye (after merge)

`curl -I https://www.defi.garden/CLAUDE.md` should flip from 200 to 404;
`curl -I https://www.defi.garden/app.js`, `.../tokens/usdc`,
`.../auth.md`, and `.../data/pools-snapshot.json` should all stay 200. Bare
`/` should still render the planner and `/?token=USDC` should still render
the analytics grid with pool cards — this item touches zero render-path
files, but a deploy-config change is exactly the kind of thing worth one
human eyeball on the live site regardless.

## 7. Measurement

None isolable, per the spec — this is hygiene under the pre-traffic
mandate, not an experiment. Informational watch: `lang=ko%60`-shaped fuzz
arrivals in the URL-provenance check should stop appearing for freshly
crawled URLs, since the served test file that minted that exact string is
no longer served. Decision rule per the spec: keep unconditionally once the
operator's post-deploy curl matrix passes both ways.
