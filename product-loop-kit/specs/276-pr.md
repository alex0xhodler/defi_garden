# 276 — PR explainer (LOW)

**What changed**: `audit-app.js`'s occlusion lens (`occlusionPassEval`) used to exempt a victim
from EVERY overlay on the page if it was fixed/sticky itself, or contained by ANY overlay. That's
why it stayed green while item 273's real P0 shipped invisible: `.app-search-input` lives inside
`.app-header-sticky` (an overlay), so the blanket rule exempted it even though a completely
different overlay (`.language-toggle`, `position:fixed`) was the one actually covering it.

**The fix**: move the containment check inside the per-overlay comparison loop, so a victim is
only exempt from the ONE overlay that actually contains it — `if (ov.el === vel || ov.el.contains(vel)) continue;`
— instead of being exempted from all overlays at once. Also drops the separate "victim is itself
fixed/sticky -> always skip" rule, since one overlay occluding a different overlay's content is
exactly the class this item closes.

**How it was verified**: reproduced the 273 shape as a Playwright fixture (nested victim + sibling
overlay) — fails on `main`, passes with the fix. A negative-control fixture (victim inside its OWN
header, no other overlay) proves the legitimate self-containment exemption is still intact — this
was the row's own flagged false-positive risk. Ran the fix against the real production site
(`test_audit_app.js`'s full `runAudit()`): zero new occlusion findings anywhere, including
pool-detail and the (now fully clear) grid quarantine.

**Deviations**: none from spec. Two unrelated findings surfaced during verification (a stale
test-2 anchor bug, the grid quarantine reading clear) were filed as backlog 278 instead of fixed
here, per smallest-change discipline.
