# Spec 226: Google head-curation — sitemaps shrink to a demand-plausible head; soft-404 class dies; estate stays live for agents

## Evidence
GSC (human screenshots, 2026-08-04): 3,274 indexed vs 38,124 known-not-indexed; `Crawled - currently
not indexed` **18,555** (Google fetched and declined — the scaled-content verdict); Soft 404 **3,246**;
sitemap index 109 children processed successfully. Mixpanel 60d (`3b2555fb`): **zero google.com
referrals ever**; bing-family ~14 (IndexNow works); perplexity.ai 2.
Human authorization (interview Q3b, standing decision 2026-08-04): de-LIST the tail from sitemaps,
delete nothing, keep the full estate live for agents + IndexNow engines.

## Hypothesis
We believe presenting Google a small, demand-plausible head (~300-500 URLs) while the tail leaves the
sitemaps will (a) stop the scaled-content signal from suppressing the head and (b) concentrate crawl
on pages that can actually earn impressions — because Google is already declining 85%+ of the estate
and indexes-but-never-ranks the rest, and a curated sitemap is the strongest de-prioritization signal
we control without deleting agent surface.
Confidence: guess for (a) — Google may still ignore the head (authority-gated); supported for (b) and
for soft-404 elimination (3,246 known-harmful pages).
- Instance of: audience-contract divergence — one artifact set serving two consumers (Google vs agents)
  with opposite size preferences; population = all ~4,400 generated leaf pages × their sitemap entries.
- Class closed by this item: yes for the sitemap contract; head-page DEPTH (making the 300 good pages
  genuinely deep) is follow-up work, left open deliberately — ticket count stated at ship.

## Change
1. Generators gain ONE head-selection predicate (single source of truth, exported): a token/chain page
   is HEAD iff it clears demand-plausibility — top-N tokens by railed TVL + recognizable majors,
   chains with ≥K railed pools, all hubs/categories (target total 300-500; N/K derived from live data
   at generation, not hardcoded page counts).
2. `sitemap-*.xml` + IndexNow-to-Google surface only HEAD pages. **Bing/IndexNow keeps the full estate**
   (separate submission list — IndexNow engines respond, and they feed answer-engine indexes).
3. Soft-404 class: a page whose railed pool set is empty at generation is NOT emitted (and existing
   empty ones stop regenerating — they fall out on the daily regen; no manual deletion). llms.txt/md
   twins keep the full live estate.
4. `robots.txt`/noindex: UNCHANGED this item (sitemaps-only lever first; measure before escalating).
OUT of scope: deleting any live page (NEVER list); head-page depth content (follow-ups); canonical.js.

## Acceptance criteria
- [ ] Sitemap URL count (entity count — `<loc>` extraction per playbook class 13, never line-grep) drops
      from ~2,2xx to the 300-500 head; every head URL renders non-empty railed content live.
- [ ] Full estate still served: sampled tail pages → 200 + present in llms surface; IndexNow full-estate
      submission list intact for Bing-family.
- [ ] Zero generated pages whose main table is empty (the soft-404 predicate, run over the whole output).
- [ ] Head-selection predicate exported + tested as the single source (mirror rule — sitemap generator
      and any other consumer read THE predicate, no second copy).
- [ ] Regen delta separated from churn per `seo-surface-regen-delta.md`; the delta report proves ONLY
      tail pages left the sitemaps.
- [ ] Non-vacuity: force the predicate to accept-all in scratch → sitemap count test goes red; restore →
      green. Population: predicate tested against the live generation set, not fixtures.

## Measurement
Metric: GSC index-coverage classes (human-read); informational: bing-family referrals, head-page
impressions when the human next shares GSC. Gate: human GSC readout (their cadence — no calendar
window). Decision rule: soft-404 elimination keeps unconditionally; head-curation reverts only on human
call (re-adding sitemap URLs is cheap and non-destructive).
