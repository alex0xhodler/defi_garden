# 126 — HIGH-tier explainer + quiz: money formatting shows cents ($0.10 not $0.1)

## Goal
On the pool-detail page (north-star surface) daily earnings rendered "**$0.1**" — a price with a single
decimal reads as unfinished/broken, a small trust leak right next to the CTA. Show proper cents everywhere.

## Intuition
`formatUsd(n, maxFrac=2)` used only `maximumFractionDigits`, which *drops* trailing zeros: `0.0986 → $0.1`,
`3.0 → $3`. The fix pins **exactly** `maxFrac` decimals (`minimumFractionDigits === maximumFractionDigits`),
so cents keep the trailing zero while `maxFrac=0` callers (projections) still render whole dollars.

## What changed (reading order)
1. **app.js `formatUsd`** — `{ minimumFractionDigits: maxFrac, maximumFractionDigits: maxFrac }`.
   `$0.0986 → $0.10`, `$3.0 → $3.00`, `formatUsd(1193, 0) → $1,193`. This one function feeds the
   pool-detail earnings/calculator (passed to PoolDetail at the mount) and the analytics pool-card daily
   figure — so the fix is consistent app-wide.
2. **translations.js EN `quickEstimate`** — the subhead daily number was formatted inline with the same
   drop-the-zero bug; pinned to 2 decimals → "$0.10/day".
3. **Regenerated** app.compiled.js/.min.js + translations.min.js (freshness gates pass).

## Why EN-only (EN+KO-together rule not violated)
KO's `quickEstimate` uses `formatKoreanCurrency` (whole won — `Math.round`, 억/만 units), where a
fractional-cent drop is structurally impossible. This is a numeric-format fix, not a copy change, so the
EN-together-with-KO copy rule doesn't apply. (KO does show "0원" for a sub-won daily estimate — a separate
localization edge, noted below, not fixed here.)

## No large-number regression
Every `formatUsd` caller passes a small earnings/gain amount; TVL renders through `formatCurrency`
(compact "$360.8M"), untouched. So nothing shows an ugly "$X,XXX.00". The 1-week/1-month calculator
figures now always show 2 decimals (e.g. "$2,740.00") — intended for money.

## Deviations / follow-up candidates (non-blocking, out of scope)
- `PoolDetail.js:25` `_formatUsd` fallback still carries the original single-arg bug, but it only fires
  when the `formatUsd` prop is undefined — app.js always passes the fixed fn, so it never executes. Left
  as-is to keep scope tight; candidate cleanup.
- KO daily estimate renders "0원" (whole-won rounding of a sub-won amount) — a real KO-localization gap
  (a $0.10/day earning reads as zero), but fixing it needs a KO product call (won-with-decimals is
  unconventional; better to show weekly/monthly in KO). Candidate follow-up.

## Trust rails / scope
No trust-rail change; `formatCurrency` (TVL), router, PoolDetail.js, generated pages untouched. Render-path
change → advisory human visual spot-check.

## 5-question quiz (HIGH gate)

1. **Why did `formatUsd(0.0986)` return "$0.1" instead of "$0.10"?**
   It set only `maximumFractionDigits: 2`, which drops trailing zeros, so 0.0986 rounded to "0.1".

2. **How does the fix keep `maxFrac=0` projections rendering "$1,193" (not "$1,193.00")?**
   It pins `min === max === maxFrac`; for projection callers maxFrac is 0, so 0 decimals.

3. **Why is fixing the single `formatUsd` enough for both the pool-detail earnings and the analytics pool cards?**
   Both render dollars through the same `formatUsd` — pool detail receives it as a prop from the mount;
   the analytics card calls it directly. One source of truth.

4. **Why is changing only the EN quickEstimate (not KO) correct here?**
   KO formats via `formatKoreanCurrency` (whole won, no cents), so the trailing-zero bug can't occur; this
   is a number-format fix, not translated copy.

5. **Could the pinned decimals make a large TVL figure render "$360,800,000.00"?**
   No — TVL uses `formatCurrency` (compact), not `formatUsd`; every `formatUsd` caller is a small
   earnings/gain amount.
