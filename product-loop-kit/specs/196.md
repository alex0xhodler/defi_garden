# Spec 196: the static-page rotation has no memory — 183's fix, never applied to the 2,197-page SEO estate

## Evidence

**No READY item existed on the board at pickup** (every row 001–195 is SHIPPED / DONE / BLOCKED / PARKED —
re-derived by parsing the Status column of every row in `BACKLOG.md`, and `git ls-remote origin
'refs/heads/claude/loop-196'` is empty). This item is therefore a **promotion from documented evidence
already in the repo**, per `prompts/build.md`'s no-READY-items branch.

**The documented, unbuilt follow-up.** `specs/154-notes.md` recorded its own limitation verbatim and named
the remedy as not built: *"4 sampled token pages/day out of 2,079 ⇒ ~1.3%/day chance of hitting a specific
known-junk page — structural blindness removed, sampling rate still weak; follow-up (**prefer
never-audited slugs** / cheap grep prescan promoting suspicious pages into the rendered sample)
documented, not built."* Item **157** built the second half (prescan promotion). Item **183 leg (b)** built
the first half — never-audited-first rotation with persisted `seen` state — **for pool-detail only**.
`BACKLOG.md`'s 183 row and `signals/2026-07-31.md`'s 191 finding both describe it as a pool-detail fix.
**Nobody ever applied it to the static leg**, which is the older and larger of the two blind spots.

**Measured this run, on this checkout** (`buildStaticSurfaces({staticSeed, prescan:false})` driven directly,
no fs writes, real `tokens/` + `chains/` directories):

| | population | picks/tick | selection |
|---|---|---|---|
| `tokens/*.html` | **2,109** (2,108 after the `tokens/usdc.html` anchor) | 4 | `sampleBySeed(tokenLeaves, 4, "<date>:tokens")` — `audit-app.js:1988` |
| `chains/*.html` | **88** (87 after the anchor fallback) | 2 | `sampleBySeed(chainLeaves, 2, "<date>:chains")` — `audit-app.js:1989` |

`sampleBySeed` is a pure date-seeded pick over the **whole** leaf list. It reads no state and writes none,
so **every tick samples with replacement against all previous ticks**. Simulated forward from 2026-08-01,
one tick per day, prescan off (measured, not estimated):

| horizon | token pages ever rendered | token re-renders | chain pages ever rendered | chain re-renders |
|---|---|---|---|---|
| 30 days | 117 | 3 | 45 | **15 of 60 (25%)** |
| 90 days | 340 | 20 | 74 | **106 of 180 (59%)** |
| 180 days | 619 | 101 | 84 of 87 | **276 of 360 (77%)** |

**Chains is the acute case**: after half a year of daily audits, **77% of the chain-page render budget is
spent re-rendering a page already audited**, and 3 of 87 chain pages have still never been rendered once.
Coupon-collector expectation for a full pass — the number 191 used to argue the pool case — is **~4,338
days for tokens and ~220 days for chains**, against **527 / 44 days** for the same budget with memory:
an **8.2× / 5.0× throughput gain for zero extra renders**.

**This is 191's thesis one level over, and the surface it covers is where the only real traffic lands.**
`signals/2026-07-31.md`'s prod `page_view` log for the week is 11 events, and **8 of the 11 are static SEO
leaves** (`/tokens/buidl`, `/tokens/usdc`, `/tokens/slisbnb`, `/tokens/eth`, `/chains/linea`,
`/chains/avalanche`, …). The static prescan already covers all 2,179 pages every tick — but only for the
five **textual/numeric** signals (`junk-slug`, `zero-yield-claim`, `link-target-integrity`,
`broken-number-literal`, `pool-link-liveness`). The classes that need a **render** — console errors,
i18n leaks, 360px clipping, dead CTAs, the classes that found 136/137/182 — reach 6 pages a tick, drawn
with replacement.

Today's own audit run on this checkout, for the record: `status OK`, 57 surfaces, **1 finding, 0
blocking** (the known auto-downgraded `201e5f6e`). There is no live defect competing for this slot.

## Hypothesis

We believe **giving the static-page rotation the same persisted never-audited-first memory item 183 gave
pool-detail** will **turn static SEO coverage from a coupon-collector lottery into a deterministic full
pass — 8.2× faster for tokens, 5.0× for chains, at exactly the same render budget** because the numbers
above are arithmetic, not a behavioural bet: the same 6 renders per tick, spent on pages that have not
been rendered yet, cover the estate 5–8× sooner. Confidence: **validated-pattern** — 183 is the shipped
precedent for this exact mechanism on this exact file, and its state file has been advancing correctly
for three days (`signals/audit-rotation.json`, `seenCount` 48 this run).

## Change

Reuse 183's machinery; invent nothing.

1. **Reuse `computeRotation()` verbatim** (already exported, already pure, already unit-tested by
   `test_audit_pool_prescan.js`) for the static leg. Call it **twice** — once for `tokens`, once for
   `chains` — so the deliberate 2:1 token:chain budget split from spec 154 Design A is preserved exactly.
   A single combined rotation is explicitly **rejected**: with 2,108 token leaves against 87 chain leaves,
   a combined unseen-first pick starves chains ~96:4 and makes the acute case worse.
2. **New state file** `product-loop-kit/signals/audit-static-rotation.json`, shape
   `{ schemaVersion: 1, tokens: { cycle, seen: [...rels] }, chains: { cycle, seen: [...rels] } }`.
   `seen` entries are **repo-relative leaf paths exactly as `listLeafPages()` returns them**
   (`tokens/gtusdccore.html`) — the same string that is the candidate identity, so there is no
   reconstruct-the-key step to get wrong.
3. **Factor, do not duplicate, the state normalization.** `readRotationState()` (`audit-app.js:2285`) and
   the new static reader share one helper that validates/defaults a `{cycle, seen}` object. Both readers
   keep their degrade-to-empty contract: a missing, corrupt, or wrong-shaped file yields a fresh
   cycle-0/empty state and **never throws**.
4. **Record everything audited this tick into `seen`** — the anchor leaf, every prescan-promoted leaf, and
   every rotation pick — mirroring 183's `thisRunPoolIds` rule. A page rendered for *any* reason has been
   audited, so it must not be re-picked by rotation until the cycle wraps.
5. **Seen cap sized above the population.** 183 uses `ROTATION_SEEN_CAP = 2000` against ~737 pools. The
   token estate is **2,109 pages — larger than that cap**, so reusing it verbatim would drop-oldest and
   silently re-pick evicted pages before a cycle ever completes, defeating the entire item. Introduce
   `STATIC_ROTATION_SEEN_CAP = 6000` (≥ 2× today's 2,197 leaves, headroom for estate growth) and state the
   reason in a comment. **A cap below the candidate population is the specific trap this item must not
   fall into.**
6. **Persist under the same gate.** Write the file only when `opts.persistRotationState` is set (CLI entry
   point only — `require.main === module`), and only when the serialized bytes differ from disk. Every
   library call — every existing `test_audit_*.js` — must leave the committed file untouched.
7. **Report the position.** Add `staticRotation: { tokens: {...}, chains: {...} }` to the findings JSON
   (each `{ cycle, seenCount, candidateCount, picked, wrapped, sampleSize }`, mirroring `poolRotation`'s
   shape) and one CLI summary line mirroring the existing `[audit] pool rotation:` line, so the heartbeat
   can read coverage position without re-deriving it.
8. **Env override for tests**, mirroring `AUDIT_ROTATION_STATE`: `AUDIT_STATIC_ROTATION_STATE` +
   `opts.staticRotationState` / `opts.staticRotationStatePath`, so tests drive the rotation as a pure
   function with no fs read at all.

**Explicitly OUT of scope**: the render budget (`DEFAULT_STATIC_SAMPLE` stays 6 — this item buys
throughput at constant cost, and raising the budget is a separate, separately-measurable decision, exactly
as 191/192 were split); the prescan and its promotion (157, untouched — promoted pages still replace
uniform picks and still bypass rotation); the anchor page (still `tokens/usdc.html`, still named
`static-page`, still first); the `AUDIT_STATIC_PAGES` override path (used verbatim, rotation off, exactly
as today — same contract as `AUDIT_POOL_IDS`); every product file. **No file outside `audit-app.js`, its
tests, `package.json`'s test chain, and this item's own bookkeeping may change.**

## Acceptance criteria

- [ ] 1. **Never-audited-first, proved on the real estate.** With a state file whose `tokens.seen` contains
      a specific real leaf, a run at any seed does not re-pick that leaf while unseen leaves remain. Same
      for `chains`.
- [ ] 2. **The 2:1 split survives.** A default run still yields 4 token surfaces + 2 chain surfaces
      (+ the anchor), and the anchor is still named `static-page` and still first.
- [ ] 3. **Determinism preserved.** Two runs with the same seed AND the same prior state pick identically;
      different seeds over the same unseen pool pick differently (the pre-existing
      `test_seo_surface_audit.js` determinism assertions must stay green, unmodified).
- [ ] 4. **Wrap works.** When every candidate is seen, `wrapped` is true, `cycle` increments, the new
      `seen` resets to just this run's picks, and the next cycle starts fresh — same contract as 183.
- [ ] 5. **Cap above population.** `STATIC_ROTATION_SEEN_CAP` ≥ the current leaf count (2,197), asserted
      against a count read from disk at test time, not a hardcoded literal — so the assertion breaks if
      the estate ever grows past the cap.
- [ ] 6. **Anchor + promoted leaves land in `seen`.** A run whose prescan promotes a page records that
      page in `seen` even though rotation did not pick it; the anchor leaf is recorded likewise.
- [ ] 7. **Library calls never write the committed state file.** A `runAudit()` call without
      `persistRotationState` leaves `product-loop-kit/signals/audit-static-rotation.json` byte-identical
      (md5 before/after).
- [ ] 8. **Degrades, never throws.** Missing file, corrupt JSON, `{}`, `{tokens: 5}`, and
      `{tokens:{seen:"nope"}}` each yield a fresh cycle-0 state and a normal pick.
- [ ] 9. **Override path unchanged.** With `AUDIT_STATIC_PAGES` set, surfaces are used verbatim, rotation
      is off, and no state is read or written — byte-identical behaviour to `origin/main`.
- [ ] 10. **Measured throughput gain, re-derived by the verifier.** A 180-day simulation on the built code
      shows ≥ 1,080 distinct token pages (6× today's 619) and full chain coverage with zero chain
      re-renders before the wrap — against `origin/main`'s measured 619 / 84-of-87 / 276 re-renders.
- [ ] 11. **A real end-to-end CLI run** of `node audit-app.js` completes with `status: "OK"`, writes the
      new state file with non-empty `tokens.seen` + `chains.seen`, and its `staticRotation` block appears
      in the findings JSON. (This is the acceptance-is-a-real-run rule; this item has no UI surface, so
      the real run is the rendered proof.)
- [ ] 12. **Tests**: new `test_audit_static_rotation.js`, registered in `package.json`'s `test:serial`
      chain next to its siblings; `test_seo_surface_audit.js`, `test_audit_prescan.js`,
      `test_audit_pool_prescan.js`, `test_audit_app.js`, `test_run_tests.js` all still green, unmodified.
- [ ] 13. **Non-vacuity**: reverting `audit-app.js` to `origin/main` with the new test in place must turn
      criterion 1's assertion RED. Stated in notes with the exact observed output.

## Measurement

Metric: **distinct `static-page:<slug>` surfaces in `surfacesCovered` per unit of calendar time**, read
from the `staticRotation.tokens.seenCount` / `.chains.seenCount` fields the heartbeat already logs.
Window: 14 days. Decision rule: **keep if `seenCount` advances by ~6/tick with zero repeats before a wrap**
(the deterministic-pass signature); revert-candidate if repeats appear while unseen candidates remain.
No isolable Mixpanel funnel metric — this is loop tooling under the 2026-07-23 pre-traffic quality
mandate, same disclosure pattern as 154/157/183/191/192.

## Territory notes

- `sampleBySeed(list, n, seed)` is the shared deterministic picker; `computeRotation(candidates,
  sampleSize, seed, state)` (`audit-app.js:2249`) already layers unseen-first + wrap + fill-from-seen on
  top of it and is exported. Seeds are namespaced (`"<date>:tokens"`, `"<date>:chains"`,
  `"<date>:prescan"`, `"<date>:pools"`) so no two legs ever pick in lockstep — keep that convention.
- `buildStaticSurfaces()` (`audit-app.js:1852`) returns `{surfaces, prescan, prescanFindings,
  prescanSuspects}`; the return shape must be **extended**, not reshaped — `runAudit()` and four tests
  destructure it.
- The pool leg persists in `runAudit()` at `audit-app.js:3580` behind `opts.persistRotationState`; put the
  static write beside it, sharing the same gate and the same write-only-if-changed rule.
- 192's `baseSeen` reconciliation exists because the pool leg can **skip** rotation picks under a time
  budget, so an un-rendered pick must not be recorded as seen. The static leg has **no such time-budget
  skip** (`AUDIT_TIME_BUDGET_MS` guards `rotationPick` pool surfaces only). Do not port `baseSeen`
  reconciliation — porting machinery whose precondition does not exist is exactly the over-application
  this item is meant to avoid. If that ever changes, the reconciliation becomes required; note it in a
  comment.
