# 180 — the AI-discovery surface must not publish links to an empty grid

**Tier: HIGH** (verifier-assigned, agreeing with the spec's guess: regenerates the committed
`llms.txt`/`llms-full.txt` AI-discovery surface — NORTH_STAR:64's explicit HIGH list — and the diff is
435 + 336 + 39 lines against LOW's 150-line cap). **Verifier: PASS, 10/10 criteria, NOT on the NEVER list.**

## Goal in one sentence

63 links published on `llms.txt`/`llms-full.txt` — the surface LLMs read to learn what this product is —
took the reader to an empty grid; after this, zero do, and the gate re-decides every link on every daily bake
so the class cannot come back by data drift.

## The intuition (this is the whole item)

`llms-full.txt` has a section called `## Chain Pages`. It listed 102 links of the form `/?chain=Cardano`.
62 of them returned **nothing**: the app filters at `DEFAULT_MIN_TVL` = $10M (`app.js:801`, `:927`) and those
chains have no pool that large. Meanwhile the *real* chain pages — `/chains/cardano`, generated at the $100K
page floor, with a real pool table on them — were **already in the same file**, 88 of them, filed under
`## Other Pages`: *"Additional site functionality and tools."*

So the section named after chain pages didn't link to the chain pages, and the links it did carry were empty.

## The hard part, and the trap that makes it hard

Item 173 fixed 1,749 dead CTAs on the HTML estate the day before, by appending `&minTvl=100000` — the
generator's own floor — to each link. The obvious move is to do that again here. **It would have been a
no-op that looked like a fix.**

`generate-llms.js:28` `MIN_TVL_USD = 10000000` is *already identical to the app's default*. These links are
dead at the generator's own floor. Appending it changes nothing; reaching *below* it publishes a floor the
same file contradicts three sections up in prose (*"TVL ≥ $10M, APY ≤ 1000%"*) — which is item **174**'s
defect, freshly fixed, re-introduced by hand.

That is why spec 175 explicitly instructed: *"check whether the section is mis-targeted rather than merely
under-floored before touching the floor."* Measuring that turned a floor argument into an arithmetic
question with one answer:

| dead `?chain=` links | static `/chains/<slug>` page exists | destination |
|---|---|---|
| **48** | yes | the real page — content at the $100K floor |
| **14** | no | none exists |

The 14 (`Abstract Alephium Boba Carbon Chia Kasplex Metis Moonriver Obyte Rollux Shape Taiko Telos Unit0`)
have **zero pools with a non-zero APY even at the $100K page floor** — largest TVL on any of them is $198K.
That is precisely *why* `generate-chain-pages.js:78`'s `MIN_QUALIFYING_POOLS` gate never minted them a page.
There is no honest destination, so the link is omitted and counted.

## What changed, in reading order

`generate-llms.js` (the only product file), new block between `buildFull()` and `main()`:

1. **`gridLinkPoolCount(url, pools, opts)` — R1, exported.** Simulates the app grid for one home-path link:
   `minTvl` explicit-param-wins else `MIN_TVL_USD`; qualification `(tvlUsd||0) >= floor && > 0`; `token` =
   case-insensitive substring on `symbol` (`app.js:835`); `chain` exact; `protocols` exact `project`;
   `poolTypes` via `getPoolType` lazily required from `generate-sitemap.js` in a `try/catch` (the one
   classifier — if unavailable, the constraint is dropped and the drop is **counted**, never silently
   ignored); `minApy`. Applies only to links carrying one of
   `token chain poolTypes protocols minTvl minApy`. **`?pool=` is never simulated** — spec 175's
   4,233-false-positive trap.
2. **`applyChainRetarget()` — R2.** A dead `?chain=<C>` link in `## Chain Pages` becomes
   `${baseUrl}/chains/<slug>` iff that URL is in the parsed **sitemap** URL set (not the filesystem — output
   dirs are configurable). Slug via `tokenSlug` reused from `generate-token-pages.js`, the same import
   `generate-chain-pages.js:41` uses. Retargeted URLs are then skipped in `## Other Pages`, so every URL
   appears exactly once.
3. **`repairMinApyLink()` — R3.** A dead link carrying `minApy` walks the rungs `[10, 5, 3, 1]` and takes the
   highest that resolves; else drops `minApy`; else is omitted. `llms.txt:71`'s *"High APY staking"* went
   `minApy=10` → **`minApy=5`**.
4. **`applyLinkIntegrityGate()`** — builds the ungated baseline first (it is both the byte-identical fallback
   and the tripwire's denominator), then the two rails, then R2 + R3, logging per-class counts.
5. `test_llms_link_integrity.js` +26 cases (**zero deleted lines**); `test_audit_text_surfaces.js`'s pinned
   known-defect assertion re-measured into a true negative per its own failure message; `llms.txt` +
   `llms-full.txt` regenerated via `npm run generate:llms`.

### The one detail that matters more than the fix

`fetchYieldsSafe()` fails **SAFE** to `{ yields: [] }` on error or timeout — an empty population is a
*success* path in this repo. With an empty population every grid link resolves to zero, so a naive gate would
respond to a 10-second DefiLlama timeout by stripping **every** link off the AI-discovery surface. Hence rail
one: empty population ⇒ gate fully disabled, output byte-identical to pre-180, loud `stderr`, exit 0 (a
DefiLlama outage must not fail CI). The verifier proved this end-to-end by pointing the generator at
`127.0.0.1:9`: both files came out identical to `origin/main`'s output under the same failure, all 102
`?chain=` links and `minApy=10` intact.

## Proof it is not vacuous

A gate reporting zero dead links on a corpus with no dead links proves nothing (LEARNINGS 2026-07-27). Three
independent lines of evidence:

| who | method | result |
|---|---|---|
| builder | own script, live fetch, pre vs post | 62 → 0 (llms-full), repaired minApy link |
| operator | own script, fresh 16,021-pool fetch | `llms.txt 38 checked / 0 dead`, `llms-full 435 / 0 dead`; all 14 omitted chains absent; zero duplicate URLs (exact-line) |
| verifier | **two mutations of its own kind** — (A) short-circuit `gridLinkPoolCount` to `{count:1}`, (B) early-return inside `applyLinkIntegrityGate` — then regenerate | `test_audit_text_surfaces.js` **RED**, quoting `"62 … grid links resolve to ZERO pools … e.g. ?chain=Abstract"` and `"1 … ?poolTypes=Staking&minApy=10"`; restored `md5sum -c` OK on all five files |

The verifier also proved the split independently (102 → 88 = 48 `/chains/` + 40 `?chain=`, `comm -12` giving
40 common and 0 only-new), and closed the URL-set arithmetic: **4,927 − 64 + 2 = 4,865**, where the 64 removed
are the 62 chain links plus 2 `?pool=` rows from ordinary top-15 leaderboard churn.

And the rung choice was verified against **both** populations, because two different simulators judge these
links — the generator uses the live feed's `apy`, while `audit-app.js:925` re-checks the committed file
against `data/pools-snapshot.json` via `apyBase+apyReward`:

```
minApy=10  live=1  snapshot=0   <- rejected (this disagreement is why the dual check exists)
minApy=5   live=3  snapshot=3   <- chosen
minApy=3   live=5  snapshot=5
minApy=1   live=13 snapshot=13
```

## Four things the verifier caught that we are NOT hiding

1. **The 40% structural tripwire cannot fire in production.** Its numerator is structurally capped at 103
   (102 chains + 1 minApy link) while its denominator is the ~480-509 grid links on the text surface, so the
   worst case the verifier could force — a 1-pool fixture killing every chain link — reached only **21.5%**
   and the gate applied normally. The threshold and the denominator shape both come from the **spec**, so the
   builder implemented what was asked; but the rail as specified is inert, and *"a simulation bug must fail
   loudly"* is not true of the production corpus. The blast radius is bounded and visible (14 omissions,
   each `log()`ged by name), and the *empty-population* rail — the one with real consequences — is proven
   working. **Recorded as a follow-up candidate for the heartbeat, not silently fixed here:** the right shape
   is a class-relative rail (e.g. "the entire chain class went dead"), which is a design change, not a
   threshold tweak, and it needs its own spec.
2. **The new committed-artifact test legs are self-referential** — they call the shipped
   `gridLinkPoolCount`, so they are blind to a defect *inside* R1 (Mutation A left them green while the
   artifacts carried all 63 dead links). The independent guard is `test_audit_text_surfaces.js`'s level-3 leg,
   which uses `audit-app.js`'s own simulator and *did* go red. The notes' claim that the artifact leg "makes
   this permanent" is overstated; the audit leg is what makes it permanent.
3. **R1's `protocols` is whole-string equality; `audit-app.js:934` uses comma-split membership.** Harmless
   today — grep confirms no multi-protocol link exists on either surface — but it is a live divergence
   between the two simulators whose agreement the dual-population check depends on. Documented, not patched:
   a post-PASS code change would need re-verification, and the spec authorised "exact `project`".
4. **The spec's evidence table labels the llms.txt "1" as live-measured.** It was, at the moment it was
   measured (~00:05Z, zero Staking pools ≥$10M above 10% APY); by the build run, `ether.fi-liquid LIQUIDUSD`
   sat at 10.18% and the live count was 1 → 0 dead, while the snapshot population still read 1. The "1 + 62"
   reproduces exactly against the snapshot — the population the checker actually uses. Annotated in
   `specs/180.md` rather than quietly restated.

## Scope and safety

`MIN_TVL_USD` and `APY_SANITY_LIMIT` byte-identical to `origin/main`; no second floor literal anywhere
(verifier re-grepped); the prose claim *"TVL ≥ $10M, APY ≤ 1000%"* byte-unchanged (only the derived pool count
561 → 555 moved with the data); no new dependency. `git diff origin/main --name-only` is empty for `app.js`,
`planner.js`, `home.html`, `plan.html`, `sitemap*.xml`, `robots.txt`, `tokens/`, `chains/`, `translations.js`,
`package.json`, `data/`, every other generator, and `audit-app.js`.

**Not on the NEVER list, and the verifier agreed independently:** no trust rail is weakened (the gate only
*adds* a bound); nothing is de-indexed — all 14 omitted chains keep their sitemap entries (2 each, EN+KO),
`sitemap*.xml` and `robots.txt` are untouched, and they are query URLs rather than pages, pageless precisely
because they have no qualifying pool.

**Pre-existing red, baselined not excused:** `test_seo_cta_targets.js` fails on the plain lane (5 of 2,186
token pages with dead CTAs from live-data drift). The verifier reproduced it in an isolated `git worktree` at
`origin/main` with the *identical* 5 pages (`gitc hahype mchc n3xt wmetax`) — a `generate-token-pages.js`
surface this diff does not touch. **UNRUN** (stated, not implied green): the browser lane and the full
unfiltered `audit-app.js`.

**Process disclosure:** the operator committed the working tree while the verifier was mid-run. The committed
bytes are identical to what it verified (it checked: `git show HEAD:llms.txt` = `04856b18…`,
`generate-llms.js` = `d4a3bb97…`), so no verdict rests on the drift — but the rule stands that the tree
should be frozen while a verifier runs.

## Compound step

`playbooks/dead-generated-link-repair.md` (new): the decision procedure for the next dead generated link —
compare the generator's floor to the app's *before* copying 173's fix, check whether the section is
mis-targeted, split the dead set by whether an honest destination exists, repair a threshold param with a
ladder rather than deleting the link, verify under every population that will judge it, and install both
anti-vacuity rails.
