## Design

### A. Sampled static surfaces (replaces `audit-app.js:472`, 487-488)

- Enumerate leaf pages: `tokens/*.html` and `chains/*.html`, **excluding** hub pages
  (`tokens/index.html`, `chains/index.html`, anything under `tokens/az/`). Hubs have their own test
  (`test_hub_pages.js`).
- **Anchor surface, always present:** the current `/tokens/usdc.html` → `/chains/ethereum.html` fallback
  pair, keeping the surface name **`static-page`** unchanged so `surfacesCovered` never regresses and the
  existing acceptance assertions keep meaning what they meant.
- **Rotating sample:** `AUDIT_STATIC_SAMPLE` more leaf pages (default **6**: up to 4 token + 2 chain,
  falling back to whatever exists), named `static-page:<slug>` (e.g. `static-page:tokens/00`).
- **Determinism, no `Math.random`:** sort the candidate list, then pick by a stride derived from a seed
  string — default the UTC date (`YYYY-MM-DD`), overridable with `AUDIT_STATIC_SEED`. Same day ⇒ same
  sample (a re-run reproduces a finding); next day ⇒ a different slice (coverage accumulates).
- **Explicit override for tests/positive control:** `AUDIT_STATIC_PAGES` = comma-separated repo-relative
  paths; when set it replaces the rotation entirely (anchor included) and is used verbatim.
- Runtime guard: the rotation is capped (`AUDIT_STATIC_SAMPLE` ≤ 12) so a heartbeat run stays bounded.

### B. New checks on `kind: 'static'` (`audit-app.js:321-328`)

Existing number-sanity + page-error checks stay. Added, all read from the **rendered** page:

| check | severity | rule |
|---|---|---|
| `junk-slug` | **P1** | the `<h1>`'s leading token is pure-numeric (`/^[0-9]+$/`) or date-shaped (`/^[0-9]{1,2}(JAN\|FEB\|MAR\|APR\|MAY\|JUN\|JUL\|AUG\|SEP\|OCT\|NOV\|DEC)[0-9]{2,4}$/i`) — the 148 class, mirrored from spec 148's predicate. Detail must quote the rendered `<h1>`. |
| `zero-yield-claim` | **P1** | rendered text matches `/up to 0\.00% APY/i` — item 032's visible-non-zero-APY gate leaked (the PT/fixed-yield class flagged in PR #309's Finding 1). |
| `empty-table` | **P1** | zero `.tp-pool-link` (token pages) / `.cp-pool-link` (chain pages) rendered — a page shipped to search engines with no data (soft-404 class, item 012's mandate). |

Symbols that merely *start* with a digit are legitimate live tickers (`1W`, `4W`, `13W`, `3CRV`,
`1INCH`, `50EIGEN`, `0X0`) — the predicate must accept them, exactly as spec 148 requires. This is a
**detector only**: it emits findings, it changes no page.

### C. Keep the acceptance test honest

`test_audit_app.js` case 1 asserts **zero P0/P1 on a clean run**. Real junk pages exist on disk today, so
an unscoped full-rotation run legitimately reports them — that assertion must be scoped to the surfaces
it was actually written about (app surfaces + the clean anchor page) rather than deleted or weakened.
The scanner's honesty is the product here; the test must not be tuned to hide a true positive.

## Acceptance criteria (rendered — real Chromium, per standing decision 2026-07-11)

1. `node audit-app.js` covers **more than one** static page: `surfacesCovered` contains `static-page`
   plus ≥1 `static-page:<slug>` entry, and the run still writes the documented findings JSON.
2. **Positive control on a real render:** `AUDIT_STATIC_PAGES=tokens/00.html` (or `tokens/8oct2026.html`)
   yields a `junk-slug` **P1** finding whose detail quotes the rendered `<h1>`. Must be a real Chromium
   render, not a string test over the file.
3. **Negative control:** the anchor page (`tokens/usdc.html`) produces **no** `junk-slug`,
   `zero-yield-claim` or `empty-table` finding.
4. **False-positive guard:** a page whose slug merely starts with a digit (`tokens/0x0.html`,
   `tokens/1inch.html` or another digit-leading slug present in the checkout) produces **no** `junk-slug`
   finding.
5. Determinism: two `runAudit()` calls with the same `AUDIT_STATIC_SEED` select the same sample; two
   different seeds select different samples (proves the rotation actually rotates).
6. `node test_audit_app.js` and `node test_audit_runner.js` pass; `test_audit_runner.js` stays wired in
   `npm test` and the new rendered test is wired in too (or `test_audit_app.js` is extended — one of the
   two, not a third orphan file).
7. No generator, page, sitemap, product file or dependency changed: `git diff --stat` touches only
   `audit-app.js`, its test(s), `package.json`'s test script (if wired), and `product-loop-kit/**`.
