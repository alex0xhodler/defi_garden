# Spec 255: source-level dictionary integrity — nothing can see a duplicated or deleted translation key

## Evidence

Commit `6fceca79bb` did two things to `translations.js` in one edit, and **no gate in this repo could see
either**:

1. It **deleted** `poolNotFoundTitle` from both namespaces (count 2 → 0; item **253**). `t()` then returns
   the key string itself (`translations.js:1546`), so `app.js:3558` renders the literal
   `poolNotFoundTitle` as a heading on the `?pool=` surface.
2. It **duplicated** `tvlTrendShrinking` in both namespaces:

| namespace | shadowed (dead) | winning |
|---|---|---|
| en | `translations.js:62` — `"…our $10M size floor…"` | `:112` — `"…our $100K size floor…"` |
| ko | `:847` — `"…$10M 규모 기준…"` | `:890` — `"…$100K 규모 기준…"` |

Occurrence count of `tvlTrendShrinking:` went **2 → 4** at that commit and is 4 at `HEAD`.

**There is no user-visible defect from the duplication today** — JavaScript object literals take the last
declaration, so the *correct* `$100K` copy renders. Stated plainly rather than inflated. The defect is the
blind spot: `audit-app.js`'s `en-ko-parity` gate, `test_translations_fallback.js`, and every other consumer
walk the **parsed object**, where a duplicate key has already collapsed into one entry and a deleted key is
indistinguishable from a key that never existed. The 2026-08-08 audit run scanned **553** keys and reported
**2** suspects — both item 248's allowlist omissions, neither of these.

So a dictionary can be silently doubled **or** silently emptied and every gate in the repo stays green. The
same commit demonstrated both halves within one diff.

## Hypothesis

We believe a **source-level** check — one that reads the file, not the parsed object — will catch both
halves, because both defects are invisible by construction to any consumer downstream of `JSON`-style
parsing, and every existing gate is downstream of it. Confidence: **supported** — the positive control
already exists on `main` in two forms, so the check can be proven non-vacuous against real defects rather
than against a synthetic fixture.

- **Instance of:** a checker that inspects the **product of** a transformation when the defect lives in the
  transformation's **input**. Same shape as item 212 (a guard watching a mechanism that *resembles* the real
  one) — LEARNINGS: *a guard watching a resemblance is strictly worse than no guard; it launders the gap as
  coverage.*
- **Class closed by this item: partially.** It closes duplicate-declaration and unresolvable-`t()`-call for
  `translations.js`. It does not generalise to other parse-then-check gates in the repo. Number left open:
  not measured this tick; the build run should count how many other gates read a parsed artifact whose
  source can carry a defect the parse erases, and record the figure rather than claiming the class closed.

## Change

Two legs, both in one new registered test:

1. **No duplicate declarations.** Parse `translations.js` **as source** (walk the token stream or the AST —
   do not `require()` it and inspect the object, which is the exact blindness this item exists to remove)
   and assert that no key is declared more than once within a namespace, at any nesting depth.
2. **Every `t()` call site resolves in EN and KO.** Enumerate every `t('…')` / `t("…")` literal-key call
   across `app.js`, `PoolDetail.js`, `planner.js`, `landing.js` and `home.html`, and assert each key exists
   in **both** namespaces. This is the leg that would have caught 253 before merge.

Report both as a count with a denominator (`N call sites checked, M keys, 0 unresolved`), so a future
"clean" line carries its population.

**Explicitly OUT of scope:** the actual repair of `tvlTrendShrinking` (delete the shadowed `$10M` pair —
that belongs to item **254**, which owns the stale-floor copy) and of `poolNotFoundTitle` (item **253**);
dynamic/computed `t(someVar)` call sites, which this check cannot see — say so with a number rather than
implying full coverage; and any change to `t()`'s fallback behaviour.

## Acceptance criteria

- [ ] The check reads `translations.js` **as source**. A `require()`-then-inspect implementation is a FAIL
      regardless of whether its assertions pass — it cannot see either defect.
- [ ] Leg 1 reports duplicate declarations per namespace with line numbers, at any nesting depth.
- [ ] Leg 2 enumerates `t('…')` literal-key call sites by scanning the source files at test time — never a
      hand-maintained key list — and asserts each resolves in EN **and** KO.
- [ ] Both legs report `checked N of M` with the denominator, and the count of `t(variable)` call sites the
      scan **cannot** resolve is printed as an explicit uncovered figure.
- [ ] Registered in `package.json`'s `test:serial` chain and passing `node test_test_registry.js`.
- [ ] Tests: the new file, plus `node test_translations_fallback.js`, `node test_i18n_pages.js`, and the
      NORTH_STAR-mandated `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js`.
      Exit codes read **without a pipe**.
- [ ] Instrumentation: none — this is a build-time gate.
- [ ] Non-vacuity, using the two real defects on `main` as positive controls: run the check against
      `git show 748582f2d4:translations.js` (today's `HEAD`) → leg 1 must flag `tvlTrendShrinking` in both
      namespaces and leg 2 must flag `poolNotFoundTitle` unresolved. Then run it against
      `git show 6f1d624451:translations.js` (the commit before) → **both legs clean**. A check that cannot
      separate those two revisions has not been proven.
- [ ] Population: leg 2's call-site set is derived by scanning the source at test time; leg 1 walks every
      namespace and every nesting level found in the file, not a listed subset.

## Measurement

Metric: guardrail integrity — the count of translation defects that reach `main`. Baseline: **2 in one
commit on 2026-08-08**, both undetected by every existing gate.
Gate: build-leg only; calendar-verified in-session (the non-vacuity cycle above IS the measurement). No
traffic gate applies — this is a detector, not a product change.
Backstop: n/a.
Decision rule: keep if the non-vacuity cycle separates `748582f2d4` from `6f1d624451`; otherwise the check
is a resemblance and should not ship.

## Risk tier (builder's guess — verifier assigns independently)

**LOW.** Test-harness only: one new test file plus its `test:serial` registration. No product file, no
generator, no generated SEO surface, no dependency, no trust rail.

**Caveat that could move it:** if the builder reaches for a parser dependency, it becomes HIGH (new
dependency) — and it is not needed; the repo already parses source text in `audit-app.js` and in the
`pr-orphan-detector.js` markdown parsing without one. Also note item 166's precedent: a test file large
enough to push the diff past 150 lines is HIGH on size alone, and the verifier assigns tier independently.
