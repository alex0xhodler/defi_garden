# 187 — the entire design system was held hostage by an unused third-party font CDN

**Tier: HIGH** (verifier-assigned independently, agreeing with the spec author). Full walkthrough +
quiz per NORTH_STAR.md's HIGH-tier rule. Verifier verdict: **PASS, 8/8 criteria**, every one
independently re-derived; NEVER list not touched.

---

## The goal

Make the product's design system apply without asking permission from a server we don't own.

## The intuition, before any code

The app defers its CSS so the first paint isn't blocked:

```html
<link rel="stylesheet" href="style.min.css" media="print" onload="this.media='all'">
```

This is a standard trick. The sheet is fetched at low priority as a *print* stylesheet — so it doesn't
block rendering — and the moment it finishes loading, `onload` flips it to `all` and it applies.

The whole trick rests on one assumption: **`onload` fires.**

`style.css` line 1 was:

```css
@import url('https://api.fontshare.com/v2/css?f[]=satoshi@400,500,700&display=swap');
```

A stylesheet's `load` event does not fire until its `@import`ed sub-resources have resolved. So the flip
to `media="all"` was, on every page of the product, downstream of a cross-origin request to a font CDN.
When that request fails — ad-blocker, content blocker, corporate or school network policy, regional CDN
filtering, or fontshare simply having a bad day — `onload` never fires, the sheet stays `print`, and
**all 545 rules never apply**. Not a font falling back to a system face: tokens, layout, neumorphic
shadows, dark mode, everything.

The user sees raw UA-default text on white. Nothing is missing from the DOM, so nothing looks broken to
a scanner. It just looks like a page from 1996.

## What was measured (2026-07-31, before writing a line of code)

Rendered, real Chromium, real local server, fresh browser context per load:

```
/plan.html            | style.min.css@print  planner-styles.min.css@all
/plan.html            | style.min.css@print  planner-styles.min.css@all
/plan.html            | style.min.css@print  planner-styles.min.css@all
/home.html?token=USDC | style.min.css@print  pool-detail-styles.min.css@all
/home.html?token=USDC | style.min.css@print  pool-detail-styles.min.css@all
/                     | style.min.css@print  landing-styles.css@all
```

**0 of 6 swapped.** `--color-background`, `--neuro-shadow-raised`, `--neuro-radius-md` all read back
empty. The sheet is fetched (`200`, 99,892 bytes) and fully parsed (546 CSSOM rules against 545
top-level rules in the file — it is *not* truncated). It is simply never taken off `print`. The three
sheets *without* an `@import` swapped every single time.

Surfaces hit: `?pool=` (the north-star surface), `?token=` (the SEO lifeline), `/plan.html` (the default
face), `/`. That is the entire product.

## Proving the cause instead of asserting it

The obvious suspect was the `@import`, but "first link in the document" was an equally good story. So:
a five-line HTML file, two `<link>`s, the two real CSS files, a minimal static server, no app code.

```
style.min.css(print,onload) + planner-styles.min.css(print,onload)
  → [ 'style.min.css@print', 'planner-styles.min.css@all' ]      token: (empty)

same file, line 1's @import stripped:
  → [ 'style-noimport.css@all', 'planner-styles.min.css@all' ]   token: #E2E8F0
```

One variable changed. The swap starts working; the token resolves. A capture-phase listener confirms
`style.min.css` fires **`error`**, never `load`, while `planner-styles.min.css` fires `load` twice (once
on `print`, once after the handler sets `all`).

## The detail that made this a deletion instead of a redesign

The imported font is never used.

- `style.css:93` — `--font-family-base: "FKGroteskNeue", "Geist", "Inter", -apple-system, …`
- `style.css:783` — `@font-face { font-family:'FKGroteskNeue'; src: url('./fonts/FKGroteskNeue.woff2') }`
  — the real font is **self-hosted** and preloaded from every HTML head.
- `grep -i satoshi *.css` → the `@import` line, and nothing else.

**The request that could break every page was fetching a typeface the product never renders.** So the
fix has no happy-path visual consequence at all: it removes a resource nobody was using.

## The diff, in reading order

1. **`style.css` (−2).** Delete the `@import` and its trailing blank line. That is the entire product
   change.
2. **`style.min.css` (1-line diff).** Regenerated with `node minify-assets.js` — never hand-edited; the
   file's own header comment and `.github/workflows` both say the script owns it. The verifier re-ran
   the script itself and got a byte-identical file (md5 `836d96486354b6357c617be6d83c1a5b`), and
   separately proved the post-`@import` content is byte-for-byte unchanged: only the 83-byte prefix
   went.
3. **`test_css_import_blocking.js` (+249, new).** The gate. With `api.fontshare.com` aborted via
   `page.route`, on both `/plan.html` and `/home.html?pool=<real snapshot id>`: the `style.min.css`
   link settles to `media === 'all'`, and `--color-background` resolves non-empty. Plus a source-level
   rail: `style.css` must contain no `@import` of a remote URL (`http:`, `https:`, protocol-relative
   `//`); relative imports are explicitly *not* banned, because they are not what broke this.
4. **`package.json` (+1/−1).** One insertion into the `test:serial` chain, after
   `test_css_minified_render.js`. `run-tests.js` auto-classifies the new file into the browser lane.

## Non-vacuity — the part this repo has learned to insist on

Five items running (166, 175, 183, 185, 186) found a green gate that was measuring nothing. So the
builder proved RED by re-adding the `@import` to a scratch `style.min.css`: 2/7 pass, 5 fail.

The verifier did not accept that and ran a **stronger** mutation: it re-added the `@import` to
`style.css` itself and regenerated `style.min.css` through the real `minify-assets.js`, exercising the
whole pipeline rather than a hand-edited copy. Result: **0/7 pass, all seven red**, each for the right
reason and with a useful message. Both files restored, md5-verified, `git status --porcelain` empty.

## Tests

`run-tests.js --lane=plain` **39/39** before and after (no regression). `test_css_import_blocking.js`
7/7 · `test_minified_assets.js` 9/9 · `test_css_minified_render.js` 2/2 · `test_smoke.js` 11/11 ·

## Deviations, and things we are not pretending about

- **The full 69-file browser lane was not run** — by the builder or the verifier. It does not fit the
  5-minute timebox. Disclosed deliberately rather than skipped quietly.
- **The source-level rail is narrower than the bug class.** It protects `style.css` only. A remote
  `@import` introduced into `planner-styles.css`, `pool-detail-styles.css`, or `landing-styles.css`
  would not be caught. None has one today; widening it was out of scope. This is the verifier's honest
  limitation, recorded here rather than left implied by a green tick.
- **Why the test estate never caught this.** About twenty `test_*.js` files list `fontshare` in an
  ignorable-console-noise regex (`audit-app.js:115` has the same list). Those are *correct* — the noise
  really was ignorable. The suppressed `load` event was not. One test, `test_list_polish.js`, went
  further and **worked around** the bug: it rewrites the link to `media="all"` and stubs the font route,
  so it passed while the bug shipped. Left unmodified per scope; the verifier confirmed it masks nothing
  now that the bug is gone, and that it is not in the `test:serial` chain anyway.
- **No measurement window.** This is a defect repair, not an experiment. There is no isolable Mixpanel
  metric for "the CSS applied", and at n≈0 traffic no conversion claim is attributable to it —
  **insufficient data**, stated rather than fudged. Guardrail: `error_occurred` must not rise.
- **No `translations.js` change**, so the EN+KO rule is satisfied vacuously — stated explicitly rather
  than left unsaid.

## Why it matters more than a styling bug

`CLAUDE.md`: *"Trust is the conversion currency; the default view is the product."* The two clicks the
north star counts live on the pool-detail page. A visitor arriving from search whose browser blocks font
CDNs — an increasingly ordinary configuration — was landing on an unstyled page and being asked to
trust it with a savings plan. We do not know how many; the failure was silent, and the not-knowing was
part of the defect.

   what they were blind to.
