# 137 — PR explainer (LOW tier)

## Goal
Stop the KO pool-detail page from lying about money. It rendered USD figures with a Korean-Won label and no conversion — `약 1,189원` where the real number is **$1,189 USD** (~1300× off), sitting right next to the two north-star conversion CTAs. On the ICP's trust-first surface, a wrong money number is the worst possible bug.

## What changed
`translations.js`, KO block, 5 strings (daily/monthly sub-labels, `basedOnInvestment`, `projectionBody`, `gardenThisPoolCtaConcrete`): each stopped calling `formatKoreanCurrency(usdNumber)` (which appended `원` + 만/억 grouping) and now renders `$<en-US grouped>` — numerically identical to the already-correct EN strings. The now-dead `formatKoreanCurrency` helper and its `module.exports` entry were removed. `translations.min.js` regenerated.

## Why `$` and not ₩
No FX conversion was invented. Live FX is a new dependency and a number we can't run through the trust rails (CLAUDE.md). `$` is already the KO block's convention for USD (`$10M 기준`, `$10M 안전 기준`), so this is consistent, honest, and dependency-free.

## Risk: LOW
Copy/format fix, KO-only (EN already correct → EN+KO parity satisfied), diff ~18 source lines, no new deps, no trust-rail / router / SEO-surface touch. Render-path change → flagged **needs human visual spot-check** in the log (003 smoke gate not yet shipped); a live KO screenshot is attached to the run report as the advisory check.

## How to verify
- `node test_ko_pool_money_honesty.js` → 7/7 (rendered Playwright, real UI, `lang=ko`).
- Live: open any pool with `?pool=<id>&lang=ko` — every money figure shows `$…`, none shows `…원`.
