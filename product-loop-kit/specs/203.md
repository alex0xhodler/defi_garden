## The claim, in one line

Item 202 shipped the **capture** side of `src` (`analytics.js` now reads it into `this.acquisition`, so it
rides every event). The **emit** side is still missing on the single largest surface that points at the
north-star page: the 4,360-page static SEO estate emits **3,677 `?pool=` deep links carrying no attribution
tag at all**, so an arrival at pool-detail from `tokens/usdc.html` is indistinguishable from a cold direct
hit — and the tagging cannot simply be added, because `audit-app.js`'s link gate would call all 4,360 pages
broken the moment it is.

### 4. THE TERRITORY FINDING — the naive one-line change turns the whole estate red

This is why the item is two legs and not a one-liner. `audit-app.js`'s `link-target-integrity` rule (a)
(`audit-app.js:1650`) asserts that every query key on every owned link is in the allowed set for its path;
for the **home path** (`/`, which is exactly where `?pool=` links point) that set is built by
`loadRouterAllowedParams()` (`audit-app.js:518-531`):

```js
return { allowed: new Set([...analyticsParams, ...plannerParams, 'lang']), error: null };
```

parsed out of `home.html:77-78`:

```js
var ANALYTICS_PARAMS = ['token','chain','pool','poolTypes','protocols','minTvl','minApy','app'];
var PLANNER_PARAMS   = ['goal','monthly','years','pace','preset','fresh','capital','fm','dl'];
```

**`src` is on neither list.** Adding `&src=seo_token` to a home-path link therefore makes rule (a) fire a
**P1 `link-target-integrity`** finding on *every leaf page in the estate* — 4,360 pages, a merge gate red
across the entire SEO surface. Leg B alone is not a small change that needs care; it is a broken change.

**The fix is already named by the file itself.** The `'lang'` entry above carries this comment
(`audit-app.js:528-530`):

> `'lang'` is read by **translations.js, not the router**, so it never appears in either array — a real,
> live query key (spec 169 Territory note), so it is allowed explicitly rather than fudged in by loosening
> the parse.

`src` is the *same argument, second instance*: read by `analytics.js`, not the router. Rule (a) models the
query-param consumers of this product as **exactly two routers**, and there is a **third** — the analytics
capture list — that it has never known about. That is the gate's actual defect, and `src` is merely the
first key to expose it.

### 5. Why the other three parsers of these same links are unaffected (checked, not assumed)

| consumer | mechanism | verdict |

`test_llms_link_integrity.js:230/235` (`/\?pool=[0-9a-f-]{36}/g` on the committed `llms*.txt`) is therefore
unaffected. Sitemaps emit no `?pool=` URLs at all.

### 6. It is SEO-safe — the mechanism is already in place and already proven

`canonical.js:33` `CANONICAL_PARAMS = ['token','chain','pool','poolTypes','protocols','minTvl','minApy']`.
`src` is not on it, so `/?pool=X&src=seo_token` self-canonicalises to `/?pool=X` (spec 011's "junk params
never fragment one page's indexing signal"). Tagged internal links **cannot** create the indexable
near-duplicate class item 010 was opened for and item 188 re-found. This is spec 202 §5's argument, reused
because it is the same argument, and re-verified against the current file rather than quoted from memory.

## What ships

Two legs, in one commit, because either alone is broken (leg B without leg A reddens the estate; leg A
without leg B is a widened allow-list with nothing using it).

### Leg A — rule (a) learns the third consumer, by parsing it (never by re-typing it)

`audit-app.js`: `loadRouterAllowedParams()` gains a third source — the attribution keys
`analytics.js`'s `captureAcquisition()` actually captures — parsed out of `analytics.js` with the existing
`extractQuotedArray()`-style technique, and unioned in.

Hard requirements:
- **Derived, never a literal.** No hardcoded `'src'` (or `'utm_source'`, …) anywhere in `audit-app.js`. If
  a key is removed from `analytics.js`'s capture list, the gate must start flagging links carrying it.
  A literal here would be the exact bug class item 166 shipped and spec 169 re-flagged.
- **Never-throws contract preserved.** If `analytics.js` is unreadable or the array unparseable, behave
  exactly as the existing `home.html` failure path does — return the error, caller prints the note ONCE per
  scan and skips rule (a); rules (b)/(c) and the four pre-existing signals keep working.
- **Must not become a wildcard.** Only the exact keys that list contains. An unknown key (`?bogus=1`) must
  still fire rule (a) — this is the non-vacuity rail and it is a hard acceptance criterion below.
- `'lang'` stays exactly as it is: hardcoded with its comment. `translations.js` has no parseable array,
  so deriving it is not available — do not "tidy" it, and do not delete its comment.

### Leg B — the estate tags its pool deep links

`generate-token-pages.js`: `poolHrefFor(p, fallbackUrl, src)` gains an **optional** third argument.
- Absent/falsy → returns exactly what it returns today, byte-for-byte. This is what keeps the JSON-LD path
  unchanged and is directly asserted below.
- Present → appends `src=<value>` with the correct separator (`?` vs `&`), applied to **both** branches
  (the `?pool=` link and the `fallbackUrl` — a row that falls back to the token/chain app view is the same
  attribution question and must not silently go untagged). Value passed through `encodeURIComponent`.

Call sites: the **visible row links only** — `generate-token-pages.js:789` → `'seo_token'`,
`generate-chain-pages.js:246` → `'seo_chain'`. Language-independent (KO pages emit the same tag), matching
the shipped `renderWaitlistCtaHtml` convention on these same pages; the page's own URL already carries the
language, so a `_ko` suffix would be a second taxonomy for a fact already recorded.

**DELIBERATE DEVIATION from the filed note, pre-registered here for the verifier to judge against stated
intent rather than infer:** the note says the shared helper is "the single place to add a `&src=` param",
which would tag the ItemList JSON-LD too (`renderItemListJsonLd` calls the same helper). **This spec keeps
the JSON-LD `url` canonical and clean, and tags only the visible `href`.** Reasons:
1. Google's ItemList guidance is that `url` names the canonical item page; a tracking param in schema.org
   markup makes the structured data point at a URL the page itself canonicalises away (§6).
2. 046's invariant is *anti-drift* — same pools, same order, same target page. That is preserved, and
   pinned **more tightly** than before by criterion 5, which asserts the exact relationship between the two
   rather than mere string equality.
3. The optional-argument design means the JSON-LD path calls the helper with no `src` and is provably
   byte-unchanged (criterion 2).

This deviation requires editing two existing assertions (`test_token_pages.js:252`,
`test_chain_pages.js:249`, both currently `assert.ok(html.includes(\`href="${items[i].url}"\`))`). They must
come out **strictly stronger**, not weaker — see criterion 5. Weakening either is a FAIL.

### Not in scope (say so, don't silently skip)
- **No regenerated HTML is committed.** The 4,360 pages regenerate on the next `sitemap-update.yml` CI run,
  per the standing convention for every generator change (021/041/045/050/174 precedent). The BACKLOG row
  and PR must say this plainly rather than imply pages shipped.
- Hub pages (`tokens/index.html`, `tokens/az/*`, `chains/index.html`) — measured at **0** `?pool=` links.
- `generate-llms.js`, sitemaps, `PoolDetail.js`, `planner.js`, `home.html`, `canonical.js` — untouched.
  **`home.html` must not be edited**: adding `src` to `ANALYTICS_PARAMS`/`PLANNER_PARAMS` would make it an
  IA-router *trigger* (`needsAnalytics`/`needsPlanner`), routing bare `/?src=x` to the wrong face of the
  product. That is a trap, not a shortcut; the router allow-lists are sacred (NORTH_STAR risk policy).

## Acceptance criteria

Rendered/behavioural where the artifact is a rendered page; the two generators are pure functions over
fixtures, so their criteria run on **real generator output**, never on hand-written HTML strings.

1. **Leg B emits.** `renderTokenPage` output: every `class="tp-pool-link"` anchor's `href` carries
   `src=seo_token`; `renderChainPage` output: every `class="cp-pool-link"` anchor's `href` carries
   `src=seo_chain`. Counted, and the count equals the visible row count (no row silently untagged).
   The `fallbackUrl` branch is covered by a fixture pool with no `pool` id.
2. **JSON-LD provably unchanged.** `poolHrefFor(p, fallback)` with no third argument returns a string
   byte-identical to the pre-change function for both branches, and every ItemList `url` in generated output
   matches `/^https:\/\/www\.defi\.garden\/\?pool=[^&]+$/` (or the clean fallback) — **no `src` anywhere in
   any `ld+json` block**, asserted over the whole block, not per-item.
3. **The gate accepts the new links.** `prescanStaticPages()` (or the narrowest real entry point that runs
   rule (a)) over generated token+chain output produces **zero** `link-target-integrity` findings. Run
   against real generator output written to a temp dir, not fixtures.
4. **The gate is NOT now a wildcard — non-vacuity, two ways.** (a) A page whose pool link carries a key that
   is on no list (`&bogus=1`) still produces a `link-target-integrity` finding. (b) **Mutation:** remove
   `'src'` from `analytics.js`'s capture array in a scratch copy → criterion 3's run goes RED. Both must be
   demonstrated with real output pasted into the notes, not asserted in prose.
5. **046's invariant survives, tighter.** For each row i, in both generators:
   `items[i].url` is the clean URL **and** the rendered row href is exactly `items[i].url + '&src=<tag>'`
   (or `?src=` where the fallback has no query). This replaces the two `html.includes(\`href="${url}"\`)`
   assertions and pins strictly more than they did.
6. **No literal.** `grep -n "'src'\|\"src\"" audit-app.js` shows no hardcoded attribution key added by this
   diff. Paste the grep.
7. **Never-throws preserved.** With `analytics.js` unreadable (scratch rename), the scan still completes,
   prints the note once, and rules (b)/(c) + the four pre-existing signals still report.
8. **Suite.** The plain (non-browser) lane green, plus `test_token_pages.js`, `test_chain_pages.js`,
   `test_audit_prescan.js`, `test_seo_cta_targets.js`, `test_llms_link_integrity.js` explicitly named with
   pass counts. `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js`
   (NORTH_STAR's Test command) green. **Any pre-existing red must be proven pre-existing on a clean
   `origin/main` worktree BEFORE it is attributed to the baseline** (`playbooks/pre-existing-red-triage.md`).
   Everything under the standing **300s foreground timebox** — if a lane cannot finish, say which and why.
9. **Bookkeeping in the SAME commit** (2026-07-13 rule): `BACKLOG.md` row, `specs/203-notes.md`,
   `specs/203-pr.md`, `LOG.md` entry.

## Risk tier (spec's guess — the verifier assigns independently)

**HIGH.** Not from size but from blast radius: the diff edits `audit-app.js`, the merge gate's own detector,
where a wrong edit silently weakens every later verdict (166/176/181/198/201 precedent), and it changes what
4,360 SEO pages emit. No trust rail (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly flags, degen haircut) is
touched, no `__APP_MODE` router behaviour, no dependency, no config, no out-of-scope dir, and no SEO surface
is deleted or de-indexed — so HIGH, not NEVER/BLOCKED. Counting tests, the diff will likely also clear the
150-line LOW cap on size alone (item 198's counting precedent).

## Measurement

Ships an **attribution fix, not a traffic fix** — and the row and PR must say so. `src` will still read
`undefined` for cold/organic arrivals; what changes is that an arrival *from the SEO estate* becomes
distinguishable from one that is not, on `page_view`, `pool_view` and **`pool_click`** (the north star) alike,
because 202's `this.acquisition` rides every event. No isolable funnel metric of its own, and at 24 straight
days of a zero north star there is nothing to A/B — this is the pre-traffic mandate's "make it measurable
before there is anything to measure" (2026-07-23), and the honest read is: **expect tomorrow's heartbeat to
still report zero tagged arrivals**, because the tagged links do not exist in prod until the next CI regen,
and no traffic walks them until distribution lands.
