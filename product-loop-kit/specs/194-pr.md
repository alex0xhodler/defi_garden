# 194 — explainer (HIGH tier: full walkthrough + quiz)

## Goal

Two artifacts written the same day disagreed about one pool, and one of them was making the merge gate
exit non-zero:

- `audit-app.js` (2026-07-31 tick): `pool-detail:13392973` (`sdai` / Gnosis, $55.4M TVL) → **P1
  `degraded-cta`**, `kind=defect` — blocking.
- `reports/2026-07-31.md:4`, closing item 182: *"the one genuinely unreachable pool (`sdai`) now renders
  an honest DefiLlama fallback instead of empty space"* — deliberate, shipped behaviour.

The backlog row was explicit that this had to be **diagnosed, not guessed**, because the answer decides
between a one-line classifier change and a reopened 182.

## Intuition

The audit was right about the *state* and wrong about the *category*. It could see that the page rendered
the fallback instead of the real "Start Earning on <protocol>" CTA — that part is true. What it could not
see is *why*, because the classifier had no branch for "there is no URL to render, and there never will
be". A project in that state produces **exactly the same inputs** as a project we simply forgot to cover.
Same inputs, different meaning — so the fix isn't a new branch, it's a new **input**.

The component that already knows the answer is the generator, `generate-protocol-urls.js`: it is the thing
that dropped the URL in the first place, deliberately, via `isValidHttpsUrl()`. So it now writes down what
it skipped, and the audit reads that as positive evidence.

## The diagnosis, in the order it settles

1. **Upstream has the protocol and publishes no URL for it.** Live `https://api.llama.fi/protocols`
   (7,974 protocols) contains exactly one match: `{"name":"sDAI","slug":"sdai","url":"","category":"Yield"}`.
   The `url` is the **empty string** — not a missing record, not a stale artifact, not a failed fetch.
2. **The generator is behaving correctly.** `isValidHttpsUrl()` (`/^https:\/\/\S/`) rejects blank and
   `http://` urls on purpose; its own comment says baking those *"would ship a dead/insecure link from our
   own origin forever until the next regen."*
3. **182 built the fallback for precisely this case** (`specs/182.md:93` — *"the true-null case (`sdai`
   and any brand-new protocol)"*; `182-notes.md:145` — 735/736 = 99.9%, single uncovered project `sdai`).
4. **The classifier had no way to say so.** `classifyCtaKind()` was
   `undeterminable → defect(no tier) → environment → defect`, and `CTA_KIND_SEVERITY.defect = 'P1'` ⇒
   blocking (`blockingFindings()` = P0|P1).
5. **The population is small and fully knowable.** Measured live across `api.llama.fi/protocols` ×
   `yields.llama.fi/pools` (15,826 pools): **20** project keys have no baked URL; **20/20** are present
   upstream with a blank url; **0** are absent from upstream. 250 bytes serialized.

**Verdict: fix the classifier. 182 is not reopened.** The report's close-out was accurate.

## What changed, in reading order

**1. `generate-protocol-urls.js` — record what was deliberately skipped.**
New `buildUnreachable(protocols, population, fullMapping)` returns the sorted population keys whose
upstream protocol entry **exists** (matched by `protocolUrlKey(protocol.name)` or its `slug` alias) but
was rejected by `isValidHttpsUrl()`. `buildArtifact()` now emits
`{ schemaVersion, generatedAt, urls, unreachable }`.

The load-bearing detail is the *filter*: a key with no upstream entry at all never enters the skipped set,
so it can never be listed. That is the whole "genuine coverage gap ≠ by design" distinction, enforced by
construction rather than by a downstream check.

> **The trap this had to avoid.** `SCHEMA_VERSION` stays **1**. `app.js:1293` hard-rejects the artifact
> with `if (!json || json.schemaVersion !== 1 || …) return;` — bumping it to advertise the new field would
> have made every browser silently discard the baked tier, regressing north-star protocol-CTA coverage
> **99.9% → 70.9%**. The field is purely additive; `app.js:1297` and `audit-app.js`'s
> `readBakedProtocolUrls()` both read only `urls`. `test_protocol_url_keys.js` (which pins
> `schemaVersion === 1`) is unmodified and green.

**2. `audit-app.js` — read it, classify on it, downgrade only on it.**
- `readBakedProtocolUrls()` additionally returns `unreachable: Set|null` — a `Set` when the artifact
  carries a valid string array, **`null`** when the field is absent or malformed.
- `classifyCtaKind()` takes `upstreamUnreachable` (tri-state) and gains one branch:
  ```
  1. !diskDeterminable || bakedRunOutcome === 'unknown'      -> 'undeterminable'  (unchanged)
  2. diskTiers.length === 0 && upstreamUnreachable === true  -> 'upstream-null'   (NEW, P2)
  3. diskTiers.length === 0                                  -> 'defect'          (unchanged)
  4. bakedRunOutcome === 'failed' | 'absent'                 -> 'environment'     (unchanged)
  5. otherwise                                               -> 'defect'          (unchanged)
  ```
  Strict `=== true` is the safety property: `null`/`false`/omitted ⇒ today's `defect`. The new kind sits
  **before** the catch-all but never **as** it — spec 183's non-vacuity contract, preserved.
  `upstream-null` precedes the `environment` check deliberately: when upstream has no URL to serve, this
  run's fetch outcome changes nothing about what the page *should* render.
- `CTA_KIND_SEVERITY['upstream-null'] = 'P2'` (the existing non-blocking lane — no third severity invented).
- `ctaFindingSeverity()` **untouched**: a `missing` shape stays P1 for every kind, including this one.
  182's `renderProtocolCtaBlock()` always renders one of the two buttons, so an absent element is never
  explained by URL provenance (spec 183, verifier round 3).
- The pool driver resolves `upstreamUnreachable` with the same slugified+raw key shapes `projectHasUrl()`
  already uses, and appends a by-design clause to `detail` mirroring `environment`'s reconciliation wording.

**3. `data/protocol-urls.json` — regenerated** from live sources: 476 keys, **20 unreachable**, matching
the diagnosed list byte-for-byte.

**4. Tests.** Criteria 1–4 extend `test_audit_cta_provenance.js` (35/35). Criteria 5, 7, 8 land in the new
`test_audit_upstream_unreachable.js` (3/3), registered in `package.json`'s `test:serial` — an unregistered
test never runs (193's finding).

## The acceptance is the interesting part, and it is symmetric on purpose

A fix that suppresses a false positive is indistinguishable, from the outside, from a fix that blinds the
detector. So the two rendered criteria pull in opposite directions:

- **Criterion 7 (must be QUIET):** a real-Chromium `runAudit()` over the real sdai pool
  `13392973-be6e-4b2f-bce9-4f7dd53d1c3a` yields severity **P2** with `kind=upstream-null`, and
  `blockingFindings()` contains **nothing** for that surface.
- **Criterion 8 (must still FIRE):** the same rendered path with the `unreachable` evidence withheld —
  via a tmpdir copy of the artifact, never touching the committed file — puts the **P1 `defect`** back.

The verifier ran its own mutation rather than re-reading the builder's: it forced `upstreamUnreachable = true`
unconditionally in the driver, watched criterion 8 go red (`got P2`, expected P1), restored `audit-app.js`
**byte-exact** (confirmed by `diff`), and re-ran the suite green. It also rebuilt criterion 5 on its own
fixture rather than the builder's, confirming that `http://`, whitespace-only urls, slug-alias reachability
and dual-reachability all fall the right way.

## Deviation from the spec (one, documented)

`readBakedProtocolUrls()` gained a test-only `overridePath` param, threaded as
`opts.protocolUrlsPath` / `AUDIT_PROTOCOL_URLS_PATH` through `runAudit()`'s `ctx`. Criterion 8 requires a
*real rendered run* with the evidence genuinely absent, and the path was previously hardcoded with no
injection point. It follows the file's existing `opts.X || process.env.AUDIT_X || default` convention
(`AUDIT_SNAPSHOT_PATH`, `AUDIT_ROTATION_STATE`, `AUDIT_STATIC_PAGES`). Default behaviour with no override
is byte-identical to before — the verifier confirmed the only caller passes `undefined` unless a test sets
it explicitly.

## Risk

**HIGH**, assigned independently by the verifier: it edits the merge gate's own classifier and a committed
artifact the live site fetches at runtime, and the code+test diff is **326 lines** against the LOW lane's
150-line cap (counted including the new 161-line test file — the arithmetic item 193's LOG entry records a
verifier getting wrong by omitting new test files). No NEVER-list surface is engaged: no trust rail
touched, no credentials, no SEO deletion, nothing under `telegram-bot/`/`whatsapp-bot/`/`workers/`, no new
dependency. `PoolDetail.js`, `app.js`, `translations.js` show zero diff. So autonomy (c) permits the merge;
the tier changed the paperwork, not the outcome.

No user-facing string was added — the new `detail` clause is audit-tool-internal — so the EN+KO parity rule
is **vacuously** satisfied. Stated, not left unsaid.

## Residual, stated plainly

The full ~100-file `npm test` chain was **not** run (5-minute timebox). Every audit-family test, every
`test_protocol_*` test, and `test_run_tests.js` were run by both the builder and the verifier
independently. Files with no path to `classifyCtaKind`, `readBakedProtocolUrls`, `CTA_KIND_SEVERITY` or the
regenerated artifact were not run individually.
