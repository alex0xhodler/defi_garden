# 131 — PR explainer (LOW tier)

**What & why.** On the pool-detail page (the north-star surface) "Browse tokens · Browse chains" rendered twice — once high on the page, once in the footer. Item 086 had already added a dedup rule (`html[data-app-mode="analytics"] .seo-hub-links{display:none}`) to hide the static crawler footer whenever the app also shows those links, but that rule lives in `style.css`, which loads asynchronously via the `media="print"` onload swap. Before that swap fires — during initial paint on the still-empty `#root`, and in any headless renderer (exactly the environment that produced the 2026-07-23 audit screenshot) — the static `.seo-hub-links` footer is visible alongside the React `.app-footer` copy. Result: a flash of the duplicate.

**The fix (3 files, +38 lines).** Mirror that one rule as **render-blocking inline critical CSS** in `home.html`'s `<head>`, so it applies at first paint independent of the async stylesheet:
`<style>html[data-app-mode="analytics"] .seo-hub-links{display:none}</style>`
- `home.html` — inline `<style>` + comment, placed after the `style.min.css` link, before the mode-conditional CSS script. The `__APP_MODE` router and all `?token/?chain/?pool` handling are byte-for-byte untouched (verifier-confirmed).
- `style.css` — a one-line sync-pointer comment before the existing 086 rule (rule kept intact; no `style.min.css` regen needed).
- `test_footer_hub_links.js` — new rendered-Playwright case (e) on `/?pool=usdc-base-aave` asserting `.seo-hub-links` is `display:none` **without** forcing the async swap, and exactly one visible `/tokens` + one `/chains`, both inside `.app-footer-hub-links`.

**Why it's safe.** Crawlers run no JS, so `data-app-mode` is never set for them → the inline rule doesn't match → the raw static `<a href="/tokens">`/`<a href="/chains">` anchors stay in the served HTML (045 de-orphan surface preserved). No new deps, no i18n strings, no `app.js` render change, no trust-rail touch.
