# Spec 046: ItemList + Dataset JSON-LD on the pool tables (token + chain pages)

## Evidence
Direct grep of structured-data types across the live SEO surface, 2026-07-12:
- `grep '"@type":"..."'` over `tokens/*.html`, `chains/*.html`, `home.html` → only `BreadcrumbList` (87), `ListItem` (261, all from those breadcrumbs), `WebSite` (1), `Organization` (1). **No `ItemList`, no `Dataset` anywhere.**
- The core content of every token/chain page is a ranked table of pools (protocol · chain · APY · TVL). That ranked list — the pages' actual value — carries zero structured data. 040 shipped Organization/WebSite/BreadcrumbList/FAQPage and *deliberately deferred* `Product`/`FinancialProduct` for pools (mis-typing an APY as a price risks a manual action) — but `ItemList` (the ranked list itself) and `Dataset` (the yields dataset) were left entirely unaddressed.
- 2026 SOTA: `ItemList` on ranked/collection pages → mobile carousel eligibility + an AI-Overview/entity citation signal that Gemini/ChatGPT/Perplexity/Claude use when generating answers. The documented caveat — don't mark a collection page as a single `Product` — is exactly why `ItemList` (not `Product`) is the correct type here, confirming 040's deferral was right and `ItemList` is the safe, additive next step.

## Hypothesis
We believe adding content-matched `ItemList` (the ranked pools) and `Dataset` (the yields dataset) JSON-LD to token and chain pages will improve rich-result eligibility and AI-answer citation likelihood, because the pages' primary value is currently invisible to structured-data consumers while comparable ranked-data pages gain carousel/citation eligibility from exactly this markup. Confidence: **supported by external 2026 sources; unvalidated on this site** (no prior A/B — track as a hypothesis).

## Change
Additive JSON-LD only, hand-rolled strings matching the existing generator pattern (no schema library, no new dep):
1. `generate-token-pages.js` + `generate-chain-pages.js`: add a `<script type="application/ld+json">` `ItemList` block whose `itemListElement` is the SAME ranked pools already rendered in the visible table (position, name = `<project> on <chain>`, plus the pool-detail URL as `url`). Values derive ONLY from data already on the page — no new computation, no APY re-typed as a monetary price.
2. Add a `Dataset` block describing the page's yield dataset (name, description, `creator`/`publisher` = the Organization, `dateModified` — coordinate with 048's freshness work if it lands first, else emit the CI generation date), representing the honest "live DefiLlama yields for `<TOKEN>`/`<CHAIN>`" dataset the page presents.
3. Google's rule (structured data must reflect visible content): the `ItemList` items must be exactly the rows shown, in the same order — verified programmatically, byte-for-byte, so schema can never drift from the table.

OUT of scope: `Product`/`FinancialProduct`/`Offer` for individual pools (deferred by 040 for good reason — an APY is not a schema.org `price`; mis-typing risks a misleading-structured-data manual action). No visible/UI change, no trust-rail change, no ranking/canonical change.

## Acceptance criteria
- [ ] Every generated token and chain page includes a valid `ItemList` JSON-LD block whose `itemListElement` count and order EXACTLY match the visible pool table rows, with `url` per row pointing at the same `/?pool=<id>` (or fallback) the visible row links to. Verified by parsing the emitted JSON-LD and diffing its items against the rendered table rows (programmatic, not eyeballed).
- [ ] Every generated token and chain page includes a valid `Dataset` JSON-LD block with the required schema.org properties (name, description, and a publisher/creator resolving to the site Organization).
- [ ] All JSON-LD parses as valid JSON and satisfies the documented required-property checklist for `ItemList`/`Dataset` (a live Rich Results Test isn't available in-sandbox — document the manual property checklist used, per 040's precedent).
- [ ] No visible content, meta, canonical, trust rail, or ranking altered — diff is an added script block only, confirmed by regenerating a fixture page and diffing against pre-change output (only the JSON-LD inserted).
- [ ] Tests: new assertions in `test_token_pages.js`/`test_chain_pages.js` verifying ItemList/Dataset presence, valid JSON, and the items-match-visible-table invariant, added to the `npm test` chain.
