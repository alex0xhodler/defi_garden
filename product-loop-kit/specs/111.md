# 111 — Analytics nav + filter-dropdown UI polish

**Status:** IN_PROGRESS (2026-07-15) · **Score:** 7.0 · **Risk:** HIGH
**Evidence:** human feedback 2026-07-15 on 093's shipped nav ("the data and icons are very
confusing, needs an upgrade"; "these selectors need better hover overlay controls and UI for
[the open-dropdown] state"). Human chose **option 1** of the operator's proposal: strip the
category-tab icons, keep the filter icons. Backlog row 111. Active focus decision 2026-07-11
("fix what makes the product feel bad/untrustworthy").

## Why (north-star linkage)
The analytics app is the SEO arrival surface feeding the card funnel. The human called its nav
"confusing"; competing glyphs and a mushy open-dropdown state erode the trust the funnel depends
on. This is a clarity/trust polish on a funnel-facing surface — no isolable Mixpanel metric of its
own; it lands as a guardrail (planner-conversion / analytics-URL integrity) quality fix.

## Scope — TWO parts

### (A) NAV RAIL — de-noise the primary category tabs
- Drop the `navIcon(icon)` call from the `.google-nav-primary` `CATEGORY_TABS.map(...)` render in
  `app.js` (~L2810). The 6 competing glyphs read as noise next to plain text labels ("Lending",
  "Staking", …). Category tabs become **text-only**.
- **KEEP** the `navIcon(...)` glyphs on the 4 filter buttons in `.google-nav-secondary`
  (chains/tvl/protocols/apy). Retain `NAV_ICONS` and `navIcon` unchanged — still used by the
  filters. (The now-unused category glyph keys in `NAV_ICONS` may remain; leaving them keeps the
  diff surgical.)
- Leave `CATEGORY_TABS`' `icon` field in place (harmless; removing it is churn) OR drop it — do
  NOT let its removal cascade. Minimal diff preferred: just remove `navIcon(icon),` from the map.

### (B) OPEN FILTER-DROPDOWN STATE (`.global-filter-dropdown`, `style.css` ~1233-1364)
1. **Remove the CLAUDE.md-BANNED scale-pop hover.** `.global-filter-dropdown .filter-pill:hover:not(.active), .filter-chip:hover:not(.active)`
   (style.css ~1300-1302) currently uses `transform: translateY(-2px) scale(1.02)`. Replace with
   neuro lift only: `transform: translateY(-1px)` + keep the `box-shadow` raise. **No `scale()`.**
2. **Make the SELECTED chip unmistakable — filled primary.** The TVL/APY chips
   (`.global-filter-dropdown .filter-chip.active`, style.css ~1354) render with only a 1px lift +
   raised shadow; make them read as filled-primary like `.google-filter-btn.has-selection`
   (`background: var(--color-primary); color: white; font-weight: var(--font-weight-semibold)`).
   **Do NOT** add a `--color-primary` background to the shared `.filter-pill.active` global rule —
   that would stomp `.chain-pill.active`'s brand-color fill (higher specificity). Scope the new
   fill to `.filter-chip.active` only; chain/protocol pills keep their existing filled/brand look.
3. **Add a subtle scrim + robust close-on-outside-click.**
   - **Audit finding:** the existing outside-close handler (`app.js` ~L1255) tests
     `!event.target.closest('.filter-dropdown-container')` — a selector that does **not** exist in
     this nav (the dropdowns are `.global-filter-dropdown`, rendered at document top level with
     `position:fixed`). So it currently closes on *essentially any* click, and clicking inside the
     open panel only stays open because each pill self-closes. Coincidental, not robust.
   - **Tighten** the handler to treat clicks inside `.global-filter-dropdown` OR on a
     `.google-filter-btn` as "inside" (so panel interaction and direct filter-to-filter switching
     don't misfire); everything else closes.
   - **Add a scrim element** rendered alongside the global dropdowns (only when `activeDropdown` is
     truthy), `onClick: () => setActiveDropdown(null)`. CSS `.global-filter-scrim`:
     `position:fixed; top:128px; left:0; right:0; bottom:0; z-index:99998` (below the dropdowns'
     99999, above content). **`top:128px`** matches the existing hardcoded dropdown `top` so the
     scrim starts *below* the sticky header (z-index 100) — the filter buttons stay clickable, so
     switching filters directly still works; only the results area is dimmed/click-to-close.
     Subtle tint (light `rgba(15,23,42,0.06)`, dark `rgba(0,0,0,0.28)`), gentle fade-in,
     `prefers-reduced-motion` → no animation. Neumorphic-calm, no glow/bounce.

## Territory notes
- Base `.filter-chip.active` (style.css ~4900) already sets filled-primary; the
  `.global-filter-dropdown .filter-chip.active` override (~1354) only re-declares transform +
  box-shadow, so the fill *does* fall through — but the human perceives it as weak. Making the
  fill explicit on the global rule removes the fragility and guarantees B2.
- `.chain-pill.active` (~4746) uses `--chain-color` brand fill at specificity 0,2,0; the global
  `.filter-pill.active` rule at 0,3,0 must NOT declare `background` or it stomps brand color.
- Global dropdowns render at top level in `app.js` (~L3270+) with `position:fixed; top:128px;
  zIndex:99999`; the sticky header is z-index 100. The scrim at z 99998 + `top:128px` sits between
  them and leaves the header interactive.
- Sandbox: browser-originated HTTPS to `icons.llamao.fi` is connection-reset (pre-existing; the
  baseline `test_nav_rail_ia.js` fails only on this via assertion #10). Ignore-pattern extension is
  the sanctioned fix (same as fontshare/mixpanel already in the pattern).
