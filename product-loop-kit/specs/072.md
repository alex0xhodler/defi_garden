# 072 — Honest dead-`?pool=` empty state: noindex + "no longer tracked" + alternatives (extends 012 to pool deep links)

Promoted by the 2026-07-13 build loop (no READY items existed). Next ID after 071.

## Evidence (documented, in-repo)

- `specs/012-pr.md` (Deviations): "`?pool=<dead-id>` deep links are not extended to. They're
  structurally a soft-404-shaped gap (a dead pool id silently falls back to the full homepage
  DOM, no empty-state ever renders, because `selectedToken`/`selectedChain` are never set by
  that code path) … Documented rather than silently left; **candidate for a future item**."
- Confirmed live in code this run: `app.js:1009-1031` — the `?pool=` effect only acts when
  `foundPool` is truthy. When the id isn't in the live pools list, nothing happens: no filters
  are set, `filteredPools` = ALL pools, and the full homepage grid renders under a
  self-canonical `?pool=<dead-id>` URL (011's router self-canonicalizes every analytics URL).
  To Google that's duplicate/soft-404 content; to a human arriving from a shared link it's a
  silent bait-and-switch with zero explanation.
- `specs/010-diagnosis.md`: Soft 404 = 3,568 URLs (High confidence); dead/delisted entities
  rendering 200s is the named mechanism. 012 fixed the token/chain legs; the pool leg is open.
- Why it matters MORE now: pool ids are the rot-prone unit. Token pages (029) deep-link
  `/?pool=<id>`, the share/spotlight surfaces (024/060/069) point at specific pools, and pools
  delist from DefiLlama constantly — every such link eventually dies. Trust is the conversion
  currency (CLAUDE.md); the 2026-07-11 standing focus is "fix what makes the product feel
  bad/untrustworthy" on the pool-detail path.

Score 7.2 — same class as 012 (8.6) but on the lower-traffic leg; boosted by link-rot exposure
of the share/spotlight artifacts. Risk HIGH (app.js render path + robots meta behavior adjacent
to sacred `?pool=` URLs).

## Hypothesis → metric

Not a growth experiment — an honesty/SEO-quality fix on an existing surface (012/070/071
disclosure pattern). No new Mixpanel event (`pool_view` correctly does NOT fire for dead ids
today and must stay that way). Proxy metrics: GSC soft-404 class over the ongoing 2-6wk
validation cycles (026 human-checked); zero regression on the guardrail "analytics URLs keep
rendering pool cards".

## Change (smallest that closes the gap — reuse 012's machinery, invent nothing)

All in `app.js` + `translations.js` (+ regenerated compiled/min artifacts). NO changes to
home.html, the router, canonical logic, PoolDetail.js, planner.js, or any generator.

1. **Track the miss.** New state `deadPoolParam` (string|null, default null). In the existing
   `?pool=` effect (`app.js:1009`): when `pools.length > 0`, `urlParams.pool` present and no
   `foundPool` → `setDeadPoolParam(urlParams.pool)`; when `foundPool` → ensure it's null.
   In the popstate handler (`app.js:925`): when the URL no longer carries a `pool` param →
   reset to null.
2. **Resolved flag, 012 shape:**
   `deadPoolResolved = currentView !== 'pool-detail' && pools.length > 0 && !!deadPoolParam`
   (never true during the pre-fetch flash — same "never claim dead while loading" rule as 012).
3. **Suppress the false homepage.** The results branch (`app.js:~2827`,
   `filteredPools.length > 0 ? [grid] : empty-state`): when `deadPoolResolved`, render the
   empty-state block instead of the grid.
4. **Honest empty state.** Inside the existing `.empty-state` block, branch FIRST on
   `deadPoolResolved`: headline `t('poolNotFoundTitle')` and explanation
   `t('poolNotFoundExplanation')` (this pool is no longer tracked in live DefiLlama data —
   likely delisted or migrated; no scary jargon, calm tone). Below it, reuse the 012
   alternatives grid verbatim with `getEmptyStateAlternatives(null)` → top-TVL stablecoin
   alternatives via the existing trust rails, heading `t('emptyStateAltHeadingStable')`.
   Existing token/chain empty-state copy paths must render byte-identically when
   `deadPoolResolved` is false. The reset-filters buttons may render as-is (resetApp is a
   correct escape hatch here too).
5. **noindex.** Extend the 012 robots effect condition from `emptyStateResolved` to
   `emptyStateResolved || deadPoolResolved` (same idempotent find-or-create node; restore to
   `index, follow` when neither holds — e.g. after clicking an alternative into a live pool
   detail, mirroring 012's `currentView !== 'pool-detail'` guard rationale).
6. **Translations.** New keys `poolNotFoundTitle`, `poolNotFoundExplanation` in BOTH `en` and
   natural `ko`, in the analytics-app section next to `noYieldsFound`/`emptyStateExplanation`.
   No other key touched.
7. **Artifacts.** `npm run compile && npm run minify` — regenerate `app.compiled.js`,
   `app.compiled.min.js`, `translations.min.js` (and whatever else the minify script rewrites);
   `test_compiled_assets.js`/`test_minified_assets.js` must stay green (they enforce
   freshness — the 061 staleness bug class).

OUT of scope: dead-id handling inside an already-open pool-detail view, new analytics events,
canonical changes, generator/SEO-page changes, PoolDetail.js, any styling beyond existing
empty-state classes (reuse `.empty-state`, `.empty-message`, `.empty-submessage`,
`.empty-state-alternatives`, `.pools-grid` — zero new CSS).
