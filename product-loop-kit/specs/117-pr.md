# 117 — Risk-adjusted yield (Sharpe ratio) KPI · compute leg — PR explainer

## Goal
Give every pool a **rate-stability Sharpe ratio** — the quantified form of 088's thesis that
"a steady 6% beats a spiky 20% for a subscription garden." This run ships the **compute leg
only**: the number is computed and baked into the data layer; nothing renders yet (surfaces
ship one at a time, pool-detail first, per the spec).

## Intuition
A classic Sharpe ratio is `(return − risk-free) / volatility` — reward per unit of risk. For a
DeFi pool the self-consistent mapping over the retained daily `apy_t` series (already an
annualized %) is:

```
apySharpe = (mean(apy_t) − RISK_FREE_APY) / stdev(apy_t)
```

- **Rate-stability, not principal-safety.** It measures how steady a pool's *yield* has been
  relative to how much it pays. A pool paying a rock-steady 6% scores far higher than one
  averaging 20% that swings ±12. It says NOTHING about impermanent loss, depeg, exploits, or
  TVL flight — a pool can depeg to zero the snapshot after showing a beautiful Sharpe. That
  caveat is why the spec tags the item HIGH and why it must travel WITH the number when it is
  eventually surfaced; it is captured in the code comment now.
- **No √T annualization.** `apy_t` is already annualized, so numerator and denominator are both
  in annual units. Multiplying by √252 would be wrong — documented inline so nobody "fixes" it.
- **RISK_FREE_APY = 4.0%** — one disclosed benchmark (~US T-bill), configurable. Any future
  display must name it ("vs a ~4% risk-free rate").

## What changed and why (diff in reading order)

`compute-kpis.js`
1. **Two constants** after `HISTORY_RETENTION`: `RISK_FREE_APY = 4.0` and
   `SHARPE_MIN_POINTS = 8`. Eight is the noise floor — below ~8 daily points the ratio is too
   jumpy to mean anything, so it returns `null` ("not enough history"), the same honest-null
   discipline the existing KPIs already use.
2. **`computeKpis` refactor**: compute the apy array, its population stdev (`sd`), and its
   mean ONCE, then reuse. `apyStdev` now reads that shared `sd` — its emitted value is
   byte-identical to before (`round(sd, 2)` gated on `enough`), so no existing KPI output
   changes. Two new fields are added inside the returned `kpis` object:
   - `apyMean = round(mean, 2)` — plain mean, computed at any point count (never null-gated).
   - `apySharpe = round((mean − RISK_FREE_APY) / sd, 2)` when `series.length ≥ 8 && sd > 0`,
     else `null`. The `sd > 0` guard is a division guard: a perfectly flat rate has an
     *undefined* Sharpe, not an infinite one.
3. **Exports**: `RISK_FREE_APY`, `SHARPE_MIN_POINTS` added so the tests can assert them.

`test_compute_kpis.js`
- 5 new tests, existing ones untouched: apyMean at any count (incl. 1 point); apySharpe null
  for <8 points; apySharpe = 0.5 on the textbook `[2,4,4,4,5,5,7,9]` series (mean 5, pop-stdev
  2 → (5−4)/2); apySharpe null on sd=0 with 8 points; exported-constants sanity.

## Deviations from spec
None material. Followed the spec's compute snippet verbatim except for reusing the existing
`sd` (a cleaner, output-identical form of "compute apySharpe from the SAME series as
apyStdev"). Surfaces deliberately deferred per the spec's "one at a time" instruction.

## Trust rails
Byte-untouched. The script still only ADDS a derived field; it never filters, reorders, drops,
or re-weights a pool, and never reads or relaxes `APY_SANITY_LIMIT` / `DEFAULT_MIN_TVL` /
anomaly flags (those are applied upstream by the 059 generator). The 059 churn-trap holds:
`generate-pools-snapshot.js` strips the whole `kpis` object in its freshness compare, so
adding keys inside it cannot trigger a spurious daily rewrite — the existing CHURN-TRAP
regression test still passes.

## Measurement
No isolable Mixpanel funnel metric — this is data-layer infra feeding a future ICP-facing KPI
(088's "steady beats spiky"). Live proof lands on the next `sitemap-update.yml` CI run: each
pool's `kpis` object gains `apyMean` + `apySharpe` (the latter `null` until a pool accrues ≥8
daily history points, ~8 days out). Sharpens automatically when the D1 intraday leg (108–110)
provides denser history.
