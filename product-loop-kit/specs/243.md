## Change

**1. No new implementation — reuse 242's exports.** Add `headlinePoolFor` and `isRepresentativeRate` to the
existing `const { ... } = tp;` destructure at the top of `generate-chain-pages.js` (both already exported by
`generate-token-pages.js` since 242). No local definition, no re-typed literal, no second implementation.

**2. The chain headline becomes one pool's claim — HTML (`renderChainPage`, ~`:169`).**
Replace `const bestApy = Math.max(...rec.pools.map(poolTotalApy));` with:
```js
const headlinePool = headlinePoolFor(rec.pools);
const bestApy = poolTotalApy(headlinePool);
```
and change `buildAnswerAndFaq(rec.chain, rec, bestApy, top, language)` (~`:210`) to
`buildAnswerAndFaq(rec.chain, rec, bestApy, headlinePool, language)`. `top = rec.pools[0]` (~`:178`) is
**untouched** — it still feeds `tcpChainIntro` with its own APY, exactly as 242 left `top`'s equivalent role
on token pages.

**3. The same change — Markdown twin (`renderChainPageMarkdown`, ~`:422`/`:423`/`:428`).** Identical
substitution: `headlinePool = headlinePoolFor(rec.pools)`, `bestApy = poolTotalApy(headlinePool)`,
`buildAnswerAndFaq(rec.chain, rec, bestApy, headlinePool, language)`. `top` stays `rec.pools[0]` if the
markdown file uses it elsewhere (introduction line); verify before editing.

**4. Nothing else moves.** The visible pool table, its TVL order, `rankTopChains`'s page-selection gates, the
`tcpChainIntro` line (which correctly describes `top`/`rec.pools[0]` with **its own** APY), the sitemap, and
every trust rail (`APY_SANITY_LIMIT`, `MIN_POOL_TVL`, anomaly exclusion) are untouched. No page is added,
removed, or de-listed. `token-pages`, `app.js`, translations copy are OUT of scope (no string changes — the
same `tcpAnswer`/`tcpFaqA1`/`tcpChainDescription` accessors receive corrected arguments, same as 242).

## Acceptance criteria

- [ ] **Population invariant (drawn at test time via `rankTopChains(fixturePools, 0)`, never a hardcoded
      instance):** for EVERY chain record, the rendered EN+KO page's headline APY equals
      `poolTotalApy(headlinePoolFor(rec.pools))`, and when at least one pool in `rec.pools` is representative,
      the headline pool is representative.
- [ ] **Attribution invariant, same population:** the project and chain rendered in the direct-answer block
      and FAQ A1 belong to the SAME pool the headline APY came from — asserted on the emitted HTML, every
      record, EN + KO. (Chain pages already name a `project` per pool the same way token pages do — reuse the
      token-page test's assertion shape.)
- [ ] **Twin parity:** for every record, `renderChainPageMarkdown` carries the same headline APY string and
      the same project/chain as `renderChainPage` (use `buildAnswerAndFaq` as the oracle, exactly as 242's
      token-page twin-parity test does).
- [ ] **Positive controls (motivating instances, not the definition):** a fixture chain containing a pool at a
      rate far off its own `apyMean30d` alongside a representative pool → the unrepresentative pool is NOT the
      headline; a chain where ALL pools fail the gate → the highest-APY pool IS the headline (documented
      fallback), attribution still matches it. Reuse 242's POPE-style fixture shape, chain-scoped.
- [ ] **Unchanged-surface proof:** the visible pool table's rows/order, `rec.pools`, the generated chain-page
      set, and the chain sitemap are byte-identical to `main` for the same fixture.
- [ ] **No mirror-proof test needed for THIS item** (unlike 242): `generate-chain-pages.js` is importing an
      existing export, not re-exporting it onward to a third file — there is nothing downstream of it that
      could independently redefine `headlinePoolFor`/`isRepresentativeRate`. If that changes (a future file
      re-exports from `generate-chain-pages.js`), a mirror test becomes required then, not now.
- [ ] **Non-vacuity, each sub-rule neutered separately, byte-identical restore proven (`md5sum` or `git diff`
      empty):** (a) `headlinePoolFor` call reverted to the plain `Math.max` pool on the HTML path → headline
      test red; (b) `buildAnswerAndFaq`'s 4th argument reverted from `headlinePool` to `top` → attribution
      test red; (c) same two mutations on the markdown path → twin-parity test red. Each restored
      byte-identically, then green.
- [ ] **Suite:** `node test_chain_pages.js`, `node test_token_pages.js` (unaffected — proves no cross-surface
      regression), `node test_token_chain_all.js`, `node test_pool_twins.js`, and NORTH_STAR's
      `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` pass.
