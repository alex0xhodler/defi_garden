# Spec 191: 183 fixed WHICH pool-details get audited, not HOW MANY — a 367-day pass over the north-star surface

## Evidence
From this tick's `audit-app.js` run (`generatedAt` 2026-07-31T07:09:44.310Z, 29 surfaces):

```
"poolRotation": { "cycle": 0, "seenCount": 16, "candidateCount": 734, "picked": [...2 ids...], "wrapped": false }
```

- `DEFAULT_POOL_SAMPLE = 2` (`audit-app.js:214`), so the rotation renders **2 pool-detail surfaces per
  tick** against **734 candidates**. One full pass = **367 days**. A given pool-detail defect has a
  **~0.27% chance per day** of being rendered.
- After 3 days of rotation (183 shipped 07-30), `seenCount` is **16/734 = 2.2%**.
- **The cheap prescan is not a substitute.** `poolPrescan` covers all 736 pools every tick, but only for
  five *numeric* signals (`apy-rail-breach`, `mean30d-rail-breach`, `kpi-nonfinite`, `absurd-magnitude`,
  `missing-tvl`). The classes that require a render — `dead-cta`, i18n key leaks, 360px clipping, console
  errors — reach **2 pools a day**. Those render-only classes are exactly what found items **136** (CTA
  clipped at 360px), **137** (`원` stamped on USD) and **182** (the dead "Start Earning" CTA, found on
  `ae6b7add`, a pool the rotation reached by luck).
- `MAX_POOL_SAMPLE = 6` already exists (`audit-app.js:215`) and `AUDIT_POOL_SAMPLE` is already the
  documented override (`audit-app.js:79`, resolved at `:2081`). **The ceiling is built; only the default is
  low.**
- Pool-detail has been the north-star surface since the 2026-07-23 standing decision.

## Hypothesis
We believe **raising the rotation's default render budget on the north-star surface** will **cut the full-pass
time from 367 days to 123** because **the machinery to do it already shipped with 183 and only its default
is conservative.** Confidence: **supported** — the throughput arithmetic is measured, not guessed; what is
*not* claimed is that this closes the gap. Item 167's decision rule asked *"what population is this target
drawn from, and what fraction of it can this selection ever reach?"*. 167 and 183 answered it for target
**selection**; nobody has asked it about target **throughput**. This item asks it and buys a **constant
factor — 3× — not closure.** State that honestly in the PR explainer; do not let a 3× read as a fix.

## Change
Smallest version: **raise `DEFAULT_POOL_SAMPLE` from 2 toward `MAX_POOL_SAMPLE` (6), justified by measured
wall-clock, not by picking the ceiling because it is there.**

The builder must **measure before choosing**: time the current run, time a run at `AUDIT_POOL_SAMPLE=6`,
and pick the largest value whose total runtime stays inside the **5-minute foreground cap** (standing
decision 2026-07-11, "never wait unbounded on background jobs — timebox all test runs"). If 6 does not fit,
ship the largest value that does and **record the measured timings in `specs/191-notes.md`** so the next
person does not re-derive them. If even 3 does not fit, ship nothing and report that — the finding is then
"the render budget is runtime-bound," which is a different and more useful item.

Second, **make the coverage rate legible instead of implicit.** The `poolRotation` block already reports
`seenCount`/`candidateCount`; have the run's console summary also state the implied full-pass time in days
at the current sample size. One line. This is what turns "we rotate now" into "we rotate, and here is what
it does and does not cover" — the same honesty move the prescan's `suspectCount` already makes.

**Explicitly OUT of scope:** any change to which pools are *selected* (183's seeded `sampleBySeed`
rotation and 157/167's prescan-promotion stay exactly as they are); new signals; new surfaces; parallelising
the scanner; touching `DEFAULT_POOL_PRESCAN_MAX`. This item changes a budget and adds a log line. If the
timing measurement suggests an architectural change (parallel contexts, browser reuse), **file it as a
separate item — do not build it here.**

## Measurement
Metric: `poolRotation.seenCount` growth per tick, read from each heartbeat's `audit-findings.json`, and the
scanner's total wall-clock. · Window: 14 days (due **2026-08-14**) · Decision rule: **keep** if `seenCount`
