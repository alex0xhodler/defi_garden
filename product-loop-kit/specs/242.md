# Spec 242: the token page's headline rate must be checked against its own series — and attributed to the pool it came from

## Evidence

**From item 229 (BACKLOG row 242, verbatim numbers):** 229 proved out the predicate "a headline figure may
not be surfaced as a recommendation unless it is checked against that same series' own recent mean"
(`isRepresentativeRate` / `representativenessRatio`, `generate-spotlight.js:128/145`) and enforced it at
**1 of 4** ranked surfaces this repo emits. On live data (15,679 pools, 2026-08-06) it excluded **36 of the
405** rail-qualifying spotlight candidates (**8.9%**) — including `concrete · SRROYUSDC` at 86.51% against a
4.51% 30-day mean (19×) and `veda · LBTCV` at 4.14% against 0.21% (18×). Those pools are excluded from
spotlights and nothing stops them headlining the SEO surfaces, which is where the traffic actually lands.

**Measured for THIS item on live data (15,685 pools, 2026-08-06,** `scratchpad/m2.js`, `rankTopTokens(pools, 0)`
→ the real generated token-page population**):**

| measure | number |
|---|---|
| token pages generated (uncapped) | **2,097** |
| displayed pools across them (`rec.pools`, TVL-sorted, zero-APY filtered) | **3,925** |
| displayed pools failing `isRepresentativeRate` | **975 (24.8%)** |
| displayed pools with no `apyMean30d` at all | **0** |
| pages whose headline `bestApy` comes from a NON-representative pool | **103 (4.9%)** |
| pages where NO displayed pool is representative (fallback case) | **481 (22.9%)** |
| **pages where the headline APY and the protocol named beside it are DIFFERENT POOLS** | **415 (19.8%)** |

Worked instances of the headline defect (`was` = today's rendered headline, `wasMean` = that pool's own
30-day mean, `now` = the highest representative rate on the same page):

- `SUSDAT` — **694.11%** headline, that pool's 30-day mean **240.47%**; highest representative rate 20.08%
- `SKY` — 14.53% headline vs a 36.07% mean; representative 6.82%
- `SUSDE` — 12.39% vs 28.07%; representative 5.48%
- `XAUT` — 17.36% vs 6.32%; representative 6.69%

**The attribution defect, read straight off the code** (found during this item's blindspot pass, not in the
BACKLOG row): `generate-token-pages.js:764` computes `bestApy = Math.max(...rec.pools.map(poolTotalApy))`
(the max-APY pool) while `:766` sets `top = rec.pools[0]` (the TVL-**largest** pool), and `:807` passes
**both** into `buildAnswerAndFaq(rec.symbol, rec, bestApy, top, language)`. That function renders
`tcpAnswer` = *"The highest honest {label} yield right now is {apyStr} on {project} ({chain})"* and
`tcpFaqA1` = *"{apyStr} APY on {project} ({chain})"* — so on the **415 pages (19.8%)** where those are
different pools, the page states a rate and names a protocol that does not pay it. Same lines duplicated in
the markdown twin at `:965/:973`.

**Correction to the BACKLOG row's framing** (RAZOR: no claim more specific than the evidence supports): the
row says token/chain pages "order on current APY". They do **not** — `rankTopTokens` orders `rec.pools` by
**TVL** (`:222`). The unchecked-headline defect on these pages is the `Math.max` **`bestApy`**, which flows
into the meta description (`tcpTokenDescription`), the direct-answer block, the FAQ, and the FAQ ld+json.
That `Math.max` is a stronger instance of the class than a sort would be: it deliberately selects the most
extreme rate on the page, which is exactly the rate most likely to be unrepresentative.

## Hypothesis

We believe deriving the token page's headline claim (rate **and** the protocol/chain named beside it) from a
single pool that has passed 229's `isRepresentativeRate` gate will make the highest-traffic generated surface
state rates it can stand behind, because the ICP is the cautious saver and the page's own copy already
promises *"honest yields ... no anomalous rates"* while 4.9% of pages headline a rate far off its own 30-day
mean and 19.8% attribute their headline to the wrong protocol. Confidence: **supported** — the predicate is
already proven and exported (229), the population is measured, and the change is a selection rule, not new
math.

- **Instance of:** unchecked headline figures on ranked surfaces — the class 229 opened and explicitly left
  open at 1 of 4 surfaces.
- **Class closed by this item: NO.** Closed for token pages (2,097 pages). Left open, with numbers:
  - `generate-chain-pages.js:169` and `:422` — the identical `Math.max` headline + the identical
    `buildAnswerAndFaq(rec.chain, rec, bestApy, top, …)` attribution reuse, on the chain estate.
  - the analytics grid's sort modes (`app.js`) — ranked on current APY, no representativeness check.
  - **481 token pages (22.9%)** where no displayed pool is representative and the headline therefore falls
    back to today's unchecked max (see Change).
  - Ticketed as **item 243** (filed by this item in BACKLOG.md).

## Change

**1. One implementation, no cycle.** Move `REPRESENTATIVE_REL`, `REPRESENTATIVE_ABS_PP`,
`representativenessRatio(pool)` and `isRepresentativeRate(pool)` from `generate-spotlight.js` into
`generate-token-pages.js` (where `poolTotalApy`, their only dependency, already lives and where the repo's
other generators already import shared primitives from). `generate-spotlight.js` imports and **re-exports**
them under the same names, so every existing importer and test keeps working byte-identically.
Direction matters: `generate-spotlight.js` already requires `generate-token-pages.js` (`:48`), so the reverse
require would be a CJS cycle — and `generate-spotlight.js` hard-requires `@napi-rs/canvas` (`:47`), which is
not installed in this checkout, so importing it from a generator would break the SEO pipeline outright.
**Never a re-typed literal, never a second implementation.**

**2. The headline becomes one pool's claim.** Add `headlinePoolFor(pools)` to `generate-token-pages.js`:
among `pools`, return the highest-`poolTotalApy` pool that passes `isRepresentativeRate`; if none passes,
return the highest-`poolTotalApy` pool (today's behaviour, unchecked — the 481-page fallback). Both
`renderTokenPage` (`:764/:807`) and `renderTokenPageMarkdown` (`:965/:973`) derive `bestApy` **and** the pool
passed to `buildAnswerAndFaq` from this one call, so the rate and the protocol/chain named beside it always
come from the same pool. The HTML page and its markdown twin must call it identically — the twin's
"can never drift by construction" contract (`:415` comment) is preserved.

**3. Nothing else moves.** The visible pool table, its TVL order, `rankTopTokens`'s page-selection gates, the
`tcpTokenIntro` line (which correctly describes `rec.pools[0]`, the TVL-largest pool, with **its own** APY),
`yieldHeadlineFor`'s blended-rate line, the sitemap, and every trust rail (`APY_SANITY_LIMIT`,
`MIN_POOL_TVL`, anomaly exclusion) are untouched. No page is added, removed, or de-listed.

**OUT of scope:** chain pages, the analytics grid, `app.js`, translations copy (no string changes — the same
`tcpAnswer`/`tcpFaqA1`/`tcpTokenDescription` accessors receive corrected arguments), the value of
`REPRESENTATIVE_REL`, and any new user-facing wording about representativeness.

## Acceptance criteria

- [ ] **Population invariant (drawn at test time, never a hardcoded instance):** for EVERY record returned by
      `rankTopTokens(fixturePools, 0)`, the rendered EN page's headline APY equals
      `poolTotalApy(headlinePoolFor(rec.pools))`, and when at least one pool in `rec.pools` is representative
      that pool is representative.
- [ ] **Attribution invariant, same population:** the project and chain rendered in the direct-answer block
      and in FAQ A1 belong to the SAME pool the headline APY came from — asserted on the emitted HTML, for
      every record, EN and KO.
- [ ] **Twin parity:** for every record, `renderTokenPageMarkdown` carries the same headline APY string and
      the same project/chain as `renderTokenPage`.
- [ ] **Positive controls (motivating instances, not the definition):** a fixture record containing a pool at
      694.11% with `apyMean30d` 240.47% alongside a representative pool → the unrepresentative pool is NOT the
      headline; a record where ALL pools fail the gate → the highest-APY pool IS the headline (documented
      fallback), and the attribution still matches it.
- [ ] **Unchanged-surface proof:** the visible pool table's rows and order, `rec.pools`, the generated page
      set, and the token sitemap are byte-identical to `main` for the same fixture.
- [ ] **Mirror proof (RAZOR guard rule):** a test asserts `generate-spotlight.js`'s exported
      `isRepresentativeRate`/`representativenessRatio`/`REPRESENTATIVE_REL`/`REPRESENTATIVE_ABS_PP` are the
      **same function/value objects** as `generate-token-pages.js`'s — set-equality in both directions, so the
      two surfaces can never drift into two implementations.
- [ ] **Non-vacuity, each sub-rule neutered separately:** (a) make `headlinePoolFor` return the plain
      `Math.max` pool → headline test red; (b) revert the attribution to `rec.pools[0]` → attribution test
      red; (c) break the re-export identity → mirror test red. Each restored byte-identically (`git stash` /
      `md5sum` proof recorded in the notes), then green.
- [ ] **Suite:** `node test_token_pages.js`, `node test_chain_pages.js`, `node test_spotlight.js`,
      `node test_spotlight_packs.js`, `node test_token_chain_all.js`, `node test_pool_twins.js` and
      NORTH_STAR's `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` pass.

## Open questions

None that change the architecture. The fallback for the 481 all-unrepresentative pages (keep today's

nothing, that is a later one-line change on top of `headlinePoolFor`.

## Territory notes

- `generate-spotlight.js:47` hard-requires `@napi-rs/canvas`, which is **not installed** in this checkout
  (`node_modules/@napi-rs` absent though it is a declared dependency) — any generator that imports the
  spotlight module would crash the SEO pipeline. This, plus the existing `spotlight → token-pages` require at
  `:48`, is why the predicate moves INTO `generate-token-pages.js` rather than being imported from spotlight.
- `rec.pools` is already `displayPools`: TVL-sorted, `0.00%`-APY rows filtered, capped at `POOLS_PER_PAGE`
  (`:235-250`). The headline is therefore chosen only from pools the page actually displays — no pool the
  reader cannot see can become the headline, before or after this change.
- Every displayed pool has an `apyMean30d` (0 of 3,925 missing), so the gate's null branch ("no evidence of
  representativeness is not evidence of representativeness") is inert on this surface today. It is kept
  anyway — the population churns daily and the null branch is the honest default.
- `generate-chain-pages.js` imports `buildAnswerAndFaq` from `generate-token-pages.js` (`:47`) and repeats the
  same `Math.max`/`rec.pools[0]` pair at `:169/:210` and `:422/:428`. Leaving it untouched is deliberate
  scope (one surface per the BACKLOG row) and is what item 243 carries.
