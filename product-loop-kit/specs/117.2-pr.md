# 117.2 — analytics "risk-adjusted (Sharpe)" sort · HIGH-tier explainer

**Item:** 117.2 · **Verifier:** PASS, HIGH, 8/8 (mutation-killed) · **Ship:** one commit on the

## Goal
Give the cautious-saver ICP a way to rank the analytics grid by *steadiness of yield* rather than
raw APY or size — a new "Risk-adjusted" sort backed by the 117 compute leg's `kpis.apySharpe` — on
the token/chain SEO-conversion surface, WITHOUT letting any anomalous pool jump the queue and without
changing behavior until real history accrues.

## Intuition
`apySharpe = (apyMean − 4.0 risk-free) / apyStdev` (117): high when a pool pays well *and* holds its
rate steady, low/undefined when erratic. Sorting by it surfaces steadier yields first. But steadiness
must never override the trust rail: an anomalous pool (APY > 1000%) with a flukey-high Sharpe must
still be demoted below every sane pool, exactly as it is under the APY and TVL sorts. And because the
Sharpe field is `null` until a pool has ≥8 daily history points (~2026-07-22), the sort is a graceful
no-op today — the grid order is unchanged from the default until the data lights it up.

## What changed and why
1. **Three sort comparators in `app.js`** (token-first-inner ~L1823, chain-first ~L1910, token-first
   ~L2010) each get an identical `if (sortBy === 'sharpe')` branch inserted as the FIRST condition —
   so the existing `tvl`/`apy` branches are byte-untouched. The branch:
   - demotes anomalous pools (`apy > APY_SANITY_LIMIT`) below ALL sane pools (the load-bearing trust
     rail — unconditional here, a deliberate strengthening vs the `apy` branch's `!userSortedApy` gate,
     so a high-Sharpe anomaly can never surface);
   - within the sane group: numeric `kpis.apySharpe` DESC;
   - null-Sharpe pools last (numeric before null);
   - tie-break TVL DESC (the existing default) → all-null data (current prod) = order unchanged.
2. **One button in the `.sort-control`** (`app.js` ~L3179) after TVL, reusing
   `view-toggle-btn sort-toggle-btn` (ZERO new CSS), `setSortBy('sharpe'); setUserSortedApy(false)`,
   label `t('sortByRiskAdjusted')`.
3. **`translations.js`** — `sortByRiskAdjusted`: EN `"Risk-adjusted"`, KO `"위험 조정"` (together).
4. **Regenerated assets** — `node compile-app.js && node minify-assets.js` → `app.compiled.js`,
   `app.compiled.min.js`, `translations.min.js` (idempotent; other compiled/min files byte-unchanged).
5. **`package.json`** — `node test_kpi_sharpe_sort.js` wired into the npm chain after
   `test_default_sort.js`.
