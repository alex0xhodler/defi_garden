# Spec 060: X-spotlight pack generator

## Evidence
- NORTH_STAR.md standing decision 2026-07-12 (distribution channel, human interview Q1): X/Twitter protocol spotlights — posts spotlight a pool's yield + an example garden built on it, tagging the protocol; start with SMALL protocols keen to collaborate, Curve = upper bound; human produces each video from a reusable Canva template; loops build the per-spotlight data/copy/asset pack (live numbers through trust rails, a working example-garden share URL, tweet draft, template field values, share-card PNG); Canva template + posting stay human-owned.
- BACKLOG.md row 060 (score 9.0, READY, next-highest item): "given a pool id (or auto-picked candidates biased to SMALL collaboration-keen protocols, Curve = upper bound, through the full trust rails), emit a per-pool spotlight pack — live numbers, a WORKING example-garden share URL that rebuilds the garden on open (024's artifact), a tweet draft tagging the protocol, Canva-template field values, share-card PNG."
- Item 024 (SHIPPED, PR #116) built the plan-share URL round trip (`encodePlanToUrl`/`decodePlanFromUrl`, `planner.js:856-894`) — but code archaeology for this spec (territory notes below) found it encodes `goal/monthly/years/pace/capital/fm/dl` only. It does NOT encode `chain`/`token`, even though `poolFiltersState` (`planner.js:1239`) and `curatePools(pools, persona, limit, {chain, token})` (`planner.js:544-573`) already support chain/token filtering — the UI can filter to a chain/token, but a share link can't carry that filter. Without fixing this, a "working example-garden share URL" for a specific spotlighted pool/protocol is not achievable: a fresh open of any existing share link ignores chain/token entirely and just re-curates top-3 by persona.

## Hypothesis
We believe (a) closing the chain/token gap in the share-URL round trip, plus (b) a `generate-spotlight.js` pack generator that reuses the same trust rails, curation, and share-URL/share-card machinery already proven by 020/024/027, will let the human ship one X spotlight per week without any further engineering — each post carries a genuine, working, filter-pinned garden link. Confidence: supported (024/027 already validated the underlying share mechanics end to end; this closes a real, code-confirmed gap rather than guessing at one).

## Change
**In scope:**
1. `planner.js` — extend the *existing* share-URL round trip additively (no behavior change for URLs that omit the new params):
   - `encodePlanToUrl(goal, monthly, years, persona, capital, fundingMode, deadline, poolFilters)` — 8th optional param `{chain, token}`; sets `chain`/`token` query params when present, deletes them otherwise.
   - `decodePlanFromUrl` — reads `chain`/`token` params, includes them in its returned object (`null` when absent — no change to the existing null-goal/null-pace early-return contract).
   - `restart()`'s URL-param cleanup list (`planner.js` ~3540) — add `'chain'`, `'token'`.
   - `poolFiltersState` initial value (`planner.js:1239`) — seed from `sharedPlan.chain`/`sharedPlan.token` when a shared plan was decoded, same pattern already used for `ansState` a few lines below.
   - The three `encodePlanToUrl(...)` call sites (`doShareImage`/`doCopyLink`/`doNativeShare`, ~`planner.js:1779/1808/1831`) — pass `props.poolFilters` through as the 8th arg so a user's own share link also preserves their chain/token filter (this is a natural side benefit, not just spotlight-only plumbing).
2. New `generate-spotlight.js` (Node, follows `generate-token-pages.js`/`generate-og-images.js` conventions):
   - Fetch `https://yields.llama.fi/pools` (or `--fixture <path>` / `POOLS_FIXTURE` env, same flag convention as the other generators).
   - Trust rails: reuse `poolTotalApy`, `isAnomalousApy`, `formatUsd`, `formatApy` from `generate-token-pages.js` (already exported, already a Node module). Apply the APP's TVL floor, not the SEO generator's relaxed one — a spotlighted pool feeds a real example garden, so it must clear `DEFAULT_MIN_TVL = 10000000` (mirrors `app.js:730`/`planner.js`), defined locally per the established "each generator keeps its own synced copy" convention (see `generate-token-pages.js:44-56` comment block).
   - Small-protocol classification: aggregate `tvlUsd` per `project` across all trust-rail-qualifying pools; compute Curve's own aggregate as the ceiling; a protocol qualifies as "small" only if its aggregate TVL is `<=` Curve's (Curve itself excluded — it is the ceiling, not a candidate). This is a wholly new concept (grep-confirmed nothing like it exists yet) — keep it to this one pure function so it's easy to verify and re-tune.
   - Pool selection: `--pool <id>` picks a specific pool (validated against trust rails + the small-protocol ceiling; if it fails either, exit non-zero with a clear message — never emit a pack for a rail-failing or oversized-protocol pool). With no `--pool`, auto-pick the highest-APY trust-rail-qualifying pool belonging to a small-enough protocol.
   - Goal/persona for the example garden: default goal `claude` (subscription archetype — ties the spotlight to the product's own north-star funnel; the human can pass `--goal <id>` to use any `GOALS` entry mirrored locally from `planner.js`'s subscription list). Persona chosen by a simple, mirrored version of the `PERSONAS` bands (`planner.js:500-515`): stable-symbol + within the stable band's APY ceiling → `stable`; else within the `rwa` band's 20% ceiling → `rwa`; else `degen`. `monthly` = the goal's `target` (its listed subscription cost).
   - Share URL: build `https://www.defi.garden/plan.html?goal=<goal>&monthly=<target>&pace=<persona>&chain=<chain>&token=<token>` with the same param semantics as `encodePlanToUrl` (mirrors it in Node — `plan.html` runs browser-only code, so this is a small parallel builder, not a `require`).
   - Tweet draft: a short template referencing the protocol name, pool symbol/chain, live APY/TVL (through `formatApy`/`formatUsd`), the goal's subscription framing ("→ funds a $20/mo Claude Pro sub"), and the share URL. No fabricated protocol X-handle — the pack leaves an explicit `@<project>` placeholder the human confirms/edits, documented in the pack's own notes field.
   - Canva field values: a flat, named-field JSON object (protocol name, pool symbol, chain, APY, TVL, goal label, share URL, tweet draft) the human maps into the reusable Canva template.
   - Share-card PNG: new `renderSpotlightCard()` using `@napi-rs/canvas`, same technique as `generate-og-images.js`'s `renderOgCard` (reuses its exported `COLORS`) — protocol/pool label, live APY, TVL, subscription framing, `defi.garden` footer. No bundled brand-logo rendering (`brand-icons.js` is a `window`-attached IIFE, not Node-requireable, and re-implementing a Node-side logo loader is out of scope for this pass) — text-only card, matching `renderOgCard`'s existing precedent of a plain vector mark instead of a logo/emoji glyph.
   - Output: `spotlights/<slug>/pack.json` (all of the above) + `spotlights/<slug>/card.png`, `slug` built with the same slugify approach as `tokenSlug` (`generate-token-pages.js:108`) from `project-symbol-chain`. Committed output, same convention as `tokens/`/`chains/`/`og/`.
3. `package.json` — add `"spotlight": "node generate-spotlight.js"` script.
4. Tests — `test_spotlight.js`: fixture-driven (2-3 pools: one anomalous/oversized-protocol pool that must never be selected, one small-protocol qualifying pool) asserting pack.json shape, trust-rail exclusion, share-URL param correctness, and non-empty PNG output. Add to `package.json`'s `test` chain. Because this item also changes rendered product behavior (a `chain`/`token`-bearing share link must actually curate to that filter on open), a Playwright check following the `test_search.js` fixture-routing pattern (probes real hosts, falls back to a local fixture where the sandbox blocks them, logs which mode ran) drives `plan.html?goal=claude&monthly=20&pace=stable&chain=<X>&token=<Y>` in a real headless browser and asserts the rendered bloom step shows a pool matching the chain/token filter — not just the parser/encoder in isolation (2026-07-11 standing decision: UX acceptance means rendered behavior, not fixtures alone).

**Out of scope:**
- Any change to `?chain=`/`?token=` on `home.html`'s analytics-app URLs (those are the sacred sitemap surface — untouched; this spec only touches `plan.html`'s own, separate, non-sitemap param scheme).
- Bundled brand-logo rendering in the Node-side card (text-only card for this pass).
- Auto-posting to X, or any Canva integration — pack output is consumed by the human.
- Any change to which pools/protocols DefiLlama tracks, or to the trust-rail thresholds themselves.

## Acceptance criteria
- [ ] `encodePlanToUrl`/`decodePlanFromUrl` round-trip `chain`/`token` when present; existing URLs without them decode exactly as before (no regression to 024's shipped behavior).
- [ ] `node generate-spotlight.js --fixture <path>` produces `spotlights/<slug>/pack.json` + `spotlights/<slug>/card.png` for a valid small-protocol pool, and produces neither for an anomalous-APY or oversized-protocol (Curve-or-bigger) candidate.
- [ ] `pack.json` contains: protocol/pool identity, live APY/TVL (through `formatApy`/`formatUsd`), the goal/persona used, a `shareUrl` whose query string, when parsed, matches what `decodePlanFromUrl` expects (`goal`, `monthly`, `pace`, `chain`, `token`), a tweet draft, and a flat Canva-field object.
- [ ] `card.png` is a valid non-empty PNG at 1200x630.
- [ ] Playwright: opening the generated `shareUrl` against the real rendered planner UI shows a curated pool matching the pack's chain/token (or, if the sandbox's yields.llama.fi access is unavailable to the browser at test time, the same fixture-routing fallback `test_search.js` uses, with the fallback path clearly logged).
- [ ] `npm run spotlight` exists and runs the generator; `npm test` includes `test_spotlight.js`.
- [ ] No trust rail weakened: `APY_SANITY_LIMIT`/`DEFAULT_MIN_TVL` values unchanged, anomalous pools never enter a pack.
- [ ] EN/KO not applicable (generator output/CLI only, no user-facing translated strings added) — confirm no new hardcoded UI strings were added.

None that change the architecture — the chain/token gap was a discoverable code fact (confirmed via `curatePools`'s existing `opts.chain`/`opts.token` support never being wired to the URL), not an ambiguous product decision, and the smallest fix (extend the existing additive param pattern) is the same shape 024 already established.

## Territory notes
- `encodePlanToUrl`/`decodePlanFromUrl` (`planner.js:856-894`) currently: `goal`, `monthly`|`capital`+`fm`, `years`, `dl`, `pace`. No `chain`/`token`. `poolFiltersState = useState({chain:null, token:null})` (`planner.js:1239`) is never seeded from a decoded shared plan — confirmed via the `ansState` initializer (`planner.js:~3506`) which DOES seed from `sharedPlan`, `poolFiltersState`'s initializer does not.
- `curatePools(pools, personaKey, limit, opts)` (`planner.js:544`) already accepts `opts.chain`/`opts.token` (lower-cased exact chain match, substring token match) applied AFTER trust rails — safe to drive from a URL param, rails can't be bypassed by it.
- Share-card canvas (027, `renderShareImage`, `planner.js:2820`) is browser/DOM-only (`document.createElement('canvas')`, `window.BRAND_ICONS`) — not reusable from Node. `generate-og-images.js`'s `renderOgCard` (headless `@napi-rs/canvas`, already a `package.json` dependency) is the correct, already-proven Node-side pattern to mirror instead.
- `brand-icons.js` attaches `BRAND_ICONS` to `window` via an IIFE — not `require`-able as-is; out of scope to convert it this pass (text-only card instead, matching `renderOgCard`'s own precedent).
- `generate-token-pages.js` exports `poolTotalApy`, `isAnomalousApy`, `isQualifyingPool`, `formatUsd`, `formatApy`, `APY_SANITY_LIMIT`, `MIN_POOL_TVL` — but its `MIN_POOL_TVL` ($100K) is a deliberately relaxed SEO-surface floor (per its own header comment), NOT the app's $10M plan-entry floor. This spec must define its own `DEFAULT_MIN_TVL = 10000000` locally (matching `app.js:730`) rather than importing `MIN_POOL_TVL`, since a spotlight pack feeds a real example garden (plan-entry semantics), not an SEO listing.
- No existing "protocol size" concept anywhere in the repo (grep-confirmed) — the Curve-ceiling aggregate-TVL-per-project classifier is new and should stay a small, isolated, easily-adjusted function.
- Playwright in this sandbox: browser-originated HTTPS to `yields.llama.fi`/`unpkg.com` is blocked at the proxy connection level even though Node/curl reach it directly (NORTH_STAR.md 2026-07-12 standing decision) — `test_search.js`'s host-probe-then-fixture-fallback pattern is the established, correct way to write a live-UI Playwright check here.
