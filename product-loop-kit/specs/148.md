# Spec 148: Stop minting nonsense token pages from Pendle expiry-date fragments

## Evidence
All verbatim from the 2026-07-26 heartbeat (`signals/2026-07-26.md`).

Root cause, two lines in `generate-token-pages.js`:
- line 87 — `tokenSymbols(pool)` returns `String(pool.symbol).split(/[-_\/\s]/)`, so a Pendle principal token named `PT-SUSDE-22OCT2026` contributes three "tokens": `PT`, `SUSDE`, **`22OCT2026`**.
- line 71 — `const TOKEN_REGEX = /^[A-Z0-9][A-Z0-9.\-_]{1,14}$/i;` accepts pure-digit strings and date-shaped strings, so the expiry fragment passes `isValidToken()` and earns a page.

Derived from the live committed snapshot (`data/pools-snapshot.json`, `generatedAt` 2026-07-26T07:00:43Z, 738 pools), applying the generator's own eligibility rules, **8 date-fragment tokens qualify today**:

| token | example source symbol | qualifying pools |
|-------|----------------------|------------------|
| 22OCT2026 | PT-SUSDE-22OCT2026 | 2 |
| 10DEC2026 | PT-REUSD-10DEC2026 | 1 |
| 18JUN2026 | PT-SUSDE-18JUN2026 | 1 |
| 16SEP26 | PT-USX-16SEP26 | 1 |
| 8OCT2026 | PT-AUSD-8OCT2026 | 1 |

| 24SEP2026 | PT-KHYPE-24SEP2026 | 1 |
| 27AUG2026 | PT-SUSDD-27AUG2026 | 1 |

**7 junk slugs are live on the committed surface right now**, each with a `<loc>` in `sitemap-token-pages.xml` (verified by grep):
`/tokens/8oct2026` · `/tokens/17dec2026` · `/tokens/2027` · `/tokens/20261231` · `/tokens/00` · `/tokens/01` · `/tokens/67`

Each one ships **twice** (EN + KO — `ko/tokens/8oct2026.html` confirmed present), carries a generated **OG image** (`og/tokens/8oct2026.png`, `og/tokens/2027.png`), and is submitted to **IndexNow** on every regen.

Rendered content, verbatim from `tokens/8oct2026.html`:
- `<title>8OCT2026 DeFi Yields — Live Pools by TVL | DeFi Garden 🌱</title>`
- `<h1>8OCT2026 DeFi Yields</h1>`
- description: *"4 live 8OCT2026 pools above the $100K TVL floor, up to 0.20% APY, across 1 chain. Honest yields from DefiLlama data — no anomalous rates."*

**Prod crawl evidence** (Mixpanel `becb8e74`, 7d, prod filter): `https://www.defi.garden/?poolTypes=Lending&token=22OCT2026` recorded a real `page_view`. Also observed in the same read: `?poolTypes=Yield+Farming&token=20` and `?chain=Berachain&token=20%29`. Crawlers are already walking this class — these URLs were previously assumed crawler-invented; they are ours.

Scale: ~7–16 of 2,089 token pages (<1%), and the set **churns daily** as expiries roll in and out of the TVL-qualifying window.

## Hypothesis
We believe rejecting date-fragment and pure-numeric strings in `isValidToken()` will improve the generated surface's quality signal — because a page titled "8OCT2026 DeFi Yields" matches no real search intent, is thin by construction, and dilutes a surface that item 010 diagnosed as already under a GSC indexing cloud. Confidence: **supported** for "these pages are nonsense" (root-caused, reproducible, rendered evidence above); **guess** for the size of any indexing benefit (unmeasurable in-loop — GSC is human-read through ~08-23).

This is the same class as **013 (sitemap quality threshold, SHIPPED + DONE)**, which gated URLs on pool count and TVL but never on *"is this string actually a token"*.

## Change
Smallest version: tighten the shared token-validity predicate so junk never gets minted, and let the daily CI regen drop the pages that already exist.

1. In `generate-token-pages.js`, extend `isValidToken()` (keep `TOKEN_REGEX` as the first gate) with rejection rules:
   - reject pure-numeric strings (`/^[0-9]+$/`) — kills `00`, `01`, `67`, `2027`, `20261231`
   - reject date-shaped strings (`/^[0-9]{1,2}(JAN|FEB|MAR|APR|MAY|JUN|JUL|AUG|SEP|OCT|NOV|DEC)[0-9]{2,4}$/i`) — kills the eight expiry fragments
2. Mirror the identical rule in `generate-sitemap.js`'s `isValidToken` — the line-70 comment in `generate-token-pages.js` says the two are mirrors; they must not drift.
3. Regenerate via the sanctioned scripts only (`npm run tokens && npm run sitemap && npm run generate:llms`) and commit the regenerated output. Delete the now-orphaned `tokens/*.html`, `ko/tokens/*.html` and `og/tokens/*.png` files for the dropped slugs so no unreferenced page is left serving.

**Explicitly OUT of scope:**
- The `PT` token page itself (`/tokens/pt` exists, title "PT DeFi Yields"). `PT` is a Pendle structural prefix, not an asset — but it is arguably a real search term. This is bug-class 8 (honest labels — *flag, don't auto-fix*). Leave it; it is a question for the human, not a build decision.
- Any change to `MIN_POOL_TVL`, `MIN_QUALIFYING_POOLS`, `APY_SANITY_LIMIT` or any other trust rail. This item changes *which strings count as a token*, nothing about which pools qualify.
- Redirects / 410s / GSC removal requests for the dropped URLs. Out of scope; the pages simply stop being generated and stop being listed.
- Any change to `?token=` app behavior. A user typing `?token=8OCT2026` still gets whatever the app honestly returns — only the *generated static surface* changes.

Decision rule: keep if the next two heartbeat ticks find 0 date-fragment/pure-numeric slugs in a freshly CI-regenerated sitemap; revert-candidate if any real ticker is found missing from the surface.
Indexing effect on GSC: **explicitly not claimed in-loop** — GSC is human-read through ~08-23 (standing decision 2026-07-12). Per the 048 takeaway, close this on functional verification, not on an indexing number.

## Risk tier (builder's guess — verifier assigns independently)
**HIGH.** Two reasons, and the verifier should agree on both:
1. It touches generated SEO surface (`sitemap-*.xml`, `tokens/`, `ko/tokens/`, `og/`) — NORTH_STAR risk policy lists hand-edits to that surface as HIGH. This change goes *through* the `generate-*.js` scripts as required, but the blast radius is the same files.
2. It **removes URLs from the SEO surface**. NORTH_STAR's NEVER list includes "deleting or de-indexing SEO surface". The operator's read is that this is *completing* 013's already-shipped, human-sanctioned quality-threshold mandate rather than a new de-indexing decision, and that 7 nonsense URLs out of 2,089 is not the lifeline the rule protects — **but that read is flagged to the human in the 2026-07-26 report as a question.** If the human says otherwise, this item becomes BLOCKED, not built.

A regex that is too greedy silently deletes real token pages — that is the failure mode to guard, hence the explicit positive list and the exact-count criterion.

## Territory notes
<!-- Build loop appends findings from the blindspot pass here. -->
- The junk set is **data-dependent and churns daily**. The 7 slugs listed above are what is committed today; a regen on a different day will surface a different subset (today's live snapshot yields 8 date fragments, only 2 of which are in the committed `tokens/` dir). Do not hardcode the list — assert on the *predicate*, and treat the named slugs as examples.
- `tokenSlug()` (line 113) lowercases and collapses non-alphanumerics, so `8OCT2026` → `8oct2026`. The validity gate must run on the **symbol**, before slugging, or the numeric-rejection rule will also catch legitimate slugs that merely start with a digit.
- `20aaveprimeweth` and `20weth` appear in the committed `tokens/` dir but are NOT reproducible from today's snapshot; they look like `%20`-encoding residue from an older dataset. Do not build a rule specifically for them — the two rules above are what today's data justifies. Note in the notes file whether the regen clears them.
