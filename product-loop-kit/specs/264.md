# Spec 264: widen the pool-card numeral guard from neighbour overlap to section containment

Impact: test guardrail — every rendered pool-card numeral must remain inside its owning section

## Evidence

PR #429's threshold sweep showed the merged guard only checks neighbour intersection. A `nowrap`
numeral can therefore leave its own layout section without touching another text leaf and still score
clean. The same unbounded-numeral class caused items 246 and 260; item 274 later demonstrated the
card-edge form of the escape.

## Hypothesis

The existing DOM-derived scan already identifies every rendered `.pool-apy-hero`,
`.pool-apy-preview`, `.pool-apy-tag`, and `.tvl-value`, but check E compares those boxes only with
neighbours. Comparing each numeral border box with the content box of its closest owning
`.pool-apy-section` or `.pool-tvl-section` closes the narrower predicate without changing product
layout.

## Change

Extend `test_card_numeral_wrap.js` only. For every numeral already included by the class scan:

- derive its owning section from the rendered DOM;
- fail if no owning section exists;
- compute the section content box from its border box minus computed border and padding;
- require the numeral border box to be contained on all four edges, with the existing one-pixel
  rendering tolerance;
- retain all neighbour-intersection, self-overflow, nowrap, one-line, and population checks;
- add a rendered positive control that moves one numeral outside its section and proves the widened
  predicate detects it.

No product CSS or rendering change.

## Acceptance criteria

- [ ] The rendered positive control is RED before the containment predicate and GREEN after it.
- [ ] Across list/grid, light/dark, and 360/768/1280/1540 viewports, every rendered numeral class the
  existing scan discovers is contained by its own section content box.
- [ ] Existing neighbour-intersection checks remain active.
- [ ] Existing per-class non-vacuity coverage remains active for all four numeral classes.
- [ ] The full `test_card_numeral_wrap.js` behavior gate passes without product-code changes.

## Measurement

Build-leg only. Keep if the widened check remains green on the next two audit ticks over the same
DOM-derived population.

## Risk tier

LOW — test-only predicate widening; no product render path.
