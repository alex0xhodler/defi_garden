# 257 — PR explainer (LOW tier, short form)

## Goal

The north star's leg B is *pool-detail conversion clicks ÷ pool-detail views*. Its denominator was lossy:
`app.js` has three ways into the pool-detail render, and only two of them reported the view.

## What was wrong

`handleCalculateYield` — the grid card's "calculate yield" button — did `setDetailPool` +
`setCurrentView('pool-detail')` + `scrollTo(0,0)`, a full pool-detail render, and emitted only a
`pool_click`. No `pool_view`. Measured in prod on 2026-08-09: `pool_click` 1, `pool_view` 0 — a pool-detail
page rendered and no instrument recorded it. Structurally, a `garden_cta` click from a calculator-entered
page enters the north-star numerator with no matching denominator event, so the CTR was not bounded by 1.

`NORTH_STAR.md` line 37 claimed `pool_view` "fires exactly once per pool-detail render (verified for both
current paths)" — accurate about what it verified, narrower than the class it guarded.

## What changed

1. **`app.js`, +16 lines, additive only.** `handleCalculateYield` now emits
   `Analytics.trackPoolView(pool, {source: 'yield_calculator', …})`, and sets `urlDirectPoolViewFiredRef`
   first — the same anti-double-fire mechanism `handlePoolClick` already uses. The `url_direct` and
   `card_click` payloads are untouched (0 deletions, 0 modifications in the diff), so saved Mixpanel reports
   keep working.
2. **`test_pool_view_coverage.js`** (new, plain lane) — the gate that keeps the denominator complete. It
   derives both the transition-site set and the emit-site set from `app.js` at test time and asserts
   set-equality in both directions, so a fourth entry path added tomorrow fails it.
3. **`test_pool_view_calculator_fires.js`** (new, browser lane) — real Chromium clicks
   `.calculate-yield-btn-new` and asserts one `pool_view` and one `pool_click`, both with
   `source: yield_calculator` and full segmentation props, observed at the `Analytics.track` delivered
   boundary rather than at the helper.
4. `package.json` `test:serial` registers both; `app.compiled.*` regenerated (`home.html` boots the compiled
   bundle, not raw `app.js`).

## The part worth reading — the gate took three attempts and two verifier FAILs

The product change was right the first time. The **gate** was wrong twice, the same way each time: it
watched something that RESEMBLED the mechanism instead of the mechanism itself — RAZOR worked example 5,
committed inside the very item whose test file cites that example.

- **Attempt 1** covered a transition if a setter's variable name appeared anywhere in an emitting function.
  The verifier broke it with a real setter (`setSelectedChain`) whose variable happens to sit near an emit.
- **Attempt 2** hardened that rule into a three-part mechanism check but left the other rule as plain
  "the emit call is in the same function". The verifier put a transition inside an early-return guard with
  the emit later in the same function and made the **entire suite green** on a real gap.
- **Attempt 3** gave that rule a dominance check (the emit must precede the transition *and* sit in the same
  or an enclosing block, never a sibling branch), plus a positive control proving the rule doesn't just
  reject everything.

The gate went 7 → 14 → 18 assertions, and **every raise came from a verifier finding, not from volunteered
coverage.** All of the verifier's mutations are now permanent assertions, so those three holes cannot
silently reopen.

## What this does NOT close (stated with numbers)

- `grep -c "setCurrentView(" app.js` → **8** sites: 3 `'pool-detail'` (now gated), 5 `'search'` (ungated).
  The gate covers 37.5% of view transitions in `app.js`; the planner's own transitions in `planner.js` are
  outside it entirely. Not ticketed here.
- The gate's residual boundary is enumerated in `257-notes.md` as *what has been adversarially tested*, not
  as *what exists* — ternaries and `&&`/`||`, `switch` fallthrough, loops, `try/finally`,
  expression-bodied callbacks and identifier shadowing can still slip through. None of those shapes exist in
  `app.js` today. One fail-loud scanner gap (duplicate setter name in another scope) is named too.
- The historical `pool_view` series is a lower bound of unknown tightness. One prod render is confirmed
  missed. Nothing was retroactively corrected.
