# Spec 239: no-yield rows rank after yield-bearing rows in the default view

## Evidence
UX audit F4, the human's own prod screenshot of "Popular DeFi Yields" (default view, RISK-ADJUSTED
sort): 3 of the 9 visible rows are `0%` "No supply yield" — WSTETH/sparklend ($2.4B), CBBTC/morpho-blue
($2.4B), WEETH/aave-v3 ($2.3B) — ranked ABOVE yield-bearing pools. Playbook bug-class 2 (dead-end as
primary content) expressed as ranking: the flagship list of a yield-finder leads with rows that yield
nothing.

## Hypothesis
Demoting no-displayable-yield rows below yield-bearing rows (stable order within each group, every sort
mode of the default view) removes the "this site is broken" read without hiding legitimate TVL-browsing
content. Confidence: supported (ICP = cautious saver; honest numbers beat exciting numbers — and beat
confusing ones).
- Instance of: default-view content-honesty (032/033's "0.00% under a yields heading" class, ranking
  variant).
- Class closed: default grid yes; token/chain static pages already carry their own 032/033 gates —
  verify one sample each in notes, count any residual.

## Change
`app.js` ranking for the default (Popular) view: partition on "has displayable supply yield"
(`formatApy` output ≠ the zero form — reuse the 032 predicate, never a re-typed literal), yield-bearing
first, each partition keeping the active sort (APY/TVL/risk-adjusted) internally. Rows stay listed,
labeled "No supply yield" as today; no pool removed, no floor/limit touched (NOT a trust-rail change).
OUT of scope: the risk-adjusted formula itself; filters; static pages.

## Acceptance criteria
- [ ] Rendered default view (house fixture with a mixed population incl. ≥3 zero-yield + ≥6 yielding
      pools): every zero-yield row's index > every yielding row's index, under EACH sort toggle
      (APY/TVL/risk-adjusted) — population drawn from the fixture at test time.
- [ ] Zero-yield rows still render (count preserved vs input) with the honest label — nothing filtered.
- [ ] Explicit user filters (e.g. `?minApy=0`, token/chain views) behavior unchanged — the demotion is
      the DEFAULT view's rule only; test asserts a `?token=` view is byte-order-unchanged vs before.

- [ ] `pool_view`/`pool_click` instrumentation untouched (payload snapshot test).
