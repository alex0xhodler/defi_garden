# 056 — Self-host React (react/react-dom), drop the unpkg 3rd-party critical dependency

**Risk tier: HIGH** (per NORTH_STAR.md: `home.html` is the sacred IA router; this changes the render-critical script-loading source on every page). Verifier PASS, 7/7 criteria, independently re-derived. Auto-merged per standing decision 2026-07-10 (verifier PASS + tests green → merge, any tier, human reviews after the fact).

## Goal
Cut the last third-party CDN dependency (`unpkg.com`) out of the app's critical rendering path. `reports/2026-07-12-pagespeed.md` flagged this as finding 5 of the PageSpeed audit: React/Babel loaded from unpkg means no cache control and an extra DNS/TLS round trip on every single page view — planner (`/`) and every analytics/SEO page (`?token=`, `?chain=`, `?pool=`) alike. 052 already removed the Babel half of that dependency (in-browser transpile); this item removes the React half.

## Intuition
`home.html` and `plan.html` were loading React/ReactDOM as `<script defer crossorigin src="https://unpkg.com/react@18/...">`. That's a live network fetch to a third party on every page load, with no control over caching, availability, or latency. But the exact same file — `node_modules/react/umd/react.production.min.js` — was already sitting in the repo's `node_modules` (a pinned devDependency, version 18.3.1), because `test_search.js` was already using it to intercept and serve those requests locally during offline test runs. This change makes that substitution real: copy the two UMD files into the repo as committed static assets, and point both HTML shells at the local copies instead of unpkg. Same bytes, same behavior, but same-origin — no external fetch, no third-party outage risk, and (per 055's existing generic `.js`/`.css` cache rule in `vercel.json`) it now gets the same 5-minute-plus-stale-while-revalidate cache header as every other static JS file, automatically.

## What changed and why (diff in reading order)

1. **`react.production.min.js` + `react-dom.production.min.js`** (new files, repo root) — byte-identical copies of the pinned React 18.3.1 UMD production builds from `node_modules`. Committed, not hand-edited; a future React version bump means re-copying these two files.
2. **`home.html`** — the two `<script defer crossorigin src="https://unpkg.com/...">` tags became `<script defer src="./react.production.min.js">` / `./react-dom.production.min.js` (no `crossorigin` needed — same-origin file, no CORS mode). The unpkg-only `preconnect`/`dns-prefetch` hints were removed since nothing else in `home.html` fetches from unpkg (052 already dropped `@babel/standalone`). The `yields.llama.fi` hints are untouched — that's still a live third-party fetch for pool data.
3. **`plan.html`** — same script-tag swap. Its `<link rel="preload" as="script">` pair (which primed the browser to start fetching React early) was **repointed to the local files rather than deleted** — a local-file preload is still useful, deleting it would have been a pure regression with no purpose, even though the spec's literal wording said "remove the triplet." The unpkg `preconnect`/`dns-prefetch` were removed (same reasoning as home.html).
4. **Nothing else moved.** The `__APP_MODE` router block and `ANALYTICS_PARAMS` in `home.html` are byte-identical before and after (diffed directly) — this diff never touches routing logic, only which URL two `<script>` tags point at.
