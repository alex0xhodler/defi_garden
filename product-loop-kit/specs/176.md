## Non-goals

- Not a rewrite of the lane or the runner (170/163 own that).
- Not "make it green". A test updated to match a page that is wrong converts a product bug into a
  green build — the BACKLOG row says this in as many words, and
  `playbooks/pre-existing-red-triage.md` is the binding decision procedure.

## Method (binding)

Every red is classified BEFORE it is touched, using `playbooks/pre-existing-red-triage.md` step 3:

- **Rule A — product regression**: the assertion still describes what the product is supposed to do;
  the product drifted. → fix the **product**, keep the test.
- **Rule B — stale test**: the product deliberately changed (find the shipped item that authorized
  it) and the assertion encodes the old behaviour. → repoint/retire the **test**, and *re-home the
  coverage the pivot displaced* (156's precedent: bare `/` → landing, plus a new `/plan.html` case
  so the planner path keeps its coverage). Never fix the product backwards.
- **Rule C — environment**: fails only in-sandbox (blocked HTTPS, `waitUntil:'load'` never settling).
  → fixture-route / `waitUntil:'commit'`; never weaken the assertion.
- **Rule D — rotted positive control**: a rail now suppresses the injected value. → repoint the
  injection, convert the old one into a negative control.

A classification is only accepted with: the causing commit (`git log -S`), the authorizing sentence
quoted from BACKLOG/specs/NORTH_STAR (or the explicit absence of one), and the exact rendered value.

## Acceptance criteria

- **A1** Every one of the 8 reds carries a written verdict (A/B/C/D) in `specs/176-notes.md` with its
  causing commit and authorizing evidence quoted. An unclassified red is a FAIL even if it turns green.
- **A2** No assertion is deleted, loosened, or made vacuous. Any assertion that moves must move to a
  surface where it is *more* true, and the notes must say which route inherited the behaviour.
- **A3** Rule-B repoints re-home displaced coverage in the same diff (156 pattern), so the gate does
  not silently shrink.
- **A4** Any red classified rule A (a real product bug) is either fixed in product code in this diff,
  or — if the fix is larger than this item — filed as its own BACKLOG row with the evidence, and the
  test is left RED rather than silenced. Leaving a product bug green is a FAIL.
- **A5** Rendered acceptance: each repaired file is re-run through `node run-tests.js --only=<file>`
  in real Chromium and reported with its pass count. No unit-fixture-only claims (NORTH_STAR
  2026-07-11 standing decision).
- **A6** Non-vacuity: for each repaired file, the repair is proven to actually assert something —
  revert the product/test fix, confirm the case goes RED again, restore, confirm GREEN. Byte-identical
  restore confirmed.
- **A7** The port collision `test_spotlight_attribution.js` (`:28`) and `test_waitlist_pitch.js`
  (`:22`) both hardcoding `PORT = 8798` is resolved or explicitly ruled harmless with evidence from
  `run-tests.js`'s `defaultJobsFor` — the browser lane runs up to 3 concurrent jobs since item 170, so
  a shared fixed port is a flake source in the merge gate itself.
- **A8** Trust rails byte-untouched (`APY_SANITY_LIMIT`, `DEFAULT_MIN_TVL`, anomaly flags, degen
  haircut); no SEO surface de-indexed; `telegram-bot/`, `whatsapp-bot/`, `workers/` untouched.
- **A9** The final state of the lane is reported honestly: how many of the 8 are green, which remain
  red and why, and which file is the next stopper for a `test:serial` run.
- **A10** EN+KO together for any user-facing string change (`translations.js`), per CLAUDE.md.
