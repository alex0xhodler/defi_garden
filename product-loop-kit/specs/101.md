# Spec 101: Subscription share link must reproduce the full multi-service mix, not just the anchor goal

## Evidence
Heartbeat code-audit 2026-07-15 (evening), against `planner.js` at `origin/main` (dd0a546f4):
- `encodePlanToUrl(goal, monthly, years, persona, capital, fundingMode, deadline, poolFilters)` (`planner.js:903`) serializes `goal`, `capital`/`monthly`, `years`, `dl`, `pace`, `chain`, `token` — but **never the subscription mix** (`selectedSubs`).
- The share URL is built from exactly that call: `var shareUrl = encodePlanToUrl(goal, monthly, years, props.capital, props.fundingMode, props.deadline, poolFilters)` (`planner.js:1890`).
- The in-memory / localStorage plan object DOES carry the mix: `mix: archetype === 'subscription' ? selectedSubs : null` (`planner.js:1767`, `:1795`) — so the app knows the mix; it just isn't put on the wire.
- No decode side exists either: `grep "'mix'"` across `planner.js` returns **zero** hits — nothing reads a `mix` URL param on arrival. On open, the mix is re-seeded from the single `goal` anchor only (`planner.js:1506` "Seed the mix with exactly the user's picked subscription (the anchor goal)").

Net: a sender who builds a multi-service garden (e.g. Spotify + Netflix + Claude Pro) shares a link that, on the recipient's open, rebuilds only the single anchor `goal` — a **different garden than the sender built**. This directly undercuts the standing decision 2026-07-11: *"the plan share = a UNIQUE WORKING LINK that reproduces the sender's exact setup one-tap on open ... the link that rebuilds the garden is the primary artifact"* and the 024/060/069 share+spotlight artifacts (the SUBSCRIPTION archetype is the card funnel's front door).

## Hypothesis
We believe adding the subscription mix to the share URL (encode `selectedSubs` on `encodePlanToUrl`, decode + apply on arrival, `mixTouched`-aware so an untouched single pick round-trips byte-identically) will make multi-service subscription share links rebuild the sender's exact garden, because the app already computes and stores the mix — the only gap is the wire format. This strengthens the share artifact that feeds `share_link_opened → plan_created → waitlist_submitted`. Confidence: **supported** (gap reproduced by direct code audit; 024 already proved the encode/decode round-trip pattern for the rest of plan state).

## Change
Smallest version in `planner.js`:
- `encodePlanToUrl`: when `archetype === 'subscription'` and `selectedSubs` has ≥1 entry that differs from the bare `[goal]` default, set a compact `mix` param (e.g. comma-joined sub ids, `u.searchParams.set('mix', selectedSubs.join(','))`); otherwise `delete('mix')` so single-pick/anchor-only URLs stay byte-identical to today (no share-URL churn, no 081-class lastmod-style noise).
- Arrival decode: read `mix` param → parse to an id array → validate each id against the known subscription set (drop unknown ids, honest degradation — never crash on a hand-edited URL) → seed `selectedSubs` from it and set `mixTouched = true` so the sync effects (099's `slideCapital`⇄`neededCapital`) treat it as an explicit user mix, not the default seed.
- Regenerate `planner.min.js` (plan.html loads the min — 061/082/099 precedent).
- Pass `selectedSubs` into the `encodePlanToUrl` call at `planner.js:1890` (currently it isn't threaded in).

OUT OF SCOPE: changing the share-card image, the anchor `goal` semantics, non-subscription archetypes (GROWTH/TARGET carry no mix), any capital/coverage math (099 already made the numbers consistent — this only restores WHICH services), any new event. Keep every displayed number live-derived through the existing trust rails.
