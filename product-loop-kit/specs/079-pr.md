# 079 — Waitlist CTA on the hub/az spine pages (HIGH-tier explainer)

## Goal

`waitlist_submitted` is the north star, and item 062 built its SEO on-ramp: every
generated token/chain **leaf** page carries one honest card-pitch block linking to
`plan.html?waitlist=1&src=seo_*`. What 062 never touched are the **spine** pages 045
created to de-orphan that surface — `tokens/index.html`, the 27 `tokens/az/*` letter
hubs, `chains/index.html`, and their three KO mirror sets. That's 58 pages, and they're
not just any 58: home.html links **only** to the hubs, so every visitor who navigates
from the app to the SEO surface crosses them, and every non-top-N token is reachable
*exclusively* through an az page. After this change, zero pages on the ~2,190-page
static surface lack a path to the waitlist funnel.

## Intuition

The change is deliberately boring: 062 already built a parameterized CTA renderer
(`renderWaitlistCtaHtml(pitch, cssPrefix, source, t)`) and a token-only style block
(`renderWaitlistCtaStyle(cssPrefix)`), both exported. The hub pages already style an
anchor class named `.hub-cta` (their "plant a garden" back-link). Calling the renderer
with `cssPrefix='hub'` makes it emit `<a class="hub-cta">` — so the new block inherits
the hub pages' existing button chrome with **zero new styles beyond the block wrapper**,
exactly the 2026-07-10 "reuse before inventing" rule. planner.js needs no change at all:
it passes `?src=` through free-form to all five waitlist events, so the three new
sources (`seo_tokens_hub`, `seo_tokens_az`, `seo_chains_hub`) segment in Mixpanel from
day one.

## What changed, in reading order

1. **`translations.js`** (+6): one new flat key pair `tcpWaitlistPitchHub`, EN + KO.
   Hubs span mixed tokens/chains, so the pitch is subject-free ("A card that spends
   your DeFi yield — never your principal…"), same honest framing as the per-subject
   pitches; the "Card doesn't exist yet" micro-line is reused verbatim by the shared
   renderer, never re-worded. `translations.min.js` regenerated via `npm run minify`.
2. **`generate-token-pages.js`** (3 lines): `renderHubStyleBlock()` appends
   `renderWaitlistCtaStyle('hub')`; `renderTokenHubPage` and `renderTokenAzPage` insert
   the CTA block (sources `seo_tokens_hub` / `seo_tokens_az`) after the hub cards,
   before the trailing trust note — the same relative placement leaf pages use.
3. **`generate-chain-pages.js`** (1 line): `renderChainHubPage` inserts the block with
   source `seo_chains_hub`. The helpers were already imported.
4. **58 regenerated spine files**, produced by running both generators against LIVE
   yields.llama.fi data (`--out` to scratch, only the spine files copied back — leaf
   pages deliberately stay on their committed snapshot; the daily sitemap-update.yml
   run reconciles data drift as it already does between CI runs).
5. **Tests**: `test_hub_pages.js` 32→42 assertions (CTA presence on hub/az/chain-hub,
   EN+KO copy, exactly-one-block guard, per-surface source, placement);
   `test_waitlist_seo_entry.js` 3→5 assertions — real Chromium loads the served
   `tokens/index.html`, sees the CTA, clicks it, and asserts plan.html opens the
   waitlist modal with `waitlist_opened` carrying `source=seo_tokens_hub`.

## Deviations from spec

- The generators unconditionally rewrite the four sitemap XMLs at repo root (their
  sitemap path ignores `--out`); they drifted only by lastmod date and were restored
  via `git checkout` per the spec's "no sitemap changes". (Latent generator quirk of
  the same family as the og/ one 076 fixed — noted in specs/079-notes.md as a future
  candidate, not fixed here: no demonstrated harm, lastmod-only.)
- None otherwise; leaf output verified byte-identical, og/ untouched.

## Measurement

No isolated window. Hub sources land inside 062's `waitlist_opened(source=seo_*)`
stream (window to 2026-07-27) and are distinguishable by the three new source values.
