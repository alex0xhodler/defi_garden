# 139 — PR explainer (HIGH-tier gate)

**One line**: TARGET/GROWTH planner completions now end on "Start growing on `<top pool's project>` →"
(a real `/?pool=` deep link into the north-star surface) instead of the card waitlist; SUBSCRIPTION is
unchanged.

## Goal
Bet A (docs/strategy-2026-07-23-pretraffic-bets.md §3, human-approved 2026-07-23): the Garden Planner's
biggest button — the Bloom checkout panel's primary CTA — showed the SAME card-waitlist copy for every
archetype, including "your garden's yield pays your subscription automatically through a simple card"
on a plan for retirement, a home, sneakers, or an iPhone. That copy is only true for SUBSCRIPTION (the
card IS the business model). For TARGET/GROWTH it's a goal-incoherent trust bug, AND it silently skipped
the v2 spec's §4.4 primary CTA ("Start growing on the top pool →"), which would have routed
plan-completers onto PoolDetail — the same page the north star (`pool_click{source∈{garden_cta,
protocol_link}}`) measures.

## Intuition
The checkout panel already computed `curated` — the exact trust-railed, persona-scored, deduped pool
list the Engine-room cards below it render (`curatePools(pools, persona, 3, {...})`, sorted by
APY-within-band with a Sharpe tie-break). The primary CTA button just never looked at it: it always
opened the waitlist modal, regardless of archetype, and the modal's title/benefits strings were plain
strings (not archetype-dispatching functions) — so an existing `t(pitchKey('waitlistBenefits'),
archetype)` call was passing `archetype` as a no-op extra argument to a function that never used it. The
fix is almost entirely a branch on `archetype !== 'subscription'`: reuse `curated[0]` as "the top pool,"
render the SAME `.gp-primary-cta` button class as an `<a href="/?pool=...">` instead of a
waitlist-opening `<button>`, and demote the waitlist to a `.gp-share-textlink` (an existing, unstyled-here
component already used for the share prompt's secondary action).

## What changed and why (diff in reading order)
1. **`analytics.js` `trackPoolClick`** — added one additive line, `archetype: context.archetype ||
   null`, to the emitted `pool_click` payload. `trackPoolClick`'s `context` argument cherry-picks
   specific keys rather than spreading arbitrary ones (the same gap item 125 hit for `ctaPlacement`), so
   without this line the new call site's `{ archetype }` would have been silently dropped. `source`
   unchanged — this is purely additive segmentation.
2. **`planner.js` — waitlist modal copy branching** (~line 2695-2750). Added `waitlistTitleForModal` /
   `waitlistBenefitsForModal` locals: `archetype === 'subscription'` keeps the EXACT prior call
   (`t(pitchKey('waitlistTitle'))` / `t(pitchKey('waitlistBenefits'), archetype)`, pitch A/B/C variant
   included — zero behavioral change), else resolves the new `waitlistTitleEarlyAccess` /
   `waitlistBenefitsEarlyAccess` keys. The aria-label, `<h2>`, and `<p class="gp-waitlist-benefits">`
   all now read from these locals instead of calling `t(pitchKey(...))` inline three times. Also gated
   the pre-existing subscription-mix "garden already covers X" line to
   `archetype === 'subscription' && currentMixStats.count > 0` (was just the count check) — see
   Deviations below for why.
3. **`planner.js` — checkout panel primary CTA** (~line 2860-2940). Added `checkoutTopPool =
   curated[0]` (or null) and `checkoutPoolPrimary = archetype !== 'subscription' && !!checkoutTopPool`.
   Extracted the existing waitlist-open logic into `openCheckoutWaitlist()` (used by both the
   SUBSCRIPTION primary button and the new demoted secondary link) and added `handleCheckoutPoolClick()`
   (fires `Analytics.trackPoolClick(checkoutTopPool, 'plan_checkout', { archetype })`). The CTA render is
   now a ternary: pool-primary renders `<a className="gp-primary-cta gp-checkout-cta" href="/?pool=...">`
   with `t('startGrowingCta', checkoutTopPool.project)`; else the original `<button>` with `t('ctaWaitlist')`
   — byte-identical to before for SUBSCRIPTION. The microcopy paragraph below it branches the same way.
   A new `.gp-share-textlink.gp-checkout-waitlist-secondary` button (early-access copy, opens the same
   modal) renders only when `checkoutPoolPrimary` is true.
4. **`translations.js`** — 5 new EN+KO key pairs: `startGrowingCta` (function, interpolates the
   project name), `startGrowingCtaMicro`, `ctaWaitlistSecondary`, `waitlistTitleEarlyAccess`,
   `waitlistBenefitsEarlyAccess`. None mention "subscription"; none claim the card exists yet.
5. **`planner.min.js` / `translations.min.js`** — regenerated via `node minify-assets.js` (byte-identical
   to a fresh minify, confirmed by `test_minified_assets.js` and `test_translations_fallback.js`).
6. **`test_plan_checkout_cta.js`** (new, 13 assertions) — rendered Playwright, same fixture-routing
   pattern as `test_northstar_cta_fires.js` (the freshest convention: force the live pools path by
   404ing the snapshot meta, fulfill `yields.llama.fi/pools` with one fixture pool clearing the 'stable'
   persona's trust rails). Reaches Bloom via a share-plan URL (`?goal=&pace=&monthly=&years=`), which
   `planner.js` already fast-forwards straight to the bloom step once goal/persona/monthly-or-years are
   present — no need to drive the conversational chat flow. Covers GROWTH, TARGET, SUBSCRIPTION, and the
   empty-pool-list fallback. Wired into `package.json`'s `npm test` chain.
7. **`package.json`** — added `node test_plan_checkout_cta.js` to the test chain, next to its sibling
   `test_repeat_cta.js`.

## Deviations from spec
- **Modal copy for TARGET/GROWTH is one generic-but-honest string, not per-goal-personalized text.**
  Tried interpolating the literal goal label first; several labels don't sit grammatically inside a
  "toward your `<label>` goal" frame in either language (see specs/139-notes.md for the specific EN/KO
  grammar problems). Kept it generic ("growing toward your goal") — still satisfies the brief's
  "references growing toward their goal," no new copy pattern invented.
- **Gated the pre-existing subscription-mix "garden already covers X" modal line to
  `archetype === 'subscription'`.** Found during this item: it could render nonsensical dollar figures
  for TARGET plans (a `mixStats()` field-reuse quirk — TARGET goals' one-time item price gets read as a
  monthly subscription cost). This is the SAME class of goal-incoherent-copy bug the bet exists to fix,
  in the SAME modal this item already edits — in scope, not scope creep. The deeper root cause
  (renaming/guarding the shared `GOALS[].target` field) is NOT fixed here; flagged as a follow-up task
  (background-task chip spawned during this session).

## Quiz (answers base64 at bottom)
1. Why does SUBSCRIPTION keep the card waitlist as its primary CTA while TARGET/GROWTH switch to a pool
   link? (a) SUBSCRIPTION plans have no curated pools; (b) the card waitlist IS the subscription
   business model — a 2026-07-12 standing decision — so its copy ("yield pays your subscription") is
   only true for that archetype; (c) it's a coin-flip A/B test; (d) TARGET/GROWTH goals are worth more
   money.
2. Why did `Analytics.trackPoolClick(checkoutTopPool, 'plan_checkout', { archetype })` require an
   additive change to `analytics.js`, not just a call-site change in `planner.js`? (a) `trackPoolClick`
   didn't exist before; (b) `trackPoolClick`'s `context` argument cherry-picks specific keys into the
   emitted event rather than spreading it, so an unlisted `archetype` key would have been silently
   dropped; (c) Mixpanel requires server-side registration of new properties; (d) `archetype` collides
   with an existing reserved property name.
3. Why is `source: 'plan_checkout'` a brand-new value rather than reusing `garden_cta`? (a) Mixpanel
   caps the number of distinct source values; (b) reusing `garden_cta` would make the north-star metric
   (`pool_click{source∈{garden_cta,protocol_link}}`) uncountably conflate two different entry points
   into pool-detail, and NORTH_STAR.md's convention is disjoint `source` values per emitter; (c) it's
   required by trackPoolClick's type signature; (d) `garden_cta` is deprecated.
4. Why does the checkout panel fall back to the waitlist-primary layout when `curated` is empty, instead
   of always showing the pool-first CTA? (a) performance — rendering a pool link is expensive; (b) an
   empty/loading pool list would produce a dead `/?pool=` link with no pool behind it, which the spec
   explicitly forbids; (c) SUBSCRIPTION requires it; (d) it's an accessibility requirement.
5. Why was the pre-existing "garden already covers X — a card funded by $Y/mo" modal line additionally
   gated to `archetype === 'subscription'` in this item, when the brief only asked for the primary CTA
   and title/benefits copy to branch? (a) it was unrelated and shouldn't have been touched; (b) it's the
   SAME class of goal-incoherent-copy bug the bet exists to fix, discovered inside the SAME modal this
   item already edits, and leaving it ungated could show a nonsensical dollar figure to a TARGET-plan
   user opening the demoted waitlist; (c) it was required to make the primary CTA render correctly; (d)
   it fixes a currency-formatting bug.
