# 188 — PR explainer (HIGH tier: full walkthrough)

**One line:** we were asking Google to index seven URLs that our own app has no code path to render,
and telling AI crawlers they were "filtered views" — this replaces them with six URLs that render
real pool grids, gated so a filter level with no pools is never submitted at all.

---

## 1. The goal

Two surfaces publish a list of URLs on our behalf: `sitemap-main.xml` (what we ask Google to index)
and `llms-full.txt` (what AI crawlers read). Both carried a block of seven "filter" URLs:

```
?minTvl=1000000   ?minTvl=10000000   ?minTvl=100000000
?minApy=5   ?minApy=10   ?minApy=20   ?minApy=50
```

The goal of this item is that every URL we publish is a page a reader can actually land on and get
something from. Nothing more.

## 2. The intuition — why those seven URLs could never work

`minTvl` and `minApy` are **secondary** filters in the analytics app. They narrow a result set; they
never create one. The app's filtering effect returns early before any of them is consulted:

```js
// app.js:2010-2013
// Token-first mode: existing logic
if (!selectedToken) {
  setFilteredPools([]);
  return;
}
```

So `?minApy=5` does not mean "show me pools above 5%". It means "show me nothing, filtered to above
5%". Every one of the seven rendered the same thing: the analytics app's empty search hero — the
same content as `/`.

Three facts make that worse than a dud link:

1. **They were indexable.** Measured in a real browser against live DefiLlama data: 0 pool cards,
   `<meta name="robots" content="index, follow">`. Item 012's honest-empty-state `noindex` did not
   fire, because it triggers on a *resolved query returning zero* — and these queries never resolve
   at all.
2. **Each claimed to be its own page.** `canonical.js`'s `CANONICAL_PARAMS` includes `minTvl` and
   `minApy`, so each self-canonicalised. Seven distinct canonical URLs, one piece of content: the
   textbook *"Duplicate without user-selected canonical"* class that item 010's GSC diagnosis was
   opened for.
3. **No gate had ever looked at them.** Item 013 built the sitemap quality gate
   (`SITEMAP_MIN_QUALIFYING_POOLS = 2`) and wired it to the token, token+chain and token+category
   families. This block was hardcoded — `tvlLevels.forEach(...)`, `apyLevels.forEach(...)` — and
   hardcoded lists are exactly what a data-driven gate never gets pointed at.

`audit-app.js` flagged **one** of the seven (`?minApy=50`, the run's only blocking P1) and only
because that one *also* failed a pool count: live today, 15,878 pools → 548 clear the $10M floor and
the anomaly rail → **0** reach 50% APY. The other six were invisible to every automated check we
have, because every checker in this repo answers "how many pools match this query" — a question that
cannot express "the app has no branch that renders pools for this URL shape."

## 3. The fix, and why this shape

The app **already** has a token-less browse mode that renders a real grid: chain-first with
`chain=All` (`app.js:1837/1843`, `chainMatch = selectedChain === 'All' || …`). So we do not teach
`app.js` anything new — we publish the URL shape that already works. Measured, same live population:

| published now | pool cards | results |
|---|---|---|
| `?chain=All&minTvl=1000000` | 9 | 2,603 |
| `?chain=All` | 9 | 738 |
| `?chain=All&minTvl=100000000` | 9 | 158 |
| `?chain=All&minApy=5` | 9 | 137 |
| `?chain=All&minApy=10` | 9 | 31 |
| `?chain=All&minApy=20` | 9 | 9 |
| ~~`?chain=All&minApy=50`~~ | 0 | **0 → dropped by the gate** |

Two details decided the shape:

- **The $10M rung is emitted as bare `?chain=All`.** The app's own `updateUrl()` omits a `minTvl`
  equal to the default, so loading `?chain=All&minTvl=10000000` rewrites the address bar to
  `?chain=All`. Publishing the app's own normalised form keeps the submitted URL, the address bar
  and the canonical in agreement. (`?chain=All` was not in the sitemap before — grep-confirmed.)
- **`?chain=All&minApy=50` self-`noindex`es** — once the query genuinely resolves, item 012 works
  correctly and marks the empty result `noindex`. Submitting it would have manufactured a
  *"Submitted URL marked 'noindex'"* GSC error. That is why the gate is not optional.

### Is this "deleting SEO surface"? No — and the argument was checked, not assumed

NORTH_STAR's NEVER list forbids deleting or de-indexing SEO surface. This diff **deletes nothing**:
the seven bare URLs still serve exactly what they served before (no route, `app.js`, `home.html` or
`vercel.json` change), keep their self-referential canonical, and gain no `noindex`. What changed is
which URLs we *submit* — seven duplicates of `/` swapped for six that render distinct, pool-bearing
content. That is item 013's stated purpose and matches the precedent the human resolved for item 148.
The verifier judged this independently and reached the same conclusion.

One SEO file **is** deleted in this commit — `sitemap-chain-Blast.xml` — and it is **not ours**.
Both the operator and the verifier separately regenerated the sitemap in an isolated `git worktree`
at unmodified `origin/main`: the same file is deleted there. Blast has zero qualifying pools in
today's live feed, and `cleanupStaleSitemaps()` (item 080) removes stale children on every bake. It
is ordinary daily drift that would have landed with or without this item.

## 4. The diff, in reading order

**`generate-sitemap.js`** — the fix.
- `poolTotalApy(pool)` extracted (`apyBase + apyReward`) so the anomaly check and the new gate share
  one computation. This is deliberately **not** the feed's raw `apy` field: they differ, and using
  the wrong one would gate a different page than the one we publish (`apy >= 5` counts 145 pools;
  the app shows 137).
- `isQualifyingPool(pool)` → `isQualifyingPool(pool, minTvl = SITEMAP_MIN_TVL)`. Additive: every
  existing call site passes one argument and is byte-identical in behaviour. The new gate needs to
  evaluate at $1M/$10M/$100M floors, and a second near-identical helper would have been a FAIL.
- `countQualifyingChainAll()` — the gate. Floor = explicit `minTvl` when present, else
  `SITEMAP_MIN_TVL` (mirrors `app.js:927`); `minApy` against `apyBase + apyReward`; the existing
  anomaly rail via `isQualifyingPool`. No rail constant is redefined or relaxed.
- The two hardcoded `forEach` pushes replaced by gated emission, plus a `⏭️` log line naming every
  dropped rung and its measured count. The gate re-decides on every daily bake, so it tracks the
  market instead of freezing today's answer.

**`generate-llms.js`** — two changes.
- `gridLinkPoolCount()`: `chain === 'All'` is now a wildcard, not a literal chain name.
- `buildFull()`: the four unconditional section headings (`## Token Pages`, `## Chain Pages`,
  `## Pool Type Pages`, `## High-Value Filter Pages`) now use the same `if (…length > 0)` guard that
  `## Other Pages` right below them already had. This also fixes a defect that was live before this
  item: `## Pool Type Pages` shipped a heading plus *"TL;DR: Strategy-based categorization"* with
  **zero** links under it, because no `?poolTypes=` URL exists anywhere in the sitemap.

**`audit-app.js`** — `countQualifyingPools()` gets the same `chain === 'All'` wildcard, and is
exported so the fix can be unit-tested directly.

**Tests** — `test_sitemap_filter_urls.js` (new, rendered Chromium + Node gate tests, registered in
`package.json`'s `test:serial` after `test_sitemap_xml.js`), plus new cases in
`test_llms_link_integrity.js` and `test_audit_text_surfaces.js`.

**Regenerated artifacts** — `sitemap-*.xml`, `llms.txt`, `llms-full.txt`, produced by
`npm run sitemap && npm run generate:llms`, never hand-edited.

### Leg C: the regression this fix would have caused

Worth reading even if you skim the rest. Both grid-link simulators compared the chain param
literally:

```js
// generate-llms.js:878  and  audit-app.js:1038
if (chain && p.chain !== chain) continue;
```

No pool's `chain` field is ever `'All'`. So every URL this item emits would have simulated to **zero
pools**, and two things would have followed: item 180's `applyChainRetarget()` would have classified
each new URL as dead, looked for a `/chains/all` static page, not found one, and **omitted the URLs
entirely** from `llms-full.txt`; and the level-3 `link-target-integrity` check would have raised a
**new blocking P1 per URL**. An item whose point is clearing the audit's only blocker would have
multiplied it instead. Leg C teaches both simulators the wildcard `app.js:1841` has always used.

The sibling wildcard `chain=Popular` (`app.js:1838`'s 15-chain list) is deliberately **not** fixed:
grep across `sitemap-*.xml`, `llms*.txt`, `tokens/`, `chains/`, `stories/` returns 0 occurrences, so
it is dormant. Duplicating a 15-chain list into two more files to cover a case that does not exist
would be worse than recording the gap — which is done here and in the notes.

## 5. Deviations from the spec (all in `188-notes.md`, none relax a rail)

1. Leg C's unit checks were written directly against the exported `countQualifyingPools` /
   `gridLinkPoolCount` rather than only through full pipeline fixtures — more precise, and one
   integration case per file was added on top.
2. `isQualifyingPool`'s signature gained an optional second parameter (default preserved).
3. `countQualifyingPools` was added to `audit-app.js`'s exports (additive; no existing export
   touched).
4. Running the `audit-app.js` CLI during verification writes
   `product-loop-kit/signals/audit-rotation.json` (documented CLI behaviour); the builder restored it
   each time.
5. The A1 test derives its expected URL list by actually running `generateSitemapSuite()` against a
   fixture, never a hand-typed list.

## 6. What is NOT proven

- The full ~70-file browser lane was not run end to end — it does not fit the 5-minute timebox. The
  10 browser-lane files that require the three changed source files were run and pass.
- No Mixpanel funnel metric is isolable here. This is generated-surface quality, measured in GSC,
  which the human reads manually through ~2026-08-23. Honest proxies: `link-target-integrity`
  suspects 1 → 0, and six URLs rendering pool grids where seven rendered none.
- GSC will take its usual 2–6 weeks to reflect any of this.

## 7. Verification (verifier's own work, not the builder's re-run)

Verifier verdict **PASS, 9/9 criteria + Leg C, tier HIGH**. It built its own mutations rather than
reusing the builder's: reverting Leg A (test goes red), removing the `chain !== 'All'` clause from
each simulator **separately** (each corresponding assertion goes red), and a control mutation that
correctly moves nothing. It rendered all six emitted URLs itself against a live DefiLlama fetch
(≥8 pool cards each, none `noindex`), confirmed `?token=USDC` / `?chain=Ethereum` / `?pool=<real id>`
are unchanged, reproduced the `origin/main` baseline (38 pass / 1 fail — the pre-existing red is
`test_llms_link_integrity.js`, failing over the very `?minApy=50` link this item removes) against the
branch's 39/39, ran `validate-sitemaps.js` (113/113), regenerated twice and compared md5s, and
verified the `chain=Popular` grep claim itself. Tree left byte-clean.
