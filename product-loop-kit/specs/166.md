## Design

Validate `--only` against the resolved file list, and refuse to report a pass on an empty run.

1. **New exported pure function** `unknownOnlyNames(only, allFiles)` → array of entries in `only`
   that are not in `allFiles`, preserving input order and duplicates-collapsed. Exported for direct
   unit assertions.
2. **Validation point**: in `main()`, immediately after `allFiles` is resolved from
   `readSerialChain()`/`parseFileList()` and **before** the `--list` branch and **before** the
   `node_modules` preflight. Rationale: a typo is an operator error that a fresh clone (no
   `node_modules`) must still be told about, and `--list` is exactly where someone checks a name.
3. **Unknown names** → print to **stderr** one line naming every unknown entry plus a pointer to
   `--list`, then `process.exit(2)`. Exit 2 matches the existing "cannot run / operator error"
   convention already used by the preflight (`run-tests.js:314-317`); exit 1 stays reserved for
   "tests actually failed or timed out".
4. **Empty selection in RUN mode** → after lane+only filtering, if `selected.length === 0`, print
   to stderr that zero files were selected and that a zero-file run is not a pass, then
   `process.exit(2)`. This catches the legitimate-names-wrong-lane case
   (`--lane=plain --only=<a browser file>`), which name validation alone cannot.
5. **`--list` keeps exit 0** when the *filters* legitimately narrow to nothing (e.g.
   `--lane=browser` on a plain-only `--only` set). `--list` is introspection; only an unknown
   *name* is an error there.
6. Nothing else changes: `parseArgs` still stores `args.only` as an array or `null`; the default
   `npm test` path passes no `--only`, so neither new branch can fire on it.
