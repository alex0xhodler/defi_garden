# PR explainer: 027 — Share-card real logo + label/headline consistency

**Risk tier: HIGH** (touches the hero viral share artifact + its canvas export path — a
bug here breaks every image share, per NORTH_STAR's risk map).

## Goal
The share card is the one artifact meant to travel off-device and pull a new visitor
back to defi.garden. A human-reported screenshot showed it undercutting its own trust:
row 1 said "Spotify" under a headline that said "…covers ChatGPT Plus — forever," and
every card's row-1 icon was a generic 🌱 sprout regardless of which service the plan
was actually about. Spec 027 asked for two things: (1) draw the featured service's
*real* logo instead of the sprout, and (2) make row 1's label always agree with the
headline it sits under.

## Intuition
There wasn't one bug, there was one *bug shape* appearing at two call sites.
`renderShareImage(opts)` — the canvas painter — trusted whatever `opts.goalLabel` it
was handed. Both callers (`doWaitlistDownload`, and the capital-path branch of
`doShare`) build their **headline** from a *bundle* of covered/selected services (e.g.
"Spotify + Netflix" or just "ChatGPT Plus" if that's what got selected), but were
separately computing `opts.goalLabel` from the plan's single top-level `goal` — which
can be a completely different service once the user starts customizing the mix. Two
numbers that are supposed to describe the same thing, computed from two different
places, is exactly the kind of thing that erodes trust when a saver notices it.

The fix: compute the "featured service" **once**, per branch, and thread that one
value into the headline, the row-1 label, and the row-1 icon. If exactly one service
is in play, it gets its own real logo. If it's a multi-service bundle, there's no
single logo that represents "Spotify + Netflix" honestly, so the icon slot falls back
to an emoji rather than picking one arbitrarily — but the *label* still always matches
the headline.

Logos themselves are drawn as vector fills (`Path2D`), not images — the SVG path data,
viewBox, and official brand hex for each service are baked into a new static file,
`brand-icons.js`, sourced from two well-known open-source icon sets (simple-icons,
gilbarbara/logos). Nothing is fetched over the network at share time, so the canvas
can never be tainted and `toBlob`/`toDataURL` can never throw for CORS reasons — that
was the other failure mode the spec called out as a risk.

## What changed, in reading order

1. **`brand-icons.js`** (new file). A `window.BRAND_ICONS` map keyed by the same
   `icon` domain strings the app already uses (`'spotify.com'`, `'openai.com'`, …).
   Each entry: `{ vbW, vbH, color, path }` — an SVG path's `d` attribute, its viewBox
   dimensions, and the brand's official hex. 11 services covered: Spotify, Netflix,
   Claude, OpenAI/ChatGPT, Audible, YouTube, DoorDash, Uber, Max, Paramount+, Apple.

2. **`plan.html`**: one new `<script defer src="brand-icons.js">`, loaded right after
   `translations.js` (same pattern, before `planner.js` so the data's ready when
   `renderShareImage` needs it).

3. **`planner.js` — `brandForId(id)`** (new small helper, next to `goalById`):
   resolves `{ icon, emoji }` for a service id, checking `SUBSCRIPTION_LADDER` first
   (its ids can collide with `GOALS`) then falling back to `GOALS`.

4. **`planner.js` — `doWaitlistDownload()`**: now also collects the *matched*
   `SUBSCRIPTION_LADDER` objects (not just their label strings) while building the
   headline list. `opts.goalLabel` changed from `goalLabel(t, goal)` (the bug) to
   `dlList` (the same list the headline is built from — always in sync by
   construction). Added `opts.brandIcon`/`opts.brandEmoji`, resolved from the single
   matched service if there's exactly one selected, else from the anchor goal if none
   are selected, else `null` (bundle of 2+, no single logo — sprout fallback).

5. **`planner.js` — `doShare()`**: added `shareRowLabel`/`shareFeatured`, set in all
   four archetype branches. The capital-path subscription branch had the same
   bundle-vs-anchor mismatch as `doWaitlistDownload` (not called out in the spec's
   evidence, but the same bug shape) — fixed identically. The other three branches
   already had headline and label agreeing, so they just gained a real
   `brandForId(goal)` icon instead of always defaulting to sprout.

6. **`planner.js` — `renderShareImage(opts)`**: replaced the hardcoded
   `'🌱 ' + goalLabel` text draw with: look up `BRAND_ICONS[opts.brandIcon]`; if found,
   `Path2D`-fill it (brand color) to the left of the label text; if not found (or the
   fill throws — wrapped in try/catch), prefix the label with `opts.brandEmoji` or
   `'🌱'` instead. Text position shifts right by the icon's width when a real logo is
   drawn, so the label never overlaps it.

## Deviations from spec (full detail in `specs/027-notes.md`)
- Amazon, Hulu, Disney+, Xbox, Peacock, Walmart aren't bundled — no open MIT-licensed
  icon set ships them (checked two; zero matches in either). They use the spec's own
  documented fallback (service emoji). Amazon Prime is the one `SUBSCRIPTION_LADDER`
  anchor without a real logo as a result.
- Drawn via `Path2D` fill rather than a preloaded `Image`/`drawImage` — same
  never-tainted guarantee, but synchronous and vector (no image-load race, no
  rasterization softness at 2x canvas scale).
- Fixed the same bug shape in `doShare`'s capital-path branch too, not just
  `doWaitlistDownload` (the one named in the spec's evidence).

## Verification (real browser render, not just unit fixtures)
`npm install` (Playwright's Node package; Chromium already present at
`/opt/pw-browsers/chromium`), served the repo locally, and drove `plan.html` in
headless Chromium — routing the pools API to a static fixture and `unpkg.com`'s
React/ReactDOM requests to local `node_modules` copies (both needed only because this
sandbox can't reach `yields.llama.fi` or `unpkg.com`; not a product change). Captured
five real canvas renders by hooking `HTMLCanvasElement.prototype.toBlob`:
ChatGPT/capital-path (the reported bug's exact shape — now shows the real OpenAI mark
and a matching label+headline), Spotify/monthly, Claude/capital-path, and
AmazonPrime/capital-path (no bundled logo → clean emoji fallback, no crash) — plus a
full end-to-end repro of the *literal* reported screenshot: anchor goal `spotify`,
mix switched to ChatGPT Plus only, through the real waitlist-download click path.
All five: no draw error, no thrown exception. `node --check` clean on both changed
files; full test chain still 190/190.
