# 184 — PR explainer (HIGH tier)

**Automate level 2 of the link model: the estate's `?pool=` deep links now have a gate, and it ships green.**

---

## 1. The goal, in one paragraph

DeFi Garden's 2,178 generated SEO pages emit 3,670 distinct `/?pool=<uuid>` deep links. Those links are the
estate's route to the **north-star surface** — pool-detail, where the two conversion CTAs live. A dead one
does not 404; it lands the reader on the honest dead-pool empty state (`app.js:1209`), which is graceful but
is still a lost conversion. Item 175 named a three-level model for link checking — **routed** (is the query
key even in the router's allow-list?), **resolvable** (does the value name a real entity?), **non-empty**
(does the target return anything?) — and levels 1 and 3 have gates (items 172, 175/180/181). **Level 2 over
the HTML estate has never had one.** It has been run by hand four times in five days. This item builds the
gate.

## 2. The intuition: this is a gate that proves a true negative

The natural instinct on finding dead links is to fix them. That instinct is wrong here, and the spec says so
in as many words: *"a diff that regenerates `tokens/`/`chains/` to make it green is the opposite of this
item."*

Why: item 181 already established, over four live measurements 15 hours apart, that this class of "dead"
is **live-data churn**, not a repository defect. Pools appear and disappear on DefiLlama between the daily
bakes; a page baked at 04:00 can name a pool that is gone by 22:00, and the next bake resolves it with no
diff at all. 181 derived a **`DRIFT_BUDGET_FRACTION = 1.0%`** for exactly this, and built a three-class
split so a gate never reddens for a reason no diff can fix:

- **contract** — decidable from the repo alone, invariant to live data. **Fatal at any count.**
- **stale** — dead *and* the page's own visible `Last updated` date is past `STALE_AFTER_DAYS`. This is the
  real lifecycle failure (a page whose pool set emptied and the regen never refreshed). **Fatal at any count.**
- **drift** — dead on a fresh page. Self-healing. **Bounded by the budget, reported always.**

So the deliverable is not a repair. It is a check that (a) is green on today's corpus, and (b) is *proven*
able to go red — because a green gate nobody has seen fail is indistinguishable from a gate that does nothing.

## 3. What the numbers actually were

The spec was written earlier the same day; the daily bake ran in between. Both measurements are reported
rather than reconciled:

| | spec 184 | this build |
|---|---|---|
| live pools | 15,992 | 15,927 |
| distinct `?pool=` deep links | 3,677 | **3,670** |
| dead ids | 4 (0.11%) | **1 (0.027%)** |
| pages affected | 5 | **1** (`tokens/loop.html`) |
| verdict | drift, in budget | drift, in budget (allowance 36.7) |

The remaining dead id (`cc7ada00-…`) is **not one of the four the spec named** — the drift set shares zero
members with the earlier one, which is the same non-membership property 181 measured. That is the evidence
this class is churn.

Before writing the contract rules, both were checked against all 2,178 pages: **0** malformed uuids, **0**
`?pool=` links unbacked by a `tp-pool-link`/`cp-pool-link` anchor. Holding at 100% today is 181's own
stated branch condition for shipping a rule as fatal, so both ship fatal-at-count-1.

## 4. The diff, in reading order

**`test_seo_cta_targets.js`** — item 181's file, +16/−4, no logic touched.

1. `main()` is wrapped in `if (require.main === module)`. Running it as a script is byte-identical in
   behaviour; requiring it no longer kicks off a live scan as a side effect.
2. `module.exports = { DRIFT_BUDGET_FRACTION, STALE_AFTER_DAYS, parseLastUpdatedDate, verdictFor, loadPools }`.

That is the whole change, and it is the mechanism that satisfies 174's one-constant rule: 184 **imports**
181's budget and threshold rather than re-typing them.

**`audit-app.js`** — +280.

3. `const cta181 = require('./test_seo_cta_targets.js');` — with a comment stating the rule it exists to
   honour.
4. `PRESCAN_SIGNALS` gains `'pool-link-liveness': 'P1'`, so the signal appears in the audit's `bySignal`
   block with a count alongside the existing link signals — with or without suspects.
5. `POOL_ID_UUID_RE` (contract sub-rule 1) and `MS_PER_DAY_184` (a *units* conversion, not a threshold —
   see the notes file).
6. `loadLivePoolIds(opts)` — async, **never throws**. Accepts `opts.livePools` for test injection;
   otherwise delegates to `cta181.loadPools()`, which already handles `POOLS_FIXTURE`, a 6h temp cache, and
   a live fetch, and which *throws loudly rather than passing vacuously*. A failure comes back as
   `{ ids: null, error }` for the caller to degrade on.
7. The new sub-rule inside `prescanStaticPages()` — one contiguous, independently neuterable block placed
   after the existing level-2/level-3 blocks. It reuses the file's own `HTML_HREF_RE` /
   `ownedHtmlLinkSuffix` / `ownedLinkPath` / `linkQueryPairs` helpers to collect the page's `?pool=` ids and
   its `HTML_ANCHOR_TAG_RE` / `POOL_ROW_ANCHOR_CLASSES` helpers to collect the ids its own pool rows back.
   Classification is contract → ok → stale → drift, with `cta181.parseLastUpdatedDate` and
   `cta181.STALE_AFTER_DAYS` doing the freshness half. `today` is injectable.
8. The post-loop verdict calls **`cta181.verdictFor()` verbatim**. Drift suspects are emitted **only** when
   scan-wide drift exceeds the budget — under budget, drift is reported in the summary and never blocks.
   That single line is why today's corpus is green rather than red-on-a-non-defect.
9. `prescanStaticPages()` now returns `{ scanned, suspects, poolLinkLiveness }` (additive — every pre-184
   caller destructures only the first two), and `emptyPrescanResult()` gains the same field so no caller
   has to null-check.
10. `buildStaticSurfaces()` threads `livePoolIds`/`livePoolsError` through, publishes
    `prescan.poolLinkLiveness`, and — when the check was *requested but could not run* — pushes a **P1**
    `static-prescan:pool-link-liveness-unrun` finding. A fetch failure is never a silent pass. "Not
    requested" (the kill switch) stays silent, which is the distinction that keeps the switch usable.
11. `runAudit()` resolves the live id set once per run, behind `opts.poolLiveness === false` /
    `AUDIT_POOL_LIVENESS=0`.

**`test_audit_pool_link_liveness.js`** — new, 372 lines, 12 cases: healthy · contract ×2 · stale ×2 · drift
under budget · drift over budget · unrun · not-requested · real-corpus green · real-page backdated copy goes
red · `tokens/usdc.html` md5 unchanged.

**`package.json`** — 1 line: the new test joins the `test:serial` chain between its two nearest siblings.

## 5. Deviations

All five are written up in `specs/184-notes.md` §4 with reasoning. In brief: `package.json` was touched (the
spec's acceptance criterion explicitly carves out "beyond any test registration", and `run-tests.js` parses
that chain rather than globbing, so an unregistered test never runs); the file classifies **browser** lane,
not plain, because `classifyLane()` is transitive and the test requires `audit-app.js` — same as all nine
existing `test_audit_*.js` files; `MS_PER_DAY_184` is a units constant, not a restated threshold;
`verdictFor`'s `scannedWithCta` parameter is fed distinct-**ids** rather than pages, named at the call site
rather than left silent; and `runAudit()` now performs a cached-or-live pool fetch by default.

Separately, `test_audit_prescan.js`'s `A6b` case fails — **proven pre-existing** by stashing to a clean
`origin/main` and reproducing the identical `40 passed, 1 failed`. It counts raw occurrences of
`"reconcilePrescanFindings("` in source and expects 3 where `main` already has 5, two of them comments.
Item 184 adds none. Recorded, not fixed — that is a second item.

## 6. What the human should look at

Nothing renders differently; there is no user-facing surface in this diff and no visual spot-check is
needed. The one judgment call worth a human eye is **§2's framing**: this ships a gate that is green, and
deliberately does not repair the one dead link it found. If you disagree with that — if you'd rather the
loop had regenerated `tokens/loop.html` — say so and the standing decision can change.
