## Change

`audit-app.js` only (plus one new test file + bookkeeping):

1. **Two new surface kinds** in the driver section (`main()`), alongside the
   existing `loading` / `static` / `dead-pool` / `grid` / `pool` branches:
   - `kind: 'landing'` — bare `/` (the server maps `/` → `home.html`; since the
     2026-07-15 pivot this mounts the search-first landing into `#landing-root`).
   - `kind: 'planner'` — `/plan.html`, which mounts `#planner-root` and renders
     `.gp-*` components (`planner.js`).
2. **Four new surfaces in the default rotation**, appended after the existing
   nine so no existing `surfacesCovered` entry moves or changes name:
   | name | url | width | notes |
   |------|-----|-------|-------|
   | `landing` | `/` | 1280 | search-first landing |
   | `planner` | `/plan.html` | 1280 | planner, default light/EN |
   | `planner-360` | `/plan.html` | 360 | responsive check |
   | `planner-ko` | `/plan.html?lang=ko` | 1280 | i18n check |
3. **Checks per new surface** — reuse the existing helpers, invent no new
   detector vocabulary:
   - `dead-end` **P1** — the surface's mount does not render its content within
     the timeout (landing: `#landing-root` has rendered content; planner:
     `#planner-root` contains a `.gp-*` element). Use the existing
     `waitForSelector`/`pollFor` helpers, never a bare `waitForTimeout`.
   - `number-sanity` **P0** — via the existing `auditText()` on rendered
     `innerText` (NaN/Infinity, `$undefined`, 1-decimal money, absurd magnitude).
   - `page-error` **P0** — via the existing `makeErrorSink()`.
   - `dead-cta` **P1** — the surface's primary next-step control renders and is
     visible. Resolve the real selector by reading `home.html`/`planner.js`
     first; do not guess a class name that does not exist.
   - `responsive` — on the 360 surface only, via the existing `checkResponsive()`
     against the surface's own content selector.
   - `i18n` **P2** — on the `-ko` surface only, reusing the existing
     "KO surface rendered no Hangul text" check from the `pool` driver.
4. **Filtering parity**: `--only` / `opts.only` selects the new surfaces by name;
   `--static-only` still filters them out (they are not `kind: 'static'`).

Constraints: no new dependency; no change to `scanNumbers`, `setupRoutes`,
`startServer`, the prescan or the text-surface pass; no product file
(`home.html`, `plan.html`, `planner.js`, `app.js`, `PoolDetail.js`,

## Territory notes

- `startServer()` maps `/` → `home.html`, so the `landing` surface needs no
  special casing; `/plan.html` is served straight off disk.
- `setupRoutes()` already fulfils `https://yields.llama.fi/pools` from the
  committed snapshot and aborts `icons.llamao.fi` — the planner fetches the same
  live endpoint, so it gets deterministic data for free. Do NOT add new routes.
- Use `waitUntil: 'domcontentloaded'`, never `'load'` (sandbox-blocked fonts and
  analytics mean `load` never fires — the 158 root cause).
- `planner.js` is a plain script (no babel) but `home.html`'s landing goes
  through babel-standalone; both are already vendored in `UNPKG_VENDOR`.
- The planner is conversational: the first render is a goal-picker step, not a
  plan. Assert what the FIRST screen must show; do not drive a multi-step flow
  (that is a different, larger item).
