# 077 — test_smoke.js fixture-routing fallback: make the smoke gate (003) actually run in-sandbox

## Why now (evidence, all already in the repo)
- The smoke gate is the ONLY guard on the #1 guardrail metric (NORTH_STAR.md: "parameterized
  analytics URLs (`?token=/?chain=/?pool=`) keep rendering pool cards — that's the SEO lifeline"),
  yet it cannot pass in cloud-loop sandboxes: browser-originated HTTPS to yields.llama.fi is blocked
  at the proxy connection level (NORTH_STAR standing decision 2026-07-12), so `.pool-card` never
  renders and even the bare-`/` assertion fails on `net::ERR_CONNECTION_RESET` console errors.
- Confirmed live this session (2026-07-13): `node test_smoke.js` → 1/8 assertions pass; the three
  browser-path failures are all external-fetch shaped. Meanwhile `curl https://yields.llama.fi/pools`
  returns 200 from Node — the block is browser-only, exactly as diagnosed 2026-07-12.
- Because `npm test` chains with `&&`, the whole suite halts at test_smoke.js on every loop run.
  Four consecutive items had to prove the failure pre-existing by hand instead of getting a green
  chain: specs/069-notes.md ("test_smoke.js has NO vendored-React/route fallback"), specs/071-notes.md
  and specs/074-notes.md (stash-baseline proofs), specs/073-notes.md. The 052-056 BACKLOG rows all
  carry "test_smoke.js unverifiable in-sandbox".
- The fix pattern is established repo convention, prescribed by NORTH_STAR 2026-07-12: "Playwright
  tests keep the established fixture-routing pattern (test_search.js style) for external hosts."
  test_search.js, test_spotlight_url.js, test_waitlist_seo_entry.js all already do this; test_smoke.js
  (written 2026-07-10, before the pattern existed) is the one Playwright test left behind.
- Score 6.8 — loop-infrastructure/guardrail class, same band as 074 (6.8) and 076 (6.6): restores
  the risk policy's "verifier PASS + tests green" to something a sandbox run can actually establish,
  and un-hedges every future render-path merge.

## Change (test_smoke.js only — zero product code)
1. **Route the pools fetch instead of letting the browser egress.** Before each `page.goto`, install
   `page.route('https://yields.llama.fi/pools', …)` fulfilling with:
   - a **live snapshot** when Node-side egress works: probe once at startup (curl, same
     `probe()`/`execFileSync` shape as test_search.js — curl honors HTTPS_PROXY) and, on 2xx, capture
     the real response body once and serve it to every routed request → the test exercises genuinely
     live data in this sandbox (curl reaches llama here even though Chromium can't);
   - the **DefiLlama-shaped fixture** otherwise (test_search.js's `FIXTURE_POOLS` shape; must include
     USDC pools above the $10M `DEFAULT_MIN_TVL` floor so `?token=USDC` renders cards).
   Log which mode ran (test_search.js precedent: one `network:` line).
2. **Classify ignorable errors by the failing resource's URL, not the console text.**
   Chromium's "Failed to load resource" text never contains the URL — match
   `msg.location().url` against the ignorable pattern (exact test_search.js technique, its comment
   explains this). Extend the pattern to the CLAUDE.md-ignorable external hosts as observed
   (fonts/analytics/`api.llama.fi/protocols`) — but ONLY those; genuine page errors and non-ignorable
   console errors must still fail the test.
3. **Fixture sharing:** builder's choice — either require a small shared fixture module used by both
   test files, or keep an inline fixture in test_smoke.js (other test files keep their own fixtures
   today; duplication of ~20 lines is acceptable, silently diverging trust-rail thresholds is not —
   if inlined, note it in the notes file).

## Acceptance criteria
1. `node test_smoke.js` in THIS sandbox: **8/8 assertions pass** (both router paths at 360/768/1280
   + pool-detail BreadcrumbList + static JSON-LD), and the output states which data mode ran
   (live-snapshot vs fixture).
2. The routing preserves live-data semantics where possible: with the probe succeeding (as it does
   here via curl), the fulfilled body is the real yields.llama.fi payload fetched this run — not the
   canned fixture. Fixture is fallback-only. Evidence: the logged mode line + code inspection.
3. Error handling stays adversarial: a genuine page error still fails the test. Verifier mutation
   check: temporarily inject a thrown error / bogus console.error into a served page (or equivalent)
   and confirm test_smoke.js FAILS, then restore.
4. `npm test` no longer halts at test_smoke.js: the chain proceeds past it in-sandbox (run timeboxed
   ≤5 min foreground per build.md; if the full 31-file chain exceeds the timebox, evidence = the
   chain output showing test_smoke.js green and subsequent files executing).
5. Diff touches ONLY test files (test_smoke.js, optionally a new shared fixture module +
   test_search.js requiring it) and the item's bookkeeping files. No product code, no new
   dependencies, no `package.json` changes.
