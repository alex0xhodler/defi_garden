# 117.1 — Pool-detail Sharpe annotation (surface leg 1 of 117)

First surface for the shipped 117 compute leg (`apyMean`+`apySharpe` in `compute-kpis.js`, #267,
2026-07-17). 117's spec mandates surfaces ship "one at a time, pool-detail first" — this is that leg.
Read `specs/117.md` for the full meaning, the honesty caveat, and the RISK_FREE_APY=4.0 benchmark.

## Evidence
- 117 compute leg SHIPPED (#267, verifier PASS HIGH 4/4): `pool.kpis.apySharpe` and `pool.kpis.apyMean`
  are now computed and baked into the daily pools snapshot — `null` for <8 history points or sd=0.
- `apySharpe` stays `null` until a pool accrues ≥8 daily history points (~2026-07-22 on the retained
  file-history). So the annotation renders dormant now and lights up automatically as points accrue —
  the same "land now, improves as data accrues" pattern the compute leg itself used.
- The render seam already exists: `PoolDetail.js` ~L1316–1360 (the 088.1 "rate track record" block)
  already surfaces `pool.kpis.apyStdev` + `pool.kpis.historyPoints` with neuro styling and a null-safe
  `historyPoints >= 1` guard. 117.1 extends this exact block — no new render surface invented.

## Hypothesis
We believe surfacing a rate-stability Sharpe on pool-detail (with the principal-risk caveat) will
strengthen the trust signal on the SEO arrival surface — the quantified form of 088's "steady 6% beats
spiky 20%" — because a single honest, one-sentence-explainable number reads as more trustworthy than the
raw stdev alone. Confidence: supported (extends a shipped render pattern + a human-directed KPI; no
isolable funnel metric at current traffic).

## Change
Smallest version: in the existing 088.1 rate-track-record block in `PoolDetail.js`, when
`pool.kpis.apySharpe` is a finite number (not null), render ONE additional line next to the stdev note:
the Sharpe value, the named risk-free benchmark ("vs a ~4% risk-free rate"), and the mandated
principal-risk caveat framing ("how steady this pool's yield has been relative to how much it pays — not
a measure of principal safety"). Reuse the block's existing neuro classes — ZERO new CSS.

OUT OF SCOPE (each its own later sub-item per 117): the analytics-app "risk-adjusted" sort (117.2), the
planner blend preference (117.3), any cross-pool ranking UI. This item is the pool-detail annotation ONLY.
