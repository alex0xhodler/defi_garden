## Problem

`buildStaticSurfaces()` (`audit-app.js:163-211`) spreads its sample **uniformly** over the sorted leaf list via `sampleBySeed()`. Default budget = anchor + 6 pages/day against 2,176 pages ⇒ a specific known-bad page is found with p ≈ 1.3%/day, and only by luck. The rendered checks that would catch it (`junk-slug` P1 at `:467-473`, `zero-yield-claim` P1 at `:476-478`, `empty-table` P1 at `:483-486`, `number-sanity` P0 via `auditText`) are already correct — they simply almost never get pointed at a bad page.

## Design (chosen: B — cheap prescan + promotion)

Rejected **A** (persist audited slugs, prefer never-audited ones): needs a state file the loop must keep in git, still spends the render budget uniformly, and would take ~360 days to walk the set once. It does not prioritise *suspicion*, which is the whole point.

### B.1 `prescanStaticPages(opts)` — new, exported

Pure `fs` + regex over **every** leaf page from `listLeafPages('tokens')` + `listLeafPages('chains')` (existing helper at `:129`; already excludes `index.html`, and `tokens/az/*` is excluded for free since it only lists files). No Playwright, no network, no writes. Per file: read, drop `<script>…</script>` and `<style>…</style>` blocks, capture the `<h1>` inner text, then strip remaining tags to get visible text.

Signals — reuse the EXISTING constants where they exist (`JUNK_SLUG_NUMERIC`, `JUNK_SLUG_DATE`, `ZERO_YIELD_CLAIM`), do not mirror a fourth copy of the 148 predicate:

| signal | severity | rule |
|---|---|---|
| `junk-slug` | P1 | `<h1>` lead token matches `JUNK_SLUG_NUMERIC` or `JUNK_SLUG_DATE` |
| `zero-yield-claim` | P1 | `ZERO_YIELD_CLAIM` matches visible text |
| `broken-number-literal` | P0 | `/(^|[^A-Za-z0-9$])(NaN|Infinity|undefined|null)(?![A-Za-z0-9])/` on visible text |
| `absurd-magnitude` | P0 | `/(^|[^A-Za-z0-9])-?\$?[0-9][0-9,.]*\s?[TQ]\b/` on visible text — the tightened form measured 0/2,176 above; the loose form must NOT be used |

Returns `{ scanned, suspects: [{ rel, slug, signal, severity, detail }] }`, suspects sorted P0-first then `rel` (deterministic). A file that cannot be read is skipped with a stderr note — never throws.

### B.2 Promotion into the rendered sample (`buildStaticSurfaces`)

- Promote up to `prescanMax` suspects (`opts.prescanMax` / `AUDIT_STATIC_PRESCAN_MAX`, default **4**, clamped to `sampleSize`) as `static-page:<slug>` surfaces — the same shape/name the rotation already produces.
- If suspects exceed the cap, choose among them with `sampleBySeed(suspectRels, cap, seed + ':prescan')` so successive days work through the backlog of suspects instead of re-rendering the same four.
- Promoted rels are **excluded from the uniform pick lists**, and the uniform rotation fills only the remaining `sampleSize − promotedCount`. Total render budget is unchanged — this re-aims the budget, it does not grow it.
- `AUDIT_STATIC_PAGES` still replaces everything verbatim (unchanged contract), and prescan is **off** in that mode so existing controls stay predictable. Kill switch: `opts.prescan === false` / `AUDIT_STATIC_PRESCAN=0`.

### B.3 Findings + result shape

- One **aggregate** finding per signal that has ≥1 suspect: `{ surface: 'static-prescan', viewport: 'n/a', check: 'static-prescan:<signal>', severity, detail: '<n> of <scanned> static SEO pages … examples: …' }` with **at most 10 example slugs** (a systemic defect must not emit 2,000 findings).
- Per-page rendered findings for the promoted pages come from the existing static checks, unchanged. Aggregate + rendered finding for the same page is intended: one says *how many*, the other is render-confirmed.
- `runAudit()` result gains `prescan: { scanned, suspectCount, bySignal, promoted: [slugs] }`. `surfacesCovered` keeps its shape.
- **Expected behaviour change, on purpose**: while item 148's 7 junk pages are still live on `main` (PR #306 unmerged), a default `node audit-app.js` now exits non-zero with a `static-prescan:junk-slug` P1 finding every run instead of ~1 run in 75. That is the detector being correct, and it self-clears when #306 merges.

### B.4 Docs

Header env table + `playbooks/product-audit.md`: prescan-before-render as the standard way to hunt a page *class* across a large generated surface.

## Acceptance criteria (rendered where it matters — standing decision 2026-07-11)

1. **Full-set equivalence, real checkout**: `prescanStaticPages()` reports `scanned ≥ 2000`, and its `junk-slug` suspect set is *exactly* the set of on-disk leaf pages whose `<h1>` lead token matches the junk predicate — asserted by re-deriving both sides from disk, never by hardcoding today's 7 slugs (the set churns daily).
2. **False-positive control, real checkout**: the digit-leading real tickers `tokens/0x0.html`, `tokens/1inch.html`, `tokens/3crv.html`, `tokens/a0t.html` appear in NO suspect list (`a0t` specifically guards the tightened magnitude regex).
3. **Promotion works, REAL Chromium render**: with a temp junk probe page written into `tokens/` (a copy of a real token page with a date-shaped `<h1>` lead), a default-config `runAudit({ staticOnly: true })` both covers `static-page:<probe-slug>` in `surfacesCovered` and emits a per-page rendered `junk-slug` P1 finding for that surface. Probe removed in `finally`.
4. **Non-vacuity**: the same run with `prescan: false` does NOT cover the probe slug — proving criterion 3's coverage came from promotion, not from a lucky uniform pick (p ≈ 0.3%).
5. **Aggregate findings**: a prescan-enabled run emits `static-prescan:junk-slug` whose count equals the independently re-derived on-disk junk count, with example slugs in the detail; signals with zero suspects emit nothing.
6. **Determinism**: two runs with the same seed give identical `prescan.promoted` and identical `surfacesCovered`; when suspects ≤ cap, a *different* seed still promotes the same set (promotion is suspicion-driven, not seed-driven).
7. **Budget unchanged**: static surfaces in a default run ≤ anchor + `sampleSize`.
8. **No regressions**: `test_audit_app.js` and `test_seo_surface_audit.js` stay green unchanged.

New tests live in `test_audit_prescan.js`, wired into `package.json` immediately after `test_seo_surface_audit.js`.

**Timing constraint**: each static leaf page holds DOMContentLoaded ~10s (absolute `https://www.defi.garden/analytics.js` defer tag, sandbox-blocked — documented in `test_seo_surface_audit.js`'s header). Dispatch the rendered cases concurrently on separate ports via `Promise.all`, keep them to ≤ 3, and stay inside the 5-minute foreground timebox.
