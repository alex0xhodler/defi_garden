# Spec 016: Re-brand the empty-state action buttons — kill the gradient one-offs

## Evidence
Human prod review (dark-mode screenshot, 2026-07-10): "Show pools with lower TVL" (teal gradient) and "Reset Filters" (blue gradient) in the analytics empty state are visibly off-brand against the neumorphic system. Both use `.reset-filters-btn` (app.js:2746/2750), a class predating the neumorphic redesign (commit 68ef0a7). They became prominent under 012's improved empty state. Human directive (now a standing decision): reuse components, keep design tidy.

## Hypothesis
Pure design-debt cleanup; no metric hypothesis. Guardrail: don't reduce the affordances' clarity — they're the recovery path out of a dead-end state.

## Change
Smallest version:
1. Find the analytics app's existing on-brand button pattern (grep style.css/pool-detail-styles.css for the standard neumorphic button used elsewhere in the app — e.g. filter pills / modal buttons). If a suitable shared class exists: apply it to these two buttons and delete `.reset-filters-btn`'s gradient rules. If none is reusable as-is: re-token `.reset-filters-btn` in place — `--color-surface` background, `--neuro-shadow-raised`, `--neuro-radius-md`, token typography, `:active` → `--neuro-shadow-pressed` (press physics), visible `:focus-visible` ring, dark-mode automatic via tokens. NO gradients, NO new colors.
2. Visual hierarchy within the pair: primary action ("Show pools with lower TVL", when present) may use the accent text color; both stay calm.
3. No copy changes (strings already exist in EN+KO), no logic changes, no new classes unless replacing the old one 1:1.

OUT of scope: the empty-state layout (012 owns it), any other `.reset-filters-btn`-adjacent refactor, planner surfaces.

- [ ] If a shared button class was reused: no duplicated near-identical CSS remains; if re-tokened: `.reset-filters-btn` contains only token values
