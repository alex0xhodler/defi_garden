## The bug (two facets, one root cause)
The "**Garden this pool →**" CTA on pool-detail deep-links into the planner with
`plan.html?goal=retirement&pace=<tier>&capital=<lumpSum>&fm=capital&years=5` (PoolDetail.js:253).
A genuine **share link** (buildShareUrl, planner.js:965–1000) produces the **identical param shape** — `goal`+`pace`+`capital`/`monthly`+`fm`+`years` — with **no distinguishing marker**. So `sharedPlan = decodePlanFromUrl(urlParams)` (planner.js:4062) is truthy for BOTH, and the planner cannot tell a self-initiated pool CTA from a share a third party sent.

Consequences, both confirmed by rendered Playwright (scratchpad/ns_clickthrough.js, 2026-07-25 — clicking the real CTA on lido stETH):

1. **Honesty / trust bug (UX).** The pool-CTA arrival renders the share-recipient framing:
   - Arrival banner `arrivalBannerText`: **"Someone sent you this garden — it's already set up and ready to grow."** (planner.js:3802 / translations.js:298)
   - Intro line `sharedPlanIntro`: **"Someone shared their garden — make it yours."** (planner.js:4347 & 4737 / translations.js:247)
   Nobody sent it — the user clicked a CTA on our own pool page. A false "someone shared this with you" claim at the exact conversion moment undermines the trust moat (CLAUDE.md/NORTH_STAR: "Trust is the conversion currency… honest numbers beat exciting numbers").

2. **Metric-integrity bug.** planner.js:4067–4073 fires `Analytics.trackShareLinkOpened(...)` for **any** `sharedPlan`, so every "Garden this pool" arrival emits a `share_link_opened` event. That pollutes the viral-loop metric `share_link_opened → plan_created` (the closure the loop tracks; signals note "1 share_link_opened ever" — contaminable by pool-CTA arrivals). The garden_cta CLICK is already counted (`pool_click{source=garden_cta}`); the arrival must NOT double-count as a share open.

## Root-cause fix (surgical, one marker)
Make the two entry paths distinguishable via an explicit source marker, and branch honestly.

1. **PoolDetail.js:253** — append `&src=pool` to `gardenThisPoolHref` (covers both the hero CTA :555 and the repeat-footer CTA :1626 — single definition). No other PoolDetail change.

2. **planner.js** — derive `poolSourced` = (`sharedPlan` truthy AND `urlParams.get('src') === 'pool'`). Genuine share links never set `src`, so this cleanly separates them.
   - **Honesty:** when `poolSourced`, the arrival banner text and both `sharedPlanIntro` sites (4347, 4737) render **pool-honest copy** instead of the "someone sent/shared" copy. The prefilled plan, the "Make it mine" affordance, and the fast-forward-to-bloom behavior are UNCHANGED — only the attribution copy changes.
   - **Metric:** when `poolSourced`, **suppress** the `trackShareLinkOpened` call (4067–4073). A pool CTA arrival is not a share open. (No replacement event — the click is already tracked on the pool page.)

3. **translations.js** — add EN + natural KO for:
   - `arrivalBannerTextPool` — honest pool-sourced banner text.
   - `sharedPlanIntroPool` — honest pool-sourced intro.
   Reuse existing `arrivalBannerCta` ("Make it mine") / `arrivalBannerDismiss`. EN + KO updated together (one language alone = verifier FAIL).
   Suggested copy (builder may refine, must stay honest — no "someone/shared/sent"):
   - EN banner: `"Here's your plan, prefilled from the pool you picked — make it yours."`
   - EN intro: `"Prefilled from the pool you picked — make it yours."`

4. **buildShareUrl (planner.js:965–1000)** — defensively `u.searchParams.delete('src')` alongside the existing `delete('preset')/delete('fresh')` (999–1000), so a user who arrived via `?src=pool` and then shares does not propagate the marker into a genuine share link. Confirm buildShareUrl builds from state (does not blindly carry the current query).
