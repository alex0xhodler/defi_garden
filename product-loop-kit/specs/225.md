# Spec 225: DESIGN RESET — one clean-minimal system, neumorphism stripped (human directive Q2b)

## Evidence
- Human verdict (2026-08-04, verbatim intent): the UI is "below any amateuristic ui back from the 2020
  ... now it's all over the place."
- The structural cause, measured: TWO design systems coexist — the analytics app is 2020 google-mimic
  chrome (`.google-header-*`, `.google-control-btn`, `.google-nav-tab`) while the planner/landing run the
  post-2026 neumorphic token system (`--neuro-*`); loops patched seams for 3 weeks (217/218/220/222 all
  fixed chrome-collision bugs BETWEEN the eras) without ever being allowed to remove the seam.
- Item 222's build notes: at ≤640px the google-era header cannot even fit its own controls — the era is
  structurally broken at mobile widths, not just dated.

## Hypothesis
We believe one sanctioned whole-surface rebuild onto a single clean-minimal token system will make the
product feel coherent and trustworthy, because the incoherence is the seam between two eras — a global
property no sequence of local fixes can reach (three weeks of evidence).
Confidence: supported.
- Instance of: cross-era design-system divergence; population = every rendered surface (landing,
  planner, analytics home, grid, pool-detail, static SEO page chrome).
- Class closed by this item: yes IF all surfaces land in one pass — a partial reset just moves the seam.
  Static SEO page chrome (tokens/, chains/ templates) may ship as a fast-follow regen; if so, state the
  page count left open.

## Change
One item, one dispatched Opus agent, one written design spec (the build's first deliverable — reviewed
in the same pre-merge round):
- NEW single token system: clean, minimal, calm — flat surfaces, 1px hairline borders or single soft
  shadow, existing accent family (#3B82F6), generous whitespace, visible focus rings, dark mode
  first-class. STRIP every `--neuro-*` skin usage; DELETE the `.google-*` era chrome. One header pattern,
  one card pattern, one control set across landing/planner/analytics/pool-detail.
- Byte-untouched: trust rails, `__APP_MODE` router, URL behavior, analytics event emitters,
  translations keys (copy unchanged — this is skin, not content), formatUsd/formatNum/formatApy.
- CLAUDE.md design section REWRITTEN in the same commit (the "keep it neumorphic" mandate is overridden
  — standing decision 2026-08-04 Q2b).
- Gates: full rendered Playwright regression + occlusion lens zero-findings on ALL surfaces at
  360/768/1280 × light/dark; the 136-class CTA-visibility checks; KO renders.
- **HUMAN PRE-MERGE REVIEW (carve-out from autonomy (c), this item only):** the build ends by producing
  a screenshot set (4 surfaces × 3 widths × 2 themes) delivered for the human's approval; merge only on
  their explicit yes. Review rounds are expected; each round's feedback becomes spec addenda.

<!-- Build loop appends findings from the blindspot pass here. -->
Blindspot pass, 2026-08-04 (read-only recon; written design spec = `specs/225-design-system.md`):

1. **`--neuro-*` cannot be deleted outright — it is a PUBLISHED contract, not just a skin.** ~4,281
   generated static pages (`tokens/*.html` ×~4,190, `chains/*.html` ×91, hubs) bake `var(--neuro-shadow-raised)`
   / `-flat` / `-pressed` / `-subtle` / `--neuro-radius-*` into an inline `<style>` block written by
   `generate-token-pages.js` / `generate-chain-pages.js`, and **7 test assertions** across
   `test_chain_pages.js` (L207/530/639), `test_token_pages.js` (L210/590/700) and `test_hub_pages.js` (L61)
   assert the literal string `var(--neuro-shadow-raised)` is present in generator output. Deleting the
   definitions would leave those pages referencing dead custom properties. Decision: the names survive as
   **deprecated aliases pointing at the flat system** (225 acceptance #1 explicitly permits kept
   definitions) — so the SEO estate inherits the reset for free and no generator/test churn is needed.
   Skin USAGES in the four hand-written stylesheets still go to zero.
2. **Dark mode was already half-wired.** `[data-theme="dark"]` (style.css:4225-4290) re-tints only the four
   neuro shadow tokens — `--neuro-bg/-surface/-text/-radius-*` are never redefined for dark — and a
   separate `@media (prefers-color-scheme: dark)` block (165-240) re-tints the same four again. The reset
   must give dark a real surface ramp in BOTH places, or the flat system inherits light surfaces in dark.
3. **Four `.google-*` classes are already dead** (styled, never rendered): `google-tools-dropdown`,
   `google-tools-btn`, `google-tools-panel`, `google-nav-content`. Delete rather than rename.
   `style.css:1966` references `var(--neuro-shadow-inset)`, **a token defined nowhere** — dead too.
4. **The rename has structural test coupling**, not just string coupling: `test_nav_rail_ia.js` (L117-293),
   `test_mobile_controls_reachable.js` (L279-613) and `test_category_taxonomy.js` (L181-254) query
   `.google-nav-tab` / `.google-nav-primary` / `.google-nav-secondary` / `.google-nav-divider` /
   `.google-filter-btn` / `.google-header-sticky` / `.google-header-controls` / `.google-search-input`
   directly. They must be renamed in the same commit or the suite goes red on a green product.
5. **Committed build artifacts must be regenerated in the same commit**: `node compile-app.js` +
   `node minify-assets.js` — `test_compiled_assets.js` and `test_minified_assets.js` byte-compare the
   committed `.compiled.js` / `.min.js` / `.min.css` against a fresh transform, and
   `test_css_minified_render.js` / `test_min_asset_boot.js` boot the minified bundles in real Chromium.
   `landing-styles.css` and `stories/stories.css` have no minified variant and are served raw.
6. **The occlusion quarantine is a pre-existing red on exactly the surfaces this item restyles.**
   `test_audit_app.js:106` quarantines `grid-360`, `grid-token`, `grid-chain` (item 221's still-open
   defect, PR #386 PARKED). This item does not inherit an obligation to fix 221, but it must not ADD
   quarantine entries, and `pool-detail*` must stay at zero occlusion findings (the 217/218 rail).
