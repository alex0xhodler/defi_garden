# 089 — Default browse sort → TVL, not APY

Status: IN_PROGRESS (2026-07-14)
Risk: LOW
Score: 7.5
Coupled prerequisite: 092 (0%-yield demote/tag in the TVL sort) — SHIPPED 2026-07-14.

## Evidence / why
- Human analytics-UX audit (2026-07-14, BACKLOG row 089): the analytics browse grid
  defaults to APY sort (`app.js:765` `useState('apy')`). APY-first tops the grid with
  anomalous / reward-decayed pools — the opposite of what the cautious retail ICP
  (NORTH_STAR: "size = safety signal the cautious saver reads first") scans for.
- TVL-first matches the DeFi mental model and is what SOTA yield tables default to.
- The app already ships an intentional, non-user APY anomaly-demote
  (`app.js:1700-1704` etc., `!userSortedApy` branch) — evidence the product already
  treats raw-APY-first as untrustworthy for the default view.
- COUPLING (human note on the row): TVL-first surfaces 0%-yield collateral pools at the
  top of the list unless they're demoted. 092 shipped exactly that demote + an honest
  "No supply yield" tag in the `sortBy === 'tvl'` branch, so the prerequisite is met and
  the top rows will NOT read a stark "0%".

## Change (smallest that satisfies)
- `app.js:765`: `const [sortBy, setSortBy] = useState('apy');` → `useState('tvl')`.
- Nothing else. The three filter/sort `useEffect` branches (token-first, chain-first,
  token-mode) already handle `sortBy === 'tvl'` with the 092 demote (yielding pools
  before no-supply-yield, then TVL desc). The APY/TVL toggle
  (`app.js:2912-2917`) and the `userSortedApy` semantics are untouched:
  - initial state `sortBy='tvl'`, `userSortedApy=false` → TVL sort (092 demote active).
  - clicking APY → `setSortBy('apy'); setUserSortedApy(true)` → raw APY sort (anomalies
    shown but ⚠-flagged/High-risk, existing behavior — user explicitly asked for APY).
  - clicking TVL → `setSortBy('tvl'); setUserSortedApy(false)` → back to TVL.
- Regenerate `app.compiled.js` + `app.compiled.min.js` (home.html loads the min — the
  062/061 "min never regenerated" bug class).
