# 089 — BUG (human ticket 2026-07-14, follow-up to 085): capital shown before risk selection, computed from the wrong rate, inconsistent across the UI

Status: IN_PROGRESS (2026-07-14)
Risk: HIGH (planner onboarding + bloom render paths; regenerated planner.min.js; degen-haircut adjacent)
Score: 8.4 — human-reported consistency bug at the SUBSCRIPTION front door (the product's core archetype
per the 2026-07-12 business-model decision). Honest numbers are the moat; three different "capital"
values for one plan is a trust failure.

## Report (human, verbatim intent)

Strip shows "🌱 Saving for ChatGPT Plus · 💰 $4,400 capital" BEFORE the user selects a risk level.
"This should not happen before the user selects risk level in the onboarding, because then you can
really calculate how much he needs … to cover the $20 threshold per month, given the blended rate —
also this value should be used in the right column — best to unify these values across the UI and
standardize metrics."

## Root cause (operator triage, read-only)

- `planner.js:3829-3839` (`pickGoal`, subscription branch): the moment a subscription goal is picked,
  `answers.capital` is seeded as `ceil100(foreverNumber(goal.target, guidanceApy))` where
  `guidanceApy = stableGuidanceApy || 5.5` (planner.js:3565) — a PRE-RISK, stable-pinned guidance rate
  (~5.45% → $4,400 for $20/mo). Flow then advances to 'temperament' (risk).
- `planner.js:3946-3948`: the 💰 strip row renders whenever `answers.capital != null` for
  subscription/target — i.e. DURING the risk step, before any persona exists.
- The seeded value is never recomputed after the persona pick: Bloom receives `capital: answers.capital`
  (planner.js:4377) while its own `apy` is the persona's blended curated rate — so the right-column
  sidebar shows the stale guidance-rate capital while checkout's `mixStats(selectedSubs, apy)` derives a
  DIFFERENT needed-capital from the real rate (e.g. rwa ≈ 10.6% → ≈ $2,300, vs the displayed $4,400).
  Three surfaces, up to three numbers, one plan.

## The standardized metric (the unification invariant — this is the deliverable)

For a capital-funded subscription plan:

> **capital-needed = ceil100( foreverNumber( combined monthly of the selected mix, the plan's blended
> persona APY ) )** — computable only once a persona exists, with the degen ⅓ haircut INSIDE the rate
> (allPersonaApy pattern, planner.js:1409-1414: degen = raw/3 — the haircut is a trust rail, never
> bypassed by a seeding path).

Every surface renders from this single derivation (or from the user's explicit override — a deep-linked
`?capital=` or a manual slider/chip edit — which wins everywhere once made, also uniformly).

## Change

1. `pickGoal` (subscription branch): stop seeding capital — `capital: null`. The 💰 strip row therefore
   cannot render before the risk step is answered (its `answers.capital != null` guard already does the
   hiding — verify, don't assume).
2. `pickPersona`: for a subscription goal on the capital path with NO user-provided capital (no deep-link
   `?capital=`, no manual edit), seed `answers.capital` from the invariant above using the CHOSEN
   persona's blended rate — the SAME rate expression the temperament card displayed and Bloom will use
   as `apy` (trace both; they must be one expression, not two near-copies; extract a helper if needed).
   Degen persona seeds from the haircutted rate.
3. Bloom: confirm by construction + assert by test that strip 💰, the right-column sidebar capital, and
   checkout's `mixStats([goal], apy).neededCapital` all equal the invariant for a fresh arrival (modulo
   the shared ceil100 rounding — same rounding everywhere, standardize if they differ).
4. Explicit capital preserved: deep links (`?goal=…&capital=1000&fm=capital`, the 067 case), shared
   plans, and manual edits keep the user's number everywhere (no re-seed clobber — check the
   shared-plan fast-forward gate at planner.js:3814-3825 and the preset autoplay at 3799-3812 still
   sequence correctly with capital now seeded at persona-pick time).
5. `guidanceApy` remains for what it still legitimately does pre-risk elsewhere (target-archetype
   funding-mode hints, monthly chip hints — out of scope to change); the subscription seeding is the
   only consumer being moved post-risk. Document any other subscription-path guidanceApy consumers found
   (e.g. planner.js:4060-4070 funding-mode ladder — reachable for subscription only via the strip's
   💰 edit tap AFTER a persona exists; if so, it should use the persona rate then — fix if small, else
   document as follow-up).
6. planner.min.js regenerated, idempotent.
