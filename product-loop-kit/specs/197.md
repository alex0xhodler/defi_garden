# Spec 197: the audit's static population is half-size — bring the 2,186-page `/ko/` estate into the scan

## Evidence

All measured on `origin/main` @ `44f1c4013`, heartbeat tick 2026-08-01 (`signals/2026-08-01.md`).

1. **The population is built from exactly two calls, and there is no third.**
   - `audit-app.js:1398` — `const rawPages = opts.pages || listLeafPages('tokens').concat(listLeafPages('chains'));` (`prescanStaticPages`)
   - `audit-app.js:2016-2017` — `listLeafPages('tokens')` / `listLeafPages('chains')` (`buildStaticSurfaces`, the rendered rotation)
   - `grep -n "'ko'\|\"ko\"\|/ko/" audit-app.js` → **no path-level match**. The only `ko` hits are three app routes: `:3472` `pool-detail-ko` (`&lang=ko`), `:3478` `planner-ko`, `:3487` `plan-bloom-ko`.
2. **Population sizes, counted with `listLeafPages`'s own predicate** (`isFile() && .endsWith('.html') && name !== 'index.html'`):
   - EN — `tokens/` + `chains/` = **2,186** leaf pages (the number the tick reports as `prescan.scanned`).
   - KO — `ko/tokens/` + `ko/chains/` = **2,186** leaf pages. **Exactly 50% of the estate, never scanned.**
3. **The KO pages are distinct, live, indexed surface — not aliases.**
   - `cmp tokens/usdc.html ko/tokens/usdc.html` → **DIFFER**; 18,698 B vs 19,887 B.
   - `ko/tokens/usdc.html` carries `<html lang="ko">` and real Hangul body copy (`디파이 수익률 — 기준 실시간 …`).
   - Submitted to Google: `sitemap-token-pages-ko.xml` **2,127** `<loc>` + `sitemap-chain-pages-ko.xml` **88** = **2,215 KO URLs**.
4. **The covered-surface list is the direct proof.** This tick's `surfacesCovered` = **60**; the 7 `static-page*` entries are `tokens/{shit,wtao,cscbusdc,kysol}`, `chains/{solana,ethereum}` and the anchor. `JSON.stringify(surfacesCovered).match(/\/ko\//g)` → **null**.
5. **Sized honestly before ticketing — the cheap signals are clean on KO today.** Running the real exported function over the KO leaves:
   `prescanStaticPages({pages: koLeaves})` → `{scanned: 2186, suspects: []}`.
   The KO half also emits **42,604 links and 3,696 distinct `?pool=` ids — identical counts to EN** — so item 184's liveness verdict genuinely transfers and needs no re-run.
6. **The defect history is real.** Item **190** was a KO-only defect on these exact 2,201 landers (`landing.footerPoweredBy` / `landing.footerMadeWith` rendering English). It was found by a `translations.js` dictionary diff — a different checker. The estate scan could not have found it then and cannot today.

## Hypothesis

We believe **passing the KO directories through the same two collection points** will **close a 50% population gap in the audit** because **the gap is a missing argument, not a missing mechanism** — `listLeafPages(dir)` already takes a directory, `prescanStaticPages` already takes `opts.pages`, and item 196 already built persisted never-audited-first rotation state that a second leg can reuse. Confidence: **validated-pattern** (this is `detector-signal-coverage.md`'s "transplant rule" — the mechanism is written, tested and exported; applying it to a sibling population is a call, not a build).

Corollary hypothesis, stated so the item is not oversold: **we expect it to ship green.** Evidence 5 measured 0 suspects on the offline signals. The value delivered is the **render-only** classes (`dead-cta`, i18n leaks, 360px clipping, console errors) reaching KO pages for the first time, plus every future signal covering the whole estate by construction instead of half of it.

## Change

Smallest version that closes the gap:

1. **Prescan leg** — extend the default population at `audit-app.js:1398` to include `listLeafPages('ko/tokens')` and `listLeafPages('ko/chains')`. `opts.pages` override behaviour unchanged.
2. **Rendered-rotation leg** — give `buildStaticSurfaces()` KO candidates alongside the EN ones, reusing **196's existing persisted rotation state** (`product-loop-kit/signals/audit-static-rotation.json`). Two options; the builder picks one and states why in `197-notes.md`:
   - (a) two extra rotation legs (`koTokens`, `koChains`) with their own `seen` sets, mirroring the existing `tokens`/`chains` legs; or
   - (b) one merged candidate list per family with `seen` keyed by the full rel path.
   **(a) is the recommended default** — it keeps each leg's `seen` cap checkable against its own disk-read population count (see risks), and it makes KO coverage separately reportable.
3. **Budget** — the rendered static sample must not silently halve EN coverage to make room. Either raise the static sample so EN throughput is unchanged, or state the new per-family budget explicitly in the notes with the measured wall-clock. Item 192 measured ~0.19s marginal per rendered surface and the run sits well inside `FOREGROUND_CAP_MS`; measure, do not estimate.
4. **Reporting** — `prescan.scanned` and the rotation blocks must make the two populations distinguishable (e.g. `scanned: 4372` with a per-family breakdown). A single merged number that jumps 2,186 → 4,372 with no breakdown makes it impossible for the next reader to tell EN-clean from KO-clean.

**Explicitly OUT of scope:**
- Any change to the KO pages themselves or to `generate-token-pages.js` / `generate-chain-pages.js`. This is a detector item; if the new coverage finds a real defect, **file it, do not fix it here** (`detector-signal-coverage.md`, step 3 / the 175 precedent).
- New signals. Existing predicates over a larger population only.
- `tokens/az/` and `ko/tokens/az/` — the A–Z index directories are correctly excluded by `listLeafPages`'s `isFile()` filter (`audit-app.js:171` documents it). Leave them out.
- `poolLinkLiveness` re-runs over the KO half: evidence 5 proves the id set is identical, so re-resolving 3,696 ids a second time buys nothing and doubles the live-fetch cost. State this in the notes as a deliberate omission with the measurement behind it, per 196's "port the part whose precondition holds" rule.

- [ ] `prescanStaticPages()` with no `opts.pages` scans **4,372** pages (2,186 EN + 2,186 KO), asserted against a **disk-read count**, never a literal — the count must be derived by the test the same way `listLeafPages` derives it, so the assertion survives daily estate churn.
- [ ] A `runAudit()` result's `surfacesCovered` contains **at least one** rendered `static-page:ko/…` surface, and the assertion greps for the `ko/` path prefix (the failing check today).
- [ ] The rotation state file records KO progress: after two consecutive simulated ticks threading state tick-to-tick, the KO leg's `seenCount` **advances** and the second tick renders **no page the first tick already rendered** (196's own invariant, applied to the new legs).
- [ ] **Seen-cap invariant:** each leg's rotation cap is asserted **greater than that leg's real disk-read population**. (196's trap: a cap below the population makes `unseen` never empty and silently defeats the fix. `ROTATION_SEEN_CAP = 2000` against a 2,186-page leg would do exactly this — this item's populations are *larger* than the pool leg's, so this is a live risk, not a theoretical one.)
- [ ] **Positive control, executed:** a **copy** of a real KO page in a scratch dir, mutated to carry one known signal (e.g. a `junk-slug` or a `broken-number-literal`), is detected by the KO leg — and the original's `md5sum` is asserted **unchanged**, so the proof can never have come from editing the estate (184's standard).
- [ ] **True negative, executed:** the unmodified committed KO estate scans **clean** (matching this spec's evidence 5). If it goes red, the finding is real — **file it as a new item, do not relax the signal and do not fix the emitter here.**
- [ ] Per-family counts are readable in the findings JSON — a reader can tell EN-clean from KO-clean without reading the code.
- [ ] Wall-clock: a full `node audit-app.js` run completes inside `FOREGROUND_CAP_MS` with `status: "OK"`, and the measured wall-clock before/after is recorded in `197-notes.md`.
- [ ] Tests: a new/extended case in `test_audit_static_rotation.js` (and `test_audit_prescan.js` for the population count), **registered in `package.json`'s `test:serial` chain** — `run-tests.js` parses that chain and does not glob `test_*.js`, so an unregistered test is a gate that never runs. State the lane (anything requiring `audit-app.js` lands in the **browser** lane, transitively).
- [ ] Instrumentation: **none.** This is an internal detector with no user-facing surface and no analytics event. Stated explicitly so its absence is a decision, not an omission.
