# 210 — pool-detail IA: the same numbers five times, and the CTA nowhere near the intent peak

**Tier: HIGH** (verifier-assigned independently — see verdict block at the bottom).
Full walkthrough per the HIGH-tier rule, quiz at the end.

## Goal

The pool-detail page is the north-star surface: `pool_click{source ∈ garden_cta, protocol_link}`
is the metric, and both CTAs live here. A human UX audit on 2026-08-02 counted, on ONE rendered
screen: the `~$1,288 in 5y` projection **3×**, the `$4.32` monthly figure **2×**, the base/reward
split **2×**, the `$1,000` basis restated **4×**, the disclaimer **2×**, and the entire CTA block
**verbatim 2×**. Three of Pool Information's six tiles duplicated the hero.

This item is a **re-ordering and de-duplication, not a redesign** — every component and CSS class
is kept.

## The intuition

Sections 2–6 of the old page were **five presentations of one computation**: the Long Game card,
the daily card, the monthly card and the calculator all render `investmentAmount × rate` over
different periods. The three stat cards literally *were* the calculator's output at its default
input. A visitor scrolled the same arithmetic four times before reaching anything new.

Two consequences, both bad for a cautious-saver ICP:

1. **`Daily earnings $0.14` was the page's most prominent number** — the least compelling true
   statement the page can make to someone thinking in life goals.
2. **The CTA was not at the intent peak.** The repeat CTA sat at the page bottom, *after* the
   reference tiles. The actual peak — the moment a user types their own amount into the
   calculator — had no CTA on screen at all.

New order: **credibility → the headline number → your number → act → reference detail.**

## What changed, in reading order

### `PoolDetail.js` — hero (`.pool-hero-card`)

- **Risk level moved into the trust-indicator chip row**, next to `✓ Verified` and the TVL badge,
  reusing the sibling `trust-badge` class and its inline-style shape; `riskAssessment.color` tints
  the text and `riskAssessment.description` survives as the chip's `title`. The standalone
  `.metric-card-simple.risk-card` is deleted. Credibility signals now sit together, and `Low risk`
  is no longer stranded three sections away from the APY it qualifies.
- **The mutually-exclusive rate-quality note tier moved under the APY breakdown**, inside
  `.pool-action-card`: `.rate-volatility-note` (071), `.rate-track-record-note` (088.1) and
  `.rate-history-unavailable-note` (207), relocated verbatim — same conditions, classes, copy;
  only `marginBottom` tightened to `0` because `.pool-action-card`'s flex column already gaps its
  children. These three are the only content on the page DefiLlama does not have, and they used to
  render below a collapsible fold under six reference tiles. They are a mutually-exclusive chain,
  so moving them as a group preserves the "exactly one renders" invariant exactly.
  `.rate-momentum-note` (103) and `.tvl-trend-note` (104) deliberately stayed in Pool Information.
- **Hero primary CTA label shortened** to the plain `gardenThisPoolCta` ("Garden this pool →").
  The `~$X in 5y` forecast moves to the earnings block where the user controls the input — a button
  should name the action, not carry a projection the user has not yet parameterised. Because the
  label is now always generic, the hero's `ctaVariant` is hardcoded `'generic'`: leaving the old
  `showConcreteCta ? 'concrete' : 'generic'` expression there would have made the event *lie* about
  what is on the button.
- The secondary protocol CTA is untouched — `.cta-button-protocol` already reads as secondary
  against `.cta-button-primary`'s solid fill, so demoting it needed no style change. Deliberate
  no-op rather than invented styling.

### `PoolDetail.js` — the merged earnings block (`.calculator-compact`)

The standalone `.pool-projection-card` and the entire `.quick-metrics` grid (daily card, monthly
card, risk card) are **deleted as top-level sections**. Their content is merged input-first into
`calculator-compact`:

1. amount input + preset chips (already first — kept),
2. the Long Game headline, relocated verbatim and recomputing live from the input, including the
   `isAnomalous → projectionBodyOutOfRange` branch and the `projectionKeepNote` frame line
   ("Your deposit stays yours — you keep your money, and it keeps working") — the v3 yield-funded
   pitch, kept word for word,
3. the 1D/7D/30D toggle feeding one readout. The toggle is kept intact (removing user control was
   never the goal) with `activeCalculatorTab` still defaulting to `'30days'`, so `$0.14/day` is
   never the first figure rendered.
4. **the moved CTA block**, at the end of the block — the intent peak.

The moved CTA sits **inside `.calculator-compact` but outside the `calculatorExpanded &&` guard**,
so collapsing the calculator does not remove the page's second conversion point. Its
`ctaPlacement` changes `'repeat_footer'` → **`'earnings_block'`** on both the garden-CTA payload and
the `renderProtocolCtaBlock()` call. That rename is load-bearing: it is the entire reason this
rearrangement is measurable from the existing event, with no new instrumentation. It keeps the
concrete `~$X in 5y` label, because by this point the user has set their own number.

The page-bottom CTA block is deleted. Nothing renders after Pool Information.

### Deviations worth calling out

The first two were caught by the verifier rather than volunteered by the builder, which is itself
worth recording; the third is an honest note about the tension between them:

- **`riskAssessment.factors` no longer renders anywhere.** The deleted risk card had a fourth line,
  ``Key factors: ${factors.slice(0,2).join(', ')}``. The hero chip carries `level` + `.description`
  only. Defensible — the spec named only those two as the content to move, and the factor strings
  are hardcoded English (`'Low liquidity'`, `'Newer protocol'`, …) with no `translations.js`
  entries. But it is rendered content that vanished, and it went unlogged until review.
  **`factors` is now entirely dead display data.** `getRiskAssessment()` still computes it
  alongside `score` — but `score` does **not** depend on it: at `PoolDetail.js:291-364` each branch
  independently does `riskScore += N` *and* `factors.push(...)`, and the return is
  `{ …, factors, score: riskScore }`. Deleting every `factors.push()` call would leave `score`,
  `gardenPersona`, `applyDegenHaircut` and the ⅓ haircut bit-for-bit unchanged. (An earlier draft of
  this file claimed `factors` "feeds `riskAssessment.score`" and was therefore load-bearing for a
  trust rail. That was **wrong**, and it is the kind of wrong that gets a future editor to preserve
  dead code out of misplaced caution — corrected here rather than silently dropped.)
- **`riskAssessment.description` is a `title` tooltip, not visible text.** Spec §1 said to move
  "`level` + `.description`". A one-line chip between "✓ Verified" and the TVL badge cannot carry
  a sentence without breaking the row at 360px. The description is reachable on hover but no
  longer visible at rest — a small, accepted reduction in what a non-hovering reader sees.
- **Honest note on the i18n reasoning, because the two bullets above are in tension.**
  `description` is *equally* hardcoded English (`'Conservative DeFi strategy'`, `'Moderate risk
  profile'`, `'Advanced DeFi strategy'`, `'Anomalous yield — extreme caution'` at
  `PoolDetail.js:301` and `:352-362`, none routed through `t()`), and it **is** carried into the
  chip's `title` — so untranslated English still ships on a KO render, hover-only. The translation
  argument therefore does not by itself justify dropping `factors` while keeping `description`; the
  real reason is the chip's one-line size budget. The net effect is nonetheless in the right
  direction: **210 reduces untranslated English on the KO pool-detail page.** Previously both
  `factors` and `description` rendered as visible English text in the risk card; now one is gone
  and the other is hover-only. Routing both through `translations.js` is a clean follow-up item.

### `PoolDetail.js` — Pool Information

`BASE APY`, `REWARD APY` and `POOL TYPE` tiles removed (all three duplicated the hero); a `TVL`
tile added using the existing `t('tvl')` key so the grid stays balanced; `.rate-momentum-note` and
`.tvl-trend-note` promoted **above** the tile grid — prose insight outranks reference data.
Underlying Assets unchanged.

## The defect caught in review, and the fix

The first implementation put the degen-haircut warning, the anomaly warning and the single
`.calc-disclaimer` **inside the `calculatorExpanded &&` guard**. `calculatorExpanded` defaults to
`true`, so every visual check passed — but collapsing the calculator is one click, and in that
state:

- an anomalous pool rendered its raw APY in the hero with **no ⚠ flag anywhere on the page**,
  breaking the demote-AND-flag convention, which is a trust rail;
- a degen-tier pool lost its ⅓-haircut disclosure the same way;
- the moved CTA (correctly outside the guard) still displayed a concrete `~$X in 5y` projection
  with no disclaimer on the page at all.

Before this item those three lived on an always-visible top-level node, so this was a genuine
regression in a reachable state — and a trust-rail weakening is on NORTH_STAR's NEVER list, which
would have made the item non-mergeable rather than merely wrong.

**Fix:** all three are now always-rendered siblings of the collapsible content — after it, before
the moved CTA — so they survive `calculatorExpanded === false`. Classes and copy verbatim; only
position changed.

**New guard, not a weakened one:** `test_pool_detail_anomaly_projection.js` gains criteria 7 and 8.
Criterion 8 clicks the calculator header, **waits for `.calculator-content` to detach** — proving
the collapse actually happened, so the assertion cannot pass vacuously — then asserts the anomaly
warning, the degen-haircut warning and the disclaimer each still render exactly once, and both
CTAs stay visible.

**No new event.** `pool_view` and `pool_click{source}` already measure this surface exactly. The
only payload changes are the two described above: the hero's honest `ctaVariant: 'generic'`, and
`ctaPlacement: 'earnings_block'` on the moved CTA. All three emitters — `garden_cta`,
`protocol_link`, `defillama_fallback` — keep byte-identical `source` strings.

## Residual risk for the human

- **`analytics.js:251`'s comment is now stale** — it documents `ctaPlacement` as
  `'hero' | 'repeat_footer'`, and `repeat_footer` is no longer emitted anywhere. The code on that
  line is a generic pass-through (`context.ctaPlacement || null`) and functions correctly. But:
  **any saved Mixpanel report or dashboard filtering `ctaPlacement = 'repeat_footer'` reads zero
  from this deploy onward.** That break is intended and spec-mandated — it is how the move becomes
  measurable — but someone should know before reading a dashboard as a regression.
- **Dead CSS left behind:** `.quick-metrics` (`pool-detail-styles.css:704`, `:996`;
  `style.css:4513`) and `.risk-card` (`pool-detail-styles.css:901-913`, including a decorative
  gradient `::after`) now target nodes that never render. Correctly left untouched — CSS files are
  outside this item's declared file scope — but worth its own cleanup item.
- **Orphaned translation keys:** `dailyEarningsSubLabel`, `monthlyEarningsSubLabel` and `poolType`
  now have zero `t()` call sites. Harmless, deliberate.
- **Semantic nit:** a High-risk pool renders a chip classed `trust-badge` reading "Risk Assessment:
  High". No functional or visual defect (colour is inline; the class rule never touches `color`),
  no dependent CSS/JS/test, but the name no longer strictly means "trust signal".
- Pixel-level QA is still loop-side only; a visual spot-check of the rearranged page (light + dark,
  360/768/1280) is worth a minute of human eyes.
- The rearrangement is judged correct on IA principle, not on measured conversion. At n≈0 that is
  the honest ceiling — no conversion claim is made.
