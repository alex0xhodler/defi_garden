# Spec 198: finish 190's i18n predicate — `identical` is half the rule; the other half is `no Hangul`

## Evidence

All measured on `origin/main` @ `44f1c4013`, heartbeat tick 2026-08-01 (`signals/2026-08-01.md`).

1. **The rule was written down before the gate was built, and the gate implements half of it.**
   `playbooks/product-audit.md` class 5(2), authored 2026-07-31 from item 190's own investigation, states it verbatim:
   > *"A KO value byte-identical to its EN value **AND containing no Hangul** (`/[가-힣ᄀ-ᇿ㄰-㆏]/`) is untranslated."*
   The shipped `prescanI18n` tests only the first conjunct. The exported constant is named `I18N_IDENTICAL_ALLOWLIST` and the signal is `en-ko-parity`.

2. **Mutation probe against the real exported function** (`prescanI18n({dict})` — injected dictionaries, no fixture files, no render):

   | EN value | KO value | actually untranslated? | gate verdict | correct? |
   |---|---|---|---|---|
   | `Powered by` | `Powered by` | yes | **flagged** | ✅ |
   | `Powered by` | `Powered by ` (one trailing space) | yes | **clean** | ❌ **miss** |
   | `Powered by` | `Powered by the DefiLlama feed` | yes | **clean** | ❌ **miss** |
   | `Powered by` | `제공` | no | clean | ✅ |
   | `$100` | `$100` | no — a bare figure | **flagged** | ❌ **false positive** (needs an allowlist entry it should never have needed) |

3. **The miss is worst in the exact scenario the gate exists for.** Keying on *sameness* means the gate's alarm depends on a property of the **EN** string. The day anyone rewords an EN string without touching KO, the pair stops being identical and **the gate goes silent** — at precisely the moment the KO value has become stale English. It is a drift detector that switches itself off on drift.

4. **No live instance today — stated plainly so this is not oversold.** Full flattened three-namespace scan of `translations.js` this tick (top-level 185 + `landing` 41 + `planner` 319 = **543** keys):
   - KO values containing zero Hangul: **24**
   - Byte-identical EN/KO pairs: **24**
   - **The two sets are the same 24**, and all 24 are allowlisted, each with a stated reason, every one a brand name (`Claude Pro`, `Apple TV+`, `Uber One`, `Spotify`, `Netflix`, `Hulu`, `Peacock`, `DoorDash`, `Audible`, `Walmart+`, `Max`, `ChatGPT Plus`, `Leviathan News`, `DefiLlama API`) or an acronym (`TVL`, `APY`, `LP/DEX`, `RWA`).
   - `no-Hangul AND not-identical AND not-allowlisted` = **0**.
   → This is a **gate-coverage** item, not a repair. It ships with a historical positive control or it proves nothing.

5. **The allowlist was separately audited this tick and is clean** — checked because `product-audit.md` 5(3) says the allowlist is exactly where this check will rot. 24/24 entries are brands or acronyms with one-line reasons; no ordinary prose has been allowlisted into silence.

## Hypothesis

We believe **adding the Hangul conjunct** will **make the gate detect untranslated KO prose regardless of whether it is byte-identical to its EN twin, and stop it firing on values that are legitimately identical for non-linguistic reasons** because **"is this string Korean?" is a property of the KO value alone, while "is it the same as EN?" is a property of the pair — and only the first one is what the gate is actually trying to assert.** Confidence: **supported** (evidence 2 is a direct probe of the shipped function; the corrected predicate is already written down in the repo's own playbook).

Secondary, and worth stating because it is the cheap win: a `no-Hangul`-based predicate should let the **allowlist shrink**, since a bare figure like `$100` is no longer a suspect at all. Do not force this — report the resulting allowlist size and justify every entry that remains.

## Change

Smallest version that tests the hypothesis:

1. Change the suspect predicate in `prescanI18n` from `en === ko` to **`!HANGUL.test(ko)`**, with `HANGUL = /[가-힣ᄀ-ᇿ㄰-㆏]/` — the exact character class the playbook specifies, defined **once** and exported so tests interpolate it rather than re-typing it (the item-159 rule).
2. Re-derive the allowlist against the new predicate: **remove any entry that the new predicate no longer flags** (a stale allowlist entry is indistinguishable from a silenced bug to the next reader), keep the brand/acronym entries it still needs, and keep the one-line reason on every survivor. Report `allowlistSize` next to `suspectCount` as 190 already does.
3. Consider renaming the exported constant so its name matches what it now allows (e.g. `I18N_UNTRANSLATED_ALLOWLIST`). **Optional** — if renamed, keep a re-export under the old name or update `test_audit_i18n_parity.js` in the same commit; a rename that silently breaks a test import is worse than the old name.

**Explicitly OUT of scope:**
- Any change to `translations.js`. There is no live instance (evidence 4); if the new predicate finds one, **file it as a separate item, do not fix the strings here** — fixing the emitter inside a detector item destroys the positive control (`detector-signal-coverage.md`, step 3).
- Key parity (`en-ko-parity`'s existing key-set diff), the KO currency-unit check (`test_ko_pool_money_honesty.js`, item 137), and page wiring (`test_i18n_pages.js`). Those are the other two of the playbook's three i18n levels and they are separately covered.
- Widening to other languages. EN/KO is the whole dictionary today.
