# Spec 223: Stop serving the repo's internals on www.defi.garden (.vercelignore)

## Evidence
Verified live 2026-08-04 (curl, prod): `test_min_asset_boot.js`, `audit-app.js`, `generate-stories.js`,
`test_planner.js`, `product-loop-kit/NORTH_STAR.md`, `product-loop-kit/BACKLOG.md`,
`product-loop-kit/LOG.md`, `CLAUDE.md`, `.claude/agents/verifier.md` → **all 200**. No `.vercelignore`
exists; `vercel.json` has no exclusion mechanism.
Measured consequence in prod analytics: `/plan?lang=ko%60` ×2 session_starts on 08-03 (`bc8d0dd0`) —
`%60` is the closing backtick of `test_min_asset_boot.js:262`'s template literal
(`` `/plan.html?lang=ko` ``), scraped by a URL-extracting crawler from the served raw JS. Grep proves no
generated href emits that string (tokens/, chains/, sitemaps, llms*.txt, shipped app JS: 0 hits).
NOT a secrets breach: the GitHub repo is public and credentials are never committed (standing decision
2026-07-09). The harm is: crawl-budget waste on the SEO-moat domain; internal strategy docs indexable
beside `llms.txt` (an AI-discovery surface we cultivate — an LLM crawler can quote BACKLOG.md in answers
about defi.garden); and a live fuzz-URL mint feeding phantom planner arrivals.

## Hypothesis
We believe a `.vercelignore` excluding dev/test/tooling/internal-doc classes removes the exposure and the
fuzz-URL mint without touching any runtime behavior, because every file the running product needs is
enumerable and small relative to the repo. Confidence: supported (runtime asset classes are known;
the risk is entirely in the enumeration, which is why acceptance is a both-ways curl matrix).

## Change
Smallest version: one `.vercelignore` file. Exclude: `test_*.js`, `run-tests.js`, `audit-app.js`,
`generate-*.js`, `minify-assets.js`, `product-loop-kit/`, `.claude/`, `docs/`, `.agent-reviews/`,
`*.md` internal docs (CLAUDE.md, README-class files — but NOT any .md a runtime fetch or rewrite serves;
check `vercel.json` rewrites for the item-212 markdown-twin routes BEFORE excluding any .md or `tokens/*.md`
— the 212 twins are a LIVE feature and must keep serving), `telegram-bot/`, `whatsapp-bot/`, `workers/`
(never deployed surface; also OUT-OF-SCOPE dirs — excluding them from deploys is allowed, MODIFYING them
is not), fixtures/scratch dirs.
KEEP serving (the load-bearing allowlist): `home.html`, `plan.html`, all app bundles + `.min`/`.compiled`
twins (`app*`, `planner*`, `PoolDetail*`, `landing*`, `translations*`, `analytics.js`, `canonical.js`),
all CSS, `data/` (fetched client-side at `app.js:1253` and by the snapshot-first path), `tokens/`,
`chains/`, `stories/`, `sitemap*.xml`, `llms*.txt`, `robots.txt`, og/social images, favicons, and the
`tokens/*.md` twins if 212 serves them from disk.
OUT of scope: `vercel.json` rewrites (sacred parameterized-URL behavior — zero diff); deleting any file
from the repo; robots.txt changes.

## Acceptance criteria
- [ ] Post-deploy curl matrix, BOTH directions, committed to the notes: every runtime asset class above →
      200 with correct content-type; every excluded class (at least: one `test_*.js`, `audit-app.js`, one
      `generate-*.js`, `product-loop-kit/BACKLOG.md`, `CLAUDE.md`, one `.claude/` path) → 404.
- [ ] The item-212 markdown-twin route still serves (curl a `/tokens/<slug>` with `Accept: text/markdown`
      → the .md twin, exactly as before).
- [ ] Both router paths render live: bare `/` → planner, `/?token=USDC` → grid with pool cards.
- [ ] `/data/pools-snapshot.json` and `/data/pools-snapshot-meta.json` → 200 (snapshot-first paint intact).
- [ ] A pre-deploy dry run enumerates what would be excluded (e.g. compare `vercel build`/deploy file list
      or a scripted glob against the ignore rules) and its output is in the notes — the enumeration is
      checked BEFORE the deployment spends quota, not discovered after.
- [ ] Tests: none apply in-repo (deploy-config); the curl matrix IS the gate. Non-vacuity: the matrix's
      excluded-class leg must show the 404s (against the pre-change 200 transcript recorded in Evidence).

## Measurement
Metric: none isolable (hygiene under the pre-traffic mandate). Informational watch: fuzz-shaped planner
arrivals (`lang=ko%60`-class URLs) in the URL-provenance check should stop appearing for freshly-crawled
URLs. Decision rule: keep unconditionally if the curl matrix passes both ways.

## Risk tier (builder's guess — verifier assigns independently)
HIGH — deploy-config/infra governing what exists on prod; one deployment against the Vercel free-tier
quota (the 2026-07-13 quota decision applies: ONE commit, no follow-ups). Mis-enumeration breaks prod
harder than the exposure ever would — when in doubt about a file, keep serving it.
