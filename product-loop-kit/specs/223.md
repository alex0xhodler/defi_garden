# Spec 223: Stop serving the repo's internals on www.defi.garden (.vercelignore)

## Evidence
Verified live 2026-08-04 (curl, prod): `test_min_asset_boot.js`, `audit-app.js`, `generate-stories.js`,
`test_planner.js`, `product-loop-kit/NORTH_STAR.md`, `product-loop-kit/BACKLOG.md`,
`product-loop-kit/LOG.md`, `CLAUDE.md`, `.claude/agents/verifier.md` → **all 200**. No `.vercelignore`
exists; `vercel.json` has no exclusion mechanism.
Measured consequence in prod analytics: `/plan?lang=ko%60` ×2 session_starts on 08-03 (`bc8d0dd0`) —
`%60` is the closing backtick of `test_min_asset_boot.js:262`'s template literal
(`` `/plan.html?lang=ko` ``), scraped by a URL-extracting crawler from the served raw JS. Grep proves no
generated href emits that string (tokens/, chains/, sitemaps, llms*.txt, shipped app JS: 0 hits).
NOT a secrets breach: the GitHub repo is public and credentials are never committed (standing decision
2026-07-09). The harm is: crawl-budget waste on the SEO-moat domain; internal strategy docs indexable
beside `llms.txt` (an AI-discovery surface we cultivate — an LLM crawler can quote BACKLOG.md in answers
about defi.garden); and a live fuzz-URL mint feeding phantom planner arrivals.

## Hypothesis
We believe a `.vercelignore` excluding dev/test/tooling/internal-doc classes removes the exposure and the
fuzz-URL mint without touching any runtime behavior, because every file the running product needs is
enumerable and small relative to the repo. Confidence: supported (runtime asset classes are known;
the risk is entirely in the enumeration, which is why acceptance is a both-ways curl matrix).

## Change
Smallest version: one `.vercelignore` file. Exclude: `test_*.js`, `run-tests.js`, `audit-app.js`,
`generate-*.js`, `minify-assets.js`, `product-loop-kit/`, `.claude/`, `docs/`, `.agent-reviews/`,
`*.md` internal docs (CLAUDE.md, README-class files — but NOT any .md a runtime fetch or rewrite serves;
check `vercel.json` rewrites for the item-212 markdown-twin routes BEFORE excluding any .md or `tokens/*.md`
— the 212 twins are a LIVE feature and must keep serving), `telegram-bot/`, `whatsapp-bot/`, `workers/`
(never deployed surface; also OUT-OF-SCOPE dirs — excluding them from deploys is allowed, MODIFYING them
is not), fixtures/scratch dirs.
KEEP serving (the load-bearing allowlist): `home.html`, `plan.html`, all app bundles + `.min`/`.compiled`
twins (`app*`, `planner*`, `PoolDetail*`, `landing*`, `translations*`, `analytics.js`, `canonical.js`),
all CSS, `data/` (fetched client-side at `app.js:1253` and by the snapshot-first path), `tokens/`,
`chains/`, `stories/`, `sitemap*.xml`, `llms*.txt`, `robots.txt`, og/social images, favicons, and the
`tokens/*.md` twins if 212 serves them from disk.
OUT of scope: `vercel.json` rewrites (sacred parameterized-URL behavior — zero diff); deleting any file
from the repo; robots.txt changes.

## Territory notes
<!-- Build loop appends findings from the blindspot pass here. -->

**The spec's own suggested exclude list was wrong about `auth.md`.** This
spec's "Change" section named `auth.md` alongside `CLAUDE.md`/`README.md`/
`SITEMAP.md` as a root-level internal doc to exclude. It is not one:
`.well-known/oauth-authorization-server.json` and
`.well-known/openid-configuration.json` both set their `agent_auth.skill`
field to `https://www.defi.garden/auth.md`, and `auth.md` itself instructs
arriving agents to read those same two `.well-known` endpoints — it is part
of the site's agent-auth discovery loop, one hop removed from the
`.well-known/agent-skills/index.json` → `SKILL.md` pattern this spec's own
facts already warned about. `test_vercelignore.js`'s link-integrity check
(built per this spec's acceptance criterion, step 3e) caught this on its
first run, before any deploy — it is the reason that check exists rather
than a nice-to-have. `auth.md` was kept off the denylist. Full account in
`specs/223-notes.md` § "Deviation from the spec's suggested exclude list".

**Vercel already hides a small set of well-known filenames, independent of
any `.vercelignore`.** With no `.vercelignore` in existence at all (verified
before writing one), `/package.json`, `/package-lock.json`, `/README.md`,
`/vercel.json`, and `/.gitignore` were already 404 on prod, while
`/CLAUDE.md`, `/auth.md`, `/SITEMAP.md`, `/LICENSE`, `/.mcp.json` were all
200. This is Vercel's own static-deploy convention for recognized
package-manager/build-config filenames, not anything this repo configured —
worth knowing so a future curl audit doesn't mistake one of those 404s for
evidence a `.vercelignore` rule caused it.

**No build script exists.** `package.json` has no `"build"` key — confirmed
by reading the file directly. Vercel therefore uploads the static tree
as-is on every deploy; `.vercelignore` is the only lever available, exactly
as this spec assumed. Do not add one as a side effect of a future item near
this file without re-reading this note.

**The markdown-twin trap is real and easy to hit by accident.** `tokens/`,
`chains/`, `ko/**`, and `pools/` all interleave `.html` and `.md` files with
identical basenames (e.g. `tokens/usdc.html` + `tokens/usdc.md`). Any
future `.vercelignore` pattern written as a bare `*.md` (unanchored, no
directory scope) would delete the entire item-212 markdown-twin feature
across all four directories at once — thousands of files — while looking
like a small, reasonable-sounding line. This item's denylist never uses an
unanchored `.md` pattern anywhere, and `test_vercelignore.js`'s MUST-KEEP
allowlist asserts a `.md` twin sample from each of the four directories by
name specifically to catch this class of regression in the future.
