# 149 — PR explainer (HIGH tier: full walkthrough + quiz)

Risk tier **HIGH**, assigned independently by the verifier — not for what the change *does* (loop tooling,
no product surface, no trust rail) but for its size: `audit-app.js`'s diff is 154 lines against NORTH_STAR's
150-line LOW cap, and an infra resolver rewrite isn't cleanly "copy/docs/tests/instrumentation". Policy says
when in doubt → HIGH, so: HIGH. No NEVER-list category is touched, so it auto-merges under standing
autonomy (c) once this explainer exists.

---

## Goal

`node audit-app.js` must never fail *quietly*.

## The intuition

`audit-app.js` (item 142) is the scanner that mechanizes the **primary job of every pre-traffic heartbeat**
— NORTH_STAR's 2026-07-23 mandate, `heartbeat.md` §2b: with ~0 traffic there is no funnel to optimize, so
the loop's job is to keep the product from being broken, and this script is how that gets checked
mechanically instead of by hand.

Which makes its failure mode nastier than an ordinary crash. The script's only durable output is
`product-loop-kit/signals/audit-findings.json`. When it died, it died *before* writing anything — so
**yesterday's file stayed on disk**. A future heartbeat reading that file sees ten surfaces covered and zero
findings and records "audit clean". The audit never ran. Nothing in the artifact says so.

That is the same class as items 078 and 141 — a reassuring signal sitting on top of work that didn't happen
— arriving by a new route. There the lie was an unconditional `echo "✅"`. Here the lie is **silence**: an
absent write, read as an unchanged verdict.

## What was actually wrong

Line 35 of the old file:

```js
const { chromium } = require('playwright');
```

Module-level. Every cloud-routine session starts from a **fresh clone with no `node_modules`**, so this
threw `MODULE_NOT_FOUND` before a single line of audit logic ran — and before the write. Hit first-hand on
the 2026-07-26 heartbeat.

The maddening part: nothing was actually missing. `playwright` **is** declared in `devDependencies`, and it
**is** installed globally at `/opt/node22/lib/node_modules`. The heartbeat proved it by re-running with
`NODE_PATH` set and getting the real result (10 surfaces, 0 findings). Only the *resolution* was wrong.

Hence the spec's explicit out-of-scope list: no dependency added or bumped, no `npm install` at audit time.
Installing something already present would be treating the symptom.

## What changed, in reading order

**1. `audit-app.js` header comment.** Documents the two new env hooks beside the pre-existing
`AUDIT_SNAPSHOT_PATH`/`AUDIT_PORT`, and states the exit-code contract in one place.

**2. The top-level `require` is gone.** That single deletion is what makes `require('./audit-app.js')`
survive a fresh clone — which the test suite depends on, and which is why the new test is red on `main`
before it can assert anything else.

**3. `resolvePlaywright()` (new, ~70 lines — the bulk of the diff).** Tries, in order, stopping at the first
hit:

| # | source | how |
|---|--------|-----|
| 1 | `local` | bare `require('playwright')` — the normal, non-degraded path |
| 2 | `global` | `require(<npm root -g>/playwright)`, `execSync` with a 10s timeout |
| 3 | `global-fallback` | hardcoded `/opt/node22/lib/node_modules`, skipped when identical to #2 |

It logs which one won and at what version. `AUDIT_PLAYWRIGHT_ROOT`, when set, collapses all of this to a
single root — that's the hook the test uses to make "unresolvable" reproducible on any machine, including
ones that *do* have `node_modules`. Version lookup can never throw; it degrades to `'unknown'`.

**4. `runAudit()` resolves as its first action** — before the snapshot read, before the server starts. A
missing engine now fails fast and leaves no orphan HTTP server behind. On `null` it throws with
`code = 'AUDIT_PLAYWRIGHT_UNRESOLVED'`.

**5. The artifact is always written.** Success gained `status: 'OK'` and `playwright: { source, version }`.
The CLI's `.catch` now writes, on *any* fatal error:

```json
{ "status": "DID_NOT_RUN", "reason": "...", "attempts": [...], "surfacesCovered": [], "findings": [] }
```

to the same out path — deliberately **overwriting** the stale file. That overwrite is the entire point of
the item; a crash must destroy the previous verdict, not inherit it. The write is itself try/caught so a
write failure still exits non-zero.

**6. Exit codes made explicit:** `0` clean · `1` P0/P1 findings present · `2` other fatal · `3` playwright
unresolvable. Code `1` is item 142's contract and is unchanged — the inline P0/P1 filter was lifted verbatim
into an exported `blockingFindings()` (sole addition: an `f &&` null-guard) so that contract is testable
without a full audit run.

**7. `AUDIT_OUT`** redirects the artifact, so tests never clobber the real signals file.

**8. `test_audit_runner.js` (new, 9 assertions, ~0.5s, no browser).** Module loads with no `node_modules`;
`resolvePlaywright()` resolves naturally, and returns `null` — without throwing — against an empty root; a
real child-process run with an unresolvable engine exits non-zero and leaves a `DID_NOT_RUN` artifact;
`git status` is byte-identical across that run; and a source-text assertion pins the CLI's exit line.
Wired into `npm test` (the only `package.json` edit — no dependency change).

## Deviations from the spec

1. **AC5's "`git status --porcelain` is EMPTY" is asserted as before/after byte-identity**, not
   absolute-empty. An absolute check is unsatisfiable while the item's own work is legitimately uncommitted.
   The before/after form proves the property that matters — the script writes nothing into the repo — and
   the builder confirmed it still catches a real regression by temporarily making the child leak a file
   (assertion failed as intended, then reverted).
2. **`GLOBAL_FALLBACK_ROOT` never fires here**, because `npm root -g` already equals it, so step 2 always
   wins and step 3 is skipped by its own identity guard. Structurally reachable, empirically not on this
   box. Flagged so nobody hunts for a `source: 'global-fallback'` that can't appear.
3. **`resolvePlaywright.lastAttempts`** carries the failure reasons out-of-band (a property on the function)
   rather than changing the success return shape. The verifier **empirically confirmed this value goes
   stale** after an intervening successful call, since success paths never clear it — and equally confirmed
   it is *not* misread in shipped code: one call site, synchronous, read only on the immediately-following
   null branch. Left as-is rather than patched after a PASS verdict; recorded here as a known-fragile
   pattern to harden if a second call site ever appears.
4. **154-line diff**, marginally over the LOW cap — the reason the verifier tiered this HIGH. Every added
   line traces to an explicit spec requirement.
5. **`signals/audit-findings.json` kept regenerated** rather than reverted. It is the first artifact
   carrying the new `status`/`playwright` fields, from a legitimate offline run against the committed
   snapshot. The verifier judged this in-scope: writes into `signals/` are the tool's normal output.

## Proof

Non-vacuity was proven **twice, independently**. Builder and verifier each restored `origin/main`'s
`audit-app.js`, watched the suite go red (8/9 — only the git-status check passes trivially, since nothing
ran), restored, and watched it go green (9/9, 0.49s).

The verifier re-ran everything itself rather than reading the transcript: the unassisted `node audit-app.js`
(exit 0, `playwright resolved from global (1.56.1)`, `status: "OK"`, 10/10 surfaces, 0 findings); the forced
failure (exit **3**, `DID_NOT_RUN`, empty `surfacesCovered`); a copy of the script in a scratch dir to
confirm the crash path *would* overwrite the real signals file without leaving the repo's file in that
state; `test_planner.js` 208/208; and independent reproduction that `test_dead_pool.js` /
`test_token_pages.js` fail from missing `node_modules` in files this diff never touches.

Worth stating plainly: those two failures are **the same bug this item fixes, in other files**. 149's scope
is `audit-app.js` only, so they stay broken — ticket-worthy separately, not silently absorbed.

## Quiz

1. The script crashed and wrote nothing. Why is writing *nothing* worse than writing a wrong result?
2. `playwright` was declared in `devDependencies` and installed globally the whole time. So what exactly was
   broken, and why did the spec forbid fixing it with `npm install`?
3. `AUDIT_PLAYWRIGHT_ROOT` exists only for tests. Why couldn't the "playwright is unresolvable" case be
   tested without it?
4. On the failure path the artifact is written to the *real* `signals/` path, overwriting whatever was
   there. Why is that destructive behavior the point rather than a hazard?
5. The verifier proved `resolvePlaywright.lastAttempts` genuinely goes stale, then passed the item anyway.
   What makes that consistent rather than a soft call?
