# Spec 169: give the text-surface scanner a link signal (`link-target-integrity`)

## Evidence

`prescanTextSurfaces()` (item 160, `audit-app.js:230`) scored **`suspectCount: 0`** on the exact two files that were, at that moment, carrying **32 mis-targeted links** — the defect item 166 later fixed by hand-verification against live prod.

Re-derived on this checkout (pre-166 artifacts = `git show 3935e8d05:llms.txt` / `:llms-full.txt`, the commit immediately before `aff271c79` "166: the AI-discovery surface's links now go where they claim"):

| class | pre-166 `llms.txt` | pre-166 `llms-full.txt` |
|---|---|---|
| pool rows linking to the **bare origin** | 0 | **15** |
| links carrying an **unrouted query key** (`?search=`) | **7** | **10** |
| one URL shared by pool rows stating **different figures** | 1 URL (`?token=WETH-USDC&chain=Base`, 2 distinct figure sets) | 1 URL (bare origin, 15 distinct figure sets) |

`prescanTextSurfaces()`'s entire signal set is `apy-rail-breach`, `broken-number-literal`, `tvl-floor-claim`, `empty-surface` — **every one a number-or-emptiness check**, because 160 was specced from 159, and 159 was a number bug. The links were invisible by construction.

That is the third instance of one pattern, stated in the backlog row for this item:

> 148 → 159 → 166: the checker's signals are drawn from the last bug found, so the next bug always lands in the class nobody has been bitten by yet.

Item 167 fixed exactly this root cause for pool *targets* (one hand-picked flagship pool → prescan-then-promote). This item is its text-surface twin, for *claims* — a generated text surface asserts "this row is about pool X, and here is its link"; nothing has ever checked that the link goes there.

## Hypothesis

We believe adding a `link-target-integrity` signal to `prescanTextSurfaces()` converts the 166 class from hand-found to automated, because all three sub-rules are decidable from committed bytes alone (URL text + the line it sits on), and the pre-166 artifacts are a preserved, executable positive control. Confidence: **supported for the known class** (proven RED on the pre-166 bytes, GREEN on today's, both measured before writing this spec); the open bet is whether link-shape checking generalises to the *next* unknown class.

## Change

One new signal in the existing `prescanTextSurfaces()` — same file, same pure fs+regex shape, same aggregate-finding emission. No new pass, no new surface, no product file.

`link-target-integrity` — severity **P1** (a mis-targeted link is a routing/claim defect, not a false number; `tvl-floor-claim` is the severity precedent for "the surface says something untrue about itself"). Registered in `TEXT_SURFACE_SIGNALS` so severity stays single-sourced and the `bySignal` block/aggregate finding come for free.

Three sub-rules, each contributing at most one suspect per file (the 160 convention: **one suspect per file per signal**, so a systemic breach cannot flood findings — 15 bad rows are one suspect whose `detail` quotes examples):

1. **(a) unrouted query key** — every query key on every emitted `defi.garden` URL must be a member of `ANALYTICS_PARAMS ∪ PLANNER_PARAMS ∪ {lang}`, **parsed out of `home.html`** (the router's own arrays, `home.html:77-78`) at scan time. A second hardcoded copy of the param list is a FAIL — that is the bug class this signal exists to catch, and 160's `APY_SANITY_LIMIT` single-sourcing is the precedent. If `home.html` cannot be read or the arrays cannot be parsed, rule (a) is **skipped with a stderr note** and the other rules still run (the `prescanTextSurfaces()` never-throws contract).
2. **(b) pool row → bare origin** — a *pool-shaped* line (the existing `TEXT_POOL_LINE_APY` + `TEXT_POOL_LINE_TVL` predicates: the line carries both a `% APY` figure and a `TVL` figure) whose only link is the bare origin (`https://www.defi.garden` or `…/`, no path, no query). A row describing a specific pool that links to the homepage tells the reader nothing.
3. **(c) one URL, two different figure sets** — two or more pool-shaped lines sharing an identical URL while stating **different** figures (`…% APY` / `$… TVL` literals extracted from the line). Identical rows repeated verbatim are not a defect; two different pools pointing at one destination is.

Explicitly OUT of scope:
- Any change to `generate-llms.js`, `llms.txt`, `llms-full.txt` or any generated surface. 166/168 already fixed the emitters; this is the gate that keeps them fixed. **Detector only.**
- Extending the signal to HTML surfaces (`prescanStaticPages`), sitemaps, or OG cards. One surface family per item (160's own rule).
- Fetching or resolving any URL. Pure fs+regex, no network, no render — a link to a *slug that doesn't exist* is a different, more expensive check and is deliberately not attempted here.
- Non-`defi.garden` links (DefiLlama, protocol sites): out of scope, we do not own their shape.

- [ ] Tests: new cases added to the existing `test_audit_text_surfaces.js` (do **not** create a second text-surface test file); the file stays browser-free and runs in ~1s. Already wired into `test:serial` at position 96 — no `package.json` change expected.

Metric: **none — loop tooling.** No 14-day window. Success is observable at the next heartbeat: `signals/audit-findings.json` either shows `link-target-integrity: 0` (the surface's links are honest) or tickets a real routing defect without a human curling prod.

## Territory notes

- `prescanTextSurfaces()` lives at `audit-app.js:230`; signals table at `:208`; pool-line predicates at `:217-218`; aggregate emission at `:1449-1465`; kill switch `AUDIT_TEXT_SURFACES=0` at `:1444`. The new signal needs no new kill switch — it rides the existing one.
- `home.html:77-78` are literal single-line JS array declarations (`var ANALYTICS_PARAMS = ['token', …];`). A tolerant regex per array name (`var NAME = [ … ];` → split on quoted strings) is enough; do **not** execute `home.html`.
- `lang` is genuinely absent from both router arrays (it is read by `translations.js`, not the router) and is live in real URLs — hence the explicit `∪ {lang}` in rule (a). Today's committed artifacts use only `chain, minApy, minTvl, pool, poolTypes, preset, protocols, token`, so the `lang` allowance is a forward-guard, not a fudge for existing bytes.
- Rule (b) fires on `llms-full.txt` only in the pre-166 control (15 rows); pre-166 `llms.txt`'s bare-origin links sit on non-pool-shaped lines, so it is clean under (b) and red under (a)+(c). Do not "fix" that by loosening (b) to all lines — the header/footer of both files legitimately links to the homepage.
- Rule (c)'s figure extraction must ignore surrounding prose: extract the `…% APY` and `$… TVL` literals from the line, compare the extracted tuple, not the whole line (whole-line comparison makes every row trivially distinct and the rule vacuous).
