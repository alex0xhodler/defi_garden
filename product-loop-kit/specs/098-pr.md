# 098 — NL search: a bare protocol name filters by protocol, not a same-named token (HIGH)

## Goal
Human ticket 2026-07-14: typing "pendle" in the analytics search dead-ended ("No yields found for PENDLE") instead of showing Pendle's pools. Fix the NL parser so a bare protocol name is treated as a protocol search.

## Root cause
"pendle" is both a token symbol (PENDLE — 29 live pools, none above the $10M floor) and a protocol (pendle — 160 pools, 6 above the floor). `parseNaturalLanguageQuery` extracted `token='PENDLE'` (which the handler prioritises) alongside `protocols=['Pendle']`, so it filtered to PENDLE-symbol pools → below the floor → empty state, and the protocol/category signal never drove the result. Pre-existing; 091 surfaced it by adding the Yield-Derivatives category.

## The change (app.js, ~4 lines, end of `parseNaturalLanguageQuery`)
```js
if (token && protocols.some(p => p.toLowerCase() === token.toLowerCase())) {
  token = '';
}
```
When the extracted token is literally the same word as a protocol we matched, drop it. The handler already routes a token-less protocol query into "All chains" mode filtered by the protocol — so Pendle's pools (across all their underlying tokens) now show. Narrow by design: "usdc on aave" keeps token USDC (USDC ≠ Aave).

## Trust rails
Untouched — the change only reassigns a local `token` variable in the parser. No rail constant, sort, or flag touched.
