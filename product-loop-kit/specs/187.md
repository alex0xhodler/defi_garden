# 187 — the entire design system is held hostage by an unused third-party font CDN

**Status when written:** promoted by the build loop 2026-07-31 under `build.md`'s no-READY branch
(every backlog row 001–186 is SHIPPED / DONE / PARKED / BLOCKED; `git ls-remote origin
'refs/heads/claude/loop-187'` empty). Evidence is a live measurement made this run, reproduced in a
5-line control file — see **Evidence** below, every number re-derivable from the commands given.

**Risk tier (author's estimate):** HIGH — render path on *every* page of the product, and
`style.css`/`style.min.css` is the design system itself. Not on the NEVER list (no trust rail touched,
no credential, no SEO surface deleted, nothing outside the product dirs). The verifier assigns the
real tier independently.

---

## The defect, in one sentence

`style.css` line 1 is `@import url('https://api.fontshare.com/v2/css?…satoshi…')`; every page loads that
stylesheet with the deferred-CSS pattern `media="print" onload="this.media='all'"`; a `<link>`'s `load`
event does not fire until its `@import`ed sub-resources resolve; so whenever `api.fontshare.com` is
blocked, firewalled, or simply slow, **`this.media='all'` never runs and the whole 545-rule design
system stays applied to print media only** — the user gets a completely unstyled page. And the font it
imports (Satoshi) is referenced by **zero** `font-family` declarations in the codebase.

## Evidence (measured 2026-07-31, all re-derivable)

**1. The failure is total, not cosmetic.** Rendered `/plan.html` at 1280px with `api.fontshare.com`
unreachable: no cards, no chips, no layout — raw UA-default text on white. Screenshot taken this run.
Design-system tokens read back empty:

```
plan  [{"href":"style.min.css","media":"print","sheet":true,"rules":546},
       {"href":"planner-styles.min.css","media":"all","sheet":true,"rules":520}]
plan  tokens: { bg: '', neuro: '', radius: '' }        // --color-background, --neuro-shadow-raised, --neuro-radius-md
```

The sheet is fetched (`200`, `99892` bytes) and **fully parsed** (546 CSSOM rules vs 545 top-level
rules in the file — it is not truncated). It is simply never switched off `print`.

**2. It is every page, not just the planner.** Same probe, fresh browser context per load, 6 loads:

```
/plan.html            | style.min.css@print  planner-styles.min.css@all
/plan.html            | style.min.css@print  planner-styles.min.css@all
/plan.html            | style.min.css@print  planner-styles.min.css@all
/home.html?token=USDC | style.min.css@print  pool-detail-styles.min.css@all
/home.html?token=USDC | style.min.css@print  pool-detail-styles.min.css@all
/                     | style.min.css@print  landing-styles.css@all
```

`?pool=` (the north-star surface), `?token=` (the SEO lifeline), `/plan.html` and `/` all load
`style.min.css` first. Every one of them is print-only. **Deterministic — 0 of 6 swapped.**

**3. The cause is the `@import`, proven by controlled substitution, not inferred.** A five-line HTML
file, two links, same two real CSS files, minimal server, no app code:

```
links: style.min.css(print,onload) + planner-styles.min.css(print,onload)
  →  CONTROL: [ 'style.min.css@print', 'planner-styles.min.css@all' ]     token: (empty)

same file with line 1's @import stripped (sed '1s|@import url([^)]*);||'):
  →  CONTROL: [ 'style-noimport.css@all', 'planner-styles.min.css@all' ]  token: #E2E8F0
```

One variable changed; the swap starts working and `--color-background` resolves. An instrumented
capture-phase listener shows `style.min.css` firing **`error`**, never `load`, while
`planner-styles.min.css` fires `load` twice (once on `print`, once after the handler sets `all`).

**4. The imported font is not used.** `--font-family-base` (`style.css:93`) is
`"FKGroteskNeue", "Geist", "Inter", -apple-system, …`. The repo **self-hosts** its font
(`style.css:783` `@font-face { font-family:'FKGroteskNeue'; src: url('./fonts/FKGroteskNeue.woff2') }`,
preloaded from every HTML head). `grep -i satoshi` over `*.css` returns the `@import` line and nothing
else. **The request that can break every page fetches a typeface the product never renders.**

**5. Production ships the identical markup** — `curl -s https://www.defi.garden/ | grep stylesheet`
returns `home.html:134` verbatim, `media="print" onload="this.media='all'"`.

## Is this a sandbox artifact? (playbooks/product-audit.md, the three questions)

1. *Did the harness cause it?* The harness supplied the trigger — `api.fontshare.com` is blocked here.
2. *Would this condition occur in production?* **Yes, routinely.** A third-party font CDN is blocked by
   privacy extensions and content blockers, by corporate/school network policy, in regions that filter
   foreign CDNs, and it is simply *down* sometimes. This is the counter-trap the playbook records
   verbatim from item 182: *"what the harness blocked, an ad-blocker also blocks."*
3. *What fraction, and what do they see?* Unknown — and the not-knowing is part of the defect, because
   the failure is silent and total. What they see is the screenshot in (1). Note the **happy path is
   also degraded**: even when fontshare answers, the design system cannot apply until a second,
   cross-origin round-trip to an unrelated host completes, on every cold page load.

This is not a font falling back to a system face. It is the loss of all 545 rules — tokens, layout,
neumorphic shadows, dark-mode theming — on the surface where "trust is the conversion currency."

## The fix

Delete the `@import`. Nothing replaces it: the font is unused and the product's real font is
self-hosted. Then regenerate the minified artifact through the existing script, and add a rendered
regression gate so it cannot come back.

**In scope**
1. `style.css` — remove line 1 (the `@import`). No other CSS edit.
2. `style.min.css` — regenerate via `node minify-assets.js` (`npm run minify`). Never hand-edit; the
   file header comment and `.github/workflows` both say the script owns it.
3. New rendered-Playwright test `test_css_import_blocking.js`, in the house style, added to
   `package.json`'s `test:serial` list and picked up by `run-tests.js`'s lane discovery.
4. Bookkeeping in the SAME commit (2026-07-13 rule): BACKLOG row, `specs/187-notes.md`,
   `specs/187-pr.md`, `LOG.md`.

**Explicitly OUT of scope**
- Any change to `planner-styles.css`, `pool-detail-styles.css`, `landing-styles.css` — none of them
  carries an `@import` (`grep -n "@import" *.css` returns `style.css` and its minified twin only).
- Changing the `media="print" onload` deferred-CSS pattern itself, in any HTML file. The pattern is
  correct once its stylesheet has no blocking `@import`; rewriting it is a separate, larger change.
- Adding a `<link>` to fontshare "to keep the font". The font is unused — re-adding it in another
  shape would restore the third-party dependency for zero rendered benefit. If a future design wants
  Satoshi, that is its own item and it must self-host like FKGroteskNeue does.
- Touching `app.js`, `planner.js`, `PoolDetail.js`, `home.html`, `plan.html`, generators, or any
  generated SEO surface.

## Territory notes

- **T1.** The deferred-CSS pattern lives at `plan.html:55-58`, `home.html:134-135`, and the landing
  head. `home.html:162` also has a *dynamic* injector (`l.rel='stylesheet'; l.href=href`) for
  route-specific sheets — that path sets no `media`, so it was never affected. Do not touch either.
- **T2.** `minify-assets.js:21` — `CSS_FILES = ['style.css', 'planner-styles.css',
  'pool-detail-styles.css']`. `landing-styles.css` is deliberately *not* minified and is loaded
  unminified; that is pre-existing and out of scope.
- **T3.** Several existing tests grep `style.min.css` (`test_minified_assets.js`,
  `test_css_minified_render.js`, `test_pool_logo.js`, `test_footer_hub_links.js`,
  `test_filter_dropdown_polish.js`, `test_list_polish.js`). Check none of them asserts the `@import`
  line's presence or a byte-count/hash of the file before regenerating — if one does, it is asserting
  the bug, and the notes must say so explicitly rather than the assertion being quietly edited.
- **T4.** ~20 `test_*.js` files mention `fontshare` — in their *ignorable-console-noise* regexes
  (`IGNORABLE` in `audit-app.js:115` is the same list). Those stay. They are why this defect survived:
  the whole test estate was trained to treat a failing fontshare request as expected noise, and it is
  — the noise was never the problem; the `load` event it suppresses was.
- **T5.** Snapshot/fixture traps from `playbooks/product-audit.md` apply to the new test: route
  `/data/pools-snapshot-meta.json` with a fresh `generatedAt` to exercise the snapshot-first path, and
  launch Chromium with `executablePath: '/opt/pw-browsers/chromium'` (bare `chromium.launch()` fails in
  this container — the audit does exactly this at `audit-app.js:111`).
- **T6.** The assertion must read the **live `media` IDL property** (`link.media`) or the attribute
  after settling, with a poll — the swap, when it works, happens on the sheet's `load`, which is after
  document `load`. Poll up to ~10s before declaring failure (the async-read trap in the playbook).
