the two the 2026-08-01 report filed, both shipped overnight; every other row is SHIPPED/DONE/PARKED/
BLOCKED/CULLED). Promotion follows build.md's no-READY rule, from documented evidence already in the

**No new budget knob and no kill switch**, deliberately and against the file's *other* convention: these

sixth knob would be the scope creep, not the omission. The existing `opts.only` / `--only` name filter
already gives a caller per-surface control, and the existing time-budget guard already sheds work on a
slow run.

### Leg B — the landing driver gains the two checks its new lenses need

In `kind === 'landing'` (`audit-app.js:3352-3372`), immediately after the `.landing-search-submit`
presence/visibility block and before the `errors.length` push — the **same position** the planner and
bloom drivers use:

```js
// i18n — same "KO surface rendered no Hangul text" check the planner/bloom drivers run.
if (s.ko) { const hasHangul = /[가-힣]/.test(text); if (!hasHangul) findings.push(finding(s.name, s.vpLabel, 'i18n', 'P2', 'KO surface rendered no Hangul text')); }
// responsive — 360 surface only, against the landing's own primary control.
if (s.width <= 360) await checkResponsive(page, s, findings, '.landing-search-submit');
```

This requires capturing `auditText`'s return value (`const text = await auditText(page, s, findings);` —
today the landing driver discards it), which is how the planner and bloom drivers already do it. Nothing
else in the driver changes.
