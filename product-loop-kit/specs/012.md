# Spec 012: Honest empty states — noindex + real content when a query has zero pools

## Evidence
GSC Soft 404 = 3,568 (specs/010-diagnosis.md): dead/delisted tokens in old sitemap URLs render an empty result grid at HTTP 200; Google's renderer classifies "no content" pages as soft 404s. Static hosting cannot return real 404s per query.

## Hypothesis
We believe (a) injecting `<meta name="robots" content="noindex">` client-side whenever the analytics app resolves a query to ZERO pools, and (b) replacing the bare empty state with a useful content block (why it's empty + top live alternatives), will drain the Soft-404 class over the next validation cycles — rendering crawlers honor JS-injected noindex, and borderline-thin pages become genuinely useful. Confidence: supported (standard SPA remediation; mechanism confirmed in diagnosis).

## Change
app.js (+ translations.js for new strings):
1. After the pools fetch resolves and filters apply: if the active parameterized query (token/chain/pool/poolTypes/protocols) yields 0 pools → inject the robots-noindex meta into `<head>` (create once, don't duplicate). If the query yields ≥1 pool → ensure any previously injected noindex is REMOVED (SPA filter changes must not leave a stale noindex).
2. Upgrade the zero-results state from bare "no results" to a content block: one honest sentence (this token/chain has no live pools passing the $10M TVL floor today) + up to 5 live alternatives (e.g. top TVL pools of the same chain, or top stable pools) as normal pool cards/links. Use existing data already in memory — no new API calls.
3. All new strings via translations.js, EN + natural KO.
4. `error_occurred` and existing behavior untouched; trust rails (TVL floor, sanity limit) untouched.

OUT of scope: home.html/canonical (011 owns it), sitemap generation (013), prerendering (014), router semantics.

## Acceptance criteria
- [ ] Zero-pool query → exactly one `meta[name="robots"][content*="noindex"]` in head; switching to a non-empty query in the same session removes it (trace the toggle logic; no duplicates on repeated empty queries)
- [ ] Zero-pool state renders the honest sentence + up to 5 real alternative pools from in-memory data (no new network calls — verify by code trace)
- [ ] Alternatives respect trust rails (sanity limit, TVL floor, anomaly flags) — reuse existing filtered collections only
- [ ] EN + KO strings; en-US formatting helpers for any numbers
- [ ] `node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js` exit 0; no changes outside app.js/translations.js
