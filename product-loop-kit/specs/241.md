# Spec 241: every count-interpolating translation goes through the pinned formatters

## Evidence
UX audit F6, one screen: "1,976 results" (`app.js:3131`, `toLocaleString('en-US')`) rendered two inches
above "1976 pools found" (`translations.js:36`: `showingResults: (count) => \`${count} pool…\`` — bare
interpolation). Same number, two formats. Hard rule (CLAUDE.md / standing decision 2026-07-09): all
number formatting pinned en-US via the helpers; never bare. KO variant (`translations.js:765`) same
class.

## Hypothesis
Fixing the CLASS — every function-valued translation that interpolates a numeric count formats via the
pinned helper — plus a dictionary-level guard test, prevents both this instance and the next added
string from regressing. Confidence: validated-pattern (the 159 "read from the constant, never re-type"
rule applied to formatting).
- Instance of: bare-number interpolation in the dictionary (the hard rule's blind spot: the rule is
  enforced in app code, translations.js was never swept).
- Class closed: YES for translations.js (the guard test enumerates it); app-code literals already
  covered by convention — spot-count in notes.

## Change
Sweep translations.js (EN + KO, both trees, FLATTENED — the 189 lesson): every `(count)`/numeric-param
function routes the number through the en-US pinned formatter (exported/shared, not re-implemented
inline). New test: parse the dictionary, call every function-valued entry with 1976 (and 1), assert no
rendered output contains an unformatted 4+ digit run (`/\d{4,}/` with an allowlist for genuinely
unformatted values like years — data, keyed, with reasons, size reported). OUT of scope: date formats,
non-count numerics already using helpers.

## Acceptance criteria
- [ ] `showingResults(1976)` EN → "1,976 pools found"; KO → "1,976개 풀 발견" (grouping applies; wording
      unchanged).
- [ ] Dictionary guard test enumerates EVERY function-valued key (flattened, both languages — count
      printed) and fails on any bare 4+ digit output not on the reasoned allowlist.
- [ ] The two visible strings ("results" header + "pools found") render identical formatting for the
      same value in the rendered app (Playwright, one fixture).
- [ ] Non-vacuity: revert `showingResults` to bare interpolation → guard test red; byte-identical
      restore → green.
- [ ] EN + KO updated together.
