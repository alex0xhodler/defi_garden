# Spec 213: the north-star surface serves an agent zero facts — `?pool=<id>` contains not even the pool's own id

## Evidence

Measured live against prod, 2026-08-02, `origin/main` @ `7b64ae5a5`. The pool-detail page (`?pool=<id>`) is
the north-star surface (NORTH_STAR 2026-07-23) and the target of **3,984** generated deep links (post-206).

Fetched `https://www.defi.garden/?pool=43641cf5-a92e-416b-bce9-27113d3c0db6` with no JS execution —
23,502 bytes of HTML. Occurrences of the facts the page is *about*:

| string | occurrences in served HTML |
|---|---|
| the pool's own id `43641cf5` | **0** |
| the protocol `jupiter` | **0** |
| `Garden this pool` (the north-star CTA) | **0** |
| `Total APY` | **0** |
| `<title>` | generic — `DeFi Garden 🌱 \| Find your next yield`, identical for every pool |

**Every fact on that page — the APY, the TVL, the protocol, the risk read, the rate-history note item 207
just shipped, and both north-star CTAs — exists only after `babel-standalone` compiles and a live
DefiLlama fetch resolves.** An agent, a no-JS crawler, or a preview unfurler sees an empty shell with a
generic title.

**This is the exact shape of the Resend pricing example, on this product's most important page.** Their
insight: if the buyer's agent cannot parse your pricing, it recommends the competitor whose page it could.
Here the "pricing" equivalent — the yield, the size, the risk — is the entire reason the page exists, and
it is 0% readable without JS.

**Scale, measured:** the estate points **3,984** deep links at this surface, and it is where the only
observed real user journey landed (`/tokens/jitosol` → `/?pool=fdcccd6a-…`, `signals/2026-08-02.md`). The
static estate that *links* there is fully server-rendered; the destination is not. **The agent-readable
funnel dead-ends exactly one hop before the conversion surface.**

**Contrast that makes the fix obvious:** `tokens/usdc.html` already renders every one of these facts as
server HTML for ~29 pools at once. The data and the generator exist; only the per-pool address is missing.

## Hypothesis

We believe **generating a per-pool markdown twin for the deep-linked population and serving it under
`Accept: text/markdown` on `?pool=<id>`** will **make the north-star surface retrievable in one request by
an agent**, because the facts are already computed daily by the estate generators and the only gap is
addressing. Confidence: **supported** on the defect (0 facts, measured); **guess** on the traffic effect —
no agent traffic is measured today and none can be with current instrumentation.

## Change

Depends on **212** (path-aware negotiation + the removal of the silent `llms.txt` fallback). Build 212 first;
this item adds the `?pool=` case to the mechanism 212 establishes.

1. **Generate `pools/<id>.md`** for the deep-linked population — the same id set `audit-app.js`'s
   `pool-link-liveness` extractor already produces (item 206 widened the rotation to it; **reuse that
   extractor, do not write a third copy**). Emit in the existing daily generator run so it stays in sync by
   construction.
   Content, mirroring what the rendered page states: `# <SYMBOL> — <protocol> on <chain>`, total APY with
   its base/reward split, TVL, pool type, 30d mean APY, exposure, IL risk, the risk read, the rate-history
   note (207's `rateHistoryUnavailable` wording when there is no history — **the honest line must appear in
   the markdown too, not be silently omitted**), and both CTA URLs as labelled links.
2. **Negotiate it**: `Accept: text/markdown` on `/?pool=<id>` → `/pools/<id>.md`, via a `has` query-match
   rewrite in `vercel.json`. An id with no twin falls through to normal HTML per 212's rule — **never** to
   the generic index.
3. **Every rendered number passes the same trust rails as the page**: the `APY_SANITY_LIMIT` filter, the
   anomaly flag, and the degen ⅓ haircut where it applies. A markdown twin that states a rate the HTML page
   would refuse to show unflagged is a trust-rail breach in a new output format.

**OUT of scope:** server-side rendering of the actual React page (would break the no-build-step
architecture — explicitly rejected); any change to `PoolDetail.js`, `app.js`, the trust-rail constants, or
which pools the product displays; adding `.md` twins to sitemaps.

## Acceptance criteria

- [ ] `curl -H "Accept: text/markdown" "https://www.defi.garden/?pool=<live id>"` returns markdown naming
      **that pool** — its symbol, protocol, chain, APY and TVL — not the site index and not another pool's.
      Assert on ≥10 distinct ids including at least one sub-$10M pool (88.6% of the deep-linked set).
- [ ] **Number parity with the rendered page**, asserted mechanically: for ≥10 pools, APY and TVL in the
      `.md` equal the values the rendered pool-detail page shows for the same pool at the same data
      timestamp. A twin that drifts from the page is worse than no twin.
- [ ] **Trust rails hold in the new format:** an anomalous pool's twin carries the same ⚠ flag/omission the
      page applies; no twin states an APY above `APY_SANITY_LIMIT` unflagged; the degen haircut is applied
      where the page applies it. Assert on a constructed anomalous fixture — this is the criterion most
      likely to be quietly skipped.
- [ ] 207's honest no-rate-history line appears in twins for pools with no history.
- [ ] Both north-star CTA URLs appear as labelled markdown links.
- [ ] An unknown/dead `?pool=` id falls through to the normal HTML (which has the 072 dead-pool empty
      state), never to `llms.txt`.
- [ ] `/?token=`, `/?chain=` and bare `/` markdown behaviour is exactly as 212 left it — this item adds one
      case and changes no other.
- [ ] Twins are out of every sitemap and carry `noindex` (212's decision), so this cannot create the
      duplicate-content problem 211 removes.
- [ ] Both router paths still work: bare `/` → planner, `/?token=USDC` → analytics app with pool cards.
- [ ] Tests: `npm test` green; pre-existing reds baselined at `origin/main` first.
- [ ] Instrumentation: none — structurally unmeasurable client-side (see Measurement).

## Measurement

Metric: **none available.** An agent that never executes JS cannot fire a client-side event, and this stack
has no server-log access — so, exactly as 212, this is a **capability bet recorded in `LEARNINGS.md`, not
an experiment.** Window: n/a. Decision rule: keep if every acceptance criterion holds and no guardrail
moves. **Do not claim a traffic or conversion effect in either direction.** The prerequisite for ever
measuring this honestly is edge/server request logging by `Accept` header and user-agent — a separate item,
and the honest thing to file if anyone wants a number here.

## Risk tier (builder's guess — verifier assigns independently)

**HIGH.** Two independent reasons: it edits `vercel.json`'s rewrite table (config/infra, NORTH_STAR HIGH
list, and the table that routes the sacred parameterized URLs), and it emits **trust-rail-governed numbers
in a brand-new output format** — a surface where the rails have never been enforced before and where
"nobody looks at the markdown" makes a silent breach easy to miss. The rails criterion above is the one to
verify hardest.
