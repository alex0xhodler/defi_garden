## Deviations from spec
- Spec said the click-through-tracking half was explicitly OUT of scope (relying on `document.referrer` already being captured app-side). Confirmed during build: `analytics.js:32`'s `getBaseContext()` does include `referrer: document.referrer || 'direct'` on every event, and `vercel.json`'s `Referrer-Policy: strict-origin-when-cross-origin` sends the full path for same-origin navigation (both `/tokens/<slug>` and `/?token=` are `www.defi.garden`). No code needed — verified this claim rather than just asserting it, since it was load-bearing for keeping the diff small.
- Byte-identical reuse of the Mixpanel stub loader required `String.raw` (not manual backslash-doubling in a template literal) to avoid corrupting the snippet's own regex literal (`/^\/\//`). Verified programmatically (`homeSnippet.trim() === mySnippet.trim()` → `true`) rather than eyeballing — this is exactly the kind of subtle bug ("looks right, executes wrong") worth a real assertion, and one now exists in both test files.
- `generate-stories.js` has no `--fixture`/offline CLI path (unlike `generate-token-pages.js`). Rather than add one (scope creep — this diff is about the analytics block, not the CLI), `test_stories.js` calls `renderStoryPage()`/`renderAnalyticsBootstrap()` directly with a hand-built synthetic `plan` object, bypassing `curatePools`/`fetchPoolData` entirely. This is sufficient because the diff never touches curation/temperament/trust-rail logic — confirmed by re-reading `curatePools`/`conservativeApy` and observing zero changes needed there.
- Real production regeneration of the 2,045 `/tokens/<slug>.html` + 3 `stories/*.html` files could not happen in this session: `curl` to both `yields.llama.fi` and `unpkg.com` returned connection-refused (exit 56) — same wall every prior static-page item (013/014/020/022/023) hit in-sandbox. Verified via `--fixture` regeneration (5 sample token pages, byte-inspected) instead. Real pages regenerate on the next `sitemap-update.yml` CI run (daily `0 2 * * *`), same residual disclosed by every prior item in this family.

## ID collision (process note, not a spec deviation)
This item was drafted as "034" (first in a batch of five new initiatives: 034-038) during research. Mid-session, `git fetch origin main` revealed a concurrent build-loop session had already merged PR #130 using ID 034 for an unrelated pool-detail projection fix — neither session could see the other's in-flight work. Caught before any commit via a pre-branch `git fetch` + `git show origin/main:.../BACKLOG.md` check (not by luck). Renumbered the whole batch to 039-043 (all confirmed free on origin/main) before branching. Two-loop concurrency isn't new to this repo (NORTH_STAR.md's "Max parallel build loops: 2" already assumes it) — what's new is a same-day ID collision landing mid-session; worth flagging as improve-loop material: ID allocation currently has no central sequence, just "look at the last row in BACKLOG.md," which doesn't survive two concurrent sessions picking up new work in the same window.
