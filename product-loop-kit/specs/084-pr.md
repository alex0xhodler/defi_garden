# 084 — PR explainer: real assertions for the NORTH_STAR test gate

## Goal

NORTH_STAR.md's human-owned Test command is
`node test_planner.js && node test_protocol_parsing.js && node test_qualifier_fix.js`,
run verbatim by every build loop and the verifier. Two of those three files could **never fail**:
they contained zero assertions, zero non-zero exit paths, and tested a *stale inline copy* of a
simplified parser instead of the real one — the exact "fixtures passed, product failed" class that
sank item 017. A real regression in NL-search parsing (the SEO-lander funnel entry:
`search_success` 101 events/14d) would sail through the official gate silently. This item makes the
gate real without touching any product code.

## Intuition

You can't trust a test that tests a copy — copies rot. The real `parseNaturalLanguageQuery` in
app.js gained the lend-stem regex, word-boundary chain aliases, live-chain fallback, and dynamic
protocol aliases (017/018 fixes) while the copies stayed frozen in their 2025 shape. The fix
follows the repo's own precedent (test_translations_fallback.js): read the actual source file,
slice the actual function out, evaluate it in `node:vm`, and assert on what it actually returns.
Now the tests and the product cannot drift apart — if the parser moves, the gate breaks loudly;
if its behavior regresses, the gate exits non-zero.

## What changed (reading order)

1. **`test_helpers_parser.js` (new, 65 lines, dependency-free).** `extractParser(appPath)`:
   `readFileSync` the app.js the caller names (always `path.join(__dirname, 'app.js')` — repo-
   relative, the 083 hardcoded-path class banned), find the top-level
   `const parseNaturalLanguageQuery = (query` declaration, slice to the first **column-0** `\n};`
   after it. Why that's safe: the function body is fully indented, so every inner object literal
   closes with an *indented* `};`; the only column-0 closers in app.js are other top-level
   declarations (builder verified via `grep -n '^};'` — the first one after line 129 is the
   parser's own at 483). Backstop: the slice is evaluated in a vm context and `typeof`-checked, so
   a mis-slice throws rather than silently passing. Every failure path (missing declaration,
   missing closer, eval error, non-function result) throws with a specific message.

2. **`test_protocol_parsing.js` (rewritten, 9 assertions).** Extracts the real parser (extraction
   failure → `EXTRACTION FAILED` + exit 1), then locks in protocol-parsing behavior with realistic
   fixtures: context-keyword matching ("usdc on aave" → `['Aave']`), the Method-1 chain-name skip
   ("best yields on base" → no protocol, chain Base), direct word-boundary detection ("compound
   yields"), protocol-first ("aave on arbitrum"), the 018 dynamic-alias fix ("kamino lenders"/
   "kamino lending" → `['Kamino Lend']` via `{friendlyName, originalNames}` objects), static-
   fallback gating (same query returns `['Aave']` with `allProtocols: []` but `[]` with a dynamic
   list lacking aave — proving the fallback only fires when the dynamic list is empty), and Set
   dedupe. The `check()` helper asserts only the keys each case names (deep-equal via
   JSON.stringify), prints expected-vs-got on failure, and the file exits 1 unless all pass.

3. **`test_qualifier_fix.js` (rewritten, 9 assertions).** Same structure; locks in qualifier-word
   and pool-type behavior: qualifier words never become tokens ("best yields on base" → token ''),
   real tokens survive the filter ("top usdc yields" → USDC), chain-with-empty-token ("highest apy
   on arbitrum"), the chain-indicator token skip ("best yields on eth" → chain Ethereum, token ''),
   the lend-stem regex both ways ("usdt lending on venus" → `['Lending']` + Venus; "kamino
   lenders"), generic "yields" NOT adding Yield Farming (with and without a token), and explicit
   "farming" adding it.

4. **`product-loop-kit/specs/084.md` / `084-notes.md` / BACKLOG / LOG** — spec, builder notes
   (probe results, mutation-check proof, the deviation below), and bookkeeping, all in this one
   commit per the 2026-07-13/104 standing decisions.

**Not changed:** `app.js` (sha256-verified byte-identical after mutation checks were reverted),
`package.json` (chain membership and order untouched — the two files keep their names and
positions 2–3), NORTH_STAR.md (human-owned).

## Deviation from spec (documented, verifier-reviewed)

The spec's suggested case `"highest apy on ethereum" → token ''` is **wrong about the real
parser**: it actually returns token `'ETH'`. Root cause (real, pre-existing, out of scope to fix
here): the token-parse *fallback* uses a bare substring test — `'on ethereum'.includes('eth')` —
and its guards miss short aliases ('eth' inside 'ethereum', 'sol' inside 'solana'). Encoding that
output as "expected" would bless a bug; forcing `''` would fail at HEAD. Per the spec's own rule,
the builder dropped the case, substituted "highest apy on arbitrum" (clean), and documented the
bug in 084-notes.md as a follow-up candidate: a user searching "yields on ethereum" can get
spuriously token-filtered to ETH pools.

## How it was proven to bite (mutation checks on the real app.js, each reverted, sha256-verified)

- lend-stem regex neutered → qualifier test fails 7/9, exit 1
- generic-yield guard widened to `includes('yield')` → qualifier test fails 7/9, exit 1
- protocol dedupe removed → protocol test fails 8/9, exit 1
- parser declaration renamed → BOTH tests exit 1 with `EXTRACTION FAILED`
- Honest gap, recorded: mutating the Method-1 chain-name skip did NOT bite (fixtures have no
  chain/protocol-alias collision); the chain-vs-token protection is covered via "best yields on
  eth" instead.
