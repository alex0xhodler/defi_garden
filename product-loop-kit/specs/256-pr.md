# 256 — PR explainer: a rendered raw translation key is now a finding, not a clean run

## Goal

The audit's `dead-pool` check asserted that the honest empty state **exists**. It never asserted it **says
anything**. On 2026-08-09 that check scored CLEAN (83 surfaces, exit 1, `dead-pool-empty-state` ABSENT) on a
surface that was, at that moment, rendering the literal string `poolNotFoundTitle` to users — item 253's live
P0. The element was there; nobody read it.

This PR adds a signal that reads the text: **no text rendered on any audited surface may exactly equal a
translation key name.**

## The intuition

A missing translation is not a broken page. `t()` returns the key's own name on a miss, so the DOM comes out
perfectly well-formed — right element, right class, right layout, non-empty text. Every presence-based
assertion in the audit is blind to it by construction. The only thing that distinguishes the failure from
success is **what the string says**, so the check has to be about the string.

## What changed, in reading order

### 1. `audit-app.js` — the population (the part that matters)

Two run-time-derived legs, unioned. Nothing is hardcoded; adding, renaming, or deleting a key needs no edit
to `audit-app.js`.

- **Leg A — `collectI18nKeyNames()`**: every key name in the parsed dictionary, both namespaces, all nesting
  levels, reusing the SAME `flattenI18nDict()` walker `prescanI18n()` already uses (one walker, not two).
  Each flattened path contributes two candidates: the full dotted path (`planner.goalClaude`) and the bare
  leaf (`goalClaude`), because both are genuinely renderable — `translations.js`'s root `t()` echoes the bare
  top-level key, and `planner.js`'s `makeT()` (planner.js:888-899, `return v == null ? key : v;`) echoes the
  bare key inside the already-selected `planner` namespace on a miss. (An earlier draft of this doc also cited
  `landing.js`'s `getCopy()` here — that was wrong and has been corrected below.)
- **Leg B — `collectReferencedKeyNames()` over `collectRenderedScriptSources()`**: every key-name literal at a
  `t('…')` / `rootT(…, '…')` call site, in the product sources the audited shells actually load, across all
  three JS string delimiters (`'`, `"`, `` ` ``). The file list is itself derived: parse `home.html`/`plan.html`
  for local `<script src>` tags **and** for the `addScript('…')` runtime injection home.html uses for the
  analytics bundle (item 244's boot barrier — `app.js` and `PoolDetail.js` appear in no static `<script src>`
  tag, so without that second shape the whole analytics app would sit outside the population), then map
  `.min`/`.compiled` artifacts back to their sources when a source exists on disk. *(This shell-path default
  is itself a hardcoded two-item list — see "What this does NOT close" below.)*
- **`collectRawKeyPopulation()`** is the union, memoized once per process by `rawKeyPopulation()`.

**Why two legs, and why this is not scope creep.** The spec asked for the dictionary alone. That was built
first and then measured against the very defect the item exists for — and it was blind. With
`poolNotFoundTitle` deleted from both namespaces (253's exact shape), Playwright confirmed the dead-pool
surface rendering the literal `"poolNotFoundTitle"`, and `node audit-app.js --only=dead-pool` returned
`findings: []`. The reason is structural: `app.js:3587` still calls `t('poolNotFoundTitle')`, but the moment
the key leaves the dictionary its NAME leaves a dictionary-derived population. **The population shrinks
exactly when the defect appears.** Shipping that would have been the fifth entry in this item's own precedent
list (190, 198, 212, 249) rather than the fix for it. Leg B never reads the dictionary, so it survives the
deletion — and it is derived from the mechanism that renders the miss (the call site), not from a resemblance
of it.

### 2. `audit-app.js` — the predicate

`scanRawRenderedKeys(text, keyNames)`, shaped exactly like the existing `scanNumbers()`: pure, in-Node, takes
rendered text, returns detail strings. Splits `innerText` on newlines, trims, and flags a line **iff it is
exactly equal** (case-sensitive) to a population member; de-dupes per surface. Detail:
`raw translation key rendered as text: "<key>"`.

Exact-LINE matching is a deliberate trade. Token-wise matching would catch inline raw keys, but it would put
short leaf names (`back`, `no`, `yes`, `share`, `title`, `tvl`, `years`) one lowercase rendering away from a
false positive. Presence-over-precision is the failure mode this item exists to correct, so the predicate
errs in the other direction.

### 3. `audit-app.js` — the wiring

One loop added to `auditText()` — the single text collector every surface driver already calls — so the
predicate runs on **every surface the audit visits**, with no new page loads and no new rotation cost. The
`dead-pool` branch's `waitForSelector` presence check and its `dead-pool-empty-state` finding are byte
untouched: a render timeout is still a real, different failure. This item **adds** a signal; it replaces none.

### 4. `test_audit_raw_key_rendered.js` (new) + `package.json`

27 assertions (18 original + 9 added by the verifier round 1 fix below), network-free and browser-free, in
`test_audit_i18n_parity.js`'s style. Registered by appending one step to `test:serial`, which `run-tests.js`
parses as its single source of truth — an unregistered test file is not a gate (`test_boot_barrier.js`
precedent). The load-bearing cases: the leg-B regression (a dictionary WITHOUT the key plus an injected source
WITH the call site still fires), runtime derivation via injected dictionaries and files (proving no code
change is needed for a new key), the union-superset property, exact-match/trim/case/dedup behaviour,
inertness on malformed input, the documented computed-key blind spot, and the false-positive control: every
real EN string value in the dictionary, rendered one per line, produces **zero** hits against the full union
population — no allowlist, none needed.

## Verifier round 1 — FAIL, and the fix (same day, 2026-08-10)

The claim above — "every key-name literal referenced at a `t('…')`/`rootT(…, '…')` call site" — was an
overstatement as first shipped. Two STATIC-LITERAL shapes were missed, both confirmed end-to-end by the
verifier (rewrite `app.js`'s `poolNotFoundTitle` call site to the missed shape, delete the key from both
namespaces of `translations.js` AND `translations.min.js`, render the dead-pool surface,
`.empty-state .empty-message`'s textContent reads the raw key, `node audit-app.js --only=dead-pool` still
returns `findings: []`):

| call shape | round-1 collected? |
|---|---|
| `t('kA')` / `t("kB")` | yes |
| `` t(`kC`) `` (backtick) | **no** |
| `rootT(lang, 'kF')` | yes |
| `rootT(getLang(), 'kG')` (call-expression first arg) | **no** — `ROOT_T_CALL_RE`'s first-arg charclass `[^,()]+` rejects any parens in the first argument |

This is the same delimiter axis backlog item **257** took three attempts to close (attempt 1: single-quote
only; attempt 2: widened to only the double-quote variant the verifier had just demonstrated; attempt 3: all
three delimiters + trailing comma/whitespace). Round 1 here shipped attempt-2's predicate — closed the ONE
instance demonstrated, not the axis.

**Fix**: `T_CALL_RE` accepts all three delimiters (`'`, `"`, `` ` ``) via a backreferenced group.
`ROOT_T_CALL_RE`'s first argument is widened from `[^,()]+` to `(?:[^()]|\([^()]*\))*` — any run of
non-paren characters, or a single-level-balanced `(...)` group, repeated — which accepts a shallow call
expression (`getLang()`, `a.b()`) while staying bounded to the call itself: an unmatched `)` (the call's own
closing paren) can't be consumed by either alternative, so greedy backtracking only ever finds the real
second-argument literal, never a literal belonging to a later call. A backtick literal WITH interpolation
(`` t(`pre${x}`) ``) still cannot match: the key charclass excludes `{`, so the match fails at the point the
literal needs its closing backtick and finds `{` instead. Probe table (also in
`test_audit_raw_key_rendered.js`'s new cases 18-25):

| input | `collectReferencedKeyNames()` result |
|---|---|
| `t('kA')` | `{kA}` |
| `t("kB")` | `{kB}` |
| `` t(`kC`) `` | `{kC}` |
| `t('kE', x)` | `{kE}` |
| `rootT(lang,'kF')` | `{kF}` |
| `rootT(getLang(),'kG')` | `{kG}` |
| `t(someVar)` | `{}` |
| `t('a'+'b')` | `{}` |
| `` t(`pre${x}`) `` | `{}` |

Real-repo numbers, unchanged by the fix (no real call site in this repo needed the widened shapes — the fix
closes what the regex *would* match, not a gap in today's actual call sites): Leg A = 904, Leg B = 284,
union = 904.

## Non-vacuity — manufactured, both directions, on the real rendered product

253 shipped on 2026-08-09 (#417), so the spec's "free red" is gone and the spec's own inversion applies.

- **RED**: deleted `poolNotFoundTitle` and `planner.step1Question` from both namespaces of `translations.js`
  and from `translations.min.js` (the artifact `home.html:201` actually loads), then
  `node audit-app.js --only=dead-pool,planner` → **exit 1**, two `i18n:raw-key-rendered` P1 findings, one per
  surface, each quoting the offending text verbatim. Two surfaces is also the spec's "reproduced on a second
  surface" evidence, and `step1Question` is a nested key caught by its bare leaf, so both key shapes fire.
- **RESTORE**: `git checkout --` both files, md5 compared to the pre-mutation capture — byte-identical.
- **GREEN**: same command on the restored tree → **exit 0**, `findings: []`.

## What this does NOT close

- The item's own class — checks whose predicate is narrower than the class they guard — stays **open**. This
  converted the `dead-pool` assertion and added a content predicate across text-collecting surfaces; every
  other `waitForSelector`-shaped assertion in `audit-app.js` can still pass on a well-formed-but-wrong DOM.
  Verifier round 1 (above) is itself an instance of the same class one level in.
- Residual blind spots of what shipped, named precisely rather than lumped under "computed keys": (a) a
  genuinely computed key, e.g. `t(someVar)` or `t(KEY_CONST)`; (b) a concatenation, e.g. `t('a' + 'b')`;
  (c) an escape-spelled literal (`t('pool\x4eotFoundTitle')`, `String.fromCharCode(...)`); (d) a key reached
  only through an alias or named constant assigned elsewhere (`const k = 'poolNotFoundTitle'; t(k)`); (e) an
  inline raw key sharing a line with prose is not flagged; (f) a surface the rotation skipped that tick is not
  covered (item **255** is the pre-merge source-level counterpart that does not depend on the rotation).
- **Two more disclosures, stated plainly:**
  (g) `collectRenderedScriptSources()`'s shell-path default is a HARDCODED two-item list (`home.html`,
  `plan.html`) — only the script list *under* each shell is derived from that shell's own markup; nothing
  ties the shell list to the audit's own surface-URL list. Not a live hole today — verified directly:
  `tokens/*.html` and `stories/*.html` carry only the absolute `analytics.js` `<script src>` tag and zero
  `t('` call sites — but the mechanism is a hardcoded list, not a derived one.
  (h) `auditText()` is not called by the `s.kind === 'loading'` surface driver branch (the `grid-loading`
  surface): that branch returns its findings before reaching `auditText()`, so this predicate never runs on
  that surface's forced-live loading window.
- **No traffic claim, by design.** Detector, not a product change: no Mixpanel event, no funnel window, no
  gate. Its effect is on the loop's own error rate.
