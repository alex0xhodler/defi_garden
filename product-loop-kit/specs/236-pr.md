# 236 phase 1 — one header band, one content width, across all three analytics views

**Tier: HIGH** (verifier-assigned independently, concurring with the builder's guess): `app.js` render-path
changes on the sacred parameterized-URL surfaces (`?token=` / `?chain=` / `?pool=`), 174+/116− lines against
the LOW lane's 150-line cap. No trust rail touched, no router touched, no dependency, no config, nothing
de-indexed — so HIGH, not NEVER/BLOCKED.

## Goal

The human, reviewing the #393 preview on 2026-08-06: *"re using the same logo bars, same width of content,
etc, which are all over the place currently between the search, search results, and pool view views, c'mon
it's only 3 screens!"* Phase 1 of item 236 is exactly that and nothing more: **one header band on all three
views, one content-width token**. Phase 2 (the "Search yields / How it works / My garden" nav links and the
breadcrumb-on-arrival-context rule) is untouched and still open.

## The intuition

Three screens had three different answers to "who am I and where are my controls":

| view | header | controls | shell width |
|---|---|---|---|
| search / no-results | none — a giant centered `h1.logo` + subtitle | a **floating** `.theme-toggle` + `.language-toggle` pair | 600px (and `100%` below 768px) |
| results grid | `.app-header-sticky` band + nav-tabs row | inside the band | 1200px |
| pool detail | the same band, one row | inside the band | `none` (inner 880px measure) |

Two of the three already shared a band — spec 247 unified grid and pool-detail. The search state was the
holdout, and it was the holdout in the loudest possible way: it rendered a *second copy* of the identity and
the controls, floating, which is why item 222 had to ship a CSS guard hiding that pair on results pages. The
fix is not to hide the duplicate better. It is to delete it and let the band do its job everywhere.

## What changed, in reading order

**1. `app.js` — the band becomes unconditional (`:3225-3320`).**
The `.app-header-sticky` wrapper loses its `(selectedToken || (chainMode && selectedChain)) &&` guard and now
renders on every view of the component. That guard moves *inward*, onto the `.app-nav-row` (category tabs +
filters), which genuinely belongs to the results state only. `renderHeaderRow()` — the shared band component
247 already built — is called with `includeSearch = !!(selectedToken || (chainMode && selectedChain))`, i.e.
the same expression the `.has-results` class already used.

**Why the search slot is the one sanctioned variation.** The band's input is a plain input; the autocomplete
dropdown (`showAutocomplete` / `autocompleteTokens`) lives entirely in the no-results state's own
`.search-section`. Routing that state's search through the band would have silently dropped token
autocomplete from the home surface. So the no-results view renders the band *without* the search slot and
keeps its own search block below. The acceptance test asserts geometry on the band shell, the wordmark and
the controls — deliberately **not** on the search slot — and that exclusion is stated, not smuggled.

**2. `app.js` — the duplicates are deleted.** The standalone floating `.theme-toggle` and `.language-toggle`
buttons, and the `.header.animate-on-mount` block (giant `h1.logo` + hardcoded-English subtitle), are gone.
The band already carries identity and both controls on every view.

**3. `style.css` — one width token (`:903`).** New `--content-max-width: 1200px`. Every page **shell**
resolves it: `.app-header-content`, `.app-nav-row`, `.app.has-results .container`,
`.app:not(.has-results) .container` (was a lone 600px), and — in `pool-detail-styles.css` — the pool view's
`.container` (was `max-width: none`). Because the no-results shell widened, the hero's own blocks keep the
reading measure via their own `max-width: 600px; margin-inline: auto`, so nothing stretches full-bleed at
1280px.

**4. `style.css` — the media-query holdout.** `@media (max-width: 768px)` still forced `max-width: 100%` on
`.app:not(.has-results) .container` alone. Behaviourally inert below 1200px, but it was a second source of
truth for a shell width, which is the exact thing this item exists to kill — removed, along with a sweep for
any other override.

**5. `style.css` — dead code the hero removal created.** `.header.animate-on-mount`, `.logo`, and
`.logo:hover { transform: scale(1.02) }` are deleted. That last one is a CLAUDE.md- and DESIGN.md-banned
scale-pop with no reduced-motion guard, flagged by 225's verifier and ticketed as part of item **238**. It is
deleted here not as a drive-by but because its only render site disappeared in change 2. **238 keeps its
remaining scope** (the uppercase sweep, the bare `monospace` stacks); the base `.logo`/`.header`/`.subtitle`
declarations are now also dead and are explicitly *not* swept here — recorded as known debt in the notes.

**6. `test_nav_band_identity.js` (new, 359 lines).** Rendered Playwright, fixture-routed, real Chromium.
3 views × 3 widths × 2 themes, asserting: the band exists on all three; `.app-header-content` height and
resolved max-width + padding identical; `.app-logo` / `.app-header-controls` y-position and edges identical
±1px; all three shells resolve the same value, *read from the `--content-max-width` custom property at test
time* rather than hardcoding 1200 twice; exactly one language and one theme control per view; no horizontal
body scroll at 360px; and — added after review — the first content block on every view starts at or below the
band's bottom edge, because a `position: fixed` band is a new occluder and occlusion is a house defect class.
**50/50.**

**7. `test_mobile_controls_reachable.js` — migrated to the shared-header architecture.**
Homepage assertions now exercise the same in-flow control pair as results and pool-detail views. The
duplicate-control RED proof injects the retired direct-child shape only after a green precondition, then
restores the former fixed geometry so the behavioral detector must fail. The dead direct-child CSS guards
and four mobile positioning variants were removed rather than preserving an architecture the render path
cannot produce.

**8. Derived assets.** `app.compiled.js`, `app.compiled.min.js`, `style.min.css`,
`pool-detail-styles.min.css` regenerated via `npm run compile && npm run minify` — no hand-edits; the
verifier reproduced them byte-identically from a fresh run.

## Deviations from the spec

1. **`includeSearch=false` on the no-results band** — reasoned above; the alternative silently drops
   autocomplete from the home surface.
2. **`.pool-detail-container`'s 880px is left alone.** The spec says "all three content containers resolve
   the SAME max-width token"; the pool view's *shell* (`.app.pool-detail-view .container`) now does. The
   880px is the 247 world's typographic **measure**, nested inside that shell, not a second shell — and 247
   is the newer authority. Tokenizing the shell is visually inert at ≤1200px because the inner cap binds
   first.
3. **The dead-pool view gained the band as a side effect** — it renders from the same branch, and leaving it
   band-less would have reintroduced the divergence this item closes. `test_dead_pool.js` 12/12; the verifier
   additionally rendered `?pool=<garbage>` at 1280 and 360 and found the geometry identity holding.
4. **Three nested content grids** (`.results-panel`, `.pools-list`, `.pools-grid`'s desktop query) were
   tokenized too, beyond the named selectors — they are nested *inside* an already-capped `.container`, so
   their own `1200px` was a redundant no-op that read like an independent source of truth.
5. **A new `padding-top: calc(var(--ui-header-h) + 1px)`** on `.app:not(.has-results):not(.pool-detail-view)`
   — a fixed band needs clearance, and the no-results state never had any because it never had a band. Reuses
   pool-detail's existing expression and token rather than inventing a number.

## Preview follow-up

button at 360px. After rebasing onto current `main`, the repair reuses item
273's `.app-brand-wordmark` wrapper, widens its phone-only hiding threshold to
480px, removes duplicated field padding, and gives the clear action a fixed
32px box. The leaf tile and language/theme controls remain visible; the query
gets a 128px text box at 360px and long pool symbols show their prefix.
`test_mobile_search_context.js` adds rendered no-results/pool-detail coverage,
and the existing responsive-control tests now describe the shared homepage
header rather than the retired standalone pair.
The rendered contract includes the exact 480px breakpoint, not only viewports
on either side of it.

The rebase also carried the four translation-function arity repairs already
present in PR #447 so this branch's deterministic lane is independently green.
Whichever PR lands second should drop that identical overlap during rebase.
