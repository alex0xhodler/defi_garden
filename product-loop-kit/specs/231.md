# Spec 231: the occlusion lens must SEE a permanent defect on (nearly) every run

## Evidence
- **Item 221's transcript** (BACKLOG row 231, carried forward unbuilt by item 230): `audit-app.js`'s
  `occlusion` lens flagged the `dead-pool` surface in **3 of 20** true single-process isolated runs on
  unmodified `main`, while a diagnostic mirroring `checkOcclusion`'s exact sequence (900→780 resize,
  150 ms settle, `domcontentloaded`) reproduced the occluded geometry on **~14 of 14** runs, never once
  clean. Item 230 then reproduced the same defect **10 of 10** with its own instrument.
  *The PAGE is reliably broken; only the DETECTION is intermittent.*
- Two rival explanations already RULED OUT by 221: the CSS-load race (15/15 probe runs had
  `style.min.css` already applied) and content variance (`getEmptyStateAlternatives` draws from the
  in-memory snapshot, deterministic).
- **Re-measured this run, on `claude/loop-231` off `main` (`aa3242ab51`)**, with item 230's shipped fix
  mutated away in `style.css`+`style.min.css` (`position: static` → `fixed`) so the `dead-pool` surface
  once again carries a *permanent* occlusion defect:
  **`runAudit({only:['dead-pool']})` × 10 isolated processes → 2 flagged, 8 clean (20%)** — the 15% of
  221's 20-run sample, reproduced.
- **Mechanism found (this run, instrumented `occlusionPassEval` sampled at t = 0/100/200/400/800/1600 ms
  past the existing 150 ms settle, 3 isolated runs, identical in all three):**

  | t after the existing 150 ms settle | occlusions reported |
  |---|---|
  | 0 ms | **0** |
  | 100 ms | 6 |
  | 200 / 400 / 800 / 1600 ms | 6 |

  At t=0 the victims are already geometrically covered (`DIV.tvl-label` y=719 h=16, **100% covered**,
  `elementFromPoint` at its centre already resolving to `FOOTER.app-footer`) — and the pass still returns
  zero. The gate that rejects them is `occlusionPassEval`'s own `isVisible()`
  (`checkVisibility({ visibilityProperty: true, opacityProperty: true })`), because `style.css:4605`
  declares `.animate-on-mount { opacity: 0 }` and every entry animation
  (`style.css:4605-4670`, `fadeInDown`/`fadeInScale`/… with **staggered** `--entry-delay-base * N` delays)
  is still running at measurement time. `page.setViewportSize()` re-renders the React surface, which
  **re-mounts** the animated subtree, so the entry animation restarts on every single surface right
  before the lens measures it.
  So the leading hypothesis carried in the BACKLOG row ("the FIXED 150 ms settle races this surface's
  render") is **confirmed in kind and corrected in mechanism**: what the 150 ms races is not the
  alternatives-grid *render* — the render is finished — it is the **entry-animation opacity ramp**. The
  measurement lands within a few tens of ms of the animation's end, so the same page flips between
  "6 occlusions" and "0 occlusions" run to run.

## Hypothesis
We believe replacing `checkOcclusion`'s fixed 150 ms settle with a **quiescence wait derived from the
defining mechanism** — no CSS animation/transition still running (`document.getAnimations()`, excluding
infinite/looping effects, which never settle) **and** a stable geometry signature across two consecutive
samples — raises the lens's detection rate on a permanently-defective surface from ~15-20% to ≥95%,
because the only gate that rejected the already-covered victims was opacity-based visibility during an
in-flight entry animation.
Confidence: supported (mechanism measured, not inferred).
- **Instance of**: *timing-derived audit gates* — a lens whose readiness predicate is a magic number
  rather than the mechanism it needs to have finished. Population: every geometry- or visibility-reading
  check in `audit-app.js` run against the 83 surfaces of a tick.
- **Class closed by this item**: **NO — partially.** This item makes `checkOcclusion` (the lens with
  measured under-reporting) quiescence-derived. `checkResponsive` (`audit-app.js:3961`, reads
  `cta.boundingBox()`) is the other geometry-reading check and keeps its own inherited timing; it is
  **not** covered here. Uncovered: 1 of the 2 geometry-reading lenses, running on every one of the 83
  surfaces per tick. Filed as backlog **232** ("port the quiescence wait to `checkResponsive`, or prove
  its measurement is animation-independent"). Shipping the narrow fix is allowed; claiming it closed the
  class is not.

## Change
1. `audit-app.js` — new `waitForQuiescence(page, budgetMs)` helper, called by `checkOcclusion`
   **before each of its two passes** (at-rest and bottom-of-scroll; scrolling can start new animations
   and reveal lazily-mounted content):
   - polls until BOTH hold: (a) `document.getAnimations()` contains no effect with
     `playState === 'running'` **excluding** effects whose timing has `iterations === Infinity`
     (spinners/pulses never settle, and a lens that waits for them would hang every surface);
     (b) the geometry signature (overlay + candidate-victim rects, rounded) is byte-identical across two
     consecutive samples ≥ 100 ms apart.
   - **bounded**: on exceeding the budget it emits its own **P2 advisory naming the numbers**
     (`quiescence not reached in Nms: A animations still running, geometry still changing`) and measures
     anyway — never silently, never hanging (`playbooks/fixed-overlay-occlusion.md`'s "a check that
     cannot go red is not a check", generalised in `checkOcclusion`'s own header to "must never go
     silent").
2. `audit-app.js` — kill switch, house convention (`opts.occlusionQuiescence === false` /
   `AUDIT_OCCLUSION_QUIESCENCE=0`) → falls back to the pre-231 fixed 150 ms settle. Default ON. This
   exists so the acceptance test can run its own **positive control** in-session without editing source.
3. `audit-app.js` — `opts.injectStyle` (a CSS string added via `page.addStyleTag` immediately after each
   surface's `goto`). Test-injection only, same convention as `opts.rotationState` / `opts.livePools`;
   never set by the CLI. This is what lets the acceptance test re-create a **known-permanent** occlusion
   defect on a real surface without mutating the committed stylesheets.
4. `test_audit_occlusion_lens_reliability.js` — the detection-rate acceptance test (below), plus its
   registration in `run-tests.js`'s registry / `package.json`'s serial lane per the house pattern.

OUT of scope: `checkResponsive` (backlog 232); changing what the lens counts as an occlusion (thresholds,
severity, the two-position asymmetry) — this item changes only WHEN it measures; any product CSS.

## Acceptance criteria
- [ ] **The acceptance is the DETECTION RATE, never a single green run.** With item 230's fix mutated
      away via `opts.injectStyle` (`.app:not(.has-results):has(.results-section) .app-footer{position:fixed
      !important}` — a permanent, deterministic defect), `runAudit({ only:['dead-pool'] })` repeated
      **N = 20 isolated iterations** (fresh browser + fresh page per iteration) reports ≥ 1 blocking
      `occlusion` finding on **≥ 19 of 20** iterations.
- [ ] **Positive control, same harness, same session**: the identical 20 iterations with
      `occlusionQuiescence: false` (the pre-231 fixed-150 ms path) reproduce the *low* rate — **≤ 8 of 20**
      — so the harness is proven able to distinguish the two, and the ≥19/20 above is not a harness that
      would pass on anything. Both rates are printed by the test.
- [ ] **Non-vacuity of the injection itself**: with `injectStyle` supplying a no-op rule instead of the
      mutation, the same 20 iterations report **0** occlusion findings (the surface really is fixed on
      `main`; the harness is not manufacturing findings out of nothing).
- [ ] **No false positives introduced**: `node test_audit_occlusion_lens.js` (219's own acceptance suite,
      incl. its clean-surface, ordinary-top-header and static-bar negative cases) stays green.
- [ ] **Budget honesty**: a surface that never reaches quiescence emits the P2 advisory with its numbers
      and still measures — proven by a fixture carrying an infinite animation (must NOT hang, must NOT
      advise, since infinite effects are excluded) and by a fixture whose geometry never stabilises
      (must advise, must still measure).
- [ ] **Population, not instance**: the reliability harness drives the real `dead-pool` surface through
      the real `runAudit` driver (the population the lens draws from), never a hand-built fixture page.
      The `tvl-label` victim is the positive control, not the definition — the assertion is
      "≥1 blocking occlusion finding", not "this exact rect".
- [ ] Wall-clock: the added quiescence wait must not blow the audit's existing time budget — the test
      prints the mean per-iteration cost, and `specs/231-notes.md` records the delta.

## Measurement
Metric: the lens's own detection rate (build-leg verification — the 020 precedent: an instrument item
closes on functional verification, not on a traffic gate). Pre-fix 2/10 measured this run (221: 3/20).
Gate: n/a — no user-facing funnel step, nothing traffic-gated.
Decision rule: keep unconditionally if ≥19/20 with the control at ≤8/20; PARK if the rate cannot be
raised in 3 attempts (an honest recorded dead-end beats a fourth blind attempt).

## Territory notes
- `checkOcclusion` is `audit-app.js:4193`; the fixed settle is `await page.waitForTimeout(150)` at 4202;
  `occlusionPassEval` is at 3994; `isVisible()` (the gate that rejects animating victims) at ~3999.
- `pollFor(page, fn, budgetMs)` already exists in this file and is the house polling helper — reuse it
  rather than hand-rolling a loop.
- Entry animations: `style.css:4605` `.animate-on-mount { opacity: 0 }` + the per-section rules at
  4610-4670, each with a staggered `--entry-delay-base` multiple. `page.setViewportSize()` re-mounts them.
- The audit's own server serves repo files from ROOT; `style.min.css` is what `home.html` actually loads
  (the async `addCSS` media=print→all pattern), so any in-page mutation must use `!important` to beat it.
- Existing occlusion tests to keep green: `test_audit_occlusion_lens.js`, `test_footer_occlusion.js`,
  `test_cta_at_rest_occlusion.js`, `test_landing_footer_occlusion.js`, `test_dead_pool.js`.
- `data/pools-snapshot.json` drives the dead-pool alternatives grid; it churns daily — the harness must
  not assert on a specific alternative pool.

## Concurrently-written spec on `main` — folded in, not discarded (2026-08-05)

While this item was building, a heartbeat run wrote its **own** `specs/231.md` on `main`
(`1e40b5da4d`), for the same defect. That version is superseded by this one — the shipped code was
built and verified against THIS spec — but two things in it are better than what this spec said, and
are adopted here rather than lost in the merge:

1. **Its population is WIDER, and it is right.** It defined the class as *"EVERY lens/check that sleeps
   a constant then measures — grep `waitForTimeout` / hardcoded ms constants and treat each as a
   member"*, where this spec named only the 2 geometry-reading lenses. The wider reading is the weaker
   hypothesis and therefore the correct one (RAZOR). **The number, counted on `main`: 4
   `page.waitForTimeout(` sites in `audit-app.js`** — `:3464` (120 ms), `:3613` (400 ms), and the two
   at `:4202`/`:4253` inside `checkOcclusion`. This item converts the `checkOcclusion` pair to a
   quiescence wait; **`:3464` and `:3613` remain fixed-duration settles and are untouched**. So the
   class is open on **2 of 4** fixed-wait sites, not merely on `checkResponsive`. Ticketed as **233**
   (renumbered from 232 — see below), whose scope is widened accordingly.
2. **An acceptance criterion this item did NOT satisfy, stated plainly**: *"No detection regression
   elsewhere — a full scanner run before and after on the same commit; every surface flagged before is
   flagged after (the fix may only ADD detections). Diff the two findings JSONs."* This build did not
   run that full before/after tick diff. What was run instead: `test_audit_app.js` (whose clean-run
   assertions cover every non-quarantined surface) plus a 4-surface `runAudit` comparison, which found
   the same 4 occlusion findings with quiescence ON and OFF. That is weaker than the criterion asked
   for. Recorded as a gap, not as coverage.
