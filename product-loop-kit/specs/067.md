# Spec 067: Fix $0 projection on capital-funded GROWTH plans

## Evidence
Human-reported production bug (2026-07-13, screenshots), not heartbeat-derived: `/plan.html?goal=retirement&pace=rwa&capital=1000&fm=capital&years=5` (a capital-funded GROWTH-archetype plan — retirement, home) rendered:
- headline: "≈ $0 in 5 years"
- "vs $0 in a typical 0.5% savings account"
- "You'd have deposited $0 of your own money"

...despite the sidebar correctly showing `$1,000` capital and a live `10.58%` blended APY. Root cause (code-confirmed, not guessed): `futureValue(monthly, apy, years)` is a pure monthly-contribution annuity formula; `monthly` is `null` for a capital-funded plan (`decodePlanFromUrl` sets `monthly: null` when `fm === 'capital'`). GROWTH's hero/headline/report code paths only ever called `futureValue(monthly, ...)` and `totalDeposited(monthly, ...)` — never read `capital` at all, unlike TARGET and SUBSCRIPTION archetypes, which already have dedicated capital-path branches (`monthsUntilYieldCoversTarget`, `foreverNumber`). One code comment literally read `// GROWTH: unchanged` at the exact line missing the capital leg — a leftover from before the v3 capital-first funding mode was added to TARGET/SUBSCRIPTION but never backfilled to GROWTH.

CLAUDE.md: "Capital-first is the default funding path" (v3, decided) — GROWTH is one of three archetypes this applies to, so this wasn't an edge case; it broke the default funding path for one of three plan types.

## Hypothesis
N/A — this is a correctness bug fix, not a growth-hypothesis experiment. Confidence: validated (root-caused in code, reproduced via a fixture-routed Playwright test before and after the fix).

## Change
Added `capitalGrowth(capital, annualRatePct, years)` — lump-sum compounding (`capital * (1+r)^years`), the capital-path counterpart to the existing `futureValue`/`totalDeposited` monthly-annuity helpers. Threaded it into every GROWTH projection/deposited computation that was missing it:
- `buildPlanHero`'s growth branch (feeds the persisted plan's `hero.projection` and the `plan_created`-adjacent report field)
- Bloom's top-level `projection`/`bankProjection`/`deposited` vars (feeds the `plan_saved` payload and the "was $X when planted" report line)
- Bloom's live-slider `liveProjection`/`liveBankProjection` + the "You'd have deposited" line (the actual rendered headline on the reported URL) — gated by `isCapitalPath`, since `slideCapital`'s own `useState` defaults to `5000` even on monthly-funded plans and would otherwise leak a phantom capital into monthly-only projections
- `GardenReport`'s `newProjection` (the returning-visitor "your garden today" recompute, for a plan saved before this fix or reloaded later)

OUT of scope: TARGET/SUBSCRIPTION archetypes (already capital-aware, untouched), the checkout-panel yield estimate (`chkValueProp`, a different simple-yield display, already correct for its own purpose), and the pool-detail "Calculate Your Earnings"/APY-metric display the same bug report screenshot-referenced — investigated and found internally consistent (the calculator correctly uses the pool's live total APY; a separately-displayed "30D Mean APY" is a different, legitimately more volatile metric for a yield-farming reward pool, not a miscalculation) — flagged to the human rather than "fixed" since there was nothing broken to fix there.

## Territory notes
- `slideCapital`'s `useState(propCapital || 5000)` default is a trap for any future capital-aware computation in Bloom: it is NOT 0/null for a monthly-funded plan, so any code reading `slideCapital` without gating on `isCapitalPath` will leak a phantom $5,000 (or the current slider position) into a monthly-only plan's numbers. Every fix site here explicitly gates on `isCapitalPath` for this reason; the top-level (non-slider) `propCapital`/`plan.capital` values don't have this trap (they're null/0 when absent), so those sites use `capitalGrowth(propCapital, ...)` / `capitalGrowth(plan.capital, ...)` unconditionally.
- The three archetypes are NOT symmetric in how they express a capital-funded plan's hero: TARGET uses a "flip date" (`monthsUntilYieldCoversTarget`), SUBSCRIPTION uses "forever number progress" (`foreverNumber`), and GROWTH uses a dollar projection (`futureValue`-shaped). The bug was specifically that GROWTH's dollar-projection shape was never given a capital-aware formula, unlike the other two archetypes' entirely different (and already-correct) hero shapes.
