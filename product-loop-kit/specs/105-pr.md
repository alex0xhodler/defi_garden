# 105 — PR explainer: enrich live `?pool=` SEO landings with the snapshot's `kpis`

Risk tier: **HIGH** (touches `?pool=` deep-link render behavior — a sacred
parameterized-URL surface — and governs whether user-facing trust-signal notes render).
Auto-merges after verifier PASS + tests green (autonomy (c), 2026-07-10). Not on the
NEVER list.

## Goal

Bring the already-shipped KPI trust-signal notes (088.1 rate-track-record, 103
rate-momentum) to SEO arrivals. Today a visitor who lands directly on `/?pool=<id>` — the
organic SEO / share deep-link surface (item 019) — sees LESS trust signal than an in-app
browser, because that path loads live DefiLlama data which has no `kpis`. This is exactly
the audience we want to convert toward the card funnel.

## Intuition (why the notes were hiding)

`app.js` decides where pool data comes from:

```
const snapshotEligible = !urlParams.pool && urlParams.minTvl >= DEFAULT_MIN_TVL;
```

Any `?pool=<id>` deep link sets `urlParams.pool`, so `snapshotEligible` is **false** and
the app always fetches live `https://yields.llama.fi/pools`. Live pool objects have no
`kpis` field. The KPI notes in `PoolDetail.js` read `pool.kpis.*` and render nothing when
it is absent — correct, honest, but it means SEO landings never show the signal. In-app
browse→detail doesn't have this problem because `pools` came from the snapshot, which
carries per-pool `kpis`.

The fix: when the detail pool has no `kpis`, read them from the same snapshot the in-app
path uses, and merge just that `kpis` object onto the single detail pool.

## What changed and why (reading order)

1. **`app.js` — a new ref** (`kpiEnrichedPoolRef`) next to the existing refs. It records
   the pool id we already tried to enrich, so the effect never refetches and never loops.

2. **`app.js` — one new `useEffect`** immediately after the pool-detail resolution effect.
   Guard chain: only runs in pool-detail view, only when `detailPool` exists and has **no**
   `kpis`, only once per pool id. It fetches `/data/pools-snapshot.json`, validates the
   schema, finds the pool by `pool.pool`, and — only if a matching pool with a real `kpis`
   object exists — merges `{ ...detailPool, kpis: match.kpis }` via a functional
   `setDetailPool`. Every failure path (fetch error, bad schema, pool absent, no kpis) is a
   silent no-op: `detailPool` is untouched and the notes stay hidden, exactly today's
   behavior. It reads the snapshot directly (no 15-min meta freshness gate) because `kpis`
   are slow-moving derived signals and 071's live-data volatility note takes precedence
   over both kpis notes anyway.

   Why no loop: the effect's own `setDetailPool` gives `detailPool` a `kpis`, so the
   re-run short-circuits at `!detailPool.kpis`; the ref short-circuits any further attempt
   for the same id.

   Why safe: it enriches ONLY the single `detailPool` object. It never mutates the `pools`
   array (so sorting/filtering/cards are untouched), never reads or writes the rail
   constants, never filters/reorders/re-flags a pool. Trust rails byte-untouched.

3. **`test_kpi_seo_enrichment.js`** (new) — rendered-Playwright gate mirroring
   `test_kpi_track_record.js`. It routes live `/pools` to a fixture with NO kpis (the real
   SEO-landing shape) and `/data/pools-snapshot.json` to a fresh fixture WITH kpis, then
   drives real `?pool=<id>` renders. D1: enriched landing shows the NEW-tier note. D2: pool
   absent from snapshot → note absent (honest). D3: steady-tier copy driven by merged kpis.
   D4: snapshot pool without a `kpis` field → note absent (never a placeholder). D5: zero
   page errors. Wired into `package.json`'s test chain.

4. **`app.compiled.js` / `app.compiled.min.js`** — regenerated from the edited `app.js`
   (`npm run compile && npm run minify`); home.html loads the minified build.

## Deviations from spec

None on code/test content (see `specs/105-notes.md`). Two conservative choices recorded:
snapshot read bypasses the meta freshness gate (kpis are slow signals; 071 wins on live
volatility), and the effect fires for any kpis-less detail pool (the `?pool=` path is the
only such path in practice).

## No copy / no PoolDetail change

Zero new translations, zero `PoolDetail.js` edits — the 088.1 + 103 notes already read
`pool.kpis.*`; feeding them the kpis is the whole change.
