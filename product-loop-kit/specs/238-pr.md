# 238 — retire the terminal skin — one type system on the Quiet base

## Goal

Close the last visible "different product" gap the human's screenshots showed
between the analytics grid's data rows and the rest of the Quiet design
system: stray `text-transform: uppercase` left over from the old terminal
skin, two `font-family` declarations that silently bypassed the design
token layer, and one banned scale-pop `:hover` rule (CLAUDE.md forbids
these — "Banned: ... scale-pop hovers").

## Intuition

A design system is only as strong as its weakest un-migrated corner. 225 and
247 already unified geometry and color; this item finishes typography and
one hover-physics violation the earlier rounds left behind — either because
a rule was added after their sweep, or because (as turned out to be true
here) a later rule was still winning the CSS cascade over an earlier fix
that *thought* it had already killed the behavior.

## What changed, in reading order

1. **`style.css` — 8 `text-transform: uppercase` rules removed** from
   label/badge selectors (`.sota-popover-title`, `.sota-section-subtitle`,
   `.filter-label`, `.pool-detail-label`, `.seo-eyebrow`, `.start-earning-btn`,
   `.value-filter-label`, `.section-label`). Each rendered prose (a label or
   a CTA string), which the CSS was visually shouting; source strings were
   already sentence/title case, so no `translations.js` edit was needed.
2. **2 uppercase rules kept, both allowlisted with a reason** in the new
   test: `.pool-logo-monogram` (a single-character avatar glyph the JS
   already `.toUpperCase()`s independently — data, not prose) and
   `.pool-left-section::after` (confirmed dead: `content: attr(data-pool-type)`
   is never set by any JS, rule sits at `opacity: 0`).
3. **2 `font-family` fixes**: `.pool-score-chip` referenced the undefined
   `--font-mono` variable (silently fell back to the bare `monospace`
   keyword — `--font-mono` was never declared, only `--font-family-mono`
   was); `.pool-info-item .value.token-pair` used a bare `monospace`
   keyword directly. Both now `var(--font-family-mono)`.
4. **`.logo:hover`'s scale-pop deleted** (`style.css`). Not just cleanup: an
   earlier "225 round 3c" pass added a second, color-only `.logo:hover` rule
   higher in the file intending to remove the lift, but because it never
   touched `transform`, this later block was still winning the cascade and
   firing the banned scale-pop on every hover. Deleting it finishes what
   round 3c only partially did.
5. **Round-1 verifier FAIL, fixed in round 2**: the spec's own acceptance
   criterion ("no `transform: scale` on any `:hover` rule repo-wide... now
   machine-enforced") was unmet — two more scale-pop hovers existed outside
   `.logo`: `.modal-close:hover` (`style.css`) and `.landing-page-dot:hover`
   (`landing-styles.css`). Both `transform: scale` lines removed; neither
   rule's `:active` press physics was touched.
6. **Round-2 verifier FAIL, fixed in round 3**: an extension attack against
   the actual filesystem (`find . -name "*.css"`) found a sixth live
   stylesheet the round-2 scan's hand-picked file list missed —
   `hype-harvest.css` (added after that list was written), with its own
   `.quiet-slider::-webkit-slider-thumb:hover { transform: scale(1.15); }`,
   rendered live on `hype-harvest.html`. Fixed, and the scan itself now
   derives its file list from disk (`fs.readdirSync(recursive: true)`
   filtered to source `.css`) instead of a hand-maintained array, so a
   future new stylesheet is in scope automatically.
7. **`test_typography_tokens.js` (new)** enumerates, at test time, every
   `text-transform: uppercase` and `font-family` declaration in `style.css`,
   plus every `:hover` rule with `transform: scale(...)` across every
   source `.css` file the repo ships. All three checks carry an in-memory
   non-vacuity proof (mutate → red → restore → green). 11/11 passing.
8. `style.min.css` regenerated via `npm run minify` (`hype-harvest.css` has
   no minified counterpart).

## Deviations from spec

- The spec's Evidence section was measured on a stale branch (`claude/loop-225`)
  before item 247's design-world replacement landed — `SF Mono` was already 0
  on current `main`, and `.pool-symbol`/`.pool-context-inline` were already
  fixed. Re-derived the real remaining population from current `main`
  instead of trusting the spec's numbers (documented in `238-notes.md`).
- `.modal-close:active`'s pre-existing `transform: scale(0.95)` (a *separate*
  defect — a duplicate `transform` property silently overriding the
  documented `translateY(1px)` press physics, not a `:hover` scale-pop) was
  found but deliberately left untouched — it's a different defect class,
  outside this item's named scope, flagged for a follow-up.
