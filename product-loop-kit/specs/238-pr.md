# 238 — PR explainer (HIGH tier: full walkthrough + quiz)

## Goal

Item 238 was filed to "kill the terminal-skin remnants the Quiet reset leaves behind": hardcoded
monospace font stacks bypassing the token layer, uppercase micro-labels that made the data grid read
like a different product from the sentence-case landing, and a banned `scale`-pop hover on `.logo`.

## The intuition — and why the item is not what it looks like

The spec was written on 2026-08-05 against the branch `claude/loop-225`. **That tree no longer exists.**
Two days later item 247's design world shipped to main across three human-merged PRs (#409, #412, #413)
under the directive *"ONLY SOTA GRADE WORK given the ICP"*, and it rewrote the same stylesheets.

So the first act of this build was not to write code. It was to re-measure every number in the spec on
main:

| Spec's claim (225 tree) | Reality on main |
|---|---|
| 4 hardcoded `'SF Mono',…` stacks | **0.** `grep -c "SF Mono" style.css` → 0 — 247 had already cleaned them |
| — | but 3 *different* hardcoded stacks survived, which the spec's literal grep could not see |
| 11 uppercase rules, all residue | **24** rules — and `git blame` says 247 *authored* many of them |
| `.logo:hover` scale-pop | still there, plus **2 more** instances of the same banned class |

Every one of the spec's numbers was wrong, in both directions. The interesting failure is the third row.
The spec's hypothesis was "uppercase = terminal-skin residue the reset missed." Blame falsifies it:

- `pool-detail-styles.css:654` `.pool-action-apy-label` ← **#412**
- `planner-styles.css:1929/1934` `.gp-goal-cat-label`, `.gp-sub-ladder-title` ← **#413**
- one of those rules carries the repo's own comment: *"Plate-label voice — pool-detail's serif
  micro-caps recipe."*

Uppercase on `--cert-serif`/`--font-family-display` at 0.14–0.22em tracking is a **deliberate convention
of the certificate world**, not a leftover. Executing the spec literally would have been an autonomous
loop silently reverting the human's newest design directive — on a guess, at 3am, with no one watching.
That is the failure mode this whole kit exists to prevent, so the criterion was **re-scoped in the spec
first** (build.md §2 Territory notes), then built.

The re-scope keeps the part of the criterion that has teeth and drops the part that was an assumption:

> from *"remove the uppercase rules"* → to *"no **un-reasoned** uppercase rule can exist"*

Zero uppercase rendering changed. What changed is that all 24 are now enumerated in an allowlist with a
one-line reason each, checked for **set-equality in both directions**, so nobody — human or loop — can
add a 25th without saying why.

## What changed, in reading order

### 1. `style.css` / `planner-styles.css` — 6 surgical edits, the only rendering changes

**Font stacks → the token** (3):
- `.pool-info-item .value.token-pair` (style.css): bare `monospace` → `var(--font-family-mono)`
- `.gp-waitlist-link-text` (planner-styles.css): bare `monospace` → `var(--font-family-mono)`
- `.gp-journey-status` (planner-styles.css): `var(--font-family-mono, ui-monospace, monospace)` → drop
  the dead fallback

**Banned scale-pops deleted** (3):
- `.logo:hover { transform: scale(1.02) }` — the rule the spec ticketed. Its
  `transition: transform 300ms` went too: with the hover gone nothing else transforms `.logo`
  (verified by grepping all 8 `.logo` rules; `.logo:active { transform: none }` was already explicit).
- `.modal-close:hover { transform: scale(1.05) }` — the same banned class, one the spec never mentioned.
  Found by asking what `.logo:hover` was an *instance of* rather than fixing the named instance.
- `.modal-close:active` declared `transform: translateY(1px)` and then, on the very next line,
  `transform: scale(0.95)` — **the second silently killed the press physics CLAUDE.md mandates.** A live
  bug, in the same class, invisible until you enumerate the class.

### 2. `test_type_system_contract.js` (new, 406 lines) — the actual deliverable

The CSS fixes are six lines. This file is what stops them from regressing. It derives its population **at
test time** — every root `*.css` that is not `*.min.css`, plus `stories/stories.css` — so a stylesheet
added next month is covered the day it lands. A glob returning fewer than 4 files fails loudly, because
a broken glob must never read as a clean pass.

Three independently-failing rules, on a brace-depth-aware tokenizer (multi-line selector lists, quoted
strings containing braces, `@font-face`/`@keyframes` nesting):

1. **No hardcoded font stacks.** Every `font-family` must be a `var()` token reference, an `@font-face`
   descriptor, or a token definition. Nothing else.
2. **Reasoned uppercase allowlist, both directions.** An unlisted live rule fails forward; an allowlist
   entry with no matching live rule fails in reverse. One-directional would have been a verifier FAIL —
   RAZOR's mirror rule, learned from item 212.
3. **Absolute ban on `transform: scale` inside any `:hover` selector.** No allowlist; the ban is
   absolute.

The 24 allowlist reasons are the human's answer sheet, categorised: **12 `247-world micro-label`**
(certificate convention, blame-backed), **1 `data`** (`.pool-logo-monogram` — a protocol initial already
uppercased in JS), **11 `unreviewed residue`** (pre-247, no recorded rationale — the reasons say *"cannot
confirm intent from source alone"* rather than inventing it). Flip a reason to residue and the sweep
becomes a mechanical follow-up.

### 3. `test_type_system_render.js` (new, 265 lines) — rendered acceptance

UX items are not acceptable on source-text fixtures alone (standing decision 2026-07-11). Real chromium,
both themes: `.logo` computes `transform: none` under hover, and the mono call site resolves through the
token — with the expected family **read at runtime** from `--font-family-mono`, never hardcoded, so the
test tracks the token if it is ever re-themed.

### 4. `package.json`, `*.min.css`

Both tests registered in `test:serial` (which `run-tests.js` parses as its single source of truth);
`test_test_registry.js` green after. Min sheets regenerated — prod loads them, so a stale twin would have
left the fix unshipped.

## Deviations from the spec

1. **Uppercase rendering not changed** — the spec's hypothesis was falsified by blame. The big one;
   argued above and in `238-notes.md`.
2. **Count corrected twice.** Spec said 11. My hand survey said 23. The instrument said **24** — I had
   missed `stories/stories.css`. The instrument won against its own author, which is the argument for
   deriving populations rather than listing them.
3. **Render test asserts on `/?app`, not `/?token=USDC`.** `app.js` renders the `.logo` wordmark only
   when `!(selectedToken || (chainMode && selectedChain))`; on `/?token=USDC` a differently-classed
   `.app-logo` renders instead. `/?app` is a legitimate analytics URL (`app` ∈ `ANALYTICS_PARAMS`), and
   the test asserts `data-app-mode === 'analytics'` so the surface is provably right.
4. **`.gp-waitlist-link-text` has no render call site at all** — dead CSS. Tokenized anyway (so a
   future revival can't reintroduce a hardcoded stack), but the render test asserts on
   `.gp-journey-status` only and prints the gap each run instead of faking coverage.
5. **`npm install` was run** — `node_modules` was absent in the build session; pre-existing tests failed
   identically before it.

## Non-vacuity — each rule proven to fail on its own

| Mutation | Goes red | Others | Restore |
|---|---|---|---|
| bare `monospace` back on `.value.token-pair` | Rule 1 | 2, 3 green | md5 `2fd3f50d…` before = after |
| throwaway uppercase rule added | Rule 2 **forward** | 1, 3 green | tree clean |
| deleted a live rule an entry points at | Rule 2 **reverse** | others green | md5 `c67d2d0c…` before = after |
| `scale(1.02)` back on `.logo:hover` | Rule 3 | 1, 2 green | md5 `2fd3f50d…` before = after |

Four mutations, four isolated reds — so "three working rules" is distinguishable from "one working rule
and two dead ones."

## The class this item does NOT close, with a number

`@keyframes yieldBounce` (applied via `.yield-pulse-active`) is a `scale(1.02)` pop on a bounce easing
`cubic-bezier(0.34, 1.56, 0.64, 1)` — **both** banned by CLAUDE.md. It is not a `:hover` rule, so Rule 3's
predicate does not reach it. **1 rule / 1 keyframe block, unguarded**, ticketed separately. Rule 3 would
not catch a banned scale-pop introduced as a keyframe tomorrow, and this item does not pretend otherwise.

The font-stack class **is** closed for the derived population.
