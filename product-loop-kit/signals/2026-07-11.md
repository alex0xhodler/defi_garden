## Three code-verified measurement gaps (the keystone finding)
1. **`search_success.results_count` is always 0.** Breakdown: 50/50 events have `results_count=0`. The NL-Enter path (`app.js:1933` → `trackSearch`) calls `trackSearchSuccess(..., 0, ...)` (`analytics.js:125`) because filtered results aren't computed at parse time. So "success" measures *parse*, not *results shown*. 018's 92.6% is a parse rate, not a find-a-pool rate.
2. **`trackPoolView` never fires on direct `/?pool=` SEO landings.** The URL-driven pool-detail effect (`app.js:1006-1024`) sets the view without tracking; `trackPoolView` fires only on internal card clicks (`app.js:2139`). SEO-lander pool views are invisible → 019's `garden_cta` CTR has no denominator.
3. **Behavioral drop-off (not an artifact): 50 searches → 0 pool_view → 0 pool_click.** `handlePoolClick` IS wired to card `onClick` (`app.js:2343`), so pool_view would fire if cards were clicked. Internal-search users are not opening any pool. 100% drop at the analytics-app → pool-detail step.
